# 第 14 週今日 Node.js 練習題：個人部落格後端 API

## 題目說明

整合前 13 週所學知識，從零開始建構一套**個人部落格後端 API**。這個專案將涵蓋 Express、PostgreSQL、JWT 驗證、輸入驗證、檔案上傳與 Jest 測試，是最接近真實後端工程師日常工作的綜合練習。

---

## 技術要求

- **概念：** REST API、JWT 身份驗證、資料庫 CRUD、Middleware、輸入驗證、錯誤處理、檔案上傳
- **需要的套件：**
  ```
  express
  pg
  jsonwebtoken
  bcryptjs
  express-validator
  multer
  dotenv
  jest
  supertest
  ```

## 具體任務

### 1. 專案初始化
- 執行 `npm init -y` 並安裝所需套件
- 建立 `.env` 設定以下環境變數：
  ```
  PORT=3000
  DATABASE_URL=postgres://...
  JWT_SECRET=your_secret_key
  ```
- 建立以下目錄結構：
  ```
  blog-api/
  ├── src/
  │   ├── routes/
  │   ├── controllers/
  │   ├── middleware/
  │   └── db/
  ├── uploads/
  ├── tests/
  └── app.js
  ```

### 2. 資料庫設計
建立以下兩張 PostgreSQL 資料表：

```sql
-- 使用者表
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(50) UNIQUE NOT NULL,
  email VARCHAR(100) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  avatar_url TEXT,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 文章表
CREATE TABLE posts (
  id SERIAL PRIMARY KEY,
  title VARCHAR(200) NOT NULL,
  content TEXT NOT NULL,
  author_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  cover_image_url TEXT,
  published BOOLEAN DEFAULT false,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

### 3. 實作 API 端點

**身份驗證（`/api/auth`）**
| 方法 | 路徑 | 說明 |
|------|------|------|
| POST | `/register` | 使用者註冊 |
| POST | `/login` | 登入，回傳 JWT |

**文章管理（`/api/posts`）**
| 方法 | 路徑 | 權限 | 說明 |
|------|------|------|------|
| GET | `/` | 公開 | 取得所有已發布文章（支援分頁） |
| GET | `/:id` | 公開 | 取得單篇文章 |
| POST | `/` | 需登入 | 新增文章 |
| PUT | `/:id` | 需登入（本人） | 更新文章 |
| DELETE | `/:id` | 需登入（本人） | 刪除文章 |
| POST | `/:id/publish` | 需登入（本人） | 發布文章 |

**使用者頭像（`/api/users`）**
| 方法 | 路徑 | 說明 |
|------|------|------|
| POST | `/avatar` | 上傳頭像（multer，需登入） |

### 4. 實作 Middleware
- `authMiddleware`：驗證 JWT，將使用者資訊注入 `req.user`
- `ownerMiddleware`：確認操作者為文章作者本人
- `errorHandler`：全域錯誤處理，回傳一致的 JSON 格式

### 5. 輸入驗證
使用 `express-validator` 對以下欄位做驗證：
- 註冊：`username`（3–50 字元）、`email`（合法格式）、`password`（最少 8 字元）
- 文章：`title`（不得為空）、`content`（不得為空）

### 6. 撰寫 Jest 測試
使用 `supertest` 為以下情境各寫一個測試案例：
- 成功註冊新使用者
- 使用錯誤密碼登入應回傳 401
- 未登入存取需驗證的端點應回傳 401
- 成功建立文章後可用 GET 取回

## 範例

```js
// POST /api/auth/register
// Body:
{
  "username": "alice",
  "email": "alice@example.com",
  "password": "secret123"
}

// Response 201:
{
  "message": "註冊成功",
  "user": { "id": 1, "username": "alice", "email": "alice@example.com" }
}

// POST /api/auth/login
// Response 200:
{
  "token": "eyJhbGciOiJIUzI1NiIs..."
}

// GET /api/posts?page=1&limit=10
// Response 200:
{
  "data": [ { "id": 1, "title": "第一篇文章", "author": "alice", ... } ],
  "total": 1,
  "page": 1,
  "limit": 10
}
```

---

## 提示

- 密碼務必使用 `bcryptjs` 雜湊後再存入資料庫，**絕對不要明文儲存**
- JWT payload 只放 `{ userId, username }`，不要放密碼
- `multer` 的 `fileFilter` 只允許 `image/jpeg` 與 `image/png`，並限制檔案大小為 2MB
- 分頁查詢使用 `LIMIT $1 OFFSET $2` 搭配 query string `?page=1&limit=10`
- 使用 `try/catch` + `next(err)` 將錯誤統一交給全域 errorHandler 處理

## 學習重點（跟後端 API 的關聯）

這個專案模擬了真實後端服務的完整生命週期：

1. **安全性**：密碼雜湊 + JWT 無狀態驗證，是現代 API 的標準做法
2. **資料一致性**：外鍵 `ON DELETE CASCADE` 確保孤立資料不殘留
3. **可維護性**：Controller / Route / Middleware 分層讓程式碼易於擴充
4. **可測試性**：`supertest` 讓你在不啟動真實伺服器的情況下測試 HTTP 行為
5. **使用者體驗**：分頁 + 統一錯誤格式讓前端更容易串接

1. **文章標籤**：新增 `tags` 資料表（多對多關係），支援 `GET /api/posts?tag=nodejs`

4. **Rate Limiting**：登入端點加上每分鐘最多 5 次的速率限制（`express-rate-limit`）
5. **GitHub Actions CI**：建立 `.github/workflows/test.yml`，Push 時自動跑 Jest 測試
