# 第 21 週今日 Node.js 練習題：即時聊天室 WebSocket 伺服器

## 題目說明

建立一個支援即時訊息的聊天室後端，整合 WebSocket（`ws` 套件）與 Express HTTP 伺服器。使用者透過 JWT 連線後，可加入不同聊天室頻道、廣播訊息、查看線上人數，並以 Jest 撰寫整合測試。這道題目拓展前幾週 REST API 技能，進入「持久連線」與「推播」的核心場景。

## 技術要求

- **概念**：WebSocket 協定、事件驅動架構、房間（room）管理、JWT 連線驗證、廣播
- **需要的套件**：
  - `express` — 提供 HTTP REST 端點（查詢歷史訊息）
  - `ws` — WebSocket 伺服器
  - `jsonwebtoken` — 連線時驗證 token
  - `jest` + `ws`（測試用客戶端）— 整合測試

## 具體任務

1. **初始化專案結構**
   ```
   chat-server/
   ├── src/
   │   ├── auth.js          # JWT 簽發 / 驗證工具
   │   ├── roomManager.js   # 房間與連線管理
   │   ├── wsHandler.js     # WebSocket 訊息處理
   │   ├── routes/
   │   │   └── history.js   # GET /api/rooms/:room/messages
   │   └── server.js        # 組合 HTTP + WS 伺服器
   ├── tests/
   │   └── chat.test.js
   └── package.json
   ```

2. **WebSocket 連線驗證**
   - 客戶端連線時在 query string 帶上 token：
     `ws://localhost:3000?token=<JWT>&room=general`
   - 伺服器在 `upgrade` 事件驗證 token；驗證失敗直接拒絕連線（回傳 HTTP 401）

3. **房間管理（`roomManager.js`）**
   - 維護一個 `Map<roomName, Set<WebSocket>>` 記錄各房間的連線
   - 提供以下方法：
     - `join(room, ws, user)` — 將連線加入房間，廣播「*user* 加入了頻道」
     - `leave(room, ws)` — 連線斷開時移除，廣播「*user* 離開了頻道」
     - `broadcast(room, message, senderWs?)` — 廣播給房間所有人（可排除發送者）
     - `getOnlineCount(room)` — 回傳房間線上人數

4. **WebSocket 訊息協定（JSON 格式）**
   客戶端傳送：
   ```json
   { "type": "message", "content": "Hello!" }
   { "type": "ping" }
   ```
   伺服器廣播：
   ```json
   { "type": "message", "from": "alice", "content": "Hello!", "ts": 1234567890 }
   { "type": "system", "content": "alice 加入了頻道", "count": 3 }
   { "type": "pong" }
   ```

5. **訊息歷史（記憶體儲存，最多保留 50 筆）**
   - 每則廣播訊息存入 `Map<roomName, Array>` 環形緩衝
   - 新連線加入房間時，伺服器自動推送最近 20 筆歷史訊息

6. **HTTP 端點（Express）**
   - `GET /api/rooms` — 列出所有有人在線的房間及人數
   - `GET /api/rooms/:room/messages` — 回傳該房間最近 N 筆歷史（query: `?limit=20`）

7. **撰寫 Jest 整合測試**
   - 伺服器啟動後，用 `ws` 套件建立測試客戶端
   - 測試場景：token 無效時連線被拒、兩個客戶端互傳訊息、一方斷線後廣播離開通知

## 範例

```js
// 客戶端連線（Node.js ws 套件）
const WebSocket = require('ws');
const token = 'eyJ...'; // 由 auth.js 簽發
const ws = new WebSocket(`ws://localhost:3000?token=${token}&room=general`);

ws.on('message', (data) => {
  const msg = JSON.parse(data);
  // 收到歷史訊息推送
  // { type: 'history', messages: [...] }
  // 收到其他人的訊息
  // { type: 'message', from: 'bob', content: 'Hi!', ts: 1748908800 }
});

ws.on('open', () => {
  ws.send(JSON.stringify({ type: 'message', content: '大家好！' }));
});

// HTTP 查詢
// GET /api/rooms
// Response 200:
// { "rooms": [{ "name": "general", "count": 3 }, { "name": "nodejs", "count": 1 }] }
```

## 提示

- `ws` 套件與 Node.js 內建 `http.Server` 共享同一個 port：
  ```js
  const server = http.createServer(app);
  const wss = new WebSocket.Server({ server });
  server.listen(3000);
  ```
- 在 `upgrade` 事件攔截驗證，比在 `connection` 事件驗證更安全（可回傳 HTTP 狀態碼）：
  ```js
  server.on('upgrade', (req, socket, head) => { /* 驗證 token，失敗時 socket.destroy() */ });
  ```
- 測試時將 `server.listen` 的 port 設為 `0`，讓 OS 自動分配，取得實際 port：
  `server.address().port`
- 環形緩衝：陣列長度超過 50 時用 `Array.shift()` 移除最舊一筆
- 注意 `ws.readyState === WebSocket.OPEN` 才能 `send`，避免對已斷線的連線發送

## 學習重點（跟後端 API 的關聯）

| 本週練習 | 真實後端對應 |
|---|---|
| `ws` WebSocket 伺服器 | Socket.IO、STOMP over WebSocket |
| 房間廣播 | Pub/Sub 模式（Redis Pub/Sub、Kafka） |
| JWT 連線驗證 | WebSocket 無法帶 Cookie，token-in-query 是常見模式 |
| 記憶體歷史緩衝 | 換成 Redis List 或時序資料庫 |
| `server.on('upgrade')` | Reverse proxy（Nginx）的 WebSocket 升級設定 |

掌握 WebSocket 推播機制，就能應付即時通知、線上協作、遊戲同步等需要伺服器主動推送的場景。

## 進階挑戰（選做）

1. **私訊**：新增訊息類型 `{ type: "dm", to: "username", content: "..." }`，只轉發給目標使用者
2. **打字中提示**：客戶端傳 `{ type: "typing" }`，伺服器廣播 `{ type: "typing", from: "alice" }`，前端顯示「alice 正在輸入…」
3. **心跳保活**：每 30 秒對所有連線發送 `ping` frame（`ws.ping()`），60 秒未收到 `pong` 則強制斷線
4. **Redis 廣播**：用 `ioredis` Pub/Sub 讓多個 Node.js 實例共享廣播，支援水平擴展
5. **前端整合**：用原生瀏覽器 `WebSocket API` 建立一個簡單 HTML 聊天介面（`index.html`），以 Express 靜態檔案服務提供
