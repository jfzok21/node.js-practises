# 第 16 週今日 Node.js 練習題：任務管理系統 API（全端整合實戰）

## 題目說明

打造一個完整的「任務管理系統後端 API」，整合你前幾週所學的所有核心技能：
Express、JWT 身份驗證、輸入驗證、錯誤處理、REST API 設計，以及 PostgreSQL 資料庫操作。
這個專案模擬真實工作環境中的後端服務，讓你熟悉從零開始架構一個生產等級的 API。

- **概念**：REST API、JWT 驗證、Middleware 架構、錯誤處理、輸入驗證、關聯式資料庫設計

### 2. 資料庫設計

建立以下兩張資料表：

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(50) UNIQUE NOT NULL,
  email VARCHAR(100) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  title VARCHAR(200) NOT NULL,
  description TEXT,
  status VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending', 'in_progress', 'done')),
  priority VARCHAR(10) DEFAULT 'medium' CHECK (priority IN ('low', 'medium', 'high')),
  due_date DATE,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

### 3. 實作 Auth 路由

- `POST /api/auth/register` — 註冊（加密密碼，存入 DB，回傳 JWT）
- `POST /api/auth/login` — 登入（驗證密碼，回傳 JWT）

### 4. 實作 Tasks 路由（需通過 JWT 驗證）

- `GET /api/tasks` — 取得目前使用者的所有任務（支援 `?status=` 和 `?priority=` 篩選）
- `POST /api/tasks` — 新增任務
- `GET /api/tasks/:id` — 取得單一任務
- `PUT /api/tasks/:id` — 更新任務（只能更新自己的）
- `DELETE /api/tasks/:id` — 刪除任務（只能刪除自己的）
- `PATCH /api/tasks/:id/status` — 只更新任務狀態

### 5. 加入輸入驗證（使用 Joi）

```js
const createTaskSchema = Joi.object({
  title: Joi.string().min(1).max(200).required(),
  description: Joi.string().max(1000).optional(),
  priority: Joi.string().valid('low', 'medium', 'high').default('medium'),
  due_date: Joi.date().min('now').optional()
});
```

### 6. 全域錯誤處理 Middleware

所有錯誤統一格式：

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "標題不能為空",
    "statusCode": 400
  }
}
```

## 範例

```js
// POST /api/auth/register
// Request Body:
{
  "username": "alice",
  "email": "alice@example.com",
  "password": "SecurePass123!"
}

// Response 201:
{
  "message": "註冊成功",
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": { "id": 1, "username": "alice", "email": "alice@example.com" }
}

// POST /api/tasks （帶 Authorization: Bearer <token>）
// Request Body:
{
  "title": "完成 Node.js 練習",
  "priority": "high",
  "due_date": "2026-10-28"
}

// Response 201:
{
  "task": {
    "id": 1,
    "title": "完成 Node.js 練習",
    "status": "pending",
    "priority": "high",
    "due_date": "2026-10-28",
    "created_at": "2026-10-21T10:00:00Z"
  }
}
```

## 提示

- `authMiddleware.js` 負責從 `Authorization: Bearer <token>` 標頭解析 JWT，並將 `req.user` 設為解碼後的使用者資訊
- 更新/刪除任務前，先查詢 `WHERE id = $1 AND user_id = $2`，確保使用者只能操作自己的資料
- 用 `bcryptjs.hash(password, 10)` 加密，`bcryptjs.compare()` 驗證
- 將 JWT secret 存在 `.env`，不要硬編碼在程式碼中
- 使用 `try/catch` + `next(err)` 將錯誤傳遞給全域錯誤處理 middleware

## 學習重點（跟後端 API 的關聯）

- **資料隔離**：每個使用者只看到自己的任務，這是多租戶 API 的基礎設計模式
- **JWT 無狀態驗證**：伺服器不儲存 session，適合水平擴展的微服務架構
- **分層架構**：Routes → Middleware → DB，職責分明，易於測試與維護
- **統一錯誤格式**：前端可預期地處理所有錯誤，提升 DX（開發者體驗）
- **Joi 驗證**：在資料進入業務邏輯前就攔截不合法輸入，減少 DB 負擔

## 進階挑戰（選做）

1. **分頁功能**：為 `GET /api/tasks` 加入 `?page=1&limit=10` 的分頁支援
2. **軟刪除**：加入 `deleted_at` 欄位，刪除時只標記時間而非真正移除資料
3. **任務統計**：新增 `GET /api/tasks/stats` 端點，回傳各狀態的任務數量統計
4. **重新整理 Token**：實作 Refresh Token 機制，讓 Access Token 短效化（15 分鐘）
5. **Jest 測試**：為 Auth 路由撰寫整合測試，覆蓋成功與失敗情境
