# 第 7 週今日 Node.js 練習題：設計一個書籍管理 REST API

## 題目說明

使用 Express 設計並實作一套符合 REST 原則的書籍管理 API。你將會建立完整的 CRUD（新增、讀取、更新、刪除）端點，並遵守 HTTP 動詞與狀態碼的最佳慣例。

## 技術要求
- 概念：RESTful 路由設計、HTTP 動詞（GET / POST / PUT / PATCH / DELETE）、HTTP 狀態碼、資源命名慣例
- 需要的套件：`express`

## 具體任務

1. 初始化專案，安裝 `express`，建立 `app.js`。
2. 使用記憶體陣列（in-memory array）作為暫時資料庫，儲存書籍資料：
   ```js
   let books = [
     { id: 1, title: '深夜加油站遇見蘇格拉底', author: '丹‧米爾曼', year: 1980 },
     { id: 2, title: '原子習慣', author: '詹姆斯‧克利爾', year: 2018 },
   ];
   ```
3. 實作以下 REST 端點：

   | 方法   | 路徑           | 說明              | 成功狀態碼 |
   |--------|----------------|-------------------|------------|
   | GET    | `/books`       | 取得所有書籍       | 200        |
   | GET    | `/books/:id`   | 取得單本書籍       | 200        |
   | POST   | `/books`       | 新增一本書籍       | 201        |
   | PUT    | `/books/:id`   | 完整更新一本書籍   | 200        |
   | PATCH  | `/books/:id`   | 部分更新一本書籍   | 200        |
   | DELETE | `/books/:id`   | 刪除一本書籍       | 204        |

4. 若找不到對應 `id`，回傳 `404` 與 `{ error: "Book not found" }`。
5. POST 新增時，若缺少 `title` 或 `author`，回傳 `400` 與 `{ error: "title and author are required" }`。
6. 伺服器監聽 port `3000`。

## 範例

```js
// GET /books
// 回應 200
[
  { "id": 1, "title": "深夜加油站遇見蘇格拉底", "author": "丹‧米爾曼", "year": 1980 },
  { "id": 2, "title": "原子習慣", "author": "詹姆斯‧克利爾", "year": 2018 }
]

// POST /books  body: { "title": "駭客與畫家", "author": "保羅‧葛拉罕" }
// 回應 201
{ "id": 3, "title": "駭客與畫家", "author": "保羅‧葛拉罕", "year": null }

// PATCH /books/1  body: { "year": 1984 }
// 回應 200
{ "id": 1, "title": "深夜加油站遇見蘇格拉底", "author": "丹‧米爾曼", "year": 1984 }

// DELETE /books/2
// 回應 204（無 body）

// GET /books/99
// 回應 404
{ "error": "Book not found" }
```

## 提示
- `PUT` 應替換整筆資料（除了 `id`），`PATCH` 只更新傳入的欄位。
- `DELETE` 成功後回傳 `204 No Content`，不需要 body（用 `res.status(204).send()` 或 `res.sendStatus(204)`）。
- 用 `let nextId = 3` 這樣的自動遞增變數來產生新書籍的 id。
- 用 `express.json()` middleware 才能解析 request body。
- 可用 `curl` 或 Postman / Thunder Client 測試 API：
  ```bash
  curl -X POST http://localhost:3000/books \
    -H "Content-Type: application/json" \
    -d '{"title":"駭客與畫家","author":"保羅‧葛拉罕"}'
  ```

## 學習重點（跟後端 API 的關聯）

REST API 是現代後端開發的核心設計模式。學會正確使用 HTTP 動詞與狀態碼，能讓你的 API 直觀且易於維護——前端開發者只要看路徑與方法就能理解意圖。PUT vs PATCH 的差異在大型系統中尤其重要：PATCH 可避免不必要的欄位覆蓋。這套模式直接對應到之後整合資料庫（PostgreSQL）、身份驗證（JWT）時的 controller 層設計。

## 進階挑戰（選做）

1. **查詢字串過濾**：`GET /books?author=詹姆斯` 回傳符合作者關鍵字的書籍。
2. **分頁**：支援 `?page=1&limit=5`，回傳對應範圍的資料與 `{ total, page, limit, data }` 格式。
3. **排序**：支援 `?sort=year&order=asc`，依年份升冪或降冪排列。
4. **路由模組化**：將書籍路由抽離至 `routes/books.js`，在 `app.js` 用 `app.use('/books', booksRouter)` 掛載。
