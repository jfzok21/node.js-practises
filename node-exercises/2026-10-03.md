# 第 13 週今日 Node.js 練習題：即時聊天室 API（WebSocket 實戰）

## 題目說明

打造一個支援多房間的即時聊天室後端服務，整合 **Socket.io**、**Express**、**JWT 身份驗證** 以及 **PostgreSQL 訊息持久化**。使用者需先透過 REST API 登入取得 Token，再以 Token 建立 WebSocket 連線，加入聊天室後即可收發即時訊息。這是貼近真實產品的全端整合實戰。

---

## 技術要求

- **概念：** WebSocket / Socket.io 事件模型、JWT 於 WebSocket 的驗證流程、Room（頻道）管理、訊息廣播、資料持久化
- **需要的套件：**
  - `express`
  - `socket.io`
  - `pg`（PostgreSQL 客戶端）
  - `jsonwebtoken`
  - `bcryptjs`
  - `dotenv`
  - `cors`

## 具體任務

1. **設計資料庫 Schema**
   建立三張資料表：
   ```sql
   CREATE TABLE users (
     id SERIAL PRIMARY KEY,
     username VARCHAR(50) UNIQUE NOT NULL,
     password_hash VARCHAR(255) NOT NULL,
     created_at TIMESTAMP DEFAULT NOW()
   );

   CREATE TABLE rooms (
     id SERIAL PRIMARY KEY,
     name VARCHAR(100) UNIQUE NOT NULL,
     created_by INTEGER REFERENCES users(id),
     created_at TIMESTAMP DEFAULT NOW()
   );

   CREATE TABLE messages (
     id SERIAL PRIMARY KEY,
     room_id INTEGER REFERENCES rooms(id) ON DELETE CASCADE,
     user_id INTEGER REFERENCES users(id) ON DELETE SET NULL,
     content TEXT NOT NULL,
     sent_at TIMESTAMP DEFAULT NOW()
   );
   ```

2. **REST API（Express）**
   - `POST /api/auth/register`：以 `username` + `password` 註冊
   - `POST /api/auth/login`：登入，回傳 JWT
   - `GET /api/rooms`：列出所有聊天室（需要 JWT）
   - `POST /api/rooms`：建立新聊天室（需要 JWT）
   - `GET /api/rooms/:id/messages?limit=50`：取得房間最新 N 筆歷史訊息

3. **Socket.io 伺服器**

   **連線驗證 Middleware：**
   ```js
   io.use((socket, next) => {
     const token = socket.handshake.auth.token;
     // 驗證 JWT，將 user 資訊附加到 socket.data.user
   });
   ```

   **實作下列事件：**
   | 方向 | 事件名稱 | 說明 |
   |------|----------|------|
   | 客戶端 → 伺服器 | `join_room` | 加入指定房間（帶 `roomId`） |
   | 客戶端 → 伺服器 | `leave_room` | 離開指定房間 |
   | 客戶端 → 伺服器 | `send_message` | 傳送訊息（帶 `roomId`、`content`） |
   | 伺服器 → 客戶端 | `new_message` | 廣播新訊息給房間所有成員 |
   | 伺服器 → 客戶端 | `user_joined` | 通知房間有新使用者加入 |
   | 伺服器 → 客戶端 | `error` | 傳送錯誤訊息（例如未授權） |

4. **訊息持久化**
   - 每次收到 `send_message` 事件後，先將訊息寫入 `messages` 資料表，再廣播給房間成員
   - 廣播的訊息格式包含：`{ id, roomId, username, content, sentAt }`

5. **線上人數追蹤（選做基礎）**
   - 用 `socket.io` 的 `rooms` 功能追蹤各房間人數
   - 每次有人 join / leave 時，廣播 `room_stats` 事件更新人數

## 範例

```js
// === 客戶端連線範例（使用 socket.io-client）===

const { io } = require('socket.io-client');

const socket = io('http://localhost:3000', {
  auth: { token: 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...' }
});

// 加入房間
socket.emit('join_room', { roomId: 1 });

// 收到通知
socket.on('user_joined', ({ username }) => {
  console.log(`${username} 已加入聊天室`);
});

// 發送訊息
socket.emit('send_message', { roomId: 1, content: '大家好！' });

// 接收新訊息
socket.on('new_message', (msg) => {
  console.log(`[${msg.username}]: ${msg.content}`);
  // [Alice]: 大家好！
});

// === REST API：取得歷史訊息 ===
// GET /api/rooms/1/messages?limit=20
// Response 200:
// [
//   { "id": 42, "username": "Alice", "content": "大家好！", "sentAt": "2026-10-03T10:00:00Z" },
//   { "id": 43, "username": "Bob", "content": "你好！", "sentAt": "2026-10-03T10:00:05Z" }
// ]
```

---

## 提示

- `socket.join(roomId)` 讓 socket 加入特定房間；`io.to(roomId).emit(...)` 廣播給該房間所有人
- 未通過 JWT 驗證時，在 Middleware 呼叫 `next(new Error('unauthorized'))` 讓客戶端收到 `error` 事件
- 在 `disconnect` 事件中清理狀態，避免記憶體洩漏
- 使用 `socket.data.user` 儲存使用者資訊（比 Map 更乾淨）
- 歷史訊息 API 加上 `ORDER BY sent_at DESC LIMIT $1` 然後在應用層反轉順序

## 學習重點（跟後端 API 的關聯）

| 技術 | 對應真實場景 |
|------|------------|
| Socket.io 房間 | Slack Channel / Discord Server |
| JWT 於 WS 連線 | 無狀態身份驗證延伸到長連線 |
| 廣播 vs 單播 | `io.to(room)` vs `socket.emit()` 的差異 |
| 訊息持久化 | 斷線重連後仍能讀到歷史紀錄 |
| REST + WS 混合 | 大多數現代即時應用的架構模式 |

即時通訊是面試中常見加分題，掌握 Socket.io 架構能讓你的作品集更具說服力。

## 進階挑戰（選做）

1. **已讀回執**：在 `messages` 加 `read_by` 陣列欄位（PostgreSQL `integer[]`），用戶讀取訊息時 emit `message_read` 事件更新
2. **打字中提示**：實作 `typing_start` / `typing_stop` 事件，廣播「Alice 正在輸入...」
3. **私訊（DM）**：一對一聊天房間，命名規則為 `dm_${Math.min(id1,id2)}_${Math.max(id1,id2)}`
4. **附件訊息**：整合 multer，支援上傳圖片後在聊天室分享
5. **Redis Adapter**：安裝 `@socket.io/redis-adapter`，讓多個 Node.js 進程能共享 Socket.io 狀態（水平擴展基礎）
