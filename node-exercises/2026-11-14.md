# 第 19 週今日 Node.js 練習題：部落格 CMS API（Blog CMS API）

## 題目說明

實作一個功能完整的部落格內容管理系統（CMS）後端 API。使用者可以註冊登入、撰寫文章、發表留言，以及透過標籤（tags）分類文章。這個專案整合 Express、JWT 身份驗證、輸入驗證、巢狀資源設計，是一個模擬真實職場後端開發的實戰練習。

---

## 技術要求

- **概念：** REST API 設計、JWT 認證、巢狀路由（nested routes）、關聯資料操作、分頁（pagination）
- **需要的套件：**
  - `express` — HTTP 框架
  - `express-validator` — 輸入驗證
  - `jsonwebtoken` — JWT 簽發與驗證
  - `bcrypt` — 密碼雜湊
  - `uuid` — 產生唯一 ID（或使用 `crypto.randomUUID()`）
  - （選用）`pg` — 若想整合 PostgreSQL；否則使用 JSON 檔案模擬資料庫

---

## 具體任務

### 1. 資料結構設計

定義以下三種資源的資料結構（儲存於記憶體陣列或 JSON 檔案）：

```js
// 使用者
{ id, username, email, passwordHash, createdAt }

// 文章
{ id, title, content, authorId, tags: [], createdAt, updatedAt }

// 留言
{ id, postId, authorId, content, createdAt }
```

### 2. 認證路由 `/auth`

| 方法   | 路徑             | 說明           |
|--------|------------------|----------------|
| POST   | `/auth/register` | 註冊新使用者   |
| POST   | `/auth/login`    | 登入，回傳 JWT |

### 3. 文章路由 `/posts`（需登入才可寫入）

| 方法   | 路徑              | 說明                     |
|--------|-------------------|--------------------------|
| GET    | `/posts`          | 取得文章清單（支援分頁） |
| GET    | `/posts/:id`      | 取得單篇文章             |
| POST   | `/posts`          | 新增文章（需 JWT）       |
| PUT    | `/posts/:id`      | 更新文章（限作者本人）   |
| DELETE | `/posts/:id`      | 刪除文章（限作者本人）   |
| GET    | `/posts?tag=xxx`  | 依標籤篩選文章           |

### 4. 留言路由 `/posts/:postId/comments`

| 方法   | 路徑                             | 說明                   |
|--------|----------------------------------|------------------------|
| GET    | `/posts/:postId/comments`        | 取得該篇文章所有留言   |
| POST   | `/posts/:postId/comments`        | 新增留言（需 JWT）     |
| DELETE | `/posts/:postId/comments/:id`    | 刪除留言（限作者本人） |

### 5. 輸入驗證

所有寫入操作需驗證：
- `title`：必填，長度 1–200 字元
- `content`：必填，長度至少 10 字元
- `tags`：選填，陣列，每個 tag 為字串
- `email`：格式驗證
- `password`：至少 6 個字元

### 6. 錯誤處理

建立統一的錯誤回應格式，並處理以下情境：
- 401 Unauthorized：未提供或無效的 JWT
- 403 Forbidden：嘗試修改他人資源
- 404 Not Found：文章或留言不存在
- 422 Unprocessable Entity：輸入驗證失敗

## 範例

```js
// POST /auth/register
// 請求 Body
{ "username": "alice", "email": "alice@example.com", "password": "secret123" }

// 成功回應 201
{ "message": "註冊成功", "userId": "abc-123" }

// POST /auth/login
// 請求 Body
{ "email": "alice@example.com", "password": "secret123" }

// 成功回應 200
{ "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." }

// GET /posts?tag=nodejs&page=1&limit=5
// 成功回應 200
{
  "posts": [
    { "id": "p1", "title": "我的第一篇文章", "authorId": "abc-123", "tags": ["nodejs", "backend"], ... }
  ],
  "pagination": { "page": 1, "limit": 5, "total": 12 }
}

// POST /posts/:postId/comments（需帶 Authorization: Bearer <token>）
// 請求 Body
{ "content": "這篇文章很有幫助！" }

// 成功回應 201
{ "id": "c99", "postId": "p1", "authorId": "abc-123", "content": "這篇文章很有幫助！", "createdAt": "..." }
```

---

## 提示

- 用 `express.Router()` 分離各路由模組，保持 `app.js` 簡潔。
- 建立 `authMiddleware.js`，驗證 JWT 並將 `req.user` 注入請求物件。
- 分頁可從 `req.query` 取得 `page`（預設 1）與 `limit`（預設 10），計算 `offset = (page - 1) * limit`。
- 標籤篩選：`posts.filter(p => p.tags.includes(tag))`。
- 授權檢查（作者本人）可抽成 helper function，避免重複邏輯。

---

## 學習重點（跟後端 API 的關聯）

- **巢狀路由**：`/posts/:postId/comments` 是 RESTful 設計中描述「從屬資源」的標準模式，真實專案（Discourse、Medium）皆採用此設計。
- **分頁**：所有生產環境的清單 API 都需要分頁，避免一次回傳大量資料拖垮資料庫與前端。
- **授權 vs 認證**：JWT 驗證身份（Authentication），但「只有作者才能刪除自己文章」屬於授權（Authorization），兩者需分開處理。
- **統一錯誤格式**：前端開發者能預測錯誤結構，減少整合溝通成本。

## 進階挑戰（選做）

1. **搜尋功能**：`GET /posts?search=keyword`，對 `title` 與 `content` 做關鍵字搜尋。
2. **文章草稿**：新增 `status: 'draft' | 'published'` 欄位，`GET /posts` 只回傳已發布文章，作者本人可看自己的草稿。
3. **點讚功能**：`POST /posts/:id/like`、`DELETE /posts/:id/like`，回傳文章的點讚總數。
4. **Jest 測試**：為 `POST /auth/register` 和 `GET /posts` 各寫 3 個測試案例（正常流程、缺少欄位、無效 token）。
5. **整合 PostgreSQL**：將記憶體資料庫改為真實 PostgreSQL，使用 `pg` 套件執行 SQL 查詢。
