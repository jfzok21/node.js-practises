# 第 17 週今日 Node.js 練習題：即時聊天室（WebSocket + Node.js）

## 題目說明

使用 Node.js 內建的 `ws` 套件，打造一個支援多人同時上線的**即時聊天室伺服器**。
使用者連線後可選擇暱稱、加入公開頻道，並能即時看到所有人的訊息與上下線通知。
這個練習讓你從 REST 的「request/response」模式，跨入**雙向、持久連線**的 WebSocket 世界。

---

## 技術要求

- **概念**：WebSocket 協定、事件驅動架構、廣播（broadcast）、連線管理、JSON 訊息格式
- **需要的套件**：
  - `ws` — WebSocket 伺服器實作
  - `uuid` — 為每個連線產生唯一 ID（選用）
  - `express`（選用）— 同時提供 HTTP 靜態頁面給簡易前端測試

---

## 具體任務

### 1. 建立 WebSocket 伺服器

```js
// server.js
const { WebSocketServer } = require('ws');
const server = new WebSocketServer({ port: 8080 });
```

伺服器需維護一份線上使用者清單（Map 或 Set），記錄每個 `ws` 連線對應的暱稱。

### 2. 定義訊息格式（JSON）

所有訊息以 JSON 傳遞，用 `type` 欄位區分：

| `type`       | 方向            | 說明                               |
|--------------|-----------------|------------------------------------|
| `join`       | 客戶端 → 伺服器 | 使用者加入，帶暱稱                 |
| `message`    | 客戶端 → 伺服器 | 傳送聊天訊息                       |
| `broadcast`  | 伺服器 → 全體   | 廣播任一訊息（含系統通知與聊天）   |
| `userList`   | 伺服器 → 單一   | 回傳目前線上使用者清單             |
| `error`      | 伺服器 → 單一   | 錯誤訊息（如暱稱已被使用）         |

### 3. 實作以下伺服器邏輯

1. **使用者加入**：收到 `join` 訊息後，檢查暱稱是否重複；若無衝突，記錄並向全體廣播「`xxx 加入聊天室`」，並回傳當前線上清單給新使用者
2. **收到訊息**：收到 `message` 後，向全體（含發送者）廣播，訊息需帶上暱稱與時間戳記
3. **使用者離線**：監聽 `close` 事件，移除該連線並廣播「`xxx 已離開`」
4. **心跳檢測（Ping/Pong）**：每 30 秒向所有連線發送 `ping`，若無 `pong` 回應則主動斷線，避免殭屍連線（zombie connections）

### 4. 專案結構

```
realtime-chat/
├── server.js        # WebSocket 伺服器主程式
├── client.html      # 簡易瀏覽器測試頁（選做）
└── package.json
```

## 範例

```js
// 客戶端送出：加入聊天室
{ "type": "join", "nickname": "Alice" }

// 伺服器廣播給全體：
{ "type": "broadcast", "from": "系統", "text": "Alice 加入聊天室", "timestamp": "2026-10-27T10:00:00.000Z" }

// 伺服器回傳給 Alice：目前線上清單
{ "type": "userList", "users": ["Alice"] }

// 客戶端送出：傳送訊息
{ "type": "message", "text": "大家好！" }

// 伺服器廣播給全體：
{ "type": "broadcast", "from": "Alice", "text": "大家好！", "timestamp": "2026-10-27T10:00:05.000Z" }

// Alice 離線後，伺服器廣播：
{ "type": "broadcast", "from": "系統", "text": "Alice 已離開聊天室", "timestamp": "2026-10-27T10:05:00.000Z" }
```

## 提示

- 用 `ws.readyState === ws.OPEN` 確認連線狀態再發送，避免送訊息給已斷線的 socket
- `wss.clients` 是所有連線的 Set，廣播可用：
  ```js
  wss.clients.forEach(client => {
    if (client.readyState === client.OPEN) client.send(JSON.stringify(msg));
  });
  ```
- 用 `Map` 儲存 `ws → nickname` 的對應關係，離線時能快速找到暱稱
- 心跳實作：在每個 `ws` 上設 `isAlive = true`，`pong` 事件時重設為 `true`；定時器發 `ping` 前先檢查，若 `isAlive` 為 `false` 則 `terminate()`

## 學習重點（跟後端 API 的關聯）

| 本週練習                  | 對應實務                                          |
|---------------------------|---------------------------------------------------|
| WebSocket 持久連線        | 即時通知（訂單狀態更新、外送追蹤、股價變動）      |
| 廣播機制                  | 多人協作工具（如 Notion 同步游標、Google Docs）   |
| 連線狀態管理              | 線上/離線指示燈、使用者在線清單                   |
| Ping/Pong 心跳            | 服務穩定性；避免 CDN/負載均衡器強制斷線           |
| JSON 訊息協定設計         | 自訂 WebSocket 協定（type-based message routing） |

WebSocket 是 REST API 的補充，而非替代：適合**頻繁、低延遲、伺服器主動推送**的場景；一般 CRUD 仍以 REST 為主。

## 進階挑戰（選做）

1. **房間（Room）系統**：加入 `room` 欄位，訊息只廣播給同一房間的使用者
2. **私訊（DM）**：支援 `{ "type": "dm", "to": "Bob", "text": "..." }` 點對點訊息
3. **訊息歷史**：用 PostgreSQL 或記憶體陣列儲存最近 50 則訊息，新使用者加入時補發
4. **Express 整合**：同一個 `http.Server` 同時跑 Express（HTTP）與 WebSocket，共用 port 3000
5. **前端頁面**：實作 `client.html`，用瀏覽器原生 `WebSocket` API 連線，顯示聊天介面
