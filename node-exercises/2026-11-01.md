# 第 17 週今日 Node.js 練習題：任務管理 REST API（實戰專案）

## 題目說明

建立一個功能完整的任務管理（Task Manager）REST API，整合資料庫、JWT 身份驗證、輸入驗證、以及錯誤處理。這是一個綜合性實戰專案，融合過去 16 週所學的知識。

## 技術要求
- 概念：REST API 設計、JWT 驗證、資料庫 CRUD、Middleware 鏈、輸入驗證
- 需要的套件：`express`、`jsonwebtoken`、`bcryptjs`、`joi`（或 `express-validator`）、`pg`（或 `sqlite3`）、`dotenv`

## 具體任務

1. **初始化專案**：`npm init -y`，安裝所需套件，建立 `.env` 存放 `JWT_SECRET` 與 DB 連線字串。

2. **設計資料結構**：建立兩張資料表（或記憶體物件陣列模擬）：
   - `users`：`id`, `email`, `password_hash`, `created_at`
   - `tasks`：`id`, `user_id`, `title`, `description`, `status`（`pending`/`in_progress`/`done`）, `due_date`, `created_at`

3. **實作身份驗證路由**：
   - `POST /auth/register`：註冊（密碼用 bcrypt hash 後存入）
   - `POST /auth/login`：登入後回傳 JWT token

4. **實作任務 CRUD 路由**（需驗證 JWT）：
   - `GET    /tasks`：取得目前使用者所有任務（可用 `?status=pending` 過濾）
   - `POST   /tasks`：新增任務
   - `GET    /tasks/:id`：取得單一任務（需確認是該使用者的任務）
   - `PATCH  /tasks/:id`：更新任務（部分更新）
   - `DELETE /tasks/:id`：刪除任務

5. **加入 Middleware**：
   - `authMiddleware`：解析並驗證 JWT，將 `req.user` 注入
   - 輸入驗證 Middleware：確保 `title` 不為空、`status` 為合法值
   - 統一錯誤處理 Middleware（最後一個 middleware）

## 範例

```js
// POST /auth/register
// Request body
{ "email": "user@example.com", "password": "Secret123" }
// Response 201
{ "message": "註冊成功", "userId": 1 }

// POST /auth/login
// Response 200
{ "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." }

// POST /tasks  (Header: Authorization: Bearer <token>)
// Request body
{ "title": "完成報告", "description": "Q4 季報", "due_date": "2026-11-15" }
// Response 201
{ "id": 3, "title": "完成報告", "status": "pending", "due_date": "2026-11-15" }

// PATCH /tasks/3
{ "status": "in_progress" }
// Response 200
{ "id": 3, "title": "完成報告", "status": "in_progress" }
```

## 提示
- 用 `express.Router()` 將 `/auth` 與 `/tasks` 拆成獨立路由檔案（`routes/auth.js`、`routes/tasks.js`）
- `authMiddleware` 放在 `middlewares/auth.js`，在 task router 前統一套用：`app.use('/tasks', authMiddleware, taskRouter)`
- JWT `sign` 時將 `{ userId, email }` 放入 payload，`expiresIn: '7d'`
- `bcrypt.hash(password, 10)` 於註冊時使用，`bcrypt.compare` 於登入時驗證
- 若查無任務或任務不屬於該使用者，回傳 `404`；驗證失敗回傳 `401`；輸入錯誤回傳 `422`

## 學習重點（跟後端 API 的關聯）

這個練習直接模擬真實產品後端的核心架構：
- **多層 Middleware**：認證 → 驗證 → 業務邏輯 → 錯誤處理，這是業界標準流程
- **資源隔離**：每位使用者只能操作自己的任務，防止越權存取（IDOR 漏洞防護）
- **JWT 無狀態驗證**：適合水平擴展的微服務架構
- **部分更新（PATCH）vs 全量更新（PUT）**：節省頻寬，減少欄位覆蓋風險

## 進階挑戰（選做）

- **分頁**：`GET /tasks?page=1&limit=10` 實作 offset-based pagination
- **排序**：`?sort=due_date&order=asc` 動態排序
- **標籤系統**：新增 `tags` 多對多關聯（`task_tags` 中間表）
- **Refresh Token**：實作 access token（15 分鐘）+ refresh token（7 天）雙 token 流程
- **整合測試**：用 Jest + Supertest 撰寫 `POST /auth/login` 與 `GET /tasks` 的整合測試
