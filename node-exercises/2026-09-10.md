# 第 10 週今日 Node.js 練習題：輸入驗證與錯誤處理中介層

## 題目說明

建立一個 Express API，實作完整的輸入驗證與錯誤處理機制。透過自訂 middleware 攔截不合法的請求，並以一致的格式回傳錯誤訊息，模擬真實後端 API 的防護層。

## 技術要求
- 概念：Express middleware、輸入驗證、集中式錯誤處理、HTTP 狀態碼
- 需要的套件：`express`、`joi`（或手動驗證）

## 具體任務

1. 建立 `server.js`，設定 Express 應用程式並掛載 `express.json()`
2. 建立 `POST /users` 路由，接受以下 JSON body：
   ```json
   { "name": "string", "age": number, "email": "string" }
   ```
3. 撰寫驗證 middleware `validateUser`：
   - `name`：必填，長度 2–50 字元
   - `age`：必填，整數，18–120
   - `email`：必填，需符合 email 格式
4. 建立集中式錯誤處理 middleware（四個參數：`err, req, res, next`），統一回傳：
   ```json
   { "success": false, "error": "錯誤訊息", "statusCode": 400 }
   ```
5. 加入 `GET /users/:id` 路由，若 `id` 非數字或小於 1，回傳 422 Unprocessable Entity

## 範例

```js
// 正確請求
POST /users
{ "name": "Alice", "age": 25, "email": "alice@example.com" }
// → 201 { "success": true, "message": "使用者建立成功", "data": { ... } }

// 缺少欄位
POST /users
{ "name": "B" }
// → 400 { "success": false, "error": "age 為必填欄位", "statusCode": 400 }

// age 超出範圍
POST /users
{ "name": "Carol", "age": 15, "email": "carol@example.com" }
// → 400 { "success": false, "error": "age 必須介於 18 到 120 之間", "statusCode": 400 }

// 非數字 id
GET /users/abc
// → 422 { "success": false, "error": "id 必須為正整數", "statusCode": 422 }
```

## 提示

- 驗證 middleware 發現錯誤時，用 `next(new Error('訊息'))` 或自訂 `AppError` 類別傳遞給錯誤處理器
- 可建立 `AppError` 類別擴展 `Error`，加入 `statusCode` 屬性，讓錯誤處理 middleware 能取得正確的 HTTP 狀態碼
- 集中式錯誤處理 middleware **必須** 放在所有路由的後面
- email 驗證可用正則：`/^[^\s@]+@[^\s@]+\.[^\s@]+$/`

## 學習重點

輸入驗證是後端 API 的第一道防線。真實專案中，所有從前端或外部傳入的資料都不可信任，必須在進入業務邏輯前完成驗證。集中式錯誤處理則讓 API 的錯誤格式一致，前端能更容易處理各種異常情況，也讓日後維護更輕鬆。

## 進階挑戰（選做）

1. 改用 `joi` 套件重寫驗證邏輯，比較與手動驗證的差異
2. 加入 `PATCH /users/:id` 路由，支援部分更新（每個欄位變為選填，但如果提供就必須合法）
3. 建立 `asyncHandler` 包裝函式，自動捕捉 async 路由中的 `throw` 並傳給錯誤處理 middleware
4. 記錄所有錯誤到 `error.log` 檔案，包含時間戳記與 request 資訊
