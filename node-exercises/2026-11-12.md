# 第 19 週今日 Node.js 練習題：即時聊天室 API（WebSocket + JWT 驗證）

## 題目說明

建立一個具備 JWT 身份驗證的即時聊天室後端服務，使用者登入後可加入聊天室、發送訊息，並即時接收其他用戶的訊息。這道題整合了前幾週學過的 Express、JWT、REST API、以及本週新增的 WebSocket（`ws` 套件）。

---

## 技術要求

- **概念**：WebSocket、JWT 驗證、事件廣播、訊息持久化（記憶體即可）
- **需要的套件**：
  - `express` — HTTP 路由
  - `ws` — WebSocket 伺服器
  - `jsonwebtoken` — JWT 簽發與驗證
  - `bcryptjs` — 密碼雜湊
  - `uuid` — 訊息 ID 生成

---

## 具體任務

1. **建立 HTTP 路由（REST API）**
   - `POST /register`：使用者註冊（帳號、密碼），密碼以 bcrypt 雜湊後存入記憶體陣列
   - `POST /login`：驗證帳密，回傳 JWT token（有效期 1 小時）
   - `GET /messages`：需攜帶 JWT，回傳最近 50 筆聊天記錄

2. **建立 WebSocket 伺服器**
   - 客戶端升級 WebSocket 連線時，需在 URL query string 帶入 token（`ws://localhost:3000?token=xxx`）
   - 在升級握手階段驗證 JWT；驗證失敗則拒絕連線（HTTP 401）
   - 連線成功後廣播系統訊息：`[系統] <username> 加入了聊天室`

3. **訊息處理**
   - 客戶端傳送 JSON：`{ "type": "message", "content": "Hello!" }`
   - 伺服器儲存訊息（含 `id`、`userId`、`username`、`content`、`timestamp`）
   - 廣播給所有已連線的客戶端：`{ "type": "message", "from": "alice", "content": "Hello!", "timestamp": "..." }`

4. **離線處理**
   - 連線斷開時廣播：`[系統] <username> 離開了聊天室`
   - 從活躍連線列表移除該用戶

5. **錯誤處理**
   - 訊息格式非 JSON → 回傳 `{ "type": "error", "message": "Invalid format" }`
   - content 超過 500 字元 → 回傳 `{ "type": "error", "message": "Message too long" }`

## 範例

```js
// 伺服器啟動
const express = require('express');
const http = require('http');
const { WebSocketServer } = require('ws');
const jwt = require('jsonwebtoken');

const app = express();
const server = http.createServer(app);
const wss = new WebSocketServer({ server });

const JWT_SECRET = 'your_secret_key';
const users = [];       // { id, username, passwordHash }
const messages = [];    // { id, userId, username, content, timestamp }
const clients = new Map(); // ws -> { userId, username }

// WebSocket 升級驗證
wss.on('connection', (ws, req) => {
  const url = new URL(req.url, 'http://localhost');
  const token = url.searchParams.get('token');

  try {
    const payload = jwt.verify(token, JWT_SECRET);
    clients.set(ws, { userId: payload.userId, username: payload.username });

    broadcast({ type: 'system', message: `${payload.username} 加入了聊天室` });

    ws.on('message', (raw) => {
      // TODO: 解析、驗證、儲存、廣播
    });

    ws.on('close', () => {
      broadcast({ type: 'system', message: `${payload.username} 離開了聊天室` });
      clients.delete(ws);
    });

  } catch (err) {
    ws.close(1008, 'Unauthorized');
  }
});

function broadcast(data) {
  const payload = JSON.stringify(data);
  for (const [client] of clients) {
    if (client.readyState === 1) client.send(payload);
  }
}

server.listen(3000, () => console.log('Server running on port 3000'));
```

## 提示

- `ws` 套件的 `WebSocketServer` 可接受 `{ server }` 與 Express 的 HTTP server 共用同一個 port
- WebSocket 握手發生在 HTTP upgrade 之前，`wss.on('connection')` 裡的 `req` 就是原始的 HTTP request，可從 `req.url` 拿 query string
- 若要在 `upgrade` 事件中提前拒絕（返回 401），可以用 `server.on('upgrade', ...)` 配合 socket.write / socket.destroy
- `clients` 用 `Map<WebSocket, userInfo>` 比陣列更方便查詢與刪除

## 學習重點（跟後端 API 的關聯）

| 概念 | 本題對應 | 實際應用 |
|------|----------|----------|
| JWT 驗證 | WebSocket 連線時驗證 token | 任何需要身份識別的 WS 服務 |
| REST + WebSocket 混用 | 同一 port 分流 HTTP / WS | 生產環境常見架構 |
| 廣播模式 | 迭代 `clients` Map 發送 | 通知系統、訂閱推播 |
| 訊息持久化 | 記憶體陣列（可升級為 DB） | 聊天記錄、事件日誌 |
| 連線狀態管理 | on('close') 清理資源 | 防止記憶體洩漏 |

## 進階挑戰（選做）

1. **聊天室分組**：支援多個房間，客戶端可傳 `{ "type": "join", "room": "general" }` 切換房間，訊息只廣播給同房間的用戶
2. **已讀回執**：廣播時記錄每則訊息被哪些 `userId` 已讀，透過 `GET /messages/:id/reads` 查詢
3. **速率限制**：同一用戶每秒最多傳 5 則訊息，超過則回傳錯誤並斷線
4. **持久化升級**：將 `users` 與 `messages` 改為 PostgreSQL（使用 `pg` 套件），讓重啟後資料不遺失
5. **整合測試**：用 Jest + `ws` 套件模擬客戶端，測試連線驗證、廣播、斷線等行為
