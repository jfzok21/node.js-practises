# 第 6 週今日 Node.js 練習題：自訂 CORS Middleware

## 題目說明

跨來源資源共享（CORS, Cross-Origin Resource Sharing）是瀏覽器的安全機制，防止前端網頁向不同網域的 API 發送請求。本題要求你不使用任何第三方套件，純手工實作一個完整的 CORS middleware，並處理包含「預檢請求（Preflight）」的情境。

## 技術要求

- 概念：CORS 原理、HTTP OPTIONS 方法、Preflight Request、`Origin` / `Access-Control-*` headers、Express middleware
- 需要的套件：`express`（`npm install express`）

## 具體任務

1. **建立 `corsMiddleware.js`**，實作並匯出一個 `createCors(options)` 工廠函式：
   - 接受選項物件 `{ allowedOrigins, allowedMethods, allowedHeaders, maxAge }`
     - `allowedOrigins`：允許的來源陣列，例如 `['http://localhost:5173', 'https://myapp.com']`，傳入 `'*'` 表示允許所有來源
     - `allowedMethods`：允許的 HTTP 方法陣列，例如 `['GET', 'POST', 'PUT', 'DELETE']`
     - `allowedHeaders`：允許的請求 headers 陣列，例如 `['Content-Type', 'Authorization']`
     - `maxAge`：Preflight 快取秒數，例如 `86400`（1 天）
   - 回傳一個 Express middleware 函式 `(req, res, next) => {}`

2. **實作 CORS 邏輯**：
   - 讀取 `req.headers.origin`
   - 若 `allowedOrigins` 為 `'*'`，回應 header 加上 `Access-Control-Allow-Origin: *`
   - 若 `allowedOrigins` 為陣列，且請求的 `Origin` 在其中，回應 header 加上 `Access-Control-Allow-Origin: <origin>`，並加上 `Vary: Origin`
   - 若來源不被允許，直接回傳 HTTP 403 與 JSON `{ "error": "CORS policy: Origin not allowed" }`
   - 對所有合法請求加上：
     - `Access-Control-Allow-Methods`：allowedMethods 的逗號分隔字串
     - `Access-Control-Allow-Headers`：allowedHeaders 的逗號分隔字串

3. **處理 Preflight 請求（OPTIONS method）**：
   - 若 `req.method === 'OPTIONS'`，在加上上述 headers 後，額外加上：
     - `Access-Control-Max-Age: <maxAge>`
   - 回傳 HTTP 204（No Content），**不呼叫 `next()`**

4. **建立 `app.js`**，監聽 port 3000，並設定以下場景：
   - 全域套用 CORS middleware，`allowedOrigins: ['http://localhost:5173']`
   - `GET /api/data` → 回傳 `{ "items": ["蘋果", "香蕉", "芒果"] }`
   - `POST /api/data` → 讀取 `req.body.name`，回傳 `{ "created": true, "name": "<name>" }`
   - 另外建立 `GET /api/public`，套用允許所有來源（`'*'`）的 CORS middleware

5. **實作全域錯誤處理 middleware**。

## 範例

```js
// corsMiddleware.js 用法範例
const createCors = require('./corsMiddleware');

// 嚴格模式：只允許特定來源
const strictCors = createCors({
  allowedOrigins: ['http://localhost:5173', 'https://myapp.com'],
  allowedMethods: ['GET', 'POST', 'PUT', 'DELETE'],
  allowedHeaders: ['Content-Type', 'Authorization'],
  maxAge: 86400,
});

// 開放模式：允許所有來源
const openCors = createCors({
  allowedOrigins: '*',
  allowedMethods: ['GET'],
  allowedHeaders: ['Content-Type'],
  maxAge: 3600,
});

app.use('/api/data', strictCors);
app.use('/api/public', openCors);

// --- 測試情境 ---

// 1. 合法來源的 Preflight（應回傳 204）
// curl -X OPTIONS http://localhost:3000/api/data \
//   -H "Origin: http://localhost:5173" \
//   -H "Access-Control-Request-Method: POST" -v
// → HTTP 204, Access-Control-Allow-Origin: http://localhost:5173

// 2. 非法來源（應回傳 403）
// curl http://localhost:3000/api/data \
//   -H "Origin: http://evil.com"
// → { "error": "CORS policy: Origin not allowed" }

// 3. 開放端點（任意來源均可）
// curl http://localhost:3000/api/public \
//   -H "Origin: http://anywhere.io"
// → HTTP 200, Access-Control-Allow-Origin: *
```

## 提示

- Preflight 是瀏覽器在傳送「非簡單請求」（如帶有自訂 header 或使用 PUT/DELETE）前自動發出的探測請求，必須以 204 回應，不帶 body。
- `Vary: Origin` 告訴 CDN 和代理伺服器，此回應依 Origin 不同而不同，避免快取錯誤。
- 使用 `res.setHeader('key', 'value')` 設定回應 header。
- 判斷是否為 Preflight：`req.method === 'OPTIONS'` 且帶有 `Access-Control-Request-Method` header。
- `app.use(express.json())` 要加在 CORS middleware **之後**，才能正確解析 POST body。

## 學習重點（跟後端 API 的關聯）

CORS 是前後端分離架構的必備知識，任何 REST API 一旦被瀏覽器呼叫就需要處理它：

| 情境 | 建議設定 |
|---|---|
| 本地開發（Vite / CRA） | `allowedOrigins: ['http://localhost:5173']` |
| 正式環境 | `allowedOrigins: ['https://yourdomain.com']` |
| 公開 CDN / 靜態資源 API | `allowedOrigins: '*'`（只開 GET） |
| 管理後台 API | 嚴格白名單 + `Authorization` header |

實際專案通常使用 `cors` npm 套件，但理解其底層實作能讓你在遇到奇怪的 CORS 錯誤時迅速定位問題，例如：Preflight 被快取、多重 `Access-Control-Allow-Origin` header 衝突等。

## 進階挑戰（選做）

1. 支援 **正則表達式來源比對**：讓 `allowedOrigins` 也接受 `RegExp` 物件，例如 `/\.myapp\.com$/` 允許所有子網域。
2. 加入 **`credentials` 支援**：當選項設定 `credentials: true` 時，加上 `Access-Control-Allow-Credentials: true`，注意此時 `allowedOrigins` 不能為 `'*'`（應拋錯提示）。
3. 建立一個 `corsReport()` 路由（`GET /cors-debug`），接受任意 `Origin` header 並回傳 CORS 決策報告（是否允許、原因、套用的 headers），方便前端開發者除錯。
