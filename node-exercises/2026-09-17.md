# 第 11 週今日 Node.js 練習題：使用 Multer 實作多種檔案上傳情境

## 題目說明

在後端 API 開發中，檔案上傳是非常常見的功能需求，例如使用者頭像上傳、文件附件、產品圖片等。本週練習將使用 `multer` 中介軟體，實作三種常見的上傳情境：單一檔案、多個檔案、以及混合欄位（文字 + 檔案）上傳，並加入基本的檔案類型與大小驗證。

---

## 技術要求

- **概念**：multipart/form-data、檔案緩衝區（buffer）、磁碟儲存（disk storage）、MIME 類型驗證、限制設定
- **需要的套件**：
  - `express`
  - `multer`
  - （測試工具）`curl` 或 Postman / Insomnia

---

## 具體任務

1. **初始化專案並安裝依賴**
   - `npm init -y`
   - `npm install express multer`
   - 建立 `uploads/` 資料夾（存放上傳的檔案）

2. **設定 Multer 的磁碟儲存引擎**
   - 指定目的地為 `uploads/`
   - 自訂檔案名稱格式：`[時間戳]-[原始檔名]`（避免同名覆蓋）
   - 設定 `fileFilter`，只允許 `image/jpeg`、`image/png`、`application/pdf` 三種類型
   - 設定單一檔案上限為 **5 MB**

3. **建立三個上傳路由**
   - `POST /upload/single` — 接受單一欄位 `avatar`，回傳上傳後的檔案資訊
   - `POST /upload/multiple` — 接受欄位 `photos`，最多 5 個檔案，回傳所有檔案資訊陣列
   - `POST /upload/mixed` — 接受文字欄位 `title`、`description`，加上單一檔案欄位 `attachment`，一併回傳

4. **統一錯誤處理**
   - 捕捉 multer 拋出的錯誤（`MulterError`）並回傳結構化的 JSON 錯誤訊息
   - 捕捉不合法檔案類型，回傳 `400` 並說明原因

5. **驗收測試（用 curl 或 Postman）**
   - 上傳一張 JPG 圖片到 `/upload/single`，確認 `uploads/` 資料夾有新增檔案
   - 上傳超過 5 MB 的檔案，確認收到 `413` 錯誤
   - 上傳 `.txt` 檔案，確認收到 `400` 並提示不支援的類型

## 範例

```js
// server.js 骨架

const express = require('express');
const multer  = require('multer');
const path    = require('path');
const fs      = require('fs');

const app = express();
const UPLOAD_DIR = path.join(__dirname, 'uploads');

// 確保目錄存在
if (!fs.existsSync(UPLOAD_DIR)) fs.mkdirSync(UPLOAD_DIR);

// --- 儲存設定 ---
const storage = multer.diskStorage({
  destination: (req, file, cb) => cb(null, UPLOAD_DIR),
  filename:    (req, file, cb) => {
    const unique = `${Date.now()}-${file.originalname}`;
    cb(null, unique);
  },
});

// --- 檔案類型過濾 ---
const ALLOWED_TYPES = ['image/jpeg', 'image/png', 'application/pdf'];
const fileFilter = (req, file, cb) => {
  if (ALLOWED_TYPES.includes(file.mimetype)) {
    cb(null, true);
  } else {
    cb(new Error(`不支援的檔案類型：${file.mimetype}`), false);
  }
};

const upload = multer({
  storage,
  fileFilter,
  limits: { fileSize: 5 * 1024 * 1024 }, // 5 MB
});

// --- 路由 ---
// 1. 單一檔案
app.post('/upload/single', upload.single('avatar'), (req, res) => {
  if (!req.file) return res.status(400).json({ error: '未收到檔案' });
  res.json({
    message: '上傳成功',
    file: {
      originalName: req.file.originalname,
      savedAs:      req.file.filename,
      size:         req.file.size,
      mimeType:     req.file.mimetype,
    },
  });
});

// 2. 多個檔案（最多 5 個）
app.post('/upload/multiple', upload.array('photos', 5), (req, res) => {
  if (!req.files || req.files.length === 0)
    return res.status(400).json({ error: '未收到任何檔案' });
  res.json({
    message: `成功上傳 ${req.files.length} 個檔案`,
    files: req.files.map(f => ({
      originalName: f.originalname,
      savedAs:      f.filename,
      size:         f.size,
    })),
  });
});

// 3. 混合欄位（文字 + 單一附件）
app.post('/upload/mixed',
  upload.fields([{ name: 'attachment', maxCount: 1 }]),
  (req, res) => {
    res.json({
      message:    '上傳成功',
      title:      req.body.title       ?? '（未提供）',
      description:req.body.description ?? '（未提供）',
      attachment: req.files?.attachment?.[0] ?? null,
    });
  }
);

// --- 統一錯誤處理 ---
app.use((err, req, res, next) => {
  if (err.code === 'LIMIT_FILE_SIZE') {
    return res.status(413).json({ error: '檔案超過 5 MB 上限' });
  }
  if (err.code === 'LIMIT_FILE_COUNT') {
    return res.status(400).json({ error: '超過允許的檔案數量' });
  }
  // 自訂 fileFilter 拋出的錯誤
  return res.status(400).json({ error: err.message });
});

app.listen(3000, () => console.log('伺服器已啟動：http://localhost:3000'));
```

### 測試指令範例

```bash
# 單一上傳
curl -F "avatar=@./photo.jpg" http://localhost:3000/upload/single

# 多檔上傳
curl -F "photos=@./img1.jpg" -F "photos=@./img2.png" http://localhost:3000/upload/multiple

# 混合上傳
curl -F "title=我的文件" -F "description=測試說明" -F "attachment=@./report.pdf" \
     http://localhost:3000/upload/mixed

# 測試大小限制（產生 6 MB 假檔案）
dd if=/dev/urandom of=big.bin bs=1M count=6
curl -F "avatar=@./big.bin" http://localhost:3000/upload/single
```

## 提示

- `multer.diskStorage` 的 `filename` callback 中，`file.originalname` 若包含中文或空白，建議用 `Buffer.from(file.originalname, 'latin1').toString('utf8')` 修正編碼問題。
- 錯誤處理中介軟體需要四個參數 `(err, req, res, next)` 才會被 Express 識別為錯誤處理器。
- 若要在記憶體中處理（不落磁碟），改用 `multer({ storage: multer.memoryStorage() })`，檔案內容會存在 `req.file.buffer`。
- `limits.fileSize` 以 **bytes** 為單位，5 MB = `5 * 1024 * 1024`。

---

## 學習重點（與後端 API 的關聯）

| 概念 | 對應的實際 API 場景 |
|---|---|
| `upload.single()` | 使用者頭像、個人照片上傳 |
| `upload.array()` | 產品多張圖片、相簿批量上傳 |
| `upload.fields()` | 表單同時送出文字資料與附件（如履歷表） |
| `fileFilter` + `limits` | API 的輸入驗證層，防止惡意或錯誤格式的請求 |
| `MulterError` 處理 | 統一錯誤回應格式，讓前端能正確顯示錯誤訊息 |

檔案上傳通常與資料庫操作結合：成功儲存到磁碟後，把檔案路徑（或雲端 URL）寫入資料庫，形成完整的「上傳 → 儲存路徑 → 查詢回傳」流程。

## 進階挑戰（選做）

1. **改用記憶體儲存 + 串流寫入 S3**
   使用 `multer.memoryStorage()` 取得 buffer，再透過 AWS SDK（`@aws-sdk/client-s3`）的 `PutObjectCommand` 將檔案上傳至 S3 Bucket。

2. **產生縮圖**
   安裝 `sharp`，在儲存原始圖片後，自動產生 `thumbnail-[原始檔名]` 的 150×150 縮圖並一起存入 `uploads/`。

3. **限制每位使用者的每日上傳總量**
   搭配 Express 的 session 或 JWT 識別使用者，在記憶體（或 Redis）中記錄每位使用者當日已上傳的總 bytes，超過 20 MB 時回傳 `429 Too Many Requests`。

4. **斷點續傳（chunked upload）**
   前端將大檔切成多個小片段（chunk），每次 POST 送一片，後端用 `fs.appendFileSync` 依序拼接，全部收齊後回傳完整檔案資訊。
