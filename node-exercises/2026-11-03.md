# 第 18 週今日 Node.js 練習題：待辦事項 REST API（含身份驗證與測試）

## 題目說明

建立一個完整的待辦事項（Todo）REST API 服務，整合 Express、JWT 身份驗證、輸入驗證、以及 Jest 單元測試。這個專案將串連你過去幾週所學到的核心後端技術。

---

## 技術要求

- **概念：** REST API 設計、JWT 身份驗證、Middleware、輸入驗證、錯誤處理、Jest 測試
- **需要的套件：**
  - `express`
  - `jsonwebtoken`
  - `bcryptjs`
  - `express-validator`
  - `jest`
  - `supertest`（API 整合測試）

---

## 具體任務

1. **初始化專案**
   - `npm init -y` 並安裝上述套件
   - 建立資料夾結構：`src/routes/`、`src/middlewares/`、`src/controllers/`

2. **實作使用者模組**
   - `POST /api/auth/register`：接受 `username`（至少 3 字元）和 `password`（至少 6 字元），以 `bcryptjs` 雜湊密碼後存入記憶體陣列
   - `POST /api/auth/login`：驗證密碼，成功後回傳 JWT（有效期 1 小時）

3. **實作 JWT Middleware**
   - 建立 `authMiddleware.js`，驗證請求 Header 中的 `Authorization: Bearer <token>`
   - Token 無效或過期時回傳 `401 Unauthorized`

4. **實作 Todo CRUD**
   - 所有路由都需通過 `authMiddleware`
   - `GET /api/todos`：回傳目前登入使用者的所有待辦事項
   - `POST /api/todos`：新增待辦（`title` 必填，`completed` 預設為 `false`）
   - `PUT /api/todos/:id`：更新指定待辦（只能修改自己的）
   - `DELETE /api/todos/:id`：刪除指定待辦（只能刪除自己的）

5. **加入輸入驗證**
   - 使用 `express-validator` 驗證 `register` 與 `POST /api/todos`，錯誤時回傳 `422` 與詳細訊息

6. **撰寫 Jest 測試**
   - 使用 `supertest` 測試以下情境：
     - 未帶 Token 呼叫 `/api/todos` → 回傳 `401`
     - 成功 register + login + 取得 token
     - 用 token 新增、取得、刪除 Todo

---

## 範例

```js
// 成功登入回傳
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}

// 新增 Todo（需帶 Bearer token）
POST /api/todos
Body: { "title": "學習 Node.js" }

// 回傳
{ "id": 1, "title": "學習 Node.js", "completed": false, "userId": 1 }

// 未帶 Token 時
{ "error": "Unauthorized: No token provided" }
```

---

## 提示

- 資料可存在記憶體（陣列），不需要真實資料庫
- JWT secret 可寫死在開發環境，例如 `"dev_secret_key_123"`
- `supertest` 可直接傳入 `app`（不需要真正 listen 一個 port）
- `bcryptjs` 的 `hash` 和 `compare` 是非同步的，記得 `await`

---

## 學習重點（跟後端 API 的關聯）

這道題模擬了真實後端服務的核心架構：
- **Stateless 驗證**（JWT）讓 API 可水平擴展，無需 server-side session
- **Middleware 鏈**實現了關注點分離（authentication vs business logic）
- **輸入驗證前置**能阻擋惡意輸入，避免資料層出錯
- **測試驅動**確保 API 合約穩定，在重構時可快速驗證回歸

---

## 進階挑戰（選做）

- 加入 `refresh token` 機制（短效 access token + 長效 refresh token）
- 將資料層抽象成 `repository` 模式，便於未來替換成真實 DB
- 加入 `rate limiting` middleware（可用 `express-rate-limit`），每個 IP 每分鐘最多 20 次請求
- 使用 `winston` 或 `morgan` 加入 request logging
