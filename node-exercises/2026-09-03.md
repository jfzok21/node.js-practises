# 第 9 週今日 Node.js 練習題：JWT 身份驗證系統

## 題目說明

實作一個具備 JWT（JSON Web Token）身份驗證功能的 Express API。使用者可以註冊、登入，並使用 JWT token 存取受保護的路由。

## 技術要求

- **概念**：JWT 結構（header.payload.signature）、Token 簽發與驗證、Middleware 保護路由、Token 過期處理
- **需要的套件**：`express`、`jsonwebtoken`、`bcryptjs`

## 具體任務

1. 建立 `auth-server.js`，設定 Express 伺服器（port 3000）
2. 建立一個簡單的記憶體用戶資料庫（陣列），儲存 `{ id, username, passwordHash }`
3. 實作 `POST /register` 端點：
   - 接收 `username` 和 `password`
   - 用 `bcryptjs` 對密碼做 hash
   - 將新用戶存入記憶體資料庫
   - 回傳成功訊息
4. 實作 `POST /login` 端點：
   - 驗證帳號密碼
   - 成功後用 `jsonwebtoken` 簽發 JWT，設定過期時間為 1 小時
   - 回傳 `{ token, username }`
5. 建立 `authenticateToken` middleware：
   - 從 `Authorization: Bearer <token>` header 取得 token
   - 驗證 token，失敗回傳 401
   - 成功則將解碼資料附加到 `req.user`，呼叫 `next()`
6. 實作 `GET /profile` 受保護端點：
   - 套用 `authenticateToken` middleware
   - 回傳目前登入用戶的資訊

## 範例

```js
// 1. 先註冊
// POST /register
// Body: { "username": "alice", "password": "secret123" }
// Response: { "message": "用戶 alice 註冊成功" }

// 2. 登入取得 token
// POST /login
// Body: { "username": "alice", "password": "secret123" }
// Response: { "token": "eyJhbGci...", "username": "alice" }

// 3. 使用 token 存取受保護路由
// GET /profile
// Header: Authorization: Bearer eyJhbGci...
// Response: { "username": "alice", "id": 1, "message": "歡迎回來！" }

// 4. 無效 token 的回應
// GET /profile（無 header 或錯誤 token）
// Response 401: { "error": "未授權：請提供有效的 token" }
```

## 提示

- `jwt.sign(payload, secret, { expiresIn: '1h' })` 用來簽發 token
- `jwt.verify(token, secret)` 用來驗證，失敗會丟出例外，需用 try/catch 處理
- `bcrypt.hash(password, saltRounds)` 做密碼 hash，`bcrypt.compare(password, hash)` 做驗證
- JWT secret 建議存在環境變數：`process.env.JWT_SECRET || 'dev-secret'`
- Authorization header 格式：`Bearer <token>`，記得用 `.split(' ')[1]` 取出 token 部分

## 學習重點

JWT 是現代 REST API 最常見的無狀態身份驗證機制。與 Session-Cookie 不同，JWT 讓伺服器不需儲存狀態，每個請求自帶驗證資訊，非常適合：
- **微服務架構**：多個服務共用同一個 secret 即可互相驗證
- **前後端分離**：React/Vue 前端只需在 header 帶 token 即可
- **行動應用**：App 儲存 token，比 Cookie 更靈活

這個練習直接對應實際專案中的 `middleware/auth.js` 模式。

## 進階挑戰（選做）

1. **Refresh Token 機制**：實作 `POST /refresh` 端點，用長效 refresh token 換取短效 access token
2. **登出黑名單**：在記憶體中維護一個撤銷 token 的黑名單，讓用戶可以登出
3. **角色授權**：在 JWT payload 加入 `role` 欄位（`user`/`admin`），建立一個只有 admin 才能存取的端點
4. **Token 自動刷新**：若 token 剩餘時間少於 10 分鐘，在回應 header 中自動附上新 token
