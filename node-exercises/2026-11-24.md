# 第 21 週今日 Node.js 練習題：WebSocket 即時聊天室後端

## 題目說明

使用 Node.js 的 `ws` 套件建立一個即時聊天室後端伺服器。WebSocket 讓伺服器與客戶端之間維持持久雙向連線，不需要客戶端不斷輪詢，非常適合聊天、通知、即時協作等應用場景。本題將帶你從 HTTP 升級到 WebSocket 協定，實作訊息廣播與房間管理。

## 技術要求
- 概念：WebSocket 協定、事件驅動架構、廣播（broadcast）、連線管理
- 需要的套件：`ws`、`express`（選用，提供 HTTP 服務與升級端點）

## 具體任務

1. **基本 WebSocket 伺服器**
   - 安裝 `ws` 並建立 WebSocket 伺服器（可搭配 Express HTTP 伺服器）
   - 監聽 `connection` 事件，當有新客戶端連線時印出「新用戶連線」
   - 監聽 `message` 事件接收訊息，並將訊息廣播給所有連線的客戶端

2. **訊息格式與用戶識別**
   - 定義 JSON 訊息格式：`{ type, username, content, timestamp }`
   - 客戶端連線時傳送 `type: "join"` 通知其他人誰加入了
   - 客戶端斷線時傳送 `type: "leave"` 通知其他人

3. **房間（Room）功能**
   - 支援多個聊天房間，訊息只廣播給同房間的用戶
   - 訊息格式加入 `room` 欄位
   - 實作 `type: "join_room"` 切換房間的邏輯

4. **連線清單查詢**
   - 提供一個 HTTP GET `/rooms` 端點，回傳各房間目前的線上人數

## 範例

```js
// 伺服器端 (server.js)
const { WebSocketServer } = require('ws');
const express = require('express');
const http = require('http');

const app = express();
const server = http.createServer(app);
const wss = new WebSocketServer({ server });

// 儲存所有連線：Map<ws, { username, room }>
const clients = new Map();

function broadcast(room, message) {
  const payload = JSON.stringify(message);
  for (const [client, info] of clients.entries()) {
    if (info.room === room && client.readyState === 1) {
      client.send(payload);
    }
  }
}

wss.on('connection', (ws) => {
  clients.set(ws, { username: 'anonymous', room: 'general' });

  ws.on('message', (raw) => {
    const msg = JSON.parse(raw);
    const clientInfo = clients.get(ws);

    if (msg.type === 'join') {
      clients.set(ws, { ...clientInfo, username: msg.username });
      broadcast(clientInfo.room, {
        type: 'system',
        content: `${msg.username} 加入了聊天室`,
        timestamp: Date.now(),
      });
    } else if (msg.type === 'message') {
      broadcast(clientInfo.room, {
        type: 'message',
        username: clientInfo.username,
        content: msg.content,
        timestamp: Date.now(),
      });
    }
  });

  ws.on('close', () => {
    const info = clients.get(ws);
    broadcast(info.room, {
      type: 'system',
      content: `${info.username} 離開了聊天室`,
      timestamp: Date.now(),
    });
    clients.delete(ws);
  });
});

app.get('/rooms', (req, res) => {
  const roomCount = {};
  for (const info of clients.values()) {
    roomCount[info.room] = (roomCount[info.room] || 0) + 1;
  }
  res.json(roomCount);
});

server.listen(3000, () => console.log('伺服器啟動於 port 3000'));

// 客戶端測試 (client.js) — 用 Node.js 模擬
const WebSocket = require('ws');
const ws = new WebSocket('ws://localhost:3000');

ws.on('open', () => {
  ws.send(JSON.stringify({ type: 'join', username: 'Alice' }));
  setTimeout(() => {
    ws.send(JSON.stringify({ type: 'message', content: '大家好！' }));
  }, 500);
});

ws.on('message', (data) => {
  console.log('收到:', JSON.parse(data));
});
```

## 提示
- `ws.readyState === WebSocket.OPEN`（值為 `1`）才能安全地 `send()`
- 廣播時要迭代 `wss.clients` 或自己維護的 Map
- `JSON.parse()` 要包 `try/catch` 防止客戶端傳入非 JSON 字串導致崩潰
- 心跳（heartbeat）機制：定期發送 `ping`，若客戶端無回應則主動關閉連線，防止殭屍連線佔用記憶體
- 測試時可使用 `wscat` CLI 工具：`npx wscat -c ws://localhost:3000`

## 學習重點

**與後端 API 的關聯：**
WebSocket 並不取代 REST API，而是互補。REST 適合「請求—回應」模式（查詢資料、建立資源），WebSocket 適合「持續推送」模式（即時通知、協作編輯、股票報價）。實務上常見架構是：REST API 負責身份驗證與資源管理，WebSocket 連線升級後攜帶 JWT token 驗證身份，只負責即時事件推播。

## 進階挑戰（選做）

- **身份驗證整合**：WebSocket 連線時從 URL query string 或首次訊息中取得 JWT token，驗證後才允許廣播
  ```
  ws://localhost:3000?token=eyJ...
  ```
- **訊息持久化**：每條訊息存入 PostgreSQL，提供 `GET /rooms/:room/history` 查詢歷史訊息
- **心跳機制**：每 30 秒對所有連線發送 `ping`，若 60 秒內無 `pong` 回應則終止連線
- **水平擴展思考**：若部署多台伺服器，不同伺服器上的客戶端無法互相廣播——思考如何用 Redis Pub/Sub 解決這個問題（不需實作，寫出設計思路即可）
