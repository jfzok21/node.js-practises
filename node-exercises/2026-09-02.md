# 第 9 週今日 Node.js 練習題：JWT 身份驗證實作

## 題目說明

建立一個具備 JWT（JSON Web Token）身份驗證機制的 Express API。使用者可以註冊、登入，並透過 JWT token 存取受保護的路由。這是現代 RESTful API 最常見的無狀態身份驗證方式。

## 技術要求
- 概念：JWT 簽發、驗證、中介軟體（middleware）保護路由、token 過期處理
- 需要的套件：`express`、`jsonwebtoken`、`bcryptjs`（或 `bcrypt`）、`dotenv`

## 具體任務

1. **初始化專案**：`npm init -y` 並安裝所需套件，建立 `.env` 存放 `JWT_SECRET` 與 `PORT`。

2. **建立使用者資料儲存**（本次練習用記憶體陣列模擬資料庫）：
   ```js
   const users = []; // { id, username, hashedPassword }
   ```

3. **實作 `POST /auth/register`**：
   - 接收 `username`、`password`
   - 用 `bcryptjs.hash()` 雜湊密碼後存入 `users`
   - 回傳成功訊息（不回傳密碼）

4. **實作 `POST /auth/login`**：
   - 查找使用者，用 `bcryptjs.compare()` 驗證密碼
   - 驗證成功後用 `jwt.sign()` 簽發 token（設定 1 小時過期）
   - 回傳 `{ token }`

5. **建立 JWT 驗證 middleware `authenticateToken`**：
   - 從 `Authorization: Bearer <token>` 標頭取出 token
   - 用 `jwt.verify()` 驗證，失敗回傳 401 或 403
   - 驗證成功將 payload 掛到 `req.user`

6. **實作受保護路由 `GET /profile`**：
   - 套用 `authenticateToken` middleware
   - 回傳 `req.user` 的使用者資訊

## 範例

```js
// .env
JWT_SECRET=my_super_secret_key_change_this
PORT=3000

// 請求流程
// 1. 註冊
POST /auth/register
Body: { "username": "alice", "password": "pass1234" }
Response: { "message": "註冊成功" }

// 2. 登入取得 token
POST /auth/login
Body: { "username": "alice", "password": "pass1234" }
Response: { "token": "eyJhbGci..." }

// 3. 使用 token 存取受保護路由
GET /profile
Headers: { "Authorization": "Bearer eyJhbGci..." }
Response: { "id": 1, "username": "alice" }

// 4. token 無效或過期
GET /profile
Headers: { "Authorization": "Bearer invalid_token" }
Response 403: { "error": "Token 無效或已過期" }
```

## 提示
- `jwt.sign(payload, secret, { expiresIn: '1h' })` 簽發 token
- `jwt.verify(token, secret, callback)` 驗證 token，錯誤物件的 `name` 為 `'TokenExpiredError'` 或 `'JsonWebTokenError'`
- `bcrypt.hash(password, 10)` 雜湊密碼（10 為 salt rounds）
- `bcrypt.compare(plaintext, hash)` 回傳 Promise<boolean>
- 注意：`jwt.sign()` 的 payload 不要放敏感資訊（如密碼），因為 payload 可被解碼

## 學習重點（跟後端 API 的關聯）

JWT 是現代 REST API 身份驗證的基石：
- **無狀態**：伺服器不需儲存 session，適合水平擴展的微服務架構
- **Middleware 模式**：`authenticateToken` 體現了 Express middleware 的可重用性——只要加上它，任何路由都能被保護
- **實際應用**：幾乎所有生產環境的 Node.js API（NestJS、Fastify、Koa）都有類似的 guard/middleware 機制
- **安全考量**：`JWT_SECRET` 必須夠長（至少 256 bits）且絕不能 commit 到版本控制

## 進階挑戰（選做）

1. **Refresh Token 機制**：access token 設定 15 分鐘過期，另外簽發長效 refresh token，實作 `POST /auth/refresh` 換取新的 access token

2. **角色權限（RBAC）**：在 token payload 加入 `role`（`'admin'` / `'user'`），建立 `requireRole(role)` middleware factory，讓某些路由只有 admin 可以存取

3. **登出黑名單**：維護一個記憶體 Set 存放已登出的 token（或其 `jti`），在 middleware 中檢查是否在黑名單內
