# 第 17 週今日 Node.js 練習題：全端任務管理 API（Task Manager API）

## 題目說明

實作一個完整的**任務管理 REST API**，整合你在前 16 週所學的所有技術：Express、PostgreSQL、JWT 身份驗證、輸入驗證、錯誤處理、檔案上傳，以及 Jest 測試。這是一個貼近真實工作場景的後端專案。

---

## 技術要求

- **概念：** REST API 設計、JWT 認證流程、資料庫 CRUD、Middleware 組合、錯誤統一處理、單元測試
- **需要的套件：**

## 具體任務

### 1. 資料庫設計
建立以下兩張資料表（SQL schema）：

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  title VARCHAR(255) NOT NULL,
  description TEXT,
  status VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending', 'in_progress', 'done')),
  due_date DATE,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 2. 建立 Express 應用程式結構

```
task-manager/
├── src/
│   ├── app.js           ← Express 主程式
│   ├── db.js            ← PostgreSQL 連線池
│   ├── routes/
│   │   ├── auth.js      ← POST /api/auth/register, /api/auth/login
│   │   └── tasks.js     ← CRUD /api/tasks
│   ├── middleware/
│   │   ├── auth.js      ← JWT 驗證 middleware
│   │   └── errorHandler.js ← 統一錯誤處理
│   └── validators/
│       └── taskValidator.js ← express-validator 規則
├── tests/
│   ├── auth.test.js
│   └── tasks.test.js
└── package.json
```

### 3. 實作 API 端點

| 方法 | 路徑 | 說明 | 需要 JWT |
|------|------|------|----------|
| `POST` | `/api/auth/register` | 註冊新用戶 | 否 |
| `POST` | `/api/auth/login` | 登入取得 token | 否 |
| `GET` | `/api/tasks` | 取得當前用戶所有任務 | 是 |
| `POST` | `/api/tasks` | 建立新任務 | 是 |
| `GET` | `/api/tasks/:id` | 取得單一任務 | 是 |
| `PUT` | `/api/tasks/:id` | 更新任務 | 是 |
| `DELETE` | `/api/tasks/:id` | 刪除任務 | 是 |

### 4. JWT Middleware 實作要求

每個需要認證的路由，必須：
1. 從 `Authorization: Bearer <token>` header 取得 token
2. 使用 `jwt.verify()` 驗證
3. 將 `req.user` 設定為解碼後的用戶資訊
4. 驗證失敗時回傳 `401 Unauthorized`

### 5. 輸入驗證規則（express-validator）

建立任務時必須驗證：
- `title`：必填，長度 1–255 字元
- `status`：必須是 `pending`、`in_progress`、`done` 之一
- `due_date`：若提供，必須是合法的日期格式

### 6. 撰寫 Jest 測試

至少撰寫以下測試案例：
- 成功註冊用戶
- 登入回傳 JWT token
- 未帶 token 存取受保護路由應得到 401
- 成功建立任務
- 不能存取其他用戶的任務（回傳 403 或 404）

## 範例

```js
// POST /api/auth/login
// 輸入
{
  "email": "user@example.com",
  "password": "mypassword"
}

// 輸出（成功）
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}

// POST /api/tasks（帶 Authorization header）
// 輸入
{
  "title": "完成 Node.js 練習",
  "description": "第 17 週實戰專案",
  "status": "in_progress",
  "due_date": "2026-11-07"
}

// 輸出（成功）
{
  "id": 1,
  "user_id": 3,
  "title": "完成 Node.js 練習",
  "description": "第 17 週實戰專案",
  "status": "in_progress",
  "due_date": "2026-11-07",
  "created_at": "2026-10-31T08:00:00.000Z"
}
```

## 提示

- 用 `bcryptjs.hash(password, 10)` 儲存密碼，絕對不要存明碼
- PostgreSQL 連線池用 `new Pool({ connectionString: process.env.DATABASE_URL })`，不要硬寫憑證
- 統一錯誤處理 middleware 放在所有路由的最後：`app.use(errorHandler)`
- `supertest` 測試時使用 SQLite 或測試資料庫，避免污染正式資料
- 用 `try/catch` + `next(err)` 將非同步錯誤傳給 Express 的錯誤處理

## 進階挑戰（選做）

1. **分頁查詢**：`GET /api/tasks?page=1&limit=10` 支援分頁
2. **篩選與排序**：`GET /api/tasks?status=pending&sort=due_date`
3. **附件上傳**：用 `multer` 讓任務支援上傳圖片或文件
4. **Refresh Token**：實作 `POST /api/auth/refresh` 端點，延長 session
5. **軟刪除**：加入 `deleted_at` 欄位，刪除時只標記不真正刪除
6. **Docker Compose**：用 `docker-compose.yml` 一鍵啟動 app + PostgreSQL
