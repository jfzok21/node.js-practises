# 第 15 週今日 Node.js 練習題：任務管理 REST API（實戰專案）

## 題目說明

建立一個完整的任務管理（Todo List）REST API 後端服務。這個專案將整合你前幾週學到的所有技能，包含 Express、路由設計、Middleware、資料驗證與錯誤處理，打造一個接近生產環境的應用。

---

## 技術要求

- **概念**：REST API 設計、CRUD 操作、資料驗證、錯誤處理、Middleware 串接
- **需要的套件**：
  - `express` — HTTP 框架
  - `express-validator` — 輸入驗證
  - `uuid` — 產生唯一 ID
  - `morgan` — 請求日誌記錄（可選）

---

## 具體任務

1. **初始化專案**
   - `npm init -y`，安裝上述套件
   - 建立以下資料夾結構：
     ```
     task-api/
     ├── src/
     │   ├── routes/
     │   │   └── tasks.js
     │   ├── middleware/
     │   │   └── errorHandler.js
     │   ├── data/
     │   │   └── store.js      ← 以記憶體陣列模擬資料庫
     │   └── app.js
     └── server.js
     ```

2. **實作資料層（`src/data/store.js`）**
   - 以模組內的陣列作為資料儲存
   - 匯出 CRUD 函式：`getAllTasks`、`getTaskById`、`createTask`、`updateTask`、`deleteTask`

3. **實作路由（`src/routes/tasks.js`）**
   完成以下 5 個端點：

   | 方法   | 路徑              | 說明             |
   |--------|-------------------|------------------|
   | GET    | `/api/tasks`      | 取得所有任務     |
   | GET    | `/api/tasks/:id`  | 取得單一任務     |
   | POST   | `/api/tasks`      | 新增任務         |
   | PUT    | `/api/tasks/:id`  | 更新任務（全量） |
   | DELETE | `/api/tasks/:id`  | 刪除任務         |

4. **加入輸入驗證**
   - `title` 必填，長度 1–100 字元
   - `status` 只允許 `"pending"` / `"in-progress"` / `"done"`
   - 驗證失敗時回傳 `400` 含錯誤訊息陣列

5. **實作全域錯誤處理 Middleware**
   - 未找到資源回傳 `404 { error: "Task not found" }`
   - 未知路由回傳 `404 { error: "Route not found" }`
   - 伺服器錯誤回傳 `500 { error: "Internal server error" }`

## 範例

```js
// POST /api/tasks  — 新增任務
// Request body
{
  "title": "閱讀 Node.js 官方文件",
  "status": "pending",
  "description": "重點看 Streams 章節"
}

// Response 201
{
  "id": "a1b2c3d4-...",
  "title": "閱讀 Node.js 官方文件",
  "status": "pending",
  "description": "重點看 Streams 章節",
  "createdAt": "2026-10-14T08:00:00.000Z",
  "updatedAt": "2026-10-14T08:00:00.000Z"
}

// GET /api/tasks?status=pending  — 篩選（進階）
// Response 200
[
  { "id": "...", "title": "...", "status": "pending", ... }
]

// DELETE /api/tasks/不存在的ID
// Response 404
{ "error": "Task not found" }
```

## 提示

- `store.js` 模擬資料庫：用陣列 + 函式封裝，讓路由層不需知道儲存細節。
- 用 `uuid` 的 `v4()` 產生 `id`，用 `new Date().toISOString()` 產生時間戳。
- Express 中 `app.use(express.json())` 要在路由掛載**之前**加，否則 `req.body` 會是 `undefined`。
- 錯誤處理 Middleware 的函式簽名需有 4 個參數 `(err, req, res, next)`，Express 才能識別為錯誤處理器。
- 用 `morgan('dev')` 可快速看到每次請求的方法、路徑與狀態碼，方便除錯。

## 學習重點（跟後端 API 的關聯）

這個練習模擬了真實後端服務的完整架構：

- **分層設計**：路由層（Routes）、資料層（Store）、Middleware 層分離，符合關注點分離原則。
- **RESTful 語意**：正確使用 HTTP 動詞與狀態碼（201 Created、204 No Content、404 Not Found）。
- **輸入驗證**：在資料進入系統前攔截非法輸入，避免壞資料污染儲存層。
- **集中式錯誤處理**：讓錯誤回應格式統一，方便前端解析。

這套模式可以直接套用到日後連接 PostgreSQL 或 MongoDB 的真實專案。

## 進階挑戰（選做）

1. **查詢篩選**：支援 `GET /api/tasks?status=pending` 以 `status` 篩選結果。
2. **分頁**：支援 `?page=1&limit=10` 回傳分頁資料，並在回應中附上 `total`、`page`、`totalPages`。
3. **持久化**：將陣列改為讀寫 `tasks.json` 檔案，讓伺服器重啟後資料不消失。
4. **單元測試**：用 Jest + Supertest 撰寫至少 5 個整合測試，涵蓋正常與錯誤情境。
