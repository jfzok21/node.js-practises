# 第 21 週今日 Node.js 練習題：任務管理 REST API（完整實戰）

## 題目說明

建立一個具備完整 CRUD 功能的任務管理 REST API，整合 JWT 身份驗證、輸入驗證、錯誤處理，以及簡單的資料持久化（使用 JSON 檔案模擬資料庫）。這是一道綜合性的實戰題，涵蓋前幾週所學的所有核心概念。

## 技術要求

- 概念：Express Router、JWT 驗證、middleware 組合、輸入驗證、錯誤處理、fs 模組持久化
- 需要的套件：
  - `express`
  - `jsonwebtoken`
  - `bcryptjs`
  - `express-validator`
  - `uuid`

## 具體任務

1. **初始化專案**
   - 建立 `week21-task-api/` 資料夾並執行 `npm init -y`
   - 安裝所需套件

2. **建立資料儲存層** (`data/users.json`、`data/tasks.json`)
   - 以 JSON 檔案取代資料庫，讀寫使用 `fs.promises`

3. **實作使用者認證路由** (`POST /api/auth/register`、`POST /api/auth/login`)
   - 密碼用 `bcryptjs` hash 後儲存
   - 登入成功回傳 JWT token（有效期 1 小時）

4. **建立 JWT 驗證 middleware** (`middleware/auth.js`)
   - 從 `Authorization: Bearer <token>` 標頭解析並驗證 token
   - 驗證失敗回傳 `401 Unauthorized`

5. **實作任務 CRUD 路由**（所有路由需通過 JWT 驗證）
   - `GET    /api/tasks`         — 取得該使用者所有任務（支援 `?status=pending|done` 篩選）
   - `POST   /api/tasks`         — 建立任務（標題必填、描述選填）
   - `GET    /api/tasks/:id`     — 取得單一任務
   - `PUT    /api/tasks/:id`     — 更新任務（只能修改自己的任務）
   - `DELETE /api/tasks/:id`     — 刪除任務（只能刪除自己的任務）
   - `PATCH  /api/tasks/:id/done` — 將任務標記為完成

6. **加入統一錯誤處理 middleware** (`middleware/errorHandler.js`)
   - 捕捉所有未處理的錯誤，回傳標準格式 `{ error: "...", message: "..." }`

## 範例

```js
// 請求：建立任務
// POST /api/tasks
// Headers: { Authorization: "Bearer <token>" }
// Body:
{
  "title": "準備技術面試",
  "description": "複習 Node.js、資料庫、系統設計"
}

// 回應 201 Created:
{
  "id": "a1b2c3d4-...",
  "title": "準備技術面試",
  "description": "複習 Node.js、資料庫、系統設計",
  "status": "pending",
  "owner": "user123",
  "createdAt": "2026-11-25T08:00:00.000Z"
}

// 請求：篩選已完成任務
// GET /api/tasks?status=done
// 回應 200 OK:
[
  { "id": "...", "title": "...", "status": "done", ... }
]

// 錯誤回應範例（存取他人任務）
// 回應 403 Forbidden:
{
  "error": "Forbidden",
  "message": "您沒有權限操作此任務"
}
```

## 提示

- 用 `uuid` 套件的 `v4()` 產生任務 ID，避免衝突
- 讀寫 JSON 檔案時，記得用 `JSON.parse` / `JSON.stringify`，並處理檔案不存在的情況
- JWT 的 `payload` 可以存入 `{ userId, email }`，讓後續 middleware 直接使用 `req.user`
- 操作任務前先比對 `task.owner === req.user.userId`，防止越權存取
- 可以用 `express-validator` 的 `body('title').notEmpty().trim()` 做輸入驗證

## 學習重點（跟後端 API 的關聯）

| 本題技術 | 實際後端場景 |
|---|---|
| JWT middleware | 所有需登入的 API 都必須驗證身份 |
| 輸入驗證 | 防止惡意輸入與資料格式錯誤 |
| 錯誤處理 middleware | 統一 API 錯誤格式，前端才好處理 |
| 資源授權檢查 | 只允許資源擁有者修改自己的資料 |
| 狀態篩選 (`?status=`) | 實際 API 常見的查詢參數設計 |

將 JSON 檔案換成真實資料庫（PostgreSQL）時，只需修改資料存取層，路由邏輯完全不用動——這就是**關注點分離**的好處。

## 進階挑戰（選做）

1. **分頁功能**：在 `GET /api/tasks` 加入 `?page=1&limit=10` 分頁參數
2. **截止日期**：任務新增 `dueDate` 欄位，提供 `GET /api/tasks/overdue` 路由回傳逾期任務
3. **排序**：支援 `?sortBy=createdAt&order=desc` 讓前端自訂排序
4. **Jest 測試**：為所有路由寫整合測試（使用 `supertest`），包含驗證成功與失敗的情境
5. **Rate Limiting**：使用 `express-rate-limit` 防止暴力破解登入
