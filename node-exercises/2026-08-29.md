# 第 8 週今日 Node.js 練習題：PostgreSQL 資料庫整合 — 用戶管理 CRUD

## 題目說明

建立一個 Node.js 應用程式，透過 `pg`（node-postgres）套件連接 PostgreSQL 資料庫，實作完整的用戶資料 CRUD（Create、Read、Update、Delete）操作，並以函式封裝各項資料庫查詢。

---

## 技術要求

- **概念：** 資料庫連線池（Connection Pool）、SQL 參數化查詢（Parameterized Queries）、async/await 錯誤處理
- **需要的套件：**
  - `pg`（`npm install pg`）
  - `dotenv`（`npm install dotenv`）— 管理資料庫連線設定

---

## 具體任務

1. **建立 `.env` 設定檔**，存放 PostgreSQL 連線資訊（host、port、user、password、database）。

2. **建立 `db.js`**，使用 `pg.Pool` 建立連線池並匯出，供其他模組共用。

3. **建立 `migrations/init.sql`**，包含建立 `users` 資料表的 SQL：
   ```sql
   CREATE TABLE IF NOT EXISTS users (
     id SERIAL PRIMARY KEY,
     name VARCHAR(100) NOT NULL,
     email VARCHAR(150) UNIQUE NOT NULL,
     created_at TIMESTAMP DEFAULT NOW()
   );
   ```

4. **建立 `userRepository.js`**，實作以下四個非同步函式：
   - `createUser(name, email)` — 新增用戶，回傳新建的用戶資料
   - `getAllUsers()` — 取得所有用戶清單
   - `getUserById(id)` — 依 ID 查詢單筆用戶
   - `updateUser(id, name, email)` — 更新用戶資料，回傳更新後的用戶
   - `deleteUser(id)` — 刪除用戶，回傳被刪除的用戶資料

5. **建立 `index.js`**，依序呼叫上述函式並將結果印出，驗證每個操作是否正確。

---

## 範例

```js
// db.js
const { Pool } = require('pg');
require('dotenv').config();

const pool = new Pool({
  host: process.env.DB_HOST,
  port: process.env.DB_PORT,
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
});

module.exports = pool;

// userRepository.js
const pool = require('./db');

async function createUser(name, email) {
  const result = await pool.query(
    'INSERT INTO users (name, email) VALUES ($1, $2) RETURNING *',
    [name, email]
  );
  return result.rows[0];
}

async function getAllUsers() {
  const result = await pool.query('SELECT * FROM users ORDER BY created_at DESC');
  return result.rows;
}

async function getUserById(id) {
  const result = await pool.query('SELECT * FROM users WHERE id = $1', [id]);
  return result.rows[0] || null;
}

async function updateUser(id, name, email) {
  const result = await pool.query(
    'UPDATE users SET name = $1, email = $2 WHERE id = $3 RETURNING *',
    [name, email, id]
  );
  return result.rows[0] || null;
}

async function deleteUser(id) {
  const result = await pool.query('DELETE FROM users WHERE id = $1 RETURNING *', [id]);
  return result.rows[0] || null;
}

module.exports = { createUser, getAllUsers, getUserById, updateUser, deleteUser };

// index.js 執行範例輸出：
// ✅ 建立用戶: { id: 1, name: 'Alice', email: 'alice@example.com', created_at: ... }
// 📋 所有用戶: [ { id: 1, ... } ]
// 🔍 查詢 ID=1: { id: 1, name: 'Alice', ... }
// ✏️  更新 ID=1: { id: 1, name: 'Alice Updated', email: 'new@example.com', ... }
// 🗑️  刪除 ID=1: { id: 1, name: 'Alice Updated', ... }
```

---

## 提示

- `.env` 範例格式：
  ```
  DB_HOST=localhost
  DB_PORT=5432
  DB_USER=postgres
  DB_PASSWORD=yourpassword
  DB_NAME=node_practice
  ```
- 使用 `$1, $2, ...` 參數化查詢，**絕對不要**用字串拼接 SQL，避免 SQL Injection 漏洞。
- `Pool` 比 `Client` 更適合伺服器情境，可自動管理多條連線。
- 若尚未安裝 PostgreSQL，可用 Docker 快速啟動：
  ```bash
  docker run --name pg-practice -e POSTGRES_PASSWORD=yourpassword -p 5432:5432 -d postgres
  ```
- 記得在 `index.js` 結束後呼叫 `pool.end()` 關閉連線，否則程式不會自動結束。

## 學習重點（與後端 API 的關聯）

本週是後端開發的核心里程碑。真實的 REST API（如第 7 週的設計）幾乎都需要一個持久化資料層：

- **Repository Pattern**：將 SQL 查詢封裝在 `userRepository.js` 中，讓 Express 路由層只需呼叫函式，不接觸原始 SQL，提高可維護性與可測試性。
- **Connection Pool**：Web 伺服器同時接受多個請求，Pool 可讓多個 request 共享資料庫連線，避免每次請求都重新建立連線的效能損耗。
- **RETURNING \***：PostgreSQL 的 `RETURNING` 子句讓 INSERT / UPDATE / DELETE 直接回傳受影響的資料列，省去額外的 SELECT 查詢。

## 進階挑戰（選做）

1. **整合 Express**：將 `userRepository.js` 的函式接到 Express 路由，建立完整的 RESTful User API（`GET /users`、`POST /users`、`PUT /users/:id`、`DELETE /users/:id`），結合第 7 週的成果。

2. **Transaction 練習**：建立一個 `transferOperation(fromId, toId, amount)` 函式，模擬「帳戶轉帳」，使用 `BEGIN / COMMIT / ROLLBACK` 確保原子性。

3. **加入輸入驗證**：在 `createUser` 和 `updateUser` 前，驗證 `email` 格式是否合法（使用正規表示式或 `validator` 套件），並在不合法時拋出自訂錯誤。

4. **撰寫測試**：用 Jest + `jest-mock-extended` 或直接 mock `pool.query`，對 `userRepository.js` 的每個函式撰寫單元測試，不需要真實資料庫連線。
