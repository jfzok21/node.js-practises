# 第 7 週今日 Node.js 練習題：設計一個書籍管理 REST API

## 題目說明

使用 Express 建立一套符合 REST 規範的書籍管理 API。這個練習將幫助你理解 RESTful 設計原則，包含資源命名、HTTP 動詞使用、狀態碼回應，以及標準化的 JSON 回應格式。

---

## 技術要求

- **概念**：RESTful 設計原則、HTTP 動詞（GET / POST / PUT / PATCH / DELETE）、HTTP 狀態碼、JSON 回應結構、路由組織
- **需要的套件**：`express`

---

## 具體任務

1. **初始化專案**
   - 建立新資料夾，執行 `npm init -y`
   - 安裝 `express`，建立 `index.js`

2. **定義資料結構（記憶體陣列模擬資料庫）**

   每本書的資料格式如下：
   ```js
   {
     id: 1,
     title: "深入淺出 Node.js",
     author: "朴靈",
     genre: "技術",
     published_year: 2013,
     available: true
   }
   ```
   預先放入至少 3 筆假資料。

3. **實作以下 5 個 REST 端點**

   | 方法     | 路徑              | 說明             |
   |--------|-----------------|----------------|
   | GET    | `/books`        | 取得所有書籍         |
   | GET    | `/books/:id`    | 取得單一書籍         |
   | POST   | `/books`        | 新增一本書          |
   | PUT    | `/books/:id`    | 更新整本書資料        |
   | DELETE | `/books/:id`    | 刪除一本書          |

4. **統一回應格式**

   成功：
   ```json
   { "success": true, "data": { ... } }
   ```
   失敗（例如找不到資源）：
   ```json
   { "success": false, "message": "Book not found" }
   ```

5. **正確使用 HTTP 狀態碼**
   - `200 OK`：查詢、更新、刪除成功
   - `201 Created`：新增成功
   - `404 Not Found`：找不到指定 id 的書籍
   - `400 Bad Request`：缺少必要欄位（title、author）

---

## 範例

```js
// GET /books/1 → 200
{
  "success": true,
  "data": {
    "id": 1,
    "title": "深入淺出 Node.js",
    "author": "朴靈",
    "genre": "技術",
    "published_year": 2013,
    "available": true
  }
}

// GET /books/999 → 404
{
  "success": false,
  "message": "Book not found"
}

// POST /books（body 缺少 title）→ 400
{
  "success": false,
  "message": "title and author are required"
}

// POST /books（正確）→ 201
{
  "success": true,
  "data": {
    "id": 4,
    "title": "JavaScript: The Good Parts",
    "author": "Douglas Crockford",
    "genre": "技術",
    "published_year": 2008,
    "available": true
  }
}
```

---

## 提示

- 使用 `express.json()` middleware 才能解析 POST / PUT 的 request body
- 用 `let nextId = books.length + 1` 來自動遞增 id
- `PUT` 應替換整筆資料；如果只想更新部分欄位，需改用 `PATCH`
- 用 `parseInt(req.params.id)` 轉換 id 為數字，再用 `Array.find()` 找到對應書籍
- 刪除時用 `Array.findIndex()` 找索引，再用 `Array.splice()` 移除

---

## 學習重點（跟後端 API 的關聯）

REST API 是現代後端開發的核心語言——前後端分離、行動 App、第三方串接都依賴它。

| REST 原則           | 實際意義                                   |
|-------------------|----------------------------------------|
| 資源導向 URL          | `/books` 代表「書籍集合」，清晰易懂                 |
| 動詞由 HTTP 方法表達      | 不要寫 `/deleteBook`，用 `DELETE /books/:id` |
| 狀態碼傳達結果           | 前端不用解析訊息文字，直接看狀態碼就知道成功或失敗              |
| 統一回應格式            | 團隊協作時前端可預期資料結構，減少溝通成本                  |

---

## 進階挑戰（選做）

1. **新增 PATCH `/books/:id`**：只更新傳入的欄位（部分更新），未傳入的欄位維持原值
2. **查詢過濾**：`GET /books?genre=技術` 或 `GET /books?available=true` 支援條件篩選
3. **分頁功能**：`GET /books?page=1&limit=2` 回傳分頁結果，並在回應中附上 `total` 和 `totalPages`
4. **資料驗證強化**：`published_year` 必須是合理數字（例如 1800–2026），否則回傳 400
