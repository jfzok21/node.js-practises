# 第 7 週今日 Node.js 練習題：RESTful Todo API 設計與實作

## 題目說明

設計並實作一個符合 REST 規範的 Todo 清單 API。透過本題，你將練習如何設計資源導向的路由結構、正確使用 HTTP 方法與狀態碼，並讓前端或其他服務能夠以標準化方式操作資料。

---

## 技術要求

- **概念**：REST 資源設計、HTTP 方法（GET / POST / PUT / PATCH / DELETE）、HTTP 狀態碼語義、JSON 回應格式
- **需要的套件**：`express`（`npm install express`）

---

## 具體任務

1. **建立 Express 應用程式**，監聽在 port `3000`。
2. **設計以下 5 個 REST 端點**，資料暫存在記憶體陣列中（不需資料庫）：

   | HTTP 方法 | 路由              | 功能               |
   |-----------|-------------------|--------------------|
   | GET       | `/todos`          | 取得所有 Todo 列表 |
   | POST      | `/todos`          | 新增一筆 Todo      |
   | GET       | `/todos/:id`      | 取得單一 Todo      |
   | PUT       | `/todos/:id`      | 完整更新一筆 Todo  |
   | DELETE    | `/todos/:id`      | 刪除一筆 Todo      |

3. **每筆 Todo 的資料結構**：

   ```json
   {
     "id": 1,
     "title": "學習 REST API",
     "completed": false
   }
   ```

4. **正確使用 HTTP 狀態碼**：
   - `200 OK`：成功取得或更新
   - `201 Created`：成功新增
   - `204 No Content`：成功刪除（不回傳 body）
   - `404 Not Found`：找不到指定 id 的資源

5. **新增一個 PATCH 端點**（進階，見下方）讓使用者只更新 `completed` 狀態。

---

## 範例

```js
// GET /todos → 200
[
  { "id": 1, "title": "學習 REST API", "completed": false },
  { "id": 2, "title": "寫測試", "completed": true }
]

// POST /todos  body: { "title": "複習 Express" }  → 201
{ "id": 3, "title": "複習 Express", "completed": false }

// GET /todos/99 → 404
{ "error": "Todo not found" }

// PUT /todos/1  body: { "title": "學習 REST API（更新版）", "completed": true }  → 200
{ "id": 1, "title": "學習 REST API（更新版）", "completed": true }

// DELETE /todos/1 → 204  (no body)
```

---

## 提示

- 使用 `let nextId = 1` 並在每次 POST 時遞增，作為簡易 ID 產生器。
- `PUT` 是**完整替換**：若請求 body 缺少 `title` 或 `completed`，應回傳 `400 Bad Request`。
- 記得在 `app.use(express.json())` 解析請求 body，否則 `req.body` 會是 `undefined`。
- 用 `array.findIndex()` 搭配 id 找到目標項目，若回傳 `-1` 代表找不到。
- 刪除時使用 `array.splice(index, 1)` 移除元素。

---

## 學習重點

REST API 是現代後端開發的核心語言。無論是 Next.js、React 前端，還是行動 App，都透過 REST（或 GraphQL）與後端溝通。掌握：

- **資源命名**（名詞複數 `/todos`，而非動詞 `/getTodo`）
- **HTTP 方法的語義**（GET 不應修改資料）
- **狀態碼的正確使用**（201 vs 200、204 vs 200）

這三點是面試與實際開發中最常被審視的基本功，也是銜接資料庫整合（第 8 週）的必要基礎。

## 進階挑戰（選做）

1. **新增 PATCH `/todos/:id`**：只更新 `completed` 欄位，其餘欄位保持不變。
2. **新增查詢篩選**：`GET /todos?completed=true` 只回傳已完成的項目。
3. **輸入驗證**：若 POST 的 `title` 為空字串或未提供，回傳 `400 Bad Request` 與錯誤訊息。
4. 用 `curl` 或 Postman 測試所有端點，截圖記錄每個請求與回應。
