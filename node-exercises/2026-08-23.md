# 第 7 週今日 Node.js 練習題：巢狀資源路由 — 部落格文章與留言 API

## 題目說明

在 REST API 設計中，當一個資源**從屬於**另一個資源時（例如留言屬於文章），使用**巢狀路由（Nested Routes）**能讓 URL 語意更清晰、層次更分明。本題要求你設計並實作一套「部落格文章 + 留言」的巢狀資源 API，這是後端工程師在設計關聯式資料 API 時最常遇到的結構。

---

## 技術要求

- **概念**：巢狀資源路由、父子資源關係、URL 設計語意、HTTP 狀態碼
- **需要的套件**：`express`（`npm install express`）

---

## 具體任務

### 1. 資料結構

在記憶體中維護兩個陣列：

```js
// 文章（父資源）
const posts = [
  { id: 1, title: "Node.js 入門", author: "Alice", createdAt: "2026-08-23T08:00:00.000Z" },
  { id: 2, title: "REST API 設計原則", author: "Bob", createdAt: "2026-08-23T09:00:00.000Z" }
];

// 留言（子資源，透過 postId 關聯到文章）
const comments = [
  { id: 1, postId: 1, author: "Carol", body: "寫得很清楚！", createdAt: "2026-08-23T10:00:00.000Z" },
  { id: 2, postId: 1, author: "Dave",  body: "感謝分享。",   createdAt: "2026-08-23T11:00:00.000Z" },
  { id: 3, postId: 2, author: "Eve",   body: "很實用的文章", createdAt: "2026-08-23T12:00:00.000Z" }
];
```

---

### 2. 建立以下 REST 路由

#### 文章（頂層資源）

| 方法   | 路由          | 說明             |
|--------|---------------|------------------|
| GET    | `/posts`      | 列出所有文章     |
| GET    | `/posts/:id`  | 取得單一文章     |
| POST   | `/posts`      | 新增文章         |
| DELETE | `/posts/:id`  | 刪除文章（同時刪除所有留言） |

#### 留言（巢狀子資源）

| 方法   | 路由                            | 說明                         |
|--------|---------------------------------|------------------------------|
| GET    | `/posts/:postId/comments`       | 列出指定文章的所有留言       |
| GET    | `/posts/:postId/comments/:id`   | 取得指定文章的單一留言       |
| POST   | `/posts/:postId/comments`       | 在指定文章下新增留言         |
| DELETE | `/posts/:postId/comments/:id`   | 刪除指定文章的指定留言       |

---

### 3. 驗證規則

- 存取留言路由時，若 `postId` 對應的文章不存在 → 回傳 `404`
- 存取單一留言時，若留言的 `postId` 與路由參數不符 → 回傳 `404`（防止跨文章存取）
- 刪除文章時，**連同該文章的所有留言一起刪除**

---

### 4. 統一回應格式

**成功（列表）**：
```json
{
  "success": true,
  "data": [...]
}
```

**成功（單筆或新增）**：
```json
{
  "success": true,
  "data": { "id": 1, "postId": 1, "author": "Carol", "body": "寫得很清楚！", "createdAt": "..." }
}
```

**成功（刪除）**：
```json
{
  "success": true,
  "message": "Deleted successfully"
}
```

**失敗**：
```json
{
  "success": false,
  "error": "Post not found"
}
```

## 範例

```js
// GET /posts/1/comments
// 回應：
{
  "success": true,
  "data": [
    { "id": 1, "postId": 1, "author": "Carol", "body": "寫得很清楚！", "createdAt": "..." },
    { "id": 2, "postId": 1, "author": "Dave",  "body": "感謝分享。",   "createdAt": "..." }
  ]
}

// POST /posts/1/comments
// Body: { "author": "Frank", "body": "學到很多！" }
// 回應 201 Created：
{
  "success": true,
  "data": { "id": 4, "postId": 1, "author": "Frank", "body": "學到很多！", "createdAt": "..." }
}

// GET /posts/99/comments
// 回應 404：
{
  "success": false,
  "error": "Post not found"
}

// GET /posts/2/comments/1   ← 留言 id=1 實際上屬於 postId=1，不是 postId=2
// 回應 404：
{
  "success": false,
  "error": "Comment not found in this post"
}
```

## 提示

- 處理留言路由前，先用一個 helper function 確認 `postId` 是否存在：
  ```js
  function findPost(id) {
    return posts.find(p => p.id === parseInt(id));
  }
  ```
- 刪除文章時記得同步清理留言：
  ```js
  comments = comments.filter(c => c.postId !== parseInt(req.params.id));
  ```
- 巢狀路由的 `postId` 與 `id` 要分清楚，避免混用
- 可嘗試用 `express.Router()` 將兩組路由拆開，再組合

## 學習重點（跟後端 API 的關聯）

| 今日概念             | 真實後端場景                                                      |
|----------------------|-------------------------------------------------------------------|
| 巢狀資源路由         | 訂單 → 訂單項目、課程 → 章節、專案 → 任務                         |
| 父子關聯驗證         | 確保子資源屬於正確的父資源，防止資料洩漏或跨用戶存取              |
| 級聯刪除（Cascade）  | 刪除用戶時同步刪除其所有資料（帖子、留言、訂單等）                 |
| URL 語意設計         | `/users/:id/orders` 比 `/orders?userId=123` 更直覺、更符合 REST   |

## 進階挑戰（選做）

1. **留言計數**：`GET /posts` 的回應中，每篇文章附帶 `commentCount` 欄位
2. **三層巢狀**：在留言下再加「回覆」：`/posts/:postId/comments/:commentId/replies`（思考：三層巢狀是否合適？）
3. **Express Router 拆分**：
   ```
   routes/
     posts.js       → /posts
     comments.js    → /posts/:postId/comments
   ```
4. **PATCH 文章**：允許只更新 `title` 或 `author`，不影響留言
