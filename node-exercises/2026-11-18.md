# 第 20 週今日 Node.js 練習題：即時通知系統（Server-Sent Events）

## 題目說明

實作一個使用 **Server-Sent Events（SSE）** 的即時通知系統。伺服器能主動推送訊息到前端，不需要輪詢（polling）。這是許多後端 API 的重要功能，例如訂單狀態更新、系統警告、即時儀表板等。

## 技術要求

- **概念**：Server-Sent Events（SSE）、Event Emitter、流式回應（Streaming Response）
- **需要的套件**：
  - `express`
  - `events`（Node.js 內建）
  - （選做）`cors`

## 具體任務

1. **建立 SSE 端點** `GET /events`
   - 設定正確的 `Content-Type: text/event-stream` 標頭
   - 保持連線開啟（不能 `res.end()`）
   - 當客戶端斷線時清理資源

2. **建立通知發布端點** `POST /notify`
   - 接收 JSON body：`{ "message": "...", "type": "info|warning|error" }`
   - 透過 EventEmitter 廣播給所有已連線的 SSE 客戶端

3. **管理連線清單**
   - 用陣列或 Map 追蹤所有已連線的 `res` 物件
   - 客戶端斷線（`req.on('close')`）時從清單移除

4. **SSE 訊息格式**
   - 每則訊息須包含 `id`（遞增）、`event` 名稱、`data`（JSON 字串）
   - 格式範例：
     ```
     id: 1
     event: notification
     data: {"message":"Hello","type":"info","timestamp":"2026-11-18T..."}
     
     ```

5. **自動 heartbeat**（選做）
   - 每 15 秒傳送一次 `: ping\n\n` 避免連線逾時

## 範例

```js
// 啟動伺服器後，用兩個終端機測試：

// 終端機 1：訂閱 SSE
// curl -N http://localhost:3000/events

// 終端機 2：發送通知
// curl -X POST http://localhost:3000/notify \
//   -H "Content-Type: application/json" \
//   -d '{"message":"部署完成","type":"info"}'

// 終端機 1 預期輸出：
// id: 1
// event: notification
// data: {"message":"部署完成","type":"info","timestamp":"2026-11-18T10:00:00.000Z"}
```

## 提示

- `res.write()` 而非 `res.send()` — SSE 要持續寫入，不能結束回應
- 每則 SSE 訊息結尾須有**兩個換行** `\n\n`，否則瀏覽器不會觸發事件
- 設定 `res.setHeader('Cache-Control', 'no-cache')` 和 `res.setHeader('Connection', 'keep-alive')`
- 使用 `res.flushHeaders()` 確保標頭立即送出（某些反向代理需要）
- Node.js 的 `EventEmitter` 是廣播的核心：`emitter.on('notify', handler)` / `emitter.emit('notify', data)`

## 學習重點

**跟後端 API 的關聯：**

SSE 是 REST API 的補充方案。傳統 REST 是「客戶端請求 → 伺服器回應」的單向模型；SSE 讓伺服器能主動推送，適合：
- CI/CD 建構進度、部署日誌串流
- 訂單、付款狀態即時更新
- 多用戶協作的即時同步（比 WebSocket 實作更簡單）
- 監控儀表板的 metrics 推送

與 WebSocket 比較：SSE 是單向（伺服器 → 客戶端）、基於 HTTP、自動重連；WebSocket 是雙向但需要額外協議。大多數「推播通知」場景 SSE 就足夠了。

## 進階挑戰（選做）

1. **頻道訂閱**：讓客戶端用 query string `?channel=deploy` 訂閱特定頻道，`POST /notify` 也接受 `channel` 欄位，只廣播給對應頻道的訂閱者
2. **歷史補發**：在 SSE 請求中讀取 `Last-Event-ID` 標頭，將斷線期間錯過的訊息補送給重連的客戶端（需要在記憶體中保留最近 N 則訊息）
3. **連線統計端點** `GET /stats`：回傳目前有多少 SSE 客戶端正在連線、各頻道人數
4. **使用 Redis Pub/Sub**：將 EventEmitter 換成 Redis，讓多個 Node 實例也能同步廣播（水平擴展）
