# 第 12 週今日 Node.js 練習題：用 Jest 測試 Express REST API

## 題目說明

你已經學會了如何設計 REST API、處理錯誤與驗證輸入。本週的重點是為你的 API 撰寫**自動化測試**。你將使用 Jest 和 Supertest 為一個簡單的待辦事項（Todo）API 建立完整的測試套件，涵蓋正常流程與錯誤情境。

---

## 技術要求

- **概念：** 單元測試、整合測試、測試覆蓋率（code coverage）、模擬（mock）、非同步測試
- **需要的套件：**
  - `jest` — 測試框架
  - `supertest` — 對 Express 應用程式發出 HTTP 請求的測試工具
  - `express` — 建立受測的 API

---

## 具體任務

1. **建立受測的 Express 應用程式**
   - 建立 `app.js`，包含以下路由：
     - `GET /todos` → 回傳所有待辦事項
     - `GET /todos/:id` → 回傳單一待辦事項（找不到時回 404）
     - `POST /todos` → 建立新待辦事項（`title` 為必填，缺少時回 400）
     - `DELETE /todos/:id` → 刪除待辦事項（找不到時回 404）
   - **不要**在 `app.js` 中呼叫 `app.listen()`，改由獨立的 `server.js` 啟動，讓測試可以直接 import `app`。

2. **安裝與設定 Jest**
   - 執行 `npm install --save-dev jest supertest`
   - 在 `package.json` 加入測試指令：
     ```json
     "scripts": {
       "test": "jest --coverage"
     }
     ```

3. **撰寫測試檔案 `app.test.js`**
   - 測試 `GET /todos`：應回傳 200 及陣列
   - 測試 `POST /todos`：成功時回 201，缺少 `title` 時回 400
   - 測試 `GET /todos/:id`：存在時回 200，不存在時回 404
   - 測試 `DELETE /todos/:id`：成功時回 200，不存在時回 404
   - 每個測試前用 `beforeEach` 重置資料狀態

4. **執行並確認覆蓋率**
   - 執行 `npm test`，確認所有測試通過
   - 確認 Jest 的 coverage 報告中，`app.js` 的行覆蓋率（Lines）達 **80% 以上**

---

## 範例

```js
// app.js（片段）
const express = require('express');
const app = express();
app.use(express.json());

let todos = [];
let nextId = 1;

app.get('/todos', (req, res) => {
  res.json(todos);
});

app.post('/todos', (req, res) => {
  const { title } = req.body;
  if (!title) {
    return res.status(400).json({ error: 'title 為必填欄位' });
  }
  const todo = { id: nextId++, title, done: false };
  todos.push(todo);
  res.status(201).json(todo);
});

// ... 其他路由

module.exports = app; // 注意：不呼叫 listen()
```

```js
// app.test.js（片段）
const request = require('supertest');
const app = require('./app');

describe('Todo API', () => {
  beforeEach(() => {
    // 重置模組狀態或清空資料（視實作方式而定）
  });

  test('GET /todos 應回傳空陣列', async () => {
    const res = await request(app).get('/todos');
    expect(res.statusCode).toBe(200);
    expect(Array.isArray(res.body)).toBe(true);
  });

  test('POST /todos 缺少 title 應回傳 400', async () => {
    const res = await request(app).post('/todos').send({});
    expect(res.statusCode).toBe(400);
    expect(res.body).toHaveProperty('error');
  });

  test('GET /todos/:id 不存在應回傳 404', async () => {
    const res = await request(app).get('/todos/9999');
    expect(res.statusCode).toBe(404);
  });
});
```

---

## 提示

- **分離 app 與 server**：`app.js` 只負責定義路由、export `app`；`server.js` 才呼叫 `app.listen(port)`。這樣 Supertest 才能在不啟動真實 server 的情況下執行測試。
- **重置狀態**：若 `todos` 陣列是模組層級的變數，每次測試前需重置（可匯出一個 `resetTodos()` 函式，或用 `jest.resetModules()` 重新載入模組）。
- **非同步測試**：測試函式加上 `async/await`，否則 Supertest 的 Promise 不會被正確等待。
- **describe 分組**：用 `describe` 將相關測試包在一起，讓報告更易讀。
- **`--coverage` 旗標**：會在 `coverage/` 目錄產生 HTML 報告，可用瀏覽器開啟檢視哪些行尚未被測試覆蓋。

## 學習重點

**與後端 API 的關聯：**

自動化測試是生產級後端服務的核心實踐。在真實專案中：
- **整合測試（Supertest）** 驗證路由邏輯、HTTP 狀態碼、回應格式，等同於模擬前端或外部服務對 API 的呼叫。
- **覆蓋率報告** 讓你一眼看出哪些錯誤路徑（如 404、400）尚未被驗證，降低上線後才發現 bug 的風險。
- 養成「寫功能、寫測試」的習慣，未來加上 CI/CD 流程後，每次 push 都能自動驗證 API 是否正常，防止回歸（regression）。

## 進階挑戰（選做）

1. **Mock 外部依賴**：將 `todos` 改為從 JSON 檔案讀取，並用 `jest.mock('fs')` 模擬檔案系統，測試讀寫失敗的情境。
2. **測試 Middleware**：為你的 API 加入一個 `requestLogger` middleware，並撰寫測試驗證它確實被呼叫（使用 `jest.fn()` spy）。
3. **參數化測試**：使用 `test.each` 一次測試多組輸入，例如各種非法的 `title` 值（空字串、數字、null）。
4. **整合資料庫測試**：將 `todos` 改存入 SQLite（使用 `better-sqlite3`），並在測試前建立測試資料庫，測試後自動清除。
