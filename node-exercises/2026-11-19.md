# 第 20 週今日 Node.js 練習題：API 速率限制與安全加固

## 題目說明

實作一個具備**速率限制（Rate Limiting）**與**安全強化（Security Hardening）**的 Express API。真實的生產環境後端不能放任所有請求通行——需要防範暴力破解、DDoS 攻擊、敏感資訊洩漏等威脅。這個練習整合常見的 Express 安全中介軟體，讓你的 API 更接近職場標準。

## 技術要求

- **概念**：Rate Limiting、Security Headers、CORS 管控、API Key 驗證、請求記錄
- **需要的套件**：
  - `express`
  - `express-rate-limit`（速率限制）
  - `helmet`（安全標頭）
  - `cors`（跨來源管控）
  - `express-validator`（輸入驗證）
  - `morgan`（請求記錄，選做）

## 具體任務

### 1. 安裝與初始化

```bash
npm init -y
npm install express express-rate-limit helmet cors express-validator morgan
```

### 2. 設定全域安全中介軟體

套用 `helmet` 自動設定安全標頭（如 `X-Content-Type-Options`、`X-Frame-Options`、`Strict-Transport-Security`），並限制 CORS 只允許特定來源：

```js
app.use(helmet());
app.use(cors({ origin: ['http://localhost:3000'] }));
```

### 3. 實作三層速率限制

| 層級 | 路由 | 限制 |
|------|------|------|
| 全域 | 全部 | 每 IP 每 15 分鐘 100 次 |
| 嚴格 | `POST /auth/*` | 每 IP 每 15 分鐘 10 次 |
| API Key | `GET /api/*` | 每 API Key 每分鐘 30 次 |

### 4. 實作 API Key 驗證中介軟體

建立 `middleware/apiKey.js`：
- 從 `x-api-key` 標頭讀取金鑰
- 對照有效金鑰清單（可用 `Map` 或 `.env` 模擬）
- 無效或缺少時回傳 `401 Unauthorized`

### 5. 建立受保護端點

```
POST /auth/login       ← 嚴格速率限制，驗證帳密格式
GET  /api/data         ← 需要 API Key + API 速率限制
GET  /api/profile      ← 需要 API Key
GET  /health           ← 公開，不限速（監控用）
```

### 6. 輸入驗證

在 `POST /auth/login` 使用 `express-validator` 驗證：
- `email`：必填、格式正確
- `password`：必填、最少 8 字元

## 範例

```js
// middleware/apiKey.js
const VALID_KEYS = new Map([
  ['key-abc-123', { owner: 'client-A', tier: 'standard' }],
  ['key-xyz-789', { owner: 'client-B', tier: 'premium' }],
]);

module.exports = (req, res, next) => {
  const key = req.headers['x-api-key'];
  if (!key || !VALID_KEYS.has(key)) {
    return res.status(401).json({ error: 'Invalid or missing API key' });
  }
  req.apiClient = VALID_KEYS.get(key);
  next();
};
```

```js
// 嚴格速率限制（登入用）
const { rateLimit } = require('express-rate-limit');

const authLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,
  max: 10,
  message: { error: 'Too many login attempts, please try again later.' },
  standardHeaders: true,  // 回傳 RateLimit-* 標頭
  legacyHeaders: false,
});

app.use('/auth', authLimiter);
```

```bash
# 測試速率限制（超過後應收到 429）
for i in $(seq 1 12); do
  curl -s -o /dev/null -w "%{http_code}\n" \
    -X POST http://localhost:3000/auth/login \
    -H "Content-Type: application/json" \
    -d '{"email":"test@example.com","password":"password123"}'
done
```

## 提示

- `express-rate-limit` 預設以 IP 為鍵，可透過 `keyGenerator` 改為 API Key
- `helmet()` 已是最佳實踐，直接用預設值即可；個別標頭可用 `helmet.contentSecurityPolicy(...)` 細調
- 速率限制超過時，HTTP 狀態碼應為 **429 Too Many Requests**
- 在開發環境可將限制調高（`process.env.NODE_ENV !== 'production'`），避免頻繁觸發

## 學習重點

**跟後端 API 的關聯：**
- 速率限制是防止帳號暴力破解與 DDoS 的第一道防線
- `helmet` 設定的安全標頭可防止 XSS、點擊劫持（Clickjacking）
- CORS 管控確保只有授權的前端網域能呼叫 API
- API Key 管理是 B2B 或第三方整合常見的認證方案（比 JWT 更適合機器對機器）
- 速率限制回傳的 `RateLimit-Remaining` 標頭讓客戶端能自我調節請求頻率

## 進階挑戰（選做）

1. **Redis 儲存計數器**：將速率限制的計數器從記憶體改為 Redis，使多台伺服器能共享狀態（使用 `rate-limit-redis`）
2. **動態黑名單**：當同一 IP 在 5 分鐘內觸發速率限制超過 3 次，自動封鎖 1 小時
3. **不同 Tier 不同限制**：`standard` API Key 每分鐘 30 次，`premium` 每分鐘 100 次
4. **安全事件記錄**：將所有 401／429 回應寫入結構化 JSON 日誌，方便 SIEM 分析
