# 第 20 週今日 Node.js 練習題：任務管理 API 完整實作

## 題目說明

綜合前 19 週所學，從零開始建立一個功能完整的「任務管理系統（Task Manager API）」。
系統需要具備使用者身份驗證、任務 CRUD、附件上傳、輸入驗證與完整的錯誤處理。

---

## 技術要求

- **概念：** Express、REST API、JWT 驗證、PostgreSQL、Multer 檔案上傳、Jest 測試、輸入驗證
- **需要的套件：**
  - `express`
  - `pg`（或 `knex`）
  - `jsonwebtoken`
  - `bcrypt`
  - `multer`
  - `joi`（或 `express-validator`）
  - `jest`、`supertest`

---

## 具體任務

1. **初始化專案**
   - `npm init -y`，安裝所有必要套件
   - 建立 `.env`（`PORT`、`DATABASE_URL`、`JWT_SECRET`）
   - 建立資料夾結構：`routes/`、`controllers/`、`middlewares/`、`models/`、`tests/`

2. **設定 PostgreSQL**
   建立兩張資料表：
   ```sql
   CREATE TABLE users (
     id SERIAL PRIMARY KEY,
     email VARCHAR(255) UNIQUE NOT NULL,
     password_hash TEXT NOT NULL,
     created_at TIMESTAMPTZ DEFAULT NOW()
   );

   CREATE TABLE tasks (
     id SERIAL PRIMARY KEY,
     user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
     title VARCHAR(255) NOT NULL,
     description TEXT,
     status VARCHAR(50) DEFAULT 'pending', -- pending | in_progress | done
     attachment_url TEXT,
     created_at TIMESTAMPTZ DEFAULT NOW()
   );
   ```

3. **實作身份驗證路由**
   - `POST /auth/register`：註冊（email + password，以 bcrypt hash 密碼）
   - `POST /auth/login`：登入，回傳 JWT（有效期 24 小時）

4. **實作任務 CRUD（需要 JWT 中介層保護）**
   - `GET    /tasks`         ：列出目前使用者的所有任務（支援 `?status=` 篩選）
   - `POST   /tasks`         ：建立任務
   - `GET    /tasks/:id`     ：取得單一任務
   - `PUT    /tasks/:id`     ：更新任務
   - `DELETE /tasks/:id`     ：刪除任務

5. **實作附件上傳**
   - `POST /tasks/:id/attachment`：使用 Multer 上傳圖片（限 jpg/png，最大 5MB）
   - 將檔案儲存於 `uploads/` 資料夾，並更新資料庫中的 `attachment_url`

6. **輸入驗證**
   - 建立任務時，`title` 為必填且不可超過 255 字元
   - 狀態只允許 `pending`、`in_progress`、`done`

7. **撰寫測試（Jest + Supertest）**
   - 測試 `POST /auth/register`（成功、重複 email）
   - 測試 `POST /tasks`（有 token、無 token）
   - 測試 `GET /tasks?status=done`

## 範例

```js
// POST /auth/login 成功回應
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}

// POST /tasks 請求（帶 Authorization: Bearer <token>）
{
  "title": "準備技術面試",
  "description": "複習 Node.js、SQL、系統設計",
  "status": "in_progress"
}

// GET /tasks?status=in_progress 回應
{
  "tasks": [
    {
      "id": 3,
      "title": "準備技術面試",
      "status": "in_progress",
      "attachment_url": null,
      "created_at": "2026-11-20T08:00:00.000Z"
    }
  ]
}
```

## 提示

- 將 JWT 驗證邏輯抽成獨立的 `middlewares/auth.js`，所有需要登入的路由都使用它
- 使用 `req.user.id`（從 JWT payload 解碼）確保使用者只能操作自己的任務
- Multer 的 `fileFilter` 可用來限制副檔名；`limits.fileSize` 限制大小
- 測試時用 `supertest` 的 `.set('Authorization', 'Bearer ' + token)` 帶入 token
- 使用 `process.env.NODE_ENV === 'test'` 切換測試用資料庫，避免污染正式資料

## 進階挑戰（選做）

- **分頁**：`GET /tasks` 加上 `?page=1&limit=10`，回應包含 `total`、`page`、`totalPages`
- **軟刪除**：加入 `deleted_at` 欄位，刪除時只設時間戳而非真的刪掉
- **Rate Limiting**：使用 `express-rate-limit` 限制登入端點每分鐘最多 5 次
- **Docker Compose**：撰寫 `docker-compose.yml`，一指令啟動 Node.js + PostgreSQL
