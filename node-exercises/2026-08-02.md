# 第 4 週今日 Node.js 練習題：打造靜態檔案伺服器

## 題目說明

前兩次練習你已經能手動分派路由、處理 JSON 資料。今天要跨出一步：結合 Week 2 學過的 `fs` 模組，讓 HTTP 伺服器真正能**從硬碟讀取並回傳檔案**——這正是 Nginx / Apache 最基礎的工作，也是 Express 的 `express.static()` 底層做的事。

## 技術要求

- 概念：`fs.readFile`、MIME Type 對應、串流（`fs.createReadStream`）、`path` 模組、404 / 500 錯誤處理
- 需要的套件：無（僅使用 Node.js 內建模組：`http`、`fs`、`path`）

## 具體任務

1. 建立一個 `public/` 資料夾，放入以下三個測試檔案：
   - `public/index.html`：任意 HTML 內容（例如 `<h1>Hello from Static Server!</h1>`）
   - `public/style.css`：任意 CSS（例如 `body { background: #f0f0f0; }`）
   - `public/data.json`：任意 JSON（例如 `{"status": "ok"}`）

2. 建立 `server.js`，監聽 **port 3000**，實作以下邏輯：
   - 將 `req.url` 的路徑對應到 `public/` 目錄下的檔案（`/` 自動對應到 `index.html`）
   - 根據副檔名設定正確的 `Content-Type`（參見下表）
   - 使用 `fs.createReadStream()` 串流回傳檔案內容（比 `readFile` 更省記憶體）
   - 找不到檔案時回傳 **404**，其他讀取錯誤回傳 **500**

3. MIME Type 對應表（至少實作這四種）：

   | 副檔名 | Content-Type |
   |--------|-------------|
   | `.html` | `text/html; charset=utf-8` |
   | `.css` | `text/css; charset=utf-8` |
   | `.js` | `text/javascript` |
   | `.json` | `application/json` |

4. 防止**路徑穿越攻擊**：確認解析後的路徑仍在 `public/` 目錄內，否則回傳 403。

## 範例

```js
// server.js

const http = require('http');
const fs   = require('fs');
const path = require('path');

const PUBLIC_DIR = path.join(__dirname, 'public');

const MIME_TYPES = {
  '.html': 'text/html; charset=utf-8',
  '.css':  'text/css; charset=utf-8',
  '.js':   'text/javascript',
  '.json': 'application/json',
};

const server = http.createServer((req, res) => {
  // 1. 決定對應的檔案路徑
  let urlPath = req.url === '/' ? '/index.html' : req.url;
  const filePath = path.join(PUBLIC_DIR, urlPath);

  // 2. 防路徑穿越：確認 filePath 在 PUBLIC_DIR 內
  if (!filePath.startsWith(PUBLIC_DIR + path.sep) && filePath !== PUBLIC_DIR) {
    res.writeHead(403, { 'Content-Type': 'text/plain' });
    res.end('403 Forbidden');
    return;
  }

  // 3. 取得 MIME Type
  const ext = path.extname(filePath);
  const contentType = MIME_TYPES[ext] || 'application/octet-stream';

  // 4. 串流回傳檔案
  const stream = fs.createReadStream(filePath);

  stream.on('error', (err) => {
    if (err.code === 'ENOENT') {
      res.writeHead(404, { 'Content-Type': 'text/plain' });
      res.end('404 Not Found');
    } else {
      res.writeHead(500, { 'Content-Type': 'text/plain' });
      res.end('500 Internal Server Error');
    }
  });

  // 5. 先送出 header，再 pipe 串流
  res.writeHead(200, { 'Content-Type': contentType });
  stream.pipe(res);
});

server.listen(3000, () => {
  console.log('靜態檔案伺服器啟動：http://localhost:3000');
});
```

```bash
# 建立測試檔案
mkdir -p public
echo '<h1>Hello from Static Server!</h1>' > public/index.html
echo 'body { background: #f0f0f0; }' > public/style.css
echo '{"status": "ok"}' > public/data.json

# 啟動伺服器
node server.js

# 測試
curl http://localhost:3000/            # => HTML 內容
curl http://localhost:3000/style.css   # => CSS 內容
curl http://localhost:3000/data.json   # => JSON 內容
curl http://localhost:3000/missing.txt # => 404 Not Found

# 測試路徑穿越（應回傳 403）
curl "http://localhost:3000/../package.json"
```

## 提示

- `path.join()` 會自動處理 `..`，但仍須用 `startsWith(PUBLIC_DIR)` 確認最終路徑沒有跳出目錄
- `fs.createReadStream(filePath)` 回傳一個 Readable Stream，監聽 `'error'` 事件才能捕捉「找不到檔案」的錯誤（因為 stream 是惰性的，錯誤在 open 時才會發生）
- `stream.pipe(res)` 會自動把資料一片一片送進 `res`，且在 stream 結束時自動呼叫 `res.end()`——所以不需要手動呼叫
- `res.writeHead()` 必須在 `stream.pipe(res)` **之前**呼叫，因為 header 一旦開始發送就無法修改

## 學習重點

（跟後端 API 的關聯）

| 本週學到的 | 對應框架 / 實務概念 |
|-----------|-------------------|
| `fs.createReadStream().pipe(res)` | Express `res.sendFile()`、Nginx 靜態檔案服務的精髓 |
| MIME Type 對應表 | 瀏覽器根據 `Content-Type` 決定如何渲染（HTML 顯示、JS 執行、圖片預覽） |
| 路徑穿越防護 | OWASP Top 10 之一：Path Traversal（目錄穿越漏洞） |
| `stream.pipe()` | Node.js Stream 的核心模式，大檔下載、影片串流都依賴它 |

靜態檔案伺服器看似簡單，卻集結了 I/O、安全、HTTP Header、Stream 四個重要概念。理解它，你就知道 `express.static()` 中間件背後在做什麼，也能在 CDN / 反向代理設定 cache 時更有把握。

## 進階挑戰（選做）

1. **`Cache-Control` Header**：加上 `Cache-Control: max-age=3600`，告訴瀏覽器快取靜態檔案一小時
2. **ETag 支援**：用 `fs.stat()` 取得檔案 `mtime`，產生簡易 ETag；若請求帶有相符的 `If-None-Match`，回傳 304 Not Modified
3. **目錄列表**：當 URL 對應到一個目錄（而非檔案）時，用 `fs.readdir()` 回傳目錄內容的 HTML 列表
4. **支援圖片**：擴充 MIME Type 表，加入 `.png`（`image/png`）、`.jpg`（`image/jpeg`）、`.svg`（`image/svg+xml`），並測試圖片能否在瀏覽器正常顯示
