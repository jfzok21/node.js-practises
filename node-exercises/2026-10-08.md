# 第 14 週今日 Node.js 練習題：全端任務管理 REST API

## 題目說明

建立一個完整的任務管理（Todo List）REST API 服務，整合你前幾週所學的所有核心技術：Express、PostgreSQL、JWT 身份驗證、輸入驗證、錯誤處理，以及 Jest 測試。這是一個貼近真實後端開發工作的實戰專案。

## 技術要求

- **概念：** REST API 設計、JWT 驗證、資料庫 CRUD、Middleware 串接、統一錯誤處理
- **需要的套件：**
  - `express` — HTTP 框架
  - `pg` — PostgreSQL 客戶端
  - `jsonwebtoken` — JWT 簽發與驗證
  - `bcrypt` — 密碼雜湊
  - `joi` 或 `zod` — 輸入驗證
  - `dotenv` — 環境變數管理
  - `jest` + `supertest` — 測試

## 具體任務

1. **資料庫設計**
   建立兩張 PostgreSQL 資料表：
   - `users`：`id`, `email`, `password_hash`, `created_at`
   - `tasks`：`id`, `user_id`, `title`, `description`, `status` (`pending`/`in_progress`/`done`), `created_at`, `updated_at`

2. **身份驗證路由**
   - `POST /auth/register` — 註冊（密碼用 bcrypt 雜湊後存入）
   - `POST /auth/login` — 登入，成功後回傳 JWT token

3. **任務 CRUD 路由（需驗證 JWT）**
   - `GET /tasks` — 取得目前登入使用者的所有任務（支援 `?status=` 篩選）
   - `POST /tasks` — 建立新任務
   - `PUT /tasks/:id` — 更新任務（只能更新自己的）
   - `DELETE /tasks/:id` — 刪除任務（只能刪除自己的）

4. **輸入驗證**
   使用 `joi` 或 `zod` 驗證所有請求的 body，錯誤時回傳 `400 Bad Request` 與清楚的訊息。

5. **統一錯誤處理**
   建立全域錯誤處理 middleware，確保所有錯誤都以一致的 JSON 格式回應：
   ```json
   { "error": "錯誤說明", "code": "ERROR_CODE" }
   ```

6. **撰寫 Jest + Supertest 測試**
   至少覆蓋：
   - 未帶 token 存取 `/tasks` 應回傳 `401`
   - 成功建立任務後 `GET /tasks` 應包含該筆資料
   - 嘗試刪除他人任務應回傳 `403`

## 範例

```js
// POST /auth/login
// 請求 body
{ "email": "user@example.com", "password": "mypassword" }

// 成功回應 200
{ "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." }

// ---

// POST /tasks  (Header: Authorization: Bearer <token>)
// 請求 body
{ "title": "完成 Node.js 練習", "description": "每日一題", "status": "pending" }

// 成功回應 201
{
  "id": 1,
  "user_id": 42,
  "title": "完成 Node.js 練習",
  "description": "每日一題",
  "status": "pending",
  "created_at": "2026-10-08T08:00:00.000Z"
}
```

## 提示

- 將 `app.js`（Express app）和 `server.js`（啟動 listen）分開，方便 Supertest 在測試時不真正啟動埠號。
- 使用 `process.env` + `.env` 管理資料庫連線字串與 JWT secret，切勿寫死在程式碼中。
- middleware 的順序很重要：`body-parser` → 身份驗證 → 路由 → 錯誤處理。
- 更新任務前，先用 `WHERE id = $1 AND user_id = $2` 確認擁有者，避免越權存取。

## 學習重點（跟後端 API 的關聯）

這個實戰專題完整示範了一個生產等級後端 API 的骨架：

| 概念 | 本週實作 |
|------|----------|
| 身份識別 | JWT 無狀態驗證 |
| 資源隔離 | `user_id` 篩選確保資料安全 |
| 合約保護 | Joi/Zod schema 驗證輸入 |
| 可觀測性 | 統一錯誤格式便於日誌解析 |
| 可測試性 | app/server 分離 + Supertest |

掌握這個骨架後，任何商業後端（電商訂單、社群貼文、預約系統）都是在此基礎上增加業務邏輯，而非重新發明輪子。

## 進階挑戰（選做）

- 新增任務排序：`GET /tasks?sort=created_at&order=desc`
- 加入分頁：`?page=1&limit=10`，回應同時包含 `total` 筆數
- 實作 refresh token 機制（短效 access token + 長效 refresh token）
- 使用 `pg-pool` 的 transaction，確保刪除帳號時連帶刪除所有任務為原子操作
- 以 Docker Compose 同時啟動 API 服務與 PostgreSQL，寫入 `docker-compose.yml`
