# 第 10 週今日 Node.js 練習題：Express 輸入驗證與錯誤處理

## 題目說明

建立一個 Express API，實作完整的輸入驗證（使用 `express-validator`）與集中式錯誤處理機制。你將建立一個「使用者註冊」端點，確保資料在進入業務邏輯前即完成驗證，並以統一格式回傳錯誤訊息。

## 技術要求

- **概念**：Middleware 錯誤處理、輸入驗證鏈、自訂 Error 類別、HTTP 狀態碼語義
- **需要的套件**：`express`、`express-validator`

## 具體任務

1. **建立專案結構**
   - 初始化專案並安裝 `express` 與 `express-validator`
   - 建立 `app.js`（Express 設定）與 `routes/users.js`（路由）

2. **實作輸入驗證 Middleware**
   使用 `express-validator` 驗證 POST `/api/users/register` 的請求體：
   - `username`：必填，長度 3–20，只允許英數字與底線
   - `email`：必填，須為有效 Email 格式
   - `password`：必填，至少 8 個字元，需包含大寫、小寫、數字各至少一個
   - `age`：選填，若提供則需為 18–120 的整數

3. **建立集中式錯誤處理**
   - 建立一個自訂 `AppError` 類別（繼承 `Error`），包含 `statusCode` 與 `errors` 欄位
   - 在 `app.js` 最後加上 4 個參數的錯誤處理 Middleware：`(err, req, res, next) => {}`
   - 所有錯誤統一回傳 JSON 格式：
     ```json
     {
       "success": false,
       "message": "Validation failed",
       "errors": [{ "field": "email", "message": "必須是有效的 Email" }]
     }
     ```

4. **測試各種情境**
   - 用 `curl` 或 `Postman` 測試：完全正確的資料、缺少必填欄位、格式錯誤（密碼太弱、Email 無效）、未成年使用者

## 範例

```js
// routes/users.js
const { body, validationResult } = require('express-validator');

const validateRegister = [
  body('username')
    .trim()
    .isLength({ min: 3, max: 20 }).withMessage('使用者名稱需為 3–20 個字元')
    .matches(/^[a-zA-Z0-9_]+$/).withMessage('只允許英數字與底線'),
  body('email')
    .isEmail().withMessage('必須是有效的 Email')
    .normalizeEmail(),
  body('password')
    .isLength({ min: 8 }).withMessage('密碼至少需要 8 個字元')
    .matches(/[A-Z]/).withMessage('需包含至少一個大寫字母')
    .matches(/[a-z]/).withMessage('需包含至少一個小寫字母')
    .matches(/[0-9]/).withMessage('需包含至少一個數字'),
  body('age')
    .optional()
    .isInt({ min: 18, max: 120 }).withMessage('年齡需為 18–120 的整數'),
];

router.post('/register', validateRegister, (req, res, next) => {
  const errors = validationResult(req);
  if (!errors.isEmpty()) {
    return res.status(400).json({
      success: false,
      message: 'Validation failed',
      errors: errors.array().map(e => ({ field: e.path, message: e.msg })),
    });
  }
  // 模擬成功（實際專案這裡會存入資料庫）
  res.status(201).json({ success: true, message: '使用者已成功建立' });
});
```

```js
// app.js — 集中式錯誤處理 Middleware（放在所有路由之後）
app.use((err, req, res, next) => {
  const statusCode = err.statusCode || 500;
  res.status(statusCode).json({
    success: false,
    message: err.message || 'Internal Server Error',
    errors: err.errors || [],
  });
});
```

```bash
# 測試指令範例
curl -X POST http://localhost:3000/api/users/register \
  -H "Content-Type: application/json" \
  -d '{"username": "jo", "email": "not-an-email", "password": "weak"}'
# 預期回應：400 + 驗證錯誤清單
```

## 提示

- `express-validator` 的 `validationResult(req)` 需要在路由 handler 內呼叫，不是自動執行的
- 4 個參數的 Middleware `(err, req, res, next)` 必須放在 `app.use()` 的**最後**，Express 才會把它識別為錯誤處理器
- `.withMessage()` 可以鏈式呼叫，每個驗證規則都能有自己的錯誤訊息
- 用 `.optional()` 讓欄位變選填，但一旦提供就必須通過後續驗證

## 學習重點

**與後端 API 的關聯**：在真實的 REST API 中，輸入驗證是第一道防線——它保護業務邏輯不被錯誤資料汙染，也避免惡意輸入造成安全漏洞（如 SQL injection 的前置防護）。集中式錯誤處理則確保前端永遠收到格式一致的錯誤回應，降低整合成本。這兩者是生產環境 API 的基礎建設，幾乎每個 Express 專案都需要。

## 進階挑戰（選做）

1. **自訂 Sanitizer**：在驗證通過後，自動將 `username` 轉為小寫並去除前後空白，再存入 `req.body`
2. **非同步驗證**：使用 `.custom()` 搭配 async 函式，模擬「檢查 Email 是否已被使用」（回傳一個假的 Promise，500ms 後 reject 若 email 為 `test@test.com`）
3. **Schema-based 驗證**：改用 `checkSchema()` 重寫所有驗證規則，並比較與鏈式寫法的差異
4. **全域 404 處理**：在錯誤處理 Middleware 前加一個 Middleware，攔截所有未定義路由並回傳統一的 404 JSON
