# 第 18 週今日 Node.js 練習題：迷你 URL 縮短服務

## 題目說明

打造一個可運作的 URL 縮短服務（類似 bit.ly）。使用者送出長網址後，系統產生一個短代碼並儲存對應關係；訪問短網址時自動 301 重導向至原始網址。資料以 JSON 檔案持久化，確保重啟後不遺失。

---

## 技術要求

- **概念：** Express 路由、Base62 編碼、檔案持久化、301 重導向、輸入驗證
- **需要的套件：**
  - `express` — HTTP 框架
  - `nanoid` v3（`const { nanoid } = require('nanoid')`）— 短代碼生成

---

## 具體任務

1. **初始化專案**
   - `npm init -y`，安裝 `express` 與 `nanoid@3`
   - 建立 `server.js`（主程式）與 `store.js`（資料存取層）

2. **資料存取層 `store.js`**
   - 以 `urls.json` 儲存 `{ [code]: { original, createdAt, clicks } }` 格式
   - 匯出 `load()`、`save(data)`、`findByCode(code)`、`findByOriginal(url)`、`add(original)` 函式
   - `add()` 用 `nanoid(6)` 產生代碼，若重複則重試（最多 5 次）

3. **POST `/shorten`**
   - Body：`{ "url": "https://example.com/very/long/path" }`
   - 驗證：`url` 必須存在且以 `http://` 或 `https://` 開頭
   - 若相同網址已存在，回傳現有短網址（冪等）
   - 成功回應：`201 Created`，body：`{ "short": "http://localhost:3000/abc123", "code": "abc123" }`

4. **GET `/:code`**
   - 查找代碼對應的原始網址
   - 找到：將 `clicks` 累加 1 並存檔，然後 `301` 重導向至原始網址
   - 找不到：`404`，body：`{ "error": "短網址不存在" }`

5. **GET `/api/stats/:code`**
   - 回傳 `{ code, original, createdAt, clicks }` 統計資訊
   - 找不到：`404`

6. **錯誤處理中介軟體**
   - 加入全域 error handler，回傳 `{ "error": message }` JSON
   - 加入 404 catch-all，針對未定義路由回傳 `{ "error": "找不到此路由" }`

## 範例

```js
// store.js 骨架
const fs = require('fs');
const path = require('path');
const { nanoid } = require('nanoid');

const FILE = path.join(__dirname, 'urls.json');

function load() {
  try {
    return JSON.parse(fs.readFileSync(FILE, 'utf8'));
  } catch {
    return {};
  }
}

function save(data) {
  fs.writeFileSync(FILE, JSON.stringify(data, null, 2));
}

function add(original) {
  const data = load();
  // 冪等檢查
  const existing = Object.entries(data).find(([, v]) => v.original === original);
  if (existing) return existing[0];

  let code, attempts = 0;
  do {
    code = nanoid(6);
    attempts++;
  } while (data[code] && attempts < 5);

  if (data[code]) throw new Error('無法產生唯一代碼，請稍後重試');

  data[code] = { original, createdAt: new Date().toISOString(), clicks: 0 };
  save(data);
  return code;
}

module.exports = { load, save, findByCode: (c) => load()[c], add };
```

```js
// server.js 骨架
const express = require('express');
const store = require('./store');

const app = express();
app.use(express.json());

const BASE = 'http://localhost:3000';

app.post('/shorten', (req, res, next) => {
  try {
    const { url } = req.body;
    if (!url || !/^https?:\/\//i.test(url)) {
      return res.status(400).json({ error: '請提供有效的 http/https 網址' });
    }
    const code = store.add(url);
    res.status(201).json({ short: `${BASE}/${code}`, code });
  } catch (err) {
    next(err);
  }
});

app.get('/api/stats/:code', (req, res) => {
  const entry = store.findByCode(req.params.code);
  if (!entry) return res.status(404).json({ error: '短網址不存在' });
  res.json({ code: req.params.code, ...entry });
});

app.get('/:code', (req, res) => {
  // TODO: 查找、累加 clicks、重導向
});

// 404 catch-all 與 error handler
app.use((req, res) => res.status(404).json({ error: '找不到此路由' }));
app.use((err, req, res, next) => res.status(500).json({ error: err.message }));

app.listen(3000, () => console.log('URL Shortener 啟動於 http://localhost:3000'));
```

```bash
# 測試流程
curl -X POST http://localhost:3000/shorten \
  -H "Content-Type: application/json" \
  -d '{"url":"https://www.example.com/very/long/article?id=123"}'
# => {"short":"http://localhost:3000/xK9pLm","code":"xK9pLm"}

curl -L http://localhost:3000/xK9pLm   # 應重導向至原始網址

curl http://localhost:3000/api/stats/xK9pLm
# => {"code":"xK9pLm","original":"https://...","createdAt":"...","clicks":1}
```

## 提示

- `fs.writeFileSync` 是同步寫入，小型專案可接受；高並發場景需考慮鎖定或改用資料庫
- `301 Moved Permanently` 會被瀏覽器快取；若要在測試中看到 `clicks` 增加，可暫改為 `302`
- `nanoid@3` 使用 CommonJS，`nanoid@4+` 改為 ESM；本題指定 v3 以配合 `require()`
- 路由順序重要：`/api/stats/:code` 必須在 `/:code` **之前** 註冊，否則 `api` 會被視為代碼

---

## 學習重點（跟後端 API 的關聯）

| 概念 | 對應場景 |
|------|----------|
| 冪等 POST | 相同輸入多次呼叫結果一致，RESTful 設計原則 |
| 301 重導向 | HTTP 語意的正確使用，非 JSON 回應也是 API 設計的一環 |
| 資料存取層分離 | 將 I/O 邏輯抽成 `store.js`，方便日後替換為 DB |
| 點擊計數 | 讀取－修改－寫入的原子性問題，引出資料庫事務概念 |
| 路由衝突排解 | 路由順序與具名參數的優先級，Express 常見陷阱 |

真實 URL 縮短服務（如 bit.ly）會用 Redis 做快取、PostgreSQL 存資料、CDN 做全球邊緣重導向——本題的結構是同一個架構的縮小版。

## 進階挑戰（選做）

1. **自訂短代碼**：`POST /shorten` 接受可選的 `{ "url": "...", "alias": "my-brand" }`，若 alias 已被使用則回傳 `409 Conflict`
2. **過期機制**：加入 `expiresAt` 欄位，訪問已過期的短網址時回傳 `410 Gone`
3. **QR Code 端點**：`GET /api/qr/:code` 使用 `qrcode` 套件回傳 PNG 圖片（`res.setHeader('Content-Type', 'image/png')`）
4. **改用 Map + 定時快照**：以 in-memory `Map` 為主要存取，每 10 秒才將變更同步至 `urls.json`，減少磁碟 I/O
