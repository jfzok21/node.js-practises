# 第 20 週今日 Node.js 練習題：即時任務看板 API

## 題目說明

建立一個具備即時通知功能的任務看板後端 API。使用者可以建立、更新、刪除任務，並透過 Server-Sent Events（SSE）即時收到看板狀態變更的推播通知，不需要輪詢。

## 技術要求
- 概念：Server-Sent Events（SSE）、事件發射器（EventEmitter）、REST API 設計、資料過濾與排序
- 需要的套件：`express`、`uuid`（或使用 `crypto.randomUUID()`）

## 具體任務

1. **設計資料模型**
   - 任務欄位：`id`、`title`、`description`、`status`（`todo` / `in_progress` / `done`）、`priority`（`low` / `medium` / `high`）、`createdAt`、`updatedAt`
   - 使用記憶體陣列儲存（不需要資料庫）

2. **實作 REST 端點**
   - `GET /tasks` — 列出所有任務，支援 `?status=` 與 `?priority=` 查詢參數過濾
   - `POST /tasks` — 新增任務（`title` 必填，其餘選填，預設 `status: "todo"`）
   - `PATCH /tasks/:id` — 局部更新任務（只更新傳入的欄位）
   - `DELETE /tasks/:id` — 刪除任務

3. **實作 SSE 端點**
   - `GET /tasks/events` — 建立 SSE 連線，回傳 `Content-Type: text/event-stream`
   - 每當任務被新增、更新或刪除時，向所有已連線的客戶端推播事件
   - 事件格式：`event: task_created | task_updated | task_deleted`，`data: <JSON 字串>`

4. **實作心跳機制**
   - 每 30 秒傳送一次 `: keepalive` 註解行，防止連線逾時

5. **輸入驗證**
   - 新增任務時若缺少 `title`，回傳 `400 Bad Request`
   - `status` 或 `priority` 值不合法時回傳 `400 Bad Request`
   - 任務不存在時回傳 `404 Not Found`

## 範例

```js
// SSE 客戶端連線（Node.js fetch 示意）
const response = await fetch('http://localhost:3000/tasks/events');
const reader = response.body.getReader();

// 新增任務後，SSE 推播內容範例：
// event: task_created
// data: {"id":"abc-123","title":"實作登入頁","status":"todo","priority":"medium","createdAt":"2026-11-22T10:00:00.000Z","updatedAt":"2026-11-22T10:00:00.000Z"}

// PATCH /tasks/abc-123  body: { "status": "in_progress" }
// 推播：
// event: task_updated
// data: {"id":"abc-123","title":"實作登入頁","status":"in_progress","priority":"medium",...}
```

## 提示

- 用 Node.js 內建的 `EventEmitter` 建立一個全域的 `taskEmitter`，讓 REST 路由在修改資料後 `emit` 事件，SSE 路由監聽並轉發給客戶端。
- SSE 連線關閉時（`req.on('close', ...)`），記得從訂閱清單中移除該客戶端，並清除心跳計時器，避免記憶體洩漏。
- `PATCH` 只更新 body 中存在的欄位，不要整筆覆蓋；記得更新 `updatedAt`。
- 在 `GET /tasks/events` 回應 header 中加入 `Cache-Control: no-cache` 與 `X-Accel-Buffering: no`（避免 Nginx 緩衝截斷串流）。

## 學習重點

**跟後端 API 的關聯：**
SSE 是輕量的伺服器推播方案，適合單向、頻率不高的即時通知（例如後台任務完成通知、訂單狀態更新）。相比 WebSocket，它建立在標準 HTTP 之上，穿越防火牆更容易，且斷線後瀏覽器會自動重連。在微服務架構中，可以搭配訊息佇列（如 Redis Pub/Sub）讓多個 API 實例共享推播事件。

## 進階挑戰（選做）

- 加入 `GET /tasks/:id` 端點，回傳單一任務詳情
- 在 SSE 端點支援 `?status=` 訂閱過濾，只推播符合狀態的事件
- 加入簡單的 API Key 驗證中介層（從 `Authorization: Bearer <key>` header 讀取，與環境變數比對）
- 撰寫 Jest 測試，測試過濾邏輯與 `404` / `400` 回應
