# 第 10 週今日 Node.js 練習題：Express 輸入驗證與錯誤處理

## 題目說明

建立一個 Express 使用者註冊 API，實作完整的輸入驗證與集中式錯誤處理。學習如何防止非法資料進入系統、回傳統一的錯誤格式，並區分 4xx 用戶端錯誤與 5xx 伺服器錯誤。

## 技術要求

- **概念**：Middleware 錯誤處理、輸入驗證、HTTP 狀態碼語意、自訂 Error class
- **需要的套件**：
  - `express`
  - `express-validator`（或手動驗證）
  - `joi`（可選，擇一）

## 具體任務

1. 建立 `src/app.js`，設定 Express 應用程式與 JSON body parser。

2. 建立 `POST /api/register` 路由，接受以下 body：
   ```json
   {
     "username": "john_doe",
     "email": "john@example.com",
     "password": "Secure123!",
     "age": 25
   }
   ```

3. 對每個欄位實作驗證規則：
   - `username`：必填、3–20 字元、只允許英數字與底線
   - `email`：必填、格式必須合法
   - `password`：必填、至少 8 字元、需包含大小寫字母與數字
   - `age`：必填、整數、18–120 之間

4. 建立自訂 `AppError` class，繼承 `Error`，包含 `statusCode` 與 `isOperational` 屬性。

5. 實作集中式錯誤處理 middleware（4 個參數：`err, req, res, next`），回傳統一 JSON 格式：
   ```json
   {
     "success": false,
     "error": {
       "message": "錯誤訊息",
       "code": "ERROR_CODE",
       "details": []
     }
   }
   ```

6. 處理以下錯誤情境：
   - 驗證失敗 → 400 Bad Request，列出所有錯誤欄位
   - 資源不存在 → 404 Not Found
   - 伺服器內部錯誤 → 500 Internal Server Error（隱藏錯誤細節）

7. 建立 `GET /api/users/:id` 路由，當 id 不是數字時回傳 400；找不到使用者時回傳 404（模擬資料即可）。

## 範例

```js
// 輸入（合法）
POST /api/register
{
  "username": "john_doe",
  "email": "john@example.com",
  "password": "Secure123!",
  "age": 25
}

// 輸出（成功）→ 201 Created
{
  "success": true,
  "data": {
    "id": 1,
    "username": "john_doe",
    "email": "john@example.com"
  }
}

// 輸入（非法）
POST /api/register
{
  "username": "j",
  "email": "not-an-email",
  "password": "weak",
  "age": 15
}

// 輸出（失敗）→ 400 Bad Request
{
  "success": false,
  "error": {
    "message": "輸入驗證失敗",
    "code": "VALIDATION_ERROR",
    "details": [
      { "field": "username", "message": "username 需介於 3-20 個字元" },
      { "field": "email", "message": "email 格式不正確" },
      { "field": "password", "message": "password 至少需要 8 個字元，且包含大小寫字母與數字" },
      { "field": "age", "message": "age 必須為 18 至 120 之間的整數" }
    ]
  }
}
```

## 提示

- `express-validator` 使用 `body('field').notEmpty().withMessage('...')` 串接驗證規則，再用 `validationResult(req)` 取得結果。
- 自訂 `AppError` 範例：
  ```js
  class AppError extends Error {
    constructor(message, statusCode, code = 'APP_ERROR') {
      super(message);
      this.statusCode = statusCode;
      this.code = code;
      this.isOperational = true;
    }
  }
  ```
- 錯誤處理 middleware 必須是 Express app 中**最後**被 `app.use()` 的 middleware。
- 在 production 環境，不要把 stack trace 回傳給用戶端（用 `process.env.NODE_ENV` 判斷）。
- 正規表達式驗證 username：`/^[a-zA-Z0-9_]+$/`

## 學習重點（跟後端 API 的關聯）

輸入驗證是後端安全的第一道防線：

- **防止無效資料**：在存入資料庫之前攔截，避免 DB constraint 錯誤或資料汙染。
- **一致的錯誤格式**：前端只需處理一種錯誤結構，降低前後端溝通成本。
- **區分錯誤類型**：4xx 代表用戶端的問題（可修正），5xx 代表伺服器的問題（需要警報）。
- **isOperational 旗標**：在實際專案中，非 operational 的錯誤（如程式 bug）會觸發告警或重啟，而 operational 錯誤只需回傳適當 HTTP 回應即可。

## 進階挑戰（選做）

1. 使用 `joi` schema 取代手動驗證，將所有驗證規則集中到 `validators/` 資料夾。
2. 加入 `sanitize` 步驟（例如用 `xss` 套件清除 HTML 標籤），防止 XSS 注入。
3. 建立非同步錯誤包裝函式 `asyncHandler`，避免每個 async 路由都要寫 try/catch：
   ```js
   const asyncHandler = fn => (req, res, next) => Promise.resolve(fn(req, res, next)).catch(next);
   ```
4. 整合 `winston` 或 `pino` 記錄錯誤 log，區分 error level 與 warn level。
