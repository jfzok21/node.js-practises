# 第 8 週今日 Node.js 練習題：用 PostgreSQL 建立使用者資料庫 CRUD API

## 題目說明

使用 Node.js 搭配 `pg`（node-postgres）套件，連接 PostgreSQL 資料庫，建立一套完整的使用者（Users）資料表，並透過 Express 提供 CRUD（Create、Read、Update、Delete）API 端點。

## 技術要求
- 概念：SQL DDL（CREATE TABLE）、參數化查詢（防止 SQL Injection）、非同步資料庫操作、Connection Pool
- 需要的套件：`express`、`pg`、`dotenv`

## 具體任務

1. 建立 `.env` 檔案，設定 PostgreSQL 連線資訊：
   ```
   DB_HOST=localhost
   DB_PORT=5432
   DB_NAME=practice_db
   DB_USER=your_user
   DB_PASSWORD=your_password
   ```

2. 建立 `db.js`，使用 `pg.Pool` 初始化連線池，並匯出供其他模組使用。

3. 建立 `initDb.js`，在 PostgreSQL 中建立 `users` 資料表（若不存在則建立）：
   ```sql
   CREATE TABLE IF NOT EXISTS users (
     id SERIAL PRIMARY KEY,
     name VARCHAR(100) NOT NULL,
     email VARCHAR(150) UNIQUE NOT NULL,
     created_at TIMESTAMP DEFAULT NOW()
   );
   ```

4. 在 Express 路由中實作以下 API 端點：
   - `GET /users` — 取得所有使用者列表
   - `GET /users/:id` — 依 ID 取得單一使用者
   - `POST /users` — 新增使用者（body: `{ name, email }`）
   - `PUT /users/:id` — 更新使用者資料
   - `DELETE /users/:id` — 刪除使用者

5. 所有資料庫查詢必須使用**參數化查詢**（`$1, $2, ...`），不可直接拼接 SQL 字串。

## 範例

```js
// db.js
const { Pool } = require('pg');
require('dotenv').config();

const pool = new Pool({
  host: process.env.DB_HOST,
  port: process.env.DB_PORT,
  database: process.env.DB_NAME,
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
});

module.exports = pool;

// routes/users.js（片段）
const pool = require('../db');

// GET /users
router.get('/', async (req, res) => {
  try {
    const result = await pool.query('SELECT * FROM users ORDER BY created_at DESC');
    res.json(result.rows);
  } catch (err) {
    res.status(500).json({ error: err.message });
  }
});

// POST /users
router.post('/', async (req, res) => {
  const { name, email } = req.body;
  try {
    const result = await pool.query(
      'INSERT INTO users (name, email) VALUES ($1, $2) RETURNING *',
      [name, email]
    );
    res.status(201).json(result.rows[0]);
  } catch (err) {
    if (err.code === '23505') { // unique violation
      res.status(409).json({ error: 'Email 已被使用' });
    } else {
      res.status(500).json({ error: err.message });
    }
  }
});
```

## 提示
- 使用 `pool.query()` 而非 `client.query()`，Pool 會自動管理連線，不需要手動 `connect()` / `release()`。
- 新增使用者時若 email 重複，PostgreSQL 會拋出 error code `23505`（unique_violation），記得在 catch 中判斷並回傳 409 狀態碼。
- 在 `app.js` 啟動時呼叫 `initDb.js` 確保資料表已建立。
- 使用 `RETURNING *` 可讓 INSERT/UPDATE 直接回傳操作後的資料列，省去額外的 SELECT 查詢。

## 學習重點（跟後端 API 的關聯）

這週是後端開發的核心轉折點：從記憶體資料（陣列）升級到**持久化儲存**。真實的後端 API 幾乎都需要資料庫，而 PostgreSQL 是業界最常見的關聯式資料庫之一。

- **Connection Pool** 能有效管理多個並發請求共用資料庫連線，避免每次請求都重新建立連線的效能開銷。
- **參數化查詢** 是防止 SQL Injection 攻擊的基本防線，這在任何生產環境都是強制要求。
- 熟悉 `pg` 套件後，下一步可以進階到 ORM（如 Prisma、Sequelize），但理解原生 SQL 是必要基礎。

## 進階挑戰（選做）

1. **分頁功能**：為 `GET /users` 加入 `?page=1&limit=10` 查詢參數，使用 `LIMIT` 與 `OFFSET` 實作分頁。
2. **搜尋功能**：加入 `?search=關鍵字` 參數，使用 `ILIKE` 對 name 或 email 進行模糊搜尋。
3. **Transaction**：建立 `POST /users/bulk` 端點，接受使用者陣列，使用 Transaction 確保批次新增要麼全成功要麼全回滾。
4. **連線錯誤處理**：在 `db.js` 監聽 Pool 的 `error` 事件，當資料庫連線中斷時印出警告並優雅地重試。
