# 第 16 週今日 Node.js 練習題：實作簡易任務管理 REST API（含 JWT 保護）

## 題目說明

綜合前幾週所學，建立一個完整的「任務管理系統」後端 API。使用者可以註冊、登入，並對自己的任務進行 CRUD（建立、讀取、更新、刪除）操作。所有任務端點須以 JWT 驗證保護，確保使用者只能存取自己的任務。

---

## 技術要求

- **概念**：Express 路由、JWT 身份驗證、輸入驗證、錯誤處理、REST API 設計
- **需要的套件**：
  - `express` — HTTP 伺服器框架
  - `jsonwebtoken` — JWT 簽發與驗證
  - `bcrypt` — 密碼雜湊
  - `express-validator` — 輸入驗證
  - `uuid` — 產生唯一 ID（或使用 `crypto.randomUUID()`）

> 本練習使用記憶體陣列儲存資料，不需連接資料庫。

---

## 具體任務

1. **初始化專案**
   - `npm init -y`，安裝上述套件
   - 建立 `src/app.js`（主程式）、`src/routes/auth.js`、`src/routes/tasks.js`、`src/middleware/auth.js`

2. **實作使用者認證（`/auth`）**
   - `POST /auth/register`：接收 `{ username, password }`，將密碼以 bcrypt 雜湊後存入記憶體使用者清單，回傳 `201`
   - `POST /auth/login`：驗證帳密，成功則回傳簽發的 JWT（有效期 1 小時）

3. **實作 JWT 中介層（`src/middleware/auth.js`）**
   - 讀取 `Authorization: Bearer <token>` 標頭
   - 驗證 token，將解碼的 `userId` 附加到 `req.user`
   - token 無效或過期則回傳 `401`

4. **實作任務 CRUD（`/tasks`，全部需通過 JWT 中介層）**
   - `GET /tasks` — 列出當前使用者所有任務
   - `POST /tasks` — 建立新任務（必填欄位：`title`；選填：`description`、`status`）
   - `PUT /tasks/:id` — 更新指定任務（只能更新自己的任務，否則 `403`）
   - `DELETE /tasks/:id` — 刪除指定任務（同上）

5. **加入輸入驗證**
   - 登入 / 註冊：`username` 不可空白；`password` 至少 6 碼
   - 建立任務：`title` 不可空白、`status` 若提供則只允許 `"pending"` / `"done"`

---

## 範例

```js
// 1. 註冊
// POST /auth/register
// Body: { "username": "alice", "password": "secret123" }
// Response 201: { "message": "使用者已建立" }

// 2. 登入取得 token
// POST /auth/login
// Body: { "username": "alice", "password": "secret123" }
// Response 200: { "token": "eyJhbGci..." }

// 3. 建立任務（帶 Bearer token）
// POST /tasks
// Headers: Authorization: Bearer eyJhbGci...
// Body: { "title": "買牛奶", "status": "pending" }
// Response 201: { "id": "a1b2c3", "title": "買牛奶", "status": "pending", "userId": "..." }

// 4. 取得任務清單
// GET /tasks
// Response 200: [ { "id": "a1b2c3", "title": "買牛奶", ... } ]
```

---

## 提示

- 使用 `Map` 或陣列分別儲存 `users` 與 `tasks`，key 用 `userId`
- `jwt.sign({ userId: user.id }, process.env.JWT_SECRET, { expiresIn: '1h' })`
- 中介層若驗證失敗，記得 `return res.status(401).json(...)` 避免繼續執行
- 用 `validationResult(req)` 收集 express-validator 的錯誤後統一回傳 `400`
- 更新/刪除任務前先確認 `task.userId === req.user.userId`，不符則 `403`

## 學習重點（與後端 API 的關聯）

這道題整合了現代後端 API 的核心要素：

| 概念 | 對應真實開發場景 |
|---|---|
| JWT 身份驗證 | 大多數 SaaS / 行動應用的無狀態認證 |
| 輸入驗證 | 防止惡意輸入，避免業務邏輯錯誤 |
| 錯誤處理中介層 | 統一 API 錯誤格式，方便前端處理 |
| 資源所有權保護 | 多租戶系統的基本安全需求 |

在真實環境中，`users` 與 `tasks` 會存入 PostgreSQL（第 8 週），但架構與路由設計方式完全相同。

## 進階挑戰（選做）

1. **分頁**：`GET /tasks?page=1&limit=10`，回傳 `{ data, total, page, limit }`
2. **篩選**：`GET /tasks?status=pending` 只回傳指定狀態的任務
3. **Refresh Token**：實作 `POST /auth/refresh`，以 refresh token 換發新 access token
4. **全域錯誤處理中介層**：在 `app.js` 最末加入 `app.use((err, req, res, next) => {...})`，集中處理未捕獲的錯誤
5. **Jest 測試**：為 `POST /auth/login` 及 `GET /tasks` 各寫至少兩個測試案例（成功 / 失敗）
