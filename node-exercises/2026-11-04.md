# 第 18 週今日 Node.js 練習題：任務管理 REST API（整合實戰）

## 題目說明

綜合前幾週所學，建立一個完整的「任務管理系統」REST API。  
系統需支援使用者登入、以 JWT 保護路由、CRUD 任務操作，以及完整的輸入驗證與錯誤處理。  
這是貼近真實後端開發工作的完整練習。

## 技術要求

- **概念**：Express 路由、JWT 身份驗證、REST API 設計、Middleware、輸入驗證、錯誤處理
- **需要的套件**：
  - `express` — HTTP 伺服器框架
  - `jsonwebtoken` — JWT 簽發與驗證
  - `bcrypt` — 密碼雜湊
  - `express-validator` — 輸入驗證
  - `uuid` — 產生唯一 ID（或使用內建 `crypto.randomUUID()`）

## 具體任務

1. **初始化專案**
   - 建立 `task-api/` 目錄，執行 `npm init -y`，安裝所需套件。

2. **建立使用者資料層（in-memory）**
   - 使用陣列模擬資料庫，預設兩位使用者：
     ```js
     { id: '1', email: 'alice@example.com', password: '<bcrypt hash of "password123">' }
     { id: '2', email: 'bob@example.com',   password: '<bcrypt hash of "secret456">' }
     ```

3. **實作 `POST /auth/login`**
   - 驗證 email、password 格式
   - 比對密碼雜湊，成功回傳 JWT（有效期 1 小時）
   - 失敗回傳 `401 Unauthorized`

4. **建立 JWT 驗證 Middleware `authenticateToken`**
   - 從 `Authorization: Bearer <token>` 標頭取得 token
   - 驗證失敗回傳 `401`；token 過期回傳 `403`

5. **實作任務 CRUD（需 JWT 保護）**
   - `GET    /tasks`         — 取得當前使用者的所有任務
   - `POST   /tasks`         — 新增任務（title 必填、description 選填、status 預設 `pending`）
   - `GET    /tasks/:id`     — 取得單一任務（僅限任務擁有者）
   - `PATCH  /tasks/:id`     — 更新任務（title、description、status 可選）
   - `DELETE /tasks/:id`     — 刪除任務（僅限任務擁有者）

6. **全域錯誤處理 Middleware**
   - 統一回傳格式 `{ error: "...", details: [...] }`
   - 區分 400（驗證錯誤）、401/403（認證錯誤）、404（找不到）、500（伺服器錯誤）

## 範例

```js
// POST /auth/login
// Request body
{ "email": "alice@example.com", "password": "password123" }

// Response 200
{ "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." }

// ---

// POST /tasks（需帶 Authorization header）
// Request body
{ "title": "準備技術面試", "description": "複習 Node.js 與資料結構" }

// Response 201
{
  "id": "a1b2c3d4",
  "userId": "1",
  "title": "準備技術面試",
  "description": "複習 Node.js 與資料結構",
  "status": "pending",
  "createdAt": "2026-11-04T00:00:00.000Z"
}

// ---

// PATCH /tasks/a1b2c3d4
// Request body
{ "status": "done" }

// Response 200
{ ...task, "status": "done", "updatedAt": "2026-11-04T01:00:00.000Z" }

// ---

// GET /tasks/a1b2c3d4（其他使用者存取）
// Response 403
{ "error": "Forbidden: you do not own this task" }
```

## 提示

- 將 `JWT_SECRET` 存在 `process.env.JWT_SECRET`，透過 `.env` 檔案載入（可用 `dotenv`）。
- `bcrypt.hash()` 和 `bcrypt.compare()` 都是非同步的，記得用 `await`。
- Express 的錯誤處理 middleware 需要四個參數：`(err, req, res, next)`。
- 任務資料建議用 `Map<id, task>` 儲存，查找更有效率。
- `express-validator` 的錯誤可透過 `validationResult(req)` 取得。

## 學習重點（跟後端 API 的關聯）

| 本週練習 | 實際後端開發對應 |
|----------|-----------------|
| `authenticateToken` middleware | 保護私有 API 端點的標準做法 |
| bcrypt 密碼雜湊 | 任何需要登入的系統都必須做到 |
| 輸入驗證 + 錯誤格式統一 | 前端 / 客戶端才能正確解讀錯誤 |
| 任務所有權檢查 | 多租戶系統中資料隔離的核心邏輯 |
| 以 userId 過濾任務 | SQL `WHERE user_id = ?` 的 in-memory 模擬 |

## 進階挑戰（選做）

1. **新增 `GET /tasks?status=pending` 篩選功能**，支援 `pending`、`in-progress`、`done`。
2. **加入 Refresh Token 機制**：`POST /auth/refresh` 以 refresh token 換取新 access token。
3. **撰寫 Jest 整合測試**，使用 `supertest` 測試所有路由（含認證成功 / 失敗情境）。
4. **替換 in-memory 儲存為 SQLite**（使用 `better-sqlite3`），讓資料在重啟後持久保存。
