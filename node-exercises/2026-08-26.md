# 第 8 週今日 Node.js 練習題：用 node-postgres 建立使用者資料庫 CRUD

## 題目說明

建立一個 Node.js 腳本，使用 `pg`（node-postgres）套件連接 PostgreSQL 資料庫，並對 `users` 資料表實作完整的 CRUD 操作（新增、查詢、更新、刪除）。這是後端 API 最核心的技能之一——幾乎所有真實專案都需要與關聯式資料庫溝通。

## 技術要求

- **概念：** 資料庫連線池（Pool）、參數化查詢（Parameterized Query）、async/await 錯誤處理
- **需要的套件：** `pg`（`npm install pg`）
- **前置條件：** 本機或 Docker 需有 PostgreSQL 執行中（`docker run --name pg-demo -e POSTGRES_PASSWORD=secret -p 5432:5432 -d postgres` 即可快速啟動）

## 具體任務

1. **建立連線池**：使用 `pg.Pool` 設定連線參數（host、port、database、user、password）。
2. **初始化資料表**：執行 SQL 建立 `users` 資料表（若不存在），欄位包含 `id SERIAL PRIMARY KEY`、`name VARCHAR(100)`、`email VARCHAR(150) UNIQUE`、`created_at TIMESTAMPTZ DEFAULT NOW()`。
3. **實作 `createUser(name, email)`**：插入一筆新使用者，回傳插入後的完整列資料（使用 `RETURNING *`）。
4. **實作 `getAllUsers()`**：查詢所有使用者，依 `created_at` 遞減排序。
5. **實作 `updateUser(id, name)`**：依 `id` 更新使用者名稱，若找不到則回傳 `null`。
6. **實作 `deleteUser(id)`**：依 `id` 刪除使用者，回傳被刪除的列資料。
7. **撰寫主流程**：依序呼叫上述函式並印出結果，最後關閉連線池。

## 範例

```js
// db.js

const { Pool } = require('pg');

const pool = new Pool({
  host: 'localhost',
  port: 5432,
  database: 'postgres',
  user: 'postgres',
  password: 'secret',
});

async function initTable() {
  await pool.query(`
    CREATE TABLE IF NOT EXISTS users (
      id         SERIAL PRIMARY KEY,
      name       VARCHAR(100) NOT NULL,
      email      VARCHAR(150) UNIQUE NOT NULL,
      created_at TIMESTAMPTZ DEFAULT NOW()
    )
  `);
}

async function createUser(name, email) {
  const { rows } = await pool.query(
    'INSERT INTO users (name, email) VALUES ($1, $2) RETURNING *',
    [name, email]
  );
  return rows[0];
}

async function getAllUsers() {
  const { rows } = await pool.query(
    'SELECT * FROM users ORDER BY created_at DESC'
  );
  return rows;
}

async function updateUser(id, name) {
  const { rows } = await pool.query(
    'UPDATE users SET name = $1 WHERE id = $2 RETURNING *',
    [name, id]
  );
  return rows[0] ?? null;
}

async function deleteUser(id) {
  const { rows } = await pool.query(
    'DELETE FROM users WHERE id = $1 RETURNING *',
    [id]
  );
  return rows[0];
}

async function main() {
  await initTable();

  const alice = await createUser('Alice', 'alice@example.com');
  console.log('新增：', alice);

  const bob = await createUser('Bob', 'bob@example.com');
  console.log('新增：', bob);

  const all = await getAllUsers();
  console.log('所有使用者：', all);

  const updated = await updateUser(alice.id, 'Alice（更新後）');
  console.log('更新：', updated);

  const deleted = await deleteUser(bob.id);
  console.log('刪除：', deleted);

  await pool.end();
}

main().catch(console.error);
```

```
// 預期輸出（id 與 created_at 依環境而異）
新增： { id: 1, name: 'Alice', email: 'alice@example.com', created_at: 2026-08-26T... }
新增： { id: 2, name: 'Bob',   email: 'bob@example.com',   created_at: 2026-08-26T... }
所有使用者： [ { id: 2, ... }, { id: 1, ... } ]
更新： { id: 1, name: 'Alice（更新後）', ... }
刪除： { id: 2, name: 'Bob', ... }
```

## 提示

- **務必使用參數化查詢**（`$1, $2, ...`），絕對不要用字串拼接組 SQL，否則會有 SQL Injection 風險。
- `Pool` 比 `Client` 更適合伺服器情境：它自動管理多個連線，不需手動釋放。
- 若 `email` 重複插入，`pg` 會拋出 `error.code === '23505'`（unique violation），可用 `try/catch` 捕捉並回傳友善錯誤訊息。
- 完成後可用 `psql -U postgres -c "SELECT * FROM users;"` 驗證資料真的寫進去了。

## 學習重點（跟後端 API 的關聯）

在真實 REST API 中，`createUser` 對應 `POST /users`，`getAllUsers` 對應 `GET /users`，`updateUser` 對應 `PATCH /users/:id`，`deleteUser` 對應 `DELETE /users/:id`。本題的每個函式，之後都會直接成為 Express 路由處理器（route handler）裡呼叫的資料層（data layer / repository），讓你的 API 真正「有記憶」——重啟伺服器資料也不會消失。

## 進階挑戰（選做）

1. **環境變數**：改用 `dotenv` 套件，把資料庫連線參數移到 `.env` 檔，避免硬編碼密碼。
2. **錯誤處理**：替 `createUser` 加上重複 email 的友善錯誤處理，回傳 `{ error: 'Email 已被使用' }` 而非讓程式崩潰。
3. **分頁查詢**：替 `getAllUsers` 加上 `limit` 和 `offset` 參數，實作基本分頁（`LIMIT $1 OFFSET $2`）。
4. **連線測試**：用 `pool.query('SELECT NOW()')` 在啟動時驗證資料庫連線是否正常，失敗時輸出明確錯誤並退出。
