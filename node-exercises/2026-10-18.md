# 第 15 週今日 Node.js 練習題：圖書館借閱 REST API（實戰專案）

## 題目說明

建立一個完整的「圖書館借閱管理系統 API」，整合你在過去 14 週學到的所有核心技術：Express、PostgreSQL、JWT 身份驗證、輸入驗證、錯誤處理，以及 Jest 測試。這是一個接近真實後端產品的全端練習。

## 技術要求

- **概念：** REST API 設計、關聯式資料庫、JWT 認證、中介層、輸入驗證、錯誤處理、單元測試
- **需要的套件：**
  - `express` — HTTP 伺服器框架
  - `pg` — PostgreSQL 客戶端
  - `jsonwebtoken` — JWT 簽發與驗證
  - `bcryptjs` — 密碼雜湊
  - `joi` 或 `express-validator` — 輸入驗證
  - `dotenv` — 環境變數
  - `jest` + `supertest` — 整合測試

## 具體任務

1. **初始化專案**
   - `npm init -y`，安裝上述套件
   - 建立 `.env`：`DATABASE_URL`、`JWT_SECRET`、`PORT`
   - 建立 `src/` 資料夾，區分 `routes/`、`controllers/`、`middlewares/`、`db/`

2. **設計資料庫 Schema（PostgreSQL）**
   - `users` 表：`id`, `email`, `password_hash`, `created_at`
   - `books` 表：`id`, `title`, `author`, `isbn`, `available_copies`, `created_at`
   - `loans` 表：`id`, `user_id`（FK）, `book_id`（FK）, `borrowed_at`, `returned_at`

3. **實作使用者認證**
   - `POST /api/auth/register` — 註冊，密碼用 bcrypt 雜湊後存入 DB
   - `POST /api/auth/login` — 登入，回傳 JWT（有效期 24 小時）
   - 建立 `authMiddleware`：解析 `Authorization: Bearer <token>`，將 `req.user` 注入

4. **實作圖書 CRUD（需登入）**
   - `GET /api/books` — 列出所有書籍（支援 `?search=` 查詢書名或作者）
   - `GET /api/books/:id` — 取得單本書籍詳情
   - `POST /api/books` — 新增書籍（需驗證欄位）
   - `PUT /api/books/:id` — 更新書籍資訊
   - `DELETE /api/books/:id` — 刪除書籍

5. **實作借閱功能**
   - `POST /api/loans` — 借書（需確認 `available_copies > 0`，借出後減少庫存）
   - `PATCH /api/loans/:id/return` — 還書（更新 `returned_at`，增加庫存）
   - `GET /api/loans/me` — 查詢目前使用者的借閱紀錄

6. **統一錯誤處理**
   - 建立全域 error handler middleware
   - 區分 400（驗證失敗）、401（未授權）、404（資源不存在）、500（伺服器錯誤）

7. **撰寫 Jest 整合測試**
   - 測試 `POST /api/auth/register` 正常流程與重複 email 情況
   - 測試 `POST /api/loans` 借書成功與庫存不足情況

## 範例

```js
// 借書 API 核心邏輯（controllers/loanController.js）
const borrowBook = async (req, res, next) => {
  const { book_id } = req.body;
  const user_id = req.user.id;

  try {
    const book = await db.query('SELECT * FROM books WHERE id = $1', [book_id]);
    if (!book.rows[0]) return res.status(404).json({ error: '找不到此書籍' });
    if (book.rows[0].available_copies < 1) {
      return res.status(400).json({ error: '此書目前無庫存' });
    }

    await db.query('BEGIN');
    await db.query(
      'INSERT INTO loans (user_id, book_id, borrowed_at) VALUES ($1, $2, NOW())',
      [user_id, book_id]
    );
    await db.query(
      'UPDATE books SET available_copies = available_copies - 1 WHERE id = $1',
      [book_id]
    );
    await db.query('COMMIT');

    res.status(201).json({ message: '借書成功' });
  } catch (err) {
    await db.query('ROLLBACK');
    next(err);
  }
};
```

```js
// JWT 中介層（middlewares/auth.js）
const jwt = require('jsonwebtoken');

module.exports = (req, res, next) => {
  const token = req.headers.authorization?.split(' ')[1];
  if (!token) return res.status(401).json({ error: '請先登入' });

  try {
    req.user = jwt.verify(token, process.env.JWT_SECRET);
    next();
  } catch {
    res.status(401).json({ error: 'Token 無效或已過期' });
  }
};
```

## 提示

- 借書與還書涉及兩個 table 的更新，務必用 **PostgreSQL Transaction**（`BEGIN` / `COMMIT` / `ROLLBACK`）確保資料一致性
- `.env` 中的敏感資訊不可提交到 Git，在 `.gitignore` 加上 `.env`
- 用 `supertest` 測試時，可以在 `beforeAll` 先建立測試資料庫連線，`afterAll` 關閉
- 密碼雜湊用 `bcrypt.hash(password, 10)`，比對用 `bcrypt.compare(plain, hash)`

## 學習重點

**跟後端 API 的關聯：**

這個專案模擬真實生產環境中常見的「資源借用管理」場景，讓你體驗：

| 概念 | 在哪裡體現 |
|------|-----------|
| RESTful 設計 | 資源導向的路徑命名（`/loans`, `/books`） |
| 資料庫 Transaction | 借書/還書涉及多表更新，必須保持原子性 |
| 認證與授權 | JWT 讓 API 無狀態，適合前後端分離架構 |
| 輸入驗證 | 防止非法資料進入 DB，是第一道防線 |
| 整合測試 | 確保 API 端對端行為符合預期 |
