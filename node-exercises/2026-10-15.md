# 第 15 週今日 Node.js 練習題：任務管理 REST API（整合實戰）

## 題目說明

建立一個完整的「任務管理」後端 API，整合本課程前幾週學到的所有核心技術：Express、JWT 身份驗證、PostgreSQL 資料庫、輸入驗證、錯誤處理，以及 Jest 測試。這個專案模擬真實工作場景中的後端開發流程。

## 技術要求
- 概念：REST API 設計、JWT 身份驗證、資料庫 CRUD、Middleware 串接、錯誤處理、單元測試
- 需要的套件：`express`、`pg`（或 `better-sqlite3` 若無 PostgreSQL 環境）、`jsonwebtoken`、`bcryptjs`、`express-validator`、`jest`、`supertest`

## 具體任務

1. **初始化專案結構**
   建立以下目錄結構：
   ```
   task-manager/
   ├── src/
   │   ├── routes/
   │   │   ├── auth.js      # POST /register, POST /login
   │   │   └── tasks.js     # CRUD for /tasks
   │   ├── middleware/
   │   │   ├── auth.js      # JWT 驗證 middleware
   │   │   └── validate.js  # express-validator 錯誤回應
   │   ├── db/
   │   │   └── index.js     # 資料庫連線
   │   └── app.js           # Express app（不 listen，供測試使用）
   ├── server.js            # 啟動點（app.listen）
   └── tests/
       └── tasks.test.js
   ```

2. **實作身份驗證路由**
   - `POST /auth/register`：接收 `email`、`password`，密碼以 `bcryptjs` 雜湊後存入 DB
   - `POST /auth/login`：驗證帳密，回傳 JWT（有效期 1 小時）

3. **實作任務 CRUD 路由（需登入）**
   - `GET    /tasks`        — 取得目前使用者的所有任務
   - `POST   /tasks`        — 建立任務（`title` 必填，`status` 預設 `"pending"`）
   - `GET    /tasks/:id`    — 取得單一任務（需屬於目前使用者）
   - `PUT    /tasks/:id`    — 更新任務的 `title` 或 `status`
   - `DELETE /tasks/:id`    — 刪除任務

4. **加入輸入驗證**
   使用 `express-validator` 確保：
   - `email` 格式正確
   - `password` 長度至少 6 字元
   - `title` 不能為空字串
   - `status` 只能是 `"pending"`、`"in-progress"`、`"done"` 之一

5. **統一錯誤處理**
   加入全域 error handler middleware，所有錯誤統一回傳：
   ```json
   { "error": "錯誤訊息", "status": 400 }
   ```

6. **撰寫 Jest + Supertest 測試**
   至少覆蓋：
   - 未登入時呼叫 `GET /tasks` 應回傳 `401`
   - 成功登入後取得 token，再呼叫 `POST /tasks` 建立任務
   - 嘗試刪除不屬於自己的任務應回傳 `403`

## 範例

```js
// POST /auth/login 請求
// Body: { "email": "user@example.com", "password": "secret123" }

// 成功回應
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}

// POST /tasks 請求（需帶 Authorization: Bearer <token>）
// Body: { "title": "完成 Node.js 第 15 週練習" }

// 成功回應 201
{
  "id": 1,
  "title": "完成 Node.js 第 15 週練習",
  "status": "pending",
  "user_id": 42
}
```

## 提示
- 將 `app.js` 與 `server.js` 分開，`app.js` 只匯出 Express instance，測試時直接 `require('./src/app')` 搭配 `supertest`，不需真正啟動 port
- JWT secret 放在 `.env`，透過 `process.env.JWT_SECRET` 讀取，切勿 hardcode
- 用 `try/catch` + `next(err)` 將非同步錯誤傳給全域 error handler
- 任務查詢加上 `WHERE user_id = $1` 確保使用者隔離，避免水平越權

## 學習重點（跟後端 API 的關聯）

這道題整合了實際 API 開發的完整流程：
- **身份驗證**（JWT）：現代 RESTful API 的標準鑑權方式
- **資源隔離**：確保使用者只能操作自己的資料，是 API 安全的基本要求
- **輸入驗證**：防止惡意輸入或 DB 錯誤，是後端的第一道防線
- **統一錯誤格式**：讓前端能一致地處理錯誤，是 API 設計的良好實踐
- **測試分離**（app vs server）：是可測試架構設計的核心概念
