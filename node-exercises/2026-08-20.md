# 第 7 週今日 Node.js 練習題：設計一個書籍管理 REST API

## 題目說明

使用 Express 設計一套符合 REST 風格的書籍管理 API。本練習將讓你實際體驗如何規劃 URL 路由、HTTP 動詞的使用時機，以及統一的回應格式設計，這些都是後端工程師在日常工作中最常需要的技能。

## 技術要求
- 概念：RESTful 路由設計、HTTP 方法（GET / POST / PUT / PATCH / DELETE）、統一回應格式、HTTP 狀態碼
- 需要的套件：`express`

## 具體任務

1. **建立 Express 應用**：在 `books-api/index.js` 中啟動一個 Express 伺服器，監聽 3000 埠。

2. **使用記憶體陣列模擬資料庫**：定義一個 `books` 陣列，每本書的結構如下：
   ```js
   { id: 1, title: '書名', author: '作者', year: 2023, available: true }
   ```

3. **實作以下 5 個 RESTful 端點**：
   - `GET /books` — 取得所有書籍列表（支援 `?available=true` 查詢篩選）
   - `GET /books/:id` — 取得單一書籍，找不到回傳 404
   - `POST /books` — 新增書籍，缺少必填欄位回傳 400
   - `PUT /books/:id` — 完整更新書籍資料
   - `DELETE /books/:id` — 刪除書籍，並在回應中附上被刪除的資料

4. **統一回應格式**：所有端點都使用以下 JSON 結構回應：
   ```json
   { "success": true, "data": ..., "message": "..." }
   ```
   錯誤時：
   ```json
   { "success": false, "error": "錯誤說明" }
   ```

5. **撰寫 `books-api/README.md`**，列出所有端點的用途與範例 curl 指令。

## 範例

```js
// GET /books
// 回應 200
{
  "success": true,
  "data": [
    { "id": 1, "title": "Node.js 實戰", "author": "王小明", "year": 2023, "available": true }
  ],
  "message": "取得 1 本書籍"
}

// POST /books — 請求 body 缺少 title
// 回應 400
{
  "success": false,
  "error": "title、author、year 為必填欄位"
}

// DELETE /books/1
// 回應 200
{
  "success": true,
  "data": { "id": 1, "title": "Node.js 實戰", ... },
  "message": "書籍已刪除"
}
```

## 提示
- 用 `let nextId = 2` 作為自動遞增 ID 的計數器。
- 可用 `books.findIndex(b => b.id === parseInt(req.params.id))` 來搜尋書籍。
- `req.query.available` 的值是字串 `"true"`，不是布林值，需要做轉換。
- `express.json()` middleware 必須在路由之前掛載，否則 `req.body` 會是 undefined。
- 刪除時先用 `splice` 取出被刪除的元素再回傳，讓呼叫方知道刪了什麼。

## 學習重點（跟後端 API 的關聯）

REST API 是目前後端開發最廣泛使用的架構風格。學會這一套設計原則後，無論未來接手任何後端專案——電商平台、社群網站、SaaS 服務——你都能快速看懂既有 API 並且正確地擴充新端點。統一回應格式也是前後端合作的基礎共識，能大幅減少溝通成本。

## 進階挑戰（選做）

- **PATCH `/books/:id`**：只更新傳入的欄位（部分更新），而不是覆蓋整筆資料。
- **分頁功能**：為 `GET /books` 增加 `?page=1&limit=5` 分頁參數，並在回應中附上 `total`、`page`、`limit` 欄位。
- **搜尋功能**：`GET /books?search=Node` 可依書名或作者進行模糊搜尋（使用 `includes()`）。
- **錯誤中介層**：在 Express 中加入全域錯誤處理 middleware（4 個參數的 `(err, req, res, next)`），統一捕捉未預期的錯誤並回傳 500。
