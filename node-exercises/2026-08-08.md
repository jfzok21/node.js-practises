# 第 5 週今日 Node.js 練習題：Express 入門 — 建立你的第一個 Web 伺服器

## 題目說明

上週你用 Node.js 內建的 `http` 模組手刻了一個簡單的伺服器，這週要切換到業界最流行的框架 **Express**。Express 大幅簡化了路由設定、請求解析、回應格式化等繁瑣工作，是絕大多數 Node.js 後端 API 專案的起點。

本題目要你從零開始，用 Express 建立一個「個人書單管理」API，支援查詢與新增書籍。

---

## 技術要求

- **概念**：Express 路由（Route）、req / res 物件、JSON 回應、query string 解析、body 解析
- **需要的套件**：
  - `express` — Web 框架本體
  - `nodemon`（開發用，可選）— 自動重啟伺服器

---

## 具體任務

1. 初始化專案：在 `week5/` 資料夾執行 `npm init -y`，安裝 `express`。
2. 建立 `week5/server.js`，啟動 Express app，監聽 port `3000`。
3. 在記憶體中維護一個書單陣列（初始資料至少包含 3 本書）：
   ```js
   let books = [
     { id: 1, title: '深入淺出 Node.js', author: '樸靈', year: 2013 },
     { id: 2, title: 'Clean Code', author: 'Robert C. Martin', year: 2008 },
     { id: 3, title: '你不知道的 JS', author: 'Kyle Simpson', year: 2015 },
   ];
   ```
4. 實作以下路由：
   - `GET /` — 回傳 JSON `{ message: "書單 API 已啟動" }`
   - `GET /books` — 回傳全部書籍陣列
   - `GET /books?author=XXX` — 用 query string 過濾作者（不分大小寫）
   - `GET /books/:id` — 依 id 取得單本書；找不到時回傳 404 與錯誤訊息
   - `POST /books` — 接收 JSON body，新增一本書到陣列，回傳新增後的書籍物件（HTTP 201）

5. 確認 `POST /books` 需要解析 JSON body（使用 `express.json()` middleware）。
6. 啟動伺服器後，用 `curl` 或 Postman 手動測試每個端點。

## 提示

- `req.params.id` 取到的是**字串**，記得用 `Number()` 或 `parseInt()` 轉換後再比對。
- Query string 用 `req.query.author` 讀取；過濾時可用 `.toLowerCase()` 做不分大小寫比較。
- `res.status(404).json({ error: '找不到書籍' })` 可以鏈式呼叫設定狀態碼與回應體。
- 新增書籍時要自行維護遞增的 `id`（或用 `books.length + 1`，但注意刪除後會重複）。
- 別忘了在 `package.json` 的 `scripts` 加上 `"start": "node server.js"` 與 `"dev": "nodemon server.js"`。

## 學習重點（跟後端 API 的關聯）

Express 的路由系統直接對應到 RESTful API 設計的核心：
- **HTTP 方法**（GET / POST / PUT / DELETE）決定操作語意
- **路徑參數** `/:id` 指定資源
- **Query string** 用於過濾、排序、分頁
- **HTTP 狀態碼** 傳達操作結果（200 OK、201 Created、404 Not Found）

這些概念在你之後學習 Express Middleware、資料庫整合（PostgreSQL）、JWT 驗證時會一直用到，是整個後端技術棧的地基。

## 進階挑戰（選做）

1. **PUT /books/:id** — 更新指定書籍的資訊（若不存在回 404）。
2. **DELETE /books/:id** — 刪除指定書籍（成功回 204 No Content）。
3. 將書單資料抽離到獨立的 `books.js` 模組，用 `module.exports` 匯出，`server.js` 用 `require` 引入。
4. 加入基本輸入驗證：`POST /books` 時若缺少 `title` 或 `author`，回傳 HTTP 400 與說明訊息。
5. 用 `morgan` 套件加入請求 logging，觀察每次請求的 method、path、回應時間。
