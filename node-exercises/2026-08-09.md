# 第 5 週今日 Node.js 練習題：Express Router 與路由模組化

## 題目說明

上次你建立了一個單檔的 Express 書籍 API。隨著功能增加，所有路由擠在 `index.js` 會讓程式碼難以維護。本題練習使用 **Express Router** 將路由拆分成獨立模組，這是真實專案的標準結構。你將同時管理「書籍（books）」與「使用者（users）」兩個資源，體驗多路由模組並存的組織方式。

---

## 技術要求

- **概念**：`express.Router()`、路由模組化、`app.use()` 掛載前綴、路由中介層、`router.param()`
- **需要的套件**：
  ```bash
  npm init -y
  npm install express
  ```

---

## 具體任務

1. **建立以下目錄結構**
   ```
   router-api/
   ├── index.js          # 應用程式入口
   ├── routes/
   │   ├── books.js      # 書籍路由模組
   │   └── users.js      # 使用者路由模組
   └── package.json
   ```

2. **在 `routes/books.js` 建立書籍路由**
   - `GET /` — 取得所有書籍（支援 `?genre=` 查詢篩選）
   - `GET /:id` — 取得單本書
   - `POST /` — 新增書籍（必填欄位：`title`、`author`、`genre`）
   - `DELETE /:id` — 刪除書籍
   - 使用 `router.param('id', ...)` 統一處理「找不到書籍」的 404 邏輯

3. **在 `routes/users.js` 建立使用者路由**
   - `GET /` — 取得所有使用者
   - `GET /:id` — 取得單一使用者
   - `POST /` — 新增使用者（必填欄位：`name`、`email`）

4. **在 `index.js` 掛載兩個路由模組**
   - 書籍路由掛載於 `/api/books`
   - 使用者路由掛載於 `/api/users`
   - 加入一個 `GET /api/health` 端點回傳 `{ status: 'ok' }`

5. **加入 404 兜底路由與全域錯誤處理 middleware**

## 範例

```js
// routes/books.js
const express = require('express');
const router = express.Router();

let books = [
  { id: 1, title: '深入淺出 Node.js', author: '朴靈', genre: 'tech' },
  { id: 2, title: '原子習慣', author: 'James Clear', genre: 'self-help' },
];
let nextId = 3;

// 使用 router.param 統一處理 :id 查找，避免每個路由都重複
router.param('id', (req, res, next, id) => {
  const book = books.find(b => b.id === parseInt(id));
  if (!book) {
    return res.status(404).json({ success: false, message: `書籍 ID ${id} 不存在` });
  }
  req.book = book; // 將找到的書掛到 req 上，讓後續路由直接使用
  next();
});

// GET / (對應掛載後的 GET /api/books)
router.get('/', (req, res) => {
  const { genre } = req.query;
  const result = genre ? books.filter(b => b.genre === genre) : books;
  res.json({ success: true, count: result.length, data: result });
});

// GET /:id
router.get('/:id', (req, res) => {
  res.json({ success: true, data: req.book }); // req.book 由 router.param 設定
});

// POST /
router.post('/', (req, res) => {
  const { title, author, genre } = req.body;
  if (!title || !author || !genre) {
    return res.status(400).json({ success: false, message: 'title、author、genre 為必填欄位' });
  }
  const newBook = { id: nextId++, title, author, genre };
  books.push(newBook);
  res.status(201).json({ success: true, data: newBook });
});

// DELETE /:id
router.delete('/:id', (req, res) => {
  books = books.filter(b => b.id !== req.book.id);
  res.json({ success: true, message: `書籍「${req.book.title}」已刪除` });
});

module.exports = router;
```

```js
// index.js
const express = require('express');
const app = express();

const booksRouter = require('./routes/books');
const usersRouter = require('./routes/users');

app.use(express.json());

// 掛載路由模組
app.use('/api/books', booksRouter);
app.use('/api/users', usersRouter);

// 健康檢查
app.get('/api/health', (req, res) => {
  res.json({ status: 'ok', timestamp: new Date().toISOString() });
});

// 404 兜底路由（必須放在所有路由之後）
app.use((req, res) => {
  res.status(404).json({ success: false, message: `路由 ${req.method} ${req.path} 不存在` });
});

// 全域錯誤處理 middleware（4 個參數為固定簽名）
app.use((err, req, res, next) => {
  console.error(err.stack);
  res.status(500).json({ success: false, message: '伺服器內部錯誤' });
});

app.listen(3000, () => console.log('API 伺服器運行在 http://localhost:3000'));
```

**測試指令：**
```bash
# 健康檢查
curl http://localhost:3000/api/health

# 取得所有書籍
curl http://localhost:3000/api/books

# 依 genre 篩選
curl "http://localhost:3000/api/books?genre=tech"

# 取得單本書
curl http://localhost:3000/api/books/1

# 新增書籍
curl -X POST http://localhost:3000/api/books \
  -H "Content-Type: application/json" \
  -d '{"title":"Clean Code","author":"Robert C. Martin","genre":"tech"}'

# 刪除書籍
curl -X DELETE http://localhost:3000/api/books/2

# 測試 404
curl http://localhost:3000/api/unknown
```

## 提示

- `express.Router()` 建立的是一個「迷你 Express 應用」，可以有自己的 middleware 與路由
- `app.use('/api/books', booksRouter)` 掛載後，`booksRouter` 內的 `router.get('/')` 對應的是 `/api/books`，`router.get('/:id')` 對應 `/api/books/:id`
- `router.param('id', callback)` 只需定義一次，所有含 `:id` 的路由都會先執行它，是消除重複程式碼的好工具
- 全域錯誤處理 middleware 的簽名**一定要有 4 個參數** `(err, req, res, next)`，少一個 Express 就不會把它當作錯誤處理器

---

## 學習重點（跟後端 API 的關聯）

路由模組化是後端架構的基石。在大型專案中，通常的分層結構為：

```
routes/      ← 只負責路由定義（本週練習）
controllers/ ← 處理請求邏輯
services/    ← 業務邏輯
models/      ← 資料庫操作
```

`router.param()` 示範了「關注點分離」：把「查找資源」的邏輯抽出路由，讓每個處理器只專注自己的工作。這個概念在加入資料庫後更加重要，因為查找操作通常是非同步的。
