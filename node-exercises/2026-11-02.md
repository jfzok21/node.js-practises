# 第 17 週今日 Node.js 練習題：任務管理 REST API 實戰專案

## 題目說明

整合前幾週所學，從頭打造一個功能完整的「任務管理系統」後端 API。
系統需支援使用者註冊／登入（JWT）、CRUD 任務操作、輸入驗證，並具備完善的錯誤處理機制。

---

## 技術要求

- **概念**：REST API 設計、JWT 身份驗證、Middleware、輸入驗證、錯誤處理
- **需要的套件**：
  - `express` — HTTP 框架
  - `jsonwebtoken` — JWT 簽發與驗證
  - `bcryptjs` — 密碼雜湊
  - `joi` 或 `express-validator` — 輸入驗證
  - `uuid` — 產生任務 ID（若不使用資料庫）

---

## 具體任務

1. **專案初始化**
   - 建立 `task-manager/` 目錄，執行 `npm init -y`，安裝所需套件
   - 規劃目錄結構：`routes/`、`middleware/`、`controllers/`、`data/`

2. **使用者系統**
   - `POST /api/auth/register`：接受 `{ name, email, password }`，密碼用 bcrypt 雜湊後存入記憶體陣列（或 JSON 檔）
   - `POST /api/auth/login`：驗證帳密，成功後回傳 JWT（有效期 1 小時）

3. **JWT 驗證 Middleware**
   - 建立 `middleware/auth.js`：從 `Authorization: Bearer <token>` 標頭取得並驗證 token
   - 驗證失敗回傳 `401 Unauthorized`；驗證成功將 `req.user` 設為解碼後的使用者資訊

4. **任務 CRUD（需通過 JWT 驗證）**
   - `GET /api/tasks` — 列出目前使用者的所有任務
   - `POST /api/tasks` — 建立任務（`{ title, description?, priority? }`）
   - `PUT /api/tasks/:id` — 更新任務內容
   - `PATCH /api/tasks/:id/complete` — 將任務標記為已完成
   - `DELETE /api/tasks/:id` — 刪除任務（只能刪自己的）

5. **輸入驗證**
   - `title` 必填，長度 1–100 字元
   - `priority` 若存在，只允許 `"low"`、`"medium"`、`"high"`
   - 驗證失敗回傳 `400 Bad Request` 並附上明確錯誤訊息

6. **全域錯誤處理 Middleware**
   - 建立 `middleware/errorHandler.js`，統一處理所有未捕捉的錯誤
   - 回傳格式：`{ success: false, message: "...", stack: (僅開發環境顯示) }`

## 範例

```js
// POST /api/auth/register
// Request body:
{ "name": "Alice", "email": "alice@example.com", "password": "secret123" }

// Response 201:
{ "success": true, "message": "註冊成功" }

// POST /api/auth/login
// Response 200:
{ "success": true, "token": "eyJhbGci..." }

// POST /api/tasks  (帶 Authorization header)
// Request body:
{ "title": "完成作業", "priority": "high" }

// Response 201:
{
  "success": true,
  "task": {
    "id": "uuid-xxxx",
    "title": "完成作業",
    "priority": "high",
    "completed": false,
    "createdAt": "2026-11-02T08:00:00.000Z",
    "userId": "uuid-user"
  }
}

// PATCH /api/tasks/:id/complete
// Response 200:
{ "success": true, "task": { "id": "...", "completed": true, ... } }
```

## 提示

- 使用 `express.Router()` 分別管理 `authRouter` 與 `taskRouter`，再掛載到主 `app.js`
- 任務資料可用 `Map` 以 userId 為 key 分組儲存，避免不同使用者的任務混在一起
- 刪除或更新時，記得檢查任務是否屬於當前使用者（防止越權存取）
- `bcrypt.hash(password, 10)` 產生雜湊；`bcrypt.compare(plain, hash)` 驗證
- JWT secret 應存在環境變數 `JWT_SECRET`，避免硬寫在程式碼中

## 學習重點（跟後端 API 的關聯）

這道題涵蓋真實後端 API 的完整生命週期：

| 概念 | 對應場景 |
|------|----------|
| JWT Middleware | 保護需登入才能存取的路由 |
| 輸入驗證 | 防止壞資料進入系統，減少 bug |
| 錯誤處理 Middleware | 統一錯誤格式，前端易於解析 |
| 資料隔離 | 確保使用者只能操作自己的資源（多租戶概念）|
| REST 語意 | `PATCH /complete` 比 `POST /setComplete` 更符合 REST 設計 |

## 進階挑戰（選做）

1. **分頁**：`GET /api/tasks?page=1&limit=10` 支援任務列表分頁
2. **篩選排序**：`?priority=high&completed=false&sortBy=createdAt&order=desc`
3. **Refresh Token**：加入 refresh token 機制，讓使用者可以無縫更新過期的 access token
4. **Jest 測試**：使用 `supertest` 對每個端點撰寫整合測試，確保功能正確
