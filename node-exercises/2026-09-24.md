# 第 12 週今日 Node.js 練習題：使用 Jest 測試 REST API 路由

## 題目說明

在這週的練習中，你將學習如何使用 Jest 搭配 Supertest 對一個 Express REST API 進行單元測試與整合測試。測試是後端開發中不可或缺的一環，能確保 API 在各種情況下都能正確運作。

## 技術要求

- **概念：** 單元測試、整合測試、Mock、測試覆蓋率（coverage）
- **需要的套件：**
  - `jest`
  - `supertest`
  - `express`

## 具體任務

1. 初始化專案並安裝所需套件：
   ```bash
   npm init -y
   npm install express
   npm install --save-dev jest supertest
   ```

2. 建立一個簡單的 Express 應用程式 `app.js`，包含以下路由：
   - `GET /users` - 回傳所有使用者（使用記憶體陣列模擬資料庫）
   - `GET /users/:id` - 根據 ID 回傳單一使用者
   - `POST /users` - 新增使用者（需要 `name` 與 `email` 欄位）
   - `DELETE /users/:id` - 刪除指定使用者

3. 建立測試檔 `app.test.js`，撰寫以下測試案例：
   - 測試 `GET /users` 回傳狀態碼 200 及陣列格式資料
   - 測試 `GET /users/:id` 找到使用者時回傳 200，找不到時回傳 404
   - 測試 `POST /users` 成功新增時回傳 201，缺少欄位時回傳 400
   - 測試 `DELETE /users/:id` 成功刪除時回傳 200，使用者不存在時回傳 404

4. 在 `package.json` 中設定測試指令：
   ```json
   "scripts": {
     "test": "jest",
     "test:coverage": "jest --coverage"
   }
   ```

5. 執行測試並確保所有測試通過，然後執行覆蓋率報告。

## 範例

```js
// app.js
const express = require('express');
const app = express();
app.use(express.json());

let users = [
  { id: 1, name: 'Alice', email: 'alice@example.com' },
  { id: 2, name: 'Bob', email: 'bob@example.com' },
];
let nextId = 3;

app.get('/users', (req, res) => {
  res.json(users);
});

app.get('/users/:id', (req, res) => {
  const user = users.find(u => u.id === parseInt(req.params.id));
  if (!user) return res.status(404).json({ error: 'User not found' });
  res.json(user);
});

app.post('/users', (req, res) => {
  const { name, email } = req.body;
  if (!name || !email) return res.status(400).json({ error: 'Name and email are required' });
  const newUser = { id: nextId++, name, email };
  users.push(newUser);
  res.status(201).json(newUser);
});

app.delete('/users/:id', (req, res) => {
  const index = users.findIndex(u => u.id === parseInt(req.params.id));
  if (index === -1) return res.status(404).json({ error: 'User not found' });
  users.splice(index, 1);
  res.json({ message: 'User deleted' });
});

module.exports = app;
```

```js
// app.test.js
const request = require('supertest');
const app = require('./app');

describe('GET /users', () => {
  it('should return status 200 and an array', async () => {
    const res = await request(app).get('/users');
    expect(res.statusCode).toBe(200);
    expect(Array.isArray(res.body)).toBe(true);
  });
});

describe('GET /users/:id', () => {
  it('should return 200 for existing user', async () => {
    const res = await request(app).get('/users/1');
    expect(res.statusCode).toBe(200);
    expect(res.body).toHaveProperty('name');
  });

  it('should return 404 for non-existing user', async () => {
    const res = await request(app).get('/users/9999');
    expect(res.statusCode).toBe(404);
  });
});

describe('POST /users', () => {
  it('should create a user and return 201', async () => {
    const res = await request(app)
      .post('/users')
      .send({ name: 'Carol', email: 'carol@example.com' });
    expect(res.statusCode).toBe(201);
    expect(res.body).toHaveProperty('id');
  });

  it('should return 400 if name or email is missing', async () => {
    const res = await request(app).post('/users').send({ name: 'Dave' });
    expect(res.statusCode).toBe(400);
  });
});

describe('DELETE /users/:id', () => {
  it('should return 200 when user is deleted', async () => {
    const res = await request(app).delete('/users/2');
    expect(res.statusCode).toBe(200);
  });

  it('should return 404 for non-existing user', async () => {
    const res = await request(app).delete('/users/9999');
    expect(res.statusCode).toBe(404);
  });
});
```

## 提示

- 在 `app.js` 最後使用 `module.exports = app` 匯出，而不是呼叫 `app.listen()`，讓 Supertest 可以控制伺服器的啟動與關閉。
- 若測試之間共用資料（如記憶體陣列），注意測試執行順序可能影響結果，可使用 `beforeEach` 重置資料。
- `describe` 用於分組相關測試，`it`（或 `test`）用於定義個別測試案例。
- `expect(value).toBe(expected)` 用於嚴格相等比較，`toHaveProperty` 用於檢查物件是否包含指定屬性。

## 學習重點

**與後端 API 的關聯：**

測試是生產環境後端 API 的基石。在真實專案中：
- 單元測試確保每個函式（如資料驗證、業務邏輯）單獨運作正確。
- 整合測試（如本練習）確保 HTTP 路由、中介層、資料庫互動能正確協同運作。
- 測試覆蓋率報告幫助團隊了解哪些程式碼路徑尚未被測試，降低上線前的風險。
- 持續整合（CI）流水線通常在每次提交時自動執行測試，防止回歸錯誤進入主分支。

## 進階挑戰（選做）

1. **Mock 資料庫**：將使用者資料移到獨立模組（如 `userService.js`），並在測試中使用 `jest.mock()` 模擬此模組，測試路由與服務層的隔離性。

2. **測試中間件**：撰寫一個簡單的身份驗證中間件（如檢查 `Authorization` header），並用 Jest 測試有/無 token 時的不同回應。

3. **覆蓋率目標**：執行 `npm run test:coverage`，嘗試讓語句覆蓋率（Statements）達到 90% 以上。

4. **測試資料隔離**：使用 `beforeEach` 在每個測試前重置使用者陣列，確保測試之間互不影響。
