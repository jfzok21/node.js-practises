# 第 19 週今日 Node.js 練習題：建立任務管理 REST API（附 JWT 驗證與完整測試）

## 題目說明

實作一個完整的「任務管理系統」後端 API，整合先前所學的所有核心技術：Express、REST API 設計、JWT 身份驗證、輸入驗證、錯誤處理，以及 Jest 單元測試。這是一個貼近真實工作場景的全端練習。

## 具體任務

### 1. 專案初始化

建立 `task-manager/` 目錄，初始化 npm，安裝必要套件：

```bash
mkdir task-manager && cd task-manager
npm init -y
npm install express jsonwebtoken bcryptjs express-validator
npm install --save-dev jest supertest
```

建立以下檔案結構：

```
task-manager/
├── src/
│   ├── app.js          ← Express app（不含 listen）
│   ├── server.js       ← 啟動點（app.listen）
│   ├── middleware/
│   │   ├── auth.js     ← JWT 驗證 middleware
│   │   └── validate.js ← express-validator 錯誤收集
│   ├── routes/
│   │   ├── auth.js     ← POST /auth/register, POST /auth/login
│   │   └── tasks.js    ← CRUD /tasks
│   └── data/
│       └── store.js    ← 以 Map 模擬記憶體資料庫
└── tests/
    ├── auth.test.js
    └── tasks.test.js
```

### 2. 記憶體資料庫（`src/data/store.js`）

用 `Map` 分別儲存使用者與任務，提供以下函式：

```js
// 使用者相關
createUser(email, hashedPassword)   // → { id, email, password }
findUserByEmail(email)              // → user 或 undefined

// 任務相關
createTask(userId, title, description) // → { id, userId, title, description, done: false, createdAt }
getTasksByUser(userId)                 // → task[]
getTaskById(id)                        // → task 或 undefined
updateTask(id, fields)                 // → 更新後的 task 或 null
deleteTask(id)                         // → true 或 false
```

---

### 3. 身份驗證路由（`src/routes/auth.js`）

#### `POST /auth/register`

- 接受 `{ email, password }`
- 以 `bcryptjs.hash(password, 10)` 雜湊密碼
- 若 email 重複回傳 `409 Conflict`
- 成功回傳 `201` 與 `{ message, userId }`

#### `POST /auth/login`

- 驗證 email / password
- 成功後以 `jsonwebtoken.sign({ userId, email }, SECRET, { expiresIn: '1h' })` 產生 token
- 回傳 `200` 與 `{ token }`

### 5. 任務路由（`src/routes/tasks.js`），全部需驗證

| Method | Path        | 說明                                 |
|--------|-------------|--------------------------------------|
| GET    | /tasks      | 取得目前使用者的所有任務             |
| POST   | /tasks      | 新增任務（`title` 必填）             |
| PATCH  | /tasks/:id  | 更新 `title`、`description`、`done` |
| DELETE | /tasks/:id  | 刪除任務（只能刪自己的）             |

> 嘗試操作他人任務回傳 `403 Forbidden`，找不到回傳 `404`。

---

### 6. 輸入驗證（`express-validator`）

在 `register` 與 `create task` 路由加入驗證：

```js
body('email').isEmail().withMessage('請輸入有效的 email')
body('password').isLength({ min: 6 }).withMessage('密碼至少 6 位')
body('title').notEmpty().withMessage('標題不可為空')
```

驗證失敗統一回傳 `422 Unprocessable Entity`，格式：

```json
{ "errors": [{ "field": "email", "message": "請輸入有效的 email" }] }
```

## 範例

```js
// 1. 註冊
POST /auth/register
{ "email": "alice@example.com", "password": "secret123" }
// → 201 { "message": "註冊成功", "userId": "u_abc123" }

// 2. 登入取得 token
POST /auth/login
{ "email": "alice@example.com", "password": "secret123" }
// → 200 { "token": "eyJhbGc..." }

// 3. 新增任務（帶 Authorization header）
POST /tasks
Authorization: Bearer eyJhbGc...
{ "title": "寫 API 文件", "description": "OpenAPI 3.0 規格" }
// → 201 { "id": "t_xyz", "title": "寫 API 文件", "done": false, ... }

// 4. 標記完成
PATCH /tasks/t_xyz
Authorization: Bearer eyJhbGc...
{ "done": true }
// → 200 { "id": "t_xyz", "done": true, ... }
```

## 提示

- `app.js` 只匯出 Express app，`server.js` 才呼叫 `app.listen()`，這樣 `supertest` 才能在不占用 port 的情況下測試。
- `SECRET` 可先硬寫在常數，不需要用環境變數（真實專案中必須）。
- 用 `crypto.randomUUID()` 或簡單的遞增數字產生 ID 皆可。
- 若 `PATCH` 請求 body 中沒有帶某欄位，不要清空原有值。

## 進階挑戰（選做）

1. **分頁**：`GET /tasks?page=1&limit=10`，回傳 `{ data, total, page, totalPages }`。
2. **篩選**：支援 `GET /tasks?done=false` 只回傳未完成任務。
3. **重新整理 token（Refresh Token）**：登入時同時回傳 `accessToken`（15 分鐘）與 `refreshToken`（7 天），並新增 `POST /auth/refresh` 端點。
4. **速率限制**：用 `express-rate-limit` 限制 `/auth/login` 每分鐘最多 5 次請求，防止暴力破解。
