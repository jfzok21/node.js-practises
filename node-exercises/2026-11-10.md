# 第 19 週今日 Node.js 練習題：API 速率限制與快取層

## 題目說明

建立一個具備速率限制（Rate Limiting）與記憶體快取（In-memory Cache）的 Express API 服務。模擬真實後端常見的兩層防護：防止短時間大量請求打爆伺服器，以及減少重複計算以提升效能。所有功能使用純 Node.js 實作，不依賴外部 Redis。

## 技術要求
- **概念**：中間件（Middleware）、滑動視窗速率限制、TTL 快取、Map 資料結構
- **需要的套件**：`express`（無需其他外部套件）

## 具體任務

1. **實作 Rate Limiter 中間件**
   - 每個 IP 在 60 秒的滑動視窗內最多允許 10 次請求
   - 超過上限時回傳 HTTP 429，body 為 `{ error: "Too Many Requests", retryAfter: <秒> }`
   - 在 response header 加入：
     ```
     X-RateLimit-Limit: 10
     X-RateLimit-Remaining: <剩餘次數>
     X-RateLimit-Reset: <Unix timestamp，視窗重置時間>
     ```

2. **實作 TTL 快取中間件**
   - 只快取 `GET` 請求
   - 快取 key = `req.method + req.originalUrl`
   - 預設 TTL 為 30 秒；命中快取時加入 header `X-Cache: HIT`，否則 `X-Cache: MISS`
   - 使用 `Map` 儲存 `{ data, expiresAt }` 物件；可在背景以 `setInterval` 清理過期項目

3. **建立示範 API 路由**
   ```
   GET  /api/products          → 回傳假商品列表（模擬耗時 200ms 的 DB 查詢）
   GET  /api/products/:id      → 回傳單一商品
   POST /api/products          → 新增商品（不套用快取，但套用速率限制）
   GET  /api/cache/stats        → 回傳快取命中率統計（hits / misses / size）
   DELETE /api/cache            → 清空所有快取（管理用）
   ```

4. **整合兩層中間件**
   - 速率限制套用於所有路由
   - 快取只套用於 `GET /api/products*`

5. **優雅關機（Graceful Shutdown）**
   - 監聽 `SIGTERM` / `SIGINT`，清除所有 `setInterval`，再關閉伺服器

## 範例

```js
// middleware/rateLimit.js
function createRateLimiter({ windowMs = 60000, max = 10 } = {}) {
  const requests = new Map(); // ip -> [timestamp, ...]

  return (req, res, next) => {
    const ip = req.ip;
    const now = Date.now();
    const windowStart = now - windowMs;

    // 只保留視窗內的請求時間戳
    const timestamps = (requests.get(ip) || []).filter(t => t > windowStart);
    timestamps.push(now);
    requests.set(ip, timestamps);

    const remaining = Math.max(0, max - timestamps.length);
    const resetAt = Math.ceil((timestamps[0] + windowMs) / 1000);

    res.setHeader('X-RateLimit-Limit', max);
    res.setHeader('X-RateLimit-Remaining', remaining);
    res.setHeader('X-RateLimit-Reset', resetAt);

    if (timestamps.length > max) {
      return res.status(429).json({
        error: 'Too Many Requests',
        retryAfter: resetAt - Math.ceil(now / 1000),
      });
    }
    next();
  };
}

module.exports = { createRateLimiter };
```

```js
// middleware/cache.js
function createCache({ ttl = 30000 } = {}) {
  const store = new Map(); // key -> { data, expiresAt }
  let hits = 0, misses = 0;

  const interval = setInterval(() => {
    const now = Date.now();
    for (const [key, entry] of store) {
      if (entry.expiresAt < now) store.delete(key);
    }
  }, 10000);
  interval.unref(); // 不阻止 process 結束

  function middleware(req, res, next) {
    if (req.method !== 'GET') return next();
    const key = req.method + req.originalUrl;
    const entry = store.get(key);

    if (entry && entry.expiresAt > Date.now()) {
      hits++;
      res.setHeader('X-Cache', 'HIT');
      return res.json(entry.data);
    }

    misses++;
    res.setHeader('X-Cache', 'MISS');

    // 攔截 res.json，將結果存入快取
    const originalJson = res.json.bind(res);
    res.json = (body) => {
      store.set(key, { data: body, expiresAt: Date.now() + ttl });
      return originalJson(body);
    };
    next();
  }

  middleware.stats = () => ({ hits, misses, size: store.size });
  middleware.clear = () => store.clear();

  return middleware;
}

module.exports = { createCache };
```

## 提示
- `res.json` 是可以被替換的函式，透過猴子補丁（monkey-patching）攔截回應是快取中間件的常見手法
- `interval.unref()` 讓計時器不阻塞 Node.js event loop 結束，在測試環境特別重要
- 測試速率限制時，可暫時將 `max` 設為 3，不必等到第 11 次
- 使用 `Map` 而非物件（`{}`）的好處：有 `size` 屬性、鍵的型別更安全、迭代順序穩定

## 學習重點（跟後端 API 的關聯）

| 概念 | 本練習的體現 |
|------|-------------|
| 速率限制 | 保護 API 免於被爬蟲或惡意用戶打爆，SaaS 計費也常依此實作 |
| 快取層 | 減少資料庫壓力，同一資料 30 秒內只查一次 DB |
| 中間件鏈 | 可插拔設計，限流與快取互不耦合，易於測試與替換 |
| 優雅關機 | 生產環境部署（如 Kubernetes）需要 SIGTERM 處理，確保請求不中斷 |
| Header 語意 | `X-RateLimit-*` 是 IETF 草案標準，了解它有助於整合第三方 API |

## 進階挑戰（選做）

1. **分路由設定不同限制**：公開路由 60/min，登入後路由 300/min（依 `req.user?.id` 分組）
2. **快取失效（Cache Invalidation）**：`POST /api/products` 成功後，自動清除 `/api/products` 的快取
3. **LRU 快取**：當 `store.size` 超過 100 時，自動淘汰最久未存取的項目
4. **Redis 整合**：將記憶體 `Map` 替換為 `ioredis` 客戶端，讓多個 Node 程序共享快取與限流狀態
5. **單元測試**：用 Jest + Supertest 測試中間件，模擬快速連打場景確認 429 正確觸發
