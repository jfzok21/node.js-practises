# 第 15 週今日 Node.js 練習題：任務管理 API 整合實戰

## 題目說明

綜合前幾週所學，打造一個具備完整功能的「任務管理 REST API」。此專案整合了 Express、PostgreSQL、JWT 身份驗證、輸入驗證、檔案上傳與 Jest 測試，模擬真實後端開發情境。

---

## 技術要求

- **概念**：REST API 設計、JWT 驗證、Middleware 串聯、資料庫 CRUD、單元測試
- **需要的套件**：
  - `express` — HTTP 伺服器框架
  - `pg` — PostgreSQL 客戶端
  - `jsonwebtoken` — JWT 產生與驗證
  - `bcryptjs` — 密碼雜湊
  - `express-validator` — 輸入驗證
  - `multer` — 附件上傳
  - `jest` + `supertest` — API 測試

---

## 具體任務

### 1. 資料庫結構設計

建立 `schema.sql`，包含以下兩張表：

```sql
-- 使用者表
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 任務表
CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  title VARCHAR(255) NOT NULL,
  description TEXT,
  status VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending', 'in_progress', 'done')),
  attachment_url VARCHAR(500),
  due_date DATE,
  created_at TIMESTAMP DEFAULT NOW()
);
```

### 2. 身份驗證模組 (`src/auth/`)

- `POST /api/auth/register`：接受 `email`、`password`，驗證格式後以 bcrypt 雜湊密碼，寫入 DB，回傳 JWT
- `POST /api/auth/login`：驗證帳密，回傳 JWT（有效期 24 小時）
- 建立 `authMiddleware.js`：驗證 `Authorization: Bearer <token>` header，將 `req.user` 注入 userId

### 3. 任務 CRUD API (`src/tasks/`)

所有路由需通過 `authMiddleware`，只能操作「自己的」任務：

| 方法   | 路徑              | 說明                        |
|--------|-------------------|-----------------------------|
| GET    | `/api/tasks`      | 列出任務（支援 `?status=` 篩選） |
| POST   | `/api/tasks`      | 新增任務                    |
| GET    | `/api/tasks/:id`  | 取得單一任務                |
| PATCH  | `/api/tasks/:id`  | 更新任務（部分欄位）        |
| DELETE | `/api/tasks/:id`  | 刪除任務                    |

### 4. 附件上傳

- `POST /api/tasks/:id/attachment`：用 multer 接收圖片（限 5MB，僅允許 jpg/png），儲存至 `uploads/` 資料夾，將路徑更新至 `tasks.attachment_url`

### 5. 輸入驗證

使用 `express-validator` 在 POST/PATCH 路由加入驗證：
- `email`：需為有效 email 格式
- `password`：至少 8 字元
- `title`：不可為空，最多 255 字元
- `status`：必須是 `pending`、`in_progress`、`done` 其中之一
- `due_date`：需為有效日期格式（`YYYY-MM-DD`）

### 6. 統一錯誤處理 Middleware

建立 `src/middleware/errorHandler.js`：

```js
// 捕捉所有未處理的錯誤，回傳統一格式
// { success: false, message: "...", errors: [...] }
```

### 7. Jest 測試（至少 3 個測試案例）

建立 `tests/tasks.test.js`，使用 `supertest` 測試：
1. 未帶 JWT 呼叫 `/api/tasks` 應回傳 `401`
2. 成功新增任務後應回傳 `201` 及任務物件
3. 嘗試刪除他人任務應回傳 `403`

## 範例

```js
// POST /api/tasks 請求
{
  "title": "完成 Node.js 練習",
  "description": "整合實戰專案",
  "status": "in_progress",
  "due_date": "2026-10-31"
}

// 成功回應 201
{
  "success": true,
  "data": {
    "id": 42,
    "title": "完成 Node.js 練習",
    "status": "in_progress",
    "due_date": "2026-10-31",
    "created_at": "2026-10-19T10:00:00.000Z"
  }
}

// 驗證失敗回應 400
{
  "success": false,
  "message": "驗證失敗",
  "errors": [
    { "field": "title", "message": "標題不可為空" }
  ]
}
```

## 提示

- 使用 `dotenv` 管理 DB 連線字串與 JWT_SECRET，不要寫死在程式碼中
- JWT payload 只需存放 `{ userId: id }`，避免放入敏感資訊
- Multer 的 `fileFilter` 可用 `file.mimetype` 判斷檔案類型
- 資料庫查詢一律使用參數化查詢（`$1, $2`），防止 SQL Injection
- 測試時可使用 SQLite in-memory 或 mock pg 模組以避免依賴真實 DB

## 學習重點（跟後端 API 的關聯）

這道題整合了業界後端開發的核心流程：

1. **認證層（Auth）**：現代 API 幾乎都使用 JWT 做 stateless 驗證，不需 session
2. **授權檢查（Authorization）**：資源操作前驗證擁有權，防止 IDOR 漏洞
3. **輸入驗證**：在業務邏輯執行前攔截非法資料，保護資料庫完整性
4. **統一錯誤回應**：前端可依固定格式解析錯誤，提升 API 可用性
5. **自動化測試**：CI/CD 流程中測試覆蓋率是 code review 的重要指標

## 進階挑戰（選做）

1. **分頁功能**：在 `GET /api/tasks` 加入 `?page=1&limit=10` 參數，回傳 `total`、`page`、`data[]`
2. **排序功能**：支援 `?sort=due_date&order=asc`
3. **軟刪除**：新增 `deleted_at` 欄位，DELETE 只更新時間戳，不實際刪除資料列
4. **Rate Limiting**：使用 `express-rate-limit` 限制登入端點每分鐘最多 10 次，防暴力破解
5. **Docker Compose**：撰寫 `docker-compose.yml` 同時啟動 Node.js app 與 PostgreSQL
