# 第 10 週今日 Node.js 練習題：輸入驗證與錯誤處理

## 題目說明

建立一個 Express API，針對使用者註冊端點實作完整的輸入驗證與統一錯誤處理機制。透過這個練習，你將學會如何防止無效資料進入系統，並以一致的格式回傳錯誤訊息。

---

## 技術要求

- **概念**：輸入驗證、自訂錯誤類別、Express 錯誤處理 middleware、HTTP 狀態碼語意
- **需要的套件**：
  - `express`
  - `joi` 或 `zod`（擇一，用於 schema 驗證）

---

## 具體任務

1. **初始化專案**
   - `npm init -y`
   - 安裝 `express` 與 `joi`（或 `zod`）

2. **建立自訂錯誤類別**
   - 建立 `ValidationError`（extends Error），帶有 `statusCode: 400` 與 `errors` 陣列
   - 建立 `NotFoundError`（extends Error），帶有 `statusCode: 404`

3. **建立驗證 schema**
   使用 joi 或 zod 定義 `registerSchema`，規則如下：
   - `username`：字串，3–20 字元，僅允許英數字與底線，必填
   - `email`：合法 email 格式，必填
   - `password`：字串，至少 8 字元，需含大小寫字母與數字，必填
   - `age`：整數，18–120，選填

4. **建立驗證 middleware**
   ```js
   // validateBody(schema) middleware
   // 若驗證失敗，丟出 ValidationError 並附上所有欄位錯誤
   ```

5. **建立路由**
   - `POST /api/register`：套用驗證 middleware，驗證通過後回傳 `201` 與使用者資料（密碼不回傳）
   - `GET /api/users/:id`：若 id 不是正整數，丟出 ValidationError；若查無用戶，丟出 NotFoundError

6. **建立統一錯誤處理 middleware**
   將所有錯誤統一格式化為：
   ```json
   {
     "success": false,
     "error": {
       "code": "VALIDATION_ERROR",
       "message": "輸入資料有誤",
       "details": [...]
     }
   }
   ```

---

## 範例

**請求（成功）：**
```js
POST /api/register
{
  "username": "john_doe",
  "email": "john@example.com",
  "password": "Secret123",
  "age": 25
}
```

**回應（201）：**
```json
{
  "success": true,
  "data": {
    "username": "john_doe",
    "email": "john@example.com",
    "age": 25
  }
}
```

**請求（失敗）：**
```js
POST /api/register
{
  "username": "jo",
  "email": "not-an-email",
  "password": "weak"
}
```

**回應（400）：**
```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "輸入資料有誤",
    "details": [
      { "field": "username", "message": "至少需要 3 個字元" },
      { "field": "email", "message": "必須是合法的 email 格式" },
      { "field": "password", "message": "密碼需至少 8 碼且包含大小寫字母與數字" }
    ]
  }
}
```

---

## 提示

- joi 用 `error.details` 陣列回傳所有欄位錯誤，zod 用 `error.errors`
- 密碼複雜度可用 joi 的 `.pattern(/^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}$/)` 驗證
- Express 錯誤處理 middleware 有 **四個參數**：`(err, req, res, next)`，缺一不可
- 回傳錯誤時記得使用 `err.statusCode || 500`，避免非預期錯誤洩漏

---

## 學習重點（跟後端 API 的關聯）

輸入驗證是後端 API 的**第一道防線**：
- 防止無效資料進入資料庫（例如 SQL injection、型別錯誤）
- 統一的錯誤格式讓前端可以一致地處理錯誤，不需要針對每個端點寫不同的錯誤解析邏輯
- 自訂錯誤類別讓程式碼更易讀，也讓錯誤處理集中在一個地方（單一責任原則）
- 這個模式直接對應 NestJS 的 `ValidationPipe` 與 `ExceptionFilter`

---

## 進階挑戰（選做）

1. **非同步驗證**：在 middleware 中額外檢查 email 是否已被使用（用一個假的 Set 模擬資料庫），若重複則回傳 `409 Conflict`
2. **請求 logging**：建立一個 middleware，記錄每個請求的方法、路徑、狀態碼與耗時（ms）
3. **rate limiting 概念**：用 `Map` 追蹤每個 IP 的請求次數，超過 5 次/分鐘回傳 `429 Too Many Requests`
4. **Zod 整合**：改用 `zod` 完成同樣的驗證邏輯，比較兩者的差異
