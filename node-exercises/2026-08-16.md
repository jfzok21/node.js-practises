# 第 6 週今日 Node.js 練習題：Express Middleware 實戰

## 題目說明

本週主題是 **Express Middleware（中介軟體）**。Middleware 是 Express 應用程式的核心，每個請求在到達路由處理器之前，都可以經過一系列的中介軟體進行處理。你將實作幾種常見的自訂 middleware，深入理解請求生命週期。

---

## 技術要求

- **概念：** Express middleware 機制、`next()`、錯誤處理 middleware、`app.use()`
- **需要的套件：**
  - `express`
  - `morgan`（選用，HTTP 請求記錄器）

---

## 具體任務

1. **建立專案結構**
   - 建立 `week6-middleware/` 資料夾
   - 初始化 `package.json`（`npm init -y`）
   - 安裝 `express` 與 `morgan`

2. **實作 Logger Middleware（自訂）**
   - 記錄每個請求的方法（GET/POST/...）、路徑、時間戳記
   - 格式：`[2026-08-16T10:30:00.000Z] GET /api/users`
   - 將此 middleware 套用到「所有路由」

3. **實作 Auth Middleware**
   - 讀取請求 header 中的 `x-api-key`
   - 若不存在或不等於 `secret-key`，回傳 `401 Unauthorized`
   - 僅套用到 `/api/protected` 路由

4. **實作 Request Timing Middleware**
   - 計算請求處理所花費的毫秒數
   - 在 response header 加入 `X-Response-Time: <ms>ms`

5. **實作全域錯誤處理 Middleware**
   - 接收四個參數：`(err, req, res, next)`
   - 回傳 `{ error: err.message, status: err.status || 500 }`
   - 測試：建立一個會拋出錯誤的路由 `/api/crash`

---

## 範例

```js
// middleware/logger.js
function logger(req, res, next) {
  const timestamp = new Date().toISOString();
  console.log(`[${timestamp}] ${req.method} ${req.path}`);
  next(); // 一定要呼叫 next()，否則請求會卡住！
}

module.exports = logger;
```

```js
// middleware/auth.js
function auth(req, res, next) {
  const apiKey = req.headers['x-api-key'];
  if (!apiKey || apiKey !== 'secret-key') {
    return res.status(401).json({ error: 'Unauthorized: invalid API key' });
  }
  next();
}

module.exports = auth;
```

```js
// app.js
const express = require('express');
const logger = require('./middleware/logger');
const auth = require('./middleware/auth');

const app = express();
app.use(express.json());
app.use(logger); // 套用到所有路由

// 公開路由
app.get('/api/public', (req, res) => {
  res.json({ message: 'Anyone can see this!' });
});

// 受保護路由（需要 auth middleware）
app.get('/api/protected', auth, (req, res) => {
  res.json({ message: 'Welcome, authenticated user!' });
});

// 測試錯誤
app.get('/api/crash', (req, res, next) => {
  const err = new Error('Something went wrong!');
  err.status = 500;
  next(err); // 傳遞給錯誤處理 middleware
});

// 錯誤處理 middleware（必須放在最後）
app.use((err, req, res, next) => {
  res.status(err.status || 500).json({
    error: err.message,
    status: err.status || 500,
  });
});

app.listen(3000, () => console.log('Server running on port 3000'));
```

**預期測試結果：**
```bash
# 公開路由（成功）
curl http://localhost:3000/api/public
# → {"message":"Anyone can see this!"}

# 受保護路由（無 key，失敗）
curl http://localhost:3000/api/protected
# → {"error":"Unauthorized: invalid API key"}

# 受保護路由（有正確 key，成功）
curl -H "x-api-key: secret-key" http://localhost:3000/api/protected
# → {"message":"Welcome, authenticated user!"}

# 錯誤路由
curl http://localhost:3000/api/crash
# → {"error":"Something went wrong!","status":500}
```

## 提示

- Middleware 的執行順序很重要，`app.use()` 的呼叫順序決定執行順序
- **一定要呼叫 `next()`**，否則請求會永遠卡在該 middleware 不繼續
- 錯誤處理 middleware 必須有**四個參數** `(err, req, res, next)`，Express 才能辨識它
- `return res.json(...)` 中的 `return` 可防止繼續執行後面的程式碼
- Route-level middleware（路由級）可以寫成 `app.get('/path', middleware, handler)`

---

## 學習重點（跟後端 API 的關聯）

Middleware 是真實後端 API 開發中最重要的設計模式之一：

| Middleware 類型 | 實際應用場景 |
|---|---|
| Logger | 記錄 API 存取日誌，用於除錯與監控 |
| Auth | JWT 驗證、API Key 驗證，保護私有資源 |
| Rate Limiting | 限制每個 IP 的請求次數，防止濫用 |
| Body Parser | 解析 JSON / form data 請求體 |
| CORS | 允許前端跨域請求 |
| Error Handler | 統一 API 錯誤格式，避免洩漏系統細節 |

你在第 9 週學習 JWT 驗證時，Auth Middleware 的模式將會大量使用！

## 進階挑戰（選做）

1. **Rate Limiting Middleware**：同一個 IP 在 60 秒內最多只能請求 10 次，超過回傳 `429 Too Many Requests`（使用 `Map` 物件儲存計數，不需要額外套件）

2. **Request ID Middleware**：為每個請求產生唯一 ID（可用 `Date.now() + Math.random()`），加入 header `X-Request-ID`，並在 logger 中一起記錄

3. **Conditional Middleware**：實作一個 `unless()` 輔助函式，讓某個 middleware 可以排除指定路徑（例如：`app.use(unless('/api/health', auth))`）
