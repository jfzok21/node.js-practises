# 第 19 週今日 Node.js 練習題：電商購物車與訂單管理 API

## 題目說明

實作一個電商後端的核心功能：購物車（Cart）與訂單（Order）管理系統。使用者登入後可將商品加入購物車、修改數量、結帳產生訂單，並可追蹤訂單狀態。這個實戰練習整合 JWT 認證、複雜業務邏輯（庫存檢查、金額計算）與狀態機（order status）設計模式。

---

## 技術要求

- **概念：** 購物車狀態管理、訂單狀態機、業務邏輯封裝、Transaction-like 操作、RESTful 資源設計
- **需要的套件：**
  - `express` — HTTP 框架
  - `express-validator` — 輸入驗證
  - `jsonwebtoken` — JWT 簽發與驗證
  - `bcrypt` — 密碼雜湊
  - `uuid` 或 `crypto.randomUUID()` — 產生唯一 ID
  - （選用）`pg` — 整合 PostgreSQL；否則使用 JSON 檔案模擬資料庫

## 具體任務

### 1. 資料結構設計

```js
// 使用者
{ id, username, email, passwordHash, createdAt }

// 商品（Products）— 預先建立測試資料
{ id, name, price, stock, description }

// 購物車項目（CartItem）— 每位使用者一個購物車（in-memory 或 JSON）
{ id, userId, productId, quantity, addedAt }

// 訂單（Order）
{ id, userId, items: [{ productId, name, price, quantity }], totalAmount, status, createdAt, updatedAt }
// status: 'pending' | 'confirmed' | 'shipped' | 'delivered' | 'cancelled'
```

### 2. 認證路由 `/auth`

| 方法 | 路徑             | 說明           |
|------|------------------|----------------|
| POST | `/auth/register` | 註冊           |
| POST | `/auth/login`    | 登入，回傳 JWT |

### 3. 商品路由 `/products`（公開，不需登入）

| 方法 | 路徑             | 說明                         |
|------|------------------|------------------------------|
| GET  | `/products`      | 取得商品列表（支援搜尋/分頁） |
| GET  | `/products/:id`  | 取得單一商品詳情             |

### 4. 購物車路由 `/cart`（需 JWT）

| 方法   | 路徑             | 說明                           |
|--------|------------------|--------------------------------|
| GET    | `/cart`          | 取得目前使用者的購物車         |
| POST   | `/cart/items`    | 新增商品到購物車               |
| PUT    | `/cart/items/:productId` | 更新商品數量（0 = 移除） |
| DELETE | `/cart`          | 清空購物車                     |

### 5. 訂單路由 `/orders`（需 JWT）

| 方法  | 路徑              | 說明                         |
|-------|-------------------|------------------------------|
| POST  | `/orders/checkout`| 結帳（將購物車轉為訂單）     |
| GET   | `/orders`         | 取得使用者所有訂單           |
| GET   | `/orders/:id`     | 取得單一訂單詳情             |
| PATCH | `/orders/:id/cancel` | 取消訂單（限 pending 狀態） |

### 6. 核心業務邏輯

**結帳（checkout）時必須：**
1. 確認購物車不為空
2. 逐一檢查每項商品庫存是否足夠
3. 計算總金額（`items.reduce(...)`）
4. 扣減庫存（`product.stock -= quantity`）
5. 建立訂單記錄，狀態設為 `'pending'`
6. 清空購物車
7. 若任何商品庫存不足，回傳 `422` 並**不執行任何扣減**

**取消訂單時：**
- 只有 `pending` 狀態的訂單可取消
- 取消後需**歸還庫存**（`product.stock += quantity`）
- 狀態更新為 `'cancelled'`

## 範例

```js
// POST /cart/items（需帶 Authorization: Bearer <token>）
// 請求 Body
{ "productId": "prod-1", "quantity": 2 }

// 成功回應 200
{
  "cart": [
    { "productId": "prod-1", "name": "機械鍵盤", "price": 2500, "quantity": 2, "subtotal": 5000 }
  ],
  "total": 5000
}

// POST /orders/checkout
// 請求 Body: {}（使用當前購物車）

// 成功回應 201
{
  "orderId": "ord-abc123",
  "status": "pending",
  "items": [
    { "productId": "prod-1", "name": "機械鍵盤", "price": 2500, "quantity": 2 }
  ],
  "totalAmount": 5000,
  "createdAt": "2026-11-16T10:30:00.000Z"
}

// 庫存不足時回應 422
{
  "error": "庫存不足",
  "details": [
    { "productId": "prod-2", "requested": 5, "available": 3 }
  ]
}

// PATCH /orders/ord-abc123/cancel
// 成功回應 200
{ "message": "訂單已取消", "status": "cancelled" }

// 嘗試取消非 pending 訂單 → 回應 409
{ "error": "只有 pending 狀態的訂單可以取消" }
```

## 提示

- 預先在程式啟動時建立 3–5 筆測試商品（seed data），方便測試。
- `checkout` 是最關鍵的業務邏輯：先用 `for` 迴圈做**全部**庫存檢查，確認都通過後才扣減，避免「扣了一半發現不夠」的不一致狀態。
- 購物車的 GET 回應最好計算每項的 `subtotal` 與整體 `total`，讓前端不需自行計算。
- 更新購物車數量時，`quantity === 0` 應視同移除該項目。
- 訂單狀態機可用一個 object 定義合法轉換，例如 `const VALID_TRANSITIONS = { pending: ['confirmed', 'cancelled'], confirmed: ['shipped'], ... }`。

---

## 學習重點（跟後端 API 的關聯）

- **原子性操作**：真實資料庫會用 Transaction 確保「扣庫存」與「建訂單」要嘛全成功、要嘛全失敗。本題用陣列模擬時，先驗證全部再執行，是相同的思路。
- **狀態機（State Machine）**：訂單狀態不能任意跳轉（`delivered` 不能回到 `pending`），用明確的合法轉換表比一堆 `if/else` 更安全、更易維護。
- **商業邏輯封裝**：`checkout` 函式不應混在路由 handler 裡，抽成 `services/orderService.js` 是業界慣例，讓路由只做 HTTP 層的事。
- **資源快照（Snapshot）**：訂單的 `items` 儲存下單當時的商品名稱與價格，而非只存 `productId`，確保即使商品後來修改，訂單紀錄仍正確。

## 進階挑戰（選做）

1. **管理員路由**：新增 `role: 'admin' | 'user'` 欄位，管理員可執行 `PATCH /orders/:id/status` 推進訂單狀態（`pending → confirmed → shipped → delivered`）。
2. **商品管理**：管理員可 `POST /products`、`PUT /products/:id`（更新庫存、價格）、`DELETE /products/:id`。
3. **訂單篩選**：`GET /orders?status=pending&from=2026-01-01&to=2026-12-31` 支援狀態與日期範圍篩選。
4. **Jest 測試**：為 `POST /orders/checkout` 寫 4 個測試：正常結帳、購物車為空、庫存不足（部分）、庫存不足（全部）。
5. **整合 PostgreSQL**：將資料改為真實資料庫，`checkout` 改用 `BEGIN / COMMIT / ROLLBACK` 實作真正的 Transaction。
