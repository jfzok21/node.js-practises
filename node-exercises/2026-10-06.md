# 第 14 週今日 Node.js 練習題：任務管理 REST API 實戰專案

## 題目說明

建立一個完整的「任務管理系統」後端 API，整合前幾週學過的所有核心概念：Express、Middleware、REST API 設計、輸入驗證、JWT 身份驗證與錯誤處理。這是一個接近真實工作場景的全端後端專案。

---

## 技術要求

- **概念：** REST API、JWT 驗證、Middleware 鏈、輸入驗證、錯誤處理、非同步操作
- **需要的套件：**
  - `express` — HTTP 框架
  - `jsonwebtoken` — JWT 簽發與驗證
  - `bcryptjs` — 密碼雜湊
  - `express-validator` — 輸入驗證
  - `uuid` — 產生唯一 ID（或使用 Node 內建 `crypto.randomUUID()`）

## 具體任務

### 1. 專案初始化

```
mkdir task-manager-api && cd task-manager-api
npm init -y
npm install express jsonwebtoken bcryptjs express-validator uuid
```

建立以下目錄結構：

```
task-manager-api/
├── src/
│   ├── routes/
│   │   ├── auth.js
│   │   └── tasks.js
│   ├── middleware/
│   │   ├── auth.js
│   │   └── errorHandler.js
│   ├── data/
│   │   └── store.js   ← 用記憶體陣列模擬資料庫
│   └── app.js
└── server.js
```

### 2. 使用者認證（`/api/auth`）

實作以下端點：

| 方法 | 路徑 | 說明 |
|------|------|------|
| POST | `/api/auth/register` | 註冊（email、password、name） |
| POST | `/api/auth/login` | 登入，回傳 JWT token |
| GET  | `/api/auth/me` | 取得目前使用者資訊（需 JWT） |

### 3. 任務 CRUD（`/api/tasks`，全部需要 JWT）

| 方法 | 路徑 | 說明 |
|------|------|------|
| GET    | `/api/tasks`        | 列出目前使用者的所有任務 |
| POST   | `/api/tasks`        | 新增任務 |
| GET    | `/api/tasks/:id`    | 取得單一任務 |
| PUT    | `/api/tasks/:id`    | 更新任務 |
| DELETE | `/api/tasks/:id`    | 刪除任務 |

### 4. 任務資料結構

```js
{
  id: "uuid-string",
  userId: "owner-uuid",
  title: "完成 Node.js 作業",
  description: "選填說明",
  status: "pending" | "in_progress" | "done",
  priority: "low" | "medium" | "high",
  createdAt: "2026-10-06T00:00:00.000Z",
  updatedAt: "2026-10-06T00:00:00.000Z"
}
```

### 5. 驗證規則（express-validator）

- `title`：必填，長度 1–100
- `status`：只能是 `pending`、`in_progress`、`done`
- `priority`：只能是 `low`、`medium`、`high`
- `email`：必須為有效格式
- `password`：最少 6 個字元

### 6. 全域錯誤處理 Middleware

統一錯誤回應格式：

```json
{
  "success": false,
  "error": "錯誤訊息",
  "statusCode": 400
}
```

## 提示

- **記憶體資料庫**：用模組層級的陣列 `const users = []; const tasks = [];` 暫時儲存，重啟後清空，但足夠練習邏輯。
- **JWT Middleware**：在 `src/middleware/auth.js` 中讀取 `Authorization` header，驗證 token 後把 `req.user` 設為解碼後的 payload。
- **使用者隔離**：`GET /api/tasks` 只能回傳 `task.userId === req.user.id` 的任務。
- **密碼雜湊**：`bcryptjs.hash(password, 10)` 存入，`bcryptjs.compare()` 驗證，**絕對不能明文存密碼**。
- **`app.js` vs `server.js`**：分離路由設定與伺服器啟動，方便未來撰寫 Jest 測試。

## 學習重點（跟後端 API 的關聯）

這個練習模擬了業界最常見的後端模式：

| 練習中的實作 | 實際工作對應 |
|--------------|--------------|
| 記憶體陣列 | PostgreSQL / MongoDB 資料表 |
| `bcryptjs` 雜湊 | 生產環境密碼安全規範 |
| JWT Middleware | API Gateway / Auth Service |
| express-validator | DTO 驗證層（Zod、Joi） |
| 全域錯誤 Middleware | 集中式 logging / Sentry |

完成後你擁有一個可部署的 MVP 後端，只需把記憶體換成真正的資料庫即可上線。

## 進階挑戰（選做）

1. **過濾與排序**：`GET /api/tasks?status=done&priority=high&sortBy=createdAt&order=desc`
2. **分頁**：`?page=1&limit=10`，回應中包含 `total`、`page`、`totalPages`
3. **Refresh Token**：發行短效 access token（15 分鐘）與長效 refresh token（7 天），實作 `POST /api/auth/refresh`
4. **Jest 整合測試**：使用 `supertest` 測試所有端點，含驗證失敗情境
5. **Rate Limiting**：使用 `express-rate-limit`，對登入端點每分鐘最多 5 次請求
