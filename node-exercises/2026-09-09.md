# 第 10 週今日 Node.js 練習題：輸入驗證與錯誤處理

## 題目說明

建立一個 Express API，實作完整的輸入驗證與錯誤處理機制。你將學習如何使用 `joi` 或 `express-validator` 驗證請求資料，並設計統一的錯誤回應格式，讓 API 在遇到無效輸入或系統錯誤時能優雅地回應。

## 技術要求

- 概念：Schema 驗證、中介層錯誤處理、自訂錯誤類別、HTTP 狀態碼語意
- 需要的套件：`express`、`joi`（或 `express-validator`）、`nodemon`（開發用）

## 具體任務

1. 初始化專案並安裝依賴套件：
   ```bash
   npm init -y
   npm install express joi
   npm install -D nodemon
   ```

2. 建立自訂錯誤類別 `AppError`，包含 `message`、`statusCode`、`code` 欄位：
   ```js
   class AppError extends Error {
     constructor(message, statusCode, code) { ... }
   }
   ```

3. 建立 `validate` 中介層工廠函式，接收 Joi schema 並在驗證失敗時拋出 `400` 錯誤。

4. 建立以下三個路由，每個都套用對應的驗證 schema：
   - `POST /api/users` — 建立使用者（name、email、age）
   - `POST /api/login` — 登入（email、password）
   - `GET /api/items/:id` — 取得項目（id 必須為正整數）

5. 實作全域錯誤處理中介層（4 個參數的 `(err, req, res, next)`），統一回傳以下格式：
   ```json
   {
     "success": false,
     "error": {
       "code": "VALIDATION_ERROR",
       "message": "...",
       "details": [...]
     }
   }
   ```

6. 處理 404 路由（未找到的路徑）並回傳對應錯誤。

## 範例

```js
// 正確請求
POST /api/users
{ "name": "Alice", "email": "alice@example.com", "age": 25 }

// 成功回應 201
{ "success": true, "data": { "id": 1, "name": "Alice", "email": "alice@example.com", "age": 25 } }

// 驗證失敗請求
POST /api/users
{ "name": "", "email": "not-an-email", "age": -5 }

// 錯誤回應 400
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "輸入資料無效",
    "details": [
      "name 不能為空",
      "email 格式不正確",
      "age 必須為正整數"
    ]
  }
}

// 未知路由
GET /api/unknown

// 錯誤回應 404
{
  "success": false,
  "error": {
    "code": "NOT_FOUND",
    "message": "找不到路由 GET /api/unknown"
  }
}
```

## 提示

- Joi schema 範例：
  ```js
  const createUserSchema = Joi.object({
    name: Joi.string().min(1).max(100).required(),
    email: Joi.email().required(),
    age: Joi.number().integer().min(1).max(150).required()
  });
  ```
- 驗證失敗時使用 `error.details.map(d => d.message)` 取出所有錯誤訊息。
- 全域錯誤中介層必須是 Express 中 **最後** 一個 `app.use()`（路由之後）。
- `process.env.NODE_ENV === 'production'` 時，隱藏系統內部錯誤細節，只回傳通用訊息。

## 學習重點

輸入驗證是後端 API 的第一道防線。在真實專案中：
- **驗證**（Validation）確保資料格式正確，避免損壞資料庫或造成邏輯錯誤。
- **統一錯誤格式**讓前端開發者能可預測地處理所有錯誤，無需針對每支 API 寫不同的錯誤邏輯。
- **HTTP 狀態碼語意**（400 客戶端錯誤、404 找不到、422 無法處理、500 伺服器錯誤）讓 API 符合 RESTful 規範，方便整合監控與除錯工具。

## 進階挑戰（選做）

1. **非同步錯誤包裝**：寫一個 `asyncHandler(fn)` 高階函式，自動 catch async route handler 的錯誤並傳給 `next(err)`，不需在每個路由手動 try/catch。
2. **Sanitization**：使用 `.trim()`、`.lowercase()` 等 Joi 轉換，自動清理輸入資料後再儲存。
3. **請求 ID 追蹤**：在每個請求加上唯一的 `X-Request-Id` header，並在錯誤回應中包含它，方便對應 log。
4. **分層錯誤**：區分 `ValidationError`（400）、`AuthenticationError`（401）、`NotFoundError`（404）各自的子類別，讓錯誤處理中介層能自動判斷狀態碼。
