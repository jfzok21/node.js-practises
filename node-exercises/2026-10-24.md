# 第 16 週今日 Node.js 練習題：任務管理 REST API（完整實戰）

## 題目說明

綜合運用前 15 週所學，從零打造一個具備完整功能的「任務管理 API」（Task Manager API）。
這支 API 需支援使用者註冊登入、建立/管理任務（含分類與優先級）、並搭配 JWT 驗證、輸入驗證、PostgreSQL 儲存與 Jest 測試。

## 具體任務

### 1. 資料庫設計

建立以下兩張 PostgreSQL 資料表：

```sql
-- 使用者表
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 任務表
CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  title VARCHAR(255) NOT NULL,
  description TEXT,
  priority VARCHAR(10) CHECK (priority IN ('low', 'medium', 'high')) DEFAULT 'medium',
  status VARCHAR(20) CHECK (status IN ('todo', 'in_progress', 'done')) DEFAULT 'todo',
  due_date DATE,
  created_at TIMESTAMP DEFAULT NOW()
);
```

### 2. 實作以下 API 端點

| 方法   | 路徑                    | 說明                         | 需驗證 |
|--------|-------------------------|------------------------------|--------|
| POST   | `/auth/register`        | 使用者註冊                   | 否     |
| POST   | `/auth/login`           | 登入，回傳 JWT token         | 否     |
| GET    | `/tasks`                | 取得目前使用者的所有任務     | 是     |
| POST   | `/tasks`                | 新增任務                     | 是     |
| GET    | `/tasks/:id`            | 取得單一任務                 | 是     |
| PUT    | `/tasks/:id`            | 更新任務                     | 是     |
| DELETE | `/tasks/:id`            | 刪除任務                     | 是     |
| GET    | `/tasks?status=todo`    | 依狀態篩選任務（Query 參數） | 是     |
| GET    | `/tasks?priority=high`  | 依優先級篩選                 | 是     |

### 4. JWT 驗證 Middleware

```js
// src/middleware/auth.js
const jwt = require('jsonwebtoken');

module.exports = (req, res, next) => {
  const authHeader = req.headers.authorization;
  if (!authHeader?.startsWith('Bearer ')) {
    return res.status(401).json({ error: '未提供 Token' });
  }
  try {
    const token = authHeader.split(' ')[1];
    req.user = jwt.verify(token, process.env.JWT_SECRET);
    next();
  } catch {
    res.status(401).json({ error: 'Token 無效或已過期' });
  }
};
```

### 5. 撰寫測試（至少涵蓋）

- 成功註冊與登入
- 未帶 Token 時回傳 401
- 新增任務成功（status 預設為 `todo`）
- 嘗試存取他人任務時回傳 403

## 提示

- 使用 `bcrypt.hash(password, 10)` 儲存雜湊密碼，永遠不要明文儲存
- `.env` 存放 `DATABASE_URL`、`JWT_SECRET`（不要 commit 進 git）
- `GET /tasks` 一定要加上 `WHERE user_id = $1` 確保使用者只能看到自己的任務
- 篩選 Query 參數可用 `if (req.query.status)` 動態組合 SQL 條件
- 測試前可用 `beforeAll` 建立測試用使用者，`afterAll` 清理資料

## 學習重點（跟後端 API 的關聯）

這個練習是現實工作中最常見的後端需求雛形——幾乎所有 SaaS 產品的核心都是「使用者 + 資源的 CRUD + 權限控制」。

| 本週練習                | 對應實務                                    |
|-------------------------|---------------------------------------------|
| JWT auth middleware     | 所有需登入才能操作的 API                    |
| User-scoped queries     | 多租戶（multi-tenant）資料隔離              |
| Query 參數篩選          | 前端表格的 filter/sort 功能                 |
| bcrypt 密碼雜湊         | OWASP 密碼儲存最佳實踐                      |
| supertest 整合測試      | CI/CD 自動化測試流程                        |

## 進階挑戰（選做）

1. **分頁**：在 `GET /tasks` 加入 `?page=1&limit=10` 支援
2. **排序**：支援 `?sort=due_date&order=asc`
3. **軟刪除**：加入 `deleted_at` 欄位，刪除時只更新此欄位而非真正刪除
4. **Rate Limiting**：使用 `express-rate-limit` 限制登入嘗試（防暴力破解）
5. **Refresh Token**：實作 access token (15min) + refresh token (7d) 雙 token 機制
