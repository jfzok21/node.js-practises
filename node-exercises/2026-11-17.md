# 第 20 週今日 Node.js 練習題：WebSocket 即時訂單狀態推播系統

## 題目說明

在上週電商系統的基礎上，加入 WebSocket 即時推播功能。當管理員更新訂單狀態（`pending → confirmed → shipped → delivered`）時，前端客戶端能**立即收到通知**，不需主動輪詢（polling）。這個練習整合 HTTP REST API 與 WebSocket 雙向通訊，是現代 Web 應用的核心技術之一。

---

## 技術要求

- **概念：** WebSocket 協定、事件驅動架構、訂閱／推播模式、身份驗證於 WS 連線、連線管理（Map）
- **需要的套件：**
  - `express` — HTTP 框架
  - `ws` — Node.js WebSocket 伺服器（`npm install ws`）
  - `jsonwebtoken` — JWT 驗證（複用上週認證邏輯）
  - `uuid` 或 `crypto.randomUUID()` — 訂單 ID

---

## 具體任務

### 1. 建立 WebSocket 伺服器（與 HTTP 共用同一 port）

```js
const http = require('http');
const { WebSocketServer } = require('ws');
const app = require('./app'); // Express app

const server = http.createServer(app);
const wss = new WebSocketServer({ server });

server.listen(3000);
```

### 2. 連線驗證：用 JWT token 識別使用者

客戶端連線時，URL 帶上 token：
```
ws://localhost:3000?token=<JWT>
```

伺服器端在 `connection` 事件中驗證：
- token 無效 → 立即 `ws.close(4001, 'Unauthorized')` 並拒絕
- token 有效 → 將連線存入 Map：`clients.set(userId, ws)`

### 3. 管理連線 Map

```js
// server 層級的全域 Map
const clients = new Map(); // userId → WebSocket instance

wss.on('connection', (ws, req) => {
  // 解析 URL query param
  const token = new URL(req.url, 'http://localhost').searchParams.get('token');
  
  try {
    const payload = jwt.verify(token, JWT_SECRET);
    clients.set(payload.userId, ws);
    
    ws.on('close', () => clients.delete(payload.userId));
    ws.on('error', () => clients.delete(payload.userId));
    
    // 連線成功確認
    ws.send(JSON.stringify({ type: 'connected', message: '即時通知已啟用' }));
  } catch {
    ws.close(4001, 'Unauthorized');
  }
});
```

### 4. 推播函式

```js
function notifyUser(userId, payload) {
  const ws = clients.get(userId);
  if (ws && ws.readyState === ws.OPEN) {
    ws.send(JSON.stringify(payload));
  }
}
```

### 5. HTTP API：管理員更新訂單狀態

```
PATCH /admin/orders/:id/status
Authorization: Bearer <admin JWT>
Body: { "status": "confirmed" }
```

更新成功後，呼叫 `notifyUser` 推播給該訂單的所屬使用者：

```js
notifyUser(order.userId, {
  type: 'order_status_updated',
  orderId: order.id,
  newStatus: req.body.status,
  updatedAt: new Date().toISOString()
});
```

### 6. 狀態機限制（複用上週邏輯）

合法轉換：
```
pending → confirmed
confirmed → shipped
shipped → delivered
```
非法轉換回傳 `422 Unprocessable Entity`。

### 7. 心跳機制（Heartbeat）— 偵測斷線

```js
const HEARTBEAT_INTERVAL = 30_000; // 30 秒

setInterval(() => {
  wss.clients.forEach(ws => {
    if (!ws.isAlive) return ws.terminate();
    ws.isAlive = false;
    ws.ping();
  });
}, HEARTBEAT_INTERVAL);

wss.on('connection', ws => {
  ws.isAlive = true;
  ws.on('pong', () => { ws.isAlive = true; });
  // ... 其他邏輯
});
```

## 範例

**客戶端（瀏覽器 / wscat）連線：**
```bash
# 安裝 wscat 測試工具
npx wscat -c "ws://localhost:3000?token=eyJhbGci..."
```

**連線後收到：**
```json
{ "type": "connected", "message": "即時通知已啟用" }
```

**管理員透過 HTTP 更新訂單狀態：**
```bash
curl -X PATCH http://localhost:3000/admin/orders/ord-abc123/status \
  -H "Authorization: Bearer <admin_token>" \
  -H "Content-Type: application/json" \
  -d '{"status": "confirmed"}'
```

**使用者的 WebSocket 立即收到：**
```json
{
  "type": "order_status_updated",
  "orderId": "ord-abc123",
  "newStatus": "confirmed",
  "updatedAt": "2026-11-17T10:00:00.000Z"
}
```

**連線驗證失敗：**
```
# WS 連線被關閉，code: 4001, reason: "Unauthorized"
```

## 提示

- `ws` 套件的 `WebSocketServer` 可以直接附加到現有的 `http.Server`，不需要另開 port。
- 在 `clients` Map 裡用 `userId` 當 key，同一使用者只保留**最新**連線（舊的直接覆蓋）；若需支援多裝置，改用 `Map<userId, Set<WebSocket>>`。
- `ws.readyState === ws.OPEN` 在推播前務必檢查，避免對已斷線的 socket 送訊息。
- 測試時用 `wscat`（`npx wscat`）模擬客戶端，比自己寫 HTML 方便。
- `JWT_SECRET` 要在 HTTP 路由與 WebSocket handler 共用同一個常數，可抽到 `config.js`。

## 學習重點（跟後端 API 的關聯）

- **輪詢 vs. 推播**：傳統做法是客戶端每 N 秒 `GET /orders/:id` 詢問狀態，浪費資源。WebSocket 建立持久連線後，伺服器主動推播，延遲低、流量省。
- **連線狀態管理**：`clients` Map 是伺服器內存的「線上使用者清單」。生產環境若有多個 Node instance，需改用 Redis Pub/Sub 廣播，讓任一台 server 都能推播到正確連線。
- **協定升級**：WebSocket 是在 HTTP `Upgrade` 請求之上建立的，與 REST API 共用同一 port 是業界慣例（Nginx 可同時代理兩種協定）。
- **心跳機制**：TCP 連線可能在中間設備（NAT、負載平衡器）閒置後被靜默切斷，定期 `ping/pong` 確保連線仍然存活。

## 進階挑戰（選做）

1. **房間（Room）訂閱**：讓客戶端發送 `{ "type": "subscribe", "orderId": "..." }` 訊息，只接收指定訂單的更新，而非所有自己的訂單。
2. **廣播給管理員**：所有管理員連線都訂閱一個「新訂單通知」頻道，每當有新訂單建立時，推播 `{ type: 'new_order', orderId, userId, totalAmount }`。
3. **Redis Pub/Sub 擴展**：用 `ioredis` 的 `publish/subscribe` 模式，讓兩個 Node process 各自只管理自己的 WebSocket 連線，透過 Redis 中繼推播事件。
4. **前端整合**：寫一個簡單的 HTML 頁面，用瀏覽器原生 `WebSocket` API 連線，訂單狀態更新時動態更新 DOM，模擬真實前後端整合。
5. **Jest 測試**：用 `ws` 套件的客戶端模式（`new WebSocket('ws://localhost:3000?token=...')`）寫 E2E 測試，驗證狀態更新後 WebSocket 確實收到推播。
