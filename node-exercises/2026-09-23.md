# 第 12 週今日 Node.js 練習題：Jest 測試 — 為 Express API 撰寫單元與整合測試

## 題目說明

你已建立了一個簡單的 Express REST API，現在需要替它加上自動化測試。本練習將帶你使用 Jest 與 Supertest，針對「使用者管理」API 撰寫單元測試（unit test）與整合測試（integration test），確保每個端點的行為符合預期。

---

## 技術要求

- **概念：** Jest 測試框架、describe / it / expect、mock 函式、Supertest HTTP 測試、beforeEach / afterEach 生命週期
- **需要的套件：**
  - `jest`
  - `supertest`
  - `@types/jest`（選用，若使用 VS Code 提示）

---

## 具體任務

1. **建立專案結構**
   - 建立 `app.js`（Express 應用程式，不呼叫 `app.listen`）
   - 建立 `userService.js`（負責資料邏輯，使用記憶體陣列模擬資料庫）
   - 建立 `__tests__/userService.test.js`（單元測試）
   - 建立 `__tests__/app.test.js`（整合測試）

2. **`userService.js` 需實作以下函式：**
   - `getAllUsers()` → 回傳所有使用者陣列
   - `getUserById(id)` → 找不到時回傳 `null`
   - `createUser(name, email)` → 建立使用者，自動產生 id
   - `deleteUser(id)` → 成功回傳 `true`，找不到回傳 `false`

3. **單元測試 (`userService.test.js`) 需覆蓋：**
   - `getAllUsers` 回傳陣列
   - `createUser` 正確新增使用者並包含必要欄位
   - `getUserById` 找到與找不到兩種情境
   - `deleteUser` 成功與失敗兩種情境

4. **`app.js` 需實作以下路由：**
   - `GET /users` → 回傳全部使用者
   - `GET /users/:id` → 回傳單一使用者或 404
   - `POST /users` → 新增使用者，缺少欄位時回傳 400
   - `DELETE /users/:id` → 刪除使用者或 404

5. **整合測試 (`app.test.js`) 需覆蓋：**
   - `GET /users` 回傳 200 與陣列
   - `POST /users` 成功建立回傳 201
   - `POST /users` 缺少 email 時回傳 400
   - `GET /users/:id` 找不到時回傳 404
   - `DELETE /users/:id` 成功回傳 200

## 範例

```js
// userService.js
let users = [];
let nextId = 1;

function getAllUsers() {
  return users;
}

function getUserById(id) {
  return users.find(u => u.id === id) || null;
}

function createUser(name, email) {
  const user = { id: nextId++, name, email };
  users.push(user);
  return user;
}

function deleteUser(id) {
  const index = users.findIndex(u => u.id === id);
  if (index === -1) return false;
  users.splice(index, 1);
  return true;
}

module.exports = { getAllUsers, getUserById, createUser, deleteUser };
```

```js
// __tests__/userService.test.js
const { getAllUsers, createUser, getUserById, deleteUser } = require('../userService');

beforeEach(() => {
  // 清空模組快取，讓每次測試從乾淨狀態開始
  jest.resetModules();
});

describe('userService', () => {
  it('getAllUsers 應回傳陣列', () => {
    expect(Array.isArray(getAllUsers())).toBe(true);
  });

  it('createUser 應建立含 id、name、email 的使用者', () => {
    const user = createUser('Alice', 'alice@example.com');
    expect(user).toHaveProperty('id');
    expect(user.name).toBe('Alice');
    expect(user.email).toBe('alice@example.com');
  });

  it('getUserById 找不到時應回傳 null', () => {
    expect(getUserById(9999)).toBeNull();
  });
});
```

```js
// __tests__/app.test.js
const request = require('supertest');
const app = require('../app');

describe('POST /users', () => {
  it('缺少 email 時應回傳 400', async () => {
    const res = await request(app)
      .post('/users')
      .send({ name: 'Bob' });
    expect(res.statusCode).toBe(400);
  });

  it('資料完整時應回傳 201', async () => {
    const res = await request(app)
      .post('/users')
      .send({ name: 'Carol', email: 'carol@example.com' });
    expect(res.statusCode).toBe(201);
    expect(res.body).toHaveProperty('id');
  });
});
```

## 提示

- `app.js` 只匯出 `module.exports = app`，**不要**呼叫 `app.listen()`，讓 Supertest 自行管理連線
- 若測試之間互相干擾（狀態殘留），在 `beforeEach` 中重設記憶體陣列
- 使用 `jest --coverage` 可看到覆蓋率報告
- `package.json` 中加入 `"test": "jest"` 腳本，即可用 `npm test` 執行

---

## 學習重點（跟後端 API 的關聯）

測試是後端工程的基石。在實際專案中：

- **單元測試**保護服務層邏輯，讓你在重構時不怕破壞行為
- **整合測試**以真實 HTTP 請求驗證路由、middleware、錯誤處理的完整流程
- CI/CD 管線（GitHub Actions 等）會在每次 push 時自動跑測試，確保主幹永遠可部署
- 高測試覆蓋率讓團隊有信心快速迭代，也是 PR review 的重要品質指標

## 進階挑戰（選做）

1. **Mock 外部依賴：** 將 `userService` 改為連接真實 SQLite（使用 `better-sqlite3`），然後在測試中用 `jest.mock()` 替換掉資料庫呼叫，驗證 mock 被正確呼叫
2. **測試覆蓋率門檻：** 在 `jest.config.js` 加入 `coverageThreshold`，要求語句覆蓋率 ≥ 80%，覆蓋率不足時讓 CI 失敗
3. **參數化測試：** 使用 `it.each` 對多組輸入（合法 / 非法 email 格式）執行同一驗證邏輯的測試
