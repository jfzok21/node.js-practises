# 第 11 週今日 Node.js 練習題：多類型檔案上傳 API

## 題目說明

建立一個 Express API 伺服器，支援單檔與多檔上傳功能，並針對不同類型的路由（頭像上傳、文件上傳）設定不同的檔案限制規則。上傳後要能回傳檔案的基本 metadata，並在 server 端做副檔名與大小的驗證。

---

## 技術要求

- **概念：** multer middleware、fileFilter 過濾、DiskStorage 設定、錯誤處理
- **需要的套件：**
  ```
  npm install express multer
  ```

---

## 具體任務

1. **初始化專案結構**
   ```
   upload-api/
   ├── uploads/
   │   ├── avatars/
   │   └── documents/
   ├── index.js
   └── package.json
   ```

2. **設定 Avatar 上傳（單檔）**
   - 路由：`POST /upload/avatar`
   - 只接受 `.jpg`、`.jpeg`、`.png`
   - 單檔大小上限：**2 MB**
   - 儲存於 `uploads/avatars/`
   - 自動以時間戳記重新命名檔案，避免衝突（例如 `1726000000000-photo.jpg`）

3. **設定 Document 上傳（多檔）**
   - 路由：`POST /upload/documents`
   - 只接受 `.pdf`、`.doc`、`.docx`、`.txt`
   - 單檔大小上限：**10 MB**
   - 最多同時上傳 **5** 個檔案
   - 儲存於 `uploads/documents/`

4. **回應格式**
   - 成功時回傳：
     ```json
     {
       "success": true,
       "files": [
         {
           "originalName": "report.pdf",
           "savedName": "1726000000000-report.pdf",
           "size": 204800,
           "mimetype": "application/pdf",
           "path": "uploads/documents/1726000000000-report.pdf"
         }
       ]
     }
     ```
   - 失敗時（類型不符、超過大小限制）回傳 HTTP 400 加上說明訊息

5. **全域錯誤處理 middleware**
   - 捕捉 multer 的 `MulterError`（例如 `LIMIT_FILE_SIZE`）並回傳易讀的錯誤訊息
   - 捕捉自訂 fileFilter 的驗證錯誤

## 範例

```js
// 啟動後測試（使用 curl）

// 上傳頭像
curl -X POST http://localhost:3000/upload/avatar \
  -F "avatar=@./photo.jpg"

// 預期回應
{
  "success": true,
  "files": [
    {
      "originalName": "photo.jpg",
      "savedName": "1726012345678-photo.jpg",
      "size": 153600,
      "mimetype": "image/jpeg",
      "path": "uploads/avatars/1726012345678-photo.jpg"
    }
  ]
}

// 上傳不允許的格式
curl -X POST http://localhost:3000/upload/avatar \
  -F "avatar=@./script.js"

// 預期回應（400）
{
  "success": false,
  "error": "只允許上傳 jpg、jpeg、png 格式的圖片"
}
```

## 提示

- `multer.diskStorage()` 的 `destination` 和 `filename` 回呼函式可用於控制儲存路徑與檔名
- `fileFilter(req, file, cb)` 中，`cb(new Error('message'))` 可拒絕檔案，`cb(null, true)` 可放行
- 捕捉 multer 錯誤時，使用 `err instanceof multer.MulterError` 來判斷錯誤類型
- `LIMIT_FILE_SIZE` 是超過大小限制時 multer 拋出的 `MulterError` 代碼
- `req.file`（單檔）和 `req.files`（多檔）是上傳成功後 multer 掛載的屬性

```js
// 全域錯誤處理 middleware 範例骨架
app.use((err, req, res, next) => {
  if (err instanceof multer.MulterError) {
    if (err.code === 'LIMIT_FILE_SIZE') {
      return res.status(400).json({ success: false, error: '檔案大小超過限制' });
    }
  }
  if (err) {
    return res.status(400).json({ success: false, error: err.message });
  }
  next();
});
```

## 學習重點

**與後端 API 的關聯：**

- 實際產品幾乎都有檔案上傳需求（使用者頭像、KYC 文件、報告匯出等）
- multer 是 Express 生態系最主流的 multipart/form-data 解析工具
- `fileFilter` + 大小限制 = 最基本的伺服端安全防線，防止惡意檔案與資源耗盡攻擊
- 了解 multer 錯誤處理流程後，可搭配後續 Week 10 的輸入驗證概念，建立完整的「上傳 → 驗證 → 儲存 → 回應」pipeline
- 真實環境通常會把 `destination` 換成雲端儲存（AWS S3、GCS），透過 multer-s3 或先存本地再上傳
