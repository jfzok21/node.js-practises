# 第 14 週今日 Node.js 練習題：任務清單 REST API 實戰專案

## 題目說明

綜合前幾週所學，建立一個完整的「任務清單（Todo List）」REST API 後端服務。這個專案將涵蓋 Express 路由、Middleware、JWT 身份驗證、輸入驗證、PostgreSQL 資料庫操作，以及 Jest 單元測試，模擬真實的後端開發工作流程。

## 技術要求

- **概念**：REST API 設計、JWT 身份驗證、資料庫 CRUD 操作、輸入驗證、錯誤處理、單元測試
- **需要的套件**：
  - `express` — HTTP 框架
  - `pg` — PostgreSQL 客戶端
  - `jsonwebtoken` — JWT 簽發與驗證
  - `bcryptjs` — 密碼雜湊
  - `express-validator` — 輸入驗證
  - `jest` + `supertest` — API 整合測試
  - `dotenv` — 環境變數管理

## 具體任務

1. **初始化專案**
   - `npm init -y`，安裝上述套件
   - 建立 `.env` 檔案，設定 `DATABASE_URL`、`JWT_SECRET`、`PORT`

2. **資料庫設計**
   建立兩張表（可用 SQL 腳本 `db/schema.sql`）：
   ```sql
   CREATE TABLE users (
     id SERIAL PRIMARY KEY,
     email VARCHAR(255) UNIQUE NOT NULL,
     password_hash TEXT NOT NULL,
     created_at TIMESTAMPTZ DEFAULT NOW()
   );

   CREATE TABLE todos (
     id SERIAL PRIMARY KEY,
     user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
     title VARCHAR(255) NOT NULL,
     completed BOOLEAN DEFAULT FALSE,
     created_at TIMESTAMPTZ DEFAULT NOW()
   );
   ```

3. **身份驗證模組**（`routes/auth.js`）
   - `POST /api/auth/register` — 接收 `email`、`password`，雜湊密碼後存入 DB，回傳 JWT
   - `POST /api/auth/login` — 驗證帳密，回傳 JWT

4. **JWT Middleware**（`middleware/auth.js`）
   - 從 `Authorization: Bearer <token>` 標頭取出 token
   - 驗證後將 `req.user` 設為解碼的使用者資訊
   - 驗證失敗回傳 `401 Unauthorized`

5. **Todo CRUD 路由**（`routes/todos.js`），所有路由皆需通過 JWT Middleware：
   - `GET /api/todos` — 取得目前使用者所有任務
   - `POST /api/todos` — 新增任務（body: `{ title }`）
   - `PATCH /api/todos/:id` — 更新任務（body: `{ title?, completed? }`）
   - `DELETE /api/todos/:id` — 刪除任務（僅限本人）

6. **輸入驗證**
   - `register`：email 格式正確、password 長度至少 8 字元
   - `POST /api/todos`：title 不得為空字串

7. **統一錯誤處理 Middleware**（`middleware/errorHandler.js`）
   - 捕捉所有未處理錯誤，回傳 `{ error: "訊息" }` JSON

8. **撰寫測試**（`tests/todos.test.js`）
   使用 `supertest` 測試至少 3 個情境：
   - 未帶 token 存取 `GET /api/todos` → 應回傳 401
   - 成功新增任務 → 應回傳 201 及新任務物件
   - 刪除不屬於自己的任務 → 應回傳 403

## 範例

```js
// POST /api/todos 請求
// Headers: Authorization: Bearer <JWT>
// Body: { "title": "閱讀 Node.js 文件" }

// 成功回應 201
{
  "id": 5,
  "user_id": 2,
  "title": "閱讀 Node.js 文件",
  "completed": false,
  "created_at": "2026-10-12T08:00:00.000Z"
}

// DELETE /api/todos/99（非本人任務）
// 回應 403
{
  "error": "無權限刪除此任務"
}
```

## 提示

- 使用 `pg.Pool` 管理資料庫連線，避免每次請求都建立新連線
- JWT payload 只存 `{ id, email }`，不放敏感資訊
- `bcryptjs.hash(password, 12)` 中 `12` 是 salt rounds，開發時可降低至 `10` 加快速度
- `express-validator` 的 `validationResult(req)` 放在路由最前面做早期回傳
- 測試時使用獨立的測試資料庫，或用 `jest.mock` 模擬 DB 層

## 學習重點

（跟後端 API 的關聯）

這個實戰專案是前幾週所有主題的整合：Express 路由（第 5-6 週）提供架構、JWT（第 9 週）保護端點、`express-validator`（第 10 週）確保資料品質、PostgreSQL（第 8 週）持久化資料、Jest（第 12 週）驗證行為正確。這正是真實 SaaS 後端 API 的標準結構——掌握它，你就能讀懂並貢獻大多數 Node.js 後端專案。

## 進階挑戰（選做）

- 加入**任務優先等級**欄位（`priority: 'low' | 'medium' | 'high'`），並支援以此過濾 `GET /api/todos?priority=high`
- 實作**分頁**：`GET /api/todos?page=1&limit=10`，回傳 `{ data, total, page, totalPages }`
- 加入 **Redis** 快取：`GET /api/todos` 結果快取 60 秒，`POST/PATCH/DELETE` 時清除快取
- 撰寫 `Dockerfile`，讓整個服務可以 `docker-compose up` 一鍵啟動（含 PostgreSQL）
