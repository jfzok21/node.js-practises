# 第 13 週今日 Node.js 練習題：任務管理 REST API 實戰專案

## 題目說明

歡迎來到實戰專案週！這週你將整合前 12 週所學的所有技術，從頭建立一個完整的「任務管理系統 API」（Task Manager API）。這個專案涵蓋使用者註冊/登入、JWT 驗證、CRUD 操作、輸入驗證、錯誤處理，以及基本測試，貼近真實後端開發的完整流程。

## 技術要求

- **概念**：Express、JWT 身份驗證、REST API 設計、輸入驗證、錯誤處理中介軟體、Jest 整合測試
- **需要的套件**：
  ```
  express
  jsonwebtoken
  bcryptjs
  express-validator
  dotenv
  jest
  supertest
  ```
- **資料儲存**：使用記憶體內陣列模擬資料庫（不需要實際 DB，降低環境需求）

## 具體任務

### 1. 專案初始化
建立 `task-manager/` 目錄，執行 `npm init -y`，安裝上述套件，並建立 `.env` 檔：
```
PORT=3000
JWT_SECRET=mysecretkey123
```

### 2. 使用者功能（`/api/auth`）
實作兩支路由：
- `POST /api/auth/register`：接收 `name`、`email`、`password`，將密碼用 `bcryptjs` 雜湊後存入記憶體陣列，回傳使用者資訊（不含密碼）
- `POST /api/auth/login`：驗證 email 與密碼，成功後回傳 JWT token（有效期 1 小時）

### 3. JWT 驗證中介軟體
建立 `middleware/auth.js`，從 `Authorization: Bearer <token>` 標頭中解析並驗證 JWT。驗證失敗時回傳 `401 Unauthorized`。

### 4. 任務 CRUD（`/api/tasks`，需登入）
所有路由都必須通過 JWT 驗證中介軟體，且每位使用者只能操作**自己的任務**：
- `GET /api/tasks`：取得目前使用者的所有任務（支援 `?status=pending|done` 查詢篩選）
- `POST /api/tasks`：建立任務（欄位：`title`、`description`、`dueDate`）
- `PATCH /api/tasks/:id`：更新任務（可更新 `title`、`description`、`dueDate`、`status`）
- `DELETE /api/tasks/:id`：刪除任務

### 5. 輸入驗證
使用 `express-validator` 驗證：
- `register`：`email` 必須為有效格式，`password` 至少 6 個字元，`name` 不得為空
- `createTask`：`title` 不得為空，`dueDate` 若有提供則必須為有效日期格式

### 6. 統一錯誤處理中介軟體
建立 `middleware/errorHandler.js`，捕捉所有未處理錯誤，回傳標準格式：
```json
{ "error": "訊息說明", "details": [] }
```

### 7. 撰寫 Jest 整合測試
使用 `supertest` 測試至少以下情境：
- 成功註冊使用者
- 登入後取得 JWT
- 未帶 token 呼叫 `GET /api/tasks` 應回傳 `401`
- 帶有效 token 成功建立任務
- 帶有效 token 刪除不屬於自己的任務應回傳 `403`

## 提示

- `app.js` 只匯出 `app`，由 `server.js` 呼叫 `app.listen()`；這樣 `supertest` 可以直接 `require('./app')` 而不會佔用 port
- 記憶體陣列在測試之間需要重置，可在 `beforeEach` 中清空 `store/db.js` 的陣列
- `bcryptjs.compare()` 回傳 Promise，記得 `await`
- JWT payload 只需存放 `{ id, email }`，不要存密碼

## 學習重點（跟後端 API 的關聯）

這個練習整合了真實後端 API 的核心流程：
- **身份驗證**（JWT）確保只有登入使用者才能操作資源
- **授權檢查**（userId 比對）防止越權存取他人資料
- **輸入驗證**在資料進入系統前攔截錯誤輸入
- **統一錯誤處理**讓 API 回應格式一致，前端更易整合
- **測試驗證**確保重構後行為不變，是實際開發中保護 API 的安全網

## 進階挑戰（選做）

1. **分頁**：在 `GET /api/tasks` 加入 `?page=1&limit=10` 支援
2. **任務優先級**：新增 `priority` 欄位（`low` / `medium` / `high`），並可依此排序
3. **Refresh Token**：實作 refresh token 機制，讓 access token 過期後可無縫換新
4. **Rate Limiting**：使用 `express-rate-limit` 限制 `/api/auth/login` 每分鐘最多 5 次請求，防止暴力破解
