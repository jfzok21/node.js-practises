# 第 19 週今日 Node.js 練習題：全端任務管理 API

## 題目說明

建立一個功能完整的任務管理 REST API，整合前幾週所學的所有核心技術：Express、PostgreSQL、JWT 身份驗證、輸入驗證、錯誤處理、以及 Jest 測試。這是一個模擬真實後端開發情境的實戰專案。

---

## 技術要求

- **概念**：REST API 設計、JWT 驗證、資料庫 CRUD、Middleware 串聯、錯誤處理、單元測試
- **需要的套件**：
  - `express`

## 具體任務

### 1. 資料庫設計

建立兩個 PostgreSQL 資料表：

```sql
-- 使用者資料表
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(50) UNIQUE NOT NULL,
  email VARCHAR(100) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 任務資料表
CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  title VARCHAR(200) NOT NULL,
  description TEXT,
  status VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending', 'in_progress', 'done')),
  due_date DATE,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

### 2. 實作 API 端點

#### 身份驗證
| 方法 | 路由 | 說明 |
|------|------|------|
| POST | `/api/auth/register` | 使用者註冊 |
| POST | `/api/auth/login` | 登入，回傳 JWT |

#### 任務管理（需 JWT）
| 方法 | 路由 | 說明 |
|------|------|------|
| GET | `/api/tasks` | 取得目前使用者的所有任務（支援 `?status=` 篩選） |
| GET | `/api/tasks/:id` | 取得單一任務 |
| POST | `/api/tasks` | 新增任務 |
| PATCH | `/api/tasks/:id` | 更新任務（部分欄位） |
| DELETE | `/api/tasks/:id` | 刪除任務 |

### 3. Middleware 實作

```js
// authMiddleware.js — 驗證 JWT
// validationMiddleware.js — 使用 express-validator 驗證輸入
// errorHandler.js — 統一錯誤回應格式
```

### 4. 輸入驗證規則

- `register`：username 長度 3–50、email 格式正確、password 至少 8 碼
- `POST /tasks`：title 不可為空、status 限定三種值、due_date 必須是有效日期
- `PATCH /tasks/:id`：所有欄位皆選填，但不能全部為空

### 5. 撰寫 Jest 測試

至少包含：
- 註冊成功 / 重複 email 失敗
- 登入成功 / 密碼錯誤失敗
- 未帶 JWT 存取任務 → 401
- CRUD 任務的完整流程

## 範例

```js
// 請求：POST /api/auth/login
// Body: { "email": "user@example.com", "password": "mypassword" }

// 成功回應 (200)
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": { "id": 1, "username": "alice", "email": "user@example.com" }
}

// 請求：POST /api/tasks（帶 Authorization: Bearer <token>）
// Body: { "title": "完成 Node.js 練習", "status": "in_progress", "due_date": "2026-11-15" }

// 成功回應 (201)
{
  "id": 42,
  "user_id": 1,
  "title": "完成 Node.js 練習",
  "description": null,
  "status": "in_progress",
  "due_date": "2026-11-15",
  "created_at": "2026-11-11T08:00:00.000Z"
}

// 驗證錯誤回應 (400)
{
  "errors": [
    { "field": "title", "message": "標題不可為空" },
    { "field": "status", "message": "status 必須是 pending、in_progress 或 done" }
  ]
}
```

---

## 提示

- 密碼用 `bcryptjs.hash(password, 10)` 雜湊後儲存，絕不存明文
- JWT `payload` 只放 `{ userId, username }`，secret 存在環境變數 `JWT_SECRET`
- 更新任務時記得同時更新 `updated_at = NOW()`
- 任何資料庫操作都加 `try/catch`，並透過 `next(err)` 傳給 errorHandler
- 測試時使用獨立的測試資料庫（`process.env.DATABASE_URL` 區分環境）

## 學習重點

**跟後端 API 的關聯：**
這個練習整合了完整的後端 API 開發流程：

1. **資料層**：PostgreSQL 設計與 `pg` 操作，對應真實產品的資料持久化
2. **邏輯層**：JWT 保護路由，每個請求只能存取自己的資料（多租戶隔離）
3. **驗證層**：`express-validator` 防止髒資料進入資料庫
4. **錯誤層**：統一格式讓前端開發者能可靠地處理錯誤
5. **測試層**：`supertest` 整合測試確保 API 行為符合預期

這就是業界標準 Node.js/Express API 的基本結構，掌握後即可快速上手大多數後端職缺。

## 進階挑戰（選做）

1. **分頁**：`GET /api/tasks?page=1&limit=10` 加入 LIMIT/OFFSET
2. **排序**：支援 `?sortBy=due_date&order=asc`
3. **軟刪除**：加 `deleted_at` 欄位，DELETE 時不真正移除
4. **Rate Limiting**：用 `express-rate-limit` 防止 API 被濫用
5. **Swagger 文件**：用 `swagger-jsdoc` + `swagger-ui-express` 自動產生 API 文件
6. **Docker Compose**：撰寫 `docker-compose.yml`，一鍵啟動 PostgreSQL + Node.js 服務
