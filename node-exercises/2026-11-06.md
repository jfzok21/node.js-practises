# 第 18 週今日 Node.js 練習題：Webhook 接收與事件處理系統

## 題目說明

在現代後端服務中，Webhook 是外部服務（如 GitHub、Stripe、Shopify）主動推送事件到你伺服器的常見機制。本練習要求你建立一個 **Webhook 接收伺服器**，能夠：
- 驗證請求簽名（防偽造）
- 解析並分類事件類型
- 非同步處理事件（寫入 log 檔）
- 提供 `/status` 端點查詢已接收的事件統計

## 技術要求

- 概念：HMAC 簽名驗證、事件驅動架構、非同步 I/O、JSON 解析
- 需要的套件：`express`、`crypto`（Node.js 內建）、`fs/promises`（Node.js 內建）

## 具體任務

1. **建立 Express 伺服器**，監聽 `POST /webhook`，接收 JSON payload。
2. **驗證簽名**：請求 Header 包含 `x-hub-signature-256`，格式為 `sha256=<HMAC>`。使用 `crypto.timingSafeEqual` 驗證，密鑰為環境變數 `WEBHOOK_SECRET`（預設 `"mysecret"`）。若驗證失敗，回傳 `401 Unauthorized`。
3. **解析事件**：payload 結構如下，依 `event` 欄位分類處理：
   ```json
   { "event": "payment.success", "data": { "orderId": "ORD-001", "amount": 500 } }
   ```
4. **非同步寫入 log**：將事件以 JSON Lines 格式（每行一筆）追加寫入 `events.log`，每筆包含 `timestamp`、`event`、`data`。
5. **建立 `GET /status` 端點**，讀取 `events.log`，回傳各事件類型的計數統計：
   ```json
   { "total": 5, "breakdown": { "payment.success": 3, "payment.failed": 2 } }
   ```
6. 伺服器啟動時若 `events.log` 不存在，自動建立空檔案。

## 範例

```js
// 發送合法 Webhook（以 curl 模擬）
// BODY='{"event":"payment.success","data":{"orderId":"ORD-001","amount":500}}'
// SIG=$(echo -n "$BODY" | openssl dgst -sha256 -hmac "mysecret" | awk '{print "sha256="$2}')
// curl -X POST http://localhost:3000/webhook \
//   -H "Content-Type: application/json" \
//   -H "x-hub-signature-256: $SIG" \
//   -d "$BODY"
// → 200 { "message": "Event received", "event": "payment.success" }

// 查詢統計
// curl http://localhost:3000/status
// → 200 { "total": 1, "breakdown": { "payment.success": 1 } }

// 偽造簽名
// curl -X POST http://localhost:3000/webhook \
//   -H "Content-Type: application/json" \
//   -H "x-hub-signature-256: sha256=invalidsig" \
//   -d "$BODY"
// → 401 { "error": "Invalid signature" }
```

## 提示

- 使用 `express.json()` middleware 解析 body，但**驗證前需要原始 body bytes**。可在 `express.json()` 之前用 `express.raw({ type: 'application/json' })` 拿到 `Buffer`，再自行 `JSON.parse`。
- `crypto.createHmac('sha256', secret).update(rawBody).digest('hex')` 產生 HMAC。
- `crypto.timingSafeEqual` 要求兩個 Buffer 長度相同，長度不同時直接回傳 false 即可。
- 寫入 log 用 `fs.appendFile`，讀取時用 `fs.readFile` 後以 `\n` 分割並 filter 空行。

## 學習重點（跟後端 API 的關聯）

| 概念 | 實際應用 |
|---|---|
| HMAC 簽名驗證 | GitHub Webhooks、Stripe Events 皆使用此機制確保來源合法 |
| `timingSafeEqual` | 防止 timing attack，是安全比較字串的正確做法 |
| JSON Lines 格式 | 大量事件 log 的輕量儲存格式，易於串流讀取 |
| 事件分類統計 | 建立監控 dashboard、告警系統的基礎 |
| `fs.appendFile` | 高頻寫入場景下比覆寫整個檔案更有效率 |

## 進階挑戰（選做）

1. **重試機制**：若 log 寫入失敗，將事件存入記憶體佇列，每 5 秒重試一次。
2. **事件過濾**：`GET /status?event=payment.success` 只回傳指定類型的記錄詳情。
3. **限流保護**：使用 Map 紀錄 IP，同一 IP 每秒超過 10 次請求則回傳 `429 Too Many Requests`。
4. **啟動時載入統計快取**：伺服器啟動時讀取 `events.log` 建立記憶體快取，`/status` 直接從快取回應（無需每次讀檔）。
