# 第 12 週今日 Node.js 練習題：用 Jest 測試 REST API 路由

## 題目說明

在真實的後端開發中，每次修改程式碼都需要確保原有功能不被破壞。本題要求你為一個簡單的「待辦事項（Todo）」Express API 撰寫完整的單元測試與整合測試，使用業界標準的 **Jest** 測試框架搭配 **Supertest** 進行 HTTP 層級的測試。

---

## 技術要求

- **概念**：單元測試（Unit Test）、整合測試（Integration Test）、測試覆蓋率（Code Coverage）、Mock、`describe` / `it` / `expect`
- **需要的套件**：
  - `jest`
  - `supertest`
  - `express`

---

## 具體任務

1. **建立待測試的 Express 應用程式**
   - 建立 `src/app.js`，匯出 Express app（不呼叫 `app.listen`，方便測試）
   - 實作以下路由（資料存在記憶體陣列中即可）：
     - `GET  /todos`         → 回傳所有待辦事項
     - `GET  /todos/:id`     → 回傳單一待辦事項（找不到回 404）
     - `POST /todos`         → 新增待辦事項（需有 `title` 欄位，否則回 400）
     - `DELETE /todos/:id`   → 刪除待辦事項（找不到回 404）

2. **設定 Jest**
   - 在 `package.json` 加入 `"test": "jest --coverage"` 腳本
   - 建立 `jest.config.js`，設定 `testEnvironment: 'node'`

3. **撰寫整合測試** `src/__tests__/todos.test.js`
   - 測試 `GET /todos` 回傳空陣列
   - 測試 `POST /todos` 成功新增並回傳 201
   - 測試 `POST /todos` 缺少 `title` 時回傳 400
   - 測試 `GET /todos/:id` 找到與找不到的兩種情境
   - 測試 `DELETE /todos/:id` 成功刪除與找不到的兩種情境

4. **確保每次測試互相隔離**
   - 在 `beforeEach` 重置記憶體資料，避免測試互相污染

5. **執行 `npm test` 並達到 ≥ 80% 行覆蓋率**

## 範例

```js
// src/app.js（部分）
const express = require('express');
const app = express();
app.use(express.json());

let todos = [];
let nextId = 1;

app.get('/todos', (req, res) => {
  res.json(todos);
});

app.post('/todos', (req, res) => {
  const { title } = req.body;
  if (!title) return res.status(400).json({ error: 'title is required' });
  const todo = { id: nextId++, title, done: false };
  todos.push(todo);
  res.status(201).json(todo);
});

// ... 其他路由

module.exports = { app, resetTodos: () => { todos = []; nextId = 1; } };
```

```js
// src/__tests__/todos.test.js（部分）
const request = require('supertest');
const { app, resetTodos } = require('../app');

beforeEach(() => {
  resetTodos();
});

describe('GET /todos', () => {
  it('應回傳空陣列', async () => {
    const res = await request(app).get('/todos');
    expect(res.status).toBe(200);
    expect(res.body).toEqual([]);
  });
});

describe('POST /todos', () => {
  it('成功新增時應回傳 201', async () => {
    const res = await request(app)
      .post('/todos')
      .send({ title: '買牛奶' });
    expect(res.status).toBe(201);
    expect(res.body).toMatchObject({ title: '買牛奶', done: false });
  });

  it('缺少 title 時應回傳 400', async () => {
    const res = await request(app).post('/todos').send({});
    expect(res.status).toBe(400);
  });
});
```

---

## 提示

- `supertest` 的 `request(app)` 會自動啟動臨時伺服器，不需要手動呼叫 `listen`
- 使用 `beforeEach` 而非 `afterEach` 重置狀態，確保每個測試開始時環境乾淨
- `toMatchObject` 比 `toEqual` 更有彈性，只驗證你關心的欄位
- 執行 `npx jest --coverage` 後，查看 `coverage/lcov-report/index.html` 可看到視覺化的覆蓋率報告

---

## 學習重點

**與後端 API 的關聯：**

在生產環境中，測試是確保 API 品質的核心機制：
- **整合測試**（本題重點）直接測試 HTTP 層，最接近真實用戶行為
- **持續整合（CI）** 在每次 Pull Request 時自動跑測試，防止 regression
- 良好的測試覆蓋率讓你在重構或新增功能時更有信心
- `beforeEach` / `afterEach` 的隔離策略同樣適用於資料庫（每次測試開啟 transaction 後 rollback）
