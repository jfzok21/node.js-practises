# 第 6 週今日 Node.js 練習題：自訂 Express Middleware 鏈

## 題目說明

Express 的核心優勢之一就是強大的 Middleware（中介軟體）系統。每個 Middleware 都是一個函式，能夠存取 `req`、`res` 與 `next`，並決定是否將控制權傳遞給下一個 Middleware 或直接回應請求。本次練習將帶你建立一套完整的 Middleware 鏈，涵蓋日誌記錄、身份驗證模擬與錯誤處理。

## 技術要求

- **概念：** Express Middleware、`app.use()`、`next()`、錯誤處理 Middleware（4 個參數）、路由級 Middleware
- **需要的套件：**
  - `express`（`npm install express`）
  - （選用）`morgan`（`npm install morgan`）用於與自訂 logger 比較

## 具體任務

1. **建立 `server.js`**，初始化 Express app，監聽 `PORT=3000`。

2. **實作「請求日誌」全域 Middleware** `requestLogger`：
   - 輸出格式：`[2026-08-11T10:00:00.000Z] GET /api/users 200`
   - 必須在請求結束後（使用 `res.on('finish', ...)`）才輸出狀態碼。

3. **實作「API Key 驗證」Middleware** `requireApiKey`：
   - 讀取請求 Header：`x-api-key`
   - 若值等於 `SECRET123`，呼叫 `next()` 繼續。
   - 否則回應 `401 Unauthorized`，JSON body：`{ "error": "Invalid or missing API key" }`。

4. **建立以下路由：**
   - `GET /public`：不需要 API Key，回應 `{ "message": "公開資源，任何人皆可存取" }`
   - `GET /api/users`：需要 `requireApiKey`，回應假資料使用者陣列（至少 2 筆）
   - `POST /api/users`：需要 `requireApiKey`，從 `req.body` 讀取 `{ name, email }`，若缺少任一欄位回應 `400 Bad Request`，否則回應 `201 Created` 與新建立的使用者資料

5. **實作「錯誤處理」Middleware**（4 個參數：`err, req, res, next`）：
   - 統一回應格式：`{ "error": err.message, "status": err.status || 500 }`
   - 在 `GET /api/broken` 路由中，呼叫 `next(new Error('資料庫連線失敗'))` 來觸發此 Middleware。

## 範例

```js
// 範例請求與預期回應

// 1. 公開路由（不需要 API Key）
// GET /public
// → 200 { "message": "公開資源，任何人皆可存取" }

// 2. 缺少 API Key
// GET /api/users
// → 401 { "error": "Invalid or missing API key" }

// 3. 正確 API Key
// GET /api/users  Headers: { "x-api-key": "SECRET123" }
// → 200 [{ "id": 1, "name": "Alice" }, { "id": 2, "name": "Bob" }]

// 4. 建立使用者（缺少欄位）
// POST /api/users  Headers: { "x-api-key": "SECRET123" }
// Body: { "name": "Carol" }
// → 400 { "error": "name 與 email 為必填欄位" }

// 5. 觸發錯誤處理
// GET /api/broken  Headers: { "x-api-key": "SECRET123" }
// → 500 { "error": "資料庫連線失敗", "status": 500 }
```

```js
// server.js 骨架
const express = require('express');
const app = express();

app.use(express.json()); // 解析 JSON body

// --- 全域 Middleware ---
function requestLogger(req, res, next) {
  const start = new Date().toISOString();
  res.on('finish', () => {
    console.log(`[${start}] ${req.method} ${req.path} ${res.statusCode}`);
  });
  next();
}

function requireApiKey(req, res, next) {
  // TODO：驗證 x-api-key header
}

app.use(requestLogger);

// --- 路由 ---
app.get('/public', (req, res) => {
  // TODO
});

app.get('/api/users', requireApiKey, (req, res) => {
  // TODO
});

app.post('/api/users', requireApiKey, (req, res, next) => {
  // TODO
});

app.get('/api/broken', requireApiKey, (req, res, next) => {
  next(new Error('資料庫連線失敗'));
});

// --- 錯誤處理 Middleware（必須放在最後）---
app.use((err, req, res, next) => {
  // TODO
});

app.listen(3000, () => console.log('Server running on http://localhost:3000'));
```

## 提示

- `app.use(fn)` 會對**所有路由**套用 Middleware；`app.get('/path', fn, handler)` 只對**該路由**套用。
- 錯誤處理 Middleware 必須宣告為**4 個參數**（`err, req, res, next`），Express 才能識別它為錯誤處理器。
- 在 `requireApiKey` 中，若驗證失敗記得 **`return`**，避免繼續執行後面的程式碼。
- 使用 `curl` 或 [Postman](https://www.postman.com/) 測試各種情境。

```bash
# 快速測試指令
curl http://localhost:3000/public
curl -H "x-api-key: SECRET123" http://localhost:3000/api/users
curl -X POST -H "x-api-key: SECRET123" -H "Content-Type: application/json" \
     -d '{"name":"Carol","email":"carol@example.com"}' \
     http://localhost:3000/api/users
curl -H "x-api-key: SECRET123" http://localhost:3000/api/broken
```

## 學習重點（跟後端 API 的關聯）

Middleware 是實際後端專案的骨幹：

| Middleware 類型 | 真實應用場景 |
|---|---|
| 日誌記錄 | 追蹤 API 使用量、除錯問題 |
| 身份驗證 | JWT 驗證、API Key 保護 |
| 請求驗證 | 確保輸入資料完整性（第 10 週深入探討）|
| 錯誤處理 | 統一回應格式、防止敏感資訊外洩 |

理解 Middleware 鏈的執行順序（`next()` 的流向）是掌握 Express 架構的關鍵。

## 進階挑戰（選做）

1. **速率限制 Middleware**：用 `Map` 在記憶體中追蹤每個 IP 的請求次數，1 分鐘內超過 10 次則回應 `429 Too Many Requests`。

2. **回應時間 Header**：在 `requestLogger` 中計算請求處理時間（毫秒），並加入 `X-Response-Time: 42ms` Header。

3. **條件式 Middleware**：建立一個 `skipIfPublic` 函式，讓某些路由能夠動態跳過特定 Middleware（提示：可在 `req` 物件上附加自訂屬性）。

4. **Middleware 模組化**：將 `requestLogger` 與 `requireApiKey` 抽取到獨立的 `middlewares/` 資料夾，並用 `module.exports` 匯出。
