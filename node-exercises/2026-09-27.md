# 第 12 週今日 Node.js 練習題：使用 Jest 測試 REST API

## 題目說明

在這個練習中，你將為一個簡單的使用者管理 API 撰寫 Jest 測試。透過撰寫單元測試和整合測試，學習如何確保程式碼的正確性和穩定性，並建立良好的測試習慣。

## 技術要求

- **概念**：Jest 測試框架、describe/it/test、expect 斷言、mock 函數、非同步測試、beforeEach/afterEach
- **需要的套件**：`jest`、`supertest`、`express`

## 具體任務

1. 建立一個 Express 應用程式，提供以下 REST API 端點：
   - `GET /users` - 取得所有使用者
   - `GET /users/:id` - 依 ID 取得單一使用者
   - `POST /users` - 新增使用者
   - `DELETE /users/:id` - 刪除使用者

2. 為資料層（data layer）撰寫**單元測試**：
   - 測試取得所有使用者
   - 測試依 ID 查詢（找到 / 找不到兩種情境）
   - 測試新增使用者
   - 測試刪除使用者

3. 使用 `supertest` 撰寫 **API 整合測試**：
   - 測試 `GET /users` 回傳 200 及陣列
   - 測試 `GET /users/:id` 找到時回傳 200、找不到時回傳 404
   - 測試 `POST /users` 建立成功回傳 201
   - 測試 `DELETE /users/:id` 刪除成功回傳 200

4. 在 `package.json` 中設定 `"test": "jest --verbose"` 指令並確認所有測試通過。

## 範例

```js
// userService.js
const users = [
  { id: 1, name: '小明', email: 'xiao@example.com' },
  { id: 2, name: '小花', email: 'hua@example.com' },
];

function getAllUsers() {
  return users;
}

function getUserById(id) {
  return users.find(u => u.id === id) || null;
}

function createUser(name, email) {
  const newUser = { id: users.length + 1, name, email };
  users.push(newUser);
  return newUser;
}

function deleteUser(id) {
  const index = users.findIndex(u => u.id === id);
  if (index === -1) return false;
  users.splice(index, 1);
  return true;
}

module.exports = { getAllUsers, getUserById, createUser, deleteUser };

// userService.test.js
const { getAllUsers, getUserById, createUser, deleteUser } = require('./userService');

describe('UserService 單元測試', () => {
  test('getAllUsers 應回傳使用者陣列', () => {
    const result = getAllUsers();
    expect(Array.isArray(result)).toBe(true);
    expect(result.length).toBeGreaterThan(0);
  });

  test('getUserById 找到時應回傳使用者物件', () => {
    const user = getUserById(1);
    expect(user).not.toBeNull();
    expect(user.name).toBe('小明');
  });

  test('getUserById 找不到時應回傳 null', () => {
    const user = getUserById(999);
    expect(user).toBeNull();
  });
});

// app.test.js（整合測試）
const request = require('supertest');
const app = require('./app');

describe('GET /users', () => {
  it('應回傳 200 及使用者陣列', async () => {
    const res = await request(app).get('/users');
    expect(res.statusCode).toBe(200);
    expect(Array.isArray(res.body)).toBe(true);
  });
});

describe('GET /users/:id', () => {
  it('找到時應回傳 200', async () => {
    const res = await request(app).get('/users/1');
    expect(res.statusCode).toBe(200);
    expect(res.body.id).toBe(1);
  });

  it('找不到時應回傳 404', async () => {
    const res = await request(app).get('/users/9999');
    expect(res.statusCode).toBe(404);
  });
});

describe('POST /users', () => {
  it('新增成功應回傳 201 及新使用者', async () => {
    const res = await request(app)
      .post('/users')
      .send({ name: '阿志', email: 'zhi@example.com' });
    expect(res.statusCode).toBe(201);
    expect(res.body.name).toBe('阿志');
  });
});
```

## 提示

- 使用 `describe` 將相關測試群組化，讓測試報告更易讀。
- 測試檔案命名慣例：`*.test.js` 或 `*.spec.js`，Jest 會自動找到它們。
- 非同步測試記得使用 `async/await` 或回傳 Promise，否則 Jest 可能在非同步完成前就結束。
- `beforeEach` 可用來在每個測試前重置資料狀態，避免測試互相干擾。
- `supertest` 不需要真正啟動伺服器，直接傳入 Express app 即可測試 HTTP 請求。

## 學習重點（跟後端 API 的關聯）

在實際後端開發中，測試扮演非常關鍵的角色：

- **單元測試**確保每個函數的邏輯正確，能快速定位 bug。
- **整合測試**驗證 API 端點在真實 HTTP 環境下的行為，模擬前端呼叫。
- 測試套件能在重構或新增功能時保護既有功能不被破壞（**迴歸測試**）。
- CI/CD pipeline 通常在每次 push 自動執行測試，確保程式碼品質。
- 良好的測試覆蓋率讓團隊成員更有信心修改程式碼。

## 進階挑戰（選做）

1. **Mock 外部依賴**：使用 `jest.mock()` 模擬資料庫呼叫（例如假設資料來自 PostgreSQL），讓單元測試不依賴真實 DB。
2. **測試覆蓋率報告**：執行 `jest --coverage` 查看哪些程式碼尚未被測試覆蓋。
3. **測試錯誤情境**：新增 `POST /users` 缺少必填欄位（name/email）時回傳 400 的測試。
4. **beforeEach 重置狀態**：在整合測試中使用 `beforeEach` 重置使用者列表，確保每個測試獨立。
5. **快照測試（Snapshot）**：使用 `expect(result).toMatchSnapshot()` 記錄 API 回應格式，防止意外變更。
