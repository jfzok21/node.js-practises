# 第 17 週今日 Node.js 練習題：任務管理 REST API 實戰專案

## 題目說明

建立一個完整的「個人任務管理系統」REST API，整合 Express、PostgreSQL、JWT 身份驗證與輸入驗證。這個練習模擬真實後端工作場景，要求你從零到一完成一套可上線的 API 服務。

---

## 技術要求

- **概念：** REST API 設計、JWT 驗證、資料庫 CRUD、Middleware 鏈、錯誤處理
- **需要的套件：**
  - `express`
  - `pg`（PostgreSQL 客戶端）
  - `jsonwebtoken`
  - `bcryptjs`
  - `joi`（輸入驗證）
  - `dotenv`

---

## 具體任務

### 1. 專案初始化

建立 `task-manager/` 專案資料夾，初始化 `package.json`，安裝必要套件，並設定以下目錄結構：

```
task-manager/
├── src/
│   ├── routes/
│   │   ├── auth.js
│   │   └── tasks.js
│   ├── middleware/
│   │   ├── auth.js       ← JWT 驗證 middleware
│   │   └── validate.js   ← Joi 驗證 middleware
│   ├── db/
│   │   └── index.js      ← pg Pool 連線
│   └── app.js
├── .env
└── server.js
```

---

### 2. 資料庫設計

建立兩張資料表：

**users 表：**
```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);
```

**tasks 表：**
```sql
CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  title VARCHAR(255) NOT NULL,
  description TEXT,
  status VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending', 'in_progress', 'done')),
  due_date DATE,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

---

### 3. 實作 Auth API

| 方法 | 路徑 | 說明 |
|------|------|------|
| POST | `/api/auth/register` | 使用者註冊 |
| POST | `/api/auth/login` | 登入並取得 JWT |

- 密碼使用 `bcryptjs` 雜湊（salt rounds: 10）
- 登入成功回傳 `{ token, user: { id, email } }`
- Token 有效期設為 7 天

---

### 4. 實作 Tasks CRUD API（需要 JWT 驗證）

| 方法 | 路徑 | 說明 |
|------|------|------|
| GET | `/api/tasks` | 取得當前使用者的所有任務 |
| POST | `/api/tasks` | 建立新任務 |
| GET | `/api/tasks/:id` | 取得單一任務 |
| PATCH | `/api/tasks/:id` | 更新任務（部分更新） |
| DELETE | `/api/tasks/:id` | 刪除任務 |

**注意：每位使用者只能存取自己的任務（user_id 隔離）。**

---

### 5. 加入查詢過濾功能

`GET /api/tasks` 支援 query string 過濾：

```
GET /api/tasks?status=pending
GET /api/tasks?status=done&sort=due_date
GET /api/tasks?search=報告
```

---

### 6. 統一錯誤處理

實作 Express 全域錯誤 middleware，回傳一致格式：

```json
{
  "success": false,
  "message": "錯誤說明",
  "errors": []
}
```

## 範例

```js
// 註冊
// POST /api/auth/register
// Body: { "email": "user@example.com", "password": "secret123" }
// Response:
{
  "success": true,
  "message": "註冊成功",
  "user": { "id": 1, "email": "user@example.com" }
}

// 登入後建立任務
// POST /api/tasks
// Headers: Authorization: Bearer <token>
// Body: { "title": "準備週報", "status": "pending", "due_date": "2026-11-01" }
// Response:
{
  "success": true,
  "task": {
    "id": 1,
    "title": "準備週報",
    "status": "pending",
    "due_date": "2026-11-01",
    "created_at": "2026-10-29T08:00:00.000Z"
  }
}
```

---

## 提示

- 在 JWT middleware 裡，從 `Authorization: Bearer <token>` 標頭提取 token，驗證後將 `req.user = { id, email }` 注入到請求物件。
- 所有資料庫查詢都加上 `WHERE user_id = $1` 確保資料隔離。
- 使用 `pg` 的 parameterized query（`$1`, `$2`...）防止 SQL Injection。
- `PATCH` 路由只更新傳入的欄位，不影響未傳入的欄位（使用動態 SQL 建構）。
- 善用 `.env` 儲存 `DATABASE_URL`、`JWT_SECRET`，不要 hardcode 到程式碼裡。

---

## 學習重點（跟後端 API 的關聯）

這個練習是真實後端工作的縮影：

1. **JWT + Middleware 鏈**：驗證邏輯與業務邏輯分離，是大型 API 的標準模式。
2. **資料隔離（user_id 邊界）**：多租戶系統的核心安全概念，一旦缺漏即是資料洩漏漏洞。
3. **動態 PATCH**：比覆蓋式 PUT 更節省頻寬，也更接近現代 API 設計（如 GitHub API）。
4. **統一錯誤格式**：前端只需處理一種錯誤結構，大幅降低整合成本。
5. **參數化查詢**：防止 SQL Injection，是後端開發者必備的安全習慣。

## 進階挑戰（選做）

1. **分頁功能**：`GET /api/tasks?page=1&limit=10`，回傳 `{ tasks, total, page, totalPages }`
2. **任務標籤**：新增 `tags` 資料表，實作多對多關聯（tasks ↔ tags）
3. **軟刪除**：加入 `deleted_at` 欄位，`DELETE` 改為 soft delete，並提供 `/api/tasks/trash` 查看已刪除任務
4. **Rate Limiting**：使用 `express-rate-limit` 限制登入 API 每分鐘最多 5 次嘗試，防暴力破解
5. **Jest 整合測試**：使用測試資料庫撰寫 Auth 與 Tasks 路由的整合測試
