# 第 15 週今日 Node.js 練習題：任務管理 REST API 實戰專案

## 題目說明

綜合運用前 14 週所學，從零到一打造一個完整的「任務管理系統」後端 API。
此系統需支援使用者註冊/登入、JWT 驗證、任務 CRUD、圖片附件上傳，並搭配 PostgreSQL 儲存資料與 Jest 撰寫測試。

## 技術要求
- 概念：Express、JWT 身份驗證、輸入驗證（joi/zod）、PostgreSQL、檔案上傳（multer）、Jest 單元測試
- 需要的套件：`express`, `pg`, `jsonwebtoken`, `bcryptjs`, `multer`, `joi`, `jest`, `supertest`, `dotenv`

## 具體任務

1. **專案初始化**
   - `npm init -y`，安裝上述套件
   - 建立 `.env`（`DATABASE_URL`、`JWT_SECRET`、`PORT`）
   - 建立 `src/` 目錄結構（`routes/`、`controllers/`、`middleware/`、`db/`）

2. **資料庫 Schema**
   - 建立 `users` 資料表：`id`（serial PK）、`email`（unique）、`password_hash`、`created_at`
   - 建立 `tasks` 資料表：`id`（serial PK）、`user_id`（FK → users）、`title`、`description`、`status`（pending/in_progress/done）、`attachment_path`、`created_at`、`updated_at`

3. **使用者 API**
   - `POST /api/auth/register`：驗證 email 格式與密碼長度（≥8 字元），用 bcrypt hash 後儲存
   - `POST /api/auth/login`：驗證成功後回傳 JWT（有效期 7 天）

4. **任務 CRUD API（需 JWT 驗證）**
   - `GET /api/tasks`：取得目前使用者的所有任務（支援 `?status=` 篩選）
   - `POST /api/tasks`：建立任務，驗證 `title`（必填，1–100 字）
   - `PUT /api/tasks/:id`：更新任務（僅能更新自己的任務）
   - `DELETE /api/tasks/:id`：刪除任務
   - `POST /api/tasks/:id/attachment`：上傳圖片附件（限 jpg/png，≤ 2MB）

5. **撰寫 Jest 測試**
   - 測試 `POST /api/auth/register`（成功、email 重複、格式錯誤）
   - 測試 `POST /api/tasks`（帶 / 不帶 token、欄位驗證失敗）

## 範例

```js
// POST /api/auth/register
// Body: { "email": "alice@example.com", "password": "secret123" }
// Response 201:
{ "message": "註冊成功", "userId": 1 }

// POST /api/auth/login
// Response 200:
{ "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." }

// GET /api/tasks?status=pending  (Authorization: Bearer <token>)
// Response 200:
[
  { "id": 3, "title": "寫 API 文件", "status": "pending", "created_at": "2026-10-16T..." }
]

// POST /api/tasks/:id/attachment  (multipart/form-data, field: "file")
// Response 200:
{ "message": "附件上傳成功", "path": "/uploads/task-3-1729123456789.png" }
```

## 提示
- 使用 `express-async-errors` 套件可統一捕捉 async controller 的例外
- `multer` 的 `fileFilter` 回呼可用來拒絕非圖片格式
- 測試時可使用 `supertest` 直接測試 Express app，不需實際啟動伺服器
- 善用 `pg` 的 `Pool` 物件管理連線，避免 connection leak
- `process.env.NODE_ENV === 'test'` 時可切換到測試資料庫

## 學習重點（跟後端 API 的關聯）

| 本週技能 | 實際場景 |
|----------|----------|
| JWT 身份驗證 | 幾乎所有需登入的 SaaS API 都使用此模式 |
| 輸入驗證 | 防止注入攻擊、確保資料完整性 |
| 檔案上傳 | 電商商品圖片、用戶頭像、文件管理系統 |
| PostgreSQL FK | 確保資料關聯性（用戶刪除 → 任務一併處理）|
| Jest + supertest | CI/CD pipeline 中的自動化測試把關 |

## 進階挑戰（選做）

- **分頁**：`GET /api/tasks?page=1&limit=10`，回傳 `{ data, total, page, totalPages }`
- **軟刪除**：在 `tasks` 加入 `deleted_at` 欄位，查詢時過濾掉已刪除的記錄
- **任務優先級**：加入 `priority`（low/medium/high）欄位，並支援依 priority 排序
- **Swagger 文件**：使用 `swagger-jsdoc` + `swagger-ui-express` 自動產生 API 文件
- **Rate Limiting**：使用 `express-rate-limit` 限制登入 API（每分鐘最多 5 次）
