# 第 9 週今日 Node.js 練習題：JWT 身份驗證系統

## 題目說明

實作一個完整的 JWT（JSON Web Token）身份驗證系統，包含使用者登入、Token 簽發、受保護路由的存取控制，以及 Token 刷新機制。這是現代 REST API 最常見的無狀態身份驗證方式。

## 技術要求

- 概念：JWT 結構（Header、Payload、Signature）、非對稱 / 對稱加密、Token 過期機制、Middleware 攔截
- 需要的套件：`express`、`jsonwebtoken`、`bcryptjs`、`dotenv`

## 具體任務

1. **初始化專案**
   - 建立 `week9-jwt/` 資料夾，`npm init -y`
   - 安裝所需套件：`npm install express jsonwebtoken bcryptjs dotenv`
   - 建立 `.env` 檔，設定 `JWT_SECRET` 與 `JWT_REFRESH_SECRET`

2. **建立使用者資料（模擬資料庫）**
   - 在 `users.js` 中建立一個記憶體陣列存放使用者（id、username、passwordHash）
   - 用 `bcryptjs.hashSync` 預先雜湊密碼

3. **實作 `/api/login` 端點（POST）**
   - 接收 `{ username, password }`
   - 用 `bcryptjs.compare` 驗證密碼
   - 簽發 Access Token（15 分鐘過期）與 Refresh Token（7 天過期）
   - 回傳 `{ accessToken, refreshToken }`

4. **實作 JWT 驗證 Middleware**
   - 從 `Authorization: Bearer <token>` 標頭取得 Token
   - 用 `jwt.verify` 驗證，失敗時回傳 `401 Unauthorized`
   - 驗證成功後將 `payload` 掛到 `req.user`

5. **建立受保護路由 `/api/profile`（GET）**
   - 套用驗證 Middleware
   - 回傳目前登入使用者的資訊

6. **實作 `/api/refresh` 端點（POST）**
   - 接收 `{ refreshToken }`
   - 驗證 Refresh Token，簽發新的 Access Token
   - 回傳 `{ accessToken }`

## 範例

```js
// 登入請求
POST /api/login
Body: { "username": "alice", "password": "secret123" }

// 成功回應
{
  "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refreshToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}

// 存取受保護路由
GET /api/profile
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

// 成功回應
{
  "id": 1,
  "username": "alice",
  "message": "歡迎回來，alice！"
}

// Token 過期或無效的錯誤回應
HTTP 401
{
  "error": "Token 無效或已過期"
}
```

## 提示

- `jwt.sign(payload, secret, { expiresIn: '15m' })` 簽發 Token
- `jwt.verify(token, secret)` 驗證時若失敗會拋出例外，記得用 `try/catch`
- Refresh Token 應使用不同的 Secret，增加安全性
- 生產環境中 Refresh Token 應存在資料庫（Redis / PostgreSQL）並支援撤銷
- 可用 [jwt.io](https://jwt.io) 解碼 Token 觀察結構

## 學習重點

（跟後端 API 的關聯）

JWT 是現代 REST API 最主流的身份驗證方案，取代傳統 Session Cookie 的有狀態設計：

- **無狀態（Stateless）**：伺服器不需要存儲 Session，適合橫向擴展的微服務架構
- **Middleware 模式**：身份驗證邏輯集中在 Middleware，所有受保護路由統一套用，符合 DRY 原則
- **Access / Refresh Token 雙 Token 機制**：短效 Access Token 降低洩漏風險，長效 Refresh Token 維持使用者登入狀態
- **第 10 週預告**：下週將在此基礎上加入輸入驗證（Joi / Zod）與全域錯誤處理 Middleware

## 進階挑戰（選做）

1. **Token 黑名單**：登出時將 Token 加入記憶體黑名單，驗證 Middleware 需額外檢查
2. **角色權限控管**：在 JWT Payload 加入 `role`（admin / user），實作角色型存取控制（RBAC）Middleware
3. **HTTPOnly Cookie**：將 Refresh Token 改用 `res.cookie` 設為 HTTPOnly Cookie，防止 XSS 竊取
4. **Token 自動刷新**：在前端攔截 401 回應，自動呼叫 `/api/refresh` 後重試原請求
