# 第 17 週今日 Node.js 練習題：個人日記 REST API（完整實戰專案）

## 題目說明

建立一個具備完整後端功能的「個人日記 API」，涵蓋使用者身份驗證、CRUD 操作、標籤分類、圖片附件、搜尋功能與單元測試。本題整合前 12 週所有核心技術，模擬真實工作中的後端 API 開發流程。

---

## 技術要求

- **概念**：REST API 設計、JWT 身份驗證、資料庫關聯、分頁、搜尋、錯誤處理、測試
- **需要的套件**：
  - `express` — 路由與伺服器
  - `pg` — PostgreSQL 連線
  - `bcryptjs` — 密碼雜湊
  - `jsonwebtoken` — JWT 產生與驗證
  - `multer` — 圖片上傳
  - `joi` — 輸入驗證
  - `jest` + `supertest` — API 測試

## 具體任務

### 1. 資料庫設計（PostgreSQL）

建立以下三張資料表：

```sql
-- 使用者
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 日記文章
CREATE TABLE diary_entries (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  title VARCHAR(255) NOT NULL,
  content TEXT NOT NULL,
  mood VARCHAR(50),          -- happy / neutral / sad / anxious
  is_private BOOLEAN DEFAULT true,
  image_url VARCHAR(500),
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- 標籤
CREATE TABLE tags (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  name VARCHAR(100) NOT NULL
);

-- 日記與標籤的多對多關聯
CREATE TABLE entry_tags (
  entry_id INTEGER REFERENCES diary_entries(id) ON DELETE CASCADE,
  tag_id   INTEGER REFERENCES tags(id) ON DELETE CASCADE,
  PRIMARY KEY (entry_id, tag_id)
);
```

### 2. 實作 API 路由

**身份驗證：**
- `POST /api/auth/register` — 註冊（email、password）
- `POST /api/auth/login` — 登入，回傳 JWT

**日記文章（需攜帶 JWT）：**
- `GET /api/entries?page=1&limit=10&mood=happy&search=關鍵字` — 列出我的日記（分頁 + 篩選）
- `POST /api/entries` — 新增日記（可含標籤陣列）
- `GET /api/entries/:id` — 取得單篇日記（含標籤）
- `PUT /api/entries/:id` — 更新日記
- `DELETE /api/entries/:id` — 刪除日記
- `POST /api/entries/:id/image` — 上傳封面圖片（multer）

**標籤管理：**
- `GET /api/tags` — 列出我的所有標籤
- `POST /api/tags` — 新增標籤
- `DELETE /api/tags/:id` — 刪除標籤

### 3. 中介層（Middleware）

```
src/
  middleware/
    auth.js        ← 驗證 JWT，將 user 掛在 req.user
    validate.js    ← 包裝 Joi schema 的通用驗證 middleware
    errorHandler.js ← 全域錯誤處理
```

### 4. 輸入驗證（Joi）

至少為以下路由加上 Joi 驗證 schema：
- 註冊：email 格式、密碼至少 8 字元
- 新增/更新日記：title 必填、mood 限定枚舉值、tags 為字串陣列

### 5. 撰寫 Jest 測試

為以下情境各寫一個測試：
- 成功註冊並取得 201 狀態碼
- 重複 email 註冊回傳 409
- 未帶 token 呼叫受保護路由回傳 401
- 成功新增日記並驗證回應結構

## 範例

```js
// POST /api/entries
// Request body:
{
  "title": "第一次爬山",
  "content": "今天挑戰了合歡山，景色壯麗...",
  "mood": "happy",
  "is_private": false,
  "tags": ["戶外", "運動"]
}

// Response 201:
{
  "id": 42,
  "title": "第一次爬山",
  "content": "今天挑戰了合歡山，景色壯麗...",
  "mood": "happy",
  "is_private": false,
  "image_url": null,
  "tags": ["戶外", "運動"],
  "created_at": "2026-10-30T08:00:00.000Z"
}
```

---

## 提示

- 用 `bcryptjs.hash(password, 10)` 儲存密碼，登入時用 `bcryptjs.compare()` 驗證
- JWT payload 只放 `{ userId, email }`，不要放敏感資訊
- 分頁查詢：`LIMIT $1 OFFSET $2`，offset = (page - 1) * limit
- 搜尋功能：`WHERE title ILIKE $1 OR content ILIKE $1`，參數傳 `%關鍵字%`
- multer 可設定 `destination: 'uploads/'` 搭配靜態路由 `app.use('/uploads', express.static('uploads'))`
- 標籤的新增可在 transaction 裡批次 INSERT INTO entry_tags

## 進階挑戰（選做）

1. **軟刪除**：在 `diary_entries` 加入 `deleted_at` 欄位，刪除時只更新時間戳，查詢時加上 `WHERE deleted_at IS NULL`
2. **Redis 快取**：用 `ioredis` 快取 `GET /api/entries` 的結果（TTL 60 秒），更新 / 刪除時清除快取
3. **Rate Limiting**：用 `express-rate-limit` 限制登入路由每 IP 每分鐘最多 5 次，防止暴力破解
4. **Swagger 文件**：使用 `swagger-ui-express` + `swagger-jsdoc` 自動產生 API 文件頁面
5. **Docker Compose**：撰寫 `docker-compose.yml`，一鍵啟動 Node.js + PostgreSQL 開發環境
