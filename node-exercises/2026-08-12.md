# 第 6 週今日 Node.js 練習題：Express Middleware 中介軟體

## 題目說明

本週的重點是 Express 的核心概念之一：**Middleware（中介軟體）**。Middleware 是在請求（Request）和回應（Response）之間執行的函式，可用來處理驗證、日誌記錄、錯誤處理等任務。本題將帶你實作多種類型的 middleware，並了解其執行順序與應用場景。

---

## 技術要求

- **概念**：Middleware 執行順序、`next()` 函式、錯誤處理 middleware、Router-level middleware
- **需要的套件**：
  - `express`（核心框架）
  - `morgan`（HTTP 請求日誌）
  - `cors`（跨來源資源共享）

---

## 具體任務

1. **初始化專案**
   - 建立新資料夾 `week6-middleware`，執行 `npm init -y`
   - 安裝相依套件：`npm install express morgan cors`

2. **建立基本 Express 伺服器**（`app.js`）
   - 使用 `express.json()` 解析 JSON 請求體
   - 整合 `morgan('dev')` 顯示請求日誌
   - 整合 `cors()` 允許跨來源請求

3. **實作自訂 Application-level Middleware**
   - 建立一個 `requestLogger` middleware，在每次請求時印出：
     - 時間戳記、HTTP 方法、請求路徑、用戶端 IP
   - 建立一個 `authChecker` middleware，檢查 request header 是否包含 `x-api-key: secret123`，若無則回傳 `401 Unauthorized`

4. **實作 Router-level Middleware**
   - 建立 `/api/public` router：不需要驗證，任何人都能存取
   - 建立 `/api/private` router：套用 `authChecker`，需要有效 API Key 才能存取

5. **實作錯誤處理 Middleware**
   - 建立一個全域錯誤處理 middleware（4 個參數：`err, req, res, next`）
   - 回傳統一格式：`{ success: false, message: "...", status: 狀態碼 }`

6. **建立測試路由**
   - `GET /api/public/hello`：回傳 `{ message: "公開路由，歡迎訪問！" }`
   - `GET /api/private/profile`：回傳 `{ message: "私人路由，驗證成功！", user: "admin" }`
   - `GET /api/error-test`：手動拋出一個 `Error("測試錯誤")` 讓錯誤 middleware 捕捉

---

## 範例

```js
// middleware/authChecker.js
const authChecker = (req, res, next) => {
  const apiKey = req.headers['x-api-key'];
  if (apiKey !== 'secret123') {
    return res.status(401).json({
      success: false,
      message: '未授權：缺少或無效的 API Key',
    });
  }
  next(); // 驗證通過，繼續往下執行
};

module.exports = authChecker;

// ---

// middleware/errorHandler.js
const errorHandler = (err, req, res, next) => {
  const status = err.status || 500;
  res.status(status).json({
    success: false,
    message: err.message || '伺服器內部錯誤',
    status,
  });
};

module.exports = errorHandler;

// ---

// app.js 結構
const express = require('express');
const morgan = require('morgan');
const cors = require('cors');
const authChecker = require('./middleware/authChecker');
const errorHandler = require('./middleware/errorHandler');

const app = express();

// Application-level middleware（全域套用）
app.use(cors());
app.use(morgan('dev'));
app.use(express.json());

// 自訂 requestLogger
app.use((req, res, next) => {
  console.log(`[${new Date().toISOString()}] ${req.method} ${req.path} - IP: ${req.ip}`);
  next();
});

// 公開路由（不需驗證）
app.use('/api/public', require('./routes/public'));

// 私人路由（套用 authChecker）
app.use('/api/private', authChecker, require('./routes/private'));

// 錯誤測試路由
app.get('/api/error-test', (req, res, next) => {
  next(new Error('測試錯誤'));
});

// 全域錯誤處理 middleware（必須放在最後）
app.use(errorHandler);

app.listen(3000, () => console.log('Server running on port 3000'));
```

```bash
# 測試指令

# 公開路由（不需 API Key）
curl http://localhost:3000/api/public/hello

# 私人路由（無 API Key，應回傳 401）
curl http://localhost:3000/api/private/profile

# 私人路由（帶 API Key，應成功）
curl -H "x-api-key: secret123" http://localhost:3000/api/private/profile

# 錯誤處理測試
curl http://localhost:3000/api/error-test
```

---

## 提示

- Middleware 的**執行順序**非常重要，`app.use()` 的宣告順序就是執行順序。
- 每個 middleware 必須呼叫 `next()` 才能繼續執行，否則請求會「卡住」。
- 錯誤處理 middleware 必須有 **4 個參數**（`err, req, res, next`），Express 才會將其識別為錯誤處理器。
- 將 middleware 分開到 `middleware/` 資料夾是良好的專案結構習慣。
- 使用 `next(err)` 來將錯誤傳遞給錯誤處理 middleware。

---

## 學習重點（跟後端 API 的關聯）

Middleware 是現代後端 API 架構的基石，幾乎所有真實專案都會大量使用：

| Middleware 類型 | 真實應用場景 |
|---|---|
| `express.json()` | 解析前端送來的 JSON 請求體 |
| `cors()` | 允許前端（不同 port/域）呼叫 API |
| `morgan` | 生產環境的請求日誌記錄 |
| 自訂 `authChecker` | JWT 驗證（第 9 週將深入實作） |
| 錯誤處理 middleware | 統一的錯誤格式，前端才能可靠地處理錯誤 |

理解 middleware 的執行鏈後，你將能輕鬆看懂任何 Express 專案的架構。

## 進階挑戰（選做）

1. **速率限制**：安裝 `express-rate-limit`，對 `/api/private` 路由設定每分鐘最多 5 次請求的限制。
2. **請求計時**：建立一個 middleware 計算每個請求的處理時間，並在 response header 加上 `X-Response-Time: Xms`。
3. **條件式 middleware**：讓 `authChecker` 支援兩種驗證方式：`x-api-key` header 或 URL query string `?apiKey=secret123`。
