# 第 21 週今日 Node.js 練習題：即時資料儀表板 API（WebSocket + SSE）

## 題目說明

建立一個「即時資料儀表板」後端服務，能讓前端透過 Server-Sent Events（SSE）或 WebSocket 訂閱即時更新，同時提供 REST API 供管理端查詢與推送資料。這道題整合了前面所有週次的核心技能，是貼近實務的全端專案場景。

---

## 技術要求

- **概念**：WebSocket 雙向通訊、SSE 單向推送、事件驅動架構、記憶體狀態管理
- **需要的套件**：
  - `express` — HTTP 伺服器與 REST API
  - `ws` — WebSocket 伺服器
  - `express-validator` — 輸入驗證
  - `jsonwebtoken` — 連線驗證（選做）
  - `jest` + `supertest` — 測試

---

## 具體任務

1. **初始化專案**
   - `npm init -y`，安裝 `express`、`ws`、`express-validator`
   - 建立 `src/` 目錄，拆分 `app.js`（Express）、`wsServer.js`（WebSocket）、`store.js`（狀態）

2. **建立記憶體狀態層（`store.js`）**
   - 維護一個「指標清單」，每筆資料格式：
     ```js
     { id, name, value, unit, updatedAt }
     ```
   - 提供 `getAll()`、`upsert(metric)`、`subscribe(fn)` / `unsubscribe(fn)` 方法
   - 當資料更新時，透過 pub/sub 通知所有訂閱者

3. **REST API（`app.js`）**
   - `GET  /api/metrics` — 回傳所有指標
   - `POST /api/metrics` — 新增或更新一筆指標（需驗證 `name`、`value` 欄位）
   - `GET  /api/metrics/:id` — 取得單一指標

4. **SSE 端點**
   - `GET /api/stream` — 建立 SSE 連線
   - 客戶端連線後，立即推送目前所有指標的快照
   - 之後每次 store 更新，推送 `data: <JSON>\n\n` 給所有已連線客戶端
   - 客戶端斷線時清除訂閱，避免記憶體洩漏

5. **WebSocket 伺服器（`wsServer.js`）**
   - 建立獨立的 `ws.Server`，共用同一個 HTTP server
   - 連線時傳送快照；之後 store 更新時廣播給所有 ws 客戶端
   - 支援客戶端傳送 `{ type: "ping" }` → 伺服器回應 `{ type: "pong" }`
   - 連線關閉或錯誤時清除訂閱

6. **整合進 `index.js`**
   - 建立單一 `http.Server`，同時掛載 Express app 與 ws.Server
   - 監聽 `PORT`（預設 3000）

## 範例

```js
// store.js — 簡化示意
const EventEmitter = require('events');
const emitter = new EventEmitter();
const metrics = new Map();

function upsert(metric) {
  metrics.set(metric.id, { ...metric, updatedAt: new Date().toISOString() });
  emitter.emit('update', metric);
}

function subscribe(fn) { emitter.on('update', fn); }
function unsubscribe(fn) { emitter.off('update', fn); }

module.exports = { getAll: () => [...metrics.values()], upsert, subscribe, unsubscribe };
```

```js
// SSE 端點示意
app.get('/api/stream', (req, res) => {
  res.setHeader('Content-Type', 'text/event-stream');
  res.setHeader('Cache-Control', 'no-cache');
  res.setHeader('Connection', 'keep-alive');

  // 1. 推送快照
  res.write(`data: ${JSON.stringify(store.getAll())}\n\n`);

  // 2. 訂閱後續更新
  const listener = (metric) => res.write(`data: ${JSON.stringify(metric)}\n\n`);
  store.subscribe(listener);

  // 3. 清理
  req.on('close', () => store.unsubscribe(listener));
});
```

```bash
# 測試 SSE（另開一個終端機）
curl -N http://localhost:3000/api/stream &

# 推送一筆資料觀察即時更新
curl -X POST http://localhost:3000/api/metrics \
  -H "Content-Type: application/json" \
  -d '{"id":"cpu","name":"CPU Usage","value":72,"unit":"%"}'
```

## 提示

- `http.createServer(app)` 回傳的 server 物件可同時傳給 `new ws.Server({ server })`，不需要兩個 port。
- SSE 在斷線（如 `req.on('close')`）時務必 `unsubscribe`，否則 `res.write` 會對已關閉的 response 寫入而報錯。
- WebSocket 廣播時要判斷 `client.readyState === ws.OPEN`，跳過未就緒的連線。
- 用 `Map` 儲存指標可用 `id` 做 upsert，比 Array `findIndex` 更有效率。

## 學習重點（跟後端 API 的關聯）

| 技術 | 實務場景 |
|------|----------|
| SSE | 監控儀表板、訂單狀態、股票報價 |
| WebSocket | 聊天室、協同編輯、線上遊戲 |
| pub/sub 模式 | 解耦事件來源與消費者，易於擴充 |
| 共用 HTTP server | 生產環境常見做法，只佔用一個 port |
| 記憶體洩漏防護 | 長連線服務必備技能 |

這道題直接對應真實的 **IoT 感測器儀表板**、**DevOps 監控面板** 或 **金融資料推播** 場景，是面試時展示架構思維的好題材。

## 進階挑戰（選做）

1. **房間（Room）機制**：讓客戶端訂閱特定 `namespace`，只收到對應指標的更新。
2. **Redis Pub/Sub**：將 store 的 pub/sub 替換成 Redis，讓多個 Node.js 行程可以橫向擴展。
3. **JWT 驗證**：SSE 連線時從 query string 取 token 驗證，ws 連線時從第一則訊息取 token。
4. **歷史紀錄**：每筆指標保留最近 100 筆更新，提供 `GET /api/metrics/:id/history` 端點。
5. **Jest 測試**：
   - 測試 `store.js` 的 upsert 與 pub/sub 邏輯
   - 用 `supertest` 測試 REST API
   - 用 `ws` 套件的測試客戶端測試 WebSocket 行為
