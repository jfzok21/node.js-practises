# 第 11 週今日 Node.js 練習題：使用 Multer 實作檔案上傳 API

## 題目說明

建立一個 Express API，讓使用者可以上傳圖片檔案（單張與多張），並實作基本的檔案驗證（類型、大小限制）。上傳後，API 需回傳檔案資訊（原始檔名、儲存路徑、大小）。

## 技術要求

- **概念**：multipart/form-data、檔案 MIME type 驗證、檔案大小限制、磁碟儲存策略
- **需要的套件**：
  - `express`
  - `multer`

## 具體任務

1. 使用 `npm init -y` 初始化專案，並安裝 `express` 與 `multer`
2. 建立 `uploads/` 目錄用來存放上傳的檔案
3. 設定 `multer` 的 `diskStorage`：
   - 目的地（`destination`）設為 `./uploads`
   - 檔名（`filename`）格式：`Date.now() + 原始副檔名`（例如 `1726660800000.jpg`）
4. 加入 `fileFilter`，只允許 `image/jpeg`、`image/png`、`image/gif` 三種格式；其他類型回傳 400 錯誤
5. 設定最大檔案大小限制為 **2MB**
6. 實作以下兩個路由：
   - `POST /upload/single`：上傳單一圖片（欄位名稱 `image`），回傳上傳成功的檔案資訊
   - `POST /upload/multiple`：同時上傳最多 5 張圖片（欄位名稱 `images`），回傳所有檔案資訊陣列
7. 統一的錯誤處理 middleware，捕捉 multer 的錯誤（如 `LIMIT_FILE_SIZE`）並回傳 400 或 500 訊息

## 範例

```js
// POST /upload/single 成功回應
{
  "message": "上傳成功",
  "file": {
    "originalname": "photo.jpg",
    "filename": "1726660800000.jpg",
    "path": "uploads/1726660800000.jpg",
    "size": 204800,
    "mimetype": "image/jpeg"
  }
}

// POST /upload/multiple 成功回應
{
  "message": "上傳成功",
  "count": 3,
  "files": [
    { "originalname": "a.png", "filename": "1726660800001.png", "size": 102400 },
    { "originalname": "b.jpg", "filename": "1726660800002.jpg", "size": 153600 },
    { "originalname": "c.gif", "filename": "1726660800003.gif", "size": 81920 }
  ]
}

// 檔案過大時（超過 2MB）
// HTTP 400
{
  "error": "檔案大小超過 2MB 限制"
}

// 不支援的格式
// HTTP 400
{
  "error": "只允許上傳 JPEG、PNG、GIF 格式的圖片"
}
```

## 提示

- `multer` 的 `fileFilter` 是在檔案被存入磁碟**之前**執行的；使用 `cb(new Error('...'), false)` 拒絕檔案
- `limits: { fileSize: 2 * 1024 * 1024 }` 設定 2MB 上限
- Multer 拋出的 `MulterError` 有 `code` 屬性（例如 `LIMIT_FILE_SIZE`），可在 error middleware 中判斷
- 使用 `upload.single('image')` 和 `upload.array('images', 5)` 分別處理兩個路由
- 測試時可以用 Postman 或 `curl -F "image=@photo.jpg" http://localhost:3000/upload/single`

## 學習重點（跟後端 API 的關聯）

在真實後端系統中，檔案上傳是非常常見的需求（例如用戶頭像、商品圖片、文件附件）。掌握 `multer` 讓你能夠：
- 理解 HTTP multipart/form-data 的運作原理
- 學會在 server 端驗證與過濾使用者上傳的內容，避免惡意檔案
- 為後續與雲端儲存（如 AWS S3、Google Cloud Storage）整合打好基礎
- 在 REST API 設計中正確處理非 JSON 資料格式

## 進階挑戰（選做）

1. **改用 Memory Storage**：不把檔案存到磁碟，而是暫存在 `buffer` 中，然後模擬上傳到「雲端」（可以只是 `console.log` buffer 大小）
2. **自動建立 `uploads/` 目錄**：如果目錄不存在，用 `fs.mkdirSync` 自動建立，避免 multer 報錯
3. **產生縮圖**：整合 `sharp` 套件，在上傳後額外產生一份 200×200 的縮圖，儲存為 `thumb_<filename>`
4. **回傳可存取的 URL**：讓 Express 提供 `uploads/` 靜態目錄（`express.static`），並在回應中回傳完整的存取網址（例如 `http://localhost:3000/uploads/1726660800000.jpg`）
