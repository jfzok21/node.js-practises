# 第 13 週今日 Node.js 練習題：Todo 清單 REST API 實戰專案

## 題目說明

綜合前 12 週所學，從零開始建立一個完整的 **Todo 清單後端 API**。
這個專案涵蓋：Express 路由、JWT 驗證、資料驗證、錯誤處理、Jest 測試，以及清晰的 REST API 設計。

---

## 技術要求

- **概念**：REST API 設計、JWT 身份驗證、輸入驗證、錯誤處理中介層、單元測試
- **需要的套件**：
  - `express` — HTTP 伺服器框架
  - `jsonwebtoken` — JWT 簽發與驗證
  - `bcryptjs` — 密碼雜湊
  - `joi` — 輸入驗證
  - `jest` + `supertest` — 整合測試

---

## 具體任務

1. **初始化專案**
   - `npm init -y`，安裝所有套件
   - 建立以下目錄結構：
     ```
     todo-api/
     ├── src/
     │   ├── app.js          # Express app（不含 listen）
     │   ├── server.js       # 啟動入口
     │   ├── routes/
     │   │   ├── auth.js     # POST /auth/register、POST /auth/login
     │   │   └── todos.js    # CRUD /todos
     │   ├── middleware/
     │   │   ├── auth.js     # JWT 驗證中介層
     │   │   └── validate.js # Joi 驗證中介層工廠
     │   └── data/
     │       └── store.js    # 記憶體資料儲存（模擬資料庫）
     └── tests/
         ├── auth.test.js
         └── todos.test.js
     ```

2. **實作身份驗證（`routes/auth.js`）**
   - `POST /auth/register`：接收 `{ username, password }`，密碼以 bcrypt 雜湊後儲存
   - `POST /auth/login`：驗證帳密，回傳 JWT（有效期 1 小時）
   - 兩支 API 皆需以 Joi 驗證輸入（username 最少 3 字、password 最少 6 字）

3. **實作 Todo CRUD（`routes/todos.js`）**
   - 所有路由都需通過 JWT 中介層驗證（從 `Authorization: Bearer <token>` 取得）
   - `GET    /todos`         — 取得當前使用者的所有 todo
   - `POST   /todos`         — 新增 todo（`{ title, completed?: boolean }`）
   - `PUT    /todos/:id`     — 更新指定 todo
   - `DELETE /todos/:id`     — 刪除指定 todo
   - 每位使用者只能存取自己的 todo（根據 JWT payload 的 userId 過濾）

4. **實作統一錯誤處理中介層**
   - 捕捉所有未處理錯誤，回傳格式：`{ error: "訊息" }`
   - 404 路由（`*`）也回傳統一格式

5. **撰寫 Jest + Supertest 測試**
   - `auth.test.js`：測試註冊成功、重複帳號 400、登入成功、登入失敗 401
   - `todos.test.js`：測試未授權 401、新增 todo 201、取得清單 200、刪除 204

## 範例

```js
// 1. 註冊
// POST /auth/register
// Body: { "username": "alice", "password": "secret123" }
// Response 201: { "message": "註冊成功" }

// 2. 登入
// POST /auth/login
// Body: { "username": "alice", "password": "secret123" }
// Response 200: { "token": "eyJhbGci..." }

// 3. 新增 Todo（需帶 Authorization header）
// POST /todos
// Headers: { "Authorization": "Bearer eyJhbGci..." }
// Body: { "title": "學完 Node.js" }
// Response 201: { "id": "uuid-xxx", "title": "學完 Node.js", "completed": false, "userId": "uuid-alice" }

// 4. 取得清單
// GET /todos
// Response 200: [{ "id": "...", "title": "學完 Node.js", "completed": false }]

// 5. 未帶 token 存取
// GET /todos（無 Authorization header）
// Response 401: { "error": "請先登入" }
```

## 提示

- `store.js` 可用兩個 Map 模擬資料庫：`const users = new Map()` 與 `const todos = new Map()`
- JWT 中介層從 `req.headers.authorization` 解析 `Bearer <token>`，驗證後將 `decoded` 掛到 `req.user`
- Joi 驗證中介層可設計成工廠函式：`validate(schema)` 回傳一個 Express middleware
- `app.js` 只匯出 app，`server.js` 才呼叫 `app.listen()`，這樣 supertest 測試才能乾淨地引入 app
- Todo ID 可用 `crypto.randomUUID()`（Node.js 15.6+ 內建，無需額外套件）

## 學習重點（跟後端 API 的關聯）

| 本週技能 | 實際對應場景 |
|---|---|
| JWT 驗證中介層 | 任何需要登入的 API（購物車、個人設定） |
| Joi 驗證 | 防止髒資料進資料庫，降低 Bug 率 |
| 統一錯誤格式 | 前端只需處理一種錯誤結構 |
| app/server 分離 | CI/CD 測試環境不會真的開 port |
| Supertest | 不需啟動伺服器就能跑 API 整合測試 |
