# 第 14 週今日 Node.js 練習題：RESTful 任務管理 API（全功能整合）

## 題目說明

建立一個完整的任務管理後端 API，整合前幾週所學的所有核心技術：Express、Middleware、JWT 身份驗證、輸入驗證、錯誤處理。這個專案模擬真實工作中的 API 開發流程，從零開始架構一個可交付的後端服務。

## 技術要求

- **概念**：MVC 架構、RESTful 設計原則、身份驗證流程、資料驗證、錯誤處理、中介層串接
- **需要的套件**：
  - `express` — 伺服器框架
  - `jsonwebtoken` — JWT 簽發與驗證
  - `bcryptjs` — 密碼雜湊
  - `joi` 或 `express-validator` — 輸入驗證
  - `uuid` — 產生唯一 ID（模擬資料庫 PK）

## 具體任務

1. **初始化專案結構**
   ```
   task-api/
   ├── src/
   │   ├── routes/
   │   │   ├── auth.js
   │   │   └── tasks.js
   │   ├── middleware/
   │   │   ├── auth.js        # JWT 驗證中介層
   │   │   └── validate.js    # 輸入驗證中介層
   │   ├── controllers/
   │   │   ├── authController.js
   │   │   └── taskController.js
   │   └── app.js
   └── package.json
   ```

2. **實作使用者身份驗證**（`/api/auth`）
   - `POST /register`：接收 `name`、`email`、`password`，雜湊密碼後存入記憶體陣列，回傳 JWT token
   - `POST /login`：比對 email + 密碼雜湊，成功回傳新 JWT token

3. **實作任務 CRUD**（需帶 JWT 才能存取，`/api/tasks`）
   - `GET /`：取得目前登入使用者的所有任務
   - `POST /`：新增任務（欄位：`title`、`description`、`dueDate`、`priority`）
   - `PUT /:id`：更新指定任務（只能更新自己的）
   - `DELETE /:id`：刪除指定任務（只能刪除自己的）

4. **加入輸入驗證**
   - `title` 為必填且長度 3–100 字元
   - `priority` 只能是 `low`、`medium`、`high`
   - `dueDate` 若提供必須是合法日期格式

5. **統一錯誤處理**
   - 建立全域錯誤處理中介層，回傳統一格式：
     ```json
     { "success": false, "error": "訊息" }
     ```
   - 處理 404（路由不存在）、401（未授權）、422（驗證失敗）

## 範例

```js
// POST /api/auth/register
// Request body:
{
  "name": "小明",
  "email": "ming@example.com",
  "password": "securePass123"
}

// Response 201:
{
  "success": true,
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": { "id": "uuid-xxx", "name": "小明", "email": "ming@example.com" }
}

// POST /api/tasks（Authorization: Bearer <token>）
// Request body:
{
  "title": "完成期末報告",
  "description": "需要整理所有數據",
  "dueDate": "2026-10-31",
  "priority": "high"
}

// Response 201:
{
  "success": true,
  "task": {
    "id": "uuid-yyy",
    "title": "完成期末報告",
    "description": "需要整理所有數據",
    "dueDate": "2026-10-31",
    "priority": "high",
    "completed": false,
    "userId": "uuid-xxx",
    "createdAt": "2026-10-10T00:00:00.000Z"
  }
}
```

## 提示

- 使用 `process.env.JWT_SECRET` 儲存金鑰，不要硬寫在程式碼中（搭配 `dotenv`）
- JWT 驗證中介層解碼 token 後，將 user 資訊掛到 `req.user`，後續 controller 直接使用
- 資料暫存在記憶體陣列即可（`const users = []`、`const tasks = []`），不需要真實資料庫
- 查詢任務時記得用 `userId` 過濾，確保使用者只能看到自己的任務
- 驗證中介層可以用 factory function 設計，讓不同路由傳入不同 schema

## 學習重點（跟後端 API 的關聯）

這個練習整合了真實後端開發的完整流程：**身份驗證→授權→資料驗證→業務邏輯→統一回應格式**。在職場中，幾乎每一個需要登入的 API 都遵循此模式。掌握這個架構後，換成真實資料庫（PostgreSQL/MongoDB）只需替換資料存取層，其餘邏輯完全不變。

## 進階挑戰（選做）

- 加入任務狀態過濾：`GET /api/tasks?status=completed&priority=high`（Query string 篩選）
