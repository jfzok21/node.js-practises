# 第 16 週今日 Node.js 練習題：任務管理 REST API 實戰

## 題目說明

建立一個完整的任務管理（Todo List）REST API，整合你這 16 週所學的所有技能：Express、資料驗證、JWT 身份驗證、錯誤處理，以及 Jest 測試。這個專案模擬真實後端 API 的完整開發流程。

## 技術要求
- 概念：REST API 設計、JWT 身份驗證、輸入驗證、錯誤處理中介層、單元測試
- 需要的套件：`express`、`jsonwebtoken`、`joi`（或 `zod`）、`jest`、`supertest`、`bcryptjs`

## 具體任務

### 1. 專案初始化
建立 `todo-api/` 資料夾，執行 `npm init -y`，安裝所需套件，設定以下結構：
```
todo-api/
├── src/
│   ├── app.js          ← Express 主設定
│   ├── routes/
│   │   ├── auth.js     ← 登入 / 註冊路由
│   │   └── todos.js    ← 任務 CRUD 路由
│   ├── middleware/
│   │   ├── auth.js     ← JWT 驗證中介層
│   │   └── validate.js ← 輸入驗證中介層
│   └── data/
│       └── store.js    ← 記憶體資料儲存（陣列模擬 DB）
├── tests/
│   └── todos.test.js
└── package.json
```

### 2. 實作使用者驗證（`src/routes/auth.js`）
- `POST /auth/register`：接受 `{ name, email, password }`，密碼用 bcryptjs 雜湊後儲存
- `POST /auth/login`：驗證帳密，成功回傳 JWT Token（有效期 1 小時）

### 3. 實作任務 CRUD（`src/routes/todos.js`）
所有路由需通過 JWT 中介層驗證，每位使用者只能操作自己的任務：
- `GET /todos` — 取得目前登入使用者的所有任務
- `POST /todos` — 新增任務（需帶 `title`，選填 `done: false`）
- `PUT /todos/:id` — 更新任務標題或完成狀態
- `DELETE /todos/:id` — 刪除任務

### 4. 輸入驗證（`src/middleware/validate.js`）
用 Joi 或 Zod 建立 schema，驗證失敗時回傳 `400 Bad Request` 及清楚錯誤訊息。

### 5. 撰寫測試（`tests/todos.test.js`）
用 Jest + Supertest 至少測試以下情境：
- 未帶 Token 呼叫 `GET /todos` → 應回傳 `401`
- 新增任務後 `GET /todos` 應包含剛建立的項目
- 刪除不存在的任務 → 應回傳 `404`

## 範例

```js
// POST /auth/login 請求
{ "email": "user@example.com", "password": "secret123" }

// 成功回應
{ "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." }

// POST /todos（帶 Authorization: Bearer <token>）
{ "title": "學習 Node.js 第 16 週練習" }

// 成功回應
{ "id": "a1b2c3", "title": "學習 Node.js 第 16 週練習", "done": false, "userId": "u001" }

// GET /todos 成功回應
[
  { "id": "a1b2c3", "title": "學習 Node.js 第 16 週練習", "done": false }
]
```

## 提示
- JWT Secret 可存在 `.env`，用 `process.env.JWT_SECRET || 'dev-secret'` 讀取
- 記憶體儲存用 `Map` 管理使用者與任務，Key 為使用者 ID
- `supertest` 可直接匯入 `app.js` 進行整合測試，不需實際啟動 server
- 用 `crypto.randomUUID()` 產生唯一 ID，不需額外套件

## 學習重點（跟後端 API 的關聯）

這個練習整合了真實產品 API 的核心骨幹：
- **身份驗證流程**：Register → Login → JWT → Protected Route，是幾乎所有現代 API 的標配
- **Middleware 鏈**：`authMiddleware → validateMiddleware → routeHandler`，讓關注點分離、易於測試
- **資料隔離**：依 `userId` 過濾資料，防止越權存取（IDOR 漏洞的防範）
- **測試驗證行為**：確保安全性規則（如 401/403/404）在每次改動後仍然正確

## 進階挑戰（選做）

1. **分頁**：`GET /todos?page=1&limit=10`，回應加上 `{ data, total, page, totalPages }`
2. **排序 & 篩選**：支援 `?done=true` 篩選已完成任務，`?sort=createdAt` 排序
3. **Refresh Token**：Login 時同時回傳短效 `accessToken`（15 分鐘）與長效 `refreshToken`（7 天），實作 `POST /auth/refresh`
4. **Rate Limiting**：用 `express-rate-limit` 限制登入端點每分鐘最多 5 次，防止暴力破解
