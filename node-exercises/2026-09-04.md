# 第 9 週今日 Node.js 練習題：JWT 身份驗證系統

## 題目說明

實作一個完整的 JWT（JSON Web Token）身份驗證系統。你將建立使用者註冊、登入、以及受保護路由的 Express API，透過 JWT 管理身份狀態，不需要 session 或 cookie。

## 技術要求

- **概念**：JWT 結構（Header.Payload.Signature）、Token 簽發與驗證、Middleware 保護路由、密碼雜湊
- **需要的套件**：`express`、`jsonwebtoken`、`bcryptjs`

## 具體任務

1. 初始化專案並安裝套件：
   ```
   npm init -y
   npm install express jsonwebtoken bcryptjs
   ```

2. 建立 `server.js`，設定 Express 並以記憶體陣列模擬使用者資料庫。

3. 實作 `POST /register` 路由：
   - 接收 `username` 與 `password`
   - 用 `bcryptjs.hash()` 對密碼雜湊後儲存
   - 回傳成功訊息

4. 實作 `POST /login` 路由：
   - 查找使用者、用 `bcryptjs.compare()` 驗證密碼
   - 驗證成功後，用 `jwt.sign()` 簽發 Token（有效期 1 小時）
   - 回傳 `{ token: "..." }`

5. 建立 `authMiddleware`：
   - 從 `Authorization: Bearer <token>` 標頭取出 Token
   - 用 `jwt.verify()` 驗證，失敗回傳 401
   - 成功將 `decoded` 使用者資訊附加到 `req.user`

6. 實作 `GET /profile` 受保護路由（需套用 `authMiddleware`），回傳目前登入的使用者名稱。

## 範例

```js
// POST /register
// Request Body: { "username": "alice", "password": "secret123" }
// Response: { "message": "使用者 alice 註冊成功" }

// POST /login
// Request Body: { "username": "alice", "password": "secret123" }
// Response: { "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." }

// GET /profile  (需帶 Header: Authorization: Bearer <token>)
// Response: { "message": "歡迎，alice！", "user": { "username": "alice" } }

// GET /profile  (無 Token 或 Token 無效)
// Response: 401 { "error": "未授權，請先登入" }
```

## 提示

- JWT 的 `secret` 應從環境變數讀取（`process.env.JWT_SECRET || 'dev-secret'`），正式環境絕不能硬寫在程式碼裡。
- `bcryptjs.hash(password, 10)` 中的 `10` 是 salt rounds，數字越高越安全但越慢。
- `jwt.sign({ username }, secret, { expiresIn: '1h' })` 用來產生 Token。
- `jwt.verify(token, secret)` 成功時回傳 decoded payload，失敗時拋出錯誤，記得用 try/catch 包住。
- 用 `curl` 或 Postman 測試時，Login 取得 Token 後帶入 `Authorization` 標頭測試 `/profile`。

## 學習重點

JWT 是現代後端 API 最常見的無狀態身份驗證方案。與 session 不同，伺服器不需儲存任何狀態，Token 本身即含有使用者資訊，可輕鬆應用於微服務與前後端分離架構。這個模式在實際專案（Next.js 前端 + Node.js API）中極為普遍，是必備技能。

## 進階挑戰（選做）

- **Refresh Token**：實作 `/refresh` 路由，用有效期較長的 Refresh Token 換發新的 Access Token（短效期）。
- **Token 黑名單**：在記憶體 Set 中維護已登出的 Token，讓 `POST /logout` 真正失效 Token。
- **角色控管（RBAC）**：在 JWT Payload 加入 `role` 欄位（`admin` / `user`），建立 `requireRole(role)` Middleware 保護管理員路由。
