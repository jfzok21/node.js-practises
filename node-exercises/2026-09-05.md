# 第 9 週今日 Node.js 練習題：JWT 身份驗證系統

## 題目說明

實作一個完整的 JWT（JSON Web Token）身份驗證流程，包含使用者登入、token 發放、受保護路由的存取控制，以及 token 刷新機制。JWT 是現代 REST API 最常見的無狀態身份驗證方式，理解它對於後端開發至關重要。

## 技術要求

- **概念**：JWT 結構（Header.Payload.Signature）、非對稱 vs 對稱加密、Access Token vs Refresh Token、middleware 驗證
- **需要的套件**：
  - `jsonwebtoken`（JWT 簽發與驗證）
  - `bcryptjs`（密碼雜湊）
  - `express`
  - `dotenv`

## 具體任務

1. **初始化專案並安裝依賴**
   ```bash
   mkdir jwt-auth-demo && cd jwt-auth-demo
   npm init -y
   npm install express jsonwebtoken bcryptjs dotenv
   ```

2. **建立 `.env` 設定檔**，定義以下環境變數：
   - `ACCESS_TOKEN_SECRET`（至少 32 字元隨機字串）
   - `REFRESH_TOKEN_SECRET`（另一個隨機字串）
   - `ACCESS_TOKEN_EXPIRES_IN=15m`
   - `REFRESH_TOKEN_EXPIRES_IN=7d`

3. **建立使用者資料（模擬資料庫）**：在記憶體中維護一個使用者陣列，包含 `id`、`username`、`passwordHash` 欄位。預先使用 `bcrypt.hashSync` 建立兩個測試使用者。

4. **實作 `POST /auth/login` 路由**：
   - 接收 `username` 與 `password`
   - 驗證使用者是否存在，並用 `bcrypt.compare` 比對密碼
   - 成功後簽發 access token（payload 含 `userId`、`username`）與 refresh token
   - 將 refresh token 儲存於伺服器端陣列（模擬 DB）

5. **實作 JWT 驗證 middleware `authenticateToken`**：
   - 從 `Authorization: Bearer <token>` header 取出 token
   - 用 `jwt.verify` 驗證，失敗回傳 `401`
   - 成功將 payload 掛載至 `req.user`

6. **實作受保護路由 `GET /profile`**：套用 `authenticateToken` middleware，回傳目前登入使用者的資訊。

7. **實作 `POST /auth/refresh`**：
   - 接收 refresh token
   - 驗證是否在伺服器端有效列表中
   - 通過後發放新的 access token

8. **實作 `POST /auth/logout`**：將 refresh token 從伺服器端列表移除（使其失效）。

## 範例

```js
// 登入請求
// POST /auth/login
// Body: { "username": "alice", "password": "password123" }

// 成功回應
{
  "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refreshToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}

// 存取受保護路由
// GET /profile
// Header: Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

// 成功回應
{
  "userId": 1,
  "username": "alice",
  "message": "歡迎回來，alice！"
}

// Token 過期時
// 401 Unauthorized
{
  "error": "Token 已過期或無效"
}

// Refresh Token 請求
// POST /auth/refresh
// Body: { "refreshToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." }

// 成功回應
{
  "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

## 提示

- **不要**在 JWT payload 中放入密碼或敏感資訊，payload 只是 Base64 編碼，任何人都能解碼
- Access token 生命週期短（15 分鐘）是故意的，降低 token 外洩的風險
- Refresh token 需要伺服器端儲存才能支援登出（純 JWT 本身是無狀態的，無法主動作廢）
- `jwt.verify` 會在 token 過期時拋出 `TokenExpiredError`，記得用 `try/catch` 處理
- 使用 `crypto.randomBytes(64).toString('hex')` 在 Node.js 中生成安全的 secret

```js
// middleware 範例骨架
function authenticateToken(req, res, next) {
  const authHeader = req.headers['authorization'];
  const token = authHeader && authHeader.split(' ')[1]; // 取出 Bearer 後面的 token

  if (!token) return res.status(401).json({ error: '未提供 Token' });

  try {
    const decoded = jwt.verify(token, process.env.ACCESS_TOKEN_SECRET);
    req.user = decoded;
    next();
  } catch (err) {
    return res.status(401).json({ error: 'Token 已過期或無效' });
  }
}
```

## 學習重點

**與後端 API 的關聯：**

JWT 是現代 API 身份驗證的核心。在真實的後端架構中：

- **無狀態驗證**：伺服器不需要查資料庫就能驗證 token，適合水平擴展的微服務架構
- **雙 Token 策略**：短命的 access token + 長命的 refresh token 是業界標準做法（OAuth 2.0 也採用此模式）
- **middleware 鏈**：驗證、授權（RBAC）、速率限制等都可以做成 middleware，掛在路由前
- **Cookie vs Header**：生產環境中 refresh token 通常存在 `HttpOnly Cookie` 而非 response body，防止 XSS 竊取

這個練習直接對應到未來你實作用戶系統、API 存取控制時會用到的完整流程。

## 進階挑戰（選做）

1. **角色授權（RBAC）**：在 token payload 加入 `role`（`"admin"` / `"user"`），並實作 `authorizeRole(role)` middleware，讓 `GET /admin` 只有 `admin` 才能存取。

2. **Token 黑名單**：access token 提前作廢通常需要黑名單機制，用 `Map<token, expiry>` 實作一個簡單的記憶體黑名單，並在 middleware 中檢查。

3. **Token Rotation**：每次使用 refresh token 時，廢棄舊的並發放新的 refresh token，降低 token 被竊後的風險。

4. **加入 Zod 驗證**：對 `/auth/login` 的 request body 加入 schema 驗證，在碰資料庫之前就拒絕格式錯誤的請求。
