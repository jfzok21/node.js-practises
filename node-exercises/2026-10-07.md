# 第 14 週今日 Node.js 練習題：個人記帳 REST API

## 題目說明

建立一個完整的「個人記帳系統」REST API，整合之前所學的 Express、JWT 身份驗證、PostgreSQL、輸入驗證與錯誤處理，實現一個可上線使用的後端服務。

## 技術要求
- **概念：** Express Router、JWT 驗證、資料庫 CRUD、輸入驗證、錯誤中介軟體
- **需要的套件：** `express`、`jsonwebtoken`、`bcryptjs`、`pg`（或 `better-sqlite3` 輕量版）、`joi` 或 `express-validator`、`dotenv`

## 具體任務

1. **專案結構設計**
   建立以下目錄結構：
   ```
   budget-api/
   ├── src/
   │   ├── routes/
   │   │   ├── auth.js        # 登入 / 註冊
   │   │   └── transactions.js # 記帳 CRUD
   │   ├── middleware/
   │   │   ├── auth.js        # JWT 驗證中介軟體
   │   │   └── validate.js    # 輸入驗證中介軟體
   │   ├── db.js              # 資料庫連線
   │   └── app.js             # Express 應用程式
   ├── .env
   └── package.json
   ```

2. **資料表設計**
   設計並建立以下資料表（SQL DDL）：
   ```sql
   CREATE TABLE users (
     id SERIAL PRIMARY KEY,
     email VARCHAR(255) UNIQUE NOT NULL,
     password_hash VARCHAR(255) NOT NULL,
     created_at TIMESTAMPTZ DEFAULT NOW()
   );

   CREATE TABLE transactions (
     id SERIAL PRIMARY KEY,
     user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
     type VARCHAR(10) CHECK (type IN ('income', 'expense')) NOT NULL,
     amount NUMERIC(10, 2) NOT NULL,
     category VARCHAR(100) NOT NULL,
     description TEXT,
     date DATE NOT NULL DEFAULT CURRENT_DATE,
     created_at TIMESTAMPTZ DEFAULT NOW()
   );
   ```

3. **實作 API 端點**

   | 方法 | 路由 | 說明 | 需要驗證 |
   |------|------|------|----------|
   | POST | `/auth/register` | 使用者註冊 | 否 |
   | POST | `/auth/login` | 登入，回傳 JWT | 否 |
   | GET | `/transactions` | 列出所有記錄（支援分頁與篩選） | 是 |
   | POST | `/transactions` | 新增一筆記錄 | 是 |
   | PUT | `/transactions/:id` | 修改記錄 | 是 |
   | DELETE | `/transactions/:id` | 刪除記錄 | 是 |
   | GET | `/transactions/summary` | 收支統計（依類別分組） | 是 |

4. **輸入驗證規則**
   - `email`：必填，格式正確
   - `password`：必填，至少 8 碼
   - `amount`：必填，大於 0 的數字
   - `type`：必須為 `income` 或 `expense`
   - `category`：必填，不可空白

5. **統一錯誤格式**
   所有錯誤回應統一為：
   ```json
   { "error": "錯誤訊息", "code": "ERROR_CODE" }
   ```

## 範例

```js
// POST /auth/register
// 請求 body:
{ "email": "alice@example.com", "password": "secret123" }

// 成功回應 201:
{ "message": "註冊成功", "userId": 1 }

// POST /auth/login
// 成功回應 200:
{ "token": "eyJhbGciOiJIUzI1NiIs..." }

// GET /transactions?type=expense&page=1&limit=10
// 成功回應 200:
{
  "data": [
    { "id": 3, "type": "expense", "amount": "150.00",
      "category": "餐飲", "description": "午餐", "date": "2026-10-07" }
  ],
  "pagination": { "total": 1, "page": 1, "limit": 10 }
}

// GET /transactions/summary
// 成功回應 200:
{
  "income": [{ "category": "薪資", "total": "50000.00" }],
  "expense": [{ "category": "餐飲", "total": "3200.00" }],
  "balance": "46800.00"
}
```

## 提示

- JWT 驗證中介軟體從 `Authorization: Bearer <token>` header 中取出 token，驗證後把 `userId` 掛到 `req.user`
- 查詢 transactions 時記得加上 `WHERE user_id = $1`，確保使用者只看得到自己的資料
- 使用 `bcryptjs.hash(password, 10)` 雜湊密碼，`bcryptjs.compare()` 驗證
- `summary` 端點可用 SQL `GROUP BY category` 搭配 `SUM(amount)` 來完成
- 可用 SQLite（`better-sqlite3`）代替 PostgreSQL，方便本機開發

## 學習重點

這題整合了整個課程的核心知識鏈：

| 能力 | 對應後端 API 的應用 |
|------|------|
| Express Router 模組化 | 大型專案的路由分層管理 |
| JWT 中介軟體 | 保護任何需要登入的端點 |
| 輸入驗證 | 防止 SQL injection、維持資料品質 |
| 統一錯誤處理 | 前端可依 `code` 欄位顯示對應訊息 |
| SQL 聚合查詢 | 儀表板、報表等資料統計需求 |

## 進階挑戰（選做）

1. **軟刪除**：在 transactions 加入 `deleted_at` 欄位，刪除時只更新該欄位而不真正移除資料
2. **日期區間篩選**：支援 `?from=2026-10-01&to=2026-10-07` 查詢參數
3. **單元測試**：用 Jest + Supertest 為 `/auth/register` 和 `/transactions` 各寫至少兩個測試案例
4. **Rate Limiting**：使用 `express-rate-limit` 限制登入端點每分鐘最多 5 次請求，防止暴力破解
