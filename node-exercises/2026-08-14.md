# 第 6 週今日 Node.js 練習題：自訂 Express Middleware 鏈

## 題目說明

在 Express 中，Middleware（中介軟體）是請求與回應之間的「攔截層」，每個 middleware 都可以讀取、修改請求/回應物件，或決定是否繼續往下傳遞。本題要求你實作三個自訂 middleware，並將它們串接成一條處理鏈。

## 技術要求

- 概念：Express middleware、`next()`、`req` / `res` 物件、錯誤處理 middleware
- 需要的套件：`express`（`npm install express`）

## 具體任務

1. **建立 `app.js`**，使用 Express 建立一個基本應用程式，監聽 port 3000。

2. **實作 `loggerMiddleware`**  
   - 每次收到請求時，印出以下格式到 console：  
     `[2026-08-14T10:00:00.000Z] GET /api/hello`  
   - 印完後呼叫 `next()` 繼續往下。

3. **實作 `authMiddleware`**  
   - 讀取 request header 中的 `x-api-key`。  
   - 若值為 `"secret-key-123"`，則繼續往下（`next()`）。  
   - 若缺少或錯誤，回傳 HTTP 401 與 JSON `{ "error": "Unauthorized" }`。

4. **實作 `responseTimeMiddleware`**  
   - 在 `req` 上記錄請求開始時間。  
   - 在 `res` 的 `finish` 事件中計算並印出耗時（毫秒）：  
     `Response time: 5ms`

5. **掛載三個 middleware**（順序：logger → responseTime → auth），並建立以下路由：
   - `GET /api/hello` → 回傳 `{ "message": "Hello, World!" }`
   - `GET /api/secret` → 需通過 auth，回傳 `{ "data": "這是秘密資料" }`

6. **實作全域錯誤處理 middleware**（四個參數 `err, req, res, next`），回傳 HTTP 500 與 `{ "error": err.message }`。

## 範例

```js
// 啟動應用程式後，測試請求：

// 1. 不帶 API Key（應回傳 401）
// curl http://localhost:3000/api/secret
// → { "error": "Unauthorized" }

// 2. 帶正確 API Key（應回傳秘密資料）
// curl -H "x-api-key: secret-key-123" http://localhost:3000/api/secret
// → { "data": "這是秘密資料" }

// 3. 公開路由不需 API Key
// curl http://localhost:3000/api/hello
// → { "message": "Hello, World!" }

// Console 輸出範例：
// [2026-08-14T10:00:01.234Z] GET /api/hello
// Response time: 3ms
```

## 提示

- middleware 的順序很重要：`app.use()` 的呼叫順序就是執行順序。
- `authMiddleware` 只掛在需要保護的路由上，不要全域掛載。
- `res.on('finish', callback)` 可以在回應完成後觸發回調。
- 記得在 `authMiddleware` 中 `return` 提前結束，避免「headers already sent」錯誤。
- 錯誤處理 middleware 必須放在所有路由**之後**。

## 學習重點（跟後端 API 的關聯）

Middleware 是所有現代後端框架的核心概念：

| Middleware 類型 | 實際應用 |
|---|---|
| Logger | 記錄 API 存取日誌、除錯 |
| Auth | JWT 驗證、API Key 保護 |
| Response Time | 效能監控、SLA 追蹤 |
| Error Handler | 統一錯誤格式、避免洩漏敏感資訊 |

掌握 middleware 鏈後，你可以輕鬆加入 CORS、rate limiting、request validation 等功能，這些都是實際 REST API 的標配。

## 進階挑戰（選做）

1. 將 `authMiddleware` 改為讀取 `Authorization: Bearer <token>` header，並用簡單的 token list（陣列）驗證。
2. 新增 `requestIdMiddleware`，為每個請求附加 UUID（可用 `crypto.randomUUID()`），並在 logger 中一起印出，讓每筆 log 都可被追蹤。
3. 讓 `loggerMiddleware` 將 log 同時寫入 `access.log` 檔案（使用 `fs.appendFile`）。
