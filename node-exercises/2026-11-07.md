# 第 18 週今日 Node.js 練習題：個人任務管理 REST API（整合實戰）

## 題目說明

綜合前 17 週所學，打造一個具備完整功能的「個人任務管理 API」。系統需支援使用者註冊/登入（JWT）、CRUD 任務管理、圖片附件上傳、輸入驗證，並覆蓋單元測試與整合測試。

---

## 技術要求

- **概念**：REST API 設計、JWT 身份驗證、Middleware 鏈、PostgreSQL ORM 操作、檔案上傳、Jest 測試
- **需要的套件**：
  - `express`、`pg`（或 `prisma`）、`bcryptjs`、`jsonwebtoken`
  - `multer`、`joi`（或 `zod`）
  - `jest`、`supertest`
  - `dotenv`

---

## 具體任務

### 1. 專案初始化
- 執行 `npm init -y` 並建立以下目錄結構：
  ```
  task-api/
  ├── src/
  │   ├── routes/
  │   ├── controllers/
  │   ├── middleware/
  │   └── db/
  ├── uploads/
  ├── tests/
  ├── .env
  └── server.js
  ```

### 2. 資料庫設計（PostgreSQL）
建立兩張資料表：

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  title VARCHAR(255) NOT NULL,
  description TEXT,
  status VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending', 'in_progress', 'done')),
  attachment_path TEXT,
  created_at TIMESTAMP DEFAULT NOW()
);
```

### 3. 實作 API 端點

| 方法   | 路徑                    | 描述              | 需驗證 |
|------|------------------------|-----------------|------|
| POST | `/api/auth/register`   | 使用者註冊          | 否    |
| POST | `/api/auth/login`      | 登入，回傳 JWT token | 否    |
| GET  | `/api/tasks`           | 取得我的所有任務       | 是    |
| POST | `/api/tasks`           | 新增任務           | 是    |
| PUT  | `/api/tasks/:id`       | 更新任務內容/狀態      | 是    |
| DELETE | `/api/tasks/:id`    | 刪除任務           | 是    |
| POST | `/api/tasks/:id/upload`| 上傳任務附件圖片      | 是    |

### 4. JWT 中介軟體
建立 `src/middleware/auth.js`，驗證 `Authorization: Bearer <token>` 並將 `req.user` 注入。

### 5. 輸入驗證
使用 `joi` 或 `zod` 驗證：
- 註冊：email 格式、密碼至少 8 字元
- 新增/更新任務：title 不可空白、status 只能是允許值

### 6. 檔案上傳
使用 `multer` 限制：
- 只允許 `image/jpeg`、`image/png`
- 單檔最大 2MB
- 儲存至 `uploads/<userId>/` 資料夾

### 7. 撰寫測試（Jest + Supertest）
至少覆蓋：
- 成功註冊 / 重複 email 應回傳 400
- 登入成功 / 錯誤密碼應回傳 401
- 未帶 token 存取 `/api/tasks` 應回傳 401
- 新增任務成功 / 缺少 title 應回傳 422

## 範例

```js
// 登入請求
POST /api/auth/login
{
  "email": "user@example.com",
  "password": "mySecret123"
}

// 成功回應
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": { "id": 1, "email": "user@example.com" }
}

// 新增任務（需帶 Authorization header）
POST /api/tasks
Authorization: Bearer <token>
{
  "title": "準備期末簡報",
  "description": "使用 Reveal.js",
  "status": "in_progress"
}

// 成功回應 201
{
  "id": 5,
  "title": "準備期末簡報",
  "status": "in_progress",
  "created_at": "2026-11-07T10:00:00.000Z"
}
```

---

## 提示

- 使用 `bcryptjs.hash(password, 10)` 儲存密碼，絕對不要明文存入資料庫
- JWT secret 存在 `.env`，不要寫死在程式碼中
- 中介軟體驗證失敗要統一回傳 JSON 格式（`{ "error": "..." }`），不要讓 Express 預設 HTML 錯誤頁洩漏
- Supertest 測試時使用獨立的測試資料庫，可在 `beforeAll` / `afterAll` 建立及清除資料
- `uploads/` 加入 `.gitignore`

## 學習重點（跟後端 API 的關聯）

這道題把你過去學的所有模組串聯成一個真實可部署的後端服務：
- **JWT + Middleware**：每個需驗證的路由自動保護，與真實 SaaS 架構相同
- **PostgreSQL 外鍵 + CASCADE**：資料完整性，使用者刪除時任務自動清除
- **multer 限制**：防止惡意上傳，對應生產環境安全要求
- **Jest 整合測試**：在 CI/CD pipeline 中自動化驗收每次變更

## 進階挑戰（選做）

1. **分頁查詢**：`GET /api/tasks?page=1&limit=10`，使用 `OFFSET` 實作
2. **任務標籤**：新增 `tags` 資料表（多對多），支援依標籤篩選任務
3. **軟刪除**：加入 `deleted_at` 欄位，`DELETE` 只更新時間戳而非真正刪除
4. **速率限制**：使用 `express-rate-limit` 限制 `/api/auth/login` 每分鐘最多 10 次
5. **Swagger 文件**：整合 `swagger-ui-express` 自動產生 API 文件頁面
