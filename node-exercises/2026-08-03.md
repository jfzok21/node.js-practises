# 第 4 週今日 Node.js 練習題：打造一個簡易 JSON API 伺服器

## 題目說明

使用 Node.js 內建的 `http` 模組，從零開始建立一個 HTTP 伺服器，不依賴任何第三方框架。伺服器需能根據請求的路徑與方法，回傳對應的 JSON 資料，並正確處理 404 與不支援的方法等錯誤狀況。

## 技術要求
- 概念：`http.createServer`、`req.method`、`req.url`、`res.writeHead`、`res.end`、JSON 序列化
- 需要的套件：無（僅使用 Node.js 內建模組）

## 具體任務
1. 建立一個 `server.js`，在 `3000` 埠啟動 HTTP 伺服器
2. 實作以下三個路由：
   - `GET /` → 回傳 `{ "message": "歡迎來到我的 API" }`
   - `GET /users` → 回傳一個包含至少 3 位使用者的 JSON 陣列（id、name、email）
   - `GET /users/:id`（手動解析路徑）→ 依 id 回傳單一使用者，找不到時回傳 `{ "error": "使用者不存在" }` 並使用 404 狀態碼
3. 所有回應皆須設定 `Content-Type: application/json` 標頭
4. 對於不存在的路徑，回傳 404 與 `{ "error": "路由不存在" }`
5. 對於非 GET 方法，回傳 405 與 `{ "error": "不支援的方法" }`

## 範例

```js
// GET /users 回應
[
  { "id": 1, "name": "Alice", "email": "alice@example.com" },
  { "id": 2, "name": "Bob",   "email": "bob@example.com" },
  { "id": 3, "name": "Carol", "email": "carol@example.com" }
]

// GET /users/2 回應
{ "id": 2, "name": "Bob", "email": "bob@example.com" }

// GET /users/99 回應（404）
{ "error": "使用者不存在" }

// POST /users 回應（405）
{ "error": "不支援的方法" }
```

## 提示
- 使用 `req.url.split('/')` 來解析路徑段落，例如 `/users/2` 拆成 `['', 'users', '2']`
- 記得用 `parseInt()` 將路徑中的 id 字串轉為數字
- `res.writeHead(statusCode, headers)` 可以同時設定狀態碼與標頭
- 測試時可使用 `curl http://localhost:3000/users` 或瀏覽器直接開啟

## 學習重點（跟後端 API 的關聯）

這道題直接模擬了 Express/Fastify 在底層做的事情——路由分發、狀態碼管理、JSON 回應。理解原生 `http` 模組能讓你：
- 明白為何 Express 的 `res.json()` 如此方便（它幫你處理了 `writeHead` 與 `JSON.stringify`）
- 在需要輕量無框架的 serverless 環境（如 AWS Lambda handler）時，可直接操作 HTTP 原語
- 更清楚地除錯框架層之下的網路行為

## 進階挑戰（選做）
- 支援 `POST /users`：讀取 `req` 的 body（使用 `data` 與 `end` 事件），將新使用者加入記憶體陣列並回傳 201 狀態碼
- 加入請求日誌，將每次請求的方法、路徑與回應時間（ms）印到 console
- 將路由邏輯抽離成一個簡單的 `router` 物件，讓 `server.js` 更清晰
