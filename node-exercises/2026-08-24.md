# 第 7 週今日 Node.js 練習題：RESTful 書籍管理 API

## 題目說明

使用 Express 設計並實作一個符合 REST 規範的「書籍管理 API」。你將依照 REST 原則設計資源路徑、HTTP 方法、狀態碼，並實作完整的 CRUD 操作，同時在記憶體中模擬資料儲存。

## 技術要求

- 概念：REST 設計原則、HTTP 動詞語意、正確使用 HTTP 狀態碼、資源命名規範
- 需要的套件：`express`、`uuid`（選用，用於產生 ID）

## 具體任務

1. 建立 Express 應用，監聽 port 3000
2. 設計以下 RESTful 端點，資料以陣列儲存於記憶體：

   | HTTP 方法 | 路徑            | 說明                   | 成功狀態碼 |
   |-----------|-----------------|------------------------|------------|
   | GET       | `/books`        | 取得所有書籍清單       | 200        |
   | GET       | `/books/:id`    | 取得單一書籍           | 200        |
   | POST      | `/books`        | 新增一本書             | 201        |
   | PUT       | `/books/:id`    | 完整更新書籍資料       | 200        |
   | PATCH     | `/books/:id`    | 部分更新書籍資料       | 200        |
   | DELETE    | `/books/:id`    | 刪除書籍               | 204        |

3. 每本書的資料結構如下：
   ```json
   {
     "id": "自動產生的唯一 ID",
     "title": "書名",
     "author": "作者",
     "year": 出版年份,
     "genre": "類型"
   }
   ```
4. 實作正確的錯誤處理：
   - 找不到資源時回傳 `404` 與錯誤訊息
   - 缺少必要欄位時回傳 `400` 與錯誤訊息
5. 支援 `GET /books` 的查詢參數過濾：`?genre=Fiction` 過濾特定類型的書籍

## 範例

```js
// POST /books 請求 body
{
  "title": "Clean Code",
  "author": "Robert C. Martin",
  "year": 2008,
  "genre": "Technology"
}

// 回應 201 Created
{
  "id": "a1b2c3d4",
  "title": "Clean Code",
  "author": "Robert C. Martin",
  "year": 2008,
  "genre": "Technology"
}

// GET /books/不存在的ID
// 回應 404 Not Found
{
  "error": "找不到 ID 為 xxx 的書籍"
}

// PATCH /books/:id 請求 body（只更新部分欄位）
{ "year": 2009 }
// 回應 200，僅更新 year，其餘欄位不變
```

## 提示

- 使用 `express.json()` middleware 解析請求 body
- 可用 `Date.now().toString(36)` 或 `crypto.randomUUID()` 快速產生唯一 ID
- `PUT` 與 `PATCH` 的差異：PUT 替換整筆資料（需傳入所有欄位），PATCH 只更新部分欄位
- `DELETE` 成功後回傳 `204 No Content`，不要回傳 body
- 用 `Array.prototype.findIndex` 找到目標書籍的索引以便更新或刪除

## 學習重點（跟後端 API 的關聯）

REST API 是業界最普遍的後端設計風格。正確使用 HTTP 動詞和狀態碼，能讓前端開發者和第三方用戶端直觀地理解 API 行為，不需要閱讀文件也能猜到操作結果。掌握這套規範是後端工程師的核心基礎，也是面試常見考題。

## 進階挑戰（選做）

1. **排序與分頁**：支援 `GET /books?sort=year&order=asc&page=1&limit=5`
2. **搜尋功能**：支援 `GET /books?search=clean` 模糊搜尋書名或作者
3. **子資源設計**：設計 `/books/:id/reviews` 讓使用者可以對書籍留評論，思考巢狀資源的 REST 設計
4. **請求驗證 middleware**：將欄位驗證邏輯抽出為獨立的 middleware 函式，讓路由處理器更簡潔
5. **統一回應格式**：讓所有回應包裝在 `{ success: true/false, data: ..., message: ... }` 結構中
