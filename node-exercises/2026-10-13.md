# 第 15 週今日 Node.js 練習題：任務管理 REST API 實戰專案

## 題目說明

實作一個完整的「任務管理系統（Task Manager API）」，整合前幾週所學的所有核心概念：Express、JWT 身份驗證、REST API 設計、輸入驗證與錯誤處理，並撰寫 Jest 測試確保 API 品質。

---

## 技術要求

- **概念：** Express、JWT、REST API、Middleware、輸入驗證、錯誤處理、單元測試
- **需要的套件：**
  - `express` — 伺服器框架
  - `jsonwebtoken` — JWT 簽發與驗證
  - `bcryptjs` — 密碼雜湊
  - `express-validator` — 輸入驗證
  - `jest` + `supertest` — API 測試

## 具體任務

### 1. 專案初始化
建立以下目錄結構：
```
task-manager/
├── src/
│   ├── app.js          # Express app（不含 listen，方便測試）
│   ├── server.js       # 啟動點（呼叫 app.listen）
│   ├── routes/
│   │   ├── auth.js     # 登入 / 註冊路由
│   │   └── tasks.js    # 任務 CRUD 路由
│   ├── middleware/
│   │   ├── auth.js     # JWT 驗證 middleware
│   │   └── errorHandler.js
│   └── data/
│       └── store.js    # 以 Map 模擬記憶體資料庫（不需 PostgreSQL）
├── tests/
│   ├── auth.test.js
│   └── tasks.test.js
└── package.json
```

### 2. 身份驗證路由（`POST /api/auth/register` 與 `POST /api/auth/login`）

**註冊**
- 接受 `{ username, password }`
- 密碼需以 `bcryptjs` 雜湊後儲存
- 回傳 `{ message: "註冊成功", userId }`

**登入**
- 驗證帳號密碼
- 成功回傳 `{ token }` (JWT，有效期 1h)

### 3. 任務 CRUD（需 JWT 驗證）

| Method | Path | 說明 |
|--------|------|------|
| GET | `/api/tasks` | 取得目前使用者的所有任務 |
| POST | `/api/tasks` | 新增任務 |
| PUT | `/api/tasks/:id` | 更新任務 |
| DELETE | `/api/tasks/:id` | 刪除任務 |

每個任務結構：
```json
{
  "id": "uuid或遞增id",
  "userId": "任務擁有者",
  "title": "任務標題",
  "completed": false,
  "createdAt": "ISO timestamp"
}
```

### 4. 輸入驗證
- `username` 長度 3–20 字元
- `password` 長度至少 6 字元
- `title` 不能為空，最多 100 字元
- 驗證失敗回傳 `422 Unprocessable Entity`

### 5. 錯誤處理 Middleware
統一回傳格式：
```json
{ "error": "錯誤訊息", "status": 400 }
```

### 6. Jest 測試（至少涵蓋）
- 成功註冊 / 重複使用者名稱 (400)
- 成功登入 / 密碼錯誤 (401)
- 無 Token 存取任務 (401)
- 建立任務、取得任務列表
- 只能操作自己的任務（其他人刪除回傳 403）

## 範例

```js
// 註冊
// POST /api/auth/register
// Body: { "username": "alice", "password": "secret123" }
// Response 201:
{ "message": "註冊成功", "userId": 1 }

// 登入
// POST /api/auth/login
// Body: { "username": "alice", "password": "secret123" }
// Response 200:
{ "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." }

// 新增任務（帶 Authorization header）
// POST /api/tasks
// Headers: { Authorization: "Bearer <token>" }
// Body: { "title": "完成 Node.js 練習" }
// Response 201:
{
  "id": 1,
  "userId": 1,
  "title": "完成 Node.js 練習",
  "completed": false,
  "createdAt": "2026-10-13T00:00:00.000Z"
}

// Jest 測試範例
describe('POST /api/auth/register', () => {
  it('應成功註冊新使用者', async () => {
    const res = await request(app)
      .post('/api/auth/register')
      .send({ username: 'alice', password: 'secret123' });
    expect(res.status).toBe(201);
    expect(res.body).toHaveProperty('userId');
  });

  it('重複使用者名稱應回傳 400', async () => {
    await request(app)
      .post('/api/auth/register')
      .send({ username: 'alice', password: 'secret123' });
    const res = await request(app)
      .post('/api/auth/register')
      .send({ username: 'alice', password: 'anotherpass' });
    expect(res.status).toBe(400);
  });
});
```

## 提示

- 將 Express app 與 `app.listen` 分離（`app.js` 只 export app，`server.js` 啟動），supertest 才能正確測試
- JWT secret 可存在 `process.env.JWT_SECRET`，測試時用 `dotenv` 或直接設預設值
- 使用 `Map<userId, tasks[]>` 模擬資料庫，無需 PostgreSQL 也能完整練習 API 流程
- `express-validator` 的 `validationResult(req)` 在路由開頭呼叫，有錯誤直接 return

## 學習重點（跟後端 API 的關聯）

這題整合了生產環境後端 API 的完整流程：
1. **身份驗證層** — JWT 是現代 stateless API 的標準做法，React/Vue 前端在 localStorage 儲存 token 後每次請求帶上
2. **Middleware 鏈** — 認證、驗證、錯誤處理都以 middleware 串接，保持路由邏輯乾淨
3. **統一錯誤格式** — 前端只需對應一種 error schema，減少 parsing 複雜度
4. **測試先行** — `supertest` 讓你在不啟動真實 server 的情況下測試 HTTP 行為，與 CI/CD 管線整合容易

## 進階挑戰（選做）

1. **分頁功能**：`GET /api/tasks?page=1&limit=10` 加上 `X-Total-Count` header
2. **任務篩選**：`GET /api/tasks?completed=true` 只回傳已完成任務
3. **Refresh Token**：實作 `POST /api/auth/refresh` 用較長效期的 refresh token 換新 access token
4. **Rate Limiting**：使用 `express-rate-limit` 限制登入嘗試次數（防暴力破解）
5. **整合 PostgreSQL**：將記憶體 store 替換為真實 DB，加上 migration 腳本
