# 第 12 週今日 Node.js 練習題：使用 Jest 測試 REST API 服務

## 題目說明

你需要為一個簡單的「待辦事項（Todo）」服務撰寫完整的單元測試與整合測試。這個服務包含新增、查詢、更新、刪除（CRUD）功能。透過本練習，你將學會如何以 Jest 測試 Express 路由、Mock 資料庫層，以及驗證 HTTP 回應。

## 技術要求

- **概念：** 單元測試、整合測試、Mock（jest.fn / jest.mock）、describe/it/expect、beforeEach/afterEach、非同步測試（async/await）
- **需要的套件：**
  - `jest`（測試框架）
  - `supertest`（HTTP 整合測試）
  - `express`（被測試的應用程式框架）

## 具體任務

1. **建立專案結構**
   ```
   todo-api/
   ├── src/
   │   ├── app.js          # Express app（不含 listen）
   │   ├── routes/
   │   │   └── todos.js    # CRUD 路由
   │   └── services/
   │       └── todoService.js  # 資料操作邏輯（以陣列模擬）
   ├── tests/
   │   ├── unit/
   │   │   └── todoService.test.js
   │   └── integration/
   │       └── todos.route.test.js
   └── package.json
   ```

2. **實作 `todoService.js`**（使用記憶體陣列，不需真實資料庫）
   - `getAll()` → 回傳所有 todo
   - `getById(id)` → 回傳單一 todo，找不到則回傳 `null`
   - `create(text)` → 新增並回傳新 todo
   - `update(id, data)` → 更新並回傳更新後的 todo，找不到則回傳 `null`
   - `remove(id)` → 刪除並回傳 `true`，找不到則回傳 `false`

3. **撰寫 `todoService.test.js`（單元測試）**
   - 測試每個 service 方法的正常情境與邊界情況（找不到 id、空字串等）
   - 使用 `beforeEach` 重置資料，確保測試隔離

4. **撰寫 `todos.route.test.js`（整合測試）**
   - 使用 `supertest` 對 Express app 發送真實 HTTP 請求
   - 使用 `jest.mock` Mock 掉 `todoService`，讓路由測試不依賴真實資料
   - 測試項目：
     - `GET /todos` → 200 + 陣列
     - `GET /todos/:id`（存在）→ 200 + 物件
     - `GET /todos/:id`（不存在）→ 404
     - `POST /todos` → 201 + 新物件
     - `PUT /todos/:id`（存在）→ 200 + 更新後物件
     - `PUT /todos/:id`（不存在）→ 404
     - `DELETE /todos/:id`（存在）→ 204
     - `DELETE /todos/:id`（不存在）→ 404

5. **設定 `package.json` scripts**
   ```json
   "scripts": {
     "test": "jest --coverage"
   }
   ```
   執行 `npm test`，確保所有測試通過且覆蓋率達 80% 以上。

## 範例

```js
// tests/unit/todoService.test.js
const todoService = require('../../src/services/todoService');

describe('todoService', () => {
  beforeEach(() => {
    // 重置模組狀態，確保每個測試獨立
    jest.resetModules();
  });

  describe('create()', () => {
    it('應建立一個新 todo 並回傳含 id 的物件', () => {
      const todo = todoService.create('買牛奶');
      expect(todo).toMatchObject({
        text: '買牛奶',
        done: false,
      });
      expect(todo.id).toBeDefined();
    });
  });

  describe('getById()', () => {
    it('找不到 id 時應回傳 null', () => {
      const result = todoService.getById('不存在的id');
      expect(result).toBeNull();
    });
  });
});

// tests/integration/todos.route.test.js
const request = require('supertest');
const app = require('../../src/app');
const todoService = require('../../src/services/todoService');

jest.mock('../../src/services/todoService');

describe('GET /todos', () => {
  it('應回傳 200 及 todo 陣列', async () => {
    todoService.getAll.mockReturnValue([{ id: '1', text: '測試', done: false }]);

    const res = await request(app).get('/todos');

    expect(res.status).toBe(200);
    expect(res.body).toBeInstanceOf(Array);
    expect(res.body).toHaveLength(1);
  });
});

describe('POST /todos', () => {
  it('應回傳 201 及新建立的 todo', async () => {
    const newTodo = { id: '2', text: '新任務', done: false };
    todoService.create.mockReturnValue(newTodo);

    const res = await request(app)
      .post('/todos')
      .send({ text: '新任務' });

    expect(res.status).toBe(201);
    expect(res.body).toEqual(newTodo);
  });
});
```

## 提示

- **app.js 不要呼叫 `app.listen()`**，讓 supertest 自行管理 port，避免測試間的 port 衝突。
- 使用 `jest.mock('../../src/services/todoService')` 後，該模組的所有 export 都會變成 `jest.fn()`，記得在每個測試前用 `mockReturnValue` 或 `mockResolvedValue` 設定回傳值。
- 若 service 方法是 async 的，整合測試要用 `mockResolvedValue` 而非 `mockReturnValue`。
- 使用 `afterEach(() => jest.clearAllMocks())` 清除 mock 狀態，避免測試互相汙染。
- 覆蓋率報告（`--coverage`）會顯示哪些行沒被測試到，優先補齊 `branches`（分支覆蓋）。

## 學習重點（跟後端 API 的關聯）

測試是後端 API 品質保證的核心。在實際專案中：
- **單元測試** 確保每個 service / utility 邏輯正確，不受外部依賴（DB、HTTP）影響，執行速度快。
- **整合測試** 驗證路由、middleware、status code、response body 是否符合 API 規格，是最接近「API 真實行為」的自動化驗證。
- **Mock** 讓你在不連線資料庫的情況下測試路由邏輯，CI/CD Pipeline 跑測試時不需要真實環境。
- 高覆蓋率讓你在重構（如第 8 週換成 PostgreSQL、第 9 週加入 JWT）時，能快速發現回歸錯誤。

## 進階挑戰（選做）

1. **測試 Middleware：** 新增一個簡單的 `auth middleware`（檢查 `Authorization: Bearer <token>` header），並為它撰寫單元測試，測試有/無 token 兩種情境。
2. **Snapshot 測試：** 對 `GET /todos` 的回應結構使用 `expect(res.body).toMatchSnapshot()`，觀察 snapshot 檔案如何自動產生。
3. **測試覆蓋率門檻：** 在 `package.json` 的 Jest 設定加入 `coverageThreshold`，讓覆蓋率低於 80% 時 `npm test` 自動失敗：
   ```json
   "jest": {
     "coverageThreshold": {
       "global": {
         "lines": 80,
         "branches": 80
       }
     }
   }
   ```
4. **平行測試：** 使用 `--runInBand` 旗標觀察測試改為序列執行時的速度差異，思考何時需要序列執行（例如測試共用記憶體狀態時）。
