# 第 20 週今日 Node.js 練習題：任務管理 REST API 實戰專案

## 題目說明

建立一個完整的任務管理（Todo）REST API，整合 Express、JWT 身份驗證、輸入驗證、錯誤處理，並撰寫 Jest 測試。這道題目綜合了前幾週所有核心技能，模擬真實後端開發情境。

## 技術要求

- **概念**：REST API 設計、JWT 驗證、Middleware 鏈、輸入驗證、錯誤處理、單元測試
- **需要的套件**：
  - `express` — HTTP 框架
  - `jsonwebtoken` — JWT 簽發與驗證
  - `bcryptjs` — 密碼雜湊
  - `express-validator` — 輸入驗證
  - `jest` + `supertest` — API 測試

## 具體任務

1. **初始化專案結構**
   ```
   todo-api/
   ├── src/
   │   ├── routes/
   │   │   ├── auth.js       # 登入 / 註冊
   │   │   └── tasks.js      # 任務 CRUD
   │   ├── middleware/
   │   │   ├── auth.js       # JWT 驗證 middleware
   │   │   └── validate.js   # 輸入驗證 middleware
   │   ├── data/
   │   │   └── store.js      # 記憶體資料儲存（模擬 DB）
   │   └── app.js            # Express 應用程式
   ├── tests/
   │   ├── auth.test.js
   │   └── tasks.test.js
   └── package.json
   ```

2. **實作認證路由 `POST /api/auth/register` 與 `POST /api/auth/login`**
   - 註冊：接受 `email`、`password`，以 `bcryptjs` 雜湊密碼後存入記憶體 store
   - 登入：驗證帳密後簽發 JWT（有效期 1 小時）

3. **實作任務 CRUD（需攜帶 JWT）**
   - `GET    /api/tasks`        — 列出當前使用者所有任務
   - `POST   /api/tasks`        — 新增任務（`title` 必填、`description` 選填）
   - `PATCH  /api/tasks/:id`    — 更新任務內容或 `completed` 狀態
   - `DELETE /api/tasks/:id`    — 刪除任務（只能刪除自己的）

4. **加入 express-validator 輸入驗證**
   - 註冊：`email` 格式正確、`password` 至少 6 字元
   - 新增任務：`title` 不可空白、長度最多 100 字

5. **統一錯誤處理 middleware**
   - 所有錯誤統一回傳 `{ error: "...", code: "..." }` 格式
   - 區分 `400 Bad Request`、`401 Unauthorized`、`403 Forbidden`、`404 Not Found`

6. **撰寫 Jest + Supertest 測試**
   - 至少測試：成功註冊、重複 email 失敗、登入失敗、未帶 token 存取任務、新增任務成功、刪除他人任務應 403

## 範例

```js
// POST /api/auth/login
// Request body:
{ "email": "user@example.com", "password": "secret123" }

// Response 200:
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": { "id": "u1", "email": "user@example.com" }
}

// POST /api/tasks  (Authorization: Bearer <token>)
// Request body:
{ "title": "學習 Node.js", "description": "完成第 20 週練習" }

// Response 201:
{
  "id": "t1",
  "title": "學習 Node.js",
  "description": "完成第 20 週練習",
  "completed": false,
  "createdAt": "2026-11-21T10:00:00.000Z"
}

// GET /api/tasks  (沒有 token)
// Response 401:
{ "error": "Token 缺失或無效", "code": "UNAUTHORIZED" }
```

## 提示

- 記憶體 store 可用簡單的 `Map` 或陣列，不需要真實資料庫
- JWT middleware 從 `Authorization: Bearer <token>` 標頭取得 token，解碼後將 user 附加到 `req.user`
- 任務 ID 可用 `crypto.randomUUID()` 產生（Node.js 15+ 內建）
- 測試時用 `supertest(app)` 而非真正啟動伺服器，避免 port 衝突
- 分離 `app.js`（設定 Express）與 `server.js`（呼叫 `app.listen`），讓測試可以直接 import app

## 學習重點（跟後端 API 的關聯）

| 本週練習 | 真實後端對應 |
|---|---|
| 記憶體 store | 換成 PostgreSQL / MongoDB |
| JWT 簽發 | OAuth2、Session 機制 |
| Middleware 鏈 | RBAC 權限控制、Rate Limiting |
| Supertest 測試 | CI/CD 自動化測試流水線 |
| 錯誤格式統一 | API 錯誤規範（RFC 7807） |

這個練習是所有 API 後端的通用骨架——掌握它，就掌握了 Express API 開發的完整循環。

## 進階挑戰（選做）

1. **分頁**：`GET /api/tasks?page=1&limit=10`，回傳 `{ tasks, total, page, totalPages }`
2. **篩選與排序**：支援 `?completed=true`、`?sort=createdAt:desc`
3. **Refresh Token**：登入時同時簽發 access token（15 分鐘）與 refresh token（7 天），實作 `POST /api/auth/refresh`
4. **Rate Limiting**：用 `express-rate-limit` 限制登入端點每 15 分鐘最多 10 次請求
5. **OpenAPI 文件**：用 `swagger-jsdoc` + `swagger-ui-express` 自動產生 API 文件
