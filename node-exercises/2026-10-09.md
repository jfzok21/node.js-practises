# 第 14 週今日 Node.js 練習題：全端書籤管理 REST API

## 題目說明

建立一個完整的「書籤管理系統」REST API，讓使用者可以儲存、分類、搜尋網頁書籤。此專案將整合前幾週所學的所有技術：Express、PostgreSQL、JWT 驗證、輸入驗證、錯誤處理，以及 Jest 測試。

## 技術要求
- 概念：REST API 設計、JWT 身份驗證、資料庫 CRUD、分頁查詢、全文搜尋
- 需要的套件：`express`、`pg`、`jsonwebtoken`、`bcrypt`、`joi`（或 `zod`）、`jest`、`supertest`

## 具體任務

1. **資料庫設計**：建立以下兩張資料表：
   - `users`：`id`、`email`、`password_hash`、`created_at`
   - `bookmarks`：`id`、`user_id`（外鍵）、`title`、`url`、`description`、`tags`（TEXT ARRAY）、`created_at`

2. **身份驗證路由**：
   - `POST /api/auth/register`：註冊（email + password）
   - `POST /api/auth/login`：登入，回傳 JWT

3. **書籤 CRUD 路由**（需 JWT middleware 保護）：
   - `GET /api/bookmarks`：列出目前使用者的所有書籤（支援分頁：`?page=1&limit=10`）
   - `POST /api/bookmarks`：新增書籤
   - `GET /api/bookmarks/:id`：取得單一書籤
   - `PUT /api/bookmarks/:id`：更新書籤
   - `DELETE /api/bookmarks/:id`：刪除書籤

4. **搜尋功能**：
   - `GET /api/bookmarks/search?q=關鍵字`：依 title 或 description 搜尋

5. **輸入驗證**：
   - 新增/更新書籤時驗證 `url` 格式合法、`title` 不為空白

6. **錯誤處理 Middleware**：統一回傳格式 `{ error: "訊息" }`

7. **撰寫 Jest 測試**：至少涵蓋 `POST /api/bookmarks` 與 `GET /api/bookmarks` 的正常與錯誤情境

## 範例

```js
// POST /api/bookmarks 請求 body
{
  "title": "MDN Web Docs",
  "url": "https://developer.mozilla.org",
  "description": "Web 技術文件",
  "tags": ["javascript", "css", "html"]
}

// 成功回應 201
{
  "id": 1,
  "user_id": 3,
  "title": "MDN Web Docs",
  "url": "https://developer.mozilla.org",
  "description": "Web 技術文件",
  "tags": ["javascript", "css", "html"],
  "created_at": "2026-10-09T08:00:00.000Z"
}

// GET /api/bookmarks?page=1&limit=5 回應
{
  "data": [ /* 書籤陣列 */ ],
  "pagination": {
    "page": 1,
    "limit": 5,
    "total": 23,
    "totalPages": 5
  }
}

// 驗證錯誤回應 400
{
  "error": "url 格式不合法"
}
```

## 提示

- JWT middleware 可寫成 `src/middlewares/auth.js`，在受保護路由前使用 `router.use(authMiddleware)`
- PostgreSQL 陣列欄位在 Node.js 中用 `$1::text[]` 傳遞，例如 `['javascript', 'css']`
- 分頁查詢使用 `LIMIT $1 OFFSET $2`，`OFFSET = (page - 1) * limit`
- 搜尋可使用 `WHERE title ILIKE $1 OR description ILIKE $1`，參數傳 `%關鍵字%`
- 測試時可用 `supertest` 搭配 `jest`，資料庫可使用測試專用的 schema 或 mock

## 學習重點（跟後端 API 的關聯）

這個實戰專案模擬真實產品後端的完整結構：

- **關聯式資料庫設計**：外鍵確保資料一致性，是所有後端系統的核心
- **JWT 無狀態驗證**：每個請求攜帶 token，不需伺服器儲存 session，便於水平擴展
- **分頁查詢**：防止一次回傳過多資料，保護資料庫效能
- **統一錯誤格式**：前端可依 status code + error 訊息做出適當 UI 回應
- **自動化測試**：CI/CD 流程的基礎，確保每次更新不破壞既有功能

## 進階挑戰（選做）

- 新增 `PATCH /api/bookmarks/:id/tags` 端點，僅更新 tags 陣列（不覆蓋整筆資料）
- 實作「標籤篩選」：`GET /api/bookmarks?tag=javascript` 回傳含有該標籤的書籤
- 加入 `rate limiting` middleware（`express-rate-limit`），限制每 IP 每分鐘最多 100 次請求
- 將資料庫連線池（`pg.Pool`）抽成共用模組，並在 app 關閉時優雅地結束連線（`pool.end()`）
- 使用 `jest --coverage` 檢查測試覆蓋率，目標達到 80% 以上
