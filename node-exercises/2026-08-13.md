# 第 6 週今日 Node.js 練習題：Express Middleware 實作

## 題目說明

在 Express 框架中，Middleware（中介軟體）是處理 HTTP 請求與回應之間的函式。本次練習將帶你實作三種常見的 Middleware：日誌記錄、請求驗證、以及錯誤處理，讓你理解 Middleware 在後端 API 架構中的核心角色。

## 技術要求

- **概念**：Express Middleware、`next()` 函式、錯誤處理 Middleware、路由層級 vs 應用層級 Middleware
- **需要的套件**：`express`（`npm install express`）

## 具體任務

1. **建立 Express 應用**：初始化一個基本的 Express 伺服器，監聽 3000 port。

2. **實作 Logger Middleware（應用層級）**：
   - 每個請求進來時，輸出：`[時間戳記] METHOD /路徑 - 耗時 Xms`
   - 耗時需等回應送出後才計算（使用 `res.on('finish', ...)` 事件）。

3. **實作 Auth Middleware（路由層級）**：
   - 建立一個 `/api/secret` 路由，套用驗證 Middleware。
   - 驗證規則：請求 Header 必須包含 `x-api-key: my-secret-key`，否則回傳 `401 Unauthorized`。

4. **實作錯誤處理 Middleware**：
   - 建立一個 `/api/crash` 路由，主動呼叫 `next(new Error('Something went wrong'))`。
   - 新增 Express 的四參數錯誤處理 Middleware `(err, req, res, next)`，統一回傳 `500` 與錯誤訊息。

5. **測試所有路由**：使用 `curl` 或 Postman 驗證各種情境。

## 範例

```js
const express = require('express');
const app = express();

// Logger Middleware（應用層級）
app.use((req, res, next) => {
  const start = Date.now();
  res.on('finish', () => {
    const ms = Date.now() - start;
    console.log(`[${new Date().toISOString()}] ${req.method} ${req.path} - ${ms}ms`);
  });
  next();
});

// Auth Middleware（函式，供路由層級使用）
const authMiddleware = (req, res, next) => {
  const apiKey = req.headers['x-api-key'];
  if (apiKey !== 'my-secret-key') {
    return res.status(401).json({ error: 'Unauthorized' });
  }
  next();
};

// 一般路由
app.get('/', (req, res) => {
  res.json({ message: 'Hello, World!' });
});

// 套用 Auth Middleware 的保護路由
app.get('/api/secret', authMiddleware, (req, res) => {
  res.json({ secret: '你已通過驗證！' });
});

// 觸發錯誤的路由
app.get('/api/crash', (req, res, next) => {
  next(new Error('Something went wrong'));
});

// 錯誤處理 Middleware（四個參數，必須放在最後）
app.use((err, req, res, next) => {
  console.error(err.message);
  res.status(500).json({ error: err.message });
});

app.listen(3000, () => console.log('Server running on port 3000'));
```

```bash
# 測試一般路由
curl http://localhost:3000/

# 測試未帶 API Key（應收到 401）
curl http://localhost:3000/api/secret

# 測試帶正確 API Key（應收到 secret 訊息）
curl -H "x-api-key: my-secret-key" http://localhost:3000/api/secret

# 測試錯誤路由（應收到 500）
curl http://localhost:3000/api/crash
```

## 提示

- `next()` 不帶參數 → 繼續執行下一個 Middleware 或路由。
- `next(err)` 帶 Error 物件 → 跳過一般 Middleware，直接進入錯誤處理 Middleware。
- 錯誤處理 Middleware 的函式簽名必須是四個參數 `(err, req, res, next)`，缺少任何一個 Express 就不會把它識別為錯誤處理器。
- Middleware 的**順序**非常重要：Logger 要在所有路由之前，錯誤處理 Middleware 必須在所有路由之後。

## 學習重點

**與後端 API 的關聯：**

在真實的後端 API 開發中，Middleware 是架構的核心：

| Middleware 類型 | 實際應用 |
|---|---|
| Logger | 記錄 API 存取日誌，用於監控與除錯 |
| Auth | JWT 驗證、API Key 檢查，保護私有端點 |
| 錯誤處理 | 統一錯誤回應格式，避免 stack trace 外洩 |
| Body Parser | 解析 JSON 請求體（`express.json()`） |
| CORS | 控制跨域請求權限 |

理解 Middleware 的 **next() 流程**，是之後實作 JWT 身份驗證（第 9 週）和輸入驗證（第 10 週）的必要基礎。

## 進階挑戰（選做）

1. **限速 Middleware（Rate Limiting）**：實作一個 Middleware，限制同一個 IP 在 60 秒內最多只能發送 10 次請求，超過時回傳 `429 Too Many Requests`。（提示：使用 `Map` 儲存 IP 與請求計數）

2. **可組合的 Middleware 工廠**：將 Auth Middleware 改寫成一個工廠函式，接受允許的 API Keys 陣列作為參數：
   ```js
   const authMiddleware = (allowedKeys) => (req, res, next) => { ... };
   app.get('/api/v1', authMiddleware(['key-a', 'key-b']), handler);
   ```

3. **請求 ID 追蹤**：在 Logger Middleware 中為每個請求產生唯一的 `requestId`（可用 `Math.random().toString(36).slice(2)`），掛載到 `req.requestId`，並在回應 Header 中帶回 `X-Request-Id`。
