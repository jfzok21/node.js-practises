# 第 16 週今日 Node.js 練習題：任務管理 REST API 實戰專案

## 題目說明

建立一個完整的任務管理系統後端 API，整合 JWT 身份驗證、PostgreSQL 資料庫、輸入驗證、檔案上傳，並附上 Jest 測試。這是一個涵蓋前幾週所有核心知識的綜合實戰練習。

## 技術要求
- **概念**：REST API 設計、JWT 驗證、資料庫 CRUD、Middleware、錯誤處理、測試
- **需要的套件**：
  - `express` — 網頁框架
  - `pg` 或 `prisma` — PostgreSQL 連線
  - `jsonwebtoken` — JWT 驗證
  - `bcryptjs` — 密碼雜湊
  - `express-validator` — 輸入驗證
  - `multer` — 附件上傳
  - `jest` + `supertest` — 測試

## 具體任務

1. **資料庫設計**：建立以下兩張資料表：
   - `users`（id, email, password_hash, created_at）
   - `tasks`（id, user_id, title, description, status, attachment_url, due_date, created_at）

2. **身份驗證路由**：
   - `POST /api/auth/register` — 註冊（驗證 email 格式、密碼長度 ≥ 8）
   - `POST /api/auth/login` — 登入，回傳 JWT token

3. **任務 CRUD 路由**（需要 JWT）：
   - `GET /api/tasks` — 列出當前使用者的所有任務，支援 `?status=pending|done` 篩選
   - `POST /api/tasks` — 建立任務（驗證 title 必填、due_date 格式）
   - `PATCH /api/tasks/:id` — 更新任務狀態或內容
   - `DELETE /api/tasks/:id` — 刪除任務（只能刪除自己的）

4. **附件上傳**：
   - `POST /api/tasks/:id/attachment` — 上傳圖片或 PDF（限制 5MB），儲存路徑更新至資料庫

5. **錯誤處理 Middleware**：
   - 統一回傳格式 `{ error: "訊息", code: "ERROR_CODE" }`
   - 處理 404、401 未驗證、403 無權限、500 伺服器錯誤

6. **撰寫 Jest 測試**（至少 5 個 test case）：
   - 測試註冊成功 / 重複 email 失敗
   - 測試登入取得 token
   - 測試未帶 token 存取任務 API 回傳 401
   - 測試建立任務成功
   - 測試刪除他人任務回傳 403

## 範例

```js
// 建立任務
// POST /api/tasks
// Headers: { Authorization: "Bearer <token>" }
// Body:
{
  "title": "完成 Node.js 練習",
  "description": "整合所有本學期技術",
  "due_date": "2026-10-30"
}

// 回應 201
{
  "id": 1,
  "user_id": 42,
  "title": "完成 Node.js 練習",
  "status": "pending",
  "due_date": "2026-10-30",
  "created_at": "2026-10-23T08:00:00.000Z"
}

// 未帶 token 存取任務
// GET /api/tasks  (無 Authorization header)
// 回應 401
{
  "error": "未提供驗證 token",
  "code": "UNAUTHORIZED"
}

// 刪除他人任務
// DELETE /api/tasks/99
// 回應 403
{
  "error": "無權限操作此任務",
  "code": "FORBIDDEN"
}
```

## 提示

- 將 JWT 驗證邏輯抽成獨立 middleware（`middlewares/auth.js`），在需要保護的路由群組上套用
- 使用 `express.Router()` 分檔管理路由，避免 `app.js` 過於龐大
- 附件上傳可先存至 `uploads/` 本地資料夾，儲存相對路徑即可，不必接 S3
- 測試時使用 `supertest` 搭配測試用資料庫（或 mock pg），避免污染正式資料
- `bcryptjs` 雜湊時 salt rounds 設 10 即可，不要存明文密碼
