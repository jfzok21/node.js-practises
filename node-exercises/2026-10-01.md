# 第 13 週今日 Node.js 練習題：任務管理 REST API（全端整合實戰）

## 題目說明

打造一個完整的「任務管理系統」後端 API，整合前幾週學過的所有核心技術：Express 路由、JWT 身份驗證、PostgreSQL 資料庫、輸入驗證、錯誤處理，以及 Jest 單元測試。這是一個貼近真實工作場景的實戰專案。

---

## 技術要求

- **概念：** REST API 設計、JWT 身份驗證流程、資料庫 CRUD、middleware 組合、錯誤統一處理、分層架構（routes / controllers / services）
- **需要的套件：**
  - `express`
  - `pg`（PostgreSQL 客戶端）
  - `jsonwebtoken`
  - `bcryptjs`
  - `express-validator`
  - `jest` + `supertest`（測試）
  - `dotenv`

---

## 具體任務

1. **初始化專案**
   - `npm init -y`，安裝所有依賴套件
   - 建立 `.env` 管理資料庫連線與 JWT 密鑰

2. **設計資料庫 Schema**
   建立兩張資料表：
   ```sql
   CREATE TABLE users (
     id SERIAL PRIMARY KEY,
     email VARCHAR(255) UNIQUE NOT NULL,
     password_hash VARCHAR(255) NOT NULL,
     created_at TIMESTAMP DEFAULT NOW()
   );

   CREATE TABLE tasks (
     id SERIAL PRIMARY KEY,
     user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
     title VARCHAR(255) NOT NULL,
     description TEXT,
     status VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending', 'in_progress', 'done')),
     due_date DATE,
     created_at TIMESTAMP DEFAULT NOW()
   );
   ```

3. **實作身份驗證路由 `/api/auth`**
   - `POST /api/auth/register`：註冊（bcrypt 加密密碼，存入資料庫）
   - `POST /api/auth/login`：登入（驗證密碼，回傳 JWT）

4. **實作任務 CRUD 路由 `/api/tasks`（需要 JWT 驗證）**
   - `GET /api/tasks`：取得目前使用者的所有任務（支援 `?status=pending` 篩選）
   - `POST /api/tasks`：建立新任務
   - `PUT /api/tasks/:id`：更新任務（只能更新自己的）
   - `DELETE /api/tasks/:id`：刪除任務（只能刪除自己的）

5. **加入 Middleware**
   - `authMiddleware`：驗證 JWT，將 `req.user` 注入使用者資訊
   - `validateTask`：使用 `express-validator` 驗證 `title`（必填、最長 100 字）、`status`（只允許三種值）
   - 全域錯誤處理 middleware（捕捉未預期錯誤，回傳統一格式）

6. **撰寫 Jest 測試（至少 3 個測試案例）**
   - 使用 `supertest` 測試 API 端點
   - 測試：未帶 JWT 時回傳 401、建立任務成功回傳 201、查詢不存在任務回傳 404

## 範例

```js
// 登入成功回應
POST /api/auth/login
Body: { "email": "user@example.com", "password": "secret123" }

Response 200:
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": { "id": 1, "email": "user@example.com" }
}

// 建立任務
POST /api/tasks
Headers: { "Authorization": "Bearer <token>" }
Body: { "title": "完成 API 作業", "status": "in_progress", "due_date": "2026-10-07" }

Response 201:
{
  "id": 5,
  "title": "完成 API 作業",
  "status": "in_progress",
  "due_date": "2026-10-07",
  "created_at": "2026-10-01T10:00:00Z"
}

// 未授權存取
GET /api/tasks  (沒有帶 token)
Response 401:
{ "error": "未提供有效的身份驗證 Token" }
```

## 提示

- 將 DB 連線邏輯抽到獨立的 `db.js`，避免在 controller 裡直接寫 `pg.Pool`
- 使用 `async/await` + `try/catch` 處理所有非同步操作
- JWT 驗證 middleware 從 `Authorization: Bearer <token>` header 解析 token
- `bcryptjs.compare()` 比較密碼時不要洩漏「使用者不存在」還是「密碼錯誤」，統一回傳「帳號或密碼錯誤」
- 查詢任務時記得加 `WHERE user_id = $1` 條件，防止使用者存取他人資料

## 學習重點（跟後端 API 的關聯）

這個專案模擬真實後端開發的完整流程：

| 層次 | 技術 | 真實場景對應 |
|------|------|------------|
| 路由層 | Express Router | API endpoint 定義 |
| 驗證層 | JWT + Middleware | 使用者身份識別 |
| 業務層 | Controller/Service | 商業邏輯處理 |
| 資料層 | PostgreSQL + pg | 持久化儲存 |
| 測試層 | Jest + Supertest | CI/CD 品質保證 |

掌握這套架構，你就具備了面試中最常被問到的 Node.js 後端開發能力。

## 進階挑戰（選做）

1. **分頁功能**：`GET /api/tasks?page=1&limit=10`，回傳 `{ data, total, page, totalPages }`
2. **軟刪除**：在 tasks 加 `deleted_at` 欄位，DELETE 只設時間戳不真正刪除
3. **重新整理 Token**：實作 Refresh Token 機制，存入 `refresh_tokens` 資料表
4. **Rate Limiting**：安裝 `express-rate-limit`，限制 `/api/auth/login` 每分鐘最多 5 次請求
5. **Docker Compose**：撰寫 `docker-compose.yml`，一行指令啟動 Node.js app + PostgreSQL
