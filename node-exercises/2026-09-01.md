# 第 9 週今日 Node.js 練習題：JWT 身份驗證系統

## 題目說明

建立一個具備 JWT（JSON Web Token）身份驗證機制的 Express API。使用者需能透過帳號密碼登入取得 Token，並以 Token 存取受保護的路由，練習後端開發中最常見的認證流程。

---

## 技術要求

- **概念**：JWT 簽發與驗證、Bearer Token、Middleware 攔截、密碼雜湊
- **需要的套件**：
  - `express` — Web 框架
  - `jsonwebtoken` — JWT 簽發與驗證
  - `bcryptjs` — 密碼雜湊
  - `dotenv` — 管理環境變數

---

## 具體任務

1. 初始化專案並安裝所需套件：
   ```
   npm init -y
   npm install express jsonwebtoken bcryptjs dotenv
   ```

2. 建立 `.env` 檔案，設定以下環境變數：
   ```
   JWT_SECRET=your_super_secret_key
   JWT_EXPIRES_IN=1h
   PORT=3000
   ```

3. 建立一個模擬使用者資料庫（記憶體陣列即可），預先存入至少一組使用者，密碼需用 `bcryptjs.hashSync()` 雜湊後儲存。

4. 實作以下三支 API：

   **POST `/api/register`**
   - 接收 `{ username, password }`
   - 驗證欄位不得為空
   - 確認使用者名稱不重複
   - 以 bcrypt 雜湊密碼後儲存

   **POST `/api/login`**
   - 接收 `{ username, password }`
   - 查找使用者，用 `bcrypt.compare()` 驗證密碼
   - 驗證成功後簽發 JWT，回傳 `{ token, message }`

   **GET `/api/profile`**（受保護路由）
   - 需帶 `Authorization: Bearer <token>` Header
   - 建立 `authMiddleware` 解析並驗證 Token
   - 驗證成功回傳使用者資訊（排除密碼欄位）

5. 處理常見錯誤情境：
   - Token 缺失 → 401 Unauthorized
   - Token 過期或無效 → 403 Forbidden
   - 使用者名稱已存在 → 409 Conflict
   - 帳號或密碼錯誤 → 401 Unauthorized

---

## 範例

```js
// authMiddleware.js
const jwt = require('jsonwebtoken');

function authMiddleware(req, res, next) {
  const authHeader = req.headers['authorization'];
  const token = authHeader && authHeader.split(' ')[1]; // Bearer <token>

  if (!token) {
    return res.status(401).json({ error: 'Token 缺失，請先登入' });
  }

  try {
    const decoded = jwt.verify(token, process.env.JWT_SECRET);
    req.user = decoded; // 將解碼資料掛到 req
    next();
  } catch (err) {
    return res.status(403).json({ error: 'Token 無效或已過期' });
  }
}

module.exports = authMiddleware;
```

```js
// 登入路由範例
// POST /api/login
// 請求：{ "username": "alice", "password": "mypassword" }
// 成功回應：
{
  "message": "登入成功",
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}

// GET /api/profile（帶 Token）
// Header: Authorization: Bearer eyJhbGciOiJIUzI1...
// 成功回應：
{
  "message": "取得個人資料成功",
  "user": {
    "id": 1,
    "username": "alice"
  }
}
```

## 提示

- JWT payload 可存放 `id` 和 `username`，**不要**存放密碼。
- 使用 `jwt.sign(payload, secret, { expiresIn: '1h' })` 簽發 Token。
- `bcrypt.compare(inputPassword, hashedPassword)` 回傳 Promise，記得 `await`。
- 用 Postman 或 curl 測試時，確認 Header 格式為 `Authorization: Bearer <token>`。
- 將 `JWT_SECRET` 放進 `.env`，**不要** hardcode 在程式碼中。

## 學習重點（跟後端 API 的關聯）

JWT 是現代 REST API 中最廣泛採用的無狀態認證機制。相較於 Session/Cookie，JWT 的優勢在於：

- **無狀態**：伺服器不需儲存 Session，水平擴展更容易。
- **跨域友好**：Token 可在不同域名的前後端之間傳遞。
- **Middleware 模式**：`authMiddleware` 的寫法是 Express 保護路由的標準做法，可套用在任意路由上。

掌握 JWT 後，你就能在任何 REST API 專案（如 Week 7 設計的 API）加上身份驗證，是完整後端服務不可或缺的一環。

## 進階挑戰（選做）

1. **Refresh Token 機制**：簽發短效 Access Token（15 分鐘）與長效 Refresh Token（7 天），並實作 `POST /api/refresh` 路由更新 Access Token。

2. **角色權限（RBAC）**：在使用者資料中加入 `role`（如 `admin` / `user`），並建立 `requireRole('admin')` Middleware，讓特定路由只允許管理員存取。

3. **Token 黑名單**：實作登出（`POST /api/logout`）功能，將已登出的 Token 加入記憶體黑名單，在 Middleware 中攔截黑名單內的 Token。
