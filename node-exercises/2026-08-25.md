# 第 8 週今日 Node.js 練習題：使用 PostgreSQL 建立商品管理 API

## 題目說明

建立一個使用 PostgreSQL 資料庫的商品管理 REST API。你將學習如何在 Node.js 中連接 PostgreSQL、執行 SQL 查詢，以及透過 Express 路由提供 CRUD 操作的端點。

## 技術要求

- **概念**：PostgreSQL 連線、SQL 查詢（SELECT / INSERT / UPDATE / DELETE）、參數化查詢（防 SQL Injection）、連線池（pg Pool）
- **需要的套件**：`express`、`pg`（node-postgres）、`dotenv`

## 具體任務

1. 初始化專案並安裝所需套件：
   ```bash
   npm init -y
   npm install express pg dotenv
   ```

2. 建立 `.env` 檔案，儲存資料庫連線資訊：
   ```
   DB_HOST=localhost
   DB_PORT=5432
   DB_NAME=shop
   DB_USER=postgres
   DB_PASSWORD=yourpassword
   PORT=3000
   ```

3. 在 PostgreSQL 建立 `products` 資料表：
   ```sql
   CREATE TABLE products (
     id SERIAL PRIMARY KEY,
     name VARCHAR(100) NOT NULL,
     price NUMERIC(10, 2) NOT NULL,
     stock INTEGER NOT NULL DEFAULT 0,
     created_at TIMESTAMP DEFAULT NOW()
   );
   ```

4. 建立 `db.js`，使用 `pg.Pool` 建立連線池：
   ```js
   // db.js
   const { Pool } = require('pg');
   require('dotenv').config();
   // 匯出 pool 供其他模組使用
   ```

5. 建立 `app.js`，實作以下五個 API 端點：
   - `GET  /products`          — 取得所有商品
   - `GET  /products/:id`      — 取得單一商品
   - `POST /products`          — 新增商品
   - `PUT  /products/:id`      — 更新商品資訊
   - `DELETE /products/:id`    — 刪除商品

6. 所有 SQL 查詢必須使用**參數化查詢**（`$1`, `$2` ...），禁止直接字串拼接。

7. 若查詢的 id 不存在，回傳 `404` 與適當訊息。

## 範例

```js
// GET /products/1 的回應（200 OK）
{
  "id": 1,
  "name": "藍芽耳機",
  "price": "1299.00",
  "stock": 50,
  "created_at": "2026-08-25T08:00:00.000Z"
}

// POST /products 的請求 body
{
  "name": "無線滑鼠",
  "price": 599,
  "stock": 100
}

// POST /products 的回應（201 Created）
{
  "id": 5,
  "name": "無線滑鼠",
  "price": "599.00",
  "stock": 100,
  "created_at": "2026-08-25T09:30:00.000Z"
}

// DELETE /products/99 的回應（404 Not Found）
{
  "error": "找不到 id 為 99 的商品"
}
```

## 提示

- 使用 `Pool` 而非 `Client`，連線池能自動管理多個連線，適合 Web 伺服器情境。
- `pool.query(text, params)` 回傳 Promise，記得使用 `async/await`。
- `RETURNING *` 子句可讓 INSERT / UPDATE / DELETE 直接回傳受影響的列。
  ```sql
  INSERT INTO products (name, price, stock) VALUES ($1, $2, $3) RETURNING *;
  ```
- 用 `result.rows` 取得查詢結果陣列，`result.rows[0]` 取得第一筆。
- 記得在 `app.js` 加上 `express.json()` middleware，才能解析 POST/PUT 的 body。

## 學習重點（跟後端 API 的關聯）

| 概念 | 在實際後端的應用 |
|------|----------------|
| `pg.Pool` | 高流量情境下避免每次請求重新建立連線，降低延遲 |
| 參數化查詢 | 防止 SQL Injection，這是 OWASP Top 10 的核心防護 |
| `RETURNING *` | 減少一次額外的 SELECT 查詢，提升效能 |
| `.env` + `dotenv` | 分離環境設定與程式碼，是 12-Factor App 的核心原則 |
| 連線池錯誤處理 | 生產環境必須處理 DB 連線失敗，避免服務整體中斷 |

## 進階挑戰（選做）

1. **分頁功能**：在 `GET /products` 加入 `?page=1&limit=10` 的分頁查詢支援，使用 SQL 的 `LIMIT` 和 `OFFSET`。

2. **搜尋功能**：支援 `?name=耳機` 的模糊搜尋，使用 `ILIKE '%$1%'`（注意需用 `$1` 參數化，不可拼字串）。

3. **交易（Transaction）**：建立 `POST /products/bulk` 端點，一次接收多筆商品並在同一個 transaction 中寫入，任一失敗則全部 rollback。
   ```js
   const client = await pool.connect();
   try {
     await client.query('BEGIN');
     // ... 多次 INSERT
     await client.query('COMMIT');
   } catch (e) {
     await client.query('ROLLBACK');
   } finally {
     client.release();
   }
   ```

4. **錯誤碼分類**：區分 DB 連線失敗（503）與資料驗證錯誤（400），給前端更精確的 HTTP 狀態碼。
