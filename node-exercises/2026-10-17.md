# 第 15 週今日 Node.js 練習題：Socket.io 即時聊天室

## 題目說明

以 **Socket.io** 搭配 Express 打造一個支援多房間的即時聊天室後端。使用者需先以 JWT 登入取得 token，再透過 WebSocket 連線進入聊天室，與其他使用者即時交換訊息。本題將帶你理解 HTTP 與 WebSocket 的差異，以及如何在 Socket 層實作身份驗證。

---

## 技術要求

- **概念：** WebSocket、Socket.io、JWT Socket 驗證、事件驅動架構、房間（Room）管理
- **需要的套件：**
  - `express` — HTTP 伺服器與靜態檔案
  - `socket.io` — WebSocket 抽象層
  - `jsonwebtoken` — Socket 握手時驗證身份
  - `bcryptjs` — 密碼雜湊
  - `uuid` — 訊息 ID 生成
  - `jest` + `socket.io-client` — 整合測試（選做）

│   │   └── chatHandler.js    # 各事件處理邏輯

│       └── index.js    # 記憶體資料：users Map、訊息陣列

### 2. HTTP 身份驗證（沿用前幾週模式）

- `POST /api/auth/register`：接受 `{ username, password }`，密碼 bcrypt hash，回傳 `{ userId, message }`
- `POST /api/auth/login`：驗證成功後回傳 `{ token }`（JWT 有效期 2h，payload 含 `userId`、`username`）

### 3. Socket.io 身份驗證 Middleware

在 `socket/authMiddleware.js` 中攔截每次 WebSocket 握手：

```js
io.use((socket, next) => {
  const token = socket.handshake.auth?.token;
  // 驗證 token → 解出 user，掛到 socket.data.user
  // 驗證失敗呼叫 next(new Error('未授權'))
});
```

### 4. 聊天室事件（`socket/chatHandler.js`）

| 客戶端 emit | 伺服器行為 | 伺服器回傳事件 |
|------------|-----------|--------------|
| `join_room` `{ room }` | 加入指定房間，廣播加入通知 | `user_joined` → 同房間所有人 |
| `leave_room` `{ room }` | 離開房間，廣播離開通知 | `user_left` → 同房間所有人 |
| `send_message` `{ room, text }` | 儲存訊息，廣播至同房間 | `new_message` → 同房間所有人 |
| `get_history` `{ room }` | 取得該房間最近 50 則訊息 | `message_history` → 僅回傳給請求方 |
| `list_rooms` | 回傳目前有訊息的房間列表 | `rooms_list` → 僅回傳給請求方 |

每則訊息結構：
```json
{
  "id": "uuid",
  "room": "general",
  "userId": 1,
  "username": "alice",
  "text": "哈囉大家好！",
  "createdAt": "2026-10-17T10:00:00.000Z"
}
```

### 5. 斷線處理

使用者斷線（`disconnect`）時，廣播 `user_left` 通知其所在的所有房間。

## 範例

```js
// ---- 客戶端連線（使用 socket.io-client）----
import { io } from 'socket.io-client';

const socket = io('http://localhost:3000', {
  auth: { token: 'eyJhbGci...' }  // JWT token
});

// 加入房間
socket.emit('join_room', { room: 'general' });

// 收到其他人加入
socket.on('user_joined', ({ username, room }) => {
  console.log(`${username} 加入了 ${room}`);
});

// 發送訊息
socket.emit('send_message', { room: 'general', text: '大家好！' });

// 收到新訊息
socket.on('new_message', (msg) => {
  console.log(`[${msg.room}] ${msg.username}: ${msg.text}`);
});

// 取得歷史訊息
socket.emit('get_history', { room: 'general' });
socket.on('message_history', (messages) => {
  messages.forEach(m => console.log(`${m.username}: ${m.text}`));
});
```

---

## 提示

- `socket.join(room)` 讓 socket 加入 Socket.io 的內建 Room，`io.to(room).emit(...)` 廣播給房間所有人
- 用 `socket.rooms` Set 追蹤使用者目前在哪些房間，斷線時遍歷它廣播離開通知
- 訊息存在記憶體 `Map<room, Message[]>` 即可；若想持久化，可用 `fs.appendFileSync` 寫入 JSONL 檔
- Socket.io middleware 的 `next(new Error(...))` 會觸發客戶端的 `connect_error` 事件
- 用 `socket.data.user` 儲存解出的使用者資訊，避免重複解析 token

## 學習重點（跟後端 API 的關聯）

| 本週技能 | 實際場景 |
|----------|----------|
| WebSocket 雙向通訊 | 即時通知（訂單狀態更新、股票報價）、線上協作工具 |
| Socket.io Room | 多租戶 SaaS 的頻道/對話隔離 |
| Socket 層 JWT 驗證 | 確保 WebSocket 連線與 HTTP API 使用相同的身份機制 |
| 事件驅動架構 | Node.js 的核心強項；大量並發連線時比 Thread-per-connection 省資源 |
| 斷線清理 | 生產環境必備：避免殭屍連線殘留、廣播錯誤的「在線」狀態 |

## 進階挑戰（選做）

1. **私人訊息**：新增 `send_dm` 事件，用 `io.to(socket.id).emit(...)` 對特定使用者發送私訊

5. **Jest 整合測試**：使用 `socket.io-client` 在測試中模擬多個使用者連線，驗證廣播行為
