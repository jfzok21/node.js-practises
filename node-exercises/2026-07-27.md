# 第 3 週今日 Node.js 練習題：非同步資料讀取器

## 題目說明

你需要撰寫一個工具，模擬從「資料庫」讀取使用者資料的非同步流程，並分別用三種方式實作：Callback、Promise、以及 async/await。這三種模式在後端開發中非常常見，是理解 Node.js 非同步行為的基礎。

## 技術要求
- 概念：Callback、Promise、async/await、錯誤處理
- 需要的套件：（無，純 Node.js 內建）

## 具體任務

1. **Callback 版本**：實作 `getUserById(id, callback)`，透過 `setTimeout` 模擬非同步查詢。若 id 為負數，回傳錯誤；否則回傳假資料。

2. **Promise 版本**：將上述邏輯包裝成 `getUserByIdPromise(id)`，回傳一個 `Promise`。

3. **async/await 版本**：使用 `async/await` 呼叫 Promise 版本，並用 `try/catch` 處理錯誤。

4. **串接查詢**：模擬「先取得使用者，再取得其訂單」的兩步驟非同步流程（用 Promise chain 或 async/await 皆可）。

## 範例

```js
// --- Callback 版本 ---
function getUserById(id, callback) {
  setTimeout(() => {
    if (id < 0) {
      callback(new Error('Invalid user ID'), null);
    } else {
      callback(null, { id, name: `User_${id}`, email: `user${id}@example.com` });
    }
  }, 500);
}

// 呼叫方式
getUserById(1, (err, user) => {
  if (err) {
    console.error('Error:', err.message);
  } else {
    console.log('User:', user);
  }
});

// --- Promise 版本 ---
function getUserByIdPromise(id) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (id < 0) {
        reject(new Error('Invalid user ID'));
      } else {
        resolve({ id, name: `User_${id}`, email: `user${id}@example.com` });
      }
    }, 500);
  });
}

// --- async/await 版本 ---
async function main() {
  try {
    const user = await getUserByIdPromise(42);
    console.log('User:', user);

    const orders = await getOrdersByUserId(user.id); // 你自己實作這個
    console.log('Orders:', orders);
  } catch (err) {
    console.error('Error:', err.message);
  }
}

main();
```

## 提示
- `setTimeout(fn, ms)` 是模擬非同步延遲的常用技巧，正式環境中會換成真實的 DB query。
- Callback 的第一個參數慣例是 `err`（Error-first Callback）。
- Promise 的 `.then()` 可以串接，`.catch()` 統一捕捉錯誤。
- `async` 函式永遠回傳 Promise，`await` 必須在 `async` 函式內使用。
- 試著故意傳入 `-1` 讓錯誤路徑被觸發，確認你的錯誤處理有效。

## 學習重點（跟後端 API 的關聯）

在真實的 Express API 中，幾乎每一個路由都是非同步的——查資料庫、呼叫第三方 API、讀取檔案，全都需要非同步處理。現代 Node.js 後端幾乎全面採用 `async/await`，因為它讓程式碼更接近同步寫法，大幅降低「Callback Hell」的問題。掌握這三種模式，你才能讀懂並維護各年代的 Node.js 程式碼。
