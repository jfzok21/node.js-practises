# 第 21 週今日 Node.js 練習題：WebSocket 即時聊天室 API

## 題目說明

建立一個支援即時雙向通訊的聊天室伺服器。使用者可以加入不同的聊天室頻道，發送訊息並即時接收其他成員的訊息。這是現代 Web 應用中非常常見的功能，例如 Slack、Discord 或客服系統都仰賴類似架構。

## 技術要求
- 概念：WebSocket 協定、事件驅動架構、房間管理、廣播訊息
- 需要的套件：`ws`（或 `socket.io`）、`express`、`uuid`

## 具體任務

1. **初始化專案**
   - `npm init -y`
   - 安裝 `ws` 與 `express`
   - 建立一個 Express HTTP 伺服器，並在同一個 port 上附掛 WebSocket 伺服器

2. **實作伺服器端房間邏輯**
   - 維護一個 `rooms` Map：`roomName → Set<WebSocket client>`
   - 當收到 `join` 事件時，將該連線加入指定房間
   - 當收到 `message` 事件時，廣播給同房間的所有其他成員
   - 當連線斷開時，自動從所有房間移除

3. **定義訊息協定（JSON 格式）**
   ```
   客戶端 → 伺服器：
   { "type": "join",    "room": "general", "username": "Alice" }
   { "type": "message", "room": "general", "text": "Hello!" }

   伺服器 → 客戶端：
   { "type": "joined",   "room": "general", "username": "Alice" }
   { "type": "message",  "room": "general", "username": "Bob", "text": "Hi!", "timestamp": "..." }
   { "type": "left",     "room": "general", "username": "Alice" }
   ```

4. **HTTP REST 端點（Express）**
   - `GET /rooms` — 回傳目前所有房間及各自的線上人數
   - `GET /rooms/:name/history` — 回傳最近 50 則訊息（先用記憶體儲存即可）

5. **錯誤處理**
   - 收到不合法的 JSON 時，回傳 `{ "type": "error", "message": "Invalid JSON" }`
   - 嘗試在未 join 的情況下發送訊息時，回傳對應錯誤

## 提示
- `WebSocket.Server` 可以直接傳入 `{ server }` 和 HTTP server 共用同一個 port
- 廣播時記得跳過發送者自己：`if (client !== ws && client.readyState === WebSocket.OPEN)`
- `ws.send()` 只接受字串或 Buffer，記得 `JSON.stringify`
- 每個房間的 Set 裡可以存物件 `{ ws, username }` 方便取用名稱
- 歷史訊息可以用陣列 `push` 並用 `slice(-50)` 保留最後 50 則

## 學習重點（跟後端 API 的關聯）

| 概念 | WebSocket 中的應用 | REST API 中的對應 |
|------|-------------------|-----------------|
| 雙向通訊 | 伺服器可主動推送 | 只能客戶端主動請求 |
| 長連線 | 連線一直保持 | 每次 request 新開 |
| 廣播 | 一對多推送 | 無直接對應（需 SSE / polling） |
| 房間邏輯 | 訂閱／取消訂閱 | 類似 filter 查詢 |

實際產品中，WebSocket 通常與 REST API 並存：REST 負責資料 CRUD，WebSocket 負責即時事件推送（例如通知、訊息、狀態更新）。

## 進階挑戰（選做）

1. **心跳機制**：每 30 秒向客戶端發送 `ping`，若無 `pong` 回應則斷開連線，防止殭屍連線佔用資源
2. **私訊功能**：加入 `{ "type": "dm", "to": "Bob", "text": "..." }` 訊息類型，只發給指定使用者
3. **頻道密碼**：建立房間時可設定密碼，join 時需驗證
4. **整合 JWT**：用 `Authorization` header 或 WebSocket 連線 URL 的 query string 傳遞 JWT token 驗證身份（延伸前幾週的 JWT 練習）
