# 第 4 週今日 Node.js 練習題：打造簡易 HTTP 伺服器與路由系統

## 題目說明

使用 Node.js 內建的 `http` 模組，從零開始建立一個 HTTP 伺服器，並手動實作基本的路由分發邏輯。這是後端 API 開發的基礎——在使用 Express 等框架之前，先理解「底層到底在做什麼」。

---

## 技術要求

- **概念**：`http.createServer`、`req.url`、`req.method`、`res.writeHead`、`res.end`、路由分發
- **需要的套件**：無（只用 Node.js 內建模組）

---

## 具體任務

1. 建立一個 `server.js`，使用 `http.createServer` 啟動伺服器，監聽 `3000` 埠。
2. 實作以下四個路由（根據 `req.url` 與 `req.method` 分發）：
   - `GET /` → 回傳 `{ message: "歡迎使用我的 API" }`
   - `GET /health` → 回傳 `{ status: "ok", uptime: <伺服器已運行秒數> }`
   - `GET /echo?text=xxx` → 解析 query string，回傳 `{ echo: "xxx" }`
   - `POST /greet` → 讀取 request body（JSON），回傳 `{ greeting: "哈囉，[name]！" }`
3. 所有回應都必須設定 `Content-Type: application/json`，並使用正確的 HTTP 狀態碼。
4. 未匹配的路由一律回傳 `404` 與 `{ error: "找不到此路由" }`。
5. 將伺服器的啟動時間記錄在變數中，讓 `/health` 可以計算 uptime。

---

## 範例

```js
// 啟動伺服器後，用 curl 測試：

// GET /
// → 200 { "message": "歡迎使用我的 API" }

// GET /health
// → 200 { "status": "ok", "uptime": 42 }   ← 單位：秒

// GET /echo?text=HelloWorld
// → 200 { "echo": "HelloWorld" }

// POST /greet，body: { "name": "小明" }
// → 200 { "greeting": "哈囉，小明！" }

// GET /unknown
// → 404 { "error": "找不到此路由" }
```

### 讀取 POST body 的骨架

```js
const http = require('http');
const { URL } = require('url');

const startTime = Date.now();

const server = http.createServer((req, res) => {
  const baseUrl = `http://localhost:3000`;
  const parsedUrl = new URL(req.url, baseUrl);
  const pathname = parsedUrl.pathname;

  // 工具函式：回傳 JSON
  const sendJSON = (statusCode, data) => {
    res.writeHead(statusCode, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify(data));
  };

  // 工具函式：讀取 request body
  const readBody = () =>
    new Promise((resolve) => {
      let body = '';
      req.on('data', (chunk) => (body += chunk));
      req.on('end', () => resolve(body));
    });

  // TODO: 根據 pathname 與 req.method 實作路由
});

server.listen(3000, () => console.log('伺服器已啟動：http://localhost:3000'));
```

---

## 提示

- `URL` 類別可以方便地解析 query string：`parsedUrl.searchParams.get('text')`
- 讀取 POST body 需要監聽 `req` 的 `data` 與 `end` 事件，因為資料是以串流方式傳入。
- `uptime` 計算方式：`Math.floor((Date.now() - startTime) / 1000)`（秒）。
- 使用 `curl -X POST -H "Content-Type: application/json" -d '{"name":"小明"}' http://localhost:3000/greet` 來測試 POST 路由。
- 記得先 `JSON.parse` 收到的 body 字串，再取裡面的欄位。

---

## 學習重點

**與後端 API 的關聯：**

這個練習直接對應了任何後端框架的核心機制：
- **路由分發**：Express 的 `app.get('/path', handler)` 底層就是對 `req.url` 和 `req.method` 做比對，和你手寫的邏輯完全一樣。
- **中介層（Middleware）概念**：`readBody()` 的模式就是 Express `express.json()` middleware 在做的事情。
- **HTTP 狀態碼**：200（成功）、404（找不到）是 REST API 設計的基礎語言。
- **JSON 作為資料交換格式**：現代 REST API 幾乎全部使用 JSON，`JSON.stringify` / `JSON.parse` 是必備技能。

掌握原生 `http` 模組後，下週學 Express 時你會清楚地看到框架幫你省掉了哪些重複的樣板程式碼。

## 進階挑戰（選做）

1. **方法驗證**：如果用 `POST` 打 `/`，回傳 `405 Method Not Allowed`。
2. **錯誤處理**：如果 `POST /greet` 的 body 不是合法 JSON，回傳 `400 Bad Request` 與清楚的錯誤訊息。
3. **路由模組化**：將路由邏輯抽取到 `routes.js`，在 `server.js` 中 `require` 進來，保持程式碼整潔。
4. **簡易 Logger**：每次收到請求時，在終端機印出 `[時間] METHOD /path` 格式的日誌。
