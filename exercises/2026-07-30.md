# 第 4 週今日練習題：Express Middleware 全攻略

## 題目說明

本週的主軸是 Express.js 的 **Middleware（中介軟體）** 機制。Middleware 是 Express 架構的核心，所有請求在抵達路由處理函式之前，都會依序經過一連串的 middleware。理解並善用 middleware，能讓你的程式碼更模組化、更容易維護。

今天的練習將帶你從零開始，建立一個具備完整 middleware 架構的 Express 應用程式。

---

## 技術要求

- **Express.js**：自訂 middleware、內建 middleware（`express.json()`、`express.urlencoded()`）、第三方 middleware（`morgan`）、全域與路由層級 middleware、錯誤處理 middleware
- **PostgreSQL**：記錄每次 API 請求的 log（請求時間、路由、方法、狀態碼）

---

## 具體任務

### 任務一：建立自訂 Logger Middleware

1. 建立一個 middleware 函式 `requestLogger`，在每次收到請求時，於 console 印出：
   ```
   [2026-07-30T12:00:00.000Z] GET /api/users - 200
   ```
2. 將此 middleware 掛載至全域（`app.use(requestLogger)`），讓所有路由都會觸發它。
3. 在 response 送出後，計算並印出本次請求的處理時間（毫秒）。

**提示**：使用 `res.on('finish', callback)` 事件可以在 response 送出後取得狀態碼。

---

### 任務二：建立身份驗證 Middleware（模擬版）

1. 建立 `authMiddleware`，檢查請求 header 是否包含 `Authorization: Bearer <token>`。
2. 若 token 為字串 `"secret-token"`，呼叫 `next()` 繼續處理；否則回傳 HTTP 401：
   ```json
   { "error": "Unauthorized", "message": "無效的 token" }
   ```
3. 只將此 middleware 套用在 `/api/protected` 路由群組，公開路由不受影響。

---

### 任務三：全域錯誤處理 Middleware

1. 建立一個符合 Express 錯誤處理簽名的 middleware（四個參數：`err, req, res, next`）。
2. 將其掛載在所有路由**之後**（`app.use(errorHandler)`）。
3. 當任何路由呼叫 `next(error)` 時，此 middleware 應回傳 HTTP 500（或 `err.status`）：
   ```json
   {
     "error": "Internal Server Error",
     "message": "錯誤訊息內容"
   }
   ```
4. 在開發模式下（`NODE_ENV=development`），額外回傳 `stack` 欄位方便除錯。

---

### 任務四：將請求 Log 寫入 PostgreSQL

1. 建立資料表：
   ```sql
   CREATE TABLE IF NOT EXISTS request_logs (
     id SERIAL PRIMARY KEY,
     method VARCHAR(10),
     path TEXT,
     status_code INTEGER,
     duration_ms INTEGER,
     created_at TIMESTAMPTZ DEFAULT NOW()
   );
   ```
2. 修改 `requestLogger` middleware，在 response 完成後，將每筆請求資料非同步寫入 `request_logs`。
3. 新增路由 `GET /api/logs`，查詢並回傳最近 20 筆 log 紀錄（按 `created_at` 降冪排序）。

---

### 任務五：整合所有 middleware

依照以下順序組裝你的 Express 應用程式：

```
morgan('dev')          ← 第三方 logger（npm install morgan）
express.json()         ← 解析 JSON request body
express.urlencoded()   ← 解析表單資料
requestLogger          ← 自訂 logger（含 DB 寫入）
公開路由（/api/health、/api/logs）
authMiddleware         ← 驗證 middleware
受保護路由（/api/protected）
404 處理（app.use → next(new Error('Not Found'))）
errorHandler           ← 錯誤處理 middleware（最後掛載）
```

---

## 提示

- Middleware 的**順序非常重要**，Express 會依照 `app.use()` 的呼叫順序逐一執行。
- 錯誤處理 middleware 的函式簽名必須有四個參數 `(err, req, res, next)`，少一個 Express 就不會將它識別為錯誤處理 middleware。
- `next()` 代表「交給下一個 middleware」，`next(err)` 代表「發生錯誤，跳到錯誤處理 middleware」。
- 寫入 DB 的操作不要用 `await` 阻塞 response，讓它在背景執行（fire-and-forget）或使用 `.catch()` 處理錯誤即可。
- 可用 `curl` 或 Postman 測試：
  ```bash
  # 測試公開路由
  curl http://localhost:3000/api/health

  # 測試受保護路由（無 token）
  curl http://localhost:3000/api/protected/data

  # 測試受保護路由（有 token）
  curl -H "Authorization: Bearer secret-token" http://localhost:3000/api/protected/data
  ```

## 進階挑戰（選做）

1. **Rate Limiting**：使用 `express-rate-limit` 套件，限制同一 IP 每分鐘最多發送 30 次請求，超過後回傳 HTTP 429。

2. **CORS Middleware**：手動實作一個 CORS middleware（不用 `cors` 套件），設定允許的來源、方法與 headers，並正確處理 `OPTIONS` preflight 請求。

3. **請求 ID**：替每個請求生成唯一的 UUID（可用 `crypto.randomUUID()`），附加至 `req.id`，並在回應 header 中加上 `X-Request-Id`，方便追蹤問題。

4. **Log 分析路由**：新增 `GET /api/logs/stats`，查詢各路由的平均回應時間與請求次數，回傳類似以下的統計資料：
   ```json
   [
     { "path": "/api/protected/data", "count": 42, "avg_duration_ms": 15 },
     { "path": "/api/health", "count": 120, "avg_duration_ms": 3 }
   ]
   ```
