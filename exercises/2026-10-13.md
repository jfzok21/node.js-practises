# 第 14 週今日練習題：任務管理 API 實戰專案（Task Manager API）

## 題目說明

綜合前 13 週所學，建立一個完整的「任務管理系統」RESTful API。此專案需整合 Express 路由設計、PostgreSQL CRUD、JWT 身份驗證、資料驗證、分頁排序、交易處理及 API 測試，模擬真實工作情境。

---

## 技術要求

- **Express.js**：RESTful 路由設計、自訂 Middleware、錯誤處理
- **PostgreSQL**：多資料表設計（users、projects、tasks）、JOIN 查詢、Transaction
- **JWT**：Bearer Token 身份驗證與授權
- **Validation**：輸入驗證與結構化錯誤回應
- **Pagination**：分頁與多欄位排序
- **Testing**：supertest + Jest 撰寫整合測試

---

## 具體任務

### 1. 資料庫設計

建立以下三張資料表：

```sql
-- 使用者
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  name VARCHAR(100) NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 專案
CREATE TABLE projects (
  id SERIAL PRIMARY KEY,
  name VARCHAR(200) NOT NULL,
  description TEXT,
  owner_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 任務
CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  title VARCHAR(200) NOT NULL,
  description TEXT,
  status VARCHAR(20) DEFAULT 'todo' CHECK (status IN ('todo', 'in_progress', 'done')),
  priority INTEGER DEFAULT 3 CHECK (priority BETWEEN 1 AND 5),
  due_date DATE,
  project_id INTEGER REFERENCES projects(id) ON DELETE CASCADE,
  assignee_id INTEGER REFERENCES users(id) ON DELETE SET NULL,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

### 2. 身份驗證路由

| 方法 | 路徑 | 說明 |
|------|------|------|
| POST | `/api/auth/register` | 註冊新使用者（bcrypt 雜湊密碼） |
| POST | `/api/auth/login` | 登入，回傳 JWT Token |
| GET  | `/api/auth/me` | 取得目前登入使用者資訊（需 Token） |

### 3. 專案路由（需登入）

| 方法 | 路徑 | 說明 |
|------|------|------|
| GET    | `/api/projects` | 列出目前使用者擁有的所有專案 |
| POST   | `/api/projects` | 建立新專案 |
| GET    | `/api/projects/:id` | 取得單一專案（含任務統計） |
| PUT    | `/api/projects/:id` | 更新專案（僅限 owner） |
| DELETE | `/api/projects/:id` | 刪除專案及其所有任務（Transaction） |

### 4. 任務路由（需登入）

| 方法 | 路徑 | 說明 |
|------|------|------|
| GET    | `/api/projects/:projectId/tasks` | 列出專案任務（支援分頁、依 priority/due_date 排序、依 status 篩選） |
| POST   | `/api/projects/:projectId/tasks` | 新增任務 |
| GET    | `/api/projects/:projectId/tasks/:id` | 取得單一任務 |
| PUT    | `/api/projects/:projectId/tasks/:id` | 更新任務（含狀態變更） |
| DELETE | `/api/projects/:projectId/tasks/:id` | 刪除任務 |

### 5. 任務統計路由

```
GET /api/projects/:id/stats
```

回應範例：
```json
{
  "total": 10,
  "by_status": { "todo": 4, "in_progress": 3, "done": 3 },
  "overdue": 2,
  "avg_priority": 2.7
}
```

### 6. 批次狀態更新（Transaction）

```
PATCH /api/projects/:projectId/tasks/bulk-status
Body: { "task_ids": [1, 2, 3], "status": "done" }
```

使用 Transaction 確保批次更新的原子性，並在 Transaction 內記錄每筆更新的 `updated_at`。

### 7. 撰寫整合測試

使用 supertest + Jest 為以下情境撰寫測試：
- 未登入時存取受保護路由應回傳 401
- 登入流程（register → login → 取得 Token）
- 建立專案並新增任務
- 分頁查詢任務（驗證 `total`、`page`、`per_page`、`data` 欄位）
- 刪除專案後確認任務一併刪除

---

## 提示

- 使用 `bcryptjs` 雜湊密碼，避免明文儲存
- JWT 有效期設為 1 天（`expiresIn: '1d'`）
- 分頁查詢使用 `LIMIT $1 OFFSET $2`，並在 response 中回傳 `{ total, page, per_page, data }`
- 刪除專案時，用 `BEGIN / COMMIT / ROLLBACK` 確保 Transaction 完整
- 建議專案結構：

```
src/
  routes/       # auth.js, projects.js, tasks.js
  middleware/   # auth.js (JWT 驗證), errorHandler.js
  db/           # pool.js (pg Pool 設定)
  app.js
tests/
  auth.test.js
  tasks.test.js
```

- 統一錯誤回應格式：
```json
{ "error": "訊息描述", "field": "欄位名稱（選填）" }
```

## 進階挑戰（選做）

1. **軟刪除（Soft Delete）**：為 tasks 加入 `deleted_at` 欄位，刪除時只更新該欄位，查詢時加入 `WHERE deleted_at IS NULL`
2. **稽核日誌**：建立 `task_logs` 資料表，在每次任務狀態變更時（觸發器或 Middleware）自動記錄舊值、新值與操作使用者
3. **全文搜尋**：使用 `ILIKE` 或 PostgreSQL `tsvector` 實作任務標題關鍵字搜尋
4. **Rate Limiting**：使用 `express-rate-limit` 限制登入 API 每 IP 每分鐘最多 5 次請求
