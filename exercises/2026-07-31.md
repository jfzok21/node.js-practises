# 第 4 週今日練習題：Express Middleware 中介層實作

## 題目說明

中介層（Middleware）是 Express.js 的核心概念，幾乎所有進階功能都建立在此之上。本題將帶你從頭實作三種常見的 Middleware：自訂 Logger、body-parser 解析請求主體，以及統一的錯誤處理機制。

## 技術要求

- **Express.js**：使用 `app.use()` 掛載 Middleware，理解 `next()` 的觸發流程
- **PostgreSQL**：建立 `request_logs` 資料表，將每次請求紀錄存入資料庫

## 具體任務

1. **建立 Logger Middleware**
   - 每次收到 HTTP 請求時，記錄以下資訊：
     - 請求時間（timestamp）
     - HTTP 方法（method）
     - 請求路徑（path）
     - 回應狀態碼（status code）
   - 將上述資訊以 `INSERT` 存入 PostgreSQL 的 `request_logs` 資料表
   - 資料表結構如下：
     ```sql
     CREATE TABLE request_logs (
       id SERIAL PRIMARY KEY,
       method VARCHAR(10),
       path TEXT,
       status_code INTEGER,
       created_at TIMESTAMP DEFAULT NOW()
     );
     ```

2. **整合 body-parser（或 Express 內建 JSON 解析）**
   - 使用 `express.json()` 與 `express.urlencoded({ extended: true })` 掛載至全域
   - 建立 `POST /users` 路由，接收 `{ name, email }` 並回傳 `201 Created` 及資料內容

3. **實作自訂錯誤處理 Middleware**
   - 在所有路由之後，加上一個四參數的錯誤處理函式 `(err, req, res, next)`
   - 若錯誤物件有 `statusCode` 屬性，使用它作為 HTTP 狀態碼；否則預設回傳 `500`
   - 回傳 JSON 格式：`{ "error": "錯誤訊息" }`
   - 建立 `GET /trigger-error` 路由，刻意呼叫 `next(new Error('測試錯誤'))` 來驗證錯誤流程

4. **驗證 Middleware 執行順序**
   - 在你的 Logger Middleware 中加入 `console.log('Logger 執行')`
   - 在路由處理函式中加入 `console.log('路由執行')`
   - 送出請求後觀察 console 輸出，確認順序為 Logger → 路由 → 回應

## 提示

- `app.use()` 掛載的順序就是執行順序，Logger 必須放在路由宣告之前
- 錯誤處理 Middleware 必須放在**所有路由之後**，且函式參數一定要有四個（包含 `err`）
- 在 Logger Middleware 中若想取得回應的 status code，可監聽 `res.on('finish', callback)`，因為 Middleware 執行時 status code 尚未決定
- `next(err)` 與 `next()` 行為不同：傳入參數會跳過一般 Middleware，直接進入錯誤處理 Middleware
- PostgreSQL 連線建議使用 `pg` 套件的 `Pool`，避免每次請求都建立新連線

## 進階挑戰（選做）

- 為 Logger Middleware 加入「排除清單」，讓 `GET /health` 這類健康檢查路由不被記錄
- 實作一個「請求逾時 Middleware」：若路由超過 5 秒未回應，自動回傳 `503 Service Unavailable`
- 使用 `morgan` 套件取代手寫 Logger，比較兩者的差異與優缺點
- 在錯誤處理 Middleware 中，根據錯誤類型（`ValidationError`、`DatabaseError` 等）回傳不同的 HTTP 狀態碼
