# 第 14 週今日練習題：任務管理 REST API 實戰專案（Task Manager API）

## 題目說明

綜合前 13 週所有技術，建構一個具備完整功能的任務管理 API。此專案要求你將 Express 路由、PostgreSQL CRUD、身份驗證、資料驗證、分頁、JOIN 查詢以及交易處理整合成一個可上線運行的後端服務。

---

## 技術要求

- **Express.js**：模組化路由（`/auth`、`/users`、`/projects`、`/tasks`）、全域錯誤處理 Middleware
- **PostgreSQL**：多資料表設計（users / projects / tasks / tags），JOIN 查詢，Transaction 確保資料一致性
- **JWT**：登入後發放 Token，受保護路由需驗證
- **資料驗證**：所有輸入欄位需驗證（必填、型別、長度限制）
- **分頁與排序**：`GET /tasks` 支援 `?page=`、`?limit=`、`?sort=`、`?order=`
- **搜尋**：`GET /tasks?search=` 對標題與描述做模糊搜尋

---

## 具體任務

1. **資料庫設計**
   - 建立 `users` 資料表（id, username, email, password_hash, created_at）
   - 建立 `projects` 資料表（id, name, description, owner_id FK→users, created_at）
   - 建立 `tasks` 資料表（id, title, description, status ENUM('todo','in_progress','done'), priority INT 1–5, project_id FK→projects, assignee_id FK→users, due_date, created_at, updated_at）
   - 建立 `tags` 資料表（id, name）與 `task_tags` 中介表（task_id, tag_id）

2. **身份驗證**
   - `POST /auth/register`：注冊帳號（bcrypt 雜湊密碼）
   - `POST /auth/login`：驗證帳密，回傳 JWT（有效期 7 天）

3. **任務 CRUD**
   - `GET /tasks`：取得任務列表，支援分頁、排序、狀態篩選（`?status=todo`）及關鍵字搜尋
   - `POST /tasks`：建立任務，同時在 Transaction 中附加標籤（task_tags）
   - `GET /tasks/:id`：取得單一任務，JOIN 取出 assignee username 及所有標籤名稱
   - `PATCH /tasks/:id`：部分更新任務（狀態、優先度、到期日）
   - `DELETE /tasks/:id`：刪除任務，Transaction 中同時清除 task_tags 關聯

4. **專案管理**
   - `POST /projects`：建立專案（需登入）
   - `GET /projects/:id/tasks`：取得某專案下的所有任務，含分頁

5. **錯誤處理**
   - 統一錯誤格式：`{ "error": "訊息", "code": "ERROR_CODE" }`
   - 404 Not Found、401 Unauthorized、422 Validation Error 各自回傳對應 HTTP 狀態碼

---

## 提示

- 使用 `pg` 套件的 `pool.connect()` → `client.query()` → `client.release()` 進行 Transaction
- 分頁公式：`LIMIT $1 OFFSET $2`，offset = (page - 1) * limit
- JWT Middleware 可抽成獨立的 `middleware/auth.js`，在需要保護的路由上 `router.use(authMiddleware)`
- 標籤更新建議先 `DELETE FROM task_tags WHERE task_id=$1` 再重新 INSERT，包在同一個 Transaction 中
- 密碼雜湊使用 `bcrypt.hash(password, 10)`，驗證使用 `bcrypt.compare()`

---

## 進階挑戰（選做）

- **軟刪除**：tasks 加入 `deleted_at` 欄位，DELETE 改為 `UPDATE tasks SET deleted_at=NOW()`，所有查詢加上 `WHERE deleted_at IS NULL`
- **活動紀錄**：建立 `task_activities` 資料表，每次狀態變更自動 INSERT 一筆紀錄（可用 PostgreSQL Trigger 或在 PATCH 路由中處理）
- **統計端點**：`GET /projects/:id/stats` 回傳各狀態任務數量與平均優先度（使用 GROUP BY）
- **supertest 測試**：為 `POST /auth/register` 及 `GET /tasks` 各撰寫至少 3 個測試案例
