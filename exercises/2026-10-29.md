# 第 17 週今日練習題：任務管理 API 系統（Task Management API）

## 題目說明

建立一個完整的任務管理 RESTful API 系統，整合前幾週所學的 Express.js 與 PostgreSQL 技術，包含使用者認證、任務 CRUD、分類標籤、分頁查詢及資料驗證。這是一個接近真實工作場景的實戰練習。

## 技術要求

- **Express.js**：路由組織（Router）、Middleware 鏈、全域錯誤處理、JWT 身份驗證
- **PostgreSQL**：多資料表設計（users、tasks、tags、task_tags）、JOIN 查詢、交易處理、索引優化

## 資料庫結構

```sql
-- 使用者表
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 任務表
CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  title VARCHAR(255) NOT NULL,
  description TEXT,
  status VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending', 'in_progress', 'done')),
  priority INTEGER DEFAULT 3 CHECK (priority BETWEEN 1 AND 5),
  due_date DATE,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 標籤表
CREATE TABLE tags (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  name VARCHAR(50) NOT NULL,
  UNIQUE (user_id, name)
);

-- 任務標籤關聯表
CREATE TABLE task_tags (
  task_id INTEGER REFERENCES tasks(id) ON DELETE CASCADE,
  tag_id  INTEGER REFERENCES tags(id) ON DELETE CASCADE,
  PRIMARY KEY (task_id, tag_id)
);
```

## 具體任務

### 1. 專案初始化
- 建立專案目錄結構：`routes/`、`middleware/`、`db/`、`validators/`
- 安裝依賴：`express`、`pg`、`bcrypt`、`jsonwebtoken`、`joi`（或 `zod`）

### 2. 身份驗證 API
- `POST /api/auth/register`：註冊（email + password），密碼以 bcrypt 雜湊儲存
- `POST /api/auth/login`：登入，回傳 JWT token
- 撰寫 `authMiddleware`，驗證 Bearer token 並將 `req.user` 注入後續路由

### 3. 任務 CRUD API（需登入）
- `GET /api/tasks`：取得當前使用者的所有任務，支援：
  - 分頁：`?page=1&limit=10`
  - 篩選：`?status=pending`、`?priority=1`
  - 排序：`?sort=due_date&order=asc`
- `POST /api/tasks`：新增任務，驗證必填欄位
- `GET /api/tasks/:id`：取得單一任務（含標籤），確認屬於當前使用者
- `PUT /api/tasks/:id`：更新任務，自動更新 `updated_at`
- `DELETE /api/tasks/:id`：刪除任務（串聯刪除 task_tags）

### 4. 標籤管理 API（需登入）
- `POST /api/tasks/:id/tags`：為任務新增標籤（若標籤不存在則自動建立）
- `DELETE /api/tasks/:id/tags/:tagId`：移除任務的某個標籤

### 5. 資料驗證
- 使用 Joi 或 Zod 驗證所有請求 body
- 統一錯誤格式：`{ "error": "...", "details": [...] }`

### 6. 全域錯誤處理
- 撰寫 Express 錯誤處理 Middleware，捕捉 404 與所有未預期錯誤
- 區分開發模式（顯示 stack trace）與生產模式（隱藏細節）

## 提示

- 使用 `pg` 的 Pool 而非單一 Client，避免連線洩漏
- JWT secret 存放於環境變數 `JWT_SECRET`，不要寫死在程式碼中
- 新增/更新任務時，標籤的新增應包在同一個 Transaction 內
- `GET /api/tasks` 可使用 `COUNT(*) OVER()` 的視窗函數一次取得總筆數與分頁資料
- 建議在 `tasks.user_id`、`tasks.status`、`tasks.due_date` 欄位建立索引

## 進階挑戰（選做）

1. **軟刪除（Soft Delete）**：為 tasks 新增 `deleted_at` 欄位，刪除時僅設定時間戳，所有查詢自動過濾已刪除項目
2. **批次操作**：`PATCH /api/tasks/bulk`，一次更新多筆任務的狀態（使用 Transaction + `unnest`）
3. **統計端點**：`GET /api/tasks/stats`，回傳各狀態任務數量、本週到期任務數、平均優先度
4. **Rate Limiting**：使用 `express-rate-limit` 限制登入端點每分鐘最多 10 次請求
5. **API 測試**：使用 Jest + supertest 撰寫完整的 API 整合測試
