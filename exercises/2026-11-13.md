# 第 19 週今日練習題：電商優惠券系統實戰

## 題目說明

延續昨日的電商訂單管理系統，今天新增「優惠券（Coupon）」功能模組。實作優惠券建立、核銷、折扣計算，以及使用限制（次數上限、有效期限、最低消費門檻）。這是真實電商後端中常見的功能，同樣需要 Transaction 確保原子性。

## 技術要求

- **Express.js**：新增 `routes/coupons.js`、`controllers/couponController.js`，整合進既有 `app.js`
- **PostgreSQL**：新增 `coupons`、`coupon_usages` 資料表，並修改建立訂單的 Transaction 加入折扣計算
- **JWT**：管理員才能建立/停用優惠券；一般使用者僅能查詢與使用
- **Transaction**：使用優惠券時需原子性地核銷（更新使用次數）並建立訂單

## 資料庫 Schema

```sql
CREATE TABLE coupons (
  id SERIAL PRIMARY KEY,
  code VARCHAR(50) NOT NULL UNIQUE,
  description TEXT,
  discount_type VARCHAR(10) NOT NULL CHECK (discount_type IN ('percent', 'fixed')),
  discount_value NUMERIC(10,2) NOT NULL CHECK (discount_value > 0),
  min_order_amount NUMERIC(10,2) NOT NULL DEFAULT 0,
  max_uses INTEGER,                    -- NULL 表示無限制
  current_uses INTEGER NOT NULL DEFAULT 0,
  is_active BOOLEAN NOT NULL DEFAULT true,
  expires_at TIMESTAMP,                -- NULL 表示永不過期
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE coupon_usages (
  id SERIAL PRIMARY KEY,
  coupon_id INTEGER REFERENCES coupons(id) ON DELETE CASCADE,
  user_id INTEGER REFERENCES users(id) ON DELETE SET NULL,
  order_id INTEGER REFERENCES orders(id) ON DELETE SET NULL,
  discount_amount NUMERIC(10,2) NOT NULL,
  used_at TIMESTAMP DEFAULT NOW()
);

-- 在 orders 表新增欄位
ALTER TABLE orders
  ADD COLUMN coupon_id INTEGER REFERENCES coupons(id) ON DELETE SET NULL,
  ADD COLUMN discount_amount NUMERIC(10,2) NOT NULL DEFAULT 0;
```

## 具體任務

1. **管理員優惠券 CRUD**（需 JWT，且 `users.role = 'admin'`）
   - `POST /api/coupons`：建立優惠券，body 範例：
     ```json
     {
       "code": "SAVE100",
       "description": "滿 500 折 100",
       "discount_type": "fixed",
       "discount_value": 100,
       "min_order_amount": 500,
       "max_uses": 50,
       "expires_at": "2026-12-31T23:59:59Z"
     }
     ```
   - `GET /api/coupons`：列出所有優惠券（含使用次數統計）
   - `PATCH /api/coupons/:id/toggle`：啟用 / 停用優惠券

2. **使用者查詢優惠券**（需 JWT）
   - `GET /api/coupons/:code/check`：輸入 code 查詢優惠券是否有效，回傳：
     ```json
     {
       "valid": true,
       "code": "SAVE100",
       "discount_type": "fixed",
       "discount_value": 100,
       "min_order_amount": 500,
       "expires_at": "2026-12-31T23:59:59Z",
       "remaining_uses": 48
     }
     ```
     若無效則回傳對應錯誤（已過期 / 已停用 / 已達上限）

3. **整合優惠券到建立訂單**（修改 `POST /api/orders`）

   Request body 新增選填欄位：
   ```json
   {
     "items": [
       { "product_id": 1, "quantity": 2 }
     ],
     "coupon_code": "SAVE100",
     "note": "請用禮盒包裝"
   }
   ```

   Transaction 中在原有步驟之後新增：
   1. 若有 `coupon_code`，以 `SELECT ... FOR UPDATE` 鎖定該優惠券列
   2. 驗證優惠券有效性（`is_active`、`expires_at`、`current_uses < max_uses`、`total_amount >= min_order_amount`）
   3. 計算折扣金額：
      - `percent`：`total_amount * (discount_value / 100)`，結果無條件捨去至分（2 位小數）
      - `fixed`：直接減去 `discount_value`，折後金額不得低於 0
   4. 以折後金額寫入 `orders.total_amount`，同時記錄 `orders.discount_amount` 與 `orders.coupon_id`
   5. 在 `coupon_usages` 插入一筆使用記錄
   6. 更新 `coupons.current_uses = current_uses + 1`

4. **優惠券使用報表**（管理員端點）
   - `GET /api/coupons/:id/usages`：列出該優惠券的所有使用紀錄（含使用者 email、訂單 ID、折扣金額、使用時間），支援分頁

5. **統一驗證錯誤格式**，以下錯誤碼必須實作：
   | code | HTTP | 情境 |
   |------|------|------|
   | `COUPON_NOT_FOUND` | 404 | code 不存在 |
   | `COUPON_INACTIVE` | 400 | 已停用 |
   | `COUPON_EXPIRED` | 400 | 已過有效期 |
   | `COUPON_MAX_USES_REACHED` | 400 | 已達使用次數上限 |
   | `COUPON_MIN_AMOUNT_NOT_MET` | 400 | 未達最低消費門檻 |

## 提示

- `SELECT ... FOR UPDATE` 是防止並發超用優惠券的關鍵，不加鎖的話兩個請求可能同時通過「次數檢查」但各自 +1：
  ```sql
  SELECT * FROM coupons WHERE code = $1 FOR UPDATE
  ```
- Percent 折扣建議使用 PostgreSQL 的 `ROUND()` 避免浮點問題：
  ```sql
  ROUND(total_amount * (discount_value / 100.0), 2)
  ```
- 若優惠券無 `max_uses`（`NULL`），對應的 `remaining_uses` 可回傳 `null` 表示無限制
- 管理員角色判斷可抽成 middleware：
  ```js
  // middleware/requireAdmin.js
  module.exports = (req, res, next) => {
    if (req.user.role !== 'admin') {
      return res.status(403).json({ error: { code: 'FORBIDDEN', message: '需要管理員權限' } });
    }
    next();
  };
  ```

## 進階挑戰（選做）

- 加入「每位使用者僅限使用一次」的限制（在 `coupon_usages` 中查詢是否已有同一 `user_id` + `coupon_id` 的紀錄），並新增對應錯誤碼 `COUPON_ALREADY_USED`
- 為 `GET /api/coupons/:code/check` 與 `POST /api/orders`（含優惠券）撰寫 Jest + supertest 測試，涵蓋：
  - 優惠券過期應回傳 400
  - 未達最低消費應回傳 400
  - 並發建立兩筆訂單時 max_uses 應精確扣減（使用 `Promise.all` 模擬並發）
- 支援「百分比折扣上限」：例如 9 折但最多折 300 元，新增 `max_discount_amount` 欄位
