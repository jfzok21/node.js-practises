# 第 17 週今日練習題：任務管理 API 實戰專案（進階功能整合）

## 題目說明

建立一個具備完整 CRUD、身份驗證、分頁排序、資料驗證與錯誤處理的「任務管理 REST API」。本週將綜合前 16 週所學技術，打造一個接近生產環境水準的後端服務。

## 技術要求
- **Express.js**：路由參數、Query String、Middleware 鏈、全域錯誤處理
- **PostgreSQL**：多資料表（users、tasks、categories）、JOIN 查詢、Transaction、索引
- **JWT**：使用者註冊 / 登入、受保護路由
- **驗證**：joi 或 zod 進行請求體驗證
- **分頁與排序**：支援 `?page=`、`?limit=`、`?sort=`、`?order=`
- **錯誤回應**：統一格式 `{ success, message, errors? }`

## 具體任務

### 1. 資料庫設計
建立以下三張資料表：

```sql
-- 使用者
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(50) UNIQUE NOT NULL,
  email VARCHAR(100) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 分類
CREATE TABLE categories (
  id SERIAL PRIMARY KEY,
  name VARCHAR(50) NOT NULL,
  user_id INT REFERENCES users(id) ON DELETE CASCADE
);

-- 任務
CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  title VARCHAR(200) NOT NULL,
  description TEXT,
  status VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending','in_progress','done')),
  priority INT DEFAULT 1 CHECK (priority BETWEEN 1 AND 5),
  due_date DATE,
  user_id INT REFERENCES users(id) ON DELETE CASCADE,
  category_id INT REFERENCES categories(id) ON DELETE SET NULL,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 2. 身份驗證路由
- `POST /api/auth/register`：建立使用者（bcrypt 雜湊密碼）
- `POST /api/auth/login`：驗證後回傳 JWT

### 3. 任務 CRUD（需 JWT 驗證）
- `GET /api/tasks`：列出當前使用者的所有任務，支援：
  - `?status=pending|in_progress|done`
  - `?category_id=<id>`
  - `?sort=priority|due_date|created_at`（預設 `created_at`）
  - `?order=asc|desc`（預設 `desc`）
  - `?page=1&limit=10`
- `GET /api/tasks/:id`：取得單一任務（含分類名稱，用 JOIN）
- `POST /api/tasks`：建立任務
- `PUT /api/tasks/:id`：更新任務（Transaction 確保 `updated_at` 同步）
- `DELETE /api/tasks/:id`：刪除任務

### 4. 分類 CRUD（需 JWT 驗證）
- `GET /api/categories`
- `POST /api/categories`
- `DELETE /api/categories/:id`（連帶將任務的 category_id 設為 NULL）

### 5. 驗證規則（joi / zod）
- `register`：`username`（3~50字元英數）、`email`（合法格式）、`password`（至少 8 字元）
- `createTask`：`title` 必填（最長 200 字）、`priority`（1~5 整數）、`due_date`（合法日期，不得早於今天）

### 6. 全域錯誤處理 Middleware
```js
// 統一錯誤格式
app.use((err, req, res, next) => {
  const status = err.status || 500;
  res.status(status).json({
    success: false,
    message: err.message || 'Internal Server Error',
    errors: err.errors || undefined,
  });
});
```

## 提示
- 使用 `pg` 套件建立連線池（`Pool`），不要每次請求都建立新連線
- JWT Middleware 可設計成可選（public 路由跳過），用 `req.user` 傳遞已驗證使用者
- 分頁回應加上 `meta`：`{ total, page, limit, totalPages }`
- Transaction 寫法：`BEGIN` → 操作 → `COMMIT`，錯誤時 `ROLLBACK`

## 進階挑戰（選做）
1. **軟刪除**：替 tasks 加上 `deleted_at` 欄位，`DELETE` 只更新此欄位，查詢時加 `WHERE deleted_at IS NULL`
2. **統計端點**：`GET /api/tasks/stats` 回傳各狀態任務數量與逾期任務數（`due_date < NOW()`）
3. **Rate Limiting**：使用 `express-rate-limit` 限制登入端點每 IP 每 15 分鐘最多 10 次
4. **整合測試**：用 `supertest` + `Jest` 撰寫至少 5 個端對端測試案例
