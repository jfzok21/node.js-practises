# 第 13 週今日練習題：部落格 API 實戰專案

## 題目說明

建立一個完整的部落格後端 API，整合前幾週所學的所有技術：Express 路由、PostgreSQL CRUD、Middleware、JWT 身份驗證、資料驗證、分頁排序與交易處理。這是一個接近真實產品的全端練習，讓你將各個技術點整合成一個可運作的系統。

## 技術要求

- **Express.js**：RESTful API 設計、路由分層（router）、Middleware 鏈、錯誤處理中介層
- **PostgreSQL**：多資料表設計（users、posts、comments）、JOIN 查詢、Transaction（刪除文章時同步刪除留言）
- **身份驗證**：JWT（登入取得 token、受保護路由需帶 Bearer token）
- **資料驗證**：輸入欄位驗證（標題不得空白、內容長度限制等）
- **分頁**：文章列表支援 `?page=1&limit=10&sort=created_at&order=DESC`

## 具體任務

### 1. 資料庫設計

建立以下三張資料表：

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(50) UNIQUE NOT NULL,
  email VARCHAR(100) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE posts (
  id SERIAL PRIMARY KEY,
  title VARCHAR(200) NOT NULL,
  content TEXT NOT NULL,
  author_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE comments (
  id SERIAL PRIMARY KEY,
  post_id INTEGER REFERENCES posts(id) ON DELETE CASCADE,
  author_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  content TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);
```

### 2. 實作 API 端點

**認證路由 `/api/auth`（不需要 JWT）：**
- `POST /api/auth/register`：註冊（username、email、password）
- `POST /api/auth/login`：登入，回傳 JWT token

**文章路由 `/api/posts`：**
- `GET /api/posts`：取得所有文章（支援分頁與排序，JOIN users 顯示作者名稱）
- `GET /api/posts/:id`：取得單篇文章（含留言列表與作者資訊）
- `POST /api/posts`：新增文章（需要 JWT）
- `PUT /api/posts/:id`：修改文章（需要 JWT，且只有作者本人可修改）
- `DELETE /api/posts/:id`：刪除文章（需要 JWT，使用 Transaction 一併刪除留言）

**留言路由 `/api/posts/:postId/comments`：**
- `POST /api/posts/:postId/comments`：新增留言（需要 JWT）
- `DELETE /api/posts/:postId/comments/:commentId`：刪除留言（需要 JWT，只有留言作者可刪除）

### 3. 實作 Middleware

- `authMiddleware`：驗證 JWT，將使用者資訊注入 `req.user`
- `validatePost`：驗證文章輸入（title 必填且 ≤ 200 字，content 必填）
- `errorHandler`：統一錯誤回應格式 `{ error: "訊息", code: "ERROR_CODE" }`

### 4. 統一回應格式

成功回應：
```json
{ "success": true, "data": { ... } }
```
分頁列表：
```json
{
  "success": true,
  "data": [...],
  "pagination": { "page": 1, "limit": 10, "total": 42, "totalPages": 5 }
}
```
錯誤回應：
```json
{ "success": false, "error": "文章不存在", "code": "NOT_FOUND" }
```

### 5. 專案結構

建議以下目錄結構：

## 提示

- 密碼使用 `bcrypt`（`bcryptjs`）雜湊，不可明文儲存
- JWT secret 放在 `.env`，使用 `jsonwebtoken` 套件
- 刪除文章時使用 `BEGIN / COMMIT / ROLLBACK` 包裹交易，確保資料一致性
- 分頁查詢：`LIMIT $1 OFFSET $2`，offset = (page - 1) * limit
- 更新文章時記得同步更新 `updated_at = NOW()`
- 使用 `pg` 的 parameterized query 防止 SQL Injection

## 進階挑戰（選做）

1. **文章搜尋**：新增 `GET /api/posts?search=關鍵字`，使用 `ILIKE '%關鍵字%'` 搜尋標題與內容
2. **文章標籤**：建立 `tags` 資料表與多對多關聯，支援 `POST /api/posts/:id/tags`
3. **圖片上傳**：整合 `multer`，讓文章可附加封面圖片
4. **Rate Limiting**：使用 `express-rate-limit` 限制登入端點每分鐘最多 5 次，防止暴力破解
5. **API 文件**：使用 `swagger-ui-express` 或手寫 `README.md` 記錄所有端點規格
