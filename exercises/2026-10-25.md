# 第 16 週今日練習題：電商購物車系統 REST API

## 題目說明

建立一個「電商購物車系統（E-commerce Shopping Cart API）」。
本題聚焦於購物情境的業務邏輯：商品庫存管理、購物車操作、訂單建立與 Transaction 保護，模擬真實電商後端開發。

## 技術要求

- **Express.js**：路由模組化（Router）、JWT 身份驗證 Middleware、全域錯誤處理
- **PostgreSQL**：多資料表設計、庫存鎖定查詢（`SELECT ... FOR UPDATE`）、Transaction

## 資料庫 Schema

```sql
-- 使用者
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  name VARCHAR(100) NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 商品分類
CREATE TABLE categories (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) UNIQUE NOT NULL
);

-- 商品
CREATE TABLE products (
  id SERIAL PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  description TEXT,
  price NUMERIC(10, 2) NOT NULL CHECK (price >= 0),
  stock INTEGER NOT NULL DEFAULT 0 CHECK (stock >= 0),
  category_id INTEGER REFERENCES categories(id) ON DELETE SET NULL,
  image_url TEXT,
  is_active BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 購物車
CREATE TABLE carts (
  id SERIAL PRIMARY KEY,
  user_id INTEGER UNIQUE REFERENCES users(id) ON DELETE CASCADE,
  updated_at TIMESTAMP DEFAULT NOW()
);

-- 購物車項目
CREATE TABLE cart_items (
  id SERIAL PRIMARY KEY,
  cart_id INTEGER REFERENCES carts(id) ON DELETE CASCADE,
  product_id INTEGER REFERENCES products(id) ON DELETE CASCADE,
  quantity INTEGER NOT NULL CHECK (quantity > 0),
  UNIQUE (cart_id, product_id)
);

-- 訂單
CREATE TABLE orders (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE SET NULL,
  total_amount NUMERIC(10, 2) NOT NULL,
  status VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending', 'paid', 'shipped', 'cancelled')),
  shipping_address TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 訂單項目
CREATE TABLE order_items (
  id SERIAL PRIMARY KEY,
  order_id INTEGER REFERENCES orders(id) ON DELETE CASCADE,
  product_id INTEGER REFERENCES products(id) ON DELETE SET NULL,
  product_name VARCHAR(255) NOT NULL,
  unit_price NUMERIC(10, 2) NOT NULL,
  quantity INTEGER NOT NULL
);
```

## 具體任務

### 1. 專案初始化
建立 Express 應用程式，目錄結構如下：
```
src/
├── routes/
│   ├── auth.js
│   ├── products.js
│   ├── cart.js
│   └── orders.js
├── middleware/
│   ├── auth.js       ← JWT 驗證
│   └── errorHandler.js
├── db/
│   └── index.js      ← pg Pool 設定
└── app.js
```

### 2. 身份驗證（`/api/auth`）
- `POST /api/auth/register`：註冊（bcrypt 雜湊密碼），同時為新使用者建立空購物車
- `POST /api/auth/login`：登入，回傳 JWT（有效期 24 小時）

### 3. 商品瀏覽（`/api/products`，公開）
- `GET /api/products`：
  - 僅回傳 `is_active = true` 的商品
  - 支援篩選：`?category_id=1&search=關鍵字&min_price=100&max_price=500`
  - 支援分頁：`?page=1&limit=20`
  - 支援排序：`?sortBy=price&order=asc`
- `GET /api/products/:id`：取得單一商品詳情（含分類名稱，使用 JOIN）

### 4. 購物車管理（`/api/cart`，需登入）
- `GET /api/cart`：
  - 取得購物車，含所有商品詳情（名稱、單價、小計）
  - 回傳總金額（`total_amount`）
  - 若商品庫存不足，在回應中標記 `insufficient_stock: true`
- `POST /api/cart/items`：
  - 新增商品 `{ product_id, quantity }`
  - 若商品已在購物車，則累加數量
  - 驗證：商品存在且 `is_active = true`，`quantity` > 0
- `PUT /api/cart/items/:product_id`：
  - 更新數量 `{ quantity }`
  - `quantity = 0` 時自動移除該項目
- `DELETE /api/cart/items/:product_id`：移除單一商品
- `DELETE /api/cart`：清空購物車

### 5. 訂單結帳（`/api/orders`，需登入）
- `POST /api/orders/checkout`：
  - 請求體：`{ shipping_address }`
  - **使用 Transaction 保護整個結帳流程**：
    1. `SELECT ... FOR UPDATE` 鎖定購物車中所有商品列（防止超賣）
    2. 逐一檢查庫存是否充足
    3. 扣減所有商品庫存
    4. 建立 `orders` 記錄與 `order_items` 記錄
    5. 清空購物車
  - 若任一商品庫存不足，Rollback 並回傳 `422 Unprocessable Entity`
- `GET /api/orders`：列出登入使用者的所有訂單（分頁，含訂單項目數量）
- `GET /api/orders/:id`：取得單一訂單詳情（含所有 order_items）

### 6. 資料驗證
- `quantity`：整數，必須 >= 1
- `product_id`：必填，必須為正整數
- `shipping_address`：必填，至少 10 字元
- `price` 相關計算：使用 PostgreSQL 的 `NUMERIC` 型別，避免浮點數誤差

### 7. 統一回應格式
成功：
```json
{ "success": true, "data": { ... } }
```
失敗：
```json
{
  "success": false,
  "error": { "code": "OUT_OF_STOCK", "message": "商品「XX」庫存不足，僅剩 2 件" }
}
```

## 提示

- **防止超賣**是本題核心：`SELECT * FROM products WHERE id = ANY($1) FOR UPDATE` 鎖定資料列後再扣減庫存
- 訂單項目需記錄下單當時的 `product_name` 和 `unit_price`，避免日後商品更新影響歷史訂單
- 購物車總金額建議在 SQL 層計算：`SUM(ci.quantity * p.price)` 比在 JavaScript 迴圈算更準確
- 使用者登入後若購物車不存在（資料不一致），在取得購物車時自動建立

## 進階挑戰（選做）

1. **優惠券系統**：新增 `coupons` 資料表，結帳時支援 `{ coupon_code }` 欄位，扣除折扣金額（需驗證有效期與使用次數限制）
2. **庫存預警 API**：`GET /api/products/low-stock?threshold=10`，列出庫存低於門檻的商品（限管理員）
3. **訂單取消**：`PATCH /api/orders/:id/cancel`，僅允許 `pending` 狀態的訂單取消，同時歸還庫存（Transaction）
4. **購物車過期清理**：新增定時腳本，刪除超過 30 天未更新的購物車項目
5. **API 測試**：使用 `supertest` + `Jest` 撰寫結帳 API 的整合測試，模擬庫存不足與正常結帳兩個情境
