# 第 15 週今日練習題：電商訂單管理 API 實戰

## 題目說明

建立一個具備完整功能的電商訂單管理後端 API，整合使用者身份驗證、商品管理、訂單建立與查詢、分頁排序以及交易處理，模擬真實電商系統的核心流程。

## 技術要求

- **Express.js**：路由分層架構、JWT 中介軟體、統一錯誤處理、檔案上傳（商品圖片）
- **PostgreSQL**：多資料表 JOIN、交易（Transaction）、索引優化、分頁查詢

## 資料庫結構

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  role VARCHAR(20) DEFAULT 'customer',
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE products (
  id SERIAL PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  description TEXT,
  price NUMERIC(10, 2) NOT NULL,
  stock INTEGER NOT NULL DEFAULT 0,
  image_url TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE orders (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id),
  status VARCHAR(30) DEFAULT 'pending',
  total_amount NUMERIC(10, 2),
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE order_items (
  id SERIAL PRIMARY KEY,
  order_id INTEGER REFERENCES orders(id),
  product_id INTEGER REFERENCES products(id),
  quantity INTEGER NOT NULL,
  unit_price NUMERIC(10, 2) NOT NULL
);
```

## 具體任務

1. **使用者認證模組**
   - `POST /api/auth/register`：註冊，密碼以 bcrypt 雜湊儲存
   - `POST /api/auth/login`：登入，回傳 JWT Token

2. **商品管理模組**（需 admin 角色）
   - `GET /api/products`：列出商品（支援 `?page=&limit=&sort=price&order=asc`）
   - `POST /api/products`：新增商品，支援圖片上傳（multer）
   - `PUT /api/products/:id`：更新商品資訊與庫存
   - `DELETE /api/products/:id`：刪除商品

3. **訂單模組**（需登入）
   - `POST /api/orders`：建立訂單
     - 在 **Transaction** 中執行：
       1. 確認每項商品庫存充足
       2. 批次扣減庫存（`UPDATE products SET stock = stock - $qty WHERE id = $id AND stock >= $qty`）
       3. 建立 `orders` 記錄
       4. 批次插入 `order_items`
       5. 計算並更新 `total_amount`
     - 任一步驟失敗須 **ROLLBACK**，回傳明確錯誤訊息
   - `GET /api/orders`：查詢自己的訂單列表（分頁）
   - `GET /api/orders/:id`：查詢訂單詳情（JOIN products 取得商品名稱與圖片）

4. **統計端點**（需 admin 角色）
   - `GET /api/admin/stats`：回傳
     - 今日訂單數與總金額
     - 庫存不足 5 件的商品清單
     - 近 7 天每日訂單數（GROUP BY DATE）

5. **統一錯誤處理 Middleware**
   - 所有路由未捕捉的錯誤，回傳 `{ error: "...", code: "..." }` JSON
   - JWT 驗證失敗回傳 401，角色不足回傳 403，資源不存在回傳 404

## 提示

- 使用 `pg` 的 `pool.connect()` 取得 client，手動執行 `BEGIN / COMMIT / ROLLBACK`
- 商品庫存扣減使用 `RETURNING id, stock` 確認實際更新行數（`rowCount === 0` 代表庫存不足）
- 分頁查詢搭配 `COUNT(*) OVER()` 視窗函數，一次查詢同時取得總筆數
- 路由結構建議：`routes/auth.js`、`routes/products.js`、`routes/orders.js`、`routes/admin.js`
- 中介軟體建議：`middleware/auth.js`（驗 JWT）、`middleware/role.js`（驗角色）

## 進階挑戰（選做）

- **訂單狀態機**：新增 `PUT /api/orders/:id/status`，實作 `pending → confirmed → shipped → delivered` 的合法狀態轉換，非法轉換回傳 422
- **搜尋功能**：`GET /api/products?search=` 使用 PostgreSQL 全文搜尋（`to_tsvector` + `to_tsquery`）
- **Rate Limiting**：使用 `express-rate-limit` 對 `/api/auth/login` 設定每分鐘最多 10 次請求
- **API 測試**：使用 supertest + Jest 為訂單建立流程撰寫整合測試，覆蓋正常流程與庫存不足的失敗案例
