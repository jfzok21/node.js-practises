# 第 14 週今日練習題：線上預約管理系統（實戰專案）

## 題目說明

建立一個完整的「線上預約管理系統」REST API，模擬真實商業場景（例如：美髮沙龍、診所、會議室預約）。本題整合先前所有章節的技術，包括路由設計、資料庫關聯、JWT 驗證、資料驗證、分頁、交易處理，以及錯誤回應規範。

## 技術要求
- **Express.js**：路由模組化（Router）、自訂 middleware（認證、驗證）、統一錯誤處理
- **PostgreSQL**：多資料表設計（users、services、bookings）、JOIN 查詢、Transaction、時間衝突檢查

## 資料庫結構

```sql
-- 使用者（客戶與管理員共用）
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  email VARCHAR(150) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  role VARCHAR(20) DEFAULT 'customer',  -- 'customer' | 'admin'
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 服務項目（例如：剪髮、燙髮）
CREATE TABLE services (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  duration_minutes INT NOT NULL,
  price NUMERIC(10, 2) NOT NULL,
  is_active BOOLEAN DEFAULT TRUE
);

-- 預約記錄
CREATE TABLE bookings (
  id SERIAL PRIMARY KEY,
  user_id INT REFERENCES users(id) ON DELETE CASCADE,
  service_id INT REFERENCES services(id) ON DELETE SET NULL,
  scheduled_at TIMESTAMPTZ NOT NULL,
  ends_at TIMESTAMPTZ NOT NULL,
  status VARCHAR(20) DEFAULT 'pending',  -- 'pending' | 'confirmed' | 'cancelled'
  note TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

## 具體任務

1. **初始化專案**
   - 建立 `src/` 目錄，結構如下：
     ```
     src/
     ├── app.js
     ├── db.js
     ├── middleware/
     │   ├── auth.js        (JWT 驗證)
     │   └── validate.js    (輸入驗證)
     ├── routes/
     │   ├── auth.js
     │   ├── services.js
     │   └── bookings.js
     └── controllers/
         ├── authController.js
         ├── servicesController.js
         └── bookingsController.js
     ```

2. **實作驗證 API**（`/api/auth`）
   - `POST /register`：註冊（name、email、password），密碼以 bcrypt 雜湊後存入
   - `POST /login`：登入，驗證成功回傳 JWT（有效期 24 小時）
   - `GET /me`：需 JWT，回傳目前登入使用者資訊

3. **實作服務項目 API**（`/api/services`）
   - `GET /`：列出所有啟用中的服務（分頁：`?page=1&limit=10`）
   - `POST /`：新增服務（僅限 admin 角色）
   - `PATCH /:id`：更新服務（僅限 admin）
   - `DELETE /:id`：軟刪除（將 `is_active` 設為 false，僅限 admin）

4. **實作預約 API**（`/api/bookings`）
   - `POST /`：建立預約，需驗證：
     - 使用者已登入
     - `service_id` 存在且啟用
     - `scheduled_at` 為未來時間
     - **時間無衝突**（同時段沒有其他 `confirmed` 或 `pending` 的預約）
   - `GET /`：查詢自己的預約（分頁、可依 `?status=pending` 篩選）
   - `PATCH /:id/cancel`：取消自己的預約（狀態由 `pending` 改為 `cancelled`）
   - `GET /admin/all`：查詢所有預約（僅限 admin），支援依日期範圍篩選（`?from=&to=`）
   - `PATCH /admin/:id/confirm`：管理員確認預約（需使用 Transaction，同時更新狀態並記錄確認時間）

5. **統一錯誤回應格式**
   ```json
   {
     "success": false,
     "error": {
       "code": "BOOKING_CONFLICT",
       "message": "此時段已有其他預約，請選擇其他時間。"
     }
   }
   ```

## 提示

- 時間衝突查詢可使用 PostgreSQL 的範圍重疊判斷：
  ```sql
  SELECT id FROM bookings
  WHERE status IN ('pending', 'confirmed')
    AND scheduled_at < $1 + (duration_minutes || ' minutes')::INTERVAL
    AND ends_at > $1
  ```
- 使用 `pg` 的 `pool.connect()` 取得 client 進行 Transaction：
  ```js
  const client = await pool.connect();
  try {
    await client.query('BEGIN');
    // ...
    await client.query('COMMIT');
  } catch (e) {
    await client.query('ROLLBACK');
    throw e;
  } finally {
    client.release();
  }
  ```
- JWT middleware 可從 `Authorization: Bearer <token>` 標頭解析
- 角色權限建議封裝成 `requireRole('admin')` middleware，方便路由複用

## 進階挑戰（選做）

- **統計報表 API**（`GET /api/admin/stats`）：回傳今日預約數、本週收入（只計 `confirmed`）、最熱門服務前三名
