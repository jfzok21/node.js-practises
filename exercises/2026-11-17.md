# 第 19 週今日練習題：即時通知系統 API

## 題目說明

實作一個支援即時通知的 RESTful API 服務。使用者可以訂閱特定事件（如訂單狀態更新、留言通知），系統透過 Server-Sent Events（SSE）推送即時通知，並將通知歷史記錄儲存於 PostgreSQL。

## 技術要求

- **Express.js**：SSE 路由、通知發送端點、訂閱管理 middleware
- **PostgreSQL**：通知記錄表、已讀/未讀狀態、使用者訂閱設定

## 具體任務

1. **設計資料庫結構**
   - 建立 `notifications` 表（id、user_id、type、title、message、is_read、created_at）
   - 建立 `notification_subscriptions` 表（user_id、event_type、is_active）

2. **實作 SSE 連線端點**
   - `GET /api/notifications/stream` — 建立 SSE 連線，依 JWT 驗證使用者身份
   - 伺服器維護連線 Map，斷線時自動清除

3. **實作通知 CRUD API**
   - `GET /api/notifications` — 取得當前使用者通知列表（支援分頁、未讀篩選）
   - `PATCH /api/notifications/:id/read` — 標記單筆通知已讀
   - `PATCH /api/notifications/read-all` — 一次標記全部已讀
   - `DELETE /api/notifications/:id` — 刪除通知

4. **實作通知觸發端點**
   - `POST /api/notifications/send` — 發送通知給指定使用者（需 admin 角色 middleware）
   - 儲存至 DB 後，若目標使用者有 SSE 連線則即時推送

5. **訂閱設定 API**
   - `GET /api/notifications/subscriptions` — 取得使用者訂閱設定
   - `PUT /api/notifications/subscriptions/:event_type` — 開啟或關閉特定事件訂閱

## 提示

- SSE 回應需設定 headers：`Content-Type: text/event-stream`、`Cache-Control: no-cache`、`Connection: keep-alive`
- 用 `res.write('data: ...\n\n')` 推送訊息，用 `req.on('close', ...)` 偵測斷線
- 連線 Map 可用 `Map<userId, Response[]>` 儲存（同一使用者可能開多個分頁）
- 傳送通知前先查詢 `notification_subscriptions` 確認使用者是否訂閱該 event_type
- 注意 SSE 連線不會因一般路由 timeout 而斷開，需手動管理心跳（heartbeat）

## 進階挑戰（選做）

- 加入 **心跳機制**：每 30 秒發送 `event: heartbeat` 以維持連線並偵測殭屍連線
- 整合 **Redis Pub/Sub**：讓多個 Node 程序都能推送通知（水平擴展準備）
- 撰寫 **Jest + supertest 測試**：模擬 SSE 連線並驗證通知正確觸發
- 實作 **通知 Template**：用 JSON 設定不同 type 的訊息格式，避免硬編碼字串
