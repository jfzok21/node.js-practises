# 第 10 週今日練習題：銀行轉帳系統（交易處理）

## 題目說明

實作一個簡單的銀行帳戶轉帳 API。轉帳涉及「從 A 帳戶扣款」與「向 B 帳戶存款」兩個資料庫操作，必須確保兩步驟同時成功或同時失敗——這正是資料庫交易（Transaction）的核心應用場景。

## 技術要求

- **Express.js**：提供 RESTful API 端點處理轉帳請求與查詢帳戶餘額
- **PostgreSQL**：使用 `BEGIN / COMMIT / ROLLBACK` 確保轉帳的原子性（Atomicity），搭配 `SELECT ... FOR UPDATE` 避免並發競爭條件

## 具體任務

1. **建立資料表**
   ```sql
   CREATE TABLE accounts (
     id SERIAL PRIMARY KEY,
     owner VARCHAR(100) NOT NULL,
     balance NUMERIC(12, 2) NOT NULL DEFAULT 0,
     CHECK (balance >= 0)
   );

   -- 插入測試資料
   INSERT INTO accounts (owner, balance) VALUES
     ('Alice', 1000.00),
     ('Bob',   500.00);
   ```

2. **實作 `GET /accounts/:id`**
   - 回傳指定帳戶的 `id`、`owner`、`balance`
   - 找不到時回傳 `404 { error: "Account not found" }`

3. **實作 `POST /transfer`**
   - 接收 body：`{ from_id, to_id, amount }`
   - 在單一 Transaction 中完成：
     1. 使用 `SELECT ... FOR UPDATE` 鎖定來源與目標帳戶列
     2. 確認來源帳戶餘額 `>= amount`，不足時 `ROLLBACK` 並回傳 `400`
     3. 扣除來源帳戶餘額、增加目標帳戶餘額
     4. `COMMIT` 並回傳轉帳後雙方最新餘額
   - 任何例外（DB 錯誤、資料不存在）均需 `ROLLBACK`

4. **驗證輸入**
   - `amount` 必須為正數
   - `from_id` 與 `to_id` 不可相同

5. **統一錯誤回應格式**
   ```json
   { "error": "錯誤訊息" }
   ```

## 提示

- 使用 `pg` 套件取得 `client`，並透過 `client.query('BEGIN')` 開啟交易；記得在 `finally` 區塊呼叫 `client.release()` 歸還連線池
- `SELECT ... FOR UPDATE` 範例：
  ```sql
  SELECT id, balance FROM accounts WHERE id = $1 FOR UPDATE
  ```
- `NUMERIC` 欄位從 `pg` 讀回時是字串，需用 `parseFloat()` 轉換後再做數字比較
- 建議結構：
  ```
  src/
    db.js          # pg Pool 設定
    routes/
      accounts.js  # GET /accounts/:id
      transfer.js  # POST /transfer
    app.js
  server.js
  ```

## 進階挑戰（選做）

- **交易紀錄表**：在同一 Transaction 中，將每筆轉帳寫入 `transactions` 資料表（`from_id`、`to_id`、`amount`、`created_at`），並新增 `GET /accounts/:id/transactions` 查詢歷史
- **並發壓力測試**：使用 `Promise.all` 同時送出 10 筆相同帳戶的轉帳請求，確認最終餘額不會出現負值（`CHECK (balance >= 0)` 應在資料庫層把關）
- **Idempotency Key**：在 `POST /transfer` 的 header 加入 `Idempotency-Key`，相同 key 的重複請求直接回傳第一次的結果，避免重複扣款
