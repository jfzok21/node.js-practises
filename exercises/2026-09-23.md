# 第 12 週今日練習題：任務管理 REST API 實戰專案

## 題目說明

綜合運用前 11 週所學技術，建立一個完整的「任務管理系統」REST API。系統支援多位使用者，每位使用者可建立、管理自己的任務；任務可附加標籤，並支援分頁、排序、搜尋等功能，還能上傳任務附件。

---

## 技術要求

- **Express.js**：模組化路由（Router）、全域錯誤處理 Middleware、JWT 身份驗證 Middleware
- **PostgreSQL**：多資料表關聯（users / tasks / tags / task_tags）、JOIN 查詢、資料驗證、Transaction 處理

---

## 資料庫結構

```sql
-- 使用者
CREATE TABLE users (
  id        SERIAL PRIMARY KEY,
  email     VARCHAR(255) UNIQUE NOT NULL,
  password  VARCHAR(255) NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 任務
CREATE TABLE tasks (
  id          SERIAL PRIMARY KEY,
  user_id     INTEGER REFERENCES users(id) ON DELETE CASCADE,
  title       VARCHAR(255) NOT NULL,
  description TEXT,
  status      VARCHAR(20) CHECK (status IN ('pending','in_progress','done')) DEFAULT 'pending',
  due_date    DATE,
  created_at  TIMESTAMPTZ DEFAULT NOW()
);

-- 標籤
CREATE TABLE tags (
  id    SERIAL PRIMARY KEY,
  name  VARCHAR(50) UNIQUE NOT NULL
);

-- 任務-標籤關聯
CREATE TABLE task_tags (
  task_id INTEGER REFERENCES tasks(id) ON DELETE CASCADE,
  tag_id  INTEGER REFERENCES tags(id)  ON DELETE CASCADE,
  PRIMARY KEY (task_id, tag_id)
);
```

## 具體任務

### 1. 使用者驗證模組（`routes/auth.js`）

| 路由 | 說明 |
|------|------|
| `POST /api/auth/register` | 註冊（bcrypt 加密密碼） |
| `POST /api/auth/login` | 登入，回傳 JWT |

### 2. 任務 CRUD 模組（`routes/tasks.js`）—— 需 JWT 驗證

| 路由 | 說明 |
|------|------|
| `GET /api/tasks` | 取得登入者所有任務（支援分頁、排序、狀態過濾、關鍵字搜尋） |
| `POST /api/tasks` | 建立任務，可同時附加標籤（Transaction：同時寫入 tasks + task_tags） |
| `GET /api/tasks/:id` | 取得單一任務（含標籤，JOIN 查詢） |
| `PUT /api/tasks/:id` | 更新任務資訊（含標籤替換，Transaction） |
| `DELETE /api/tasks/:id` | 刪除任務（CASCADE 自動清除 task_tags） |

### 3. 分頁與排序（`GET /api/tasks`）

Query string 參數：

```
page=1&limit=10&sort=created_at&order=desc&status=pending&search=報告
```

- `page` / `limit`：分頁
- `sort`：排序欄位（`created_at` | `due_date` | `title`）
- `order`：`asc` | `desc`
- `status`：篩選狀態
- `search`：模糊搜尋 title / description

### 4. 全域 Middleware

- `middleware/auth.js`：驗證 JWT，將 `req.user` 注入
- `middleware/errorHandler.js`：統一錯誤格式 `{ error: string, code: number }`
- 所有端點加入輸入驗證（欄位必填、長度、狀態值白名單）

### 5. 進階整合

- 使用 `multer` 讓 `PUT /api/tasks/:id/attachment` 支援上傳附件（儲存路徑記回 tasks）
- 建立 Jest + supertest 測試：
  - 完整測試 register → login → create task → list → update → delete 流程
  - 測試分頁回應格式 `{ data: [], total, page, limit }`

## 提示

- 用 `pg` 套件連線 PostgreSQL，建議封裝成 `db/pool.js`
- Transaction 範例：
  ```js
  const client = await pool.connect();
  try {
    await client.query('BEGIN');
    // ... 多個 query
    await client.query('COMMIT');
  } catch (e) {
    await client.query('ROLLBACK');
    throw e;
  } finally {
    client.release();
  }
  ```
- JWT 驗證：`Authorization: Bearer <token>`，使用 `jsonwebtoken` 套件
- bcrypt：`bcryptjs` 套件，`saltRounds = 10`
- 回傳 404 時務必確認任務屬於當前登入使用者（防止越權存取）

## 進階挑戰（選做）

1. **軟刪除**：tasks 加入 `deleted_at` 欄位，DELETE 只設定時間戳而非真正刪除，GET 查詢自動過濾
2. **速率限制**：使用 `express-rate-limit` 限制 `/api/auth/login` 每分鐘最多 10 次
3. **統計端點**：`GET /api/tasks/stats` 回傳每種 status 的任務數量
4. **Swagger 文件**：整合 `swagger-jsdoc` + `swagger-ui-express`，為所有端點加入 OpenAPI 註解
