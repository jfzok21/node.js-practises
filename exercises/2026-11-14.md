# 第 19 週今日練習題：社群貼文平台 API 實戰專案

## 題目說明

實作一個輕量社群貼文平台的後端 REST API，支援使用者發文、留言、按讚、追蹤其他使用者，並以 Cursor-based 分頁取代傳統 OFFSET 分頁，提升大資料量時的效能。此練習整合 JWT 身份驗證、多表 JOIN、Transaction，以及 Cursor 分頁設計，模擬生產環境常見的社群系統架構。

## 技術要求

- **Express.js**：模組化架構（`routes/`、`controllers/`、`services/`），關注點分離
- **PostgreSQL**：多資料表（users、posts、comments、likes、follows），複雜 JOIN 與聚合
- **JWT**：登入後取得 token，受保護端點需驗證
- **Transaction**：按讚 / 取消按讚、追蹤 / 取消追蹤等非冪等操作需在 Transaction 中執行
- **Cursor 分頁**：以 `created_at + id` 組合游標取代 `OFFSET`，支援無限捲動場景

## 資料庫 Schema

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(50) NOT NULL UNIQUE,
  email VARCHAR(100) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  bio TEXT,
  avatar_url VARCHAR(500),
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE posts (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  content TEXT NOT NULL CHECK (char_length(content) BETWEEN 1 AND 500),
  image_url VARCHAR(500),
  likes_count INTEGER NOT NULL DEFAULT 0,
  comments_count INTEGER NOT NULL DEFAULT 0,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE comments (
  id SERIAL PRIMARY KEY,
  post_id INTEGER REFERENCES posts(id) ON DELETE CASCADE,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  content TEXT NOT NULL CHECK (char_length(content) BETWEEN 1 AND 300),
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE likes (
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  post_id INTEGER REFERENCES posts(id) ON DELETE CASCADE,
  created_at TIMESTAMP DEFAULT NOW(),
  PRIMARY KEY (user_id, post_id)
);

CREATE TABLE follows (
  follower_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  following_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  created_at TIMESTAMP DEFAULT NOW(),
  PRIMARY KEY (follower_id, following_id),
  CHECK (follower_id <> following_id)
);

CREATE INDEX idx_posts_user_id ON posts(user_id);
CREATE INDEX idx_posts_cursor ON posts(created_at DESC, id DESC);
CREATE INDEX idx_comments_post_id ON comments(post_id);
```

## 具體任務

1. **建立專案結構**
   ```
   src/
   ├── routes/
   │   ├── auth.js
   │   ├── posts.js
   │   ├── comments.js
   │   └── users.js
   ├── controllers/
   │   ├── authController.js
   │   ├── postController.js
   │   ├── commentController.js
   │   └── userController.js
   ├── services/
   │   ├── postService.js
   │   └── followService.js
   ├── middleware/
   │   ├── auth.js
   │   └── optionalAuth.js    (已登入就帶 user，未登入也能繼續)
   ├── db.js
   └── app.js
   ```

2. **實作認證**
   - `POST /api/auth/register`：新增使用者（密碼 bcrypt hash）
   - `POST /api/auth/login`：驗證帳密，回傳 JWT（有效期 24 小時）
   - `GET /api/auth/me`：回傳目前登入使用者資訊（需 JWT）

3. **實作貼文 API**
   - `POST /api/posts`：建立貼文（需 JWT）
   - `GET /api/posts/feed`：取得追蹤者的貼文動態牆（需 JWT，Cursor 分頁）
   - `GET /api/posts/explore`：取得全站最新貼文（可匿名，Cursor 分頁）
   - `GET /api/posts/:id`：取得單一貼文（含按讚數、留言數、是否已按讚）
   - `PATCH /api/posts/:id`：更新自己的貼文（僅限作者）
   - `DELETE /api/posts/:id`：刪除自己的貼文（僅限作者）

4. **實作按讚 API（Transaction 核心任務）**
   - `POST /api/posts/:id/like`：按讚
   - `DELETE /api/posts/:id/like`：取消按讚

   按讚 Transaction 需依序執行：
   1. 確認貼文存在
   2. 插入 `likes` 記錄（若已按讚則回傳 `409 ALREADY_LIKED`）
   3. `UPDATE posts SET likes_count = likes_count + 1 WHERE id = $1`
   4. COMMIT（任一失敗則 ROLLBACK）

   取消按讚同理，需確認記錄存在才允許刪除，並 `likes_count - 1`。

5. **實作留言 API**
   - `POST /api/posts/:id/comments`：新增留言（需 JWT），同時 `comments_count + 1`
   - `GET /api/posts/:id/comments`：取得留言列表（Cursor 分頁，可匿名）
   - `DELETE /api/comments/:id`：刪除自己的留言（並 `comments_count - 1`）

6. **實作追蹤 API**
   - `POST /api/users/:id/follow`：追蹤使用者（需 JWT，不能追蹤自己）
   - `DELETE /api/users/:id/follow`：取消追蹤
   - `GET /api/users/:id/followers`：取得追蹤者列表（Cursor 分頁）
   - `GET /api/users/:id/following`：取得追蹤中列表（Cursor 分頁）

7. **實作 Cursor 分頁**

   Request 範例：`GET /api/posts/explore?limit=10&cursor=eyJjcmVhdGVkX2F0IjoiMjAyNi0xMS0xMFQxMjowMDowMFoiLCJpZCI6NDJ9`

   Cursor 為 Base64 編碼的 JSON：
   ```json
   { "created_at": "2026-11-10T12:00:00Z", "id": 42 }
   ```

   SQL 查詢（以「created_at + id」做複合游標）：
   ```sql
   SELECT p.*, u.username, u.avatar_url
   FROM posts p
   JOIN users u ON p.user_id = u.id
   WHERE (p.created_at, p.id) < ($1, $2)
   ORDER BY p.created_at DESC, p.id DESC
   LIMIT $3
   ```

   Response 範例：
   ```json
   {
     "data": [...],
     "next_cursor": "eyJjcmVhdGVkX2F0IjoiMjAyNi0xMS0wOVQwODowMDowMFoiLCJpZCI6MzV9",
     "has_more": true
   }
   ```
   若回傳筆數 < limit，`has_more` 為 `false`，`next_cursor` 為 `null`。

## 提示

- `optionalAuth` middleware 範例（不強制要求 JWT，但有 JWT 時解析）：
  ```js
  module.exports = (req, res, next) => {
    const token = req.headers.authorization?.split(' ')[1];
    if (!token) return next();
    try {
      req.user = jwt.verify(token, process.env.JWT_SECRET);
    } catch {}
    next();
  };
  ```
- Cursor 編解碼工具函式：
  ```js
  const encodeCursor = (obj) => Buffer.from(JSON.stringify(obj)).toString('base64');
  const decodeCursor = (str) => JSON.parse(Buffer.from(str, 'base64').toString());
  ```
- 取得貼文時，同時回傳「目前登入使用者是否已按讚」：
  ```sql
  SELECT p.*,
    EXISTS(SELECT 1 FROM likes WHERE user_id = $1 AND post_id = p.id) AS is_liked_by_me
  FROM posts p WHERE p.id = $2
  ```
  未登入時 `$1` 傳入 `null`，EXISTS 自動回傳 false。

- 動態牆（feed）SQL 建議只取自己追蹤的人的貼文：
  ```sql
  SELECT p.*, u.username, u.avatar_url
  FROM posts p
  JOIN users u ON p.user_id = u.id
  WHERE p.user_id IN (
    SELECT following_id FROM follows WHERE follower_id = $1
  )
  AND (p.created_at, p.id) < ($2, $3)
  ORDER BY p.created_at DESC, p.id DESC
  LIMIT $4
  ```

## 進階挑戰（選做）

- 在貼文刪除時，使用 `ON DELETE CASCADE` 自動清除 likes / comments，並以 Trigger 自動維護 `likes_count` 與 `comments_count`，移除 Application 層的手動 UPDATE：
  ```sql
  CREATE OR REPLACE FUNCTION update_post_likes_count()
  RETURNS TRIGGER AS $$
  BEGIN
    IF TG_OP = 'INSERT' THEN
      UPDATE posts SET likes_count = likes_count + 1 WHERE id = NEW.post_id;
    ELSIF TG_OP = 'DELETE' THEN
      UPDATE posts SET likes_count = GREATEST(likes_count - 1, 0) WHERE id = OLD.post_id;
    END IF;
    RETURN NULL;
  END;
  $$ LANGUAGE plpgsql;

  CREATE TRIGGER trg_likes_count
  AFTER INSERT OR DELETE ON likes
  FOR EACH ROW EXECUTE FUNCTION update_post_likes_count();
  ```
- 加入全文搜尋：`GET /api/posts/search?q=關鍵字`，使用 PostgreSQL `to_tsvector` + `to_tsquery`
- 為「取得單一貼文」撰寫 `supertest + Jest` 整合測試，涵蓋：已登入（`is_liked_by_me` 正確）、未登入（`is_liked_by_me = false`）、貼文不存在（404）
- 加入 `helmet` + `express-rate-limit` 強化安全性
