# 第 10 週今日練習題：銀行轉帳系統（交易處理）

## 題目說明

建立一個簡單的銀行帳戶 API，支援帳戶間的資金轉帳。所有轉帳操作必須以 PostgreSQL **Transaction（交易）** 保護，確保資料一致性：要麼全部成功，要麼全部回滾，不會出現「A 扣款成功但 B 沒收到錢」的半途異常狀態。

## 技術要求

- **Express.js**：建立 RESTful API 端點，處理帳戶查詢與轉帳請求
- **PostgreSQL**：使用 `BEGIN` / `COMMIT` / `ROLLBACK` 管理交易，搭配 `SELECT ... FOR UPDATE` 避免並發競爭條件

## 具體任務

1. **建立資料表**
   執行以下 SQL 建立 `accounts` 資料表：
   ```sql
   CREATE TABLE accounts (
     id SERIAL PRIMARY KEY,
     owner VARCHAR(100) NOT NULL,
     balance NUMERIC(12, 2) NOT NULL DEFAULT 0,
     CHECK (balance >= 0)
   );

   -- 插入測試資料
   INSERT INTO accounts (owner, balance) VALUES
     ('Alice', 5000.00),
     ('Bob', 3000.00),
     ('Charlie', 1500.00);
   ```

2. **實作 API 端點**
   - `GET /accounts` — 取得所有帳戶清單（id、owner、balance）
   - `GET /accounts/:id` — 取得單一帳戶資訊
   - `POST /accounts/:id/transfer` — 從指定帳戶轉帳給另一個帳戶

3. **實作轉帳交易邏輯**
   `POST /accounts/:id/transfer` 請求 body：
   ```json
   {
     "to_account_id": 2,
     "amount": 500.00
   }
   ```
   轉帳流程（必須在同一個 Transaction 內完成）：
   - 以 `SELECT ... FOR UPDATE` 鎖定來源與目標帳戶（避免競爭條件）
   - 驗證來源帳戶餘額是否充足
   - 扣除來源帳戶金額
   - 增加目標帳戶金額
   - 成功則 `COMMIT`，任何錯誤則 `ROLLBACK`

4. **錯誤處理**
   - 帳戶不存在 → 回傳 404
   - 餘額不足 → 回傳 400，附帶錯誤訊息
   - 轉帳給自己 → 回傳 400
   - 金額必須大於 0 → 回傳 400

## 提示

- 使用 `node-postgres`（`pg`）時，從 pool 取出 `client`，在 client 上執行 `BEGIN` / `COMMIT` / `ROLLBACK`，而不是直接用 `pool.query()`
- 交易結束後記得呼叫 `client.release()` 歸還連線（建議用 try/catch/finally）
- `CHECK (balance >= 0)` 約束是最後一道防線，但應在應用層先驗證，不要依賴資料庫拋出例外
- `SELECT ... FOR UPDATE` 鎖定順序要一致（永遠先鎖 id 較小的帳戶），避免死鎖（Deadlock）

## 程式碼骨架參考

```javascript
// routes/transfer.js
const { Pool } = require('pg');
const pool = new Pool();

router.post('/accounts/:id/transfer', async (req, res) => {
  const fromId = parseInt(req.params.id);
  const { to_account_id: toId, amount } = req.body;

  // 基本驗證
  if (fromId === toId) return res.status(400).json({ error: '不能轉帳給自己' });
  if (!amount || amount <= 0) return res.status(400).json({ error: '金額必須大於 0' });

  const client = await pool.connect();
  try {
    await client.query('BEGIN');

    // 鎖定兩個帳戶（依 id 排序避免死鎖）
    const [lockFirst, lockSecond] = fromId < toId ? [fromId, toId] : [toId, fromId];
    const { rows } = await client.query(
      'SELECT id, balance FROM accounts WHERE id = ANY($1) FOR UPDATE',
      [[lockFirst, lockSecond]]
    );

    // TODO: 驗證帳戶存在、餘額充足，並執行扣款/入帳

    await client.query('COMMIT');
    res.json({ message: '轉帳成功' });
  } catch (err) {
    await client.query('ROLLBACK');
    res.status(500).json({ error: err.message });
  } finally {
    client.release();
  }
});
```

## 進階挑戰（選做）

1. **交易紀錄表**：建立 `transactions` 資料表，每次轉帳成功後在同一個 Transaction 內寫入轉帳紀錄（from_account_id、to_account_id、amount、created_at），並新增 `GET /accounts/:id/transactions` 查詢帳戶的歷史轉帳紀錄。

2. **並發壓力測試**：使用 `Promise.all()` 同時發出 10 筆相同的轉帳請求，觀察餘額是否保持正確（不出現超額扣款）。若有興趣，可用 Artillery 或 k6 做壓力測試。

3. **Savepoint**：嘗試在交易中使用 `SAVEPOINT` 建立部分回滾點，模擬複雜業務流程（如批次付款：部分成功、部分失敗）。
