# 第 12 週今日練習題：書籍管理 API 實戰專案

## 題目說明

整合前 11 週所學的所有技術，建構一個完整的「書籍管理系統」REST API。此專案涵蓋路由設計、資料庫操作、身份驗證、分頁排序、資料驗證、交易處理，以及完整的 API 測試。

## 技術要求

- **Express.js**：RESTful 路由設計、自訂 Middleware、錯誤處理、JWT 身份驗證
- **PostgreSQL**：多資料表 JOIN、交易處理（Transaction）、分頁排序、複雜查詢

## 資料庫結構

```sql
-- 使用者資料表
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(50) UNIQUE NOT NULL,
  email VARCHAR(100) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 書籍資料表
CREATE TABLE books (
  id SERIAL PRIMARY KEY,
  title VARCHAR(200) NOT NULL,
  author VARCHAR(100) NOT NULL,
  isbn VARCHAR(20) UNIQUE,
  price DECIMAL(10, 2) NOT NULL,
  stock INTEGER DEFAULT 0,
  category VARCHAR(50),
  created_at TIMESTAMP DEFAULT NOW()
);

-- 訂單資料表
CREATE TABLE orders (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  total_amount DECIMAL(10, 2) NOT NULL,
  status VARCHAR(20) DEFAULT 'pending',
  created_at TIMESTAMP DEFAULT NOW()
);

-- 訂單明細資料表
CREATE TABLE order_items (
  id SERIAL PRIMARY KEY,
  order_id INTEGER REFERENCES orders(id) ON DELETE CASCADE,
  book_id INTEGER REFERENCES books(id),
  quantity INTEGER NOT NULL,
  unit_price DECIMAL(10, 2) NOT NULL
);
```

## 具體任務

### 任務一：專案初始化
1. 初始化 Node.js 專案，安裝所需套件：
   - `express`、`pg`、`bcryptjs`、`jsonwebtoken`
   - `joi`（資料驗證）、`multer`（若需要上傳書籍封面）
   - `jest`、`supertest`（測試）
2. 建立專案目錄結構：
   ```
   src/
   ├── routes/
   ├── middleware/
   ├── controllers/
   ├── db/
   └── app.js
   ```

### 任務二：身份驗證模組
1. **POST /api/auth/register** — 使用者註冊
   - 驗證欄位：username（3~20 字元）、email（合法格式）、password（至少 8 碼）
   - 密碼以 bcrypt 雜湊後存入資料庫
   - 回傳 `{ message: '註冊成功', userId }`
2. **POST /api/auth/login** — 使用者登入
   - 驗證帳密，成功回傳 JWT Token（有效期 24 小時）
   - 回傳 `{ token, user: { id, username, email } }`
3. 建立 `authMiddleware`：驗證 Authorization Header 中的 Bearer Token，失敗回傳 401

### 任務三：書籍 CRUD API
1. **GET /api/books** — 取得書籍清單（需分頁與排序）
   - 查詢參數：`page`（預設 1）、`limit`（預設 10）、`sort`（price/title/created_at）、`order`（asc/desc）、`category`（分類篩選）、`search`（書名或作者模糊搜尋）
   - 回傳 `{ data: [...], total, page, totalPages }`
2. **GET /api/books/:id** — 取得單一書籍詳情
3. **POST /api/books** — 新增書籍（需要 JWT 驗證）
   - 驗證所有欄位，price 必須 > 0，stock 必須 >= 0
4. **PUT /api/books/:id** — 更新書籍資料（需要 JWT 驗證）
5. **DELETE /api/books/:id** — 刪除書籍（需要 JWT 驗證）

### 任務四：訂單 API（含交易處理）
1. **POST /api/orders** — 建立訂單（需要 JWT 驗證）
   - 接受 `{ items: [{ bookId, quantity }] }` 格式
   - 使用 **Transaction** 確保：
     - 檢查每本書的庫存是否足夠
     - 扣減庫存（UPDATE books SET stock = stock - quantity）
     - 建立 orders 記錄
     - 建立 order_items 記錄
     - 計算 total_amount
   - 任一步驟失敗則全部 ROLLBACK
2. **GET /api/orders** — 取得目前使用者的訂單清單（需要 JWT 驗證）
   - 使用 JOIN 查詢，包含訂單明細與書籍名稱
   - 支援分頁

### 任務五：統計 API
1. **GET /api/stats/books** — 書籍銷售統計（需要 JWT 驗證）
   - 回傳銷售量前 5 名的書籍（JOIN order_items + books）
   - 回傳各分類書籍數量
2. **GET /api/stats/revenue** — 收入統計（需要 JWT 驗證）
   - 回傳本月總收入（篩選 orders.created_at 為本月）
   - 回傳每日收入（GROUP BY DATE(created_at)）

### 任務六：API 測試
使用 Jest + Supertest 撰寫以下測試：
1. 身份驗證測試：註冊、登入成功/失敗案例
2. 書籍 CRUD 測試：新增、查詢、更新、刪除
3. 訂單測試：
   - 正常下單流程（庫存正確扣減）
   - 庫存不足時應回傳 400 並不扣減
4. 分頁測試：驗證回傳資料筆數正確
5. 未授權存取測試：未帶 Token 時回傳 401

## 提示

- 使用 `pg.Pool` 管理資料庫連線池，Transaction 需從 Pool 取出同一個 client 執行
- JWT Secret 應從環境變數 `process.env.JWT_SECRET` 讀取，不要寫死在程式碼中
- 建立統一的錯誤處理 Middleware，捕捉所有 async 錯誤並回傳適當 HTTP 狀態碼
- 分頁公式：`OFFSET = (page - 1) * limit`，使用 `COUNT(*) OVER()` 取總數可避免多一次查詢
- 使用 `async/await` + try/catch 處理非同步操作

## 進階挑戰（選做）

1. **Redis 快取**：為 `GET /api/books` 加入 Redis 快取，TTL 設為 5 分鐘，書籍更新時清除快取
2. **書籍封面上傳**：使用 multer 支援 `multipart/form-data`，上傳圖片並儲存路徑至資料庫
3. **Rate Limiting**：使用 `express-rate-limit`，限制同一 IP 每分鐘最多 60 次請求
4. **Swagger 文件**：使用 `swagger-jsdoc` + `swagger-ui-express` 自動生成 API 文件
5. **軟刪除**：為 books 和 orders 加入 `deleted_at` 欄位，DELETE 改為標記而非實際刪除
