# 第 15 週今日練習題：任務管理 REST API（完整實戰）

## 題目說明

建立一套完整的「任務管理系統」REST API，整合 Express.js 與 PostgreSQL，包含使用者認證、資料 CRUD、分頁查詢、錯誤處理，以及 API 測試。這是一個貫穿前 14 週所有技術的綜合實戰專案。

---

## 技術要求

- **Express.js**：路由分層、Middleware 管道、統一錯誤處理
- **PostgreSQL**：多資料表關聯（users / tasks / tags）、JOIN 查詢、Transaction
- **JWT**：使用者登入後核發 Token，保護受限路由
- **資料驗證**：欄位型別、必填、範圍檢查
- **分頁 & 排序**：支援 `?page=`、`?limit=`、`?sort=`、`?order=`
- **測試**：用 supertest + Jest 撰寫至少 5 個 API 測試案例

---

## 具體任務

### 1. 資料庫設計

建立三張資料表：

```sql
CREATE TABLE users (
  id        SERIAL PRIMARY KEY,
  email     VARCHAR(255) UNIQUE NOT NULL,
  password  VARCHAR(255) NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE tasks (
  id          SERIAL PRIMARY KEY,
  user_id     INTEGER REFERENCES users(id) ON DELETE CASCADE,
  title       VARCHAR(255) NOT NULL,
  description TEXT,
  status      VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending','in_progress','done')),
  due_date    DATE,
  created_at  TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE tags (
  id      SERIAL PRIMARY KEY,
  task_id INTEGER REFERENCES tasks(id) ON DELETE CASCADE,
  name    VARCHAR(50) NOT NULL
);
```

### 2. 使用者認證

| 方法   | 路由             | 說明                          |
|--------|------------------|-------------------------------|
| POST   | `/auth/register` | 註冊（bcrypt 雜湊密碼）       |
| POST   | `/auth/login`    | 登入，回傳 JWT                |

### 3. 任務 CRUD（需攜帶 JWT）

| 方法   | 路由              | 說明                          |
|--------|-------------------|-------------------------------|
| GET    | `/tasks`          | 列出自己的任務（分頁 & 排序） |
| POST   | `/tasks`          | 新增任務（同時可附加 tags）   |
| GET    | `/tasks/:id`      | 取得單一任務（含 tags）       |
| PATCH  | `/tasks/:id`      | 更新任務欄位                  |
| DELETE | `/tasks/:id`      | 刪除任務（Transaction 刪除相關 tags）|

### 4. 查詢功能

- `GET /tasks?page=1&limit=10&sort=due_date&order=asc`
- `GET /tasks?status=pending` — 依狀態篩選
- `GET /tasks?search=關鍵字` — 模糊搜尋 title / description

### 5. 統一錯誤格式

所有錯誤回應須符合：

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "title 為必填欄位"
  }
}
```

常見錯誤碼：`VALIDATION_ERROR`、`UNAUTHORIZED`、`NOT_FOUND`、`FORBIDDEN`

### 6. 撰寫測試

用 supertest + Jest 測試以下案例：

1. 成功註冊回傳 201
2. 重複 email 回傳 409
3. 未攜帶 JWT 存取 `/tasks` 回傳 401
4. 新增任務成功回傳 201 並含 `id`
5. 查詢分頁：`?page=2&limit=2` 回傳正確筆數

---

## 提示

- 使用 `pg` 套件（Pool 模式）管理資料庫連線
- JWT 驗證寫成獨立 Middleware（`middleware/auth.js`）
- 刪除任務時，先刪 tags 再刪 task，包在同一個 Transaction 內
- 分頁計算：`OFFSET = (page - 1) * limit`
- 模糊搜尋使用 `ILIKE '%' || $1 || '%'` 避免 SQL Injection

## 進階挑戰（選做）

- 加入 `multer`，讓任務可附上附件（存本機或 S3）
- 使用 `express-rate-limit` 對 `/auth/login` 限流（每分鐘最多 5 次）

- 將 `tasks` 加入軟刪除欄位（`deleted_at`），DELETE 改為邏輯刪除
