# 第 11 週今日練習題：API 自動化測試（supertest + Jest）

## 題目說明

你已經完成了前 10 週的 Express + PostgreSQL 開發練習。本週的重點是「讓程式碼可驗證」——使用 **Jest** 作為測試框架，搭配 **supertest** 對你的 Express API 進行自動化整合測試，確保每個端點在各種情境下都能回傳正確的結果。

你將為一個簡單的「待辦事項 API（Todo API）」撰寫完整的測試套件，涵蓋正常流程（happy path）與錯誤情境（error path）。

---

## 技術要求

- **Express.js**：建立可被測試的 Express app（不直接 `listen`，改為 export app）
- **PostgreSQL**：使用獨立的測試資料庫，每次測試前後清除資料
- **Jest**：測試框架，負責組織測試、斷言結果
- **supertest**：對 Express app 發送 HTTP 請求，無需真正啟動 server

## 具體任務

### 1. 建立測試用 Express App

建立 `src/app.js`，實作以下 Todo API：

| 方法   | 路徑           | 說明                   |
|--------|----------------|------------------------|
| GET    | /todos         | 取得所有待辦事項         |
| GET    | /todos/:id     | 取得單一待辦事項         |
| POST   | /todos         | 新增待辦事項             |
| PUT    | /todos/:id     | 更新待辦事項（標題/完成） |
| DELETE | /todos/:id     | 刪除待辦事項             |

```js
// src/app.js 結構示意
const express = require('express');
const app = express();
app.use(express.json());

// 路由...

module.exports = app; // 不呼叫 app.listen()
```

### 2. 設定測試環境

安裝依賴：
```bash
npm install --save-dev jest supertest
```

在 `package.json` 加入：
```json
{
  "scripts": {
    "test": "jest --runInBand",
    "test:watch": "jest --watch"
  },
  "jest": {
    "testEnvironment": "node"
  }
}
```

### 3. 撰寫整合測試

建立 `tests/todos.test.js`，使用 `describe` / `it` 組織測試：

**必須覆蓋的測試情境：**

```
describe('GET /todos')
  ✓ 應回傳 200 與空陣列（資料庫為空時）
  ✓ 應回傳 200 與所有待辦事項清單

describe('POST /todos')
  ✓ 傳入正確資料時，應回傳 201 與新建立的 todo
  ✓ 缺少 title 時，應回傳 400 與錯誤訊息

describe('GET /todos/:id')
  ✓ 傳入存在的 id，應回傳 200 與對應資料
  ✓ 傳入不存在的 id，應回傳 404

describe('PUT /todos/:id')
  ✓ 應能更新 title
  ✓ 應能將 completed 從 false 改為 true
  ✓ 傳入不存在的 id，應回傳 404

describe('DELETE /todos/:id')
  ✓ 應回傳 204 並從資料庫中刪除
  ✓ 傳入不存在的 id，應回傳 404
```

### 4. 管理測試資料庫生命週期

在測試中正確使用 Jest hooks：

```js
const request = require('supertest');
const app = require('../src/app');
const db = require('../src/db'); // 你的 pg pool

beforeAll(async () => {
  // 建立測試資料表
  await db.query(`
    CREATE TABLE IF NOT EXISTS todos (
      id SERIAL PRIMARY KEY,
      title TEXT NOT NULL,
      completed BOOLEAN DEFAULT false
    )
  `);
});

beforeEach(async () => {
  // 每個測試前清空資料，確保隔離
  await db.query('DELETE FROM todos');
});

afterAll(async () => {
  // 關閉資料庫連線，避免 Jest 無法結束
  await db.end();
});
```

### 5. 實際撰寫一個完整測試案例

```js
describe('POST /todos', () => {
  it('應建立新的 todo 並回傳 201', async () => {
    const res = await request(app)
      .post('/todos')
      .send({ title: '學習 supertest', completed: false });

    expect(res.status).toBe(201);
    expect(res.body).toMatchObject({
      id: expect.any(Number),
      title: '學習 supertest',
      completed: false,
    });
  });

  it('缺少 title 時應回傳 400', async () => {
    const res = await request(app)
      .post('/todos')
      .send({});

    expect(res.status).toBe(400);
    expect(res.body).toHaveProperty('error');
  });
});
```

## 提示

- **不要直接 `app.listen()`**：讓 supertest 自己管理 port，在 `src/server.js` 才呼叫 `app.listen()`
- **使用環境變數切換測試 DB**：`process.env.NODE_ENV === 'test'` 時連接到不同的資料庫
- **`--runInBand`**：讓測試序列執行，避免多個測試同時操作資料庫造成競爭問題
- **`toMatchObject` vs `toEqual`**：`toMatchObject` 只檢查部分欄位，`toEqual` 要求完全一致，測試 API 回應通常用前者
- **測試命名要清楚**：測試名稱應能說明「情境 + 預期行為」，例如「當 title 為空時，應回傳 400」
