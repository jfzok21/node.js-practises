# 第 16 週今日練習題：任務管理系統 REST API（全功能實戰）

## 題目說明

建立一個具備完整功能的「任務管理系統（Task Management System）」REST API。
本題整合前 15 週所學：路由設計、CRUD、Middleware、JOIN 查詢、JWT 身份驗證、資料驗證、分頁、排序與交易處理，模擬真實後端專案開發流程。

## 技術要求

- **Express.js**：路由模組化（Router）、自訂 Middleware（認證、錯誤處理、請求日誌）
- **PostgreSQL**：多資料表設計（users、projects、tasks、tags、task_tags）、JOIN 查詢、Transaction

## 資料庫 Schema

```sql
-- 使用者
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  name VARCHAR(100) NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 專案
CREATE TABLE projects (
  id SERIAL PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  description TEXT,
  owner_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 任務
CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  title VARCHAR(255) NOT NULL,
  description TEXT,
  status VARCHAR(20) DEFAULT 'todo' CHECK (status IN ('todo', 'in_progress', 'done')),
  priority VARCHAR(10) DEFAULT 'medium' CHECK (priority IN ('low', 'medium', 'high')),
  due_date DATE,
  project_id INTEGER REFERENCES projects(id) ON DELETE CASCADE,
  assignee_id INTEGER REFERENCES users(id) ON DELETE SET NULL,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- 標籤
CREATE TABLE tags (
  id SERIAL PRIMARY KEY,
  name VARCHAR(50) UNIQUE NOT NULL,
  color VARCHAR(7) DEFAULT '#6366f1'
);

-- 任務標籤（多對多）
CREATE TABLE task_tags (
  task_id INTEGER REFERENCES tasks(id) ON DELETE CASCADE,
  tag_id INTEGER REFERENCES tags(id) ON DELETE CASCADE,
  PRIMARY KEY (task_id, tag_id)
);
```

## 具體任務

### 1. 專案初始化
- 建立 Express 應用程式，目錄結構如下：
  ```
  src/
  ├── routes/
  │   ├── auth.js
  │   ├── projects.js
  │   └── tasks.js
  ├── middleware/
  │   ├── auth.js       ← JWT 驗證
  │   ├── validate.js   ← 輸入驗證
  │   └── logger.js     ← 請求日誌
  ├── db/
  │   └── index.js      ← pg Pool 設定
  └── app.js
  ```

### 2. 身份驗證（`/api/auth`）
- `POST /api/auth/register`：註冊（bcrypt 雜湊密碼）
- `POST /api/auth/login`：登入，回傳 JWT（有效期 7 天）
- Middleware `requireAuth`：解析 Bearer Token，將使用者資訊附加至 `req.user`

### 3. 專案管理（`/api/projects`，需登入）
- `GET    /api/projects`：列出登入使用者的所有專案
- `POST   /api/projects`：建立新專案
- `GET    /api/projects/:id`：取得單一專案（含任務數量統計）
- `PUT    /api/projects/:id`：更新專案（僅限 owner）
- `DELETE /api/projects/:id`：刪除專案（**使用 Transaction**：同時刪除所有關聯任務的 task_tags）

### 4. 任務管理（`/api/projects/:projectId/tasks`，需登入）
- `GET /api/projects/:projectId/tasks`：
  - 支援查詢參數：`?status=todo&priority=high&search=關鍵字`
  - 支援分頁：`?page=1&limit=10`
  - 支援排序：`?sortBy=due_date&order=asc`
  - 回傳格式含標籤（JOIN task_tags + tags）
- `POST /api/projects/:projectId/tasks`：
  - 建立任務並同時新增標籤（**使用 Transaction**）
  - `{ title, description, status, priority, due_date, assignee_id, tag_ids: [1, 2] }`
- `PUT  /api/projects/:projectId/tasks/:id`：更新任務（含標籤替換，Transaction）
- `DELETE /api/projects/:projectId/tasks/:id`：刪除任務

### 5. 資料驗證 Middleware
- 使用 `express-validator` 或手動驗證以下規則：
  - `email`：必填、格式正確
  - `password`：必填、至少 8 字元
  - `title`：必填、最長 255 字元
  - `status`：限 `todo | in_progress | done`
  - `priority`：限 `low | medium | high`
  - `due_date`：可選，格式為 `YYYY-MM-DD`，且不得早於今天

### 6. 統一錯誤處理
- 全域 Error Handler Middleware，統一回傳格式：
  ```json
  {
    "success": false,
    "error": {
      "code": "VALIDATION_ERROR",
      "message": "title 為必填欄位",
      "details": []
    }
  }
  ```
- 自訂錯誤類別：`AppError`（含 statusCode、code 屬性）

## 提示

- 使用 `pg` 的 `pool.connect()` + `client.query('BEGIN')` 處理 Transaction
- JWT 驗證 Middleware 應統一處理 token 過期（401）與格式錯誤（400）
- 分頁查詢可搭配 `COUNT(*) OVER()` 視窗函式一次取得總筆數，避免兩次查詢
- 回應標籤時使用 `json_agg` 或 JavaScript 層合併，避免 N+1 問題
- `.env` 存放 `DATABASE_URL`、`JWT_SECRET`，勿硬寫於程式碼中
