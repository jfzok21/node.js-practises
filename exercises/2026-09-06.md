# 第 9 週今日練習題：文章列表 API 的分頁與排序

## 題目說明

建立一個部落格文章列表 API，支援**分頁**（Pagination）與**排序**（Sorting）功能。使用者可以透過查詢字串指定每頁筆數、目前頁碼以及排序欄位與方向，API 須回傳對應的資料及分頁資訊。

---

## 技術要求

- **Express.js**：建立 `GET /api/posts` 路由，解析查詢字串參數（`page`、`limit`、`sort_by`、`order`）
- **PostgreSQL**：使用 `LIMIT`、`OFFSET`、`ORDER BY` 實作分頁與排序；使用 `COUNT(*)` 取得總筆數

---

## 具體任務

1. **建立資料庫與資料表**
   ```sql
   CREATE TABLE posts (
     id SERIAL PRIMARY KEY,
     title VARCHAR(200) NOT NULL,
     author VARCHAR(100) NOT NULL,
     views INTEGER DEFAULT 0,
     created_at TIMESTAMP DEFAULT NOW()
   );
   ```
   插入至少 20 筆測試資料（可用迴圈或 `generate_series`）。

2. **建立 Express 路由 `GET /api/posts`**
   接受以下查詢字串參數：

   | 參數 | 類型 | 預設值 | 說明 |
   |------|------|--------|------|
   | `page` | 整數 | `1` | 目前頁碼（從 1 開始） |
   | `limit` | 整數 | `5` | 每頁筆數（最大 20）|
   | `sort_by` | 字串 | `created_at` | 排序欄位（允許：`id`、`title`、`views`、`created_at`） |
   | `order` | 字串 | `desc` | 排序方向（`asc` 或 `desc`） |

3. **回傳格式**
   ```json
   {
     "data": [...],
     "pagination": {
       "total": 20,
       "page": 2,
       "limit": 5,
       "total_pages": 4,
       "has_next": true,
       "has_prev": true
     }
   }
   ```

4. **防止 SQL Injection**
   `sort_by` 與 `order` 只能是白名單中的值，不可直接拼接字串進 SQL 查詢。

5. **參數驗證與錯誤處理**
   - `page` 或 `limit` 非正整數時，回傳 `400 Bad Request`
   - `page` 超過 `total_pages` 時，回傳空的 `data` 陣列，但仍提供正確的 `pagination` 資訊

---

## 提示

- 計算 `OFFSET` 的公式：`(page - 1) * limit`
- 一次查詢同時取得資料與總數：
  ```sql
  SELECT *, COUNT(*) OVER() AS total_count
  FROM posts
  ORDER BY created_at DESC
  LIMIT $1 OFFSET $2;
  ```
  或分開執行兩條查詢（`SELECT COUNT(*)` + `SELECT ...`）
- 使用 `parseInt()` 解析查詢字串，並搭配 `isNaN()` 驗證
- 白名單範例：
  ```js
  const ALLOWED_SORT = ['id', 'title', 'views', 'created_at'];
  const ALLOWED_ORDER = ['asc', 'desc'];
  ```

## 進階挑戰（選做）

1. **關鍵字搜尋 + 分頁**：新增 `?search=關鍵字` 參數，過濾 `title` 包含關鍵字的文章，並對搜尋結果同樣套用分頁與排序。
2. **游標分頁（Cursor-based Pagination）**：改用 `?cursor=<last_id>` 取代 `page` 參數，實作更適合大資料集的分頁方式，回傳 `next_cursor` 與 `prev_cursor`。
3. **快取**：使用 `node-cache` 或 `Redis` 快取相同查詢的結果，設定 TTL 為 30 秒，並在快取命中時於回應 header 加上 `X-Cache: HIT`。
