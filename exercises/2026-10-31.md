# 第 17 週今日練習題：部落格文章管理系統 API

## 題目說明

建立一個完整的部落格文章管理系統後端 API，整合前幾週所有學過的技術：JWT 身份驗證、資料驗證、分頁排序、多資料表 JOIN、交易處理與錯誤回應。這是一個接近真實專案的綜合練習。

## 技術要求
- **Express.js**：RESTful API 設計、路由參數、middleware 鏈、統一錯誤處理
- **PostgreSQL**：多資料表關聯、JOIN 查詢、全文搜尋、分頁排序、交易處理

## 具體任務

### 1. 資料庫設計（建立 migrations）

建立以下三張資料表：

```sql
-- 使用者資料表
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(50) UNIQUE NOT NULL,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 文章資料表
CREATE TABLE posts (
  id SERIAL PRIMARY KEY,
  title VARCHAR(255) NOT NULL,
  content TEXT NOT NULL,
  author_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  status VARCHAR(20) DEFAULT 'draft' CHECK (status IN ('draft', 'published', 'archived')),
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- 標籤資料表（多對多）
CREATE TABLE tags (
  id SERIAL PRIMARY KEY,
  name VARCHAR(50) UNIQUE NOT NULL
);

CREATE TABLE post_tags (
  post_id INTEGER REFERENCES posts(id) ON DELETE CASCADE,
  tag_id INTEGER REFERENCES tags(id) ON DELETE CASCADE,
  PRIMARY KEY (post_id, tag_id)
);
```

### 2. 身份驗證路由

實作以下端點：

```
POST /api/auth/register   - 註冊新使用者
POST /api/auth/login      - 登入，回傳 JWT token
GET  /api/auth/me         - 取得目前登入使用者資訊（需 JWT）
```

### 3. 文章 CRUD 路由

```
GET    /api/posts              - 取得所有已發布文章（分頁、排序、標籤篩選）
GET    /api/posts/:id          - 取得單篇文章（含作者名稱與標籤列表）
POST   /api/posts              - 新增文章（需 JWT，可同時新增標籤）
PUT    /api/posts/:id          - 更新文章（需 JWT，只有作者可更新）
DELETE /api/posts/:id          - 刪除文章（需 JWT，只有作者可刪除）
GET    /api/posts/search?q=    - 全文搜尋文章標題與內容
```

### 4. 分頁與排序實作

`GET /api/posts` 支援以下 query 參數：
- `page`（預設 1）
- `limit`（預設 10，最大 50）
- `sortBy`（`created_at` 或 `title`，預設 `created_at`）
- `order`（`asc` 或 `desc`，預設 `desc`）
- `tag`（依標籤名稱篩選）

回應格式：
```json
{
  "data": [...],
  "pagination": {
    "page": 1,
    "limit": 10,
    "total": 42,
    "totalPages": 5
  }
}
```

### 5. 使用交易處理新增文章含標籤

新增文章時，若同時帶入 `tags` 陣列，需在同一個交易內：
1. INSERT 文章到 `posts`
2. 對每個標籤 UPSERT 到 `tags`（不存在才新增）
3. INSERT 對應關聯到 `post_tags`

任一步驟失敗則全部 ROLLBACK。

### 6. 統一錯誤處理 Middleware

```javascript
// 範例格式
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "標題不得為空",
    "details": [...]   // 選填
  }
}
```

常見 HTTP 狀態碼對應：
- `400` 資料驗證失敗
- `401` 未登入 / token 無效
- `403` 無權限操作
- `404` 資源不存在
- `500` 伺服器內部錯誤

## 提示

- 使用 `bcrypt` 進行密碼雜湊，`jsonwebtoken` 產生 JWT
- 分頁查詢可用 `LIMIT $1 OFFSET $2`，total 用 `COUNT(*)` 另外查
- 全文搜尋可用 `WHERE title ILIKE $1 OR content ILIKE $1`（`$1 = '%關鍵字%'`）
- 多對多 JOIN 可用 `array_agg(tags.name)` 搭配 `GROUP BY posts.id` 一次取回標籤陣列
- 建議建立 `src/middleware/auth.js`、`src/middleware/errorHandler.js` 分離關切點
- 用 `pg` 的 `pool.connect()` → `client.query()` → `client.release()` 管理交易

## 進階挑戰（選做）

1. **軟刪除**：改用 `deleted_at TIMESTAMP` 欄位取代實際刪除，所有查詢加上 `WHERE deleted_at IS NULL`
2. **快取**：使用 `node-cache` 或 Redis 快取熱門文章列表（TTL 60 秒）
3. **Rate Limiting**：使用 `express-rate-limit` 限制登入端點每分鐘最多 5 次請求
4. **API 測試**：用 `supertest + Jest` 為所有端點撰寫整合測試，包含驗證邊界條件
5. **Swagger 文件**：使用 `swagger-jsdoc` 加上 JSDoc 註解自動產生 API 文件
