# 第 13 週今日練習題：實戰專案 — 任務管理 API

## 題目說明

建構一個完整的「任務管理系統」RESTful API，整合前 12 週所學的所有技術：Express 路由、PostgreSQL CRUD、Middleware、JWT 身份驗證、資料驗證、分頁排序、以及交易處理。這是一個貼近真實工作場景的全端 API 專案。

## 技術要求

- **Express.js**：模組化路由結構（`/auth`、`/projects`、`/tasks`）、全域錯誤處理 Middleware、JWT 保護路由
- **PostgreSQL**：多資料表關聯（users、projects、tasks）、JOIN 查詢、Transaction 確保資料一致性
- **驗證**：輸入資料驗證（joi 或自訂）、HTTP 狀態碼語意正確

## 資料庫結構

```sql
-- 使用者
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 專案
CREATE TABLE projects (
  id SERIAL PRIMARY KEY,
  owner_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  name VARCHAR(255) NOT NULL,
  description TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 任務
CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  project_id INTEGER REFERENCES projects(id) ON DELETE CASCADE,
  assigned_to INTEGER REFERENCES users(id) ON DELETE SET NULL,
  title VARCHAR(255) NOT NULL,
  status VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending','in_progress','done')),
  due_date DATE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

## 具體任務

1. **初始化專案結構**
   - 建立 `src/routes/`、`src/middleware/`、`src/db/` 目錄
   - 設定 `pool.js`（pg Pool）與環境變數（`.env`）
   - 執行上方 SQL 建立資料表

2. **實作身份驗證模組** (`src/routes/auth.js`)
   - `POST /auth/register`：接收 email + password，bcrypt hash 後寫入 users，回傳 JWT
   - `POST /auth/login`：驗證密碼，回傳 JWT（payload 含 `userId`、`email`）
   - 建立 `src/middleware/auth.js`：從 `Authorization: Bearer <token>` 解析 JWT，掛載 `req.user`

3. **專案 CRUD** (`src/routes/projects.js`)，全部需要 JWT 驗證
   - `GET /projects`：列出目前登入者的所有專案（支援 `?page=&limit=` 分頁）
   - `POST /projects`：建立專案（owner 自動設為登入者）
   - `DELETE /projects/:id`：刪除專案（僅 owner 可刪，同時用 Transaction 刪除所有子任務）

4. **任務 CRUD** (`src/routes/tasks.js`)，全部需要 JWT 驗證
   - `GET /projects/:projectId/tasks`：列出專案任務，支援 `?status=&sort=due_date&order=asc`
   - `POST /projects/:projectId/tasks`：新增任務（驗證 projectId 屬於登入者）
   - `PATCH /tasks/:id`：更新任務狀態或截止日（部分更新）
   - `DELETE /tasks/:id`：刪除任務

5. **全域錯誤處理 Middleware**
   - 捕捉所有未處理錯誤，回傳 `{ error: "訊息" }` + 適當 HTTP 狀態碼
   - 區分 404（找不到資源）、403（無權限）、400（驗證失敗）、500（伺服器錯誤）

## 提示

- 使用 `express-async-errors` 套件可讓 async route handler 的錯誤自動傳給錯誤 Middleware，避免到處寫 `try/catch`
- DELETE 專案時包在 `BEGIN ... COMMIT` Transaction 裡：先刪 tasks，再刪 project，避免外鍵違反
- `PATCH` 任務時用動態 SQL 或 `COALESCE(input, existing_value)` 實作部分更新
- JWT secret 務必放 `.env`，不要 hardcode
- 分頁查詢搭配 `LIMIT $1 OFFSET $2`，`offset = (page - 1) * limit`

## 進階挑戰（選做）

- **任務統計**：`GET /projects/:id/stats` 回傳各狀態任務數量（用 `COUNT + GROUP BY status`）
- **任務搜尋**：`GET /tasks?q=關鍵字` 跨所有任務全文搜尋（`ILIKE '%關鍵字%'`）
- **API 測試**：用 `supertest + Jest` 撰寫至少 5 個整合測試（含正常流程與錯誤情境）
- **Rate Limiting**：加入 `express-rate-limit`，限制每個 IP 每分鐘最多 60 次請求
