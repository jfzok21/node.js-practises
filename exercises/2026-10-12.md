# 第 14 週今日練習題：部落格 API 實戰專案（完整功能整合）

## 題目說明

建立一個完整的部落格後端 API，整合前幾週學到的所有技術：Express 路由、PostgreSQL CRUD、JWT 身份驗證、資料驗證、分頁、JOIN 查詢、交易處理，以及 API 測試。這是一個貼近真實工作場景的實戰練習，目標是交出一個可部署的 RESTful API 服務。

## 技術要求
- **Express.js**：模組化路由設計（`/auth`、`/posts`、`/comments`）、全域錯誤處理 middleware、JWT 保護路由
- **PostgreSQL**：多資料表設計（users、posts、comments、tags）、JOIN 查詢、Transaction 處理

## 具體任務

1. **資料庫設計與初始化**
   建立 `schema.sql` 並執行以下資料表設計：
   ```sql
   CREATE TABLE users (
     id SERIAL PRIMARY KEY,
     email VARCHAR(255) UNIQUE NOT NULL,
     password_hash VARCHAR(255) NOT NULL,
     username VARCHAR(100) NOT NULL,
     created_at TIMESTAMP DEFAULT NOW()
   );

   CREATE TABLE posts (
     id SERIAL PRIMARY KEY,
     title VARCHAR(300) NOT NULL,
     content TEXT NOT NULL,
     author_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
     is_published BOOLEAN DEFAULT false,
     created_at TIMESTAMP DEFAULT NOW(),
     updated_at TIMESTAMP DEFAULT NOW()
   );

   CREATE TABLE comments (
     id SERIAL PRIMARY KEY,
     content TEXT NOT NULL,
     post_id INTEGER REFERENCES posts(id) ON DELETE CASCADE,
     author_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
     created_at TIMESTAMP DEFAULT NOW()
   );

   CREATE TABLE tags (
     id SERIAL PRIMARY KEY,
     name VARCHAR(50) UNIQUE NOT NULL
   );

   CREATE TABLE post_tags (
     post_id INTEGER REFERENCES posts(id) ON DELETE CASCADE,
     tag_id INTEGER REFERENCES tags(id) ON DELETE CASCADE,
     PRIMARY KEY (post_id, tag_id)
   );
   ```

2. **身份驗證路由 `/auth`**
   - `POST /auth/register`：註冊（bcrypt 雜湊密碼）
   - `POST /auth/login`：登入，回傳 JWT token
   - 驗證規則：email 格式、密碼至少 8 字元、username 必填

3. **文章路由 `/posts`（部分需要 JWT）**
   - `GET /posts`：取得已發布文章列表（分頁：`?page=1&limit=10`，支援 `?tag=` 篩選）
   - `GET /posts/:id`：取得單篇文章詳情（含作者資訊、留言數、標籤列表）
   - `POST /posts`：建立文章（需登入），支援同時新增標籤（使用 Transaction）
   - `PUT /posts/:id`：更新文章（僅作者本人）
   - `DELETE /posts/:id`：刪除文章（僅作者本人，使用 Transaction 同時刪除相關資料）
   - `PATCH /posts/:id/publish`：發布 / 取消發布文章

4. **留言路由 `/posts/:postId/comments`（需要 JWT）**
   - `GET /posts/:postId/comments`：取得某文章所有留言（含作者 username）
   - `POST /posts/:postId/comments`：新增留言
   - `DELETE /posts/:postId/comments/:commentId`：刪除留言（僅作者本人）

5. **查詢整合（JOIN 實作）**
   取得文章詳情時，單一查詢回傳以下格式：
   ```json
   {
     "id": 1,
     "title": "Hello World",
     "content": "...",
     "author": { "id": 1, "username": "alice" },
     "tags": ["nodejs", "express"],
     "comment_count": 5,
     "created_at": "2026-10-12T00:00:00Z"
   }
   ```

6. **撰寫 API 測試（supertest + Jest）**
   至少涵蓋：
   - 未登入存取受保護路由應回傳 401
   - 成功建立文章並驗證回傳格式
   - 分頁查詢回傳正確筆數
   - 刪除他人文章應回傳 403

## 提示
- 路由模組化：`routes/auth.js`、`routes/posts.js`、`routes/comments.js`，在 `app.js` 統一掛載
- 使用 `pg` 套件的 `pool.connect()` 手動管理 Transaction（`BEGIN` / `COMMIT` / `ROLLBACK`）
- JWT middleware 寫成獨立的 `middlewares/authenticate.js`，需要保護的路由直接引用
- 錯誤處理：統一在 `app.js` 最後加 `app.use((err, req, res, next) => {...})` 接住所有未處理錯誤
- 分頁計算：`LIMIT $1 OFFSET $2`，offset = (page - 1) * limit

## 進階挑戰（選做）

- **全文搜尋**：`GET /posts?search=keyword` 使用 PostgreSQL `ILIKE` 或 `to_tsvector` 實作搜尋
- **草稿功能**：登入用戶可取得自己的草稿列表 `GET /posts/drafts`
- **留言計數優化**：使用 `WITH` CTE 或子查詢，避免 N+1 問題
- **Rate Limiting**：使用 `express-rate-limit` 限制 `/auth/login` 每分鐘最多 5 次請求
- **Swagger 文件**：使用 `swagger-jsdoc` + `swagger-ui-express` 自動生成 API 文件
