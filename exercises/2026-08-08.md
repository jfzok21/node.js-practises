# 第 5 週今日練習題：書店訂單系統 JOIN 查詢

## 題目說明

建立一個書店後端 API，資料庫包含多個資料表（使用者、書籍、訂單），並透過 JOIN 查詢將資料整合後回傳給前端。這個練習的重點在於理解多資料表之間的關聯，以及如何在 Express 路由中組合複雜的 SQL 查詢。

## 技術要求

- **Express.js**：建立 RESTful API 路由，處理 GET 請求並回傳 JSON 格式資料
- **PostgreSQL**：設計多資料表結構，使用 INNER JOIN、LEFT JOIN 組合查詢結果

## 具體任務

1. **建立資料表結構**

   執行以下 SQL 初始化資料庫：

   ```sql
   CREATE TABLE users (
     id SERIAL PRIMARY KEY,
     name VARCHAR(100) NOT NULL,
     email VARCHAR(150) UNIQUE NOT NULL,
     created_at TIMESTAMP DEFAULT NOW()
   );

   CREATE TABLE books (
     id SERIAL PRIMARY KEY,
     title VARCHAR(200) NOT NULL,
     author VARCHAR(100) NOT NULL,
     price NUMERIC(8, 2) NOT NULL,
     stock INT DEFAULT 0
   );

   CREATE TABLE orders (
     id SERIAL PRIMARY KEY,
     user_id INT REFERENCES users(id),
     book_id INT REFERENCES books(id),
     quantity INT NOT NULL DEFAULT 1,
     ordered_at TIMESTAMP DEFAULT NOW()
   );
   ```

   並插入幾筆測試資料（至少 3 位使用者、5 本書、8 筆訂單）。

2. **實作 GET `/orders` — 取得所有訂單（含使用者與書籍資訊）**

   回傳格式範例：
   ```json
   [
     {
       "order_id": 1,
       "user_name": "Alice",
       "book_title": "Node.js 實戰",
       "quantity": 2,
       "total_price": 1200.00,
       "ordered_at": "2026-08-08T10:00:00.000Z"
     }
   ]
   ```

   提示：`total_price = quantity * books.price`，在 SQL 層計算。

3. **實作 GET `/users/:id/orders` — 取得特定使用者的所有訂單**

   - 若使用者不存在或沒有訂單，回傳空陣列（而非 404）
   - 使用 LEFT JOIN 確保即使沒有訂單也能找到使用者

4. **實作 GET `/books/:id/buyers` — 取得購買過某本書的所有使用者**

   回傳格式範例：
   ```json
   {
     "book_id": 3,
     "title": "PostgreSQL 從入門到精通",
     "buyers": [
       { "user_id": 1, "name": "Alice", "quantity": 1 },
       { "user_id": 2, "name": "Bob", "quantity": 3 }
     ]
   }
   ```

5. **實作 GET `/stats/top-books` — 取得銷售量前 3 名的書籍**

   使用 `GROUP BY` + `ORDER BY` + `LIMIT`，統計每本書的總銷售數量。

## 提示

- 在 Express 路由中，SQL 查詢可以包含多行，建議使用模板字串：
  ```js
  const result = await pool.query(`
    SELECT o.id AS order_id, u.name AS user_name, ...
    FROM orders o
    JOIN users u ON o.user_id = u.id
    JOIN books b ON o.book_id = b.id
  `);
  ```
- JOIN 類型選擇：
  - `INNER JOIN`：只回傳兩邊都有資料的列（適合訂單查詢）
  - `LEFT JOIN`：保留左側資料表所有列（適合「查使用者及其訂單，即使沒訂單也顯示」）
- 若要在 `GROUP BY` 之後再過濾，要使用 `HAVING`，而非 `WHERE`
- 使用 `pg` 套件時，參數化查詢格式為 `$1, $2`，第二個引數傳入陣列：`pool.query(sql, [userId])`

## 進階挑戰（選做）

- 為 `GET /orders` 加上查詢字串過濾，支援 `?user_id=1` 或 `?min_price=500` 動態篩選
- 加入分頁：支援 `?page=1&limit=10`（用 `OFFSET` + `LIMIT` 實作）
- 計算每位使用者的消費總額，建立 `GET /stats/top-spenders` API，回傳消費金額前 5 名
