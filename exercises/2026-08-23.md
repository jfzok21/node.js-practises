# 第 7 週今日練習題：JWT 身份驗證系統

## 題目說明

實作一套基於 JSON Web Token（JWT）的使用者身份驗證 API，包含使用者註冊、登入，以及受保護路由的存取控制。這是現代 Web API 最常見的無狀態驗證機制。

## 技術要求

- **Express.js**：建立 `/auth/register`、`/auth/login`、`/profile` 路由，使用自訂 middleware 驗證 JWT
- **PostgreSQL**：儲存使用者資料（id、email、password_hash、created_at），以 email 為唯一索引
- **套件**：`jsonwebtoken`、`bcrypt`（或 `bcryptjs`）、`pg`

## 具體任務

1. **建立資料庫 schema**
   ```sql
   CREATE TABLE users (
     id SERIAL PRIMARY KEY,
     email VARCHAR(255) UNIQUE NOT NULL,
     password_hash VARCHAR(255) NOT NULL,
     created_at TIMESTAMPTZ DEFAULT NOW()
   );
   ```

2. **實作 `POST /auth/register`**
   - 接收 `{ email, password }`
   - 用 `bcrypt.hash(password, 10)` 加密密碼
   - 將使用者存入 PostgreSQL
   - 回傳 `{ message: "註冊成功", userId }` 或 409 若 email 已存在

3. **實作 `POST /auth/login`**
   - 接收 `{ email, password }`
   - 從 DB 查詢使用者，用 `bcrypt.compare` 驗證密碼
   - 驗證成功後用 `jwt.sign({ userId, email }, SECRET, { expiresIn: '1h' })` 產生 token
   - 回傳 `{ token }` 或 401 若帳密錯誤

4. **實作 JWT Middleware（`authenticateToken`）**
   - 從 `Authorization: Bearer <token>` header 取出 token
   - 用 `jwt.verify(token, SECRET)` 驗證
   - 驗證成功後將 payload 掛到 `req.user`，否則回傳 401/403

5. **實作受保護路由 `GET /profile`**
   - 套用 `authenticateToken` middleware
   - 從 DB 查詢 `req.user.userId` 的使用者資料
   - 回傳 `{ id, email, created_at }`（不含密碼）

## 提示

- 將 JWT Secret 放在 `.env` 中，使用 `process.env.JWT_SECRET`，不要硬寫在程式裡
- `bcrypt.hash` 和 `bcrypt.compare` 都是非同步的，記得 `await`
- Middleware 的函式簽名是 `(req, res, next)`，驗證失敗要 `return res.status(401).json(...)` 避免繼續執行
- 可用 Postman 或 curl 測試：先 register → login 取得 token → 帶 token 存取 `/profile`
- JWT payload 不要放敏感資訊（如密碼），因為 payload 只是 Base64 編碼，任何人都能解碼

## 進階挑戰（選做）

- **Refresh Token**：實作 `POST /auth/refresh`，用長效 refresh token 換取新的 access token，並將 refresh token 存入 DB 以便撤銷
- **登出功能**：實作 Token 黑名單（用 DB 或 Redis 記錄已撤銷的 token）
- **角色權限**：在 JWT payload 加入 `role`（`admin` / `user`），並建立只有 admin 能存取的路由
- **密碼強度驗證**：在 register 時檢查密碼長度 ≥ 8、含大小寫與數字，否則回傳 400 錯誤
