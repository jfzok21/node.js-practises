# 第 4 週今日練習題：Express Middleware 中間件實作

## 題目說明

本週的核心主題是 **Express Middleware（中間件）**。Middleware 是 Express 框架的靈魂，每個請求在到達路由處理器之前，都會依序通過一連串的中間件函式。你將學會如何撰寫自訂中間件、使用第三方中間件（body-parser / express.json），以及建立統一的錯誤處理機制。

## 技術要求

- **Express.js**：自訂 middleware、application-level 與 router-level middleware、錯誤處理 middleware（4 個參數 `err, req, res, next`）
- **PostgreSQL**：在 middleware 層進行簡單的身份查驗（從 DB 查詢使用者），CRUD 操作搭配錯誤回應

## 具體任務

1. **建立專案結構**
   - 初始化 `npm` 專案，安裝 `express`、`pg`、`dotenv`
   - 建立資料夾結構：`middlewares/`、`routes/`、`db/`
   - 在 `db/index.js` 設定 PostgreSQL 連線 Pool

2. **建立 PostgreSQL 資料表**

   在資料庫執行以下 SQL：

   ```sql
   CREATE TABLE IF NOT EXISTS api_logs (
     id SERIAL PRIMARY KEY,
     method VARCHAR(10),
     path TEXT,
     status_code INT,
     duration_ms INT,
     created_at TIMESTAMPTZ DEFAULT NOW()
   );

   CREATE TABLE IF NOT EXISTS users (
     id SERIAL PRIMARY KEY,
     name VARCHAR(100) NOT NULL,
     email VARCHAR(150) UNIQUE NOT NULL,
     api_key VARCHAR(64) UNIQUE NOT NULL,
     created_at TIMESTAMPTZ DEFAULT NOW()
   );

   INSERT INTO users (name, email, api_key)
   VALUES ('測試使用者', 'test@example.com', 'my-secret-api-key-12345')
   ON CONFLICT DO NOTHING;
   ```

3. **實作三個自訂 Middleware**

   **a. 請求日誌 Middleware（`middlewares/logger.js`）**
   - 記錄每個請求的方法、路徑、執行時間（ms）
   - 請求完成後，將日誌寫入 PostgreSQL `api_logs` 資料表
   - 使用 `res.on('finish', callback)` 事件在回應結束後記錄資料

   **b. API Key 驗證 Middleware（`middlewares/auth.js`）**
   - 從 request header `x-api-key` 取得 API Key
   - 查詢 PostgreSQL `users` 資料表驗證 key 是否合法
   - 若驗證成功，將使用者資訊掛載到 `req.user`，呼叫 `next()`
   - 若驗證失敗，回傳 `401 Unauthorized` JSON 錯誤

   **c. 統一錯誤處理 Middleware（`middlewares/errorHandler.js`）**
   - 接受 4 個參數 `(err, req, res, next)`
   - 根據 `err.status` 或 `err.statusCode` 決定 HTTP 狀態碼（預設 500）
   - 回傳統一格式：`{ "error": true, "message": "..." }`

4. **建立受保護的路由（`routes/protected.js`）**

   在路由上套用 auth middleware，實作以下端點：

   | Method | Path | 說明 |
   |--------|------|------|
   | `GET` | `/api/me` | 回傳當前使用者資訊（來自 `req.user`） |
   | `GET` | `/api/logs` | 從 DB 查詢最近 20 筆 `api_logs`，由新到舊排序 |
   | `POST` | `/api/trigger-error` | 故意呼叫 `next(new Error("測試錯誤"))` 以觸發錯誤處理 |

5. **在 `app.js` 中組裝所有部件**

   ```js
   const express = require('express');
   const app = express();

   // 1. 內建 middleware
   app.use(express.json());

   // 2. 自訂 logger（套用到所有路由）
   app.use(require('./middlewares/logger'));

   // 3. 路由（auth middleware 在 router 層套用）
   app.use(require('./routes/protected'));

   // 4. 錯誤處理（必須放在最後）
   app.use(require('./middlewares/errorHandler'));

   app.listen(3000, () => console.log('Server running on port 3000'));
   ```

6. **測試你的 API**

   ```bash
   # 有效請求（帶正確 API Key）
   curl -H "x-api-key: my-secret-api-key-12345" http://localhost:3000/api/me

   # 無效請求（應得到 401）
   curl -H "x-api-key: wrong-key" http://localhost:3000/api/me

   # 無 API Key（應得到 401）
   curl http://localhost:3000/api/me

   # 觸發錯誤（應得到 500 + 統一錯誤格式）
   curl -H "x-api-key: my-secret-api-key-12345" -X POST http://localhost:3000/api/trigger-error

   # 查詢日誌（確認每筆請求都有被記錄）
   curl -H "x-api-key: my-secret-api-key-12345" http://localhost:3000/api/logs
   ```

## 提示

- Middleware 函式簽名：`(req, res, next) => {}`；錯誤處理 middleware 簽名：`(err, req, res, next) => {}`，Express 靠參數數量判斷種類
- 呼叫 `next()` 代表「繼續往下」；呼叫 `next(err)` 代表「發生錯誤，跳至錯誤處理 middleware」
- `res.on('finish', ...)` 是在回應已寫入、連線尚未關閉時觸發，適合用於非同步日誌記錄
- 記得用 `try/catch` 包住 async 操作，並在 catch 內呼叫 `next(err)`
- `.env` 範例：`DATABASE_URL=postgresql://user:password@localhost:5432/mydb`

## 進階挑戰（選做）

- **Rate Limiting**：實作一個 middleware，利用 `req.ip` 追蹤每個 IP 每分鐘的請求次數，超過 10 次回傳 `429 Too Many Requests`（資料可暫存在記憶體 Map 中，不需 Redis）
- **請求 Body 大小限制**：在 `express.json()` 中設定 `{ limit: '10kb' }`，觀察傳入大型 payload 時的行為
- **Conditional Middleware**：建立一個 helper 函式 `unless(middleware, ...paths)`，讓指定路徑跳過某個 middleware（例如讓 `/health` 跳過 auth 驗證）
- **Structured Logging**：改用 `pino` 或 `winston` 套件，將日誌以 JSON 格式輸出到 console 並同時寫入 DB
