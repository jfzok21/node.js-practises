# 第 11 週今日練習題：用 Supertest + Jest 測試 Express API

## 題目說明

你已建立了一個可運作的 Express + PostgreSQL REST API。本週的目標是學習如何撰寫自動化 API 測試，確保每次程式碼變動後，API 行為仍然正確。你將使用 **Jest** 作為測試框架、**Supertest** 作為 HTTP 測試工具，針對一組「書籍管理」API 撰寫完整的整合測試。

---

## 技術要求

- **Express.js**：建立一個簡單的書籍 CRUD API（若尚未建立，請在測試前先快速搭建）
- **PostgreSQL**：使用獨立的測試資料庫（`books_test`），避免污染開發資料
- **Jest**：設定測試環境、撰寫測試案例、使用 `beforeAll` / `afterAll` / `beforeEach` 管理測試生命週期
- **Supertest**：以程式方式發送 HTTP 請求，驗證回應狀態碼與回傳資料

---

## 具體任務

### 任務一：環境設定

1. 安裝相依套件：
   ```bash
   npm install --save-dev jest supertest
   ```
2. 在 `package.json` 加入測試腳本：
   ```json
   "scripts": {
     "test": "jest --runInBand"
   }
   ```
3. 建立測試資料庫 `books_test`，並設定 `.env.test`：
   ```
   DATABASE_URL=postgresql://user:password@localhost:5432/books_test
   ```
4. 確保 `app.js`（或 `server.js`）將 Express app **匯出**（`module.exports = app`），但不在匯出時啟動 `listen()`，讓 Supertest 自行管理連接埠。

### 任務二：建立測試檔案結構

建立 `tests/books.test.js`，實作以下測試案例：

```
books API
  GET /api/books
    ✓ 應回傳空陣列（資料庫初始為空）
    ✓ 應回傳 200 狀態碼
  POST /api/books
    ✓ 成功新增一本書，應回傳 201 與書籍資料
    ✓ 缺少必填欄位時，應回傳 400
  GET /api/books/:id
    ✓ 取得存在的書籍，應回傳 200 與正確資料
    ✓ 取得不存在的書籍，應回傳 404
  PUT /api/books/:id
    ✓ 成功更新書籍，應回傳 200 與更新後資料
  DELETE /api/books/:id
    ✓ 成功刪除書籍，應回傳 204
    ✓ 刪除後再次 GET，應回傳 404
```

### 任務三：實作測試案例

在 `tests/books.test.js` 中完成以下結構：

```javascript
const request = require('supertest');
const app = require('../app');
const db = require('../db'); // 你的資料庫連線模組

// 每個測試開始前，清空資料表
beforeEach(async () => {
  await db.query('TRUNCATE TABLE books RESTART IDENTITY CASCADE');
});

// 所有測試結束後，關閉資料庫連線
afterAll(async () => {
  await db.end();
});

describe('GET /api/books', () => {
  it('應回傳 200 與空陣列', async () => {
    const res = await request(app).get('/api/books');
    expect(res.statusCode).toBe(200);
    expect(res.body).toEqual([]);
  });
});

describe('POST /api/books', () => {
  it('應成功新增書籍並回傳 201', async () => {
    const newBook = { title: '深入淺出 Node.js', author: '朴靈', year: 2013 };
    const res = await request(app).post('/api/books').send(newBook);
    expect(res.statusCode).toBe(201);
    expect(res.body).toMatchObject(newBook);
    expect(res.body.id).toBeDefined();
  });

  it('缺少 title 時應回傳 400', async () => {
    const res = await request(app).post('/api/books').send({ author: '佚名' });
    expect(res.statusCode).toBe(400);
  });
});

// 繼續完成 GET /:id、PUT /:id、DELETE /:id 的測試…
```

```bash
NODE_ENV=test npm test
```

## 提示

- **應用程式與測試資料庫分離**：透過 `NODE_ENV=test` 環境變數切換資料庫連線，避免刪除開發資料。
- **`--runInBand` 旗標**：讓 Jest 按順序執行測試（非平行），防止多個測試同時修改資料庫造成衝突。
- **`beforeEach` 清空資料**：每個測試案例應從乾淨的資料庫狀態開始，確保測試互相獨立。
- **`toMatchObject` vs `toEqual`**：`toMatchObject` 只驗證你關心的欄位（忽略 `created_at` 等額外欄位），`toEqual` 則要求完全相符。
- **關閉連線**：忘記在 `afterAll` 關閉資料庫連線，Jest 會在測試結束後出現「開放的連線控制代碼」警告而卡住。

## 進階挑戰（選做）

1. **測試覆蓋率報告**：在 `package.json` 加入 `"test:coverage": "jest --coverage"`，觀察哪些程式碼路徑尚未被測試覆蓋。

2. **測試認證端點**：若你的 API 有 JWT 保護，撰寫測試先呼叫 `/api/auth/login` 取得 token，再帶入 `Authorization: Bearer <token>` 標頭測試受保護的路由。

3. **測試 Middleware**：驗證未認證請求確實被擋下，回傳 401；驗證格式錯誤的請求觸發你的驗證 middleware，回傳 422。

4. **資料庫遷移腳本**：建立 `scripts/setup-test-db.js`，讓 CI 管線能自動建立測試資料庫與資料表，達到一鍵執行測試的目標。
