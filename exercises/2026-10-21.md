# 第 16 週今日練習題：部落格 API 實戰專案（完整後端）

## 題目說明

實作一個具備完整功能的部落格後端 API，涵蓋使用者認證、文章管理、留言系統與分頁查詢。本練習整合前 15 週所學的所有技術，模擬真實工作場景中的後端開發流程。

---

## 技術要求

- **Express.js**：路由模組化、Middleware 鏈（驗證、錯誤處理、日誌）、RESTful 設計
- **PostgreSQL**：多資料表關聯、JOIN 查詢、Transaction、分頁與排序
- **JWT**：使用者登入 / 登出、受保護路由
- **資料驗證**：請求參數與 body 驗證，統一錯誤格式
- **multer**（選做）：文章封面圖片上傳

---

## 具體任務

### 1. 資料庫設計

建立以下三張資料表：

```sql
-- 使用者
CREATE TABLE users (
  id        SERIAL PRIMARY KEY,
  username  VARCHAR(50)  UNIQUE NOT NULL,
  email     VARCHAR(100) UNIQUE NOT NULL,
  password  VARCHAR(255) NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 文章
CREATE TABLE posts (
  id         SERIAL PRIMARY KEY,
  user_id    INT REFERENCES users(id) ON DELETE CASCADE,
  title      VARCHAR(200) NOT NULL,
  content    TEXT NOT NULL,
  cover_url  VARCHAR(500),
  published  BOOLEAN DEFAULT false,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 留言
CREATE TABLE comments (
  id         SERIAL PRIMARY KEY,
  post_id    INT REFERENCES posts(id) ON DELETE CASCADE,
  user_id    INT REFERENCES users(id) ON DELETE CASCADE,
  body       TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 2. 身份驗證 API

| 方法 | 路徑 | 說明 |
|------|------|------|
| POST | /api/auth/register | 註冊新使用者（bcrypt 雜湊密碼） |
| POST | /api/auth/login    | 登入，回傳 JWT access token |

### 3. 文章 API（部分路由需驗證）

| 方法   | 路徑              | 驗證 | 說明 |
|--------|-------------------|------|------|
| GET    | /api/posts        | 否   | 列出所有已發布文章（分頁 + 排序） |
| GET    | /api/posts/:id    | 否   | 取得單篇文章（含作者資訊） |
| POST   | /api/posts        | 是   | 建立新文章 |
| PUT    | /api/posts/:id    | 是   | 更新文章（只有作者可操作） |
| DELETE | /api/posts/:id    | 是   | 刪除文章（只有作者可操作） |

### 4. 留言 API

| 方法   | 路徑                        | 驗證 | 說明 |
|--------|----------------------------|------|------|
| GET    | /api/posts/:id/comments    | 否   | 取得文章所有留言 |
| POST   | /api/posts/:id/comments    | 是   | 新增留言 |
| DELETE | /api/comments/:commentId   | 是   | 刪除留言（只有留言者可操作） |

### 5. 分頁查詢格式

`GET /api/posts?page=1&limit=10&sort=created_at&order=DESC`

回傳格式：
```json
{
  "data": [...],
  "pagination": {
    "page": 1,
    "limit": 10,
    "total": 42,
    "totalPages": 5
  }
}
```

### 6. 統一錯誤處理 Middleware

所有錯誤回應格式統一為：
```json
{
  "error": {
    "code": "NOT_FOUND",
    "message": "文章不存在"
  }
}
```

### 7. 使用 Transaction 確保資料一致性

刪除文章時，在同一個 Transaction 中同步刪除其所有留言，確保不留孤立資料。

---

## 提示

- 使用 `pg` 套件連線 PostgreSQL；連線設定建議放在 `db/pool.js` 統一管理
- JWT 驗證 Middleware 可提取 `req.user`，後續路由直接使用
- 「只有作者可操作」邏輯：先查詢資料庫確認 `user_id === req.user.id`，不符合則回傳 403
- `updated_at` 欄位在 UPDATE 時需手動設定 `updated_at = NOW()`
- 分頁的 `offset = (page - 1) * limit`，`total` 用 `COUNT(*) OVER()` 或另下 COUNT 查詢

## 進階挑戰（選做）

1. **搜尋功能**：`GET /api/posts?search=關鍵字`，對 `title` 與 `content` 進行全文搜尋（使用 `ILIKE` 或 PostgreSQL `tsvector`）
2. **封面圖片上傳**：在建立 / 更新文章時，支援以 `multipart/form-data` 上傳圖片，並將路徑存入 `cover_url`
3. **Rate Limiting**：使用 `express-rate-limit` 為登入路由加上頻率限制（每 15 分鐘最多 10 次）
4. **整合測試**：使用 `supertest + Jest` 為至少 5 個 API 端點撰寫測試
