# 第 17 週今日練習題：任務管理 API（全功能實戰專案）

## 題目說明

實作一個完整的任務管理系統 REST API，涵蓋使用者認證、任務 CRUD、分頁排序、資料驗證與錯誤處理，整合前幾週所學的所有核心技能。

## 技術要求

- **Express.js**：路由模組化、Middleware 鏈（認證、驗證、錯誤攔截）
- **PostgreSQL**：多資料表設計（users、tasks、categories）、JOIN 查詢、Transaction
- **其他**：JWT 身份驗證、bcrypt 密碼雜湊、資料驗證、分頁與排序

## 資料庫結構

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE categories (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  name VARCHAR(100) NOT NULL
);

CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  category_id INTEGER REFERENCES categories(id) ON DELETE SET NULL,
  title VARCHAR(255) NOT NULL,
  description TEXT,
  status VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending', 'in_progress', 'done')),
  due_date DATE,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

## 具體任務

### 1. 專案初始化
```
mkdir task-manager-api && cd task-manager-api
npm init -y
npm install express pg bcryptjs jsonwebtoken express-validator dotenv
npm install -D jest supertest
```
建立目錄結構：
```
src/
  routes/        # auth.js, tasks.js, categories.js
  middleware/    # auth.js, validate.js, errorHandler.js
  controllers/   # authController.js, taskController.js
  db/            # index.js (pg pool)
```

### 2. 實作使用者認證模組
- `POST /api/auth/register`：接收 email + password，bcrypt 雜湊後存入 DB，回傳 JWT
- `POST /api/auth/login`：驗證帳密，成功回傳 JWT（含 userId payload）
- 撰寫 `authenticateToken` middleware，驗證 Bearer token 並將 `req.user` 注入下游

### 3. 實作任務 CRUD API（需通過認證）
- `GET /api/tasks`：列出當前使用者的所有任務，支援：
  - `?status=pending|in_progress|done` 篩選
  - `?category_id=N` 篩選
  - `?sort=due_date|created_at&order=asc|desc` 排序
  - `?page=1&limit=10` 分頁，回應含 `{ data, total, page, totalPages }`
- `GET /api/tasks/:id`：取得單一任務（含 category 名稱，使用 JOIN）
- `POST /api/tasks`：建立任務，驗證 title 必填、status 合法、due_date 格式正確
- `PATCH /api/tasks/:id`：部分更新，自動更新 `updated_at`
- `DELETE /api/tasks/:id`：刪除任務（只能刪自己的）

### 4. 實作分類管理 API
- `GET /api/categories`：列出當前使用者的分類（含各分類任務數量）
- `POST /api/categories`：建立分類
- `DELETE /api/categories/:id`：刪除分類（tasks.category_id 自動設 NULL）

### 5. 錯誤處理 Middleware
- 統一錯誤格式：`{ error: string, details?: any }`
- 處理：404 路由不存在、400 驗證失敗、401 未授權、403 禁止存取、500 伺服器錯誤

### 6. 撰寫整合測試
使用 supertest + Jest 測試：
- 完整的 register → login → create task → get tasks → delete task 流程
- 測試未授權存取時回傳 401
- 測試存取他人任務時回傳 403

## 提示

- 使用 `pg` 的 Pool 管理連線，在 `src/db/index.js` 統一匯出 `query` 函式
- JWT secret 與 DB 連線字串存入 `.env`，永遠不要 commit 到 git
- `PATCH` 時動態組合 SET 子句，避免寫死欄位（提示：使用陣列 + `$N` 佔位符）
- Transaction 範例：建立任務同時新增操作日誌（可選），確保原子性
- 測試時使用獨立測試資料庫或在每個 test suite 的 `beforeAll` / `afterAll` 清理資料

## 進階挑戰（選做）

1. **軟刪除（Soft Delete）**：tasks 加 `deleted_at` 欄位，`DELETE` 只設時間戳，`GET` 加 `WHERE deleted_at IS NULL`
2. **批次操作**：`PATCH /api/tasks/batch`，接收 `{ ids: [1,2,3], status: 'done' }`，用單一 Transaction 更新多筆
3. **全文搜尋**：`GET /api/tasks?search=關鍵字`，用 PostgreSQL `ILIKE` 或 `tsvector` 實作
4. **Rate Limiting**：加入 `express-rate-limit`，限制 `/api/auth/login` 每分鐘最多 5 次
5. **API 文件**：使用 JSDoc 風格注釋搭配 `swagger-jsdoc` + `swagger-ui-express` 自動產生 API 文件
