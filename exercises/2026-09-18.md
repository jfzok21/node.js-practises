# 第 11 週今日練習題：API 測試實戰

## 題目說明

你已經完成了許多 Express + PostgreSQL 的功能開發。現在是時候學習如何為你的 API 撰寫自動化測試，確保程式碼的正確性並防止回歸錯誤。本週的目標是使用 **supertest** 與 **Jest** 為一個簡單的「書籍管理」API 撰寫完整的端對端測試。

## 技術要求

- **Express.js**：建立一個可供測試的 Express 應用程式（匯出 `app`，不直接 `listen`）
- **PostgreSQL**：使用測試資料庫（`TEST_DATABASE_URL`），每次測試前後清理資料
- **Jest**：撰寫測試套件（`describe`、`test`/`it`、`expect`）
- **supertest**：模擬 HTTP 請求，無需啟動真實伺服器

## 具體任務

1. **建立可測試的 Express 應用**
   - 在 `src/app.js` 中建立並匯出 `app`（不呼叫 `app.listen`）
   - 在 `src/server.js` 中才呼叫 `listen`，作為啟動入口
   - 建立 `/api/books` 路由，支援 GET（全部）、POST（新增）、GET（單筆）、PUT（更新）、DELETE（刪除）

2. **設定測試環境**
   - 安裝依賴：`npm install --save-dev jest supertest`
   - 在 `package.json` 加入 `"test": "jest"` 腳本
   - 建立 `jest.config.js`，設定 `testEnvironment: 'node'`
   - 建立 `.env.test`，設定測試用的 `TEST_DATABASE_URL`

3. **撰寫測試前置與清理**
   - 建立 `tests/setup.js`：在 `beforeAll` 中建立 `books` 測試資料表
   - 在 `afterAll` 中關閉資料庫連線
   - 在 `beforeEach` 中清空資料表（`TRUNCATE books RESTART IDENTITY`）

4. **撰寫 API 測試**（建立 `tests/books.test.js`）
   - `GET /api/books`：測試空清單回傳 `[]`、有資料時正確回傳陣列
   - `POST /api/books`：測試成功新增回傳 201 與書籍物件、缺少必填欄位回傳 400
   - `GET /api/books/:id`：測試正確 id 回傳書籍、不存在的 id 回傳 404
   - `PUT /api/books/:id`：測試成功更新回傳修改後的資料
   - `DELETE /api/books/:id`：測試成功刪除回傳 204、再次查詢回傳 404

5. **驗證測試通過**
   - 執行 `npm test`，確認所有測試（至少 8 個）通過
   - 確認測試結束後資料庫是乾淨的，不殘留測試資料

## 提示

- `supertest` 使用方式：
  ```js
  const request = require('supertest');
  const app = require('../src/app');

  const res = await request(app).get('/api/books');
  expect(res.statusCode).toBe(200);
  expect(res.body).toEqual([]);
  ```
- 使用 `process.env.NODE_ENV = 'test'` 切換到測試資料庫連線
- `beforeEach` 清空資料確保每個測試獨立，避免測試互相干擾
- 測試 POST 時，記得在 `expect` 中檢查回傳物件的欄位值（`expect(res.body).toMatchObject({ title: '...' })`）
- 若連線到 PostgreSQL 失敗，確認 `pg` 套件的 Pool 有使用 `TEST_DATABASE_URL`

## 進階挑戰（選做）

- **測試覆蓋率**：加入 `--coverage` 標記（`jest --coverage`），確認覆蓋率達到 80% 以上
- **整合 JWT 測試**：對需要驗證的路由，在測試中先呼叫登入 API 取得 token，再帶入後續請求的 `Authorization` header
- **測試 Middleware**：撰寫測試驗證 rate limiting、錯誤處理 middleware 的行為是否正確
- **平行測試隔離**：設定 Jest 的 `--runInBand` 確保資料庫操作不會發生競爭條件（race condition）
- **測試 fixture**：建立 `tests/fixtures/books.js`，統一管理測試用的假資料
