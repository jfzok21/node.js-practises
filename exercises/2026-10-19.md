# 第 15 週今日練習題：任務管理 REST API 實戰專案

## 題目說明

建立一個完整的任務管理（Todo / Task Manager）REST API，整合 Express.js 與 PostgreSQL，涵蓋多週所學技術：路由、Middleware、JWT 驗證、資料驗證、分頁、JOIN 查詢與交易處理。

---

## 技術要求

- **Express.js**：模組化路由（`/auth`、`/tasks`、`/users`）、自訂 Middleware、JWT 驗證 Middleware、全域錯誤處理
- **PostgreSQL**：多資料表設計（`users`、`tasks`、`tags`、`task_tags`）、JOIN 查詢、Transaction、分頁排序

---

## 資料表設計

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(50) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  user_id INT REFERENCES users(id) ON DELETE CASCADE,
  title VARCHAR(200) NOT NULL,
  description TEXT,
  status VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending', 'in_progress', 'done')),
  due_date DATE,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE tags (
  id SERIAL PRIMARY KEY,
  name VARCHAR(50) UNIQUE NOT NULL
);

CREATE TABLE task_tags (
  task_id INT REFERENCES tasks(id) ON DELETE CASCADE,
  tag_id  INT REFERENCES tags(id)  ON DELETE CASCADE,
  PRIMARY KEY (task_id, tag_id)
);
```

## 具體任務

1. **使用者驗證模組** (`/auth`)
   - `POST /auth/register`：接受 `{ username, password }`，驗證欄位非空、username 唯一，以 `bcrypt` 雜湊密碼後存入 DB，回傳 `201` 與使用者資訊（不含密碼）。
   - `POST /auth/login`：驗證帳密，成功回傳 JWT（含 `userId`，有效期 24 小時），失敗回傳 `401`。

2. **JWT Middleware**
   - 讀取 `Authorization: Bearer <token>`，驗證有效性，將 `req.user` 設為 `{ id, username }`，無效時回傳 `401`。

3. **任務 CRUD** (`/tasks`，需登入)
   - `GET /tasks`：回傳當前使用者的所有任務，支援：
     - 查詢字串 `?status=pending`（篩選狀態）
     - `?search=關鍵字`（模糊搜尋 title / description）
     - `?page=1&limit=10`（分頁）
     - `?sort=due_date&order=asc`（排序）
     - 每筆任務附帶其 tags 陣列（JOIN）
   - `GET /tasks/:id`：取得單一任務（含 tags），僅能存取自己的任務，否則 `403`。
   - `POST /tasks`：建立任務，同時可傳入 `tags: ["urgent", "work"]`，用 **Transaction** 確保任務與 tag 關聯一併成功或回滾。
   - `PATCH /tasks/:id`：更新任務欄位，自動更新 `updated_at`，可更新 tags（先刪舊關聯再新增）。
   - `DELETE /tasks/:id`：刪除任務（CASCADE 自動移除 task_tags）。

4. **資料驗證**
   - `title` 必填，長度 1–200。
   - `status` 若提供，需為 `pending` / `in_progress` / `done`。
   - `due_date` 若提供，格式需為有效日期且不得早於今天。
   - 驗證失敗回傳 `400` 並附帶具體錯誤訊息（JSON）。

5. **統計端點**
   - `GET /tasks/stats`：回傳當前使用者的任務統計：
     ```json
     {
       "total": 20,
       "by_status": { "pending": 10, "in_progress": 5, "done": 5 },
       "overdue": 3
     }
     ```
     使用單一 SQL 查詢完成（`GROUP BY` + `FILTER`）。

## 提示

- 使用 `express-validator` 或手寫驗證函式，統一錯誤格式：`{ "errors": [{ "field": "title", "message": "..." }] }`。
- 分頁計算：`OFFSET = (page - 1) * limit`，回應加入 `{ data, total, page, totalPages }` 結構。
- Transaction 範例：
  ```js
  const client = await pool.connect();
  try {
    await client.query('BEGIN');
    // ... 多個查詢
    await client.query('COMMIT');
  } catch (err) {
    await client.query('ROLLBACK');
    throw err;
  } finally {
    client.release();
  }
  ```
- JWT 密鑰請存於環境變數 `JWT_SECRET`，勿寫死在程式碼。
- 建議專案結構：
  ```
  src/
    routes/       auth.js  tasks.js
    middleware/   auth.js  validate.js  error.js
    db/           pool.js
    app.js
  ```

## 進階挑戰（選做）

- **軟刪除**：新增 `deleted_at` 欄位，`DELETE` 改為設定時間戳，查詢時自動過濾已刪除資料。
- **任務指派**：允許將任務指派給同一系統的其他使用者，新增 `assigned_to` 欄位，並提供 `GET /tasks/assigned` 查看被指派的任務。
- **API 測試**：以 `supertest + Jest` 撰寫完整的整合測試，覆蓋所有端點（含驗證失敗案例）。
- **Rate Limiting**：使用 `express-rate-limit` 限制 `/auth/login` 每分鐘最多 5 次，防止暴力破解。
- **Swagger / OpenAPI**：以 `swagger-ui-express` + `swagger-jsdoc` 自動產生 API 文件。
