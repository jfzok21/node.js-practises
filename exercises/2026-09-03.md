# 第 9 週今日練習題：分頁與排序 API

## 題目說明

實作一個支援分頁（Pagination）與排序（Sorting）的 REST API。  
你將為一個「文章列表」資源建立可彈性查詢的端點，讓前端能夠按需取得資料、控制每頁筆數，以及依不同欄位排序。

---

## 技術要求

- **Express.js**：使用查詢字串（Query String）接收分頁與排序參數
- **PostgreSQL**：使用 `LIMIT`、`OFFSET`、`ORDER BY` 子句實作分頁與排序

---

## 具體任務

1. **建立資料表**  
   在 PostgreSQL 建立 `articles` 資料表：
   ```sql
   CREATE TABLE articles (
     id        SERIAL PRIMARY KEY,
     title     VARCHAR(200) NOT NULL,
     author    VARCHAR(100) NOT NULL,
     views     INTEGER DEFAULT 0,
     created_at TIMESTAMPTZ DEFAULT NOW()
   );
   ```
   插入至少 20 筆測試資料（可用迴圈或 `INSERT INTO ... VALUES` 批次插入）。

2. **實作分頁端點**  
   `GET /articles`  
   接受以下查詢字串參數：
   | 參數 | 型別 | 預設值 | 說明 |
   |------|------|--------|------|
   | `page` | integer | 1 | 目前頁碼（從 1 開始） |
   | `limit` | integer | 10 | 每頁筆數（上限 50） |
   | `sort_by` | string | `created_at` | 排序欄位（允許：`id`、`title`、`author`、`views`、`created_at`） |
   | `order` | string | `desc` | 排序方向（`asc` 或 `desc`） |

3. **回傳格式**  
   ```json
   {
     "data": [ ...文章物件陣列... ],
     "pagination": {
       "total": 20,
       "page": 1,
       "limit": 10,
       "total_pages": 2,
       "has_next": true,
       "has_prev": false
     }
   }
   ```

4. **參數驗證**  
   - `page` 與 `limit` 必須為正整數，否則回傳 `400 Bad Request`  
   - `limit` 超過 50 時，自動截斷為 50  
   - `sort_by` 不在允許清單內時，回傳 `400 Bad Request`（防止 SQL Injection）  
   - `order` 只允許 `asc` / `desc`，否則預設使用 `desc`

5. **計算 OFFSET**  
   ```
   OFFSET = (page - 1) * limit
   ```

---

## 提示

- **白名單驗證 `sort_by`**：永遠用白名單（allowlist）檢查允許的欄位名稱，**不要**直接將使用者輸入拼接進 SQL，否則會有 SQL Injection 風險。
  ```js
  const ALLOWED_SORT_FIELDS = ['id', 'title', 'author', 'views', 'created_at'];
  if (!ALLOWED_SORT_FIELDS.includes(sort_by)) {
    return res.status(400).json({ error: 'Invalid sort_by field' });
  }
  ```
- 使用 `COUNT(*) OVER()` 或兩個獨立查詢取得總筆數。
  ```sql
  SELECT *, COUNT(*) OVER() AS total FROM articles
  ORDER BY created_at DESC
  LIMIT $1 OFFSET $2;
  ```
- `parseInt()` 後記得用 `isNaN()` 檢查是否為有效數字。

## 進階挑戰（選做）

1. **關鍵字搜尋**  
   新增 `?search=` 查詢字串，對 `title` 和 `author` 做模糊搜尋（`ILIKE`），並讓分頁在搜尋結果上正確運作。

2. **游標分頁（Cursor-based Pagination）**  
   改用 `?cursor=<last_id>` 取代 `?page=`，實作基於游標的分頁，適合大型資料集或即時更新的資料。

3. **排序多個欄位**  
   支援 `?sort_by=views,created_at&order=desc,asc`，允許多欄位組合排序。

4. **加入 `Link` Header**  
   在 HTTP 回應標頭加入 `Link` header，包含 `first`、`prev`、`next`、`last` 的 URL，符合 RFC 5988 標準。
