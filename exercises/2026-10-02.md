# 第 13 週今日練習題：任務管理 REST API 完整實作

## 題目說明

建立一個完整的「任務管理系統」REST API，整合前幾週所有學到的技術，包含身份驗證、分頁排序、資料驗證、交易處理，模擬真實生產環境的後端服務。

## 技術要求

- **Express.js**：Router 模組化、JWT 中介層、全域錯誤處理、請求驗證
- **PostgreSQL**：多資料表關聯、Transaction、分頁查詢、索引優化

## 資料庫結構

```sql
-- 使用者表
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 專案表
CREATE TABLE projects (
  id SERIAL PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  description TEXT,
  owner_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 任務表
CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  title VARCHAR(255) NOT NULL,
  description TEXT,
  status VARCHAR(20) DEFAULT 'todo' CHECK (status IN ('todo', 'in_progress', 'done')),
  priority INTEGER DEFAULT 3 CHECK (priority BETWEEN 1 AND 5),
  due_date DATE,
  project_id INTEGER REFERENCES projects(id) ON DELETE CASCADE,
  assignee_id INTEGER REFERENCES users(id) ON DELETE SET NULL,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- 任務標籤表（多對多）
CREATE TABLE tags (
  id SERIAL PRIMARY KEY,
  name VARCHAR(50) UNIQUE NOT NULL
);

CREATE TABLE task_tags (
  task_id INTEGER REFERENCES tasks(id) ON DELETE CASCADE,
  tag_id INTEGER REFERENCES tags(id) ON DELETE CASCADE,
  PRIMARY KEY (task_id, tag_id)
);
```

### 2. 實作身份驗證模組（`routes/auth.js`）

- `POST /api/auth/register`：註冊（email + password），用 `bcrypt` 雜湊密碼，回傳 JWT
- `POST /api/auth/login`：登入驗證，回傳 JWT
- `GET /api/auth/me`：回傳當前登入使用者資訊（需 JWT）

### 3. 實作專案 CRUD（`routes/projects.js`，需 JWT）

- `GET /api/projects`：列出當前使用者的所有專案（含任務數量統計）
- `POST /api/projects`：建立專案
- `GET /api/projects/:id`：取得單一專案詳細資訊（含任務列表）
- `PUT /api/projects/:id`：更新專案（僅擁有者可操作）
- `DELETE /api/projects/:id`：刪除專案（**使用 Transaction**：同時刪除所有相關任務與標籤關聯）

### 4. 實作任務 CRUD（`routes/tasks.js`，需 JWT）

- `GET /api/projects/:projectId/tasks`：列出專案任務，支援：
  - 分頁：`?page=1&limit=10`
  - 排序：`?sort=priority&order=desc`
  - 篩選：`?status=todo&priority=1`
  - 搜尋：`?search=關鍵字`（搜尋 title + description）
- `POST /api/projects/:projectId/tasks`：建立任務（**使用 Transaction**：同時建立任務與標籤關聯）
- `PUT /api/tasks/:id`：更新任務（含標籤更新，使用 Transaction）
- `DELETE /api/tasks/:id`：刪除任務
- `PATCH /api/tasks/:id/status`：快速更新任務狀態

### 5. 統計 API

- `GET /api/projects/:id/stats`：回傳專案統計
  ```json
  {
    "total": 20,

    "done": 7,
  ```

### 7. 資料驗證

使用 `joi` 或手動驗證，確保：
- email 格式正確
- password 至少 8 碼
- task title 不可為空
- priority 為 1-5 整數
- status 為合法值
- due_date 不可為過去日期（建立時）

## 提示

- 使用 `pg` 的 `pool.connect()` 取得 client 進行 Transaction，記得在 `finally` 中 `client.release()`
- JWT 中介層從 `Authorization: Bearer <token>` 標頭取得 token
- 分頁查詢用 `LIMIT $1 OFFSET $2`，offset = (page - 1) * limit
- 搜尋用 `ILIKE '%' || $1 || '%'` 或 PostgreSQL 全文搜尋 `to_tsvector`
- `updated_at` 可用 PostgreSQL Trigger 自動更新，或在每次 UPDATE 手動帶入 `NOW()`

## Transaction 範例（刪除專案）

```javascript
const client = await pool.connect();
try {
  await client.query('BEGIN');
  
  // 先刪除任務標籤關聯
  await client.query(
    'DELETE FROM task_tags WHERE task_id IN (SELECT id FROM tasks WHERE project_id = $1)',
    [projectId]
  );
  
  // 刪除任務
  await client.query('DELETE FROM tasks WHERE project_id = $1', [projectId]);
  
  // 刪除專案
  await client.query('DELETE FROM projects WHERE id = $1 AND owner_id = $2', [projectId, userId]);
  
  await client.query('COMMIT');
} catch (err) {
  await client.query('ROLLBACK');
  throw err;
} finally {
  client.release();
}
```

## 進階挑戰（選做）

1. **軟刪除**：在 tasks 加入 `deleted_at` 欄位，DELETE 改為 `UPDATE tasks SET deleted_at = NOW()`，所有查詢加上 `WHERE deleted_at IS NULL`

2. **活動日誌**：建立 `activity_logs` 表，每次任務狀態變更時記錄（使用 Transaction 確保原子性）

3. **批次操作**：`PATCH /api/projects/:id/tasks/batch`，接受任務 id 陣列與新狀態，在單一 Transaction 中更新所有任務

4. **整合測試**：用 `supertest` 測試完整的 register → login → create project → create task → update task 流程

5. **效能優化**：為常用查詢欄位建立索引（`status`、`priority`、`project_id`、`assignee_id`），用 `EXPLAIN ANALYZE` 比較查詢效能
