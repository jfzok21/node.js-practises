# 第 10 週今日練習題：銀行轉帳 API 與交易處理

## 題目說明

建立一個模擬銀行帳戶轉帳的 REST API。轉帳操作涉及多個資料庫寫入（扣款 + 入款），必須以 PostgreSQL **Transaction（交易）** 保證原子性——要嘛全部成功，要嘛全部回滾，不能出現「A 扣款成功但 B 入款失敗」的不一致狀態。

---

## 技術要求

- **Express.js**：設計轉帳、查詢餘額兩支端點
- **PostgreSQL**：使用 `BEGIN / COMMIT / ROLLBACK` 或 `pg` 的 transaction client 控制交易邊界；確保轉帳失敗時自動回滾

---

## 具體任務

1. **建立資料表**

   ```sql
   CREATE TABLE accounts (
     id      SERIAL PRIMARY KEY,
     owner   VARCHAR(100) NOT NULL,
     balance NUMERIC(12, 2) NOT NULL DEFAULT 0
   );

   CREATE TABLE transfer_logs (
     id          SERIAL PRIMARY KEY,
     from_id     INT REFERENCES accounts(id),
     to_id       INT REFERENCES accounts(id),
     amount      NUMERIC(12, 2) NOT NULL,
     status      VARCHAR(20) NOT NULL,  -- 'success' | 'failed'
     reason      TEXT,
     created_at  TIMESTAMP DEFAULT NOW()
   );
   ```

   插入測試資料：帳戶 A 餘額 10000，帳戶 B 餘額 5000。

2. **實作 `POST /transfer` 端點**

   接收請求體：
   ```json
   { "from_id": 1, "to_id": 2, "amount": 3000 }
   ```

   在單一 transaction 中依序執行：
   - 以 `SELECT ... FOR UPDATE` 鎖定兩筆帳戶列，避免並發競態
   - 檢查 `from` 帳戶餘額是否足夠，不足則拋出錯誤並 ROLLBACK
   - 從 `from` 帳戶扣款，對 `to` 帳戶入款
   - 寫入 `transfer_logs`（status = 'success'）
   - COMMIT

   若任一步驟例外，ROLLBACK 並在 `transfer_logs` 寫入 status = 'failed' 與 reason（此寫入需在 transaction **之外**，否則 ROLLBACK 會把它也一起撤銷）。

3. **實作 `GET /accounts/:id/balance` 端點**

   回傳帳戶 id、owner、balance。

4. **驗證行為**

   - 轉帳成功：兩個帳戶餘額正確更新，logs 有一筆 success 記錄
   - 餘額不足：帳戶餘額不變，logs 有一筆 failed 記錄，API 回傳 422 與錯誤訊息

---

## 提示

- `pg` 套件使用 transaction 的標準寫法：
  ```js
  const client = await pool.connect();
  try {
    await client.query('BEGIN');
    // ... 所有查詢用 client.query(...)
    await client.query('COMMIT');
  } catch (err) {
    await client.query('ROLLBACK');
    throw err;
  } finally {
    client.release();
  }
  ```
- `SELECT ... FOR UPDATE` 加在查詢末尾，可防止同一帳戶被並發請求同時讀取舊餘額。
- `transfer_logs` 的失敗記錄要用獨立的 pool query（非 transaction client）來寫，確保不被 ROLLBACK 吃掉。
- 餘額欄位用 `NUMERIC` 而非 `FLOAT`，避免浮點數精度問題。

- 以 `pgbouncer` 或多個並發請求測試競態條件，確認 `FOR UPDATE` 正確序列化執行

- 將 transaction 邏輯抽成可重用的 `withTransaction(pool, callback)` helper function
- 在 `transfer_logs` 加入 `snapshot_before` / `snapshot_after` JSON 欄位，記錄轉帳前後的餘額快照
