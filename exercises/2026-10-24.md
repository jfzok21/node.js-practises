# 第 16 週今日練習題：部落格內容管理系統 REST API

## 題目說明

建立一個完整的「部落格內容管理系統（Blog CMS）」REST API。
本題整合路由設計、CRUD、Middleware、JOIN 查詢、JWT 身份驗證、分頁、檔案上傳與全文搜尋，模擬真實部落格後端開發流程。

## 技術要求

- **Express.js**：Router 模組化、JWT 認證 Middleware、multer 圖片上傳、統一錯誤處理
- **PostgreSQL**：多資料表關聯（users、posts、categories、comments、post_tags）、全文搜尋、Trigger 自動更新 `updated_at`

## 資料庫 Schema

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(50) UNIQUE NOT NULL,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  avatar_url VARCHAR(500),
  role VARCHAR(20) DEFAULT 'author' CHECK (role IN ('admin', 'author', 'reader')),
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE categories (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) UNIQUE NOT NULL,
  slug VARCHAR(100) UNIQUE NOT NULL,
  description TEXT
);

CREATE TABLE posts (
  id SERIAL PRIMARY KEY,
  title VARCHAR(255) NOT NULL,
  slug VARCHAR(255) UNIQUE NOT NULL,
  content TEXT NOT NULL,
  excerpt TEXT,
  cover_image_url VARCHAR(500),
  status VARCHAR(20) DEFAULT 'draft' CHECK (status IN ('draft', 'published', 'archived')),
  author_id INTEGER REFERENCES users(id) ON DELETE SET NULL,
  category_id INTEGER REFERENCES categories(id) ON DELETE SET NULL,
  view_count INTEGER DEFAULT 0,
  published_at TIMESTAMP,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW(),
  search_vector TSVECTOR
);

CREATE TABLE tags (
  id SERIAL PRIMARY KEY,
  name VARCHAR(50) UNIQUE NOT NULL,
  slug VARCHAR(50) UNIQUE NOT NULL
);

CREATE TABLE post_tags (
  post_id INTEGER REFERENCES posts(id) ON DELETE CASCADE,
  tag_id INTEGER REFERENCES tags(id) ON DELETE CASCADE,
  PRIMARY KEY (post_id, tag_id)
);

CREATE TABLE comments (
  id SERIAL PRIMARY KEY,
  content TEXT NOT NULL,
  post_id INTEGER REFERENCES posts(id) ON DELETE CASCADE,
  author_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  parent_id INTEGER REFERENCES comments(id) ON DELETE CASCADE,
  is_approved BOOLEAN DEFAULT false,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 全文搜尋索引
CREATE INDEX posts_search_idx ON posts USING GIN(search_vector);

-- 自動更新 search_vector 的 Trigger
CREATE OR REPLACE FUNCTION posts_search_update() RETURNS TRIGGER AS $$
BEGIN
  NEW.search_vector := to_tsvector('english', COALESCE(NEW.title, '') || ' ' || COALESCE(NEW.content, ''));
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER posts_search_trigger
BEFORE INSERT OR UPDATE ON posts
FOR EACH ROW EXECUTE FUNCTION posts_search_update();
```

## 具體任務

### 1. 專案結構

### 2. 身份驗證（`/api/auth`）
- `POST /api/auth/register`：註冊，角色預設 `reader`
- `POST /api/auth/login`：登入，回傳 JWT（有效期 24 小時）
- `GET  /api/auth/me`：取得目前使用者資料（需 JWT）
- `PUT  /api/auth/me`：更新個人資料（username、avatar）
- 撰寫 `requireAuth(role)` Middleware，支援角色檢查：
  ```js
  // 使用範例
  router.delete('/:id', requireAuth('admin'), deletePost);
  router.post('/',      requireAuth('author'), createPost);
  ```

### 3. 文章管理（`/api/posts`）
- `GET /api/posts`（公開）：
  - 查詢參數：`?status=published&category=tech&tag=node&author=1`
  - 分頁：`?page=1&limit=10`
  - 排序：`?sortBy=published_at&order=desc`
  - 全文搜尋：`?q=express+postgresql`（使用 `search_vector @@ to_tsquery`）
  - 回傳文章列表，JOIN `categories`、`users`（作者）、`tags`（陣列）
- `GET  /api/posts/:slug`（公開）：取得單篇文章，並將 `view_count + 1`
- `POST /api/posts`（需 author/admin）：
  - 建立文章，`published_at` 在 `status=published` 時自動設為當下時間
  - 同時新增 `tag_ids`（Transaction）
  - 自動從 `title` 產生 `slug`（空白轉 `-`，轉小寫，去除特殊字元）
- `PUT  /api/posts/:id`（需 author 且為作者本人，或 admin）：更新文章與標籤
- `DELETE /api/posts/:id`（需 admin）：刪除文章

### 4. 留言系統（`/api/posts/:postId/comments`）
- `GET /api/posts/:postId/comments`（公開）：
  - 只回傳 `is_approved = true` 的留言
  - 支援巢狀結構：頂層留言附帶 `replies` 陣列（`parent_id IS NULL` 的為頂層）
- `POST /api/posts/:postId/comments`（需登入）：新增留言，預設 `is_approved = false`
- `PUT  /api/comments/:id/approve`（需 admin）：審核通過留言
- `DELETE /api/comments/:id`（需 admin 或留言作者）：刪除留言

### 5. 圖片上傳（`/api/upload`）
- `POST /api/upload/cover`（需 author/admin）：
  - 使用 `multer` 接收封面圖片
  - 限制：僅接受 `image/jpeg`、`image/png`、`image/webp`，最大 5MB
  - 儲存至 `src/uploads/` 並回傳可存取的 URL
  - 設定 Express static 讓 `/uploads/` 可公開存取

### 6. 資料驗證規則
| 欄位 | 規則 |
|------|------|
| `title` | 必填，5–255 字元 |
| `content` | 必填，最少 50 字元 |
| `status` | `draft \| published \| archived` |
| `slug` | 僅允許英數字與 `-`，若未提供則自動產生 |
| `email` | 必填，格式正確 |
| `password` | 必填，至少 8 字元，含大小寫與數字 |

## 提示

- `slug` 產生邏輯：`title.toLowerCase().replace(/[^a-z0-9]+/g, '-').replace(/^-|-$/g, '')`
- 全文搜尋查詢：`WHERE search_vector @@ plainto_tsquery('english', $1)`，排名可用 `ts_rank`
- 巢狀留言組裝：在 JS 層透過 `reduce` 將平坦陣列轉為樹狀結構
- 回傳 `view_count` 時可用 `UPDATE posts SET view_count = view_count + 1 WHERE id = $1 RETURNING *`
- 使用 `pg` Pool 的 `RETURNING *` 取回插入結果，避免二次查詢

## 進階挑戰（選做）

1. **草稿預覽**：`GET /api/posts/:id/preview`（需登入），允許作者預覽未發布草稿
2. **文章收藏**：新增 `bookmarks` 資料表，`POST /api/posts/:id/bookmark` 收藏 / 取消收藏
3. **閱讀時間**：文章建立時，依 `content` 字數自動計算並儲存 `reading_time_minutes`（以 250 字/分鐘計算）
4. **Rate Limiting**：留言 API 限制每位使用者每分鐘最多 5 則，使用 `express-rate-limit`
5. **整合測試**：使用 `supertest + Jest` 撰寫 `POST /auth/register`、`GET /posts` 與全文搜尋的測試案例
