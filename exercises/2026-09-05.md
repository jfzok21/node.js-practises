# 第 9 週今日練習題：商品列表分頁與多欄位排序 API

## 題目說明

建立一個支援**分頁（Pagination）**與**多欄位排序（Sorting）**的 Express + PostgreSQL RESTful API。使用者可以透過查詢字串控制每頁筆數、目前頁碼與排序規則，系統需回傳分頁後的資料及相關的 metadata。

---

## 技術要求

- **Express.js**：設計 `GET /api/products` 路由，接受查詢字串參數
- **PostgreSQL**：使用 `LIMIT`、`OFFSET`、`ORDER BY` 進行分頁與排序查詢，並以 `COUNT(*)` 取得總筆數

---

## 具體任務

### 1. 建立資料表與測試資料

```sql
CREATE TABLE products (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  category VARCHAR(50) NOT NULL,
  price NUMERIC(10, 2) NOT NULL,
  stock INTEGER NOT NULL DEFAULT 0,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 插入至少 30 筆測試資料（不同的分類與價格範圍）
INSERT INTO products (name, category, price, stock) VALUES
  ('蘋果筆電 Pro', '電子產品', 45000, 15),
  ('無線藍牙耳機', '電子產品', 3200, 80),
  ('瑜珈墊', '運動用品', 890, 120),
  ('咖啡機', '家電', 6500, 25),
  ('程式設計入門書', '書籍', 450, 200),
  -- ... 繼續補充至 30 筆以上
  ('機械鍵盤', '電子產品', 2800, 50);
```

### 2. 實作分頁查詢路由

接受以下查詢字串參數：

| 參數 | 型別 | 預設值 | 說明 |
|------|------|--------|------|
| `page` | 整數 | `1` | 目前頁碼（從 1 開始） |
| `limit` | 整數 | `10` | 每頁筆數（最大 50） |
| `sortBy` | 字串 | `id` | 排序欄位（`id`、`name`、`price`、`stock`、`created_at`） |
| `order` | 字串 | `asc` | 排序方向（`asc` 或 `desc`） |

```http
GET /api/products?page=2&limit=5&sortBy=price&order=desc
```

### 3. 回應格式

```json
{
  "data": [
    {
      "id": 12,
      "name": "蘋果筆電 Pro",
      "category": "電子產品",
      "price": "45000.00",
      "stock": 15,
      "created_at": "2026-09-05T10:00:00.000Z"
    }
  ],
  "pagination": {
    "total": 35,
    "totalPages": 7,
    "currentPage": 2,
    "limit": 5,
    "hasPrevPage": true,
    "hasNextPage": true
  }
}
```

### 4. 輸入驗證

- `page` 必須是正整數，否則回傳 400
- `limit` 必須介於 1 ~ 50，超出範圍時自動 clamp 或回傳 400（擇一實作）
- `sortBy` 只允許白名單欄位，不在清單中時回傳 400（防止 SQL Injection）
- `order` 只允許 `asc` / `desc`，否則回傳 400

### 5. SQL 查詢實作

在 PostgreSQL 查詢中：
1. 使用 `COUNT(*) OVER()` 或分開的 `SELECT COUNT(*)` 取得總筆數
2. 使用參數化查詢（`$1`, `$2`）避免 SQL Injection
3. `ORDER BY` 欄位名稱需用白名單對應（不可直接嵌入字串）

---

## 提示

- **白名單對應**：建立一個 JavaScript 物件 `const ALLOWED_SORT_FIELDS = { id: 'id', name: 'name', price: 'price', stock: 'stock', created_at: 'created_at' }` 做映射，用映射後的值組 SQL
- **OFFSET 計算**：`offset = (page - 1) * limit`
- **總頁數計算**：`totalPages = Math.ceil(total / limit)`
- **防止 NaN**：使用 `parseInt()` 搭配 `isNaN()` 驗證數值參數
- **Window Function**：`SELECT *, COUNT(*) OVER() AS total_count FROM products ORDER BY ... LIMIT ... OFFSET ...` 可一次取得資料與總筆數

---

## 進階挑戰（選做）

1. **多欄位排序**：支援 `sortBy=price,stock&order=desc,asc`，允許同時對多個欄位指定不同排序方向

2. **游標分頁（Cursor-based Pagination）**：改用 `cursor`（最後一筆的 `id`）取代 `page`，實作 `GET /api/products?cursor=15&limit=5`，回傳格式改為：
   ```json
   {
     "data": [...],
     "nextCursor": 20,
     "hasMore": true
   }
   ```

3. **篩選功能整合**：在分頁與排序基礎上，增加 `?category=電子產品&minPrice=1000&maxPrice=50000` 篩選條件，並確保 `total` 是篩選後的總筆數

4. **快取優化**：在路由加入 `Cache-Control: public, max-age=60` header，並在資料更新後能正確讓快取失效
