# 第 4 週今日練習題：Express Middleware 全面應用

## 題目說明

本週重點是 Express Middleware（中介軟體）的設計與應用。Middleware 是 Express 架構的核心概念，每個請求在到達最終路由處理器之前，都可以經過一連串的 middleware 函式進行預處理。你將學習如何建立自訂 middleware、整合常用第三方 middleware，以及設計統一的錯誤處理機制。

## 技術要求

- **Express.js**：自訂 middleware 函式、`app.use()` 全域掛載、路由層級掛載、錯誤處理 middleware（四個參數）
- **PostgreSQL**：結合 middleware 記錄 API 請求日誌至資料庫

## 具體任務

1. **建立請求日誌 middleware**
   - 記錄每個請求的 method、path、IP、timestamp
   - 使用 `console.log` 輸出格式：`[2026-08-03 14:00:00] GET /api/users - 127.0.0.1`
   - 掛載至全域（所有路由皆適用）

2. **建立身份驗證 middleware**
   - 讀取請求標頭 `Authorization: Bearer <token>`
   - 若 token 不存在或不等於 `"secret123"`，回傳 `401 Unauthorized`：
     ```json
     { "error": "Unauthorized", "message": "請提供有效的 Authorization token" }
     ```
   - 僅掛載於需要保護的路由群組（例如 `/api/protected/*`）

3. **整合 body-parser / express.json()**
   - 確保 POST / PUT 請求可以解析 JSON body
   - 建立一個 `POST /api/products` 路由，接收 `{ name, price, stock }` 並驗證：
     - `name`：必填，字串，長度 1–100
     - `price`：必填，數字，大於 0
     - `stock`：選填，整數，預設為 0

4. **建立資料驗證 middleware**
   - 將上述驗證邏輯抽取成獨立的 middleware 函式 `validateProduct`
   - 驗證失敗時回傳 `400 Bad Request`：
     ```json
     { "error": "Validation Error", "fields": ["price 必須大於 0"] }
     ```
   - 驗證成功則呼叫 `next()` 繼續處理

5. **建立統一錯誤處理 middleware**
   - 定義四參數的錯誤 middleware：`(err, req, res, next)`
   - 區分錯誤類型：
     - 若 `err.status` 存在，使用該狀態碼
     - 其他一律回傳 `500 Internal Server Error`
   - 回應格式：
     ```json
     { "error": "Internal Server Error", "message": "伺服器發生非預期錯誤" }
     ```
   - 確保此 middleware 掛載於所有路由**之後**

6. **建立請求計時 middleware**
   - 在請求開始時記錄時間，在回應發送後計算耗時
   - 在回應標頭加入 `X-Response-Time: 12ms`

## 提示

- Middleware 的執行順序與 `app.use()` 的呼叫順序一致，務必注意掛載位置
- 錯誤處理 middleware 必須是**四個參數**（`err, req, res, next`），Express 才會識別它為錯誤處理器
- 可使用 `res.on('finish', callback)` 監聽回應完成事件來計算耗時
- 身份驗證 middleware 可以使用 `express.Router()` 搭配 `router.use()` 限制作用範圍
- 善用 `next(err)` 將錯誤傳遞給錯誤處理 middleware

## 進階挑戰（選做）

- **請求速率限制**：實作一個簡單的 in-memory rate limiter middleware，每個 IP 每分鐘最多 30 次請求，超過回傳 `429 Too Many Requests`
- **請求日誌寫入 PostgreSQL**：建立 `api_logs` 資料表，欄位包含 `id`、`method`、`path`、`ip`、`status_code`、`response_time_ms`、`created_at`，在請求完成後非同步寫入
- **CORS middleware**：手動實作 CORS 中介軟體，允許指定來源（不使用 `cors` 套件）
