# 第 19 週今日練習題：任務管理 REST API（實戰專案）

## 題目說明

實作一個完整的「任務管理系統」後端 API，整合 Express.js 與 PostgreSQL，涵蓋使用者身份驗證、任務 CRUD、分頁查詢、資料驗證與錯誤處理等前幾週所學的技術。

## 技術要求

- **Express.js**：路由拆分（Router）、自訂 Middleware、統一錯誤處理
- **PostgreSQL**：多資料表（users / tasks / tags）、JOIN 查詢、Transaction
- **JWT**：使用者登入與受保護路由
- **資料驗證**：joi 或手動驗證，回傳清晰錯誤訊息
- **分頁 & 排序**：支援 `?page=`、`?limit=`、`?sort=`、`?order=`

## 資料庫 Schema

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(50) UNIQUE NOT NULL,
  email VARCHAR(100) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  title VARCHAR(200) NOT NULL,
  description TEXT,
  status VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending','in_progress','done')),
  due_date DATE,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE tags (
  id SERIAL PRIMARY KEY,
  name VARCHAR(50) UNIQUE NOT NULL
);

CREATE TABLE task_tags (
  task_id INTEGER REFERENCES tasks(id) ON DELETE CASCADE,
  tag_id  INTEGER REFERENCES tags(id)  ON DELETE CASCADE,
  PRIMARY KEY (task_id, tag_id)
);
```

## 具體任務

1. **設定專案結構**
   - 建立 `src/routes/`、`src/controllers/`、`src/middleware/`、`src/db/` 目錄
   - 設定 `pool.js`（pg Pool）與 `app.js`

2. **實作使用者模組**
   - `POST /api/auth/register`：註冊（bcrypt 雜湊密碼）
   - `POST /api/auth/login`：登入，回傳 JWT
   - 建立 `authMiddleware.js`，驗證 Bearer Token

3. **實作任務 CRUD（需驗證）**
   - `GET    /api/tasks`         — 取得登入者所有任務（支援分頁、按 status 篩選）
   - `POST   /api/tasks`         — 新增任務（可帶 `tags` 陣列，使用 Transaction）
   - `GET    /api/tasks/:id`     — 取得單一任務（含 tags）
   - `PATCH  /api/tasks/:id`     — 更新任務（只更新傳入的欄位）
   - `DELETE /api/tasks/:id`     — 刪除任務（僅限本人）

4. **JOIN 查詢**
   - `GET /api/tasks` 回應中附帶 `tags`（陣列），使用一次 SQL 查詢完成（JSON_AGG）

5. **統計端點**
   - `GET /api/tasks/stats`：回傳各 status 的任務數量
   ```json
   { "pending": 5, "in_progress": 2, "done": 10 }
   ```

6. **全域錯誤處理 Middleware**
   - 404 路由找不到
   - 資料庫錯誤（unique violation → 409、not found → 404）
   - JWT 驗證失敗 → 401

## 提示

- 分頁計算：`LIMIT $1 OFFSET $2`，offset = (page - 1) * limit
- Transaction 範例：`BEGIN` → 插入 task → 插入 task_tags → `COMMIT`，失敗則 `ROLLBACK`
- `PATCH` 動態更新：先收集有傳入的欄位，再動態組 `SET col=$1, col2=$2` 字串
- 密碼雜湊：`bcrypt.hash(password, 10)`
- JWT：`jwt.sign({ userId }, SECRET, { expiresIn: '7d' })`
- `JSON_AGG` 範例：
  ```sql
  SELECT t.*, JSON_AGG(tg.name) FILTER (WHERE tg.name IS NOT NULL) AS tags
  FROM tasks t
  LEFT JOIN task_tags tt ON tt.task_id = t.id
  LEFT JOIN tags tg ON tg.id = tt.tag_id
  WHERE t.user_id = $1
  GROUP BY t.id;
  ```
