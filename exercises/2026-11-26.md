# 第 21 週今日練習題：任務管理 API（Task Manager）

## 題目說明

實作一個完整的任務管理 RESTful API，支援多位使用者登入、各自管理自己的任務，並包含標籤分類、分頁查詢與統計報表。本題整合前幾週所學的所有核心技術：JWT 驗證、CRUD、JOIN 查詢、交易處理、資料驗證與分頁。

## 技術要求

- **Express.js**：路由分層（`/auth`、`/tasks`、`/tags`）、自訂 Middleware 驗證 JWT、統一錯誤處理 Middleware
- **PostgreSQL**：三張資料表（`users`、`tasks`、`tags`）加上多對多關聯表（`task_tags`）、Transaction 保障資料一致性、聚合查詢（`COUNT`、`GROUP BY`）

## 具體任務

1. **資料庫設計**
   - 建立 `users` 表：`id`、`email`（唯一）、`password_hash`、`created_at`
   - 建立 `tasks` 表：`id`、`user_id`（FK）、`title`、`description`、`status`（`pending` / `in_progress` / `done`）、`due_date`、`created_at`
   - 建立 `tags` 表：`id`、`user_id`（FK）、`name`（每位使用者不重複）
   - 建立 `task_tags` 關聯表：`task_id`、`tag_id`

2. **認證端點**（`/auth`）
   - `POST /auth/register`：註冊，密碼以 `bcrypt` 雜湊儲存
   - `POST /auth/login`：登入，回傳 JWT（有效期 24 小時）

3. **任務 CRUD**（`/tasks`，需 JWT）
   - `GET /tasks`：取得當前使用者所有任務，支援 `?status=`、`?tag=`、`?page=`、`?limit=` 查詢參數
   - `POST /tasks`：新增任務（可同時附加已存在的標籤 id 陣列），使用 Transaction
   - `GET /tasks/:id`：取得單一任務（含標籤清單）
   - `PUT /tasks/:id`：更新任務內容與標籤（使用 Transaction）
   - `DELETE /tasks/:id`：刪除任務（串聯刪除 `task_tags`）

4. **標籤管理**（`/tags`，需 JWT）
   - `GET /tags`：列出當前使用者所有標籤
   - `POST /tags`：新增標籤
   - `DELETE /tags/:id`：刪除標籤（同時清除 `task_tags` 中的關聯）

5. **統計報表**
   - `GET /tasks/stats`：回傳 JSON，包含各 status 的任務數量、即將到期（7 天內）的任務數、最常使用的前 5 個標籤

6. **錯誤處理**
   - 所有端點回傳一致的 JSON 格式：`{ success, data, error }`
   - 404（找不到資源）、403（無權限）、422（驗證失敗）需分別處理

## 提示

- 使用 `pg` 套件的 `pool.connect()` 取得連線後手動管理 Transaction（`BEGIN` / `COMMIT` / `ROLLBACK`）
- JWT Middleware 可寫成獨立函式 `authenticate(req, res, next)`，掛在需要保護的 Router 上
- 分頁計算：`OFFSET = (page - 1) * limit`，回傳時附帶 `total` 筆數供前端使用
- 多對多標籤查詢善用 `LEFT JOIN task_tags tt ON t.id = tt.task_id LEFT JOIN tags tg ON tt.tag_id = tg.id`，再以 `json_agg` 聚合標籤陣列
- `due_date` 過濾：`WHERE due_date <= NOW() + INTERVAL '7 days' AND due_date >= NOW()`

## 進階挑戰（選做）

- 加入 `supertest` + `Jest` 撰寫整合測試，覆蓋 register → login → 建立任務 → 查詢 → 刪除 的完整流程
- 實作 `PATCH /tasks/:id/status` 讓前端可以單獨更新任務狀態（符合 REST 語意）
- 在 `tasks` 表加入軟刪除欄位 `deleted_at`，`DELETE` 端點改為設定此欄位，查詢時自動過濾 `WHERE deleted_at IS NULL`
- 加入 rate limiting（`express-rate-limit`）保護 `/auth/login`，防止暴力破解
