# 第 18 週今日練習題：書籍借閱管理系統 REST API

## 題目說明

建立一個功能完整的「書籍借閱管理系統」REST API，模擬圖書館的核心業務流程。系統需支援會員管理、書籍管理、借閱記錄，並整合身份驗證、資料驗證、分頁查詢等前幾週學習的技術。

---

## 技術要求

- **Express.js**：RESTful 路由設計、Middleware、錯誤處理
- **PostgreSQL**：多資料表設計、JOIN 查詢、Transaction 處理
- **JWT**：管理員與會員角色的身份驗證
- **資料驗證**：joi 或 express-validator
- **測試**：supertest + Jest（至少三條路由的整合測試）

---

## 資料庫設計

```sql
-- 會員資料表
CREATE TABLE members (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  email VARCHAR(150) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  role VARCHAR(20) DEFAULT 'member',  -- 'admin' | 'member'
  created_at TIMESTAMP DEFAULT NOW()
);

-- 書籍資料表
CREATE TABLE books (
  id SERIAL PRIMARY KEY,
  title VARCHAR(200) NOT NULL,
  author VARCHAR(100) NOT NULL,
  isbn VARCHAR(20) UNIQUE,
  total_copies INT DEFAULT 1,
  available_copies INT DEFAULT 1,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 借閱記錄資料表
CREATE TABLE borrowings (
  id SERIAL PRIMARY KEY,
  member_id INT REFERENCES members(id),
  book_id INT REFERENCES books(id),
  borrowed_at TIMESTAMP DEFAULT NOW(),
  due_date TIMESTAMP NOT NULL,
  returned_at TIMESTAMP,
  status VARCHAR(20) DEFAULT 'active'  -- 'active' | 'returned' | 'overdue'
);
```

## 具體任務

### 1. 環境設置
- 建立 `src/` 目錄結構（routes、controllers、middleware、db）
- 設定 `.env`：`DATABASE_URL`、`JWT_SECRET`、`PORT`
- 建立資料庫連線池（使用 `pg` 套件）

### 2. 身份驗證模組（`/api/auth`）
- `POST /api/auth/register`：會員註冊（bcrypt 雜湊密碼）
- `POST /api/auth/login`：登入後回傳 JWT Token
- 建立 `authMiddleware`，驗證 Bearer Token 並將 `req.user` 注入

### 3. 書籍管理（`/api/books`）（需管理員 role）
- `GET /api/books`：列出所有書籍，支援分頁（`?page=1&limit=10`）與關鍵字搜尋（`?search=書名`）
- `POST /api/books`：新增書籍（管理員專用）
- `PUT /api/books/:id`：更新書籍資訊（管理員專用）
- `DELETE /api/books/:id`：下架書籍（管理員專用，需確認無進行中借閱）

### 4. 借閱功能（`/api/borrowings`）
- `POST /api/borrowings`：借閱書籍
  - 使用 **Transaction** 確保：`available_copies - 1` 與 `borrowings` 新增是原子操作
  - 若無可用庫存，回傳 `409 Conflict`
- `PUT /api/borrowings/:id/return`：歸還書籍
  - Transaction：更新 `returned_at`、`status = 'returned'`、`available_copies + 1`
- `GET /api/borrowings/my`：查詢目前登入會員的借閱紀錄（含書籍資訊，使用 JOIN）
- `GET /api/borrowings/overdue`：（管理員）查詢所有逾期未還的借閱記錄

### 5. 資料驗證
- 為「新增書籍」和「借閱」API 加上輸入驗證（isbn 格式、due_date 必須在未來）
- 統一錯誤回應格式：
  ```json
  { "status": "error", "message": "...", "details": [...] }
  ```

### 6. 整合測試
使用 supertest + Jest，撰寫以下測試：
1. `POST /api/auth/register` 與 `POST /api/auth/login` 流程
2. 借閱書籍時庫存不足應回傳 409
3. 歸還後 `available_copies` 應正確加回

## 提示

- Transaction 寫法：
  ```javascript
  const client = await pool.connect();
  try {
    await client.query('BEGIN');
    // ... 多個查詢
    await client.query('COMMIT');
  } catch (err) {
    await client.query('ROLLBACK');
    throw err;
  } finally {
    client.release();
  }
  ```
- JWT Middleware 建議檢查 `req.headers.authorization` 是否為 `Bearer <token>` 格式
- 測試時可使用 in-memory 測試資料庫或 Docker 啟動臨時 PostgreSQL container

## 進階挑戰（選做）

1. **自動更新逾期狀態**：使用 `node-cron` 每天凌晨執行一次，將 `due_date < NOW() AND status = 'active'` 的記錄更新為 `'overdue'`
2. **借閱統計 API**：`GET /api/stats` 回傳最熱門的 5 本書（借閱次數最多）
3. **軟刪除書籍**：在 books 資料表加入 `deleted_at`，`DELETE` 操作僅標記而非真正刪除
4. **Rate Limiting**：使用 `express-rate-limit` 防止暴力登入（每 IP 每 15 分鐘最多 10 次登入嘗試）
