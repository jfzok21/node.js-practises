# 第 6 週今日練習題：資料驗證與錯誤回應

## 題目說明

建立一個使用者註冊 API，整合完整的資料驗證機制與標準化錯誤回應格式。所有輸入資料必須經過驗證，並在驗證失敗時回傳清楚、一致的錯誤訊息，協助前端開發者快速定位問題。

## 技術要求

- **Express.js**：建立 RESTful 路由，設計統一的錯誤回應中介層
- **PostgreSQL**：建立 `users` 資料表，確保唯一性約束（email 不重複）

## 具體任務

### 1. 建立資料庫資料表

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(50) NOT NULL UNIQUE,
  email VARCHAR(255) NOT NULL UNIQUE,
  age INTEGER,
  created_at TIMESTAMP DEFAULT NOW()
);
```

### 2. 實作 POST /api/users 路由

接受以下 JSON body：

```json
{
  "username": "alice",
  "email": "alice@example.com",
  "age": 25
}
```

### 3. 驗證規則（必須全部實作）

| 欄位 | 規則 |
|------|------|
| `username` | 必填、長度 3–50 字元、只允許英數字與底線 |
| `email` | 必填、合法 email 格式 |
| `age` | 選填、若有提供必須為正整數且 ≤ 150 |

### 4. 標準化錯誤回應格式

驗證失敗時回傳 HTTP 400，格式如下：

```json
{
  "status": "error",
  "code": "VALIDATION_ERROR",
  "message": "輸入資料驗證失敗",
  "errors": [
    { "field": "username", "message": "username 只能包含英數字與底線" },
    { "field": "email",    "message": "email 格式不正確" }
  ]
}
```

資料庫衝突（重複 email / username）回傳 HTTP 409：

```json
{
  "status": "error",
  "code": "CONFLICT",
  "message": "username 已被使用"
}
```

成功建立回傳 HTTP 201：

```json
{
  "status": "success",
  "data": {
    "id": 1,
    "username": "alice",
    "email": "alice@example.com",
    "age": 25,
    "created_at": "2026-08-17T00:00:00.000Z"
  }
}
```

### 5. 建立全域錯誤處理 Middleware

在 Express app 最後加上錯誤處理中介層，捕捉所有未處理的錯誤，並統一格式回傳 HTTP 500：

```json
{
  "status": "error",
  "code": "INTERNAL_SERVER_ERROR",
  "message": "伺服器發生預期外的錯誤"
}
```

### 6. 額外路由：GET /api/users/:id

- id 必須為正整數，否則回傳 400
- 找不到使用者回傳 404：

```json
{
  "status": "error",
  "code": "NOT_FOUND",
  "message": "使用者不存在"
}
```

## 提示

- 將驗證邏輯抽成獨立函式（e.g. `validateUser(body)`），保持路由程式碼簡潔
- 利用正規表達式驗證 username：`/^[a-zA-Z0-9_]{3,50}$/`
- 驗證 email 可使用正規表達式或輕量套件（如 `validator.js` 的 `isEmail`）
- PostgreSQL 拋出的唯一性錯誤 code 為 `'23505'`，可用 `err.code === '23505'` 判斷
- 善用 `parseInt()` 搭配 `isNaN()` 驗證整數欄位

## 進階挑戰（選做）

1. **使用 `joi` 或 `zod`** 取代手動驗證邏輯，讓 schema 定義更具可讀性
2. **新增 PATCH /api/users/:id** 支援部分更新，並重複使用相同的驗證邏輯
3. **速率限制**：使用 `express-rate-limit` 限制每個 IP 每分鐘最多呼叫 `/api/users` 10 次，超過時回傳 429 錯誤
4. **請求日誌**：記錄每次請求的 method、path、回應狀態碼、處理時間（ms）
