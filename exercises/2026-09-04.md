# 第 9 週今日練習題：分頁與排序 API

## 題目說明

建立一個支援分頁（Pagination）與排序（Sorting）的 Express + PostgreSQL RESTful API。
你需要設計一個「商品列表」端點，讓前端可以透過查詢字串控制每頁筆數、目前頁數、排序欄位與方向。

## 技術要求

- **Express.js**：設計 GET 路由，使用查詢字串參數控制分頁與排序行為
- **PostgreSQL**：使用 `LIMIT`、`OFFSET`、`ORDER BY` 實作資料庫層的分頁與排序
- **回應格式**：除資料本身外，一併回傳分頁後設資訊（總筆數、總頁數、目前頁數）

## 具體任務

1. **建立資料表與測試資料**
   建立 `products` 資料表：
   ```sql
   CREATE TABLE products (
     id SERIAL PRIMARY KEY,
     name VARCHAR(100) NOT NULL,
     price NUMERIC(10, 2) NOT NULL,
     stock INT NOT NULL DEFAULT 0,
     created_at TIMESTAMP DEFAULT NOW()
   );
   ```
   使用 `INSERT` 插入至少 30 筆假資料，方便測試分頁效果。

2. **實作 GET /products 路由**
   接受以下查詢字串參數：
   - `page`（預設：`1`）：目前頁數
   - `limit`（預設：`10`，最大：`50`）：每頁筆數
   - `sort_by`（預設：`id`）：排序欄位（允許：`id`、`name`、`price`、`stock`、`created_at`）
   - `order`（預設：`asc`）：排序方向（`asc` 或 `desc`）

3. **回傳結構化 JSON 回應**
   ```json
   {
     "data": [...],
     "pagination": {
       "total": 30,
       "total_pages": 3,
       "current_page": 1,
       "limit": 10,
       "has_next": true,
       "has_prev": false
     }
   }
   ```

4. **防止 SQL Injection**
   `sort_by` 與 `order` 必須經過白名單驗證，不可直接拼接進 SQL 字串。

5. **處理邊界情況**
   - `page` 或 `limit` 為非正整數時回傳 `400 Bad Request`
   - `page` 超過總頁數時回傳空 `data` 陣列，`pagination` 仍正確

## 提示

- 計算 `OFFSET`：`(page - 1) * limit`
- 取得總筆數可用 `SELECT COUNT(*) FROM products`，搭配資料查詢一起執行（兩個 query 或用 `COUNT(*) OVER()`）
- 白名單驗證範例：
  ```js
  const ALLOWED_SORT = ['id', 'name', 'price', 'stock', 'created_at'];
  const ALLOWED_ORDER = ['asc', 'desc'];
  if (!ALLOWED_SORT.includes(sort_by)) return res.status(400).json({ error: 'Invalid sort_by' });
  ```
- `parseInt()` 之後記得用 `isNaN()` 或 `Number.isInteger()` 確認型別正確

## 進階挑戰（選做）

- **關鍵字搜尋**：加入 `?search=` 參數，對 `name` 欄位做 `ILIKE '%keyword%'` 模糊搜尋，並確保分頁計算也考慮篩選後的總筆數
- **多欄位排序**：支援 `sort_by=price,created_at&order=asc,desc` 格式，依序套用多個排序條件
- **游標分頁（Cursor Pagination）**：改用 `?after_id=` 取代 offset 分頁，適合大資料集或即時更新資料的場景
