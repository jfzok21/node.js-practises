# 第 20 週今日練習題：任務管理系統 API 實戰專案

## 題目說明

實作一個完整的任務管理系統（Task Management System）後端 REST API，支援專案建立、任務指派、狀態追蹤，以及成員協作功能。整合 JWT 身份驗證、多資料表關聯、Transaction 與完整的錯誤處理，模擬真實 SaaS 產品的後端架構。

## 技術要求

- **Express.js**：RESTful 路由設計、自訂 Middleware、集中錯誤處理
- **PostgreSQL**：多資料表設計（users、projects、tasks、project_members）、JOIN 查詢、Transaction 處理
- **JWT**：Bearer Token 驗證，保護所有需要登入的端點
- **資料驗證**：輸入欄位驗證與友善的錯誤回應（HTTP 狀態碼語意正確）
- **分頁**：任務列表支援分頁與排序

## 資料表結構

```sql
-- 使用者
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 專案
CREATE TABLE projects (
  id SERIAL PRIMARY KEY,
  name VARCHAR(200) NOT NULL,
  description TEXT,
  owner_id INT REFERENCES users(id) ON DELETE CASCADE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 專案成員（多對多：users ↔ projects）
CREATE TABLE project_members (
  project_id INT REFERENCES projects(id) ON DELETE CASCADE,
  user_id INT REFERENCES users(id) ON DELETE CASCADE,
  role VARCHAR(20) DEFAULT 'member', -- 'owner' | 'member'
  joined_at TIMESTAMPTZ DEFAULT NOW(),
  PRIMARY KEY (project_id, user_id)
);

-- 任務
CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  project_id INT REFERENCES projects(id) ON DELETE CASCADE,
  title VARCHAR(300) NOT NULL,
  description TEXT,
  status VARCHAR(20) DEFAULT 'todo', -- 'todo' | 'in_progress' | 'done'
  priority VARCHAR(10) DEFAULT 'medium', -- 'low' | 'medium' | 'high'
  assignee_id INT REFERENCES users(id) ON DELETE SET NULL,
  due_date DATE,
  created_by INT REFERENCES users(id),
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

## 具體任務

### 1. 身份驗證模組

實作以下端點：

```
POST /api/auth/register   -- 註冊（name, email, password）
POST /api/auth/login      -- 登入，回傳 JWT
GET  /api/auth/me         -- 取得目前登入使用者資訊（需 JWT）
```

- 密碼使用 `bcrypt` 雜湊儲存
- JWT 有效期設為 7 天
- 驗證 Middleware `requireAuth` 解析 `Authorization: Bearer <token>`

---

### 2. 專案管理端點

```
POST   /api/projects               -- 建立專案（自動將建立者加入 project_members，role = 'owner'）
GET    /api/projects               -- 列出我參與的所有專案（JOIN project_members）
GET    /api/projects/:id           -- 取得專案詳細資訊（含成員列表）
DELETE /api/projects/:id           -- 刪除專案（僅 owner 可操作）

POST   /api/projects/:id/members   -- 邀請成員加入（提供 email，僅 owner 可操作）
DELETE /api/projects/:id/members/:userId -- 移除成員（僅 owner 可操作）
```

**Transaction 要求**：建立專案時，`INSERT INTO projects` 與 `INSERT INTO project_members` 必須在同一 Transaction 內完成，確保資料一致性。

---

### 3. 任務管理端點

```
POST   /api/projects/:projectId/tasks         -- 建立任務
GET    /api/projects/:projectId/tasks         -- 列出專案任務（支援分頁、排序、狀態篩選）
GET    /api/projects/:projectId/tasks/:taskId -- 取得單一任務
PATCH  /api/projects/:projectId/tasks/:taskId -- 更新任務（title / status / priority / assignee_id / due_date）
DELETE /api/projects/:projectId/tasks/:taskId -- 刪除任務
```

**查詢參數範例**：

```
GET /api/projects/1/tasks?status=in_progress&priority=high&assignee_id=2&sort=due_date&order=asc&page=1&limit=10
```

---

### 4. 權限控管 Middleware

實作 `requireProjectMember` Middleware：

- 確認目前使用者是該專案的成員（查詢 `project_members`）
- 若非成員，回傳 `403 Forbidden`
- 套用於所有 `/api/projects/:id/*` 路由

---

### 5. 統計端點

```
GET /api/projects/:id/stats
```

回傳：

```json
{
  "total_tasks": 20,
  "todo": 8,
  "in_progress": 7,
  "done": 5,
  "overdue": 3,
  "members_count": 4
}
```

使用單一 SQL 查詢（`COUNT + CASE WHEN`）完成統計，避免多次往返資料庫。

## 提示

- 使用 `express-async-errors` 套件，讓 async route handler 的例外自動轉交錯誤處理 Middleware
- 分頁查詢使用 `LIMIT $1 OFFSET $2`，並同時回傳 `total` 筆數（使用 `COUNT(*) OVER()` 視窗函數或兩次查詢）
- `updated_at` 欄位在每次 PATCH 任務時，以 `updated_at = NOW()` 更新
- 刪除專案時，PostgreSQL 的 `ON DELETE CASCADE` 會自動清除相關的 `project_members` 與 `tasks`，不需手動刪除
- 測試時可用 Postman 或 curl；先 register → login 取得 token → 帶入後續請求

## 進階挑戰（選做）

1. **軟刪除**：為 `tasks` 加入 `deleted_at TIMESTAMPTZ` 欄位，刪除改為 `UPDATE tasks SET deleted_at = NOW()`，所有查詢加上 `WHERE deleted_at IS NULL`

2. **任務留言**：新增 `task_comments` 資料表，實作：
   ```
   POST   /api/projects/:projectId/tasks/:taskId/comments
   GET    /api/projects/:projectId/tasks/:taskId/comments
   DELETE /api/projects/:projectId/tasks/:taskId/comments/:commentId
   ```

3. **活動紀錄**：建立 `activity_logs` 資料表，每次任務狀態變更時記錄 `(task_id, user_id, action, old_value, new_value, created_at)`

4. **API 測試**：使用 `supertest` + `Jest` 為 `POST /api/projects`、`GET /api/projects/:id/tasks` 撰寫整合測試，測試資料庫使用獨立的 test schema
