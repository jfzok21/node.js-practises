# 第 14 週今日練習題：任務管理 API（全功能實戰專案）

## 題目說明

建立一個完整的「任務管理系統」RESTful API，整合前幾週所學的所有技術：Express 路由、PostgreSQL CRUD、資料驗證、JWT 身份驗證、分頁排序、以及交易處理。這是一個接近真實業務場景的實戰練習。

---

## 技術要求

- **Express.js**：路由模組化拆分、middleware 鏈、統一錯誤處理
- **PostgreSQL**：多資料表設計（users、tasks、task_tags）、JOIN 查詢、Transaction
- **JWT**：登入取得 token，受保護路由需驗證
- **資料驗證**：joi 或自訂 validator
- **分頁與排序**：支援 `?page=&limit=&sort=&order=`

## 具體任務

### 1. 資料庫設計

建立以下三個資料表：

```sql
-- 使用者
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  name VARCHAR(100) NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 任務
CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  user_id INT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  title VARCHAR(255) NOT NULL,
  description TEXT,
  status VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending', 'in_progress', 'done')),
  priority INT DEFAULT 1 CHECK (priority BETWEEN 1 AND 5),
  due_date DATE,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 標籤（多對多）
CREATE TABLE task_tags (
  task_id INT REFERENCES tasks(id) ON DELETE CASCADE,
  tag VARCHAR(50) NOT NULL,
  PRIMARY KEY (task_id, tag)
);
```

### 2. 身份驗證模組 `/api/auth`

| 方法 | 路徑 | 說明 |
|------|------|------|
| POST | `/api/auth/register` | 註冊（email、password、name）|
| POST | `/api/auth/login` | 登入，回傳 JWT token |

- 密碼使用 `bcrypt` 雜湊儲存
- token 有效期 24 小時

### 3. 任務 CRUD `/api/tasks`（需 JWT）

| 方法 | 路徑 | 說明 |
|------|------|------|
| GET | `/api/tasks` | 列出自己的任務（支援分頁、排序、狀態篩選）|
| POST | `/api/tasks` | 建立任務（可同時附帶 tags）|
| GET | `/api/tasks/:id` | 取得單一任務（含 tags）|
| PUT | `/api/tasks/:id` | 更新任務 |
| DELETE | `/api/tasks/:id` | 刪除任務 |
| PATCH | `/api/tasks/:id/status` | 快速更新狀態 |

### 4. 標籤批次更新（使用 Transaction）

```
PUT /api/tasks/:id/tags
Body: { "tags": ["bug", "urgent", "backend"] }
```

- 在同一個 transaction 中：先刪除該任務舊有的所有 tags，再批次 INSERT 新 tags
- 任一步驟失敗則整個操作 ROLLBACK

### 5. 統計端點

```
GET /api/tasks/stats
```

回傳格式：
```json
{
  "total": 20,
  "by_status": {
    "pending": 10,
    "in_progress": 6,
    "done": 4
  },
  "overdue": 3
}
```

## 提示

- 將 JWT 驗證拆成獨立 middleware：`src/middlewares/auth.js`
- 路由按功能拆分：`src/routes/auth.js`、`src/routes/tasks.js`
- 用 PostgreSQL pool（`pg` 套件）管理連線，不要每次 request 新建連線
- Transaction 範例：
  ```js
  const client = await pool.connect();
  try {
    await client.query('BEGIN');
    await client.query('DELETE FROM task_tags WHERE task_id = $1', [taskId]);
    for (const tag of tags) {
      await client.query('INSERT INTO task_tags VALUES ($1, $2)', [taskId, tag]);
    }
    await client.query('COMMIT');
  } catch (err) {
    await client.query('ROLLBACK');
    throw err;
  } finally {
    client.release();
  }
  ```
- 分頁查詢記得用 `LIMIT $1 OFFSET $2` 並計算 total count

## 進階挑戰（選做）

1. **軟刪除**：替 tasks 加上 `deleted_at` 欄位，DELETE 只標記刪除時間而非真正移除，所有查詢加上 `WHERE deleted_at IS NULL`。

2. **搜尋功能**：支援 `?search=關鍵字`，對 title 和 description 做全文搜尋（`ILIKE '%keyword%'` 或 PostgreSQL 的 `tsvector`）。

3. **API 測試**：使用 `supertest + Jest` 為至少三個端點撰寫整合測試（含 auth 流程：先 register → login 取 token → 用 token 打受保護路由）。

4. **Rate Limiting**：使用 `express-rate-limit` 對 `/api/auth/login` 限制每分鐘最多 5 次請求，防止暴力破解。
