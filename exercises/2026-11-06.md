# 第 18 週今日練習題：電商訂單管理 API（實戰專案）

## 題目說明

建立一個電商後端 API，涵蓋商品管理、購物車與訂單流程。本練習整合 Express 路由設計、PostgreSQL 多資料表操作、JWT 身份驗證、交易處理與資料驗證，模擬真實電商後端的核心功能。

## 技術要求
- **Express.js**：RESTful 路由、自訂 Middleware（身份驗證、錯誤處理）
- **PostgreSQL**：多資料表 JOIN、交易（Transaction）、RETURNING 子句
- **驗證**：JWT 保護私有路由、請求資料格式驗證
- **設計**：適當的 HTTP 狀態碼與錯誤訊息回應

## 資料表設計

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE products (
  id SERIAL PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  price NUMERIC(10, 2) NOT NULL,
  stock INTEGER NOT NULL DEFAULT 0,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE orders (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id),
  status VARCHAR(50) DEFAULT 'pending',  -- pending / paid / cancelled
  total_price NUMERIC(10, 2) NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE order_items (
  id SERIAL PRIMARY KEY,
  order_id INTEGER REFERENCES orders(id),
  product_id INTEGER REFERENCES products(id),
  quantity INTEGER NOT NULL,
  unit_price NUMERIC(10, 2) NOT NULL
);
```

## 具體任務

1. **使用者認證**
   - `POST /api/register`：註冊帳號（email、password），密碼以 bcrypt 雜湊後儲存
   - `POST /api/login`：登入，回傳 JWT token

2. **商品 API（公開）**
   - `GET /api/products`：列出所有商品，支援 `?page=`、`?limit=`、`?search=` 查詢字串
   - `GET /api/products/:id`：取得單一商品詳情

3. **訂單 API（需 JWT 驗證）**
   - `POST /api/orders`：建立訂單
     - 請求 body：`{ items: [{ product_id, quantity }] }`
     - 使用 **交易（Transaction）** 完成：
       1. 確認每項商品庫存充足
       2. 扣減 `products.stock`
       3. 插入 `orders` 與 `order_items` 記錄
       4. 自動計算 `total_price`
     - 若任一商品庫存不足，整筆交易 ROLLBACK 並回傳 `400` 錯誤
   - `GET /api/orders`：查詢目前登入使用者的所有訂單（含訂單項目）
   - `GET /api/orders/:id`：查詢單一訂單詳情（含 JOIN 商品名稱）
   - `PATCH /api/orders/:id/cancel`：取消訂單（僅限 `pending` 狀態），並將庫存退回

4. **錯誤處理 Middleware**
   - 統一格式：`{ error: "訊息" }`
   - 處理：找不到資源（404）、驗證失敗（400）、未授權（401）

## 提示
- 交易寫法：
  ```js
  const client = await pool.connect();
  try {
    await client.query('BEGIN');
    // ... 多步驟操作
    await client.query('COMMIT');
  } catch (err) {
    await client.query('ROLLBACK');
    throw err;
  } finally {
    client.release();
  }
  ```
- 扣庫存時可用 `UPDATE products SET stock = stock - $1 WHERE id = $2 AND stock >= $1 RETURNING id` 來確保原子性，若 `rowCount === 0` 表示庫存不足
- JWT 驗證 Middleware 解析 `Authorization: Bearer <token>` header，將 `req.user` 設為 payload
- 分頁查詢使用 `LIMIT $1 OFFSET $2`，offset = (page - 1) * limit

## 進階挑戰（選做）
- 為 `products` 新增 `category` 欄位，支援 `?category=` 過濾
- 在 `GET /api/orders` 加入訂單狀態過濾：`?status=pending`
- 為訂單加入 soft delete：新增 `deleted_at` 欄位，查詢時過濾 `WHERE deleted_at IS NULL`
- 加入 rate limiting middleware（使用 `express-rate-limit`），限制登入 API 每分鐘最多 5 次請求
