# 第 16 週今日練習題：任務管理系統 API 實戰專案

## 題目說明

建立一個多人協作的任務管理系統（類似 Trello 精簡版），支援專案（Project）、任務（Task）與成員管理，並整合完整的身份驗證、資料驗證、分頁與通知記錄功能。本練習綜合前 15 週所學，模擬真實後端開發流程。

## 技術要求

- **Express.js**：RESTful API 設計、路由模組化、JWT Middleware、Joi 資料驗證、全域錯誤處理
- **PostgreSQL**：多資料表關聯（users / projects / project_members / tasks / task_comments）、JOIN 查詢、Transaction、分頁排序

## 資料庫結構

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(50) UNIQUE NOT NULL,
  email VARCHAR(100) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE projects (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  description TEXT,
  owner_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE project_members (
  project_id INTEGER REFERENCES projects(id) ON DELETE CASCADE,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  role VARCHAR(20) DEFAULT 'member',   -- 'owner' | 'member'
  joined_at TIMESTAMP DEFAULT NOW(),
  PRIMARY KEY (project_id, user_id)
);

CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  project_id INTEGER REFERENCES projects(id) ON DELETE CASCADE,
  title VARCHAR(200) NOT NULL,
  description TEXT,
  status VARCHAR(20) DEFAULT 'todo',   -- 'todo' | 'in_progress' | 'done'
  priority VARCHAR(10) DEFAULT 'medium', -- 'low' | 'medium' | 'high'
  assignee_id INTEGER REFERENCES users(id) ON DELETE SET NULL,
  due_date DATE,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE task_comments (
  id SERIAL PRIMARY KEY,
  task_id INTEGER REFERENCES tasks(id) ON DELETE CASCADE,
  author_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  content TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);
```

## 具體任務

### 任務一：專案初始化

1. 建立 Express 專案，安裝套件：
   ```
   express pg jsonwebtoken bcryptjs joi dotenv
   ```
2. 建立上述資料庫結構
3. 設定 `src/db.js`：使用 `pg.Pool`，從 `.env` 讀取 `DATABASE_URL`

### 任務二：使用者認證

4. `POST /api/auth/register`：驗證 email 格式、username 長度（3～50 字），bcrypt 雜湊密碼後存入 users
5. `POST /api/auth/login`：驗證密碼，成功回傳 JWT（有效 8 小時）
6. 實作 `src/middleware/auth.js`：解析 `Authorization: Bearer <token>`，驗證後將 `req.user` 設為 `{ id, username }`

### 任務三：專案管理

7. `POST /api/projects`：建立專案（需登入），**Transaction** 內同時將建立者加入 `project_members`（role: 'owner'）
8. `GET /api/projects`：列出目前使用者所屬的所有專案（含成員數量與任務數量，JOIN 查詢）
9. `GET /api/projects/:id`：取得專案詳情（含成員清單與最近 5 筆任務）
10. `POST /api/projects/:id/members`：邀請成員（僅 owner 可操作）；body: `{ "email": "..." }`，查詢 users 取得 user_id 後插入 project_members
11. `DELETE /api/projects/:id/members/:userId`：移除成員（僅 owner 可操作，不能移除 owner 自己）

### 任務四：任務 CRUD

12. `GET /api/projects/:id/tasks`：取得專案任務列表，支援：
    - 狀態篩選：`?status=todo`
    - 優先度篩選：`?priority=high`
    - 負責人篩選：`?assignee=userId`
    - 分頁：`?page=1&limit=20`
    - 排序：`?sort=due_date&order=asc`
13. `POST /api/projects/:id/tasks`：建立任務（需為專案成員）
14. `PUT /api/tasks/:id`：更新任務（可更新 title、description、status、priority、assignee_id、due_date）
15. `DELETE /api/tasks/:id`：刪除任務（僅專案 owner 或任務建立者）

### 任務五：任務留言

16. `GET /api/tasks/:id/comments`：取得任務的所有留言（含作者 username）
17. `POST /api/tasks/:id/comments`：新增留言（需為專案成員）
18. `DELETE /api/task-comments/:id`：刪除留言（僅留言作者）

### 任務六：統計端點

19. `GET /api/projects/:id/stats`：回傳專案統計資料，一次查詢取得：
    ```json
    {
      "total_tasks": 20,
      "todo": 8,
      "in_progress": 7,
      "done": 5,
      "overdue": 3,
      "members": 4
    }
    ```
    使用 `COUNT(*) FILTER (WHERE ...)` 語法在單一 SQL 完成

## 提示

- `project_members` 的 **成員資格驗證** 可抽成 `requireProjectMember(req, res, next)` middleware，從 `req.params.id` 與 `req.user.id` 查詢
- 更新任務時使用 **動態 SQL**：只更新 body 中有提供的欄位（建構 `SET key = $1` 片段）
- `FILTER (WHERE ...)` 是 PostgreSQL 聚合函數的條件語法：
  ```sql
  SELECT
    COUNT(*) AS total_tasks,
    COUNT(*) FILTER (WHERE status = 'todo') AS todo,
    COUNT(*) FILTER (WHERE due_date < NOW() AND status != 'done') AS overdue
  FROM tasks WHERE project_id = $1
  ```
- Transaction 範例：`pool.connect()` → `BEGIN` → 業務操作 → `COMMIT`，在 `finally` 呼叫 `client.release()`
- 路由建議：`routes/auth.js`、`routes/projects.js`、`routes/tasks.js`、`routes/taskComments.js`

## 進階挑戰（選做）

1. **任務狀態歷程**：建立 `task_history` 表，每次 status 變更時記錄舊值、新值、操作者與時間
2. **到期提醒查詢**：`GET /api/projects/:id/tasks?due_within=3`，回傳 3 天內到期且未完成的任務
3. **批次更新**：`PATCH /api/projects/:id/tasks/batch`，接受 `{ ids: [1,2,3], status: "done" }` 一次更新多筆任務（需驗證所有 id 都屬於此專案）
4. **API 測試**：使用 Jest + supertest 為任務清單 API（任務 12）撰寫至少 6 個測試案例
5. **軟刪除**：tasks 加入 `deleted_at` 欄位，刪除時只標記而非實際移除；查詢時過濾 `WHERE deleted_at IS NULL`
