# 第 20 週今日練習題：書籍借閱管理系統 API

## 題目說明

建立一個完整的書籍借閱管理系統 REST API，模擬圖書館的核心功能。系統需支援書籍管理、會員管理、借閱紀錄，並整合 JWT 身份驗證、資料驗證、分頁查詢與交易處理。

## 技術要求

- **Express.js**：RESTful 路由設計、Middleware 組合（auth、validation、error handler）
- **PostgreSQL**：多資料表關聯（JOIN）、Transaction 確保借閱一致性、分頁排序查詢

## 資料庫設計

```sql
CREATE TABLE members (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  borrow_limit INT DEFAULT 3,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE books (
  id SERIAL PRIMARY KEY,
  title VARCHAR(255) NOT NULL,
  author VARCHAR(100) NOT NULL,
  isbn VARCHAR(20) UNIQUE NOT NULL,
  total_copies INT NOT NULL DEFAULT 1,
  available_copies INT NOT NULL DEFAULT 1,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE borrow_records (
  id SERIAL PRIMARY KEY,
  member_id INT REFERENCES members(id),
  book_id INT REFERENCES books(id),
  borrowed_at TIMESTAMPTZ DEFAULT NOW(),
  due_date TIMESTAMPTZ NOT NULL,
  returned_at TIMESTAMPTZ,
  status VARCHAR(20) DEFAULT 'active' CHECK (status IN ('active', 'returned', 'overdue'))
);
```

## 具體任務

1. **會員系統**
   - `POST /api/auth/register`：註冊（bcrypt 雜湊密碼）
   - `POST /api/auth/login`：登入，回傳 JWT token

2. **書籍管理**（需 JWT 驗證）
   - `GET /api/books`：列出所有書籍，支援 `?search=關鍵字&page=1&limit=10&sort=title&order=asc`
   - `GET /api/books/:id`：取得單本書籍詳情（含目前借閱狀況）
   - `POST /api/books`：新增書籍（管理員專用，可用 role 欄位區分）
   - `PATCH /api/books/:id`：更新書籍資訊

3. **借閱功能**（需 JWT 驗證，使用 Transaction）
   - `POST /api/borrows`：借書
     - 驗證：書籍是否有庫存、會員是否超過借閱上限
     - 交易：同時更新 `available_copies` 並建立 `borrow_records`
   - `PATCH /api/borrows/:id/return`：還書
     - 交易：更新 `available_copies`，設定 `returned_at` 與 `status`
   - `GET /api/borrows/my`：查詢目前登入者的借閱紀錄（含書籍資訊）

4. **資料驗證與錯誤處理**
   - 以自訂 Middleware 驗證所有輸入（title 不可空白、isbn 格式等）
   - 統一錯誤回應格式：`{ "error": "訊息", "code": "ERROR_CODE" }`

5. **整合測試**
   - 使用 `supertest` + `Jest` 撰寫至少 5 個測試案例，覆蓋借書、還書、庫存不足等情境

## 提示

- 使用 `pg` 的 `client.query('BEGIN') / COMMIT / ROLLBACK` 管理交易
- JWT 驗證 Middleware 可從 `Authorization: Bearer <token>` header 解析
- 分頁公式：`OFFSET = (page - 1) * limit`，回應需包含 `{ data, total, page, totalPages }`
- 庫存檢查與借閱上限檢查務必在同一個 Transaction 內執行，避免 race condition
- 超過到期日的紀錄可用 `CASE WHEN due_date < NOW() AND status = 'active' THEN 'overdue'` 動態標記

## 進階挑戰（選做）

- **逾期通知**：新增 `GET /api/borrows/overdue`，列出所有逾期未還的紀錄（含會員與書籍資訊），使用 `JOIN` 一次查詢
- **統計端點**：`GET /api/stats`，回傳借閱最多的前 5 本書、目前借閱量最高的會員
- **檔案上傳**：`POST /api/books/:id/cover`，使用 `multer` 上傳書籍封面圖片並儲存路徑至 DB
- **Rate Limiting**：使用 `express-rate-limit` 限制登入端點每 15 分鐘最多 10 次請求
