# 第 8 週今日練習題：檔案上傳 API（multer）

## 題目說明

實作一個支援檔案上傳的 Express API，讓使用者能夠上傳圖片或文件，並將檔案資訊（原始檔名、儲存路徑、大小、MIME 類型）記錄至 PostgreSQL 資料庫，同時提供查詢與刪除已上傳檔案的功能。

## 技術要求
- **Express.js**：使用 `multer` middleware 處理 `multipart/form-data` 請求；設定檔案儲存路徑、命名策略與大小限制；回傳適當的 JSON 回應與 HTTP 狀態碼。
- **PostgreSQL**：建立 `uploads` 資料表儲存檔案後設資料（metadata）；支援新增、查詢、刪除紀錄。

## 具體任務

1. **建立資料表**
   在 PostgreSQL 中建立 `uploads` 資料表，欄位包含：
   - `id SERIAL PRIMARY KEY`
   - `original_name TEXT NOT NULL`（使用者原始檔名）
   - `stored_name TEXT NOT NULL`（伺服器上實際儲存的檔名，避免衝突）
   - `file_path TEXT NOT NULL`（相對儲存路徑）
   - `mime_type TEXT NOT NULL`
   - `size_bytes INTEGER NOT NULL`
   - `uploaded_at TIMESTAMP DEFAULT NOW()`

2. **實作上傳端點**
   - `POST /upload`：接收單一檔案（欄位名稱 `file`），限制大小 5 MB，僅允許 JPEG / PNG / PDF；上傳成功後將後設資料存入資料庫，並回傳：
     ```json
     { "id": 1, "original_name": "photo.jpg", "size_bytes": 204800, "uploaded_at": "..." }
     ```

3. **實作查詢端點**
   - `GET /uploads`：列出所有已上傳檔案的後設資料（不含實際檔案內容），以 `uploaded_at` 降冪排序。
   - `GET /uploads/:id`：取得單一檔案紀錄；若不存在回傳 404。

4. **實作刪除端點**
   - `DELETE /uploads/:id`：從資料庫刪除紀錄，**同時**使用 `fs.unlink` 刪除磁碟上的實際檔案；若檔案不存在回傳 404。

5. **錯誤處理**
   - 上傳檔案超過大小限制時，回傳 `{ "error": "File too large" }`（HTTP 413）。
   - 上傳不允許的 MIME 類型時，回傳 `{ "error": "Invalid file type" }`（HTTP 400）。
   - 使用 multer 的 `fileFilter` 與 `limits` 選項實作上述限制。

## 提示

- 使用 `multer.diskStorage` 自訂 `destination` 與 `filename`，檔名建議以 `Date.now() + '-' + originalname` 組成以避免衝突。
- `req.file` 物件包含 `originalname`、`filename`、`path`、`mimetype`、`size` 等欄位，可直接用來組 INSERT 語句。
- 記得在 `fileFilter` 的 callback 中傳入 `new Error(...)` 以便後續 multer 錯誤處理 middleware 能捕捉它。
- multer 的錯誤（如超過大小限制）屬於 `MulterError`，需在錯誤處理 middleware 中用 `err instanceof multer.MulterError` 判斷。
- 刪除磁碟檔案時，可用 `fs.promises.unlink` 配合 async/await 讓程式碼更整潔。

## 進階挑戰（選做）

- **多檔上傳**：改用 `multer().array('files', 10)` 支援一次上傳最多 10 個檔案，並以交易（transaction）確保所有紀錄一起寫入或全部回滾。
- **取得檔案**：新增 `GET /uploads/:id/file` 端點，用 `res.sendFile` 或 `res.download` 回傳實際檔案供下載。
- **縮圖生成**：整合 `sharp` 套件，對上傳的圖片自動產生 200×200 縮圖並一併儲存，在查詢結果中加入 `thumbnail_path` 欄位。
