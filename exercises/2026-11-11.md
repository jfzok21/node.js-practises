# 第 19 週今日練習題：電商訂單管理系統 API

## 題目說明

實作一個電商訂單管理系統的後端 REST API，整合商品目錄、購物車、訂單建立與付款狀態管理。本題著重於複雜交易流程（庫存扣減 + 訂單建立的原子性）、多層資料表關聯，以及完整的狀態機設計。

---

## 技術要求

- **Express.js**：模組化路由（`routes/`、`controllers/`、`middleware/`），統一錯誤處理
- **PostgreSQL**：多資料表（products、orders、order_items、payments），Transaction 確保訂單原子性
- **JWT**：使用者認證，區分一般用戶與管理員角色
- **資料驗證**：使用 `joi` 或 `express-validator` 驗證請求

---

## 資料庫 Schema

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  email VARCHAR(150) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  role VARCHAR(20) DEFAULT 'customer', -- 'customer' | 'admin'
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE products (
  id SERIAL PRIMARY KEY,
  name VARCHAR(200) NOT NULL,
  description TEXT,
  price NUMERIC(10,2) NOT NULL CHECK (price >= 0),
  stock INT NOT NULL DEFAULT 0 CHECK (stock >= 0),
  category VARCHAR(50),
  is_active BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE orders (
  id SERIAL PRIMARY KEY,
  user_id INT REFERENCES users(id),
  status VARCHAR(20) DEFAULT 'pending',
  -- 'pending' | 'confirmed' | 'shipped' | 'delivered' | 'cancelled'
  total_amount NUMERIC(10,2) NOT NULL,
  shipping_address TEXT,
  note TEXT,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE order_items (
  id SERIAL PRIMARY KEY,
  order_id INT REFERENCES orders(id) ON DELETE CASCADE,
  product_id INT REFERENCES products(id),
  quantity INT NOT NULL CHECK (quantity > 0),
  unit_price NUMERIC(10,2) NOT NULL
);

CREATE TABLE payments (
  id SERIAL PRIMARY KEY,
  order_id INT REFERENCES orders(id),
  amount NUMERIC(10,2) NOT NULL,
  method VARCHAR(30),  -- 'credit_card' | 'transfer' | 'cod'
  status VARCHAR(20) DEFAULT 'pending', -- 'pending' | 'paid' | 'failed' | 'refunded'
  paid_at TIMESTAMP,
  created_at TIMESTAMP DEFAULT NOW()
);
```

## 具體任務

### 1. 環境設定
- 建立 `.env`：`DATABASE_URL`、`JWT_SECRET`、`PORT`
- 建立 `src/db.js`（pg Pool）
- 執行 Schema，插入 10 筆測試商品資料

### 2. 使用者認證 `src/routes/auth.js`
- `POST /api/auth/register`：註冊（name、email、password），密碼以 `bcrypt` 雜湊
- `POST /api/auth/login`：驗證帳密，回傳 JWT（有效期 8 小時）
  - Payload 包含：`{ id, email, role }`

### 3. 商品 API `src/routes/products.js`
- `GET /api/products`：列出所有上架商品，支援：
  - `?search=關鍵字` 搜尋商品名稱
  - `?category=電子` 依分類篩選
  - `?page=1&limit=12` 分頁
  - `?sort=price&order=asc` 排序
- `GET /api/products/:id`：取得單一商品詳情
- `POST /api/products`（需 JWT，role = admin）：新增商品
- `PUT /api/products/:id`（需 JWT，role = admin）：更新商品資訊或庫存
- `DELETE /api/products/:id`（需 JWT，role = admin）：將商品設為 `is_active = false`（軟刪除）

### 4. 訂單 API `src/routes/orders.js`（需 JWT）

#### 建立訂單（核心任務）
`POST /api/orders`

Request body：
```json
{
  "items": [
    { "product_id": 1, "quantity": 2 },
    { "product_id": 3, "quantity": 1 }
  ],
  "shipping_address": "台北市信義區...",
  "note": "請放門口",
  "payment_method": "credit_card"
}
```

**使用 Transaction 完成以下步驟（全部成功才 COMMIT，任一失敗則 ROLLBACK）：**
1. 逐一確認每個 `product_id` 存在且 `is_active = true`
2. 確認每個商品的 `stock >= quantity`，不足則回傳 409 並說明哪個商品缺貨
3. 計算 `total_amount = SUM(unit_price × quantity)`
4. 建立 `orders` 記錄，status = `'pending'`
5. 批次建立 `order_items` 記錄（記錄下單當時的 `unit_price`）
6. 扣減每個商品的庫存：`stock = stock - quantity`
7. 建立 `payments` 記錄，status = `'pending'`

#### 其他端點
- `GET /api/orders`：查詢當前使用者的所有訂單（含 order_items，使用 JOIN）
- `GET /api/orders/:id`：取得單一訂單詳情（含商品名稱、付款狀態）
- `PUT /api/orders/:id/cancel`：取消訂單
  - 只有 `status = 'pending'` 的訂單可取消
  - 使用 Transaction：更新訂單 status = `'cancelled'`，並歸還庫存

### 5. 付款 API `src/routes/payments.js`（需 JWT）
- `POST /api/payments/:order_id/confirm`：模擬付款成功
  - 更新 `payments.status = 'paid'`，記錄 `paid_at`
  - 更新 `orders.status = 'confirmed'`
- `GET /api/orders/:id/payment`：查詢訂單的付款資訊

### 6. 管理員 API（需 JWT，role = admin）
- `GET /api/admin/orders`：列出所有訂單，支援 `?status=pending` 篩選
- `PUT /api/admin/orders/:id/status`：更新訂單狀態（pending → confirmed → shipped → delivered）
  - 狀態只能往前推進，不可跳過或後退，否則回傳 422

## 提示

- 訂單狀態機合法轉換：
  ```
  pending → confirmed → shipped → delivered
  pending → cancelled
  ```
- 批次 INSERT order_items 可用：
  ```sql
  INSERT INTO order_items (order_id, product_id, quantity, unit_price)
  VALUES ($1,$2,$3,$4), ($5,$6,$7,$8), ...
  ```
  或用迴圈分次插入（後者比較好除錯）
- `FOR UPDATE` 防止並發超賣：
  ```sql
  SELECT * FROM products WHERE id = $1 FOR UPDATE
  ```
- JWT Middleware 解析 role：
  ```js
  const requireAdmin = (req, res, next) => {
    if (req.user.role !== 'admin') return res.status(403).json({ error: 'Forbidden' });
    next();
  };
  ```
- 軟刪除查詢時記得加 `WHERE is_active = TRUE`

## 進階挑戰（選做）

1. **庫存警示**：當商品 `stock < 5` 時，`GET /api/products/:id` 回應中加入 `"low_stock": true`
2. **訂單統計**（管理員）：`GET /api/admin/stats`
   - 今日訂單數、今日營收
   - 庫存不足（stock < 10）的商品清單
   - 使用 `GROUP BY` + `DATE_TRUNC` 彙總
3. **折扣碼**：新增 `coupons` 資料表，建立訂單時可帶入 `coupon_code`，驗證有效性並計算折扣後金額
4. **整合測試**：使用 `supertest + Jest` 為「建立訂單 → 付款 → 取消訂單歸還庫存」撰寫端對端測試流程
