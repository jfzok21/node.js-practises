# 第 10 週今日練習題：銀行轉帳系統（Transaction 交易處理）

## 題目說明

建立一個簡易的銀行轉帳 API，使用 PostgreSQL 的交易（Transaction）機制確保資料一致性。當轉帳過程中發生任何錯誤（如餘額不足、帳戶不存在），整個操作必須回滾（Rollback），避免資料不一致的問題。

## 技術要求

- **Express.js**：建立 RESTful API 路由處理轉帳請求
- **PostgreSQL**：使用 `BEGIN / COMMIT / ROLLBACK` 進行交易控制，搭配 `pg` 套件的 `client.query()` 管理連線

## 具體任務

1. **建立資料庫結構**
   - 建立 `accounts` 資料表，欄位包含：
     - `id` SERIAL PRIMARY KEY
     - `owner` VARCHAR(100) NOT NULL
     - `balance` NUMERIC(12, 2) NOT NULL DEFAULT 0
   - 新增測試用帳戶資料（至少 2 筆，各有初始餘額）

2. **實作 GET /accounts**
   - 回傳所有帳戶列表（id、owner、balance）

3. **實作 POST /transfer**
   - 接受請求 body：`{ from_id, to_id, amount }`
   - 在同一個 Transaction 中執行以下步驟：
     a. 確認 `from_id` 帳戶存在且餘額充足
     b. 從來源帳戶扣除金額（UPDATE）
     c. 將金額加到目標帳戶（UPDATE）
     d. 成功則 COMMIT，任何錯誤則 ROLLBACK
   - 回傳轉帳結果（成功訊息 + 雙方最新餘額）

4. **錯誤處理**
   - 餘額不足：回傳 400 + `{ error: "餘額不足" }`
   - 帳戶不存在：回傳 404 + `{ error: "帳戶不存在" }`
   - 轉帳金額 <= 0：回傳 400 + `{ error: "轉帳金額必須大於 0" }`
   - 來源與目標相同：回傳 400 + `{ error: "不可轉帳給自己" }`

5. **測試**
   - 使用 curl 或 Postman 測試正常轉帳、餘額不足、帳戶不存在的情況

## 提示

- 使用 `client.query('BEGIN')` 開始交易，不要用 `pool.query()`，因為需要保持同一個連線
- 記得在 `finally` 區塊執行 `client.release()` 歸還連線
- 範例流程：
  ```js
  const client = await pool.connect();
  try {
    await client.query('BEGIN');
    // ... 執行操作 ...
    await client.query('COMMIT');
  } catch (err) {
    await client.query('ROLLBACK');
    throw err;
  } finally {
    client.release();
  }
  ```
- `FOR UPDATE` 鎖定語法可防止並發問題：`SELECT ... WHERE id = $1 FOR UPDATE`

## 進階挑戰（選做）

2. **GET /accounts/:id/transactions**：查詢某帳戶的所有轉帳紀錄（包含轉入與轉出）
3. **並發測試**：使用 `Promise.all` 同時送出多筆轉帳請求，觀察 `FOR UPDATE` 鎖定的效果
4. **Savepoint**：研究 PostgreSQL 的 `SAVEPOINT` 語法，實作部分回滾功能
