# 第 10 週今日練習題：銀行轉帳 API 與交易處理

## 題目說明

建立一個簡單的銀行帳戶轉帳系統，模擬真實環境中對「資金轉移」的原子性需求。當轉帳過程中任何一個步驟失敗（例如餘額不足、帳號不存在），整個操作必須完整回滾，確保資料一致性。

## 技術要求

- **Express.js**：建立 RESTful API 端點，處理帳戶查詢與轉帳請求
- **PostgreSQL**：使用 `BEGIN` / `COMMIT` / `ROLLBACK` 管理交易，確保原子性操作

## 具體任務

1. **建立資料表**
   - `accounts` 表：`id SERIAL PRIMARY KEY`、`owner_name VARCHAR(100)`、`balance NUMERIC(12, 2) NOT NULL DEFAULT 0`
   - 加入 `CHECK (balance >= 0)` 約束，防止餘額低於零

2. **實作 API 端點**
   - `GET /accounts` — 列出所有帳戶（id、owner_name、balance）
   - `POST /accounts` — 建立新帳戶（傳入 `owner_name`、`initial_balance`）
   - `POST /transfer` — 執行轉帳（傳入 `from_account_id`、`to_account_id`、`amount`）

3. **轉帳邏輯（`POST /transfer`）**
   - 在單一 PostgreSQL 交易中完成：
     1. 鎖定來源帳戶（`SELECT ... FOR UPDATE`）並確認餘額充足
     2. 扣除來源帳戶金額（`UPDATE`）
     3. 增加目標帳戶金額（`UPDATE`）
     4. 全部成功則 `COMMIT`；任何步驟失敗則 `ROLLBACK`
   - 回傳結果：`{ success: true, from_balance: ..., to_balance: ... }`

4. **錯誤處理**
   - 來源帳戶不存在 → HTTP 404
   - 目標帳戶不存在 → HTTP 404
   - 餘額不足 → HTTP 400 `{ error: "餘額不足" }`
   - `amount` 非正數 → HTTP 400 `{ error: "轉帳金額必須大於 0" }`

## 提示

- 使用 `node-postgres`（`pg`）的 `client.query('BEGIN')` / `client.query('COMMIT')` / `client.query('ROLLBACK')` 手動管理交易
- 記得在 `finally` 區塊中執行 `client.release()`，避免連線洩漏
- `SELECT ... FOR UPDATE` 可鎖定列，防止並發轉帳產生競態條件（race condition）
- PostgreSQL 的 `CHECK (balance >= 0)` 也是最後一道防線，即使應用層漏判，資料庫層仍會擋下

## 範例請求

```bash
# 建立帳戶
curl -X POST http://localhost:3000/accounts \
  -H "Content-Type: application/json" \
  -d '{"owner_name": "Alice", "initial_balance": 1000}'

# 執行轉帳
curl -X POST http://localhost:3000/transfer \
  -H "Content-Type: application/json" \
  -d '{"from_account_id": 1, "to_account_id": 2, "amount": 300}'
```

## 進階挑戰（選做）

1. **交易記錄表**：建立 `transactions` 表，每次成功轉帳後同一交易內寫入一筆記錄（`from_id`、`to_id`、`amount`、`created_at`），用來稽核所有金流。
2. **並發壓力測試**：使用 `Promise.all` 同時發出 10 筆轉帳請求，驗證 `SELECT ... FOR UPDATE` 的鎖定機制能否保持餘額正確。
3. **Savepoint**：在同一交易中設定 `SAVEPOINT`，示範如何做到部分回滾（rollback to savepoint）而非整筆取消。
