# 第 19 週今日練習題：電商訂單管理系統 API 實戰專案

## 題目說明

實作一個電商訂單管理系統的後端 REST API，整合商品庫存、訂單建立、付款狀態追蹤，以及完整的 Transaction 與錯誤處理。這是一個模擬真實電商後端的綜合實戰，涵蓋多資料表關聯、庫存扣減、訂單狀態流轉等核心業務邏輯。

## 技術要求

- **Express.js**：模組化架構（`routes/`、`controllers/`、`services/`、`middleware/`），關注點分離
- **PostgreSQL**：多資料表（products、orders、order_items、users），複雜 JOIN 與聚合查詢
- **JWT**：登入後取得 token，所有訂單操作需驗證身份
- **Transaction**：建立訂單時同步扣減庫存，任一步驟失敗全部 rollback
- **資料驗證**：使用 `joi` 驗證 request body，拒絕不合法輸入

## 資料庫 Schema

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(100) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  name VARCHAR(100),
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE products (
  id SERIAL PRIMARY KEY,
  name VARCHAR(200) NOT NULL,
  description TEXT,
  price NUMERIC(10,2) NOT NULL CHECK (price >= 0),
  stock INTEGER NOT NULL DEFAULT 0 CHECK (stock >= 0),
  is_active BOOLEAN DEFAULT true,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE orders (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE SET NULL,
  status VARCHAR(20) NOT NULL DEFAULT 'pending'
    CHECK (status IN ('pending', 'paid', 'shipped', 'completed', 'cancelled')),
  total_amount NUMERIC(10,2) NOT NULL,
  note TEXT,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE order_items (
  id SERIAL PRIMARY KEY,
  order_id INTEGER REFERENCES orders(id) ON DELETE CASCADE,
  product_id INTEGER REFERENCES products(id) ON DELETE SET NULL,
  quantity INTEGER NOT NULL CHECK (quantity > 0),
  unit_price NUMERIC(10,2) NOT NULL,
  subtotal NUMERIC(10,2) GENERATED ALWAYS AS (quantity * unit_price) STORED
);
```

## 具體任務

1. **建立專案結構**
   ```
   src/
   ├── routes/
   │   ├── auth.js
   │   ├── products.js
   │   └── orders.js
   ├── controllers/
   │   ├── authController.js
   │   ├── productController.js
   │   └── orderController.js
   ├── services/
   │   └── orderService.js    (Transaction 邏輯放這裡)
   ├── middleware/
   │   ├── auth.js
   │   └── validate.js
   ├── db.js
   └── app.js
   ```

2. **實作認證**
   - `POST /api/auth/register`：新增使用者（密碼用 `bcrypt` hash 後存入）
   - `POST /api/auth/login`：驗證帳密，回傳 JWT（有效期 2 小時）

3. **實作商品 API**（公開端點，不需 JWT）
   - `GET /api/products`：列出所有上架商品（`is_active = true`），支援 `?search=`、`?min_price=`、`?max_price=` 篩選，以及分頁
   - `GET /api/products/:id`：取得單一商品詳細資訊

4. **實作訂單 CRUD**（所有端點需 JWT）
   - `POST /api/orders`：建立訂單（詳見任務 5）
   - `GET /api/orders`：取得目前登入使用者的所有訂單（含訂單項目）
   - `GET /api/orders/:id`：取得單一訂單詳細資訊（需確認是本人的訂單）
   - `PATCH /api/orders/:id/status`：更新訂單狀態（限管理員或特定規則）
   - `DELETE /api/orders/:id`：取消訂單（僅限 `status = 'pending'` 可取消，同時還原庫存）

5. **建立訂單的 Transaction 邏輯**（核心任務）

   Request body 範例：
   ```json
   {
     "items": [
       { "product_id": 1, "quantity": 2 },
       { "product_id": 3, "quantity": 1 }
     ],
     "note": "請盡快出貨"
   }
   ```

   Transaction 中需依序執行：
   1. 逐一確認每個商品存在且 `is_active = true`
   2. 確認每個商品庫存足夠（`stock >= quantity`），不足則丟出錯誤並 rollback
   3. 以當下商品售價（`unit_price`）快照到 `order_items`（避免之後改價影響舊訂單）
   4. 計算 `total_amount` = 所有 `subtotal` 加總
   5. 插入 `orders` 記錄
   6. 插入所有 `order_items` 記錄
   7. 批次扣減各商品庫存（`UPDATE products SET stock = stock - $1 WHERE id = $2`）
   8. 全部成功則 COMMIT，任一步驟失敗則 ROLLBACK

6. **統一錯誤回應格式**
   ```json
   {
     "error": {
       "code": "OUT_OF_STOCK",
       "message": "商品「無線鍵盤」庫存不足，剩餘 3 件，您欲購買 5 件",
       "product_id": 2
     }
   }
   ```

## 提示

- `bcrypt` 範例：
  ```js
  const hash = await bcrypt.hash(password, 10);
  const match = await bcrypt.compare(password, hash);
  ```
- 庫存檢查建議使用 `SELECT ... FOR UPDATE` 鎖定列，防止並發超賣：
  ```sql
  SELECT id, stock FROM products WHERE id = $1 FOR UPDATE
  ```
- 取消訂單還原庫存時，同樣需用 Transaction，先更新 order status，再 `UPDATE products SET stock = stock + quantity`
- Joi 驗證範例：
  ```js
  const schema = Joi.object({
    items: Joi.array().items(
      Joi.object({
        product_id: Joi.number().integer().positive().required(),
        quantity: Joi.number().integer().min(1).required()
      })
    ).min(1).required(),
    note: Joi.string().max(500).optional()
  });
  ```
- 分頁 SQL 建議先 COUNT 再 LIMIT/OFFSET，一起回傳 `{ data, total, page, limit }`

## 進階挑戰（選做）

- 加入訂單狀態轉移驗證（State Machine）：
  - `pending` → `paid` 或 `cancelled`
  - `paid` → `shipped`
  - `shipped` → `completed`
  - 其他跳轉回傳 `400 INVALID_STATUS_TRANSITION`
- 為 `POST /api/orders` 撰寫 `supertest + Jest` 整合測試，涵蓋：
  - 正常建立訂單
  - 庫存不足應回傳 400
  - 未帶 JWT 應回傳 401
  - 商品不存在應回傳 404
- 加入 `express-rate-limit` 防止訂單 API 被濫用（每分鐘最多 20 次）
- 實作管理員角色（在 users 表加 `role` 欄位），僅管理員可更新任意訂單狀態
