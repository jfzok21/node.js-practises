# 第 7 週今日練習題：JWT 身份驗證系統

## 題目說明

實作一套完整的 JWT（JSON Web Token）身份驗證機制，包含使用者註冊、登入、以及受保護路由的存取控制。透過這個練習，你將理解 stateless 身份驗證的運作原理，以及如何在 Express 中妥善管理 Token 的發放與驗證。

## 技術要求

- **Express.js**：建立 `/auth/register`、`/auth/login` 路由，以及受 JWT 保護的 `/profile` 路由
- **PostgreSQL**：儲存使用者帳號資料（id、email、password_hash、created_at）
- **jsonwebtoken**：產生與驗證 JWT
- **bcrypt**：對密碼進行雜湊處理，禁止明文儲存

## 具體任務

1. **建立資料表**
   在 PostgreSQL 中建立 `users` 資料表：
   ```sql
   CREATE TABLE IF NOT EXISTS users (
     id SERIAL PRIMARY KEY,
     email VARCHAR(255) UNIQUE NOT NULL,
     password_hash VARCHAR(255) NOT NULL,
     created_at TIMESTAMPTZ DEFAULT NOW()
   );
   ```

2. **實作 `POST /auth/register`**
   - 接收 `{ email, password }` 
   - 驗證 email 格式與密碼長度（至少 8 字元）
   - 以 `bcrypt.hash` 雜湊密碼後存入資料庫
   - 若 email 已存在，回傳 `409 Conflict`
   - 成功回傳 `201` 與使用者 id、email

3. **實作 `POST /auth/login`**
   - 接收 `{ email, password }`
   - 查詢資料庫並以 `bcrypt.compare` 比對密碼
   - 驗證成功後，以 `jwt.sign` 產生 Token（有效期 1 小時）
   - 回傳 `{ token, expiresIn: 3600 }`

4. **實作 JWT 驗證 Middleware**
   建立 `authenticateToken` 中介層：
   - 從 `Authorization: Bearer <token>` 標頭取得 Token
   - 以 `jwt.verify` 驗證；失效或缺少時回傳 `401`
   - 驗證成功後將解碼後的 payload 掛載至 `req.user`

5. **實作 `GET /profile`（受保護路由）**
   - 套用 `authenticateToken` Middleware
   - 從資料庫查詢當前使用者資料
   - 回傳 `{ id, email, created_at }`

## 提示

- JWT Secret 請放入 `.env`（`JWT_SECRET=your_secret_here`），不要硬寫在程式碼中
- `bcrypt.hash` 的 saltRounds 建議設為 `10`
- `jwt.sign` 的 payload 只放 `{ id, email }`，不要放密碼雜湊
- 錯誤處理記得區分「Token 格式錯誤」與「Token 過期」兩種情況
- 可用 Postman 或 `curl` 測試整個流程：register → login 取得 token → 帶 token 呼叫 /profile

## 進階挑戰（選做）

- **Refresh Token 機制**：實作 `POST /auth/refresh`，使用存在資料庫的 refresh token 換取新的 access token（access token 有效期縮短為 15 分鐘）
- **登出功能**：建立 Token 黑名單（存於 PostgreSQL 或 Redis），實作 `POST /auth/logout`
- **角色權限**：在 JWT payload 中加入 `role` 欄位，建立 `authorizeRole('admin')` Middleware，限制特定路由只有管理員可存取
- **Rate Limiting**：對 `/auth/login` 加上速率限制，防止暴力破解（可用 `express-rate-limit`）
