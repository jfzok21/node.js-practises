# 第 11 週今日練習題：用 Supertest + Jest 測試 Express API

## 題目說明

你的團隊正在開發一個簡單的「任務管理 API」（Task Manager API），已有基本的 CRUD 路由。現在需要為這個 API 撰寫完整的自動化測試，確保每個端點都按預期運作，並在未來重構時能快速抓出回歸問題。

本次練習的重點是學習如何使用 **Jest** 作為測試框架、**Supertest** 作為 HTTP 測試工具，對 Express + PostgreSQL 應用程式進行整合測試。

---

## 技術要求

- **Express.js**：建立可被測試的 app 實例（不在測試中啟動真實 server）
- **PostgreSQL**：使用獨立的測試資料庫（test DB），每個測試前後清理資料
- **Jest**：撰寫 `describe` / `it` / `expect` 測試案例，使用 `beforeAll` / `afterAll` / `beforeEach`
- **Supertest**：對 Express app 發送 HTTP 請求，驗證回應狀態碼與 JSON 內容

---

## 具體任務

### 1. 建立測試環境

安裝相依套件：

```bash
npm install --save-dev jest supertest
npm install --save-dev @types/jest @types/supertest   # 若使用 TypeScript
```

在 `package.json` 加入測試腳本：

```json
"scripts": {
  "test": "jest --runInBand",
  "test:watch": "jest --watch"
}
```

建立 `jest.config.js`（或在 `package.json` 加入 `"jest"` 區塊）：

```js
module.exports = {
  testEnvironment: 'node',
  testTimeout: 10000,
};
```

建立 `.env.test`，指向測試資料庫：

```
DATABASE_URL=postgresql://user:password@localhost:5432/task_manager_test
```

---

### 2. 準備 Express App

確保 `app.js`（或 `src/app.js`）**只匯出 app，不呼叫 `.listen()`**：

```js
// app.js
const express = require('express');
const app = express();
app.use(express.json());

// 掛載路由
const tasksRouter = require('./routes/tasks');
app.use('/tasks', tasksRouter);

module.exports = app;
```

`server.js` 再負責啟動：

```js
const app = require('./app');
app.listen(3000, () => console.log('Server running on port 3000'));
```

---

### 3. 建立測試用資料庫工具

建立 `tests/helpers/db.js`：

```js
const { Pool } = require('pg');
require('dotenv').config({ path: '.env.test' });

const pool = new Pool({ connectionString: process.env.DATABASE_URL });

async function clearTables() {
  await pool.query('TRUNCATE TABLE tasks RESTART IDENTITY CASCADE');
}

async function closePool() {
  await pool.end();
}

module.exports = { pool, clearTables, closePool };
```

---

### 4. 撰寫 Tasks API 測試

建立 `tests/tasks.test.js`，涵蓋以下測試案例：

#### GET /tasks — 取得所有任務

```js
const request = require('supertest');
const app = require('../app');
const { clearTables, closePool } = require('./helpers/db');

beforeEach(async () => {
  await clearTables();
});

afterAll(async () => {
  await closePool();
});

describe('GET /tasks', () => {
  it('應回傳空陣列（資料庫為空時）', async () => {
    const res = await request(app).get('/tasks');
    expect(res.status).toBe(200);
    expect(res.body).toEqual([]);
  });

  it('應回傳已存在的任務列表', async () => {
    // 先建立一筆資料
    await request(app).post('/tasks').send({ title: '買牛奶', done: false });

    const res = await request(app).get('/tasks');
    expect(res.status).toBe(200);
    expect(res.body).toHaveLength(1);
    expect(res.body[0]).toMatchObject({ title: '買牛奶', done: false });
  });
});
```

#### POST /tasks — 建立任務

```js
describe('POST /tasks', () => {
  it('成功建立任務，回傳 201 與新資料', async () => {
    const res = await request(app)
      .post('/tasks')
      .send({ title: '寫測試', done: false });

    expect(res.status).toBe(201);
    expect(res.body).toMatchObject({ title: '寫測試', done: false });
    expect(res.body.id).toBeDefined();
  });

  it('缺少 title 時應回傳 400', async () => {
    const res = await request(app).post('/tasks').send({ done: false });
    expect(res.status).toBe(400);
    expect(res.body).toHaveProperty('error');
  });
});
```

#### GET /tasks/:id — 取得單一任務

```js
describe('GET /tasks/:id', () => {
  it('找到資料時回傳 200', async () => {
    const created = await request(app).post('/tasks').send({ title: '測試任務' });
    const { id } = created.body;

    const res = await request(app).get(`/tasks/${id}`);
    expect(res.status).toBe(200);
    expect(res.body.id).toBe(id);
  });

  it('不存在的 id 應回傳 404', async () => {
    const res = await request(app).get('/tasks/99999');
    expect(res.status).toBe(404);
  });
});
```

#### PUT /tasks/:id — 更新任務

```js
describe('PUT /tasks/:id', () => {
  it('成功更新任務', async () => {
    const created = await request(app).post('/tasks').send({ title: '原標題', done: false });
    const { id } = created.body;

    const res = await request(app)
      .put(`/tasks/${id}`)
      .send({ title: '新標題', done: true });

    expect(res.status).toBe(200);
    expect(res.body).toMatchObject({ title: '新標題', done: true });
  });
});
```

#### DELETE /tasks/:id — 刪除任務

```js
describe('DELETE /tasks/:id', () => {
  it('成功刪除，回傳 204', async () => {
    const created = await request(app).post('/tasks').send({ title: '待刪任務' });
    const { id } = created.body;

    const res = await request(app).delete(`/tasks/${id}`);
    expect(res.status).toBe(204);
  });

  it('刪除後再查詢應回傳 404', async () => {
    const created = await request(app).post('/tasks').send({ title: '待刪任務' });
    const { id } = created.body;

    await request(app).delete(`/tasks/${id}`);

    const res = await request(app).get(`/tasks/${id}`);
    expect(res.status).toBe(404);
  });
});
```

## 提示

- `supertest` 的 `request(app)` **不會真正啟動 server**，是在記憶體中直接呼叫 Express，速度快且不佔 port。
- 每個測試前用 `TRUNCATE ... RESTART IDENTITY` 清空資料，確保測試彼此獨立，順序無關。
- 使用 `--runInBand`（`-i`）讓測試依序執行，避免多個測試同時操作同一資料庫造成競爭條件。
- `toMatchObject` 只比對指定的欄位，比 `toEqual` 更有彈性（不需比對 `created_at` 等自動產生的欄位）。
- 若 response body 是陣列，可用 `expect(res.body).toHaveLength(n)` 驗證筆數。

## 進階挑戰（選做）

1. **測試覆蓋率報告**：在 `jest.config.js` 加入 `collectCoverage: true`，執行後查看 `coverage/` 目錄，嘗試讓行覆蓋率達到 80% 以上。

2. **測試 Middleware**：為第 4 週的自訂驗證 Middleware 撰寫單元測試（直接 mock `req`、`res`、`next`，不透過 HTTP）。

3. **使用 `afterEach` 替代 `beforeEach`**：理解兩者差異，說明在哪個場景下 `afterEach` 更適合清理。

4. **Mock 外部依賴**：若 API 呼叫了外部服務（如寄信、第三方 API），使用 `jest.mock()` 模擬回傳值，讓測試不依賴真實外部服務。

5. **快照測試（Snapshot Testing）**：對 GET /tasks 的回應使用 `toMatchSnapshot()`，自動記錄預期輸出格式。
