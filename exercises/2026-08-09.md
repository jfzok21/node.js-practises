# 第 5 週今日練習題：書店訂單系統 — JOIN 查詢與多資料表關聯

## 題目說明

設計一個「書店訂單系統」後端 API，資料分散在多張資料表中（顧客、書籍、訂單、訂單明細）。你需要透過 JOIN 查詢將這些資料正確地關聯起來，並透過 Express 路由回傳組合後的結果。

---

## 技術要求

- **Express.js**：建立多個 REST API 路由，回傳 JSON 格式的關聯查詢結果
- **PostgreSQL**：使用 INNER JOIN、LEFT JOIN 等關聯查詢，操作 3～4 張資料表

---

## 具體任務

### 1. 建立資料表結構

在 PostgreSQL 中建立以下 4 張資料表：

```sql
-- 顧客資料表
CREATE TABLE customers (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  email VARCHAR(150) UNIQUE NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 書籍資料表
CREATE TABLE books (
  id SERIAL PRIMARY KEY,
  title VARCHAR(200) NOT NULL,
  author VARCHAR(100) NOT NULL,
  price NUMERIC(10, 2) NOT NULL,
  stock INT DEFAULT 0
);

-- 訂單主檔
CREATE TABLE orders (
  id SERIAL PRIMARY KEY,
  customer_id INT REFERENCES customers(id),
  ordered_at TIMESTAMP DEFAULT NOW(),
  status VARCHAR(20) DEFAULT 'pending'  -- 'pending' | 'shipped' | 'cancelled'
);

-- 訂單明細（一筆訂單可包含多本書）
CREATE TABLE order_items (
  id SERIAL PRIMARY KEY,
  order_id INT REFERENCES orders(id),
  book_id INT REFERENCES books(id),
  quantity INT NOT NULL,
  unit_price NUMERIC(10, 2) NOT NULL
);
```

插入測試資料（至少 3 位顧客、5 本書、4 筆訂單）。

---

### 2. 實作 API 路由

#### `GET /orders`
回傳所有訂單，並附上**顧客姓名**。

預期回應範例：
```json
[
  { "order_id": 1, "customer_name": "王小明", "ordered_at": "2026-08-09T10:00:00Z", "status": "shipped" },
  ...
]
```

---

#### `GET /orders/:id`
回傳單筆訂單的**完整明細**，包含：
- 訂單基本資訊（id、狀態、下單時間）
- 顧客姓名與 email
- 每本書的書名、數量、單價、小計
- 訂單總金額（所有明細的 `quantity * unit_price` 加總）

預期回應範例：
```json
{
  "order_id": 1,
  "status": "shipped",
  "ordered_at": "2026-08-09T10:00:00Z",
  "customer": { "name": "王小明", "email": "wang@example.com" },
  "items": [
    { "book_title": "Node.js 實戰", "quantity": 2, "unit_price": 350, "subtotal": 700 },
    { "book_title": "PostgreSQL 入門", "quantity": 1, "unit_price": 420, "subtotal": 420 }
  ],
  "total": 1120
}
```

---

#### `GET /customers/:id/orders`
回傳指定顧客的**所有訂單摘要**（使用 LEFT JOIN，即使顧客沒有訂單也要出現）。

---

#### `GET /books/top-selling`
回傳**銷售量前 5 名的書籍**（依總銷售數量 `SUM(quantity)` 降冪排序）。

## 提示

- 使用 `pg` 套件的 `Pool`，在 `db.js` 建立連線池並 export，各路由 `require` 後使用。
- `GET /orders/:id` 的明細可用一次 JOIN 查詢取得，再用 JavaScript 在應用層組合成巢狀結構（items 陣列 + 計算 total）。
- `SUM`、`GROUP BY` 是 `top-selling` 路由的關鍵，記得加上 `ORDER BY ... DESC LIMIT 5`。
- LEFT JOIN 可確保沒有訂單的顧客也被包含在 `/customers/:id/orders` 的回應中。
- 使用參數化查詢（`$1`、`$2`）防止 SQL Injection。

## 進階挑戰（選做）

1. **篩選功能**：`GET /orders?status=shipped` — 支援依訂單狀態篩選。
2. **日期範圍**：`GET /orders?from=2026-08-01&to=2026-08-09` — 篩選特定日期區間的訂單。
3. **建立訂單**：實作 `POST /orders`，接受 `customer_id` 與 `items[]`（含 `book_id` 與 `quantity`），在 Transaction 中同時寫入 `orders` 與 `order_items`，並扣減書籍庫存。
4. **庫存警告**：`GET /books/low-stock` — 回傳庫存低於 5 本的書籍清單。
