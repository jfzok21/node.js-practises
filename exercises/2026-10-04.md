# 第 13 週今日練習題：任務管理 REST API（實戰專案）

## 題目說明

建立一個完整的「任務管理系統」REST API，整合前幾週所有學過的技術：Express 路由、PostgreSQL CRUD、Middleware、JWT 驗證、資料驗證、分頁排序與交易處理。這是一個接近生產環境標準的迷你全端後端專案。

---

## 技術要求

- **Express.js**：RESTful 路由設計、Router 模組化、全域錯誤處理 Middleware
- **PostgreSQL**：多資料表（users、tasks、categories）、JOIN 查詢、Transaction
- **JWT**：使用者登入後核發 Token，受保護路由需驗證
- **資料驗證**：使用 `express-validator` 或手動驗證，回傳標準錯誤格式
- **分頁與排序**：任務列表支援 `?page=`、`?limit=`、`?sort=`、`?order=`
- **Multer**（選做）：支援任務附件上傳

---

## 資料庫結構

```sql
-- 使用者資料表
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(50) UNIQUE NOT NULL,
  email VARCHAR(100) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 分類資料表
CREATE TABLE categories (
  id SERIAL PRIMARY KEY,
  name VARCHAR(50) NOT NULL,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE
);

-- 任務資料表
CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  title VARCHAR(200) NOT NULL,
  description TEXT,
  status VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending', 'in_progress', 'done')),
  priority INTEGER DEFAULT 1 CHECK (priority BETWEEN 1 AND 5),
  due_date DATE,
  category_id INTEGER REFERENCES categories(id) ON DELETE SET NULL,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

## 具體任務

### 1. 專案初始化
- 建立 Express 應用程式，使用 Router 將路由分拆到 `routes/auth.js`、`routes/tasks.js`、`routes/categories.js`
- 設定 `.env`：`DATABASE_URL`、`JWT_SECRET`、`PORT`
- 連線 PostgreSQL（使用 `pg` 套件的 Pool）

### 2. 使用者驗證（`/api/auth`）
- `POST /api/auth/register`：註冊（username、email、password），密碼用 `bcrypt` 雜湊後存入
- `POST /api/auth/login`：登入成功後回傳 JWT Token（`{ token, user: { id, username, email } }`）
- 建立 `middleware/auth.js`：驗證 `Authorization: Bearer <token>`，將 `req.user` 注入

### 3. 任務 CRUD（`/api/tasks`，需 JWT）
- `GET /api/tasks`：取得當前使用者所有任務，支援：
  - 分頁：`?page=1&limit=10`（預設 page=1, limit=10）
  - 排序：`?sort=due_date&order=asc`（可排序欄位：created_at、due_date、priority）
  - 篩選：`?status=pending`、`?category_id=2`、`?search=關鍵字`
  - JOIN categories 回傳分類名稱
- `GET /api/tasks/:id`：取得單一任務（僅限自己的）
- `POST /api/tasks`：新增任務，需驗證 title 必填、priority 為 1–5、due_date 格式正確
- `PUT /api/tasks/:id`：更新任務，同時更新 `updated_at`
- `DELETE /api/tasks/:id`：刪除任務

### 4. 分類管理（`/api/categories`，需 JWT）
- `GET /api/categories`：列出當前使用者所有分類
- `POST /api/categories`：新增分類
- `DELETE /api/categories/:id`：刪除分類（使用 Transaction：先確認無任務依賴，或改用 SET NULL 策略）

### 5. 批次操作（Transaction）
- `POST /api/tasks/batch-delete`：接收 `{ ids: [1, 2, 3] }`，在一個 Transaction 中刪除多筆（需確認都屬於當前使用者，否則全部 rollback）
- `POST /api/tasks/batch-status`：接收 `{ ids: [1,2], status: "done" }`，批次更新狀態

### 6. 全域錯誤處理
- 建立 `middleware/errorHandler.js`，統一回應格式：
  ```json
  { "error": { "code": "VALIDATION_ERROR", "message": "...", "details": [...] } }
  ```
- 區分 400（驗證失敗）、401（未授權）、403（禁止）、404（找不到）、500（伺服器錯誤）

## 提示

- 使用 `pg` 的 `pool.connect()` 搭配 `try/finally client.release()` 處理 Transaction
- JWT 驗證 Middleware 提取 token：`req.headers.authorization?.split(' ')[1]`
- 分頁 SQL 範例：`SELECT ... LIMIT $1 OFFSET $2`，offset = (page - 1) * limit
- 回傳分頁結果時包含 meta：`{ data: [...], meta: { total, page, limit, totalPages } }`
- 避免 N+1 問題：用 JOIN 取分類名稱而非逐筆查詢

## 進階挑戰（選做）

1. **軟刪除**：tasks 加入 `deleted_at` 欄位，DELETE 改為設定時間戳，查詢時加入 `WHERE deleted_at IS NULL`
2. **重新整理 Token**：實作 Refresh Token 機制，`POST /api/auth/refresh`
3. **任務統計**：`GET /api/tasks/stats` 回傳各狀態數量、本週到期數量
4. **附件上傳**：使用 multer 支援 `POST /api/tasks/:id/attachments`，將檔案資訊存入 task_attachments 資料表
5. **API 測試**：使用 supertest + Jest 為所有端點撰寫整合測試
