# 第 10 週今日練習題：銀行轉帳 API 與資料庫交易處理

## 題目說明

實作一個簡單的銀行帳戶系統，支援帳戶查詢與轉帳功能。轉帳操作必須以 PostgreSQL **交易（Transaction）** 包裹，確保「扣款」與「入帳」兩個步驟要麼同時成功、要麼同時失敗，不會出現資料不一致的情況。

---

## 技術要求

- **Express.js**：建立 RESTful API 路由
- **PostgreSQL**：使用 `BEGIN / COMMIT / ROLLBACK` 管理交易；帳戶餘額不足或帳戶不存在時需正確 ROLLBACK

---

## 具體任務

1. **資料庫初始化**

   建立 `accounts` 資料表：

   ```sql
   CREATE TABLE IF NOT EXISTS accounts (
     id      SERIAL PRIMARY KEY,
     owner   VARCHAR(100) NOT NULL,
     balance NUMERIC(12, 2) NOT NULL DEFAULT 0
   );

   -- 測試資料
   INSERT INTO accounts (owner, balance) VALUES
     ('Alice', 10000.00),
     ('Bob',    5000.00);
   ```

2. **GET `/accounts`** — 取得所有帳戶列表（id、owner、balance）

3. **GET `/accounts/:id`** — 取得單一帳戶資訊；帳戶不存在時回傳 `404`

4. **POST `/transfer`** — 轉帳端點

   請求 Body（JSON）：
   ```json
   {
     "from_id": 1,
     "to_id": 2,
     "amount": 1000
   }
   ```

   處理邏輯（**必須在同一個 Transaction 內完成**）：
   - 驗證 `amount > 0`
   - 鎖定來源帳戶行（`SELECT ... FOR UPDATE`），確認餘額足夠
   - 扣除來源帳戶餘額：`UPDATE accounts SET balance = balance - amount WHERE id = from_id`
   - 增加目標帳戶餘額：`UPDATE accounts SET balance = balance + amount WHERE id = to_id`
   - 任何步驟失敗（餘額不足、帳戶不存在）→ ROLLBACK，回傳適當錯誤訊息
   - 全部成功 → COMMIT，回傳轉帳後雙方最新餘額

5. **錯誤處理**

   | 情境 | HTTP 狀態碼 | 回應 |
   |------|------------|------|
   | 帳戶不存在 | 404 | `{ error: "Account not found" }` |
   | 餘額不足 | 400 | `{ error: "Insufficient balance" }` |
   | 轉帳金額 ≤ 0 | 400 | `{ error: "Invalid amount" }` |
   | 資料庫錯誤 | 500 | `{ error: "Internal server error" }` |

---

## 提示

- 使用 `pg` 套件取得 client 並手動管理交易：
  ```js
  const client = await pool.connect();
  try {
    await client.query('BEGIN');
    // ... 執行操作 ...
    await client.query('COMMIT');
  } catch (err) {
    await client.query('ROLLBACK');
    throw err;
  } finally {
    client.release();
  }
  ```
- `SELECT ... FOR UPDATE` 可防止同時轉帳時的 race condition
- 轉帳金額建議用 `parseFloat` 或 `Number` 轉型後再做比較，避免字串比較問題
- 可用 Postman 或 `curl` 測試：
  ```bash
  curl -X POST http://localhost:3000/transfer \
    -H "Content-Type: application/json" \
    -d '{"from_id":1,"to_id":2,"amount":500}'
  ```

## 進階挑戰（選做）

1. **轉帳記錄表**：新增 `transfers` 資料表，在同一個 Transaction 內同時寫入轉帳紀錄（from_id、to_id、amount、created_at），並提供 `GET /transfers` 端點查詢歷史紀錄。

2. **同帳戶轉帳防護**：若 `from_id === to_id`，回傳 `400 { error: "Cannot transfer to the same account" }`。

3. **並發壓力測試**：使用以下指令同時送出 10 筆轉帳，確認最終餘額正確（不會多扣或少扣）：
   ```bash
   for i in $(seq 1 10); do
     curl -s -X POST http://localhost:3000/transfer \
       -H "Content-Type: application/json" \
       -d '{"from_id":1,"to_id":2,"amount":100}' &
   done
   wait
   ```

4. **使用 `pg-promise` 的 Task / Transaction API**：重構現有程式碼，改用 `db.tx(t => { ... })` 語法管理交易。
