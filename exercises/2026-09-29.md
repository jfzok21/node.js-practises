# 第 12 週今日練習題：任務管理 REST API 實戰專案

## 題目說明

綜合前 11 週所學，從零開始建構一個完整的「任務管理系統」REST API。  
該系統支援多使用者、JWT 身份驗證、任務 CRUD、標籤分類、分頁查詢、檔案附件與交易處理，並附有完整的自動化測試。

---

## 技術要求

- **Express.js**：路由組織、自訂 Middleware、統一錯誤處理
- **PostgreSQL**：多資料表設計、JOIN 查詢、交易（Transaction）
- **JWT**：使用者註冊 / 登入 / 受保護路由
- **Multer**：任務附件上傳（限 PDF / 圖片，最大 5MB）
- **Jest + Supertest**：端對端 API 測試
- **資料驗證**：自訂驗證 Middleware 或 `joi` / `zod`

---

## 資料庫結構

```sql
-- 使用者
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 標籤
CREATE TABLE tags (
  id SERIAL PRIMARY KEY,
  user_id INT REFERENCES users(id) ON DELETE CASCADE,
  name VARCHAR(100) NOT NULL,
  UNIQUE(user_id, name)
);

-- 任務
CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  user_id INT REFERENCES users(id) ON DELETE CASCADE,
  title VARCHAR(255) NOT NULL,
  description TEXT,
  status VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending','in_progress','done')),
  due_date DATE,
  attachment_path TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 任務 ↔ 標籤（多對多）
CREATE TABLE task_tags (
  task_id INT REFERENCES tasks(id) ON DELETE CASCADE,
  tag_id  INT REFERENCES tags(id)  ON DELETE CASCADE,
  PRIMARY KEY (task_id, tag_id)
);
```

## 具體任務

### 1. 專案初始化
- `npm init`，安裝 `express pg bcryptjs jsonwebtoken multer joi jest supertest`
- 建立 `.env`（`DATABASE_URL`、`JWT_SECRET`、`PORT`）
- 建立 `db/init.sql` 並執行初始化腳本

### 2. 使用者模組（`/api/auth`）
1. `POST /api/auth/register` — 驗證 email 格式與密碼長度，bcrypt 雜湊後存入 DB
2. `POST /api/auth/login` — 比對密碼，回傳 JWT（有效期 7 天）

### 3. 認證 Middleware
- 解析 `Authorization: Bearer <token>`，驗證 JWT，將 `req.user` 注入後續路由
- 無效 token 回傳 `401`

### 4. 任務模組（`/api/tasks`，需認證）
1. `GET /api/tasks` — 分頁（`?page=1&limit=10`）+ 依 `status` / `tag` 篩選 + 依 `due_date` / `created_at` 排序
2. `POST /api/tasks` — 建立任務，可同時附加標籤 ID 陣列（於同一 Transaction 內完成）
3. `GET /api/tasks/:id` — 回傳任務詳情（含標籤陣列）
4. `PATCH /api/tasks/:id` — 部分更新（title / description / status / due_date），自動更新 `updated_at`
5. `DELETE /api/tasks/:id` — 刪除任務及所有關聯標籤（CASCADE）

### 5. 附件上傳（`/api/tasks/:id/attachment`，需認證）
- `POST` — 上傳單一檔案，限 PDF 或圖片（`image/*`），超過 5MB 回傳 `400`
- 儲存路徑記錄至 `tasks.attachment_path`

### 6. 標籤模組（`/api/tags`，需認證）
1. `GET /api/tags` — 列出目前使用者所有標籤
2. `POST /api/tags` — 建立標籤（同名重複回傳 `409`）
3. `DELETE /api/tags/:id` — 刪除標籤（同時移除所有 task_tags 關聯）

### 7. 統一錯誤處理 Middleware
- 捕捉所有未處理的錯誤，回傳統一格式：
  ```json
  { "error": "訊息", "code": "ERROR_CODE" }
  ```

### 8. 測試套件（Jest + Supertest）
在 `tests/` 目錄撰寫至少下列測試案例：
- 註冊成功 / 重複 email 409 / 密碼過短 400
- 登入成功 / 錯誤密碼 401
- 未帶 token 存取受保護路由 401
- 建立任務並附加標籤（驗證 JOIN 查詢結果）
- 分頁查詢（驗證 `total` / `page` / `data` 欄位）
- 上傳超過大小限制的檔案 400

## 提示

- 使用 `pg` 的 `pool.connect()` 搭配 `client.query('BEGIN')` 實作 Transaction
- Multer 的 `fileFilter` 可用來限制 MIME type
- 分頁查詢善用 `COUNT(*) OVER()` 或獨立的 `SELECT COUNT(*)` 取得總筆數
- 測試前後使用 `beforeAll` / `afterAll` 清理測試資料，避免污染
- 以 `express-async-errors` 或自訂 `asyncHandler` wrapper 減少 try/catch 重複

## 進階挑戰（選做）

1. **軟刪除**：為 `tasks` 加入 `deleted_at` 欄位，DELETE 改為軟刪除，GET 預設過濾
2. **任務統計 API**：`GET /api/tasks/stats` 回傳各 `status` 的數量與最近 7 天新增趨勢
3. **Rate Limiting**：對 `/api/auth` 路由加入每分鐘最多 10 次請求限制
4. **Refresh Token**：實作 `refreshToken` 流程，將過期時間縮短為 15 分鐘
5. **OpenAPI 文件**：使用 `swagger-jsdoc` + `swagger-ui-express` 自動產生 API 文件
