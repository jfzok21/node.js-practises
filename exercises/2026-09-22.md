# 第 11 週今日練習題：使用 Supertest + Jest 進行 API 整合測試

## 題目說明

你已經建立了一個基本的 Express + PostgreSQL API，現在是時候為它撰寫自動化測試了。
本練習將帶你使用 **Jest** 作為測試框架、**Supertest** 來對 Express 應用發送 HTTP 請求，
學會如何驗證 API 的行為是否符合預期，確保每次程式碼變動後品質不打折。

## 技術要求

- **Express.js**：建立一個可測試的 Express app（需支援 `export` / `module.exports` 以供測試引用）
- **PostgreSQL**：使用測試專用資料庫，測試前建立資料、測試後清理
- **Jest**：設定 `jest.config.js`，使用 `describe` / `it` / `expect` 結構
- **Supertest**：使用 `request(app)` 對路由發送請求，不需啟動伺服器

## 具體任務

1. **初始化專案**
   - 安裝依賴：`npm install --save-dev jest supertest`
   - 在 `package.json` 加入測試指令：`"test": "jest --runInBand"`
   - 建立 `jest.config.js`，設定測試環境為 `node`

2. **建立可測試的 Express App**
   - 在 `src/app.js` 建立 Express app，但不要在此呼叫 `app.listen()`
   - 另建立 `src/server.js` 專門負責啟動伺服器
   - 實作一個 `GET /api/users` 路由（從 PostgreSQL 回傳使用者列表）
   - 實作一個 `POST /api/users` 路由（新增使用者，需驗證 `name` 和 `email` 欄位）

3. **設定測試用資料庫**
   - 建立 `tests/setup.js`，在測試前連線至測試資料庫並建立 `users` 資料表
   - 每個測試案例前（`beforeEach`）清空資料表，確保測試互不干擾
   - 測試全部結束後（`afterAll`）關閉資料庫連線

4. **撰寫 API 測試**
   - 建立 `tests/users.test.js`
   - 測試 `GET /api/users`：
     - 空資料庫時應回傳 `[]` 與狀態碼 `200`
     - 有資料時應回傳正確的使用者陣列
   - 測試 `POST /api/users`：
     - 成功新增時應回傳 `201` 與新使用者資料
     - 缺少 `name` 或 `email` 時應回傳 `400` 與錯誤訊息
     - 重複的 `email` 應回傳 `409` 錯誤

5. **執行並確認所有測試通過**
   - 執行 `npm test`，確認所有測試案例都呈現綠色 ✅

## 提示

- 使用 `process.env.DATABASE_URL` 區分開發與測試資料庫，測試時可設定 `DATABASE_URL=postgres://localhost/myapp_test`
- `supertest` 的 `request(app)` 會自動處理連線，不需手動呼叫 `listen()`
- 在 `jest.config.js` 設定 `globalSetup` 與 `globalTeardown` 可管理跨檔案的資料庫生命週期
- 善用 `expect(response.body).toMatchObject({ name: 'Alice' })` 做部分匹配

## 範例結構

```
project/
├── src/
│   ├── app.js        ← Express app（不含 listen）
│   ├── server.js     ← 只負責 listen
│   └── routes/
│       └── users.js
├── tests/
│   ├── setup.js      ← DB setup / teardown
│   └── users.test.js ← 測試案例
├── jest.config.js
└── package.json
```

## 進階挑戰（選做）

- 使用 `jest --coverage` 產出測試覆蓋率報告，目標覆蓋率達 80% 以上
- 撰寫一個測試驗證 JWT 保護路由（帶 token 可存取，未帶 token 回傳 401）
- 使用 `jest.mock()` 模擬 PostgreSQL 連線，讓測試完全不依賴真實資料庫
- 在 `package.json` 加入 `"test:watch": "jest --watch"` 指令，於開發時即時執行測試
