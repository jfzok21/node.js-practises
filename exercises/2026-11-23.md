# 第 20 週今日練習題：部落格 API 實戰專案

## 題目說明

綜合運用前 19 週所學，建立一個具備完整功能的部落格後端 API，包含使用者驗證、文章 CRUD、留言系統、標籤分類、分頁查詢與完整錯誤處理。

## 技術要求

- **Express.js**：路由模組化（Router）、自訂 Middleware、錯誤處理中介層
- **PostgreSQL**：多資料表關聯（users、posts、comments、tags、post_tags）、JOIN 查詢、Transaction
- **驗證**：JWT 身份驗證（登入後才能發文/留言）
- **輸入驗證**：joi 或手動驗證，回傳標準化錯誤格式
- **分頁**：GET /posts 支援 `?page=&limit=&tag=&search=`

## 具體任務

### 1. 資料庫設計

建立以下資料表：

```sql
-- 使用者
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(50) UNIQUE NOT NULL,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 文章
CREATE TABLE posts (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  title VARCHAR(255) NOT NULL,
  content TEXT NOT NULL,
  published BOOLEAN DEFAULT false,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- 留言
CREATE TABLE comments (
  id SERIAL PRIMARY KEY,
  post_id INTEGER REFERENCES posts(id) ON DELETE CASCADE,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  body TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 標籤
CREATE TABLE tags (
  id SERIAL PRIMARY KEY,
  name VARCHAR(50) UNIQUE NOT NULL
);

-- 文章標籤（多對多）
CREATE TABLE post_tags (
  post_id INTEGER REFERENCES posts(id) ON DELETE CASCADE,
  tag_id INTEGER REFERENCES tags(id) ON DELETE CASCADE,
  PRIMARY KEY (post_id, tag_id)
);
```

### 2. 實作 API 端點

**驗證路由**
```
POST /api/auth/register   → 註冊（回傳 JWT）
POST /api/auth/login      → 登入（回傳 JWT）
```

**文章路由**
```
GET    /api/posts          → 列表（支援分頁、標籤篩選、關鍵字搜尋）
GET    /api/posts/:id      → 單篇文章（含標籤、留言數）
POST   /api/posts          → 建立文章（需驗證）
PUT    /api/posts/:id      → 更新文章（需驗證，只能改自己的）
DELETE /api/posts/:id      → 刪除文章（需驗證，只能刪自己的）
```

**留言路由**
```
GET    /api/posts/:id/comments   → 取得文章留言
POST   /api/posts/:id/comments   → 新增留言（需驗證）
DELETE /api/comments/:id         → 刪除留言（需驗證，只能刪自己的）
```

**標籤路由**
```
GET  /api/tags            → 列出所有標籤
POST /api/posts/:id/tags  → 為文章加標籤（需驗證）
```

### 3. 分頁查詢實作

GET `/api/posts?page=1&limit=10&tag=nodejs&search=express` 回傳：

```json
{
  "data": [...],
  "pagination": {
    "page": 1,
    "limit": 10,
    "total": 42,
    "totalPages": 5
  }
}
```

### 4. Transaction 應用

建立文章時若同時附帶標籤，使用 Transaction 確保文章與標籤的關聯同時成功或同時 rollback：

```javascript
const client = await pool.connect();
try {
  await client.query('BEGIN');
  const post = await client.query('INSERT INTO posts ...', [...]);
  for (const tagId of tagIds) {
    await client.query('INSERT INTO post_tags ...', [post.rows[0].id, tagId]);
  }
  await client.query('COMMIT');
} catch (err) {
  await client.query('ROLLBACK');
  throw err;
} finally {
  client.release();
}
```

### 5. 統一錯誤處理

建立 `middleware/errorHandler.js`，回傳標準格式：

```json
{
  "error": {
    "status": 404,
    "message": "Post not found"
  }
}
```

## 提示

- 使用 `bcrypt` 雜湊密碼，不可明文儲存
- JWT secret 存入 `.env`，不可寫死在程式碼中
- 分頁查詢用 `LIMIT $1 OFFSET $2`，offset = (page - 1) * limit
- JOIN 查詢取標籤時使用 `STRING_AGG(tags.name, ',')` 聚合成字串，或回傳陣列
- 更新文章前先確認 `user_id = req.user.id`，防止越權修改

## 進階挑戰（選做）

1. **軟刪除**：posts 加 `deleted_at` 欄位，刪除時設時間戳而非真正刪除，所有查詢加 `WHERE deleted_at IS NULL`
2. **速率限制**：使用 `express-rate-limit` 限制登入端點每 15 分鐘最多 10 次請求
3. **圖片上傳**：POST /api/posts 支援封面圖上傳（multer），儲存路徑存入 posts.cover_image
4. **API 測試**：用 supertest + Jest 為 POST /api/auth/register 和 GET /api/posts 各寫 3 個測試案例
