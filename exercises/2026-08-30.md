# 第 8 週今日練習題：使用 Multer 實作檔案上傳 API

## 題目說明

建立一個支援檔案上傳的 Express API 服務，使用者可以上傳圖片或文件，系統會將檔案儲存至本地目錄，並將上傳紀錄存入 PostgreSQL 資料庫。

## 技術要求

- **Express.js**：建立路由處理 multipart/form-data 請求，回傳上傳結果 JSON
- **PostgreSQL**：建立 `uploads` 資料表記錄每次上傳的檔名、原始檔名、大小、MIME 類型與時間戳記
- **Multer**：設定儲存引擎（diskStorage），限制檔案類型與大小

## 具體任務

1. **初始化專案**
   - `npm init -y`，安裝 `express`、`multer`、`pg`
   - 建立 `uploads/` 目錄供 multer 儲存檔案

2. **建立 PostgreSQL 資料表**
   ```sql
   CREATE TABLE uploads (
     id SERIAL PRIMARY KEY,
     original_name TEXT NOT NULL,
     stored_name   TEXT NOT NULL,
     mime_type     TEXT NOT NULL,
     size_bytes    INTEGER NOT NULL,
     uploaded_at   TIMESTAMPTZ DEFAULT NOW()
   );
   ```

3. **設定 Multer**
   - 使用 `diskStorage` 將檔案存入 `./uploads/` 目錄
   - 以 `Date.now() + '-' + originalname` 作為儲存檔名
   - 限制：只接受 `image/jpeg`、`image/png`、`application/pdf`；單檔上限 5 MB

4. **實作 API 路由**

   | 方法 | 路徑 | 說明 |
   |------|------|------|
   | `POST` | `/upload` | 上傳單一檔案（欄位名稱：`file`），存檔並寫入 DB，回傳檔案資訊 |
   | `GET`  | `/uploads` | 列出所有上傳紀錄（從 DB 查詢） |
   | `GET`  | `/uploads/:id` | 取得單筆紀錄（若不存在回傳 404） |
   | `DELETE` | `/uploads/:id` | 刪除 DB 紀錄並移除磁碟上的實體檔案 |

5. **錯誤處理**
   - Multer 錯誤（檔案過大、格式不允許）要攔截並回傳適當的 HTTP 狀態碼與訊息
   - 若 `POST /upload` 沒有附帶檔案，回傳 `400 Bad Request`

6. **測試**
   使用 `curl` 測試上傳：
   ```bash
   curl -X POST http://localhost:3000/upload \
     -F "file=@/path/to/image.png"
   ```

## 提示

- `multer().single('file')` 對應欄位名稱 `file`
- Multer 的 `fileFilter` 回呼：`cb(null, true)` 允許、`cb(new Error('...'))` 拒絕
- `req.file` 包含 `originalname`、`filename`（儲存名）、`mimetype`、`size`、`path`
- 刪除磁碟檔案：`fs.unlink(filePath, cb)` 或 `fs.promises.unlink(filePath)`
- 連線 PostgreSQL 建議使用 `pg.Pool`，避免每次請求都重新連線

## 進階挑戰（選做）

- **多檔上傳**：改用 `multer().array('files', 5)` 支援同時上傳最多 5 個檔案，並批次寫入 DB
- **雲端儲存**：整合 `multer-s3` 或 `multer-gridfs-storage`，將檔案存入 AWS S3 或 MongoDB GridFS
- **縮圖生成**：上傳圖片後，使用 `sharp` 套件自動生成 200×200 縮圖並存入 `uploads/thumbs/`
- **下載端點**：新增 `GET /uploads/:id/download`，以 `res.download()` 讓使用者直接下載檔案
