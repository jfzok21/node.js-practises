# 第 7 週今日練習題：JWT 身份驗證 API

## 題目說明

實作一套使用 JWT（JSON Web Token）進行身份驗證的 Express + PostgreSQL API。包含使用者註冊、登入，以及受保護路由的存取控制，讓你掌握現代 Web API 常見的無狀態認證流程。

## 技術要求

- **Express.js**：路由設計（公開路由 vs. 受保護路由）、自訂 middleware 驗證 token
- **PostgreSQL**：`users` 資料表儲存帳號與雜湊密碼
- **套件**：`jsonwebtoken`、`bcrypt`（或 `bcryptjs`）、`pg`、`express`

## 具體任務

1. **建立資料庫表格**
   - 建立 `users` 資料表，欄位：`id`（SERIAL PRIMARY KEY）、`username`（VARCHAR UNIQUE NOT NULL）、`password_hash`（TEXT NOT NULL）、`created_at`（TIMESTAMPTZ DEFAULT NOW()`）

2. **實作 POST /auth/register（使用者註冊）**
   - 接收 `{ username, password }`
   - 使用 `bcrypt.hash()` 雜湊密碼後存入資料庫
   - 回傳 `201` 及 `{ message: "註冊成功", userId }`
   - 若 `username` 已存在，回傳 `409` 及錯誤訊息

3. **實作 POST /auth/login（使用者登入）**
   - 接收 `{ username, password }`
   - 從資料庫查詢使用者，用 `bcrypt.compare()` 驗證密碼
   - 驗證通過後，用 `jwt.sign()` 產生 token（payload 包含 `userId`、`username`，過期時間 `1h`）
   - 回傳 `200` 及 `{ token }`
   - 帳號或密碼錯誤統一回傳 `401`

4. **撰寫 JWT 驗證 Middleware**
   - 從 `Authorization: Bearer <token>` header 取得 token
   - 用 `jwt.verify()` 驗證；成功後將解碼資訊掛在 `req.user`
   - 無 token 或無效 token 分別回傳 `401`

5. **實作受保護路由 GET /profile**
   - 套用 JWT middleware
   - 查詢資料庫取得目前登入使用者的完整資料（不回傳密碼）
   - 回傳 `{ id, username, created_at }`

6. **測試完整流程**
   - 用 `curl` 或 Postman 依序測試：register → login 取得 token → 帶 token 呼叫 /profile

## 提示

- JWT secret 存在環境變數 `JWT_SECRET`，不要硬寫在程式碼中（使用 `dotenv`）
- `bcrypt.hash(password, 10)` 中的 `10` 是 salt rounds，開發環境用 10 即可
- `jwt.sign()` 第三個參數傳 `{ expiresIn: '1h' }`
- Middleware 中記得處理 `jwt.verify()` 拋出的例外（token 格式錯誤、過期等）
- 查詢時用 `SELECT id, username, created_at FROM users WHERE id = $1`，明確排除 `password_hash`

## 進階挑戰（選做）

- **Refresh Token**：實作 `POST /auth/refresh`，使用長效 refresh token（存入 DB）來換發新的 access token
- **登出機制**：建立 `token_blacklist` 資料表，logout 時將舊 token 加入黑名單，middleware 每次驗證時一併查詢
- **角色權限**：在 `users` 表加入 `role`（`user` / `admin`），並實作只有 `admin` 才能存取的路由 `GET /admin/users`
- **密碼重設**：實作寄送重設連結（可搭配 nodemailer 或僅回傳 token），透過 token 更新密碼
