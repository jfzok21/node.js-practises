# 第 7 週今日練習題：JWT 身份驗證系統

## 題目說明

實作一個完整的 JWT（JSON Web Token）身份驗證系統，包含使用者註冊、登入、以及需要驗證才能存取的受保護路由。透過本練習理解無狀態（stateless）身份驗證的運作原理。

## 技術要求

- **Express.js**：建立路由、撰寫 middleware 進行 Token 驗證、回傳適當的 HTTP 狀態碼
- **PostgreSQL**：儲存使用者帳號（需對密碼進行 hash 儲存，禁止明文）
- **套件**：`jsonwebtoken`、`bcrypt`（或 `bcryptjs`）、`pg`

## 具體任務

1. **建立資料庫結構**
   - 建立 `users` 資料表，欄位包含：`id`（SERIAL PRIMARY KEY）、`username`（VARCHAR，唯一）、`password_hash`（VARCHAR）、`created_at`（TIMESTAMP，預設 NOW()）

2. **實作 `POST /api/auth/register` 路由**
   - 接收 `username` 與 `password`
   - 使用 `bcrypt.hash()` 對密碼進行 hash（salt rounds 建議 10）
   - 將使用者資料寫入 `users` 資料表
   - 若 `username` 已存在，回傳 `409 Conflict`
   - 成功時回傳 `201 Created` 與使用者基本資訊（不含密碼）

3. **實作 `POST /api/auth/login` 路由**
   - 接收 `username` 與 `password`
   - 從資料庫查詢使用者，使用 `bcrypt.compare()` 驗證密碼
   - 驗證成功後，使用 `jwt.sign()` 產生 Token（設定過期時間 `expiresIn: '1h'`）
   - 回傳 `{ token: '...' }` 給前端
   - 帳號不存在或密碼錯誤時，一律回傳 `401 Unauthorized`（不要透露是帳號還是密碼錯誤）

4. **撰寫 `authenticateToken` Middleware**
   - 從請求的 `Authorization` header 中取出 Bearer Token
   - 使用 `jwt.verify()` 驗證 Token 的有效性
   - 驗證成功後，將解碼的使用者資訊附加到 `req.user`，呼叫 `next()`
   - Token 不存在回傳 `401`；Token 無效或過期回傳 `403`

5. **建立受保護的路由 `GET /api/profile`**
   - 套用 `authenticateToken` middleware
   - 回傳目前登入使用者的個人資料（從資料庫查詢，不含密碼）

## 提示

- `jwt.sign({ userId: user.id, username: user.username }, process.env.JWT_SECRET, { expiresIn: '1h' })`
- JWT_SECRET 請存放於 `.env` 檔案，切勿寫死在程式碼中
- Header 格式：`Authorization: Bearer <token>`
- 可以用 `split(' ')` 解析 Bearer Token：`const token = req.headers['authorization']?.split(' ')[1]`
- 資料庫查詢使用者時，確保只回傳必要欄位（`SELECT id, username, created_at FROM users ...`）
- 注意 `bcrypt.compare()` 是非同步函式，記得 `await`

## 進階挑戰（選做）

- **Refresh Token**：實作 `POST /api/auth/refresh` 路由，接受長效的 Refresh Token，回傳新的短效 Access Token（需要在資料庫建立 `refresh_tokens` 資料表）
- **登出功能**：實作 Token 黑名單機制（可用 PostgreSQL 或 in-memory Set 儲存已撤銷的 Token）
- **密碼更新**：實作 `PUT /api/auth/password` 受保護路由，要求使用者提供舊密碼才能更新新密碼
- **登入記錄**：在資料庫記錄每次成功登入的時間與 IP，並提供 `GET /api/auth/login-history` 查詢
