# 第 7 週今日練習題：JWT 身份驗證系統

## 題目說明

實作一套完整的 JWT（JSON Web Token）身份驗證流程，包含使用者註冊、登入、以及受保護路由的存取控制。透過此練習，你將了解 Token-based 認證的核心概念，以及如何在 Express 與 PostgreSQL 環境中正確整合 JWT。

---

## 技術要求

- **Express.js**：建立 `/auth/register`、`/auth/login`、`/profile` 三條路由；實作 JWT 驗證 Middleware
- **PostgreSQL**：建立 `users` 資料表（id、username、email、password_hash、created_at）；使用 bcrypt 加密密碼後再存入資料庫
- **套件**：`jsonwebtoken`、`bcrypt`（或 `bcryptjs`）、`pg`、`express`

---

## 具體任務

1. **建立資料庫資料表**
   ```sql
   CREATE TABLE IF NOT EXISTS users (
     id SERIAL PRIMARY KEY,
     username VARCHAR(50) UNIQUE NOT NULL,
     email VARCHAR(100) UNIQUE NOT NULL,
     password_hash TEXT NOT NULL,
     created_at TIMESTAMP DEFAULT NOW()
   );
   ```

2. **實作 `POST /auth/register`**
   - 接收 `{ username, email, password }`
   - 使用 bcrypt（saltRounds = 10）雜湊密碼
   - 將使用者存入 PostgreSQL
   - 回傳 `{ message: "註冊成功", userId }` 或適當錯誤訊息（如帳號重複）

3. **實作 `POST /auth/login`**
   - 接收 `{ email, password }`
   - 從資料庫查詢使用者，並以 `bcrypt.compare()` 驗證密碼
   - 驗證通過後，簽發 JWT（payload 包含 `userId`、`username`；有效期 1 小時）
   - 回傳 `{ token: "..." }`

4. **實作 JWT 驗證 Middleware**
   ```js
   // 從 Authorization Header 取出 Bearer Token
   // 以 jwt.verify() 驗證；失敗則回傳 401
   // 成功則將 payload 掛到 req.user，呼叫 next()
   ```

5. **實作受保護路由 `GET /profile`**
   - 套用 JWT Middleware
   - 從資料庫查詢當前使用者資料（排除 password_hash）
   - 回傳使用者資訊

---

## 提示

- 將 JWT Secret 放在環境變數 `JWT_SECRET`，絕對不要寫死在程式碼中
- `bcrypt.hash()` 與 `bcrypt.compare()` 皆為非同步操作，記得使用 `await`
- 回傳錯誤時統一使用適當的 HTTP 狀態碼：400（請求錯誤）、401（未授權）、409（資源衝突，如帳號重複）
- Authorization Header 格式為 `Bearer <token>`，記得用 `split(' ')[1]` 取出 token 部分
- 可用 Postman 或 curl 測試整個流程：先 register → 再 login 取得 token → 帶 token 呼叫 /profile

---

## 進階挑戰（選做）

- **Refresh Token 機制**：實作 `/auth/refresh` 路由，讓 Access Token 到期後可用 Refresh Token 換新的 Access Token（Refresh Token 存入資料庫並設較長有效期）
- **登出功能**：建立 `token_blacklist` 資料表，在 `/auth/logout` 時將 token 的 jti（JWT ID）加入黑名單，Middleware 驗證時也需檢查黑名單
- **角色權限（RBAC）**：在 users 資料表新增 `role` 欄位（`user` / `admin`），並建立只有 admin 才能存取的路由
