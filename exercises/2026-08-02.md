# 第 4 週今日練習題：Express Middleware 實作

## 題目說明

本週主題是 **Express Middleware（中介軟體）**。Middleware 是 Express 應用程式中的核心概念，每個請求在到達最終路由處理器之前，都可以經過一系列的 middleware 函數進行處理。本練習將帶你實作自訂 middleware、使用 body-parser、以及建立統一的錯誤處理機制。

## 技術要求

- **Express.js**：建立 middleware 函數、全域與局部 middleware、錯誤處理 middleware（四個參數：err, req, res, next）
- **PostgreSQL**：記錄每次 API 請求的 log 至資料庫（可選）

## 具體任務

### 任務一：建立請求日誌 Middleware（Logger）

1. 建立 `middlewares/logger.js`，記錄每次請求的以下資訊：
   - 時間戳記（ISO 格式）
   - HTTP 方法（GET / POST / PUT / DELETE）
   - 請求路徑（req.path）
   - 回應狀態碼
   - 處理時間（毫秒）
2. 將此 middleware 套用至所有路由（使用 `app.use()`）
3. 輸出格式範例：`[2026-08-02T10:00:00.000Z] GET /api/users 200 - 12ms`

### 任務二：建立身份驗證 Middleware（Auth Check）

1. 建立 `middlewares/authCheck.js`
2. 從請求標頭讀取 `x-api-key`
3. 驗證規則：若 `x-api-key` 不等於 `secret-123`，回傳 `401 Unauthorized`：
   ```json
   { "error": "Unauthorized", "message": "Invalid or missing API key" }
   ```
4. 驗證通過則呼叫 `next()` 繼續處理
5. 只套用至 `/api/protected` 開頭的路由

### 任務三：建立資料驗證 Middleware（Validation）

1. 建立 `middlewares/validateUser.js`
2. 驗證 POST `/api/users` 的請求 body 必須包含：
   - `name`：字串，不可為空
   - `email`：合法的 Email 格式
   - `age`：數字，介於 1 至 120 之間
3. 若驗證失敗，回傳 `400 Bad Request`：
   ```json
   {
     "error": "Validation Error",
     "details": ["name is required", "invalid email format"]
   }
   ```
4. 驗證通過後，將清理過的資料存入 `req.validatedBody`，再呼叫 `next()`

### 任務四：建立全域錯誤處理 Middleware

1. 在 `app.js` 最後（所有路由之後）加入錯誤處理 middleware（四個參數）
2. 根據錯誤類型回傳對應的 HTTP 狀態碼與訊息：
   - 404：找不到資源
   - 500：伺服器內部錯誤
3. 在開發環境下（`NODE_ENV !== 'production'`）的 500 錯誤回應中附上 `stack` 欄位

### 任務五：組合應用

建立以下路由，並套用對應的 middleware：

| 路由 | Middleware | 說明 |
|------|------------|------|
| `GET /api/public` | logger | 公開路由，回傳 `{ message: "Hello, World!" }` |
| `POST /api/users` | logger + validateUser | 建立使用者，驗證後回傳 `{ message: "User created", data: req.validatedBody }` |
| `GET /api/protected/data` | logger + authCheck | 受保護路由，通過驗證後回傳 `{ secret: "This is protected data" }` |

## 提示

- `app.use(express.json())` 必須在所有路由之前宣告，才能解析 JSON body
- 錯誤處理 middleware 必須有恰好四個參數：`(err, req, res, next)`，Express 才會辨識為錯誤處理器
- 計算處理時間可用 `Date.now()` 在 middleware 開頭記錄起始時間，並在 `res.on('finish', ...)` 事件中計算差值
- 局部 middleware 可直接放在路由方法的第二個參數：`app.post('/api/users', validateUser, handler)`
- 使用 `next(err)` 將錯誤傳遞給錯誤處理 middleware

## 進階挑戰（選做）

1. **速率限制（Rate Limiting）**：建立 `middlewares/rateLimit.js`，使用 `Map` 或 PostgreSQL 記錄每個 IP 的請求次數，每分鐘超過 10 次回傳 `429 Too Many Requests`。

2. **請求 Log 寫入資料庫**：在 logger middleware 中，將每次請求資訊（method、path、status、duration、timestamp、ip）INSERT 至 PostgreSQL 的 `request_logs` 資料表。建立對應的 schema：
   ```sql
   CREATE TABLE request_logs (
     id SERIAL PRIMARY KEY,
     method VARCHAR(10),
     path TEXT,
     status_code INT,
     duration_ms INT,
     ip VARCHAR(45),
     created_at TIMESTAMPTZ DEFAULT NOW()
   );
   ```

3. **Middleware 測試**：使用 `jest` 與 `supertest` 撰寫 middleware 的單元測試，分別測試授權成功、授權失敗、驗證成功、驗證失敗四個情境。
