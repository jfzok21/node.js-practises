# 第 5 週今日練習題：書店訂單系統 — JOIN 查詢與多資料表關聯

## 題目說明

建立一個書店後端 API，包含 `users`、`books`、`orders`、`order_items` 四張資料表，並透過 JOIN 查詢實作各種跨表查詢 API。這是理解關聯式資料庫核心概念的關鍵練習。

## 技術要求

- **Express.js**：設計 RESTful 路由，回傳結構化 JSON 資料
- **PostgreSQL**：設計多資料表 schema，使用 INNER JOIN、LEFT JOIN、聚合函數（COUNT、SUM）

## 具體任務

### 1. 建立資料表 schema

在 PostgreSQL 中建立以下四張表：

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  email VARCHAR(150) UNIQUE NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE books (
  id SERIAL PRIMARY KEY,
  title VARCHAR(200) NOT NULL,
  author VARCHAR(100) NOT NULL,
  price NUMERIC(8, 2) NOT NULL,
  stock INT DEFAULT 0
);

CREATE TABLE orders (
  id SERIAL PRIMARY KEY,
  user_id INT REFERENCES users(id),
  status VARCHAR(20) DEFAULT 'pending',  -- pending / paid / shipped
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE order_items (
  id SERIAL PRIMARY KEY,
  order_id INT REFERENCES orders(id),
  book_id INT REFERENCES books(id),
  quantity INT NOT NULL,
  unit_price NUMERIC(8, 2) NOT NULL
);
```

### 2. 建立 Express API 路由

實作以下六支 API：

| Method | Path | 說明 |
|--------|------|------|
| GET | `/users/:id/orders` | 查詢某使用者的所有訂單（含訂單金額總計） |
| GET | `/orders/:id` | 查詢某筆訂單的完整明細（含書名、數量、單價） |
| GET | `/books/popular` | 查詢銷售量前 5 名的書籍（依 order_items 加總） |
| GET | `/users/top-buyers` | 查詢消費金額最高的前 3 名使用者 |
| POST | `/orders` | 建立新訂單（同時寫入 orders 與 order_items） |
| GET | `/books/:id/buyers` | 查詢購買過某本書的所有使用者（去重） |

### 3. 實作 JOIN 查詢

各 API 需使用以下 SQL 技巧：

- `GET /users/:id/orders`：
  ```sql
  SELECT o.id, o.status, o.created_at,
         SUM(oi.quantity * oi.unit_price) AS total_amount
  FROM orders o
  LEFT JOIN order_items oi ON o.id = oi.order_id
  WHERE o.user_id = $1
  GROUP BY o.id, o.status, o.created_at
  ORDER BY o.created_at DESC;
  ```

- `GET /orders/:id`：
  ```sql
  SELECT o.id AS order_id, o.status, u.name AS buyer_name,
         b.title, oi.quantity, oi.unit_price,
         (oi.quantity * oi.unit_price) AS subtotal
  FROM orders o
  JOIN users u ON o.user_id = u.id
  JOIN order_items oi ON o.id = oi.order_id
  JOIN books b ON oi.book_id = b.id
  WHERE o.id = $1;
  ```

- `GET /books/popular`：使用 `SUM(quantity)` + `GROUP BY` + `ORDER BY` + `LIMIT 5`

### 4. 錯誤處理

- 當查詢結果為空（找不到訂單 / 使用者），回傳 `404` 與說明訊息
- 建立訂單時若 `book_id` 不存在，回傳 `400` 錯誤

## 提示

- 先用純 SQL 在 `psql` 中測試 JOIN 查詢，確認結果正確後再整合進 Express
- `SUM()` 與 `COUNT()` 回傳的是字串型別（pg driver 行為），需用 `Number()` 或 `parseFloat()` 轉換
- 建立訂單（POST /orders）時，建議使用 `BEGIN / COMMIT` 交易，避免訂單與明細不一致
- LEFT JOIN 保留主表所有資料，INNER JOIN 只保留有對應的資料——選錯會影響查詢結果

## 進階挑戰（選做）

1. **庫存扣減**：POST /orders 時同時更新 `books.stock`，若庫存不足回傳 `409 Insufficient Stock`
2. **訂單狀態更新**：`PATCH /orders/:id/status`，只允許合法狀態轉移（`pending → paid → shipped`）
3. **複合統計報表**：`GET /reports/monthly`，依月份統計總訂單數、總金額、新增使用者數（三表 JOIN + GROUP BY）
4. **搜尋書籍買家**：`GET /books/:id/buyers` 的結果加上每位使用者的購買次數與總花費金額
