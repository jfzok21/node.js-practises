# 第 13 週今日練習題：部落格 API 實戰專案

## 題目說明

整合前 12 週所學，建立一個完整的部落格後端 API 系統。本專案涵蓋路由設計、資料庫操作、使用者驗證、分頁、資料驗證等完整後端開發流程。

## 技術要求
- **Express.js**：RESTful API 路由設計、Middleware 組合應用、錯誤處理中介層
- **PostgreSQL**：多資料表設計（users、posts、comments、tags）、JOIN 查詢、Transaction 操作

## 具體任務

1. **資料庫設計**
   - 建立 `users` 資料表（id, username, email, password_hash, created_at）
   - 建立 `posts` 資料表（id, title, content, user_id, created_at, updated_at）
   - 建立 `comments` 資料表（id, content, user_id, post_id, created_at）
   - 建立 `tags` 資料表（id, name）及 `post_tags` 關聯表（post_id, tag_id）

2. **使用者 API（搭配 JWT 驗證）**
   - `POST /api/auth/register`：註冊（bcrypt 雜湊密碼）
   - `POST /api/auth/login`：登入，回傳 JWT token
   - `GET /api/users/me`：取得目前登入使用者資訊（需驗證）

3. **文章 API**
   - `GET /api/posts`：列出所有文章（支援分頁 `?page=1&limit=10`、關鍵字搜尋 `?search=`、標籤篩選 `?tag=`）
   - `GET /api/posts/:id`：取得單篇文章（含作者、留言數、標籤）
   - `POST /api/posts`：建立文章（需驗證，含標籤寫入，使用 Transaction）
   - `PUT /api/posts/:id`：更新文章（僅作者可操作）
   - `DELETE /api/posts/:id`：刪除文章（僅作者可操作，同時刪除 post_tags）

4. **留言 API**
   - `GET /api/posts/:postId/comments`：取得文章的所有留言
   - `POST /api/posts/:postId/comments`：新增留言（需驗證）
   - `DELETE /api/comments/:id`：刪除留言（僅本人可操作）

5. **資料驗證與錯誤處理**
   - 使用 `express-validator` 或手動驗證必填欄位、格式正確性
   - 統一錯誤回應格式：`{ "error": "訊息", "code": "ERROR_CODE" }`
   - 針對 404（找不到資源）、401（未驗證）、403（無權限）分別處理

## 提示

- 建議專案結構：
  ```
  src/
  ├── routes/        # 路由定義
  ├── controllers/   # 商業邏輯
  ├── middleware/    # auth、validate 等
  ├── db/            # PostgreSQL 連線與 query
  └── app.js         # Express 主程式
  ```
- JWT 驗證中介層可抽取成 `middleware/auth.js`，以 `req.user` 傳遞使用者資訊
- 建立文章含標籤時，`post_tags` 的插入應與 `posts` 的插入在同一個 Transaction 中，確保原子性
- 分頁查詢搭配 `COUNT(*) OVER()` 或第二個 `SELECT COUNT(*)` 取得總筆數，一併回傳 `{ data, total, page, totalPages }`

## 進階挑戰（選做）

- **文章草稿功能**：新增 `status` 欄位（`draft` / `published`），草稿僅作者可見
- **圖片上傳**：使用 `multer` 讓文章支援封面圖上傳，存至 `uploads/` 資料夾
- **速率限制**：使用 `express-rate-limit` 限制登入 API 每分鐘最多 5 次，防止暴力破解
- **API 測試**：使用 `supertest + Jest` 撰寫 `/api/posts` 的完整測試套件（至少涵蓋 CRUD 各路由）
