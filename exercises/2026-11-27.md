# 第 21 週今日練習題：電商後端 API 實戰 — 購物車與訂單系統

## 題目說明

實作一個電商平台的核心後端模組，包含購物車管理與訂單建立流程。
本題整合 JWT 身份驗證、PostgreSQL 交易處理、資料驗證與分頁查詢等技巧，模擬真實產品環境的開發需求。

---

## 技術要求

- **Express.js**：RESTful 路由設計、JWT middleware 驗證身份、統一錯誤處理 middleware
- **PostgreSQL**：多資料表 JOIN、Transaction（庫存扣減 + 訂單建立需原子化）、分頁查詢

---

## 資料庫 Schema

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE products (
  id SERIAL PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  price NUMERIC(10, 2) NOT NULL,
  stock INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE cart_items (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  product_id INTEGER REFERENCES products(id) ON DELETE CASCADE,
  quantity INTEGER NOT NULL CHECK (quantity > 0),
  UNIQUE(user_id, product_id)
);

CREATE TABLE orders (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id),
  total_amount NUMERIC(10, 2) NOT NULL,
  status VARCHAR(50) DEFAULT 'pending',
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE order_items (
  id SERIAL PRIMARY KEY,
  order_id INTEGER REFERENCES orders(id) ON DELETE CASCADE,
  product_id INTEGER REFERENCES products(id),
  quantity INTEGER NOT NULL,
  unit_price NUMERIC(10, 2) NOT NULL
);
```

## 具體任務

### 1. 購物車 API（需 JWT 驗證）

實作以下端點：

| 方法 | 路徑 | 說明 |
|------|------|------|
| `GET` | `/api/cart` | 取得目前使用者的購物車（含商品名稱、單價、小計） |
| `POST` | `/api/cart` | 新增商品至購物車（`{ product_id, quantity }`） |
| `PUT` | `/api/cart/:product_id` | 更新數量（`{ quantity }`）；數量為 0 則自動刪除 |
| `DELETE` | `/api/cart/:product_id` | 移除指定商品 |

**`GET /api/cart` 回應範例：**
```json
{
  "items": [
    { "product_id": 1, "name": "藍牙耳機", "price": "1200.00", "quantity": 2, "subtotal": "2400.00" }
  ],
  "total": "2400.00"
}
```

### 2. 結帳下單 API

實作 `POST /api/orders/checkout`：

1. 驗證購物車不為空
2. 驗證所有商品庫存充足（若任一不足，回傳 `422` 並列出問題商品）
3. 使用 **PostgreSQL Transaction** 執行：
   - 扣減各商品庫存（`UPDATE products SET stock = stock - $1 WHERE id = $2`）
   - 建立 `orders` 記錄（計算總金額）
   - 建立對應的 `order_items` 記錄
   - 清空購物車（刪除 `cart_items`）
4. 回傳訂單 id 與總金額

**成功回應（201）：**
```json
{
  "order_id": 42,
  "total_amount": "2400.00",
  "status": "pending"
}
```

### 3. 訂單查詢 API（含分頁）

實作 `GET /api/orders?page=1&limit=10`：

- 僅回傳目前使用者的訂單
- 支援 `page` 與 `limit` 查詢參數（預設 `page=1`、`limit=10`）
- 每筆訂單含：`id`、`total_amount`、`status`、`created_at`、`item_count`

---

## 提示

- 使用 `pg` 套件的 `client.query('BEGIN')` / `COMMIT` / `ROLLBACK` 管理 Transaction
- JWT 驗證建議抽成共用 middleware（`middlewares/auth.js`），掛在需要保護的路由上
- 庫存不足的錯誤在 Transaction 開始前就先行驗證，避免 rollback 開銷
- `NUMERIC` 欄位從 PostgreSQL 回傳為字串，計算加總時需用 `parseFloat()`
- 分頁查詢使用 `LIMIT $1 OFFSET $2`，`offset = (page - 1) * limit`
- 錯誤處理 middleware 放在所有路由之後：`app.use((err, req, res, next) => { ... })`

---

## 進階挑戰（選做）

1. **樂觀鎖（Optimistic Locking）**：在 `products` 加入 `version` 欄位，以 `WHERE id = $1 AND version = $2` 防止超賣競爭條件
2. **訂單詳情 API**：實作 `GET /api/orders/:id`，回傳訂單內的所有商品明細（JOIN `order_items` + `products`）
3. **取消訂單**：實作 `PATCH /api/orders/:id/cancel`，狀態改為 `cancelled` 並歸還庫存（同樣使用 Transaction）
4. **supertest + Jest 整合測試**：為 checkout 流程撰寫測試，涵蓋庫存不足與正常下單兩種情境
