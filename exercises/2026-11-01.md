# 第 17 週今日練習題：任務管理 API（實戰專案）

## 題目說明

建立一個具備完整功能的「任務管理系統」REST API。使用者可以建立專案（Project）、在專案下新增任務（Task），並透過標籤（Tag）為任務分類。本題整合前幾週所有核心技能：CRUD、JOIN 查詢、JWT 驗證、資料驗證、分頁與錯誤處理。

## 技術要求

- **Express.js**：模組化路由（`/auth`、`/projects`、`/tasks`、`/tags`）、JWT 中介層保護私有端點、統一錯誤處理中介層
- **PostgreSQL**：多資料表關聯（users → projects → tasks ↔ tags）、JOIN 查詢、交易處理（建立任務時同時關聯標籤）

## 具體任務

### 1. 資料庫設計

建立以下資料表：

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE projects (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  name VARCHAR(255) NOT NULL,
  description TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE tags (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  name VARCHAR(100) NOT NULL,
  color VARCHAR(7) DEFAULT '#6c757d'
);

CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  project_id INTEGER REFERENCES projects(id) ON DELETE CASCADE,
  title VARCHAR(255) NOT NULL,
  description TEXT,
  status VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending', 'in_progress', 'done')),
  due_date DATE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE task_tags (
  task_id INTEGER REFERENCES tasks(id) ON DELETE CASCADE,
  tag_id  INTEGER REFERENCES tags(id) ON DELETE CASCADE,
  PRIMARY KEY (task_id, tag_id)
);
```

### 2. 身份驗證（`/auth`）

| 方法 | 路徑 | 說明 |
|------|------|------|
| POST | `/auth/register` | 註冊（email + password，bcrypt 加密） |
| POST | `/auth/login` | 登入，回傳 JWT（有效期 24h） |

### 3. 專案管理（`/projects`，需 JWT）

| 方法 | 路徑 | 說明 |
|------|------|------|
| GET | `/projects` | 列出目前使用者的所有專案（含各專案任務數量） |
| POST | `/projects` | 建立新專案 |
| GET | `/projects/:id` | 取得單一專案（含任務清單） |
| PUT | `/projects/:id` | 更新專案 |
| DELETE | `/projects/:id` | 刪除專案 |

### 4. 任務管理（`/projects/:projectId/tasks`，需 JWT）

| 方法 | 路徑 | 說明 |
|------|------|------|
| GET | `/projects/:projectId/tasks` | 分頁列出任務；支援 `?status=`、`?tag=`、`?sort=due_date` 篩選 |
| POST | `/projects/:projectId/tasks` | 建立任務（可同時帶入 `tag_ids` 陣列） |
| PATCH | `/projects/:projectId/tasks/:id` | 更新任務狀態或內容 |
| DELETE | `/projects/:projectId/tasks/:id` | 刪除任務 |

### 5. 標籤管理（`/tags`，需 JWT）

- `GET /tags`：列出使用者的所有標籤
- `POST /tags`：建立標籤（name + color）
- `DELETE /tags/:id`：刪除標籤

### 6. 跨功能需求

- 所有寫入端點必須驗證輸入（使用 `express-validator` 或手動驗證）
- 統一錯誤回應格式：`{ "error": "訊息", "code": "ERROR_CODE" }`
- 「建立任務並關聯標籤」必須在同一個資料庫交易中完成
- 分頁回應需包含 `{ data, total, page, limit }`

## 提示

- 使用 `pg` 的 `client.query('BEGIN') / COMMIT / ROLLBACK` 處理交易
- JWT 中介層可提取 `req.user.id`，所有資源操作前先驗證擁有權
- 專案列出任務數量可用子查詢：`SELECT p.*, (SELECT COUNT(*) FROM tasks WHERE project_id = p.id) AS task_count`
- 標籤篩選任務可透過 `EXISTS (SELECT 1 FROM task_tags tt JOIN tags t ON tt.tag_id = t.id WHERE tt.task_id = tasks.id AND t.name = $1)` 實作

## 進階挑戰（選做）

1. **活動紀錄**：新增 `activity_logs` 資料表，每次任務狀態變更時記錄舊值 / 新值與變更時間
2. **統計儀表板**：`GET /projects/:id/stats` 回傳各狀態任務數量、最近 7 天完成趨勢（以日期分組 COUNT）
3. **全文搜尋**：`GET /tasks/search?q=keyword` 使用 PostgreSQL `ILIKE` 或 `tsvector` 搜尋任務標題與描述
4. **匯出 CSV**：`GET /projects/:id/export` 將該專案所有任務以 CSV 格式串流輸出（使用 Node.js `stream`）
