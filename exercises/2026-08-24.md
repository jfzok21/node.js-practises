# 第 7 週今日練習題：JWT 身份驗證系統

## 題目說明

建立一個完整的 JWT（JSON Web Token）身份驗證系統，包含使用者註冊、登入、以及受保護路由的存取控制。透過本練習，你將學會如何使用 JWT 保護 API 端點，實作 Token 的簽發、驗證與刷新機制。

---

## 技術要求

- **Express.js**：建立身份驗證路由（/auth/register、/auth/login、/auth/me）、撰寫 JWT 驗證 Middleware
- **PostgreSQL**：儲存使用者帳號（email、hashed password）、建立 users 資料表
- **套件**：`jsonwebtoken`（簽發/驗證 Token）、`bcrypt`（密碼雜湊）

---

## 具體任務

1. **建立資料庫資料表**
   ```sql
   CREATE TABLE users (
     id SERIAL PRIMARY KEY,
     email VARCHAR(255) UNIQUE NOT NULL,
     password_hash VARCHAR(255) NOT NULL,
     created_at TIMESTAMP DEFAULT NOW()
   );
   ```

2. **實作 POST /auth/register**
   - 接受 `{ email, password }` 請求體
   - 使用 `bcrypt.hash()` 將密碼雜湊後存入 PostgreSQL
   - 若 email 已存在，回傳 `409 Conflict`
   - 成功回傳 `201 Created` 及使用者基本資訊（不含密碼）

3. **實作 POST /auth/login**
   - 接受 `{ email, password }` 請求體
   - 從 DB 查詢使用者，用 `bcrypt.compare()` 驗證密碼
   - 驗證成功後，使用 `jwt.sign()` 簽發 Access Token（有效期 1 小時）
   - 回傳 `{ token, user: { id, email } }`

4. **撰寫 JWT 驗證 Middleware**
   ```js
   // middleware/auth.js
   const authenticate = (req, res, next) => {
     const authHeader = req.headers['authorization'];
     const token = authHeader && authHeader.split(' ')[1]; // Bearer <token>
     if (!token) return res.status(401).json({ error: '未提供 Token' });
     try {
       const payload = jwt.verify(token, process.env.JWT_SECRET);
       req.user = payload;
       next();
     } catch (err) {
       return res.status(403).json({ error: 'Token 無效或已過期' });
     }
   };
   ```

5. **實作 GET /auth/me（受保護路由）**
   - 套用 `authenticate` Middleware
   - 從 DB 查詢並回傳當前登入使用者的資料（不含密碼）

6. **環境變數設定**
   - 在 `.env` 中設定 `JWT_SECRET`（使用隨機長字串）
   - 確保 `.env` 已加入 `.gitignore`

---

## 提示

- `JWT_SECRET` 務必使用不可預測的隨機字串，可用 `require('crypto').randomBytes(64).toString('hex')` 產生
- 驗證失敗（密碼錯誤、使用者不存在）統一回傳 `401`，避免洩漏使用者是否存在的資訊
- 使用 Postman 或 `curl` 測試流程：先 register → login 取得 token → 帶著 token 呼叫 /auth/me
- `bcrypt.hash(password, 10)` 中的 `10` 是 salt rounds，數字越大越安全但越慢，開發環境用 10 即可

---

## 進階挑戰（選做）

- **Refresh Token**：簽發短效 Access Token（15 分鐘）+ 長效 Refresh Token（7 天），並實作 `POST /auth/refresh` 端點
- **Token 黑名單**：使用者登出時，將 Token 存入 DB 黑名單，Middleware 驗證時同時檢查黑名單
- **角色權限（RBAC）**：在 users 表加入 `role` 欄位（'user' / 'admin'），撰寫 `authorize('admin')` Middleware，只允許管理員存取特定路由
- **Rate Limiting**：對 /auth/login 加上速率限制（例如每 IP 每 15 分鐘最多 5 次），防止暴力破解
