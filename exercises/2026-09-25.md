# 第 12 週今日練習題：待辦事項 API 實戰專案

## 題目說明

綜合前 11 週所學，建立一個完整的「待辦事項管理系統」REST API。此專案將整合 Express 路由、PostgreSQL CRUD、JWT 身份驗證、資料驗證、分頁查詢與錯誤處理，模擬真實後端開發流程。

---

## 技術要求

- **Express.js**：模組化路由（`/auth`、`/todos`）、middleware 鏈、統一錯誤處理
- **PostgreSQL**：多資料表設計（`users`、`todos`、`tags`）、JOIN 查詢、Transaction
- **JWT**：Bearer Token 驗證，保護需登入的路由
- **資料驗證**：輸入欄位型別與必填檢查，回傳結構化錯誤訊息
- **分頁與排序**：支援 `?page=`、`?limit=`、`?sort=` 查詢參數

## 具體任務

### 1. 資料庫設計

建立以下三張資料表：

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE todos (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  title VARCHAR(255) NOT NULL,
  description TEXT,
  completed BOOLEAN DEFAULT FALSE,
  due_date DATE,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE tags (
  id SERIAL PRIMARY KEY,
  todo_id INTEGER REFERENCES todos(id) ON DELETE CASCADE,
  name VARCHAR(50) NOT NULL
);
```

### 2. 身份驗證路由（`/auth`）

| 方法 | 路徑 | 說明 |
|------|------|------|
| POST | `/auth/register` | 註冊（email + password） |
| POST | `/auth/login` | 登入，回傳 JWT |

- 密碼使用 `bcrypt` 雜湊儲存
- 登入成功回傳 `{ token, user: { id, email } }`
- 重複 email 回傳 `409 Conflict`

### 3. 待辦事項路由（`/todos`，需 JWT）

| 方法 | 路徑 | 說明 |
|------|------|------|
| GET | `/todos` | 取得目前使用者的所有待辦（支援分頁、篩選） |
| POST | `/todos` | 新增待辦 |
| GET | `/todos/:id` | 取得單一待辦（含 tags） |
| PATCH | `/todos/:id` | 更新待辦（部分欄位） |
| DELETE | `/todos/:id` | 刪除待辦 |
| POST | `/todos/:id/tags` | 新增標籤 |

### 4. 查詢功能實作

GET `/todos` 需支援以下查詢字串：

```
GET /todos?page=1&limit=10&completed=false&sort=due_date&order=asc&search=購物
```

- `search`：模糊搜尋 `title` 或 `description`
- `completed`：篩選完成狀態
- `sort`：排序欄位（`created_at`、`due_date`、`title`）
- `order`：`asc` 或 `desc`

### 5. Transaction 範例

新增待辦同時附加初始標籤時，使用 Transaction 確保原子性：

```js
const client = await pool.connect();
try {
  await client.query('BEGIN');
  const todoResult = await client.query(
    'INSERT INTO todos (user_id, title, description, due_date) VALUES ($1, $2, $3, $4) RETURNING *',
    [userId, title, description, due_date]
  );
  const todoId = todoResult.rows[0].id;
  if (tags && tags.length > 0) {
    for (const tag of tags) {
      await client.query('INSERT INTO tags (todo_id, name) VALUES ($1, $2)', [todoId, tag]);
    }
  }
  await client.query('COMMIT');
  res.status(201).json({ todo: todoResult.rows[0] });
} catch (err) {
  await client.query('ROLLBACK');
  next(err);
} finally {
  client.release();
}
```

### 6. 統一錯誤處理 Middleware

```js
// 放在所有路由之後
app.use((err, req, res, next) => {
  const status = err.status || 500;
  res.status(status).json({
    error: {
      message: err.message || '伺服器錯誤',
      code: err.code || 'INTERNAL_ERROR'
    }
  });
});
```

## 提示

- 使用 `express.Router()` 拆分路由至 `routes/auth.js` 與 `routes/todos.js`
- JWT middleware 寫成獨立函式放在 `middlewares/auth.js`，掛載於需保護的路由
- 資料庫連線用 `pg.Pool`，建議放在 `db/pool.js` 統一管理
- `PATCH` 只更新有傳入的欄位，可用動態 SQL 或手動過濾
- 確保每個使用者只能存取自己的待辦（WHERE user_id = $1）
- 分頁回應格式建議：`{ data: [...], pagination: { page, limit, total } }`

## 進階挑戰（選做）

1. **軟刪除（Soft Delete）**：為 `todos` 增加 `deleted_at` 欄位，刪除時填入時間戳，查詢時過濾掉已刪除項目
2. **重新整理 Token（Refresh Token）**：實作 `POST /auth/refresh`，使用長效 refresh token 換發新 access token
3. **API 測試**：使用 `Jest` + `supertest` 撰寫整合測試，覆蓋所有路由的成功與失敗情境
4. **速率限制**：使用 `express-rate-limit` 限制登入路由（例如每分鐘最多 5 次）
5. **Swagger 文件**：用 `swagger-ui-express` 加上 `swagger-jsdoc` 自動產生 API 文件
