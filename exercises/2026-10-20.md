# 第 15 週今日練習題：電商訂單管理 API（整合實戰）

## 題目說明

設計並實作一個電商訂單管理系統的 REST API。本題整合你前幾週所學：路由設計、資料庫 CRUD、JWT 驗證、資料驗證、JOIN 查詢、交易處理、分頁排序，以及 API 測試，讓你體驗真實後端開發的完整流程。

---

## 技術要求

- **Express.js**：路由模組化（`routes/`）、中介軟體（auth、validate、errorHandler）
- **PostgreSQL**：多資料表（users、products、orders、order_items）、JOIN、Transaction
- **JWT**：Bearer Token 身份驗證
- **Joi / express-validator**：請求參數驗證
- **supertest + Jest**：API 整合測試

---

## 資料庫設計

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE products (
  id SERIAL PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  price NUMERIC(10, 2) NOT NULL,
  stock INT NOT NULL DEFAULT 0,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE orders (
  id SERIAL PRIMARY KEY,
  user_id INT REFERENCES users(id) ON DELETE CASCADE,
  status VARCHAR(50) DEFAULT 'pending',  -- pending, paid, cancelled
  total NUMERIC(10, 2) NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE order_items (
  id SERIAL PRIMARY KEY,
  order_id INT REFERENCES orders(id) ON DELETE CASCADE,
  product_id INT REFERENCES products(id),
  quantity INT NOT NULL,
  unit_price NUMERIC(10, 2) NOT NULL
);
```

## 具體任務

### 1. 專案初始化
- 建立 Express 應用，使用 `dotenv` 管理環境變數
- 設定 PostgreSQL 連線池（`pg.Pool`）
- 目錄結構：`routes/`、`middleware/`、`controllers/`、`db/`

### 2. 身份驗證（JWT）
- `POST /api/auth/register`：註冊，密碼使用 `bcrypt` 雜湊後存入
- `POST /api/auth/login`：登入，驗證成功後回傳 JWT（有效期 1 天）
- 建立 `authMiddleware`，解析 Bearer Token 並將 `req.user` 注入

### 3. 商品 API（需登入）
- `GET /api/products`：列出所有商品，支援分頁（`?page=1&limit=10`）與排序（`?sort=price&order=asc`）
- `GET /api/products/:id`：取得單一商品
- `POST /api/products`：新增商品（需驗證 name 非空、price > 0、stock >= 0）
- `PATCH /api/products/:id`：更新商品資訊

### 4. 訂單 API（需登入）
- `POST /api/orders`：建立訂單
  - 請求 body：`{ items: [{ productId, quantity }] }`
  - **使用 Transaction**：
    1. 確認每項商品庫存足夠
    2. 建立 `orders` 記錄
    3. 建立 `order_items` 記錄（帶入當時售價 `unit_price`）
    4. 扣減每項商品的 `stock`
    5. 任一步驟失敗，整筆回滾
- `GET /api/orders`：取得當前登入使用者的訂單列表（JOIN order_items & products）
- `GET /api/orders/:id`：取得單一訂單詳情（含商品明細）
- `PATCH /api/orders/:id/cancel`：取消訂單（限 status=pending 的訂單，並回補庫存）

### 5. 錯誤處理
- 建立全域 `errorHandler` middleware
- 統一錯誤格式：`{ error: { code, message } }`
- 常見情境：404 資源不存在、401 未授權、400 驗證失敗、422 庫存不足、500 伺服器錯誤

### 6. API 測試（supertest + Jest）
為以下端點各寫至少一個測試：
- 登入取得 JWT
- 使用有效 / 無效 Token 存取受保護的路由
- 建立訂單（成功 + 庫存不足的失敗情境）
- 取消訂單（成功 + 已付款訂單無法取消的情境）

## 提示

- Transaction 寫法範例：
  ```js
  const client = await pool.connect();
  try {
    await client.query('BEGIN');
    // ... 多個 query
    await client.query('COMMIT');
  } catch (err) {
    await client.query('ROLLBACK');
    throw err;
  } finally {
    client.release();
  }
  ```
- JWT 驗證中介軟體記得處理 `TokenExpiredError` 與 `JsonWebTokenError`
- 分頁查詢使用 `LIMIT $1 OFFSET $2`，`offset = (page - 1) * limit`
- 建立訂單時，`unit_price` 應存當下的商品售價，而非日後的售價，避免歷史訂單金額被改動

## 進階挑戰（選做）

1. **訂單狀態機**：加入 `paid` 狀態，實作 `PATCH /api/orders/:id/pay` 端點（模擬付款），只有 `pending` 訂單才能付款
2. **商品搜尋**：`GET /api/products?search=關鍵字`，使用 PostgreSQL `ILIKE` 模糊比對
3. **訂單統計**：`GET /api/admin/stats`，回傳各狀態訂單數量、總營收（需 `GROUP BY`）
4. **Rate Limiting**：使用 `express-rate-limit`，對登入路由限制每 IP 每分鐘最多 10 次
5. **Docker Compose**：撰寫 `docker-compose.yml`，將 app 與 PostgreSQL 容器化，一鍵啟動
