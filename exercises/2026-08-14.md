# 第 6 週今日練習題：資料驗證與錯誤回應

## 題目說明

建立一個「使用者註冊與更新」API，加入完整的輸入驗證邏輯，並在驗證失敗時回傳清楚、一致的錯誤訊息格式。這是實際產品中最基礎也最重要的防護層。

## 技術要求

- **Express.js**：定義路由、撰寫驗證 middleware、建立統一錯誤處理器
- **PostgreSQL**：操作 `users` 資料表，確保 email 唯一性並回傳適當的 DB 錯誤

## 具體任務

1. **建立 `users` 資料表**（若尚未建立）
   ```sql
   CREATE TABLE IF NOT EXISTS users (
     id SERIAL PRIMARY KEY,
     name VARCHAR(100) NOT NULL,
     email VARCHAR(255) UNIQUE NOT NULL,
     age INTEGER,
     created_at TIMESTAMP DEFAULT NOW()
   );
   ```

2. **實作 `POST /users` 路由**，包含以下驗證規則：
   - `name`：必填，長度 2–100 字元
   - `email`：必填，須為合法 email 格式
   - `age`：選填，若提供則必須為整數且介於 0–150 之間

3. **撰寫驗證 middleware `validateUser`**：
   - 集中所有驗證邏輯
   - 驗證失敗時回傳 `400 Bad Request`，格式如下：
     ```json
     {
       "status": "error",
       "code": "VALIDATION_ERROR",
       "errors": [
         { "field": "email", "message": "必須為合法的 Email 格式" },
         { "field": "age",   "message": "age 必須介於 0 到 150 之間" }
       ]
     }
     ```

4. **處理資料庫層的錯誤**：
   - 若 email 已存在（PostgreSQL error code `23505`），回傳 `409 Conflict`：
     ```json
     { "status": "error", "code": "EMAIL_EXISTS", "message": "此 Email 已被使用" }
     ```

5. **建立全域錯誤處理 middleware**（4 個參數 `(err, req, res, next)`）：
   - 捕捉所有未預期的錯誤，回傳 `500 Internal Server Error`：
     ```json
     { "status": "error", "code": "INTERNAL_ERROR", "message": "伺服器發生錯誤，請稍後再試" }
     ```
   - 在開發環境下（`NODE_ENV !== 'production'`）於 response 中附上 `stack` 欄位

6. **實作 `PUT /users/:id` 路由**：
   - 驗證 `:id` 必須為正整數
   - 重用 `validateUser` middleware 進行欄位驗證
   - 若使用者不存在，回傳 `404 Not Found`

## 提示

- 可用正則表達式驗證 email：`/^[^\s@]+@[^\s@]+\.[^\s@]+$/`
- 在 middleware 中收集「所有」驗證錯誤後再一次回傳，而非發現第一個就立刻中斷
- PostgreSQL 的 `err.code` 可直接判斷錯誤類型（`23505` = unique violation，`23502` = not null violation）
- 記得在 `app.js` 的最後才掛載全域錯誤 middleware，順序很重要

## 進階挑戰（選做）

- 引入 [joi](https://joi.dev/) 或 [zod](https://zod.dev/) 套件取代手寫驗證，感受兩者的差異
- 為每個請求加上唯一 `requestId`（可用 `crypto.randomUUID()`），並在錯誤回應中包含此 ID，方便 log 追蹤
- 撰寫一個 `asyncHandler` 高階函式，包裝非同步路由以自動將錯誤傳給 `next()`，消除重複的 `try/catch`
