# 第 15 週今日練習題：部落格 API 實戰專案（完整 CRUD + 驗證 + 分頁）

## 題目說明

建立一個具備完整功能的部落格後端 API，整合前幾週所學的所有技術：Express 路由設計、PostgreSQL 資料庫操作、JWT 身份驗證、資料驗證、分頁排序，以及錯誤處理。這是一個貼近真實產品的完整後端專案練習。

## 技術要求

- **Express.js**：模組化路由（`/api/auth`、`/api/posts`、`/api/comments`）、自訂 Middleware（驗證 JWT、錯誤統一處理）
- **PostgreSQL**：多資料表設計（`users`、`posts`、`comments`）、JOIN 查詢、交易處理
- **其他套件**：`jsonwebtoken`、`bcryptjs`、`joi`（資料驗證）、`express-validator` 或自訂驗證

## 資料庫結構

```sql
-- 使用者資料表
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(50) UNIQUE NOT NULL,
  email VARCHAR(100) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 文章資料表
CREATE TABLE posts (
  id SERIAL PRIMARY KEY,
  user_id INT REFERENCES users(id) ON DELETE CASCADE,
  title VARCHAR(200) NOT NULL,
  content TEXT NOT NULL,
  published BOOLEAN DEFAULT false,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- 留言資料表
CREATE TABLE comments (
  id SERIAL PRIMARY KEY,
  post_id INT REFERENCES posts(id) ON DELETE CASCADE,
  user_id INT REFERENCES users(id) ON DELETE CASCADE,
  content TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);
```

## 具體任務

1. **專案初始化**
   - 建立 Express 應用，使用 `dotenv` 管理環境變數（`DATABASE_URL`、`JWT_SECRET`）
   - 建立 `db.js` 統一管理 pg Pool 連線
   - 建立上述三個資料表的 migration 腳本（`npm run migrate`）

2. **身份驗證模組** (`/api/auth`)
   - `POST /api/auth/register`：註冊，使用 `bcryptjs` 雜湊密碼，回傳 JWT
   - `POST /api/auth/login`：登入，驗證密碼，回傳 JWT
   - 建立 `authMiddleware.js`：從 `Authorization: Bearer <token>` 解析並驗證 JWT，掛載 `req.user`

3. **文章 CRUD** (`/api/posts`)
   - `GET /api/posts`：取得所有**已發布**文章，支援分頁（`?page=1&limit=10`）與搜尋（`?q=關鍵字`），回應中包含作者 username（JOIN）
   - `GET /api/posts/:id`：取得單篇文章及其所有留言（JOIN），文章若為草稿只有作者本人可看
   - `POST /api/posts`：需登入，建立文章，驗證 `title`（不可空、最多 200 字）與 `content`（不可空）
   - `PUT /api/posts/:id`：需登入且為作者，更新文章，同步更新 `updated_at`
   - `DELETE /api/posts/:id`：需登入且為作者，刪除文章（CASCADE 會自動刪除留言）

4. **留言功能** (`/api/comments`)
   - `POST /api/posts/:postId/comments`：需登入，對已發布文章新增留言
   - `DELETE /api/comments/:id`：需登入且為留言作者，刪除留言

5. **統一錯誤處理**
   - 建立 `errorHandler.js` Middleware，捕捉所有未處理錯誤，回傳統一格式：
     ```json
     { "error": "錯誤描述", "code": "ERROR_CODE" }
     ```
   - 資源不存在回 404、未授權回 401、禁止操作回 403

## 提示

- 可用 `pg` 的 `Pool` 搭配交易（`BEGIN` / `COMMIT` / `ROLLBACK`）確保刪除等操作的資料一致性
- 分頁查詢使用 `LIMIT $1 OFFSET $2`，同時回傳 `total` 欄位讓前端知道總頁數
- 搜尋功能可用 `WHERE title ILIKE $1 OR content ILIKE $1`，`$1 = '%' + keyword + '%'`
- JWT 建議設定 `expiresIn: '7d'`，`authMiddleware` 應妥善處理 token 過期的錯誤訊息
- 建議專案結構：
  ```
  src/
  ├── routes/      (auth.js, posts.js, comments.js)
  ├── middleware/  (authMiddleware.js, errorHandler.js)
  ├── db.js
  └── app.js
  ```

## 進階挑戰（選做）

- **標籤功能**：新增 `tags` 資料表與 `post_tags` 關聯表，支援文章多標籤篩選（`?tag=nodejs`）
- **按讚功能**：新增 `POST /api/posts/:id/like`，記錄每位使用者的按讚（避免重複），文章列表回傳按讚數
- **圖片封面**：整合 `multer`，讓 `POST /api/posts` 支援上傳封面圖片，儲存路徑至資料庫
- **API 測試**：使用 `supertest` + `Jest` 為所有端點撰寫整合測試，測試前用交易確保資料庫乾淨
