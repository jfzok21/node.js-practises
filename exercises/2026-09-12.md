# 第 10 週今日練習題：銀行轉帳 API（Transaction 交易處理）

## 題目說明

建立一個模擬銀行轉帳功能的 REST API，使用 PostgreSQL 的交易（Transaction）機制確保資金轉移的原子性（Atomicity）。當轉帳過程中發生任何錯誤（如餘額不足、帳號不存在），必須自動 ROLLBACK，確保資料一致性。

## 技術要求

- **Express.js**：設計 `/transfer` POST 端點，接收 `from_account`、`to_account`、`amount`
- **PostgreSQL**：使用 `BEGIN` / `COMMIT` / `ROLLBACK` 手動控制交易；使用 `FOR UPDATE` 鎖定資料列防止競態條件（race condition）

## 具體任務

1. **建立資料庫結構**

   ```sql
   CREATE TABLE accounts (
     id SERIAL PRIMARY KEY,
     owner_name VARCHAR(100) NOT NULL,
     balance NUMERIC(12, 2) NOT NULL DEFAULT 0.00,
     CHECK (balance >= 0)
   );

   CREATE TABLE transfer_logs (
     id SERIAL PRIMARY KEY,
     from_account INT REFERENCES accounts(id),
     to_account INT REFERENCES accounts(id),
     amount NUMERIC(12, 2) NOT NULL,
     status VARCHAR(20) NOT NULL,  -- 'success' | 'failed'
     reason TEXT,
     created_at TIMESTAMP DEFAULT NOW()
   );
   ```

2. **插入測試資料**

   ```sql
   INSERT INTO accounts (owner_name, balance) VALUES
     ('Alice', 5000.00),
     ('Bob', 1000.00),
     ('Charlie', 200.00);
   ```

3. **實作轉帳端點 `POST /transfer`**

   請求 body：
   ```json
   { "from_account": 1, "to_account": 2, "amount": 500 }
   ```

   成功回應（HTTP 200）：
   ```json
   {
     "message": "轉帳成功",
     "transfer_id": 1,
     "from_balance": 4500.00,
     "to_balance": 1500.00
   }
   ```

   失敗回應（HTTP 400）：
   ```json
   { "error": "餘額不足" }
   ```

   交易流程：
   - `BEGIN`
   - 用 `SELECT ... FOR UPDATE` 鎖定 from/to 帳號列
   - 檢查 from 帳號是否存在、to 帳號是否存在
   - 檢查 from 帳號餘額是否 >= amount
   - 扣減 from 帳號餘額
   - 增加 to 帳號餘額
   - 寫入 `transfer_logs`（status: 'success'）
   - `COMMIT`
   - 若任何步驟失敗：`ROLLBACK`，寫入 `transfer_logs`（status: 'failed'）

4. **實作查詢端點 `GET /accounts/:id`**

   回傳帳號詳細資訊與最近 5 筆轉帳記錄。

5. **加入輸入驗證**

   - `amount` 必須為正數
   - `from_account` 與 `to_account` 不能相同
   - 缺少欄位時回傳 400

## 提示

- 使用 `pg` 套件的 `client.query('BEGIN')` 手動管理交易，而非 `pool.query()`，因為交易必須在同一個 connection 上執行
- 記得在 `catch` 區塊呼叫 `await client.query('ROLLBACK')` 後才 `release()` client
- PostgreSQL 的 `CHECK (balance >= 0)` 是最後一道防線，但程式碼層也應主動檢查
- `FOR UPDATE` 會對選取的列加上排他鎖，防止兩個同時進行的轉帳互相干擾

```javascript
const client = await pool.connect();
try {
  await client.query('BEGIN');
  // ... 執行轉帳邏輯
  await client.query('COMMIT');
} catch (err) {
  await client.query('ROLLBACK');
  throw err;
} finally {
  client.release();
}
```

## 進階挑戰（選做）

1. **批次轉帳**：實作 `POST /batch-transfer`，接收陣列形式的多筆轉帳，在同一個 Transaction 中全部完成，任一失敗則全部 ROLLBACK。

2. **冪等性（Idempotency）**：在請求 body 加入 `idempotency_key` 欄位，重複傳送相同 key 時直接回傳原始結果，不重複執行轉帳。

3. **Savepoint**：使用 PostgreSQL SAVEPOINT 在批次轉帳中允許部分成功、部分跳過，而非全部失敗。

4. **並發測試**：用 `Promise.all` 同時發送 100 筆相同帳號的轉帳請求，觀察 `FOR UPDATE` 如何防止餘額超支。
