# 第 11 週今日練習題：API 自動化測試

## 題目說明

為一個現有的 Express + PostgreSQL 使用者管理 API 撰寫完整的自動化測試套件。透過 **supertest** 發送 HTTP 請求、搭配 **Jest** 進行斷言，確保每支端點在正常與異常情況下皆回傳正確的狀態碼與 JSON 結構。

## 技術要求

- **Express.js**：建立一組 CRUD 路由（`/api/users`），供測試使用
- **PostgreSQL**：使用獨立測試資料庫（建議命名 `testdb`），測試前後自動清理資料
- **Jest**：作為測試執行器，設定 `--runInBand` 確保測試循序執行
- **supertest**：對 Express app 發送 HTTP 請求，不需啟動實際伺服器

## 具體任務

1. **建立 Express app**
   - `GET  /api/users`：回傳所有使用者陣列
   - `GET  /api/users/:id`：回傳單一使用者，找不到時回傳 404
   - `POST /api/users`：建立使用者（需 `name`、`email` 欄位），缺欄位時回傳 400
   - `PUT  /api/users/:id`：更新使用者，找不到時回傳 404
   - `DELETE /api/users/:id`：刪除使用者，找不到時回傳 404

2. **建立測試資料庫**
   ```sql
   CREATE DATABASE testdb;
   \c testdb
   CREATE TABLE users (
     id   SERIAL PRIMARY KEY,
     name TEXT NOT NULL,
     email TEXT UNIQUE NOT NULL
   );
   ```

3. **撰寫測試檔案 `tests/users.test.js`**，包含以下測試案例：
   - `GET /api/users` → 200，回傳陣列
   - `POST /api/users`（合法資料）→ 201，回傳新建使用者
   - `POST /api/users`（缺少欄位）→ 400，回傳錯誤訊息
   - `GET /api/users/:id`（存在）→ 200，回傳對應使用者
   - `GET /api/users/:id`（不存在）→ 404
   - `PUT /api/users/:id`（存在）→ 200，回傳更新後資料
   - `DELETE /api/users/:id`（存在）→ 200 或 204
   - `DELETE /api/users/:id`（不存在）→ 404

4. **設定測試生命週期**
   - `beforeAll`：建立資料庫連線
   - `beforeEach`：清空 `users` 資料表，插入固定測試資料
   - `afterAll`：關閉資料庫連線

5. **在 `package.json` 加入腳本**
   ```json
   "scripts": {
     "test": "jest --runInBand --forceExit"
   }
   ```

## 提示

- 將 Express app 與 `app.listen()` 分離：`app.js` 只匯出 `app`，`server.js` 負責監聽，這樣 supertest 可直接引用 `app` 而不需佔用 port
- 測試資料庫連線建議使用環境變數，例如 `DATABASE_URL=postgres://localhost/testdb`
- 使用 `TRUNCATE users RESTART IDENTITY CASCADE` 在每個測試前重置資料，確保 `id` 從 1 開始，測試結果可預測
- 善用 Jest 的 `expect(res.body).toMatchObject({...})` 進行部分欄位斷言，不必完全比對整個物件
- 若測試互相干擾，檢查是否有非同步操作沒有 `await`

## 進階挑戰（選做）

- 加入 **JWT 驗證**的整合測試：測試未帶 token 的請求是否回傳 401、帶有效 token 的請求是否正常回應
- 使用 **Jest coverage**（`jest --coverage`）檢查測試覆蓋率，目標達到 80% 以上的行覆蓋率
- 撰寫測試來驗證 `email` 欄位的唯一性：重複插入相同 email 時，API 應回傳 409 Conflict
- 使用 `jest.config.js` 設定全域 `globalSetup` / `globalTeardown`，負責測試開始前建立資料表、測試結束後刪除資料表
