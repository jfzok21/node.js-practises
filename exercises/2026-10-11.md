# 第 14 週今日練習題：書籍管理 REST API 實戰專案

## 題目說明

綜合運用前 13 週所學，建立一個完整的「書籍管理系統」REST API。此系統需支援使用者認證、書籍的完整 CRUD、分類管理、分頁查詢、檔案上傳（封面圖），以及完善的錯誤處理與測試，模擬真實後端開發工作流程。

---

## 技術要求

- **Express.js**：路由規劃、Middleware 組合（auth、validate、upload）、錯誤處理中介軟體
- **PostgreSQL**：多資料表設計（users、books、categories）、JOIN 查詢、Transaction、分頁排序
- **JWT**：使用者登入後核發 Token，受保護路由驗證 Bearer Token
- **multer**：書籍封面圖上傳（本地端 `uploads/` 目錄，限制 JPEG/PNG、2MB 以內）
- **supertest + Jest**：針對主要 API 端點撰寫整合測試

---

## 具體任務

### 1. 資料庫設計

建立以下三張資料表（含 `migrations/init.sql`）：

```sql
-- 使用者
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 書籍分類
CREATE TABLE categories (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) UNIQUE NOT NULL
);

-- 書籍
CREATE TABLE books (
  id SERIAL PRIMARY KEY,
  title VARCHAR(255) NOT NULL,
  author VARCHAR(255) NOT NULL,
  isbn VARCHAR(20) UNIQUE,
  cover_url TEXT,
  published_year INT CHECK (published_year BETWEEN 1000 AND 2100),
  category_id INT REFERENCES categories(id) ON DELETE SET NULL,
  user_id INT REFERENCES users(id) ON DELETE CASCADE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 2. 認證端點

| 方法 | 路徑 | 說明 |
|------|------|------|
| POST | `/api/auth/register` | 註冊（email + password），密碼以 bcrypt 雜湊 |
| POST | `/api/auth/login` | 登入，回傳 `{ token, expiresIn }` |

### 3. 書籍 CRUD（需 JWT 驗證）

| 方法 | 路徑 | 說明 |
|------|------|------|
| GET | `/api/books` | 列表（支援 `?page=&limit=&search=&category_id=&sort=title\|year&order=asc\|desc`） |
| GET | `/api/books/:id` | 取得單本（含分類名稱，用 JOIN） |
| POST | `/api/books` | 新增（body 驗證：title、author 為必填） |
| PUT | `/api/books/:id` | 修改（只有建立者可操作） |
| DELETE | `/api/books/:id` | 刪除（只有建立者可操作，使用 Transaction） |
| POST | `/api/books/:id/cover` | 上傳封面圖（multipart/form-data） |

### 4. 分類 CRUD（需 JWT 驗證）

| 方法 | 路徑 | 說明 |
|------|------|------|
| GET | `/api/categories` | 列出所有分類 |
| POST | `/api/categories` | 新增分類 |
| DELETE | `/api/categories/:id` | 刪除分類（若有書籍使用，回傳 409 衝突錯誤） |

### 5. 統一錯誤格式

所有錯誤回應需符合以下格式：

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "title is required"
  }
}
```

### 6. 整合測試（`tests/books.test.js`）

使用 supertest + Jest 撰寫：
- 未帶 Token → 401
- 新增書籍成功 → 201 且 body 包含 `id`
- 搜尋書籍（`?search=`）→ 結果陣列且每筆含 `category_name`
- 非建立者刪除 → 403

---

## 提示

- 用 `express-validator` 或手動驗證 body；錯誤集中在錯誤處理 middleware 回傳
- JWT secret 存於 `.env`，以 `dotenv` 載入，**不可 commit `.env`**
- 刪除書籍時，在 Transaction 中先刪除封面檔案（`fs.unlink`）再刪除資料庫記錄，任一失敗均 rollback
- 分頁公式：`LIMIT $1 OFFSET $2`，其中 `offset = (page - 1) * limit`
- multer 的 `fileFilter` 拒絕非圖片時，拋出自訂錯誤物件而非靜默忽略

---

## 進階挑戰（選做）

1. **Rate Limiting**：使用 `express-rate-limit` 限制 `/api/auth/login` 每分鐘最多 5 次
2. **Soft Delete**：books 表加 `deleted_at` 欄位，刪除時改為更新而非真刪，查詢時過濾掉已刪除
3. **書籍匯出**：`GET /api/books/export?format=csv` 將書單以 CSV 格式串流下載
4. **OpenAPI 文件**：用 `swagger-jsdoc` + `swagger-ui-express` 自動產生 `/api/docs` 頁面
