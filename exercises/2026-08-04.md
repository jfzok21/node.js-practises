# 第 4 週今日練習題：Express Middleware 實戰

## 題目說明

本週的核心是 Express Middleware（中介軟體）。Middleware 是 Express 的靈魂——每一個進來的 Request 都要穿越一連串的中介函式，才能到達最終的路由處理器。你將親手打造自訂 Middleware，並整合常用的第三方 Middleware，讓 API 更健壯。

## 技術要求

- **Express.js**：`app.use()`、`next()`、自訂 middleware、全域與區域 middleware、錯誤處理 middleware
- **PostgreSQL**：配合 middleware 記錄請求日誌至資料庫（進階），或使用 `pg` 連線進行基本查詢

## 具體任務

1. **建立 Logger Middleware**
   - 在每個請求進來時，於終端機印出：`[2026-08-04 12:34:56] GET /api/users 200`（含時間戳、HTTP 方法、路徑、回應狀態碼）
   - 將此 middleware 套用為全域（所有路由都會觸發）

2. **整合 body-parser**
   - 使用 `express.json()` 與 `express.urlencoded({ extended: true })` 處理請求主體
   - 建立一個 `POST /api/echo` 路由，將接收到的 JSON body 原封不動回傳

3. **建立身份驗證 Middleware（區域套用）**
   - 建立 `authMiddleware`：讀取 Request Header 中的 `x-api-key`
   - 若 key 等於 `secret-key-2026`，呼叫 `next()` 繼續處理
   - 若 key 不存在或錯誤，回傳 `401 Unauthorized` 與 JSON 錯誤訊息
   - 僅將此 middleware 套用在 `GET /api/protected` 這個路由上

4. **建立全域錯誤處理 Middleware**
   - Express 的錯誤 middleware 有四個參數：`(err, req, res, next)`
   - 當任何路由呼叫 `next(err)` 時，此 middleware 應回傳：
     ```json
     { "error": true, "message": "...", "statusCode": 500 }
     ```
   - 建立 `GET /api/crash` 路由，故意拋出 `new Error('伺服器爆炸了！')` 並傳給 `next(err)`，確認錯誤 middleware 能捕捉

5. **Middleware 執行順序驗證**
   - 在 `app.use()` 中加入三個簡單的 middleware（M1、M2、M3），每個都在終端機印出自己的名稱後呼叫 `next()`
   - 確認終端機依序印出 `M1 → M2 → M3`，理解 middleware 的執行順序

## 提示

- `app.use(middleware)` 會套用到所有路由；`router.get('/path', middleware, handler)` 只套用到特定路由
- 錯誤 middleware **必須放在所有路由的最後面**，否則無法捕捉錯誤
- 在 middleware 中，若不呼叫 `next()`，請求會被「卡住」——記得在每個分支都處理
- 區分 `next()` 與 `next(err)`：前者進入下一個一般 middleware，後者跳到錯誤 middleware
- 使用 `res.locals` 在 middleware 之間共享資料（例如，在 logger middleware 記錄開始時間，在回應後計算耗時）

## 進階挑戰（選做）

**A. 請求限流（Rate Limiting）**
手動實作一個簡單的 Rate Limiter Middleware：
- 使用 `Map` 儲存每個 IP 的請求次數與時間窗口
- 每個 IP 每分鐘最多允許 10 次請求
- 超過限制回傳 `429 Too Many Requests`

**B. 將日誌寫入 PostgreSQL**
修改 Logger Middleware，將每筆請求日誌（方法、路徑、狀態碼、耗時毫秒、時間戳）存入 `request_logs` 資料表：
```sql
CREATE TABLE request_logs (
  id SERIAL PRIMARY KEY,
  method VARCHAR(10),
  path TEXT,
  status_code INT,
  duration_ms INT,
  created_at TIMESTAMP DEFAULT NOW()
);
```
另建 `GET /api/logs` 路由查詢最近 20 筆日誌記錄。

**C. 條件式 Middleware**
建立一個 middleware，根據請求的 `Content-Type` header 決定如何解析 body：
- `application/json` → 用 `express.json()` 解析
- `application/x-www-form-urlencoded` → 用 `express.urlencoded()` 解析
- 其他 → 回傳 `415 Unsupported Media Type`
