# 第 17 週今日練習題：任務管理 API 實戰專案

## 題目說明

建立一個具備完整功能的「任務管理系統」REST API，整合 Express.js 與 PostgreSQL，涵蓋多資料表關聯、身份驗證、分頁查詢、資料驗證與交易處理等核心技術。

## 技術要求
- **Express.js**：路由拆分（Router）、中介軟體管道、錯誤處理中介軟體、JWT 身份驗證
- **PostgreSQL**：多資料表設計（users / projects / tasks）、JOIN 查詢、Transaction、索引優化
- **其他套件**：`bcryptjs`（密碼雜湊）、`jsonwebtoken`、`joi` 或 `express-validator`（資料驗證）、`pg`（資料庫連線池）

## 具體任務

### 資料庫設計
1. 建立以下三張資料表：
   - `users`：`id`、`email`（UNIQUE）、`password_hash`、`name`、`created_at`
   - `projects`：`id`、`owner_id`（FK → users）、`name`、`description`、`created_at`
   - `tasks`：`id`、`project_id`（FK → projects）、`assignee_id`（FK → users，可為 NULL）、`title`、`description`、`status`（'todo' / 'in_progress' / 'done'）、`due_date`、`created_at`

### 身份驗證端點
2. `POST /api/auth/register` — 使用者註冊（驗證 email 格式、密碼長度至少 8 碼，密碼以 bcrypt 雜湊後儲存）
3. `POST /api/auth/login` — 登入，回傳 JWT token（有效期 24 小時）

### 專案管理端點（需 JWT）
4. `GET /api/projects` — 列出目前使用者擁有的所有專案（含每個專案的任務數量統計）
5. `POST /api/projects` — 建立新專案
6. `DELETE /api/projects/:id` — 刪除專案，**使用 Transaction** 同時刪除該專案底下所有任務

### 任務管理端點（需 JWT）
7. `GET /api/projects/:projectId/tasks` — 列出專案任務，支援：
   - `?status=todo|in_progress|done` 篩選
   - `?page=1&limit=10` 分頁
   - `?sort=due_date&order=asc` 排序
8. `POST /api/projects/:projectId/tasks` — 新增任務（驗證 due_date 格式、status 枚舉值）
9. `PATCH /api/tasks/:id` — 更新任務狀態或指派人（使用者只能修改自己專案的任務）
10. `GET /api/tasks/summary` — 回傳目前使用者所有任務的統計摘要：各 status 的數量

## 提示
- 使用 `pg.Pool` 管理資料庫連線，避免每次請求都建立新連線
- JWT middleware 從 `Authorization: Bearer <token>` header 取得 token，驗證失敗回傳 `401 Unauthorized`
- 刪除專案時先刪 `tasks`、再刪 `project`，整個操作包在同一個 Transaction 內
- 分頁查詢同時回傳 `total`（總筆數）與 `data`（當頁資料），方便前端計算總頁數
- 資料驗證失敗一律回傳 `400 Bad Request` 並附上欄位說明，例如：
  ```json
  { "error": "Validation failed", "details": ["email must be a valid email"] }
  ```
- 路由依資源拆成獨立檔案：`routes/auth.js`、`routes/projects.js`、`routes/tasks.js`

## 進階挑戰（選做）

1. **軟刪除**：為 `tasks` 加上 `deleted_at` 欄位，`DELETE /api/tasks/:id` 改為設定時間戳而非真正刪除，所有查詢自動過濾 `deleted_at IS NULL`
2. **角色權限**：在 `projects` 建立 `project_members` 關聯表，支援邀請成員，並讓被邀請的成員也能操作該專案的任務
3. **活動紀錄**：每次任務狀態變更時，以 Transaction 同時寫入 `task_activity_logs` 資料表，記錄誰在何時做了什麼變更
4. **Supertest 整合測試**：對身份驗證及任務 CRUD 端點撰寫完整的 Jest + Supertest 測試，使用獨立測試資料庫並在每個測試套件前後清空資料
