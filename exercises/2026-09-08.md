# 第 9 週今日練習題：分頁與排序 API

## 題目說明

建立一個支援分頁（Pagination）與排序（Sorting）功能的 RESTful API。
實際應用中，資料表可能有數萬筆資料，不可能一次回傳全部，必須搭配分頁與排序才能高效使用。
本題將練習透過查詢字串參數控制資料回傳的筆數、頁碼與排序方式。

## 技術要求

- **Express.js**：設計支援查詢字串（`?page=`、`?limit=`、`?sort=`、`?order=`）的路由
- **PostgreSQL**：使用 `LIMIT`、`OFFSET`、`ORDER BY` 語法進行分頁與排序查詢

## 具體任務

1. **建立資料表**
   建立一張 `products`（商品）資料表，欄位如下：
   ```sql
   CREATE TABLE products (
     id SERIAL PRIMARY KEY,
     name VARCHAR(100) NOT NULL,
     price NUMERIC(10, 2) NOT NULL,
     category VARCHAR(50),
     created_at TIMESTAMP DEFAULT NOW()
   );
   ```
   並插入至少 30 筆測試資料（可用迴圈或 `generate_series`）。

2. **實作分頁 API**
   建立路由 `GET /api/products`，支援以下查詢字串：
   - `page`（頁碼，預設為 1）
   - `limit`（每頁筆數，預設為 10，最大不超過 100）
   - `sort`（排序欄位，允許：`id`、`name`、`price`、`created_at`，預設 `id`）
   - `order`（排序方向：`asc` 或 `desc`，預設 `asc`）

3. **回傳格式**
   回應 JSON 結構需包含分頁資訊：
   ```json
   {
     "data": [...],
     "pagination": {
       "total": 30,
       "page": 1,
       "limit": 10,
       "totalPages": 3,
       "hasNext": true,
       "hasPrev": false
     }
   }
   ```

4. **參數驗證**
   - `page` 與 `limit` 必須為正整數，若非數字則回傳 400 錯誤
   - `sort` 只允許白名單欄位（防止 SQL Injection）
   - `order` 只允許 `asc` 或 `desc`

5. **計算 OFFSET**
   公式：`OFFSET = (page - 1) * limit`

## 提示

- 使用白名單驗證 `sort` 欄位（`const ALLOWED_SORT = ['id', 'name', 'price', 'created_at']`），**不可直接將使用者輸入拼入 SQL**
- 需執行兩個查詢：一個取資料（帶 LIMIT/OFFSET），另一個用 `COUNT(*)` 取總筆數
- 可用 `Promise.all([...])` 同時執行兩個查詢以提升效能
- `parseInt()` 後記得用 `isNaN()` 驗證

```javascript
// 範例 OFFSET 計算
const page = Math.max(1, parseInt(req.query.page) || 1);
const limit = Math.min(100, Math.max(1, parseInt(req.query.limit) || 10));
const offset = (page - 1) * limit;

// 範例白名單排序
const ALLOWED_SORT = ['id', 'name', 'price', 'created_at'];
const sort = ALLOWED_SORT.includes(req.query.sort) ? req.query.sort : 'id';
const order = req.query.order === 'desc' ? 'DESC' : 'ASC';

// 查詢（注意：欄位名稱用白名單，不可參數化；數值用 $1/$2）
const sql = `SELECT * FROM products ORDER BY ${sort} ${order} LIMIT $1 OFFSET $2`;
```

## 進階挑戰（選做）

1. **加入關鍵字搜尋**：支援 `?search=關鍵字`，對 `name` 和 `category` 欄位做模糊搜尋（`ILIKE`），並與分頁結合。

2. **Cursor-based Pagination**：改用 Cursor 分頁（`?cursor=<last_id>`）取代 OFFSET，比較兩種方式的效能差異。

3. **多欄位排序**：支援 `?sort=price,created_at&order=asc,desc`，依多個欄位排序。

4. **加入 Link Header**：在 HTTP Response Header 加入 `Link` 標頭，遵循 GitHub API 的分頁慣例：
   ```
   Link: <URL?page=2>; rel="next", <URL?page=3>; rel="last"
   ```
