# 第 11 週今日練習題：用 Supertest + Jest 測試 Express API

## 題目說明

學習如何為 Express.js API 撰寫自動化測試，透過 `supertest` 模擬 HTTP 請求，搭配 `Jest` 作為測試框架，驗證路由行為、狀態碼、回傳資料結構，以及資料庫互動的正確性。

---

## 技術要求

- **Express.js**：建立一組簡單的 RESTful API（書籍管理），供測試目標使用
- **PostgreSQL**：資料庫使用獨立的測試資料庫（`test` 環境），每次測試前重置資料
- **Jest**：測試框架，使用 `describe` / `it` / `expect` 組織測試案例
- **Supertest**：在測試中直接發送 HTTP 請求，不需啟動真實伺服器

---

## 具體任務

### 1. 建立書籍 API

在 `src/app.js` 中建立以下端點（不含驗證邏輯，保持簡單）：

| 方法   | 路徑            | 功能         |
|--------|-----------------|--------------|
| GET    | `/books`        | 取得所有書籍 |
| GET    | `/books/:id`    | 取得單本書籍 |
| POST   | `/books`        | 新增書籍     |
| PUT    | `/books/:id`    | 更新書籍     |
| DELETE | `/books/:id`    | 刪除書籍     |

書籍欄位：`id`、`title`（書名）、`author`（作者）、`year`（出版年份）

### 2. 設定測試環境

- 建立 `.env.test`，設定 `DATABASE_URL` 指向測試用資料庫（例如 `books_test`）
- 在 `jest.config.js` 設定 `testEnvironment: 'node'` 並自動載入 `.env.test`
- 建立 `src/db.js` 做為資料庫連線模組，根據 `NODE_ENV` 切換資料庫

### 3. 撰寫測試（`tests/books.test.js`）

實作以下測試案例：

**GET /books**
- 回傳狀態碼 `200` 及陣列格式的書籍清單

**GET /books/:id**
- 存在的 id → 回傳 `200` 及書籍物件
- 不存在的 id → 回傳 `404`

**POST /books**
- 傳入有效資料 → 回傳 `201` 及新增的書籍（含 `id`）
- 缺少必填欄位（`title`）→ 回傳 `400`

**PUT /books/:id**
- 更新成功 → 回傳 `200` 及更新後的書籍
- 不存在的 id → 回傳 `404`

**DELETE /books/:id**
- 刪除成功 → 回傳 `204`
- 不存在的 id → 回傳 `404`

### 4. 資料隔離

- 使用 `beforeEach` 在每個測試前清空 `books` 資料表並插入固定測試資料
- 使用 `afterAll` 在所有測試結束後關閉資料庫連線

---

## 提示

- `supertest` 的使用方式：
  ```js
  const request = require('supertest');
  const app = require('../src/app');
  
  it('GET /books 回傳 200', async () => {
    const res = await request(app).get('/books');
    expect(res.status).toBe(200);
    expect(Array.isArray(res.body)).toBe(true);
  });
  ```
- `app.js` 不要呼叫 `app.listen()`，把 listen 放在獨立的 `server.js`，這樣 supertest 才能直接 import app
- 測試資料庫應與開發資料庫分開，避免測試汙染真實資料
- 可使用 `cross-env` 套件讓 `NODE_ENV=test` 在各平台都能正確設定：
  ```json
  "test": "cross-env NODE_ENV=test jest --forceExit"
  ```
- `expect(res.body).toMatchObject({ title: '...' })` 比 `toEqual` 更寬鬆，適合只驗證部分欄位

## 進階挑戰（選做）

1. **測試覆蓋率**：執行 `jest --coverage`，嘗試讓覆蓋率達到 80% 以上
2. **測試 middleware**：為某個路由加入 API Key 驗證 middleware，並撰寫測試驗證「有效 key 通過、無效 key 回傳 401」
3. **整合 CI**：建立 GitHub Actions workflow，在每次 push 時自動執行測試（使用 PostgreSQL service container）
4. **測試工廠函式**：建立 `createBook(overrides)` 工廠函式，減少測試中的重複資料建立邏輯
5. **快照測試**：使用 `expect(res.body).toMatchSnapshot()` 對回傳結構做快照比對
