# 第 8 週今日練習題：檔案上傳 API（multer）

## 題目說明

建立一個支援單檔與多檔上傳的 Express API，並將上傳記錄（檔名、大小、MIME 類型、上傳時間）儲存至 PostgreSQL。實作完整的檔案管理端點，包含上傳、列表、刪除功能。

## 技術要求

- **Express.js**：使用 `multer` middleware 處理 `multipart/form-data` 請求；限制檔案大小與允許的 MIME 類型；正確回傳 422/400 錯誤給不合法的檔案
- **PostgreSQL**：建立 `uploads` 資料表儲存上傳記錄；使用參數化查詢防止 SQL 注入

## 具體任務

1. **建立資料表**
   ```sql
   CREATE TABLE uploads (
     id        SERIAL PRIMARY KEY,
     filename  TEXT NOT NULL,
     original_name TEXT NOT NULL,
     mime_type TEXT NOT NULL,
     size_bytes INTEGER NOT NULL,
     uploaded_at TIMESTAMPTZ DEFAULT NOW()
   );
   ```

2. **設定 multer**
   - 儲存目錄：`uploads/`（不存在時自動建立）
   - 允許類型：`image/jpeg`、`image/png`、`application/pdf`
   - 單一檔案大小上限：5 MB
   - 單次多檔上傳上限：5 個檔案

3. **實作以下端點**

   | 方法 | 路徑 | 說明 |
   |------|------|------|
   | `POST` | `/upload` | 上傳單一檔案，回傳檔案 id 與 URL |
   | `POST` | `/upload/multiple` | 上傳最多 5 個檔案，回傳陣列 |
   | `GET` | `/files` | 列出所有上傳記錄（含分頁：`?page=1&limit=10`） |
   | `GET` | `/files/:id` | 取得單一記錄的詳細資訊 |
   | `DELETE` | `/files/:id` | 刪除 DB 記錄並移除磁碟檔案 |

4. **錯誤處理**
   - 檔案類型不符：回傳 `422 Unprocessable Entity`
   - 超過大小限制：回傳 `413 Payload Too Large`
   - 找不到檔案：回傳 `404 Not Found`
   - multer 錯誤需統一由 error middleware 攔截

5. **上傳成功回應格式**
   ```json
   {
     "id": 1,
     "filename": "1234567890-photo.jpg",
     "originalName": "photo.jpg",
     "mimeType": "image/jpeg",
     "sizeBytes": 204800,
     "uploadedAt": "2026-09-01T08:00:00.000Z"
   }
   ```

## 提示

- `multer.diskStorage` 的 `filename` callback 可用 `Date.now() + '-' + file.originalname` 避免命名衝突
- `fileFilter` callback 呼叫 `cb(new Error('...'), false)` 即可拒絕檔案
- 刪除磁碟檔案使用 Node.js 內建 `fs.promises.unlink(filepath)`
- 在 `multer` error middleware 中用 `err instanceof multer.MulterError` 判斷是否為 multer 拋出的錯誤
- `pg` 連線建議使用 `Pool`，並從環境變數讀取 `DATABASE_URL`

## 進階挑戰（選做）

- 在上傳影像時，使用 `sharp` 套件自動產生 150×150 的縮圖，並將縮圖路徑也寫入 DB
- 為 `GET /files` 加入依 `mime_type` 篩選的查詢字串（`?type=image/png`）
- 記錄每個檔案的下載次數，`GET /files/:id/download` 每次請求時自增 `download_count` 並回傳串流
