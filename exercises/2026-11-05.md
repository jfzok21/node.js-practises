# 第 18 週今日練習題：任務管理 REST API（實戰專案）

## 題目說明

建立一個完整的任務管理系統後端 API，整合前幾週所學的所有技術：路由、CRUD、Middleware、JOIN 查詢、資料驗證、JWT 身份驗證、分頁與排序，以及交易處理。這是一個模擬真實工作場景的綜合練習。

---

## 技術要求

- **Express.js**：RESTful 路由設計、Middleware 組合、錯誤處理中介層
- **PostgreSQL**：多資料表設計、JOIN 查詢、Transaction、索引優化
- **驗證**：JWT 保護私有路由、請求資料驗證
- **其他**：分頁、排序、錯誤回應規範化

---

## 資料庫結構

請建立以下三張資料表：

```sql
-- 使用者
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(50) UNIQUE NOT NULL,
  email VARCHAR(100) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 專案
CREATE TABLE projects (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  description TEXT,
  owner_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 任務
CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  title VARCHAR(200) NOT NULL,
  description TEXT,
  status VARCHAR(20) DEFAULT 'todo' CHECK (status IN ('todo', 'in_progress', 'done')),
  priority INTEGER DEFAULT 1 CHECK (priority BETWEEN 1 AND 5),
  project_id INTEGER REFERENCES projects(id) ON DELETE CASCADE,
  assignee_id INTEGER REFERENCES users(id) ON DELETE SET NULL,
  due_date DATE,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

## 具體任務

### 1. 身份驗證模組

實作以下端點（無需 JWT）：

```
POST /api/auth/register   - 註冊新使用者（儲存 bcrypt hash 密碼）
POST /api/auth/login      - 登入，回傳 JWT token
```

登入成功回傳範例：
```json
{
  "token": "eyJhbGci...",
  "user": { "id": 1, "username": "alice", "email": "alice@example.com" }
}
```

### 2. 專案管理端點（需 JWT）

```
GET    /api/projects          - 列出目前使用者擁有的所有專案
POST   /api/projects          - 建立新專案
GET    /api/projects/:id      - 取得單一專案詳情（含任務統計）
PATCH  /api/projects/:id      - 更新專案名稱 / 描述
DELETE /api/projects/:id      - 刪除專案（CASCADE 刪除相關任務）
```

GET `/api/projects/:id` 回傳範例（含任務統計）：
```json
{
  "id": 1,
  "name": "網站重構",
  "description": "...",
  "task_counts": {
    "todo": 5,
    "in_progress": 2,
    "done": 10
  }
}
```

### 3. 任務管理端點（需 JWT）

```
GET    /api/projects/:projectId/tasks   - 列出專案任務（支援分頁、排序、狀態篩選）
POST   /api/projects/:projectId/tasks   - 建立任務
GET    /api/tasks/:id                   - 取得單一任務（JOIN 顯示 assignee 名稱）
PATCH  /api/tasks/:id                   - 更新任務（狀態、優先級、指派人）
DELETE /api/tasks/:id                   - 刪除任務
```

GET `/api/projects/:projectId/tasks` 支援查詢字串：
- `?page=1&limit=10`（預設 page=1, limit=10）
- `?sort=priority&order=desc`（可排序欄位：priority, due_date, created_at）
- `?status=todo`（篩選狀態）

回傳格式：
```json
{
  "data": [ ... ],
  "pagination": {
    "page": 1,
    "limit": 10,
    "total": 42,
    "total_pages": 5
  }
}
```

### 4. 批次更新端點（Transaction）

```
POST /api/projects/:projectId/tasks/batch-update
```

請求 body：
```json
{
  "task_ids": [1, 2, 3],
  "status": "in_progress"
}
```

使用 PostgreSQL Transaction 確保所有任務同時更新，任一失敗則全部回滾。

### 5. Middleware 要求

- **authMiddleware**：驗證 JWT，將 `req.user` 注入後續路由
- **ownerMiddleware**：確認操作者是專案擁有者，否則回傳 403
- **validateMiddleware**：統一資料驗證，缺少必填欄位或格式錯誤時回傳 400
- **errorHandler**：全域錯誤處理，統一回傳格式：
  ```json
  { "error": "錯誤訊息", "code": "ERROR_CODE" }
  ```

## 提示

- 使用 `bcryptjs` 處理密碼雜湊，salt rounds 建議設 10
- JWT secret 存放於 `.env`，使用 `dotenv` 讀取
- 分頁查詢使用 `LIMIT $1 OFFSET $2`，total 用 `COUNT(*) OVER()` 或獨立 COUNT 查詢
- Task 統計可使用 `GROUP BY` + `COUNT(CASE WHEN status = 'todo' THEN 1 END)` 技巧
- 批次更新 Transaction 範例：
  ```javascript
  const client = await pool.connect();
  try {
    await client.query('BEGIN');
    // ... 多個 UPDATE
    await client.query('COMMIT');
  } catch (err) {
    await client.query('ROLLBACK');
    throw err;
  } finally {
    client.release();
  }
  ```
- 建議目錄結構：
  ```
  src/
    routes/     auth.js  projects.js  tasks.js
    middleware/ auth.js  owner.js  validate.js  errorHandler.js
    db/         pool.js  queries/
  ```

## 進階挑戰（選做）

1. **軟刪除**：tasks 加入 `deleted_at` 欄位，DELETE 改為設定 `deleted_at` 而非真正刪除，所有查詢加上 `WHERE deleted_at IS NULL`
2. **活動日誌**：建立 `task_logs` 資料表，每次任務狀態變更時記錄 `(task_id, old_status, new_status, changed_by, changed_at)`，使用 Trigger 或應用層實作
3. **整合測試**：用 Jest + Supertest 為 auth 和 tasks 端點撰寫至少 10 個測試案例，使用獨立測試資料庫
4. **Rate Limiting**：加入 `express-rate-limit`，限制登入端點每 IP 每分鐘最多 5 次請求
