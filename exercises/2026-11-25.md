# 第 21 週今日練習題：即時通知系統 API

## 題目說明

實作一個具備即時通知功能的後端 API。使用者可以訂閱特定類別的通知，系統會將新通知推播給對應的訂閱者，並支援通知已讀狀態管理與歷史查詢。

## 技術要求

- **Express.js**：RESTful API 設計，使用 Server-Sent Events（SSE）推播即時通知
- **PostgreSQL**：多表關聯設計，含 users、notifications、subscriptions、notification_reads 資料表

## 具體任務

1. **設計資料庫 Schema**
   - `users`：id、username、email、created_at
   - `notifications`：id、category、title、body、created_at
   - `subscriptions`：id、user_id、category、created_at
   - `notification_reads`：id、user_id、notification_id、read_at

2. **實作基本 CRUD API**
   - `POST /users` — 建立使用者
   - `POST /users/:userId/subscriptions` — 訂閱指定類別
   - `DELETE /users/:userId/subscriptions/:category` — 取消訂閱
   - `POST /notifications` — 建立新通知（指定 category）

3. **實作通知查詢 API**
   - `GET /users/:userId/notifications?page=1&limit=20` — 取得該使用者已訂閱類別的通知，支援分頁
   - `GET /users/:userId/notifications/unread-count` — 取得未讀通知數量
   - `PATCH /users/:userId/notifications/:notificationId/read` — 標記單一通知為已讀
   - `PATCH /users/:userId/notifications/read-all` — 標記所有通知為已讀

4. **實作 SSE 即時推播**
   - `GET /users/:userId/events` — 建立 SSE 連線；當該使用者訂閱的類別有新通知時，立即推播

5. **整合測試**
   - 使用 `supertest` 撰寫至少 5 個測試案例，涵蓋訂閱、建立通知、查詢未讀數

## 提示

- SSE 連線需設定 headers：`Content-Type: text/event-stream`、`Cache-Control: no-cache`、`Connection: keep-alive`
- 在 Node.js 中可用 `Map` 儲存活躍的 SSE 連線（`userId -> res`），當 `POST /notifications` 被呼叫時，查出訂閱者並逐一推播
- 分頁查詢可搭配 `LIMIT` / `OFFSET`，注意也要回傳 `total` 筆數
- `notification_reads` 使用 `INSERT ... ON CONFLICT DO NOTHING` 避免重複已讀記錄
- 建議使用 `pg` 套件的 connection pool（`Pool`），避免 SSE 長連線佔用過多資料庫連線

## 進階挑戰（選做）

- **多裝置支援**：同一個 `userId` 可同時有多個 SSE 連線（Map value 改為 `Set<res>`）
- **通知過期**：在 `notifications` 加入 `expires_at` 欄位，查詢時自動過濾過期通知
- **速率限制**：對 `POST /notifications` 加入速率限制（每分鐘最多 60 次），避免濫發
- **Redis Pub/Sub**：若有多個 Node.js 實例，改用 Redis Pub/Sub 廣播通知，解決跨實例問題
