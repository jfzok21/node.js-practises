# 第 17 週今日練習題：部落格 API 實戰專案（完整 CRUD + 認證）

## 題目說明

建立一個具備完整功能的部落格後端 API，整合前幾週所學的所有技術：Express 路由、PostgreSQL 資料庫操作、JWT 身份驗證、資料驗證、分頁查詢，以及錯誤處理。這是一個模擬真實生產環境的全功能專案。

## 技術要求

- **Express.js**：模組化路由設計（`/api/auth`、`/api/posts`、`/api/comments`）、全域錯誤處理 Middleware
- **PostgreSQL**：多資料表（users、posts、comments）、JOIN 查詢、Transaction
- **身份驗證**：JWT（登入 / 註冊 / 受保護路由）
- **資料驗證**：輸入欄位驗證（非空、長度限制、email 格式）
- **分頁 / 排序**：文章列表支援 `?page=` 與 `?sort=` 查詢字串

## 具體任務

1. **資料庫初始化**
   - 建立 `users` 資料表（id、username、email、password_hash、created_at）
   - 建立 `posts` 資料表（id、title、content、author_id、created_at、updated_at）
   - 建立 `comments` 資料表（id、post_id、author_id、content、created_at）
   - 設定外鍵約束（posts.author_id → users.id、comments.post_id → posts.id）

2. **身份驗證 API**
   - `POST /api/auth/register`：註冊（bcrypt 雜湊密碼，回傳 JWT）
   - `POST /api/auth/login`：登入（驗證密碼，回傳 JWT）
   - 撰寫 `authMiddleware`，驗證 Authorization header 中的 Bearer Token

3. **文章 CRUD API（需登入）**
   - `GET /api/posts`：取得文章列表（JOIN users 取得作者名稱，支援分頁 `?page=1&limit=10`，支援 `?sort=newest|oldest`）
   - `GET /api/posts/:id`：取得單篇文章（含留言數量）
   - `POST /api/posts`：新增文章（驗證 title、content 不為空）
   - `PUT /api/posts/:id`：更新文章（只允許作者本人修改）
   - `DELETE /api/posts/:id`：刪除文章（使用 Transaction 同時刪除相關留言）

4. **留言 API（需登入）**
   - `POST /api/posts/:postId/comments`：新增留言
   - `DELETE /api/comments/:id`：刪除留言（只允許作者本人）

5. **錯誤處理**
   - 統一錯誤格式：`{ "error": "錯誤訊息" }`
   - 處理 404（路由不存在）、401（未授權）、403（無權限）、422（驗證失敗）

## 提示

- 專案結構建議：
  ```
  src/
  ├── routes/
  │   ├── auth.js
  │   ├── posts.js
  │   └── comments.js
  ├── middleware/
  │   ├── auth.js       ← JWT 驗證
  │   └── errorHandler.js
  ├── db.js             ← PostgreSQL 連線池
  └── app.js
  ```
- 使用 `pg` 套件的 `Pool` 管理資料庫連線
- JWT 請使用 `jsonwebtoken` 套件，密鑰存於環境變數 `JWT_SECRET`
- 密碼雜湊使用 `bcryptjs`，cost factor 設為 10
- 分頁計算：`OFFSET = (page - 1) * limit`，回應需包含 `total`、`page`、`totalPages`

## 進階挑戰（選做）

- 加入文章標籤（tags）功能：多對多關聯（posts ↔ tags，透過 post_tags 中間表）
- 支援文章搜尋 `?search=關鍵字`（使用 PostgreSQL `ILIKE`）
- 加入 `GET /api/users/:id/posts` 取得某位作者的所有文章
- 為所有 API 撰寫 Supertest + Jest 測試，覆蓋正常流程與錯誤情境
