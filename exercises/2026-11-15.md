# 第 19 週今日練習題：電商購物車與訂單 API

## 題目說明

實作一個電商後端 REST API，支援商品管理、購物車操作、訂單建立與庫存控管。重點在於利用 PostgreSQL Transaction 保證庫存扣減的原子性，並模擬真實電商系統中「結帳時庫存不足」的錯誤處理流程。此練習整合 JWT 身份驗證、樂觀鎖（Optimistic Lock）、Transaction，以及分頁查詢。

## 技術要求

- **Express.js**：模組化架構（`routes/`、`controllers/`、`services/`），關注點分離
- **PostgreSQL**：多資料表（users、products、cart_items、orders、order_items），複雜 JOIN 與聚合
- **JWT**：登入後取得 token，受保護端點需驗證
- **Transaction + 樂觀鎖**：結帳時需在單一 Transaction 中驗證庫存、扣減庫存、建立訂單
- **分頁**：商品列表使用 OFFSET 分頁；訂單歷史使用 Cursor 分頁

## 資料庫 Schema

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(50) NOT NULL UNIQUE,
  email VARCHAR(100) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE products (
  id SERIAL PRIMARY KEY,
  name VARCHAR(200) NOT NULL,
  description TEXT,
  price NUMERIC(10, 2) NOT NULL CHECK (price >= 0),
  stock INTEGER NOT NULL DEFAULT 0 CHECK (stock >= 0),
  version INTEGER NOT NULL DEFAULT 0,  -- 樂觀鎖版本號
  category VARCHAR(100),
  image_url VARCHAR(500),
  is_active BOOLEAN NOT NULL DEFAULT TRUE,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE cart_items (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  product_id INTEGER REFERENCES products(id) ON DELETE CASCADE,
  quantity INTEGER NOT NULL CHECK (quantity >= 1),
  added_at TIMESTAMP DEFAULT NOW(),
  UNIQUE (user_id, product_id)
);

CREATE TABLE orders (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id),
  status VARCHAR(20) NOT NULL DEFAULT 'pending'
    CHECK (status IN ('pending', 'paid', 'shipped', 'delivered', 'cancelled')),
  total_amount NUMERIC(10, 2) NOT NULL,
  shipping_address TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE order_items (
  id SERIAL PRIMARY KEY,
  order_id INTEGER REFERENCES orders(id) ON DELETE CASCADE,
  product_id INTEGER REFERENCES products(id),
  product_name VARCHAR(200) NOT NULL,  -- 快照：下單當時的商品名稱
  unit_price NUMERIC(10, 2) NOT NULL,  -- 快照：下單當時的價格
  quantity INTEGER NOT NULL CHECK (quantity >= 1)
);

CREATE INDEX idx_products_category ON products(category) WHERE is_active = TRUE;
CREATE INDEX idx_cart_items_user_id ON cart_items(user_id);
CREATE INDEX idx_orders_user_cursor ON orders(user_id, created_at DESC, id DESC);
```

## 具體任務

1. **建立專案結構**
   ```
   src/
   ├── routes/
   │   ├── auth.js
   │   ├── products.js
   │   ├── cart.js
   │   └── orders.js
   ├── controllers/
   │   ├── authController.js
   │   ├── productController.js
   │   ├── cartController.js
   │   └── orderController.js
   ├── services/
   │   ├── checkoutService.js   ← Transaction 核心邏輯放這裡
   │   └── cartService.js
   ├── middleware/
   │   └── auth.js
   ├── db.js
   └── app.js
   ```

2. **實作認證**
   - `POST /api/auth/register`：新增使用者（密碼 bcrypt hash）
   - `POST /api/auth/login`：驗證帳密，回傳 JWT（有效期 24 小時）

3. **實作商品 API**
   - `GET /api/products`：取得商品列表（OFFSET 分頁，支援 `?page=1&limit=20&category=電子`）
   - `GET /api/products/:id`：取得單一商品詳情
   - `POST /api/products`（需 JWT，管理員可用）：新增商品
   - `PATCH /api/products/:id`（需 JWT）：更新商品資訊或庫存

4. **實作購物車 API（需 JWT）**
   - `GET /api/cart`：取得目前使用者的購物車（含商品詳情、小計、總計）
   - `POST /api/cart/items`：加入商品至購物車（若已存在則更新數量）
   - `PATCH /api/cart/items/:productId`：修改購物車內商品數量
   - `DELETE /api/cart/items/:productId`：從購物車移除商品
   - `DELETE /api/cart`：清空購物車

5. **實作結帳（Transaction 核心任務）**
   - `POST /api/orders/checkout`：結帳（需 JWT）

   Body：
   ```json
   { "shipping_address": "台北市中正區重慶南路一段122號" }
   ```

   `checkoutService.checkout(userId, shippingAddress)` 需在單一 Transaction 中依序執行：

   1. 鎖定購物車內所有商品列（`SELECT ... FOR UPDATE`）
   2. 逐一檢查庫存是否足夠，若不足立即 ROLLBACK 並回傳：
      ```json
      {
        "error": "INSUFFICIENT_STOCK",
        "product_id": 5,
        "product_name": "藍芽耳機",
        "requested": 3,
        "available": 1
      }
      ```
   3. 利用樂觀鎖扣減庫存（防止並發超賣）：
      ```sql
      UPDATE products
      SET stock = stock - $1, version = version + 1
      WHERE id = $2 AND version = $3
      RETURNING id
      ```
      若回傳 0 筆（版本號不符），代表並發衝突，ROLLBACK 並回傳 `409 CONFLICT`。
   4. 建立 `orders` 記錄（計算 `total_amount`）
   5. 批次插入 `order_items`（商品名稱、價格需快照當時值）
   6. 清空該使用者購物車
   7. COMMIT

6. **實作訂單 API（需 JWT）**
   - `GET /api/orders`：取得自己的訂單歷史（Cursor 分頁）
   - `GET /api/orders/:id`：取得單一訂單詳情（含 order_items）
   - `PATCH /api/orders/:id/cancel`：取消訂單（僅限 `pending` 狀態，並回補庫存）

## 提示

- 購物車總計查詢（JOIN products 取得即時價格）：
  ```sql
  SELECT
    ci.product_id,
    p.name,
    p.price,
    p.stock,
    ci.quantity,
    (p.price * ci.quantity) AS subtotal
  FROM cart_items ci
  JOIN products p ON ci.product_id = p.id
  WHERE ci.user_id = $1 AND p.is_active = TRUE
  ```

- Transaction 範本（在 `checkoutService.js` 中使用）：
  ```js
  const { Pool } = require('pg');
  const pool = new Pool();

  async function checkout(userId, shippingAddress) {
    const client = await pool.connect();

      await client.query('BEGIN');

  ```

- 取消訂單時回補庫存，同樣需要 Transaction：
  ```sql
  UPDATE products SET stock = stock + $1 WHERE id = $2
  ```

- OFFSET 分頁回應格式：
  ```json
  {
    "data": [...],
    "pagination": {
      "page": 1,
      "limit": 20,
      "total": 85,
      "total_pages": 5
    }
  }
  ```

- 為結帳 API 撰寫 `supertest + Jest` 整合測試，涵蓋：
  - 正常結帳流程
  - 購物車為空（400）
  - 庫存不足（409 INSUFFICIENT_STOCK）
  - 並發結帳（模擬兩個請求同時搶購最後一件商品，驗證樂觀鎖保護）
