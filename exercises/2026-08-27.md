# 第 8 週今日練習題：使用者頭像上傳與管理 API

## 題目說明

實作一個使用者頭像上傳系統，使用 `multer` 處理 multipart/form-data 請求，並將檔案資訊儲存至 PostgreSQL 資料庫。使用者可以上傳、查詢及刪除自己的頭像。

## 技術要求
- **Express.js**：設計 RESTful API 路由，處理檔案上傳請求
- **PostgreSQL**：建立 `users` 與 `avatars` 資料表，儲存上傳記錄
- **multer**：處理 multipart/form-data，限制檔案類型與大小

## 具體任務

1. **建立資料庫結構**
   ```sql
   CREATE TABLE users (
     id SERIAL PRIMARY KEY,
     username VARCHAR(50) NOT NULL UNIQUE,
     email VARCHAR(100) NOT NULL UNIQUE,
     created_at TIMESTAMP DEFAULT NOW()
   );

   CREATE TABLE avatars (
     id SERIAL PRIMARY KEY,
     user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
     filename VARCHAR(255) NOT NULL,
     original_name VARCHAR(255) NOT NULL,
     mimetype VARCHAR(100) NOT NULL,
     size INTEGER NOT NULL,
     uploaded_at TIMESTAMP DEFAULT NOW()
   );
   ```

2. **設定 multer 中介層**
   - 使用 `diskStorage` 將檔案儲存至 `uploads/avatars/` 目錄
   - 自訂 `filename`：使用 `userId_timestamp.ext` 格式命名
   - 設定 `fileFilter`：只允許 `image/jpeg`、`image/png`、`image/webp`
   - 限制檔案大小上限為 2MB（`limits: { fileSize: 2 * 1024 * 1024 }`）

3. **實作 API 路由**

   | 方法   | 路徑                        | 說明                     |
   |--------|-----------------------------|--------------------------|
   | POST   | `/api/users/:userId/avatar` | 上傳或覆蓋使用者頭像     |
   | GET    | `/api/users/:userId/avatar` | 取得頭像資訊（含 URL）   |
   | DELETE | `/api/users/:userId/avatar` | 刪除頭像（檔案 + DB 記錄）|

4. **POST `/api/users/:userId/avatar`** 邏輯：
   - 驗證 `userId` 是否存在於 `users` 資料表
   - 若該使用者已有頭像，先刪除舊檔案（`fs.unlink`）並刪除舊記錄
   - 將新檔案資訊 INSERT 至 `avatars` 資料表
   - 回傳 `201` 與新頭像資訊

5. **GET `/api/users/:userId/avatar`** 邏輯：
   - 查詢 `avatars` 資料表，JOIN `users` 取得使用者名稱
   - 若無頭像，回傳 `404`
   - 回傳頭像資訊，包含可存取的 URL（例如 `http://localhost:3000/uploads/avatars/filename`）

6. **DELETE `/api/users/:userId/avatar`** 邏輯：
   - 查詢頭像記錄，取得 `filename`
   - 使用 `fs.unlink` 刪除實體檔案（注意處理檔案不存在的情況）
   - 刪除 `avatars` 資料表的記錄
   - 回傳 `200` 確認刪除

## 提示

- 使用 `express.static('uploads')` 讓 `uploads/` 目錄下的檔案可以被存取
- multer 錯誤（如超過大小限制）要用專屬的錯誤處理 middleware 捕捉：
  ```js
  app.use((err, req, res, next) => {
    if (err.code === 'LIMIT_FILE_SIZE') {
      return res.status(400).json({ error: '檔案大小不得超過 2MB' });
    }
    next(err);
  });
  ```
- 在儲存檔案前確認 `uploads/avatars/` 目錄存在（可用 `fs.mkdirSync` 搭配 `{ recursive: true }`）
- 刪除檔案時使用 `fs.promises.unlink`，搭配 try/catch 避免因檔案已不存在而報錯

## 進階挑戰（選做）

- **圖片壓縮**：整合 `sharp` 套件，在儲存前將圖片壓縮並統一轉成 WebP 格式（寬度限制 400px）
- **多檔案上傳**：改用 `upload.array('photos', 5)` 支援一次上傳最多 5 張相片，並批次 INSERT 至資料庫
- **Cloud Storage**：將 `diskStorage` 改為串接 AWS S3 或 Cloudflare R2，使用 `multer-s3` 套件
- **單元測試**：使用 `supertest` 測試上傳 API，模擬檔案上傳（使用 `.attach('avatar', 'test/fixtures/sample.jpg')`）
